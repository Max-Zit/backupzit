Troubleshooting & FAQ

An agent shows as offline

  • Is the machine on and the service running? Windows: Get-Service backupzit-agent; Linux: systemctl status backupzit-agent.
  • Can the machine reach the console? Test-NetConnection backup-server -Port 8443 or curl -k https://backup-server:8443/login.
  • Agent log: C:\ProgramData\backupzit\agent.log or journalctl -u backupzit-agent. "fingerprint mismatch" means the console certificate changed — enroll the agent again.

A backup failed

Open the run in Activity; the message names the cause. Common ones:

Message containsFix
host key mismatch / fingerprintThe SFTP server's key changed or the fingerprint was entered wrongly. Check with ssh-keygen -lf on the server.
permission denied / access deniedStorage credentials or folder permissions. Test the login with an SFTP/SMB client.
no space left / quotaStorage is full. Reduce retention or add space; expired backups free space after the next run.
repository is lockedAnother operation (e.g. cleanup) is running on the same repository; the run retries for 30 minutes. Stale locks expire automatically.
wrong password / recovery keyThe repository was created with a different key — check that the job uses the right storage target.
bucket has no Object Lock enabledImmutability was requested on a bucket created without Object Lock. Create a new bucket with Object Lock.

A backup ends with "warning"

Some files could not be read — usually files locked by an application while VSS is not available, or files the agent has no permission for. The list is on the run page. Everything else is backed up.

Backups are slow

  • The first backup reads and uploads everything; later ones read only changed files and upload only new data.
  • Check the network path to the storage (Wi-Fi, VPN, internet upload speed for cloud storage).
  • Exclude caches, temporary files and media you do not need.

FAQ

Can I use NFS?

Yes: mount the NFS export on the agent (Linux: /etc/fstab) and use a Local / mounted path target such as /mnt/nfs-backup. For Windows machines, SMB is the better choice.

Can I move backups to another storage?

Copy the repository folder (or bucket prefix) as is — it is self-contained — and add a storage target pointing to the new location with the same recovery key.

Does deleting a job delete the backups?

No. Backups stay on the storage and remain restorable from Activity or the command line.

What happens if the console is down?

No new scheduled backups start until it is back; queued runs continue afterwards. Restores are always possible from the command line with the recovery sheet.

How much space will backups need?

Roughly the size of the data after compression for the first backup, plus the daily changes for each kept day. The Reports page shows how much was uploaded per job.
