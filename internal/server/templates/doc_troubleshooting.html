Troubleshooting & FAQ

An agent shows as offline

  • Is the machine on and the service running? Windows: Get-Service backupzit-agent; Linux: systemctl status backupzit-agent.
  • Can the machine reach the console? Test-NetConnection backup-server -Port 8443 or curl -k https://backup-server:8443/login.
  • Agent log: C:\ProgramData\backupzit\agent.log, on Linux /etc/backupzit/agent.log or journalctl -u backupzit-agent. "fingerprint mismatch" means the console certificate changed — enroll the agent again.

A backup failed

Open the run in Activity; the message names the cause. Common ones:

Message containsFix
host key mismatch / fingerprintThe SFTP server's key changed or the fingerprint was entered wrongly. Check with ssh-keygen -lf on the server.
permission denied / access deniedStorage credentials or folder permissions. Test the login with an SFTP/SMB client.
no space left / quotaStorage is full. Reduce retention or add space; expired backups free space after the next run.
repository is lockedAnother operation (e.g. cleanup) is running on the same repository; the run retries for 30 minutes. Stale locks expire automatically.
wrong password / recovery keyThe repository was created with a different key — check that the job uses the right storage target.
bucket has no Object Lock enabledImmutability was requested on a bucket created without Object Lock. Create a new bucket with Object Lock.

"several backup disks are connected"Connect only one of the rotating disks at a time.

Let's Encrypt: "no Cloudflare zone … is accessible with this token"The token must have the permission Zone → DNS → Edit for the zone that holds the console's name.

Console backup: "console backups need network storage"Choose an SFTP, S3, SMB, Azure or hardened repository target; a local path of an agent is not reachable from the console.

An administrator can lift the block under Settings → Sign-in & security. On the server, backupzit-server --unblock-ip all lifts all blocks. Accounts are never locked permanently.
Lost phone for two-factor sign-inUse one of the recovery codes; otherwise an administrator resets two-factor on your user page. The last administrator can reset their password on the server with backupzit-server --set-admin-password.
"your directory account is not in any BackupZit group"Add the user to one of the groups mapped under Settings → LDAP, or map more groups. Use Test there to see the groups found for a user.
API returns 401 / 403401: token missing, revoked, expired or its owner disabled. 403: the token's role is too low for the request.
Azure: AuthenticationFailed / AuthorizationPermissionMismatchWrong account key, or the SAS token lacks read, write, delete or list permission or has expired.
A restored Windows Server 2012 R2 / Windows 8.1 VM does not boot on Hyper-V Gen 2 ("hash was denied (DBX)")Microsoft revoked the old boot loader for Secure Boot. Turn off Secure Boot for that VM, or update the system before backing it up.

Virtual machines, Linux systems and new hardware

SituationWhat to do
Proxmox: "the guest is running and one of its disks is on storage without snapshot support"Running guests need LVM-thin, ZFS, Ceph RBD or qcow2 disks. Move the disk (Disk Action → Move Storage) or back the guest up while it is stopped.
Hyper-V: the run says "crash-consistent"The guest could not prepare for the checkpoint. In Windows guests check that the Hyper-V integration services (Backup (volume shadow copy)) are enabled in the VM settings. In Linux guests install hyperv-daemons (RHEL) or linux-cloud-tools / hyperv-daemons (Debian/Ubuntu).
VMware: "SSH off" or "SSH to …: connection refused"Enable SSH on the ESXi host: Host → Actions → Services → Enable Secure Shell (and set its policy to start with the host). Restores, and backups on the free license, need it.
VMware: "changed block tracking is off and can be enabled … only while the VM is off"Free ESXi license: shut the VM down once, then run the job; BackupZit enables changed block tracking and later backups read only changed blocks.
VMware: "copy the disk on the datastore (needs free space …)"Running VMs are copied briefly on their datastore. Free up space there (as much as the disk uses), or back up the VM while it is off.
VMware: "… is a snapshot delta disk"The VM has snapshots of its own. Delete or consolidate them in the ESXi host client (Snapshots → Delete all).
VMware: "the ESXi certificate changed"The host was reinstalled or another machine answers at its address. If that is expected, remove the host under Agents and add it again to pin the new certificate.
VMware: *.replaced-DATE.vmdk files next to VM disksThe old disks of a VM restored in place. Delete them in the datastore browser once the restored VM works.
Hyper-V: *.replaced-DATE files next to VM disksThe old disks of a VM restored in place. Delete them once the restored VM works.
Proxmox instant recovery: the VM does not boot or hangsCheck the disk server: systemctl status backupzit-instant-ID and journalctl -u backupzit-instant-ID on the node. It needs the backup storage to stay reachable; when the repository cannot be read, the VM's disk reads stall.
Proxmox instant recovery: "efidisk0 stays on storage backupzit-instant"QEMU cannot move the EFI variable store while the VM runs. Shut the VM down and run qm disk move ID efidisk0 STORAGE --delete 1; it does not depend on the backup.
Proxmox: "runs on node X; install the BackupZit agent on X"The guest was migrated. Install the agent on every node and back up each node's guests with that node's agent.
Proxmox backups or restores slow, SFTP "connection lost", "message authentication code incorrect" on the storage serverKnown problem of Intel e1000e network cards on Proxmox hosts (log: "Detected Hardware Unit Hang", "Reset adapter unexpectedly"). Turn off offloading: ethtool -K eno1 tso off gso off gro off and add it as post-up line to the interface in /etc/network/interfaces.
Browse files: "stored on a local path of the agent"The console can only read backups on network storage. Use backupzit-agent pve ls/extract or image-ls/image-extract on the agent.
Linux system restore: "missing programs …"Install the named packages on the restoring machine, or boot the BackupZit Linux recovery ISO, which has them.
Restored Linux machine has no networkThe network settings were bound to the old MAC address (netplan match: macaddress). Restore with Different hardware, or remove the match lines in /etc/netplan/.
Restored Windows stops with INACCESSIBLE_BOOT_DEVICERestore again with Restore to different hardware, or boot the recovery ISO and run backupzit-agent prepare-hardware --disk 0 [--drivers E:\Drivers].
A restored copy of a machine shows up as the original agentRestores into a new Proxmox VM unenroll the agent inside the copy automatically. For other copies, remove agent.json in the copy and enroll it as a new machine.
Agent update does not finishSee the installer log in C:\ProgramData\backupzit\updates or /var/tmp/backupzit-updates; agents before 0.21 must be updated once by hand.
The tray icon is missingClick the ^ arrow next to the clock and drag the BackupZit icon onto the taskbar, or start BackupZit Agent from the Start menu.

A backup ends with "warning"

Some files could not be read — usually files locked by an application while VSS is not available, or files the agent has no permission for. The list is on the run page. Everything else is backed up.

Backups are slow

  • The first backup reads and uploads everything; later ones read only changed files and upload only new data.
  • Check the network path to the storage (Wi-Fi, VPN, internet upload speed for cloud storage).
  • Exclude caches, temporary files and media you do not need.

FAQ

Can I use NFS?

Yes: mount the NFS export on the agent (Linux: /etc/fstab) and use a Local / mounted path target such as /mnt/nfs-backup. For Windows machines, SMB is the better choice.

Can I move backups to another storage?

Copy the repository folder (or bucket prefix) as is — it is self-contained — and add a storage target pointing to the new location with the same recovery key.

Does deleting a job delete the backups?

No. Backups stay on the storage and remain restorable from Activity or the command line.

What happens if the console is down?

No new scheduled backups start until it is back; queued runs continue afterwards. Restores are always possible from the command line with the recovery sheet.

How much space will backups need?

Roughly the size of the data after compression for the first backup, plus the daily changes for each kept day. The Reports page shows how much was uploaded per job.
