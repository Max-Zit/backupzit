Notifications: email, Slack, Teams, webhooks

Get an email when a backup fails, and a daily summary every morning.

Setting up email

Under Settings → Email notifications:

FieldExample
SMTP server / portsmtp.office365.com / 587, smtp.gmail.com / 587, internal relay / 25
SecuritySTARTTLS (port 587), TLS (port 465) or none (internal relay only)
User / passwordThe mailbox used to send; leave empty for an anonymous relay. Microsoft 365 and Gmail need an app password.
Senderbackup@example.com
RecipientsOne or more addresses, comma separated.

Use Send test email to check the settings.

What is sent

  • Failures (recommended) — one email per failed run with the reason: backups, copies, restores and failed restore tests. With this option on you also get a SUSPICIOUS alert when a backup looks like ransomware or mass deletion.
  • Warnings — runs where some files could not be read.
  • Successes — every successful run (usually too much; prefer the daily report).
  • Daily report — at the chosen hour: runs of the last 24 hours, problems and offline agents. Subject starts with OK, WARNINGS or ATTENTION, so mail rules can sort them.

For weekly or monthly summaries use scheduled reports; they are sent with the same mail settings and have their own recipients. Subjects start with [BackupZit] so mail rules can sort them. The SMTP password is stored encrypted.

Slack, Microsoft Teams and webhooks

Under Settings → Chat & webhooks add any number of channels; each chooses whether it gets failures, warnings and successes. Unusual backups (possible ransomware) count as failures. Send test checks a channel right away.

  • Slack: create an incoming webhook for the channel (Slack app settings → Incoming Webhooks) and paste its URL (https://hooks.slack.com/services/…).
  • Microsoft Teams: in the channel, add the workflow Post to a channel when a webhook request is received and paste its URL. Messages arrive as cards with a button that opens the run in the console.
  • Webhook: any URL that accepts a JSON POST — a ticket system, monitoring or automation tool. With a signing secret, each request carries X-BackupZit-Signature: sha256=<hex>, the HMAC-SHA256 of the body, so the receiver can check that it comes from your console.

The JSON of a webhook:

{"event": "run.finished", "run_id": 412, "kind": "vm-backup", "kind_title": "VM backup",
 "status": "failed", "suspicious": "", "job": "Proxmox VMs", "job_id": 7, "agent": "pve1",
 "message": "…", "errors": ["…"], "started_at": "2026-10-04T22:00:03+02:00",
 "finished_at": "2026-10-04T22:04:41+02:00", "url": "https://backup.example/runs/412"}

Messages are sent once per run, also when email is off. A channel that fails (wrong URL, service down) is logged in the console log and does not hold back the others. Webhook URLs are stored encrypted.
