Disk images & bare-metal recovery

An image backup captures a whole disk — partition table, boot partitions, system and data — so a machine can be brought back on an empty or new disk exactly as it was.

Disk image backup is available for Windows machines (NTFS volumes, GPT and MBR disks). For Linux servers use file backups of the data and configuration folders; Linux images are planned.

Creating an image job

  1. In Backup jobs choose Disk image.
  2. The agent reports its disks automatically. Tick a whole disk, or only some partitions (e.g. skip a large data partition that a file job already covers).
  3. Set retention and schedule as for any job; a weekly image plus daily file backups is a common combination.

Only used blocks are read (NTFS allocation map), the image is taken from a VSS snapshot so the running system is consistent, and unchanged blocks are deduplicated against earlier images — the second image of the same machine usually uploads only a few percent.

Restoring an image to a disk

On the image backup run, use Restore this image to a disk:

  • Restore on agent — the machine that has the target disk. This can be a running machine with a spare disk, or a machine booted from the recovery ISO.
  • Target disk — must be at least as large as the used area of the original. All data on it is destroyed.
  • Leave the disk offline afterwards — tick this when the original disk is in the same machine, so Windows does not change the disk IDs of the copy.

GPT and MBR disks, EFI and BIOS boot are supported. The partition layout and IDs are recreated, so the restored disk boots as before.

Bare-metal recovery with the recovery ISO

  1. On Recovery media download the recovery ISO. Burn it to a USB stick (Rufus, "DD image" or "ISO" mode) or attach it to a virtual machine.
  2. Optionally create a recovery code and download recovery.json; copy it to a backupzit folder on the stick so the machine connects without typing.
  3. Boot the machine to restore from the stick. It starts the agent in recovery mode and connects to the console (or asks for the server address and recovery code).
  4. The machine appears as a recovery agent with its disks.
  5. Open the image backup in Activity, choose Restore this image to a disk, select the recovery agent and its disk, confirm.
  6. When the run is finished, remove the stick and reboot.

Restoring to different hardware

Windows starts only with a driver for the disk controller it boots from, and Windows Setup disables the drivers it did not need. An image of a PC with an Intel controller therefore stops with INACCESSIBLE_BOOT_DEVICE on an AMD board, an NVMe drive, in Hyper-V or in a Proxmox VM. Tick Restore to different hardware in the restore form and BackupZit prepares the restored Windows after writing the image:

  1. The drivers for common disk controllers that are part of Windows start at boot again: AHCI/SATA, NVMe, Intel RST, LSI/Broadcom/Dell PERC SAS and RAID, HPE Smart Array, Hyper-V and VMware.
  2. Additional drivers are added with DISM: the drivers on the recovery ISO (it carries the VirtIO drivers for Proxmox/KVM) and the folders you enter under Additional drivers — e.g. the storage and network drivers of the new mainboard, extracted to a USB stick (E:\Drivers; subfolders are searched).
  3. The boot files are rebuilt for the new machine (bcdboot).

The run page lists the drivers enabled and added. Windows detects the remaining new devices at the first start; activation may ask to be repeated on new hardware. Restoring between UEFI and legacy BIOS is not possible — the target must boot the same way as the original.

Physical PC or server to Proxmox VE: create a VM with OVMF (UEFI) for GPT disks or SeaBIOS for MBR disks, a VirtIO SCSI disk at least as large as the original and a VirtIO network card, attach the recovery ISO, and restore with Restore to different hardware. The recovery ISO sees VirtIO disks and network cards itself.

Restoring to a virtual machine

Create an empty VM disk at least as large as the original, boot the VM from the recovery ISO and follow the steps above. This is also the easiest way to test that your images really boot.
