Restoring files

Every successful backup in Activity can be restored — completely or only selected folders — to the same machine or to another agent.

Restore from a file backup

  1. Open Activity (or the job page) and click the backup you want, e.g. last night's run.
  2. Under Restore from this backup choose the agent that should receive the files. It can be a different machine than the one that was backed up — for example a replacement PC.
  3. Choose where:
    • Restore into a folder (recommended) — e.g. D:\Restore. The original structure is recreated below it: D:\Restore\C\Users\ana\Documents\…. Nothing existing is touched.
    • Restore to original location — writes the files back where they were, overwriting current versions.
  4. Optionally limit to Only these paths, one per line, e.g. C:\Users\ana\Documents\Contracts.
  5. Keep Verify restored files on: each file is read back and compared with the checksum in the backup.
  6. Click Start restore. Progress and results appear on the restore run's page.

File times, Windows attributes (hidden, read-only, …) and Linux permissions are restored too.

Finding the right backup: use the Calendar to see which backups ran on which day, or the job page's history.

Restore single files from a disk image

For image backups, click Browse files on the backup run. You can navigate the NTFS file system inside the image directly in the console, tick files and folders, and restore them to any agent — without restoring the whole disk.

Restore without the console

If the console itself is lost, any machine with the agent installed can restore directly from the storage using the recovery sheet of the storage target:

set BACKUPZIT_PASSWORD=<recovery key>
set BACKUPZIT_SFTP_PASSWORD=...           (or the S3/SMB/hardened credentials)
backupzit-agent snapshots --repo sftp://backup@nas:22/backups/pc1_1a2b3c4d
backupzit-agent restore   --repo sftp://backup@nas:22/backups/pc1_1a2b3c4d --target D:\Restore latest

See Command line reference.

Test your restores

Schedule a restore test regularly (e.g. monthly): restore a folder into D:\RestoreTest with verification enabled and check a few files. It proves the backups, the storage credentials and the recovery key all work.
