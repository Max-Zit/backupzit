Restoring files

Every successful backup in Activity can be restored — completely or only selected folders — to the same machine or to another agent.

Restore from a file backup

  1. Open Activity (or the job page) and click the backup you want, e.g. last night's run.
  2. Under Restore from this backup choose the agent that should receive the files. It can be a different machine than the one that was backed up — for example a replacement PC.
  3. Choose where:
    • Restore into a folder (recommended) — e.g. D:\Restore. The original structure is recreated below it: D:\Restore\C\Users\ana\Documents\…. Nothing existing is touched.
    • Restore to original location — writes the files back where they were, overwriting current versions.
  4. Optionally limit to Only these paths, one per line, e.g. C:\Users\ana\Documents\Contracts.
  5. Keep Verify restored files on: each file is read back and compared with the checksum in the backup.
  6. Click Start restore. Progress and results appear on the restore run's page.

File times, Windows attributes (hidden, read-only, …) and Linux owners, permissions (including setuid bits), ACLs, extended attributes (SELinux labels, file capabilities), symbolic and hard links are restored too. Owners are set only when the agent runs as root/administrator.

Finding the right backup: use the Calendar to see which backups ran on which day, or the job page's history.

Restore single files from a disk image

For image backups, click Browse files on the backup run. You can navigate the NTFS file system inside the image directly in the console, tick files and folders, and restore them to any agent — without restoring the whole disk.

Restore single files from a VM (Proxmox VE, Hyper-V)

In a VM backup run click Browse files next to the guest. The console shows the partitions and LVM volumes of its disks and lets you browse NTFS, ext4 and XFS file systems. Download the ticked files (several as a ZIP archive) or restore them on any agent. See Proxmox VE and Hyper-V.

Restore whole machines

  • Windows disk images: onto a disk or bare metal, also onto different hardware — Disk images.
  • Linux systems: onto a disk or bare metal, or as a new Proxmox VM — Linux system backup.
  • Proxmox VMs and containers: as a new guest or in place — Proxmox VE.
  • Hyper-V VMs: as a new VM or in place (keeps ID and MAC addresses) — Hyper-V.

Browsing files in the console works for backups on network storage (SFTP, S3, SMB, Azure, hardened repository); the console reads them directly. For backups on a local disk of an agent use the command line.

Restore without the console

If the console itself is lost, any machine with the agent installed can restore directly from the storage using the recovery sheet of the storage target:

set BACKUPZIT_PASSWORD=<recovery key>
set BACKUPZIT_SFTP_PASSWORD=...           (or the S3/SMB/hardened credentials)
backupzit-agent snapshots --repo sftp://backup@nas:22/backups/pc1_1a2b3c4d
backupzit-agent restore   --repo sftp://backup@nas:22/backups/pc1_1a2b3c4d --target D:\Restore latest

See Command line reference.

Automatic restore tests

BackupZit proves your backups regularly without you doing anything: weekly (configurable under Settings → Restore tests) the agent of each job restores a random sample of files from the newest backup into a temporary folder, verifies every byte against the stored checksums and deletes it again. For disk images, random blocks are read and verified. This exercises the whole chain — storage access, credentials, encryption key and data integrity.

  • Results appear in Activity and the job history as Restore test runs, and per job in Reports (column Restore test).
  • A failed test is a failure like any other and triggers an email alert.
  • Test restore on a job's page starts a test immediately.
  • The sample size limits how much is read from the storage — keep it small for cloud storage with download fees.

Additionally, restore a real folder by hand from time to time (e.g. quarterly) and open a few files — it also trains the people who will need to do it in an emergency.
