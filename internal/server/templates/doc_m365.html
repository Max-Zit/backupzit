Microsoft 365: Exchange Online, OneDrive and SharePoint

BackupZit backs up the mailboxes (Exchange Online), calendars, contacts, OneDrive and SharePoint sites of a Microsoft 365 tenant through Microsoft Graph. It only reads: nothing in the tenant is changed or deleted. Any agent with internet access downloads the data — for example the agent on the console machine — and stores it like every backup: deduplicated, encrypted, with retention, copy jobs and restore tests.

1. Register an app in Microsoft Entra ID

Once per tenant, as a Global Administrator, in the Microsoft Entra admin center:

  1. App registrations → New registration: name e.g. BackupZit, Accounts in this organizational directory only, no redirect URI. Note the Application (client) ID and the Directory (tenant) ID on its overview.
  2. Certificates & secrets → New client secret: choose a lifetime (e.g. 24 months) and copy the secret's Value right away — it is shown only once. The Secret ID is not the secret.
  3. API permissions → Add a permission → Microsoft Graph → Application permissions (not delegated): User.Read.All, Mail.Read and Files.Read.All; for calendars and contacts also Calendars.Read and Contacts.Read, for SharePoint Sites.Read.All.
  4. Click Grant admin consent for …. Until then the status shows Not granted and backups are refused.

These are read permissions only. Restoring into mailboxes later needs write permissions, which BackupZit does not ask for.

To limit the app to some mailboxes, an Exchange administrator can add an application access policy or RBAC for Applications scope; accounts outside it are then reported as not readable.

2. Create the job

Under Backup jobs create a job of the kind Microsoft 365:

  • Agent: the agent that downloads (Windows or Linux, version 0.34.0 or newer; 0.35.0 for calendars, contacts and SharePoint). It needs HTTPS access to login.microsoftonline.com, graph.microsoft.com and, for OneDrive and SharePoint files, *.sharepoint.com.
  • Directory (tenant) ID, Application (client) ID and Client secret from step 1. The secret is stored encrypted.
  • What to back up: Mail, OneDrive, Calendars and contacts, SharePoint sites — any combination.
  • Accounts: one address per line, or empty for every account of the tenant that has a mailbox or OneDrive — accounts added later are included automatically; accounts without a license are skipped.
  • SharePoint sites: one site address per line (e.g. https://contoso.sharepoint.com/sites/sales), or empty for every site of the tenant — sites added later are included automatically. Personal sites (OneDrive) are left out; they are backed up with the accounts. A job with only SharePoint needs no accounts.

When the job is saved, the console signs in as the app and checks the permissions, the accounts and the sites, so a wrong secret or a missing admin consent shows at once. A console without internet access skips the check; the first backup then shows whether it works.

What is backed up

  • Mail: all mail folders with their subfolders (Inbox, Sent Items, Deleted Items, Archive, your own folders…). Each message is stored complete with attachments in MIME format as an .eml file, named by when it arrived and its subject, e.g. 2026-10-07 0621 Offer for October [3fa2c1d9e0].eml. Outlook, Thunderbird and most mail programs open .eml files.
  • OneDrive: all files and folders of the account's OneDrive, with their modification time.
  • Calendars: every calendar of the account; each event as an iCalendar file (.ics) with time, place, description, organizer, attendees, reminder and — for a series — its recurrence, named by its start and subject, e.g. 2026-10-08 1000 Board meeting [8c1e…].ics. Outlook, Google Calendar and Thunderbird import .ics files. Times are stored in UTC.
  • Contacts: the account's contacts and contact folders, each as a vCard (.vcf) with names, e-mail addresses, phone numbers, addresses, company and notes.
  • SharePoint: every document library of each site (Documents, Site Assets and libraries you created), with all folders and files.

Not included: attachments of calendar events, contact photos, single changed occurrences of a series, SharePoint lists and pages (only document libraries), Teams chats and channel messages (Teams files are in SharePoint and are backed up with it), and shared mailboxes without a user account.

A backup holds one folder per account — ana@contoso.com/Mail/Inbox/…, …/OneDrive/…, …/Calendar/Calendar/…, …/Contacts/… — and SharePoint/<site>/<library>/…. The first backup downloads everything; every later backup lists the folders again but downloads only messages and files that are new or changed since the previous backup (read, flagged, moved or edited messages count as changed) — unchanged data is taken from the previous backup. Microsoft limits how fast an app may read; BackupZit waits when Microsoft asks it to and continues, so a first backup of large mailboxes can take hours.

The backups of a tenant are stored in their own repository on the storage target (folder m365-<tenant ID>), so the downloading agent can be replaced without starting over.

Restoring

  • Browse files on a backup run: open an account's mail folders, OneDrive, calendars or contacts, or a SharePoint site, tick messages, events, files or folders and download them (one file as is, several as a ZIP) — open the .eml files in Outlook or drag them into a mailbox.
  • Restore into a folder on any agent: the messages are written as .eml files, events as .ics, contacts as .vcf and OneDrive and SharePoint files as they were, below <folder>/<account>/… and <folder>/SharePoint/….

Restoring directly into a mailbox or OneDrive is planned; it will write only into a new folder and never overwrite or delete.

Troubleshooting

  • AADSTS7000215 / invalid client secret: the secret's Value was not copied (but its ID), or it expired — create a new one and enter it in the job.
  • missing the application permissions or Authorization_RequestDenied: add the permissions as application permissions and click Grant admin consent.
  • the account has no Exchange Online mailbox: the account has no Exchange license (or is a contact); remove it from the job.
  • A run with warnings lists messages or files that could not be read (e.g. a OneNote notebook); the rest of the backup is complete.
