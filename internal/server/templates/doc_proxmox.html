Proxmox VE virtual machines

BackupZit backs up Proxmox VE virtual machines (QEMU) and containers (LXC) without installing anything inside the guests. The agent runs on the Proxmox host, takes a snapshot of each guest, reads its disks and stores them deduplicated on any storage target.

Setup

  1. Install the Linux agent — Debian / Ubuntu package from Agents on each Proxmox node (Proxmox VE 7 and 8 are Debian based): 
    apt install ./backupzit-agent_*.deb
backupzit-agent enroll --code "BZ1-..."
systemctl enable --now backupzit-agent
  2. Within a minute the node appears on the Agents page with the badge Proxmox VE · N guests.
  3. In Backup jobs select that agent and choose Proxmox VMs and containers. Back up all guests of the node (guests created later are included automatically) or tick individual ones.

The agent uses the node's own tools (qm, pct, pvesm, LVM, ZFS, Ceph); no API token or password is stored in the console.

How a guest is backed up

  1. A temporary Proxmox snapshot is taken (backupzit_…, visible under Snapshots for a few seconds to minutes). The guest keeps running.
  2. If the QEMU guest agent runs in the VM (and is enabled in the VM options), Proxmox freezes the file systems for the snapshot — the backup is then application consistent. Without it, the backup is crash consistent, like a power loss. Install qemu-guest-agent in Linux VMs and the VirtIO guest tools in Windows VMs.
  3. Every disk is read from the snapshot in 1 MiB blocks. Empty blocks are not stored and blocks already in the repository are not uploaded again, so after the first backup only changed data is transferred.
  4. The snapshot is removed. The guest configuration (CPU, memory, network, disks) is stored with the backup.

The run page lists each guest, its disks and how it was captured. Restore tests check random blocks of VM backups like disk images.

Disks marked Backup: no (backup=0) in Proxmox, passed-through physical disks and bind mounts are skipped and listed as warnings. Cloud-init drives are not stored; they are recreated from the configuration on restore.

Restoring a VM or container

Open a VM backup run (from the job page or Activity) and use Restore a VM or container:

  • Guest — one of the guests in that backup.
  • Restore on Proxmox node — any node with the BackupZit agent; also a node of another cluster.
  • As a new guest with the next free ID (default) or with ID … — the original keeps running. Because both exist, the network cards of the copy get new MAC addresses.
  • With its original ID — after the guest was deleted. If it still exists, tick stop and delete it to replace it with the backup; the existing guest and its disks are deleted first.
  • Name and Storage for the disks — e.g. restore to a different storage than the original.
  • Start the guest after the restore.

Every restore gives VMs a new generation ID (vmgenid), so Windows domain controllers and other software detect the rollback safely. Disks are allocated with pvesm on the chosen storage; on directory storage they are restored as raw files.

Command line

backupzit-agent pve list
backupzit-agent pve backup  --repo ... [--vmid 100,200] [--exclude 300]
backupzit-agent pve show    --repo ... latest
backupzit-agent pve restore --repo ... --vmid 100 [--new-vmid -1|N] [--name copy] [--storage local-lvm] [--overwrite] [--start] SNAPSHOT|latest

The repository options are the same as for all commands (see Command line reference). The command line works without the console, for example to restore a whole node after a disaster.

Clusters

Install the agent on every node. A job backs up the guests running on its agent's node; a guest listed in a job that has been migrated to another node is reported as a warning naming that node — back up each node with its own job, or use all guests of the node on every node so migrated guests are always covered.

Not yet included

  • Restoring single files from a VM backup — restore the VM under a new ID and copy the files, or back up important folders inside the guest with a file job.
  • VMware, Hyper-V and XCP-ng hosts.
