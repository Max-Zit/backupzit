Agents

An agent is installed on every machine you protect. It runs as a service, asks the console for work every 30 seconds and talks to the storage directly.

Supported systems

  • Windows 10, 11 and Windows Server 2016 and newer — Windows agent MSI.
  • Windows 7 SP1, Windows Server 2008 R2 SP1 and 2012 R2 — Windows agent — older systems MSI (…-legacy.msi), with the same features including VSS and disk images.
  • Debian, Ubuntu, AlmaLinux, Rocky Linux (64-bit).
  • Proxmox VE 7 and 8 nodes — the Debian package; the agent then also backs up the node's VMs and containers (see Proxmox VE).

Enrolling agents

  1. On the Agents page click Create enrollment token. The console shows an enrollment code (BZ1-…), valid for 7 days and usable for any number of machines. It contains the console address, the token and the certificate fingerprint.
  2. Windows: run the MSI and paste the code when the installer asks for it. Linux: run the command shown.
  3. The machine appears in the agent list within a minute.

If the console cannot be reached during installation, the agent keeps the code and retries until it can enroll. Upgrades keep the enrollment and do not ask again.

Windows, silent (GPO, Intune, RMM)

msiexec /i backupzit-agent.msi /qn ENROLLCODE="BZ1-..."

The older form SERVER="..." TOKEN="..." FINGERPRINT="SHA256:..." still works. A silent install without these properties sets up the service, which waits until you enroll it with backupzit-agent enroll --code "BZ1-..." in an administrator prompt.

Linux

apt install ./backupzit-agent_*.deb        # or: dnf install ./backupzit-agent-*.rpm
backupzit-agent enroll --code "BZ1-..."
systemctl enable --now backupzit-agent

Agent status

  • online — the agent contacted the console in the last 3 minutes.
  • offline — the machine is off, the service is stopped or the network is blocked. Scheduled backups are queued and start as soon as the agent comes back.
  • recovery — a machine booted from the recovery ISO, ready to receive a full-disk restore.

The IP addresses column lists the machine's own addresses as the agent last reported them. Seen from is the address its connections arrive from: on a local network the same address, for a machine behind NAT (e.g. a laptop at home) the router's public address. The console does not ask any external service for it.

Upgrading

When the console has a newer agent installer than an agent runs, the Agents page shows Update to x.y.z next to its version, and Update all agents below the list. The agent then:

  1. waits until it is idle (a running backup is never interrupted),
  2. downloads the matching installer from the console over its pinned connection — the MSI for Windows 10/11/2016+, the older systems MSI for Windows 7/2008 R2/2012 R2, the deb or rpm package on Linux — and checks its SHA-256,
  3. installs it and restarts; the new version appears in the list within a few minutes. The enrollment and all settings are kept.

The console offers the newest installers in its dist directory; the server package ships the agent installers of its own version. Updates from the console work for agents from version 0.21 on; older agents are updated once by installing the newer MSI / package over the old one (the enrollment is kept). The installer log is in C:\ProgramData\backupzit\updates or /var/tmp/backupzit-updates.

Removing an agent

Remove on the Agents page deletes the agent and its jobs from the console. Backups on the storage are not deleted. Uninstall the software on the machine separately.

Where the agent keeps its configuration

  • Windows: C:\ProgramData\backupzit\agent.json (accessible only to SYSTEM and Administrators).
  • Linux: /etc/backupzit/agent.json (root only).

The file contains the agent's secret. Anyone who can read it can act as that agent, so keep these permissions.

Agent log

  • Windows: C:ProgramDataackupzitgent.log
  • Linux: journalctl -u backupzit-agent

Uninstalling

Windows: Settings → Apps → BackupZit Agent → Uninstall (or msiexec /x). Linux: apt remove backupzit-agent / dnf remove backupzit-agent. Then remove the agent in the console. Backups stay on the storage.
