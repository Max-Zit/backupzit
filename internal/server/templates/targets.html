Add storage target

A Linux server running backupzit-repo. Backups written there cannot be changed or deleted by agents, this console or anyone holding the access key until the immutability period set on that server ends — protection against ransomware and compromised credentials. Disable SSH and other remote access to that server after setup.
Agents connect with these credentials themselves (SMB 2/3), so the share does not need to be mapped on the machines.
Advanced
For ransomware protection, enable version-level immutability (a time-based retention policy) on the container in Azure; deleted or overwritten backups then remain recoverable.
For offline copies on rotating USB disks: name each disk's volume BZBACKUP1, BZBACKUP2 … (Windows: right-click the drive → Properties). The agent finds the connected disk by its label, whatever drive letter it gets. Each disk holds a complete, independent backup; take one home or to a safe and swap them regularly. Connect only one disk at a time.
Protects against ransomware and deleted backups: nobody, not even with the storage keys, can delete or change backup data before the period ends. The bucket must be created with Object Lock enabled. Deleted or expired backups free space only after the period ends — add a lifecycle rule that removes noncurrent versions. Choose a period at least as long as your retention.
