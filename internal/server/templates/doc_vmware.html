VMware ESXi virtual machines

BackupZit backs up the virtual machines of VMware ESXi hosts without installing anything on ESXi or inside the VMs. A BackupZit agent on any machine in the network works as the host's proxy. It takes snapshots, reads only the changed blocks of the virtual disks and writes them to your storage.

Requirements

  • ESXi 6.7, 7 or 8, connected directly. Hosts managed by vCenter are added one by one with their own address; vCenter itself is not supported yet.
  • A user with administrator rights on the host, usually root.
  • SSH enabled on the host: Host → Actions → Services → Enable Secure Shell. Restores always need it. Hosts with the free ESXi license also need it for snapshots, because their API is read-only.
  • A proxy agent: any Windows or Linux agent that reaches the host on ports 443 and 22. The backup data flows through it, so put it on a fast network close to the host and the storage.
  • Free space on the VM's datastore while a running VM is backed up. BackupZit copies the disk there for a moment (see below). The copy is thin, so it needs as much space as the disk actually uses.

Adding a host

  1. Open Agents → VMware ESXi hosts → Add an ESXi host.
  2. Enter the address, the user, the password and the proxy agent.
  3. The console connects once to check them. It reads the VM list and the license, and pins the host's HTTPS certificate and SSH host key. If the host is later replaced by another machine with the same address, BackupZit refuses to connect instead of sending it the password.

The password is stored encrypted, like all other secrets. The VM list is refreshed every 10 minutes, or immediately with Refresh. The table shows each host's mode:

  • vSphere API: licensed hosts.
  • Free license: snapshots and restores go over SSH.

Backup jobs

In Backup jobs, choose the ESXi host (listed under VMware ESXi hosts in the agent list) and Virtual machines. Back up all VMs of the host (VMs created later are included automatically) or tick individual ones. The job runs on the host's proxy agent. If you change the proxy, the existing jobs follow.

How a VM is backed up

  1. Changed block tracking (CBT) is switched on for the VM if it is off.
    • On licensed hosts this happens automatically.
    • On free hosts CBT can only be switched on while the VM is turned off. BackupZit does it at the first backup that finds the VM off. Until then, every backup reads the whole disks and the run shows a warning.
  2. A snapshot backupzit_… is taken. When VMware Tools run in the guest, the snapshot is quiesced: applications and file systems are flushed first, which makes the backup application-consistent. Without VMware Tools it is crash-consistent. Install open-vm-tools in Linux VMs and VMware Tools in Windows VMs.
  3. CBT reports which blocks to read:
    • for the first backup, only the blocks in use;
    • after that, only the blocks changed since the previous backup.
  4. A running VM keeps its disks locked. Its disks are therefore copied on the datastore (thin) and the snapshot is removed right away, usually after seconds. The copy is then read over HTTPS and deleted. VMs that are turned off are read directly.
  5. The VM's configuration (.vmx) and NVRAM are stored with the backup.

Example from the test lab: a Debian VM with an 8 GB disk, 1.6 GB of it in use. The first backup read 1.6 GB. The next one, after 50 MB of new data, read 70 MB and took 23 seconds.

Restoring a VM

Use the restore wizard (Whole virtual machine) or the backup's page in Activity. Choose:

  • As a new VM next to the original: a copy with a new name, UUID and MAC addresses. The default name is the original's plus -restored- and the date. Guest network settings tied to the old MAC addresses, such as netplan match: macaddress in cloud images, do not apply to the copy.
  • In place of the original VM: with turn it off and replace its disks, BackupZit:
    • turns the VM off and deletes its snapshots;
    • renames the current disks to ….replaced-DATE.vmdk (delete them once the restored VM works);
    • writes the backup into new disks with the original names, and sets CPU and memory as in the backup.
    The VM keeps its UUID, network adapters and MAC addresses. If the VM was deleted, it is recreated with its original identity.
  • ESXi host and datastore: another host, or another datastore of the same host.
  • Start the VM after the restore.

Disks are restored thin, and only blocks with data are written. ISO images that were connected to CD/DVD drives are not part of the backup, so those drives are left empty.

Instant recovery

Choose Instantly, running from the backup to start a VM within seconds, without copying its disks first. The host's proxy agent — it must be a Linux agent — serves the VM's disks straight from the backup over NFS; the host mounts that as the datastore backupzit-<agent> and runs the VM from it. Changes the VM makes are kept on the agent (/var/lib/backupzit/instant-esxi, so it needs free space for them); the backup itself is never changed, and retention keeps it while the VM runs from it. If the original VM still exists, the instant VM gets a new UUID and new MAC addresses.

On the run's page, when the VM works as it should:

  • Finish copies it to a datastore of the host: the VM is shut down (through VMware Tools if they run), its disks are copied thin with vmkfstools, it is registered from the datastore and started again. The free ESXi license has no Storage vMotion, so this needs a short downtime that grows with the disk size. If the copy fails, the VM keeps running from the backup.
  • Discard stops and deletes the VM with all its changes.

The agent answers NFS on port 2049 (and registers it with the machine's rpcbind on port 111, or answers port 111 itself) only for the ESXi host's address; open these ports from the host to the agent if a firewall is in between. When the last instant VM is finished or discarded, the datastore is removed and the NFS server stops.

Single files

Browse files on the backup's page (or Files from a virtual machine in the restore wizard) opens the VM's disks. You can browse NTFS, ext2/3/4 and XFS, also on LVM, and download files or restore them to any agent.

Command line

These commands run on any agent. Set the ESXi password in BACKUPZIT_VMWARE_PASSWORD:

backupzit-agent vmware list    --host 192.168.1.20 [--user root]
backupzit-agent vmware backup  --host … --repo … [--vmid N,N]
backupzit-agent vmware restore --host … --repo … --vmid N [--new] [--name NAME] [--datastore DS] [--overwrite] [--start] SNAPSHOT|latest

vmware list shows the host's certificate and SSH key fingerprints. Pass them with --thumbprint and --ssh-host-key to pin them on the command line too.

Not yet included

  • vCenter. Add each ESXi host directly.
  • VMs with snapshots of their own. Their disks are deltas; delete or consolidate the snapshots first.
  • Some disk types. Raw device mappings (RDM) and independent disks.
  • Instant recovery through a Windows proxy agent. Instant recovery needs a Linux proxy agent.
