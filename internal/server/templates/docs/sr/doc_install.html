Instalacija servera

Konzola radi na Linuxu (Debian, Ubuntu, AlmaLinux, Rocky Linux) sa PostgreSQL-om. Svaka organizacija ima svoju konzolu na svojoj mreži.

Zahtevi

  • Linux VM ili server: 2 vCPU, 2–4 GB RAM i disk od 20 GB su dovoljni i za stotine agenata (podaci bekapa se ne čuvaju na njemu).
  • PostgreSQL 13 ili noviji (lokalno ili na drugom serveru).
  • Mreža: agenti moraju da dođu do konzole na TCP 8443 (HTTPS). Agenti moraju i direktno da dođu do skladišta.

1. Gotova slika VM-a

Gotov uređaj (Debian, PostgreSQL, konzola, automatska bezbednosna ažuriranja) koji se pokreće za manje od minuta i ne traži pristup internetu:

HipervizorKako
VMware ESXiHost Client: Create / Register VM → Deploy a virtual machine from an OVF or OVA file, izaberite backupzit-appliance.ova. vSphere: Deploy OVF Template. Workstation i VirtualBox: File → Open / Import.
Proxmox VEKopirajte backupzit-appliance.qcow2 na čvor, napravite VM bez diska (2 vCPU, 2–4 GB RAM, VirtIO mreža), zatim
qm importdisk <vmid> backupzit-appliance.qcow2 local-lvm
zakačite uvezeni disk kao SCSI, postavite ga za disk za pokretanje i uključite QEMU guest agent.
Hyper-VRaspakujte backupzit-appliance-vhdx.zip, zatim New → Virtual Machine, generacija 1, 2–4 GB RAM, Use an existing virtual hard disk: VHDX.

Pokrenite VM. Njen ekran prikazuje adresu web konzole i početnu lozinku korisnika admin (vidi Prva prijava). Dajte VM-u 2 vCPU i 2–4 GB RAM; disk od 16 GB možete povećati u bilo kom trenutku — uređaj novi prostor koristi od sledećeg pokretanja (root fajl-sistem se povećava u radu). Pri prvom pokretanju svaka kopija pravi svoje SSH ključeve, lozinku baze i ključ za tajne, pa jedna slika može da se postavi mnogo puta. Mrežna kartica dobija adresu preko DHCP-a.

2. ISO uređaja

ISO uređaja instalira sve bez pitanja: Debian, PostgreSQL, konzolu i automatska bezbednosna ažuriranja.

  1. Napravite VM (ili koristite server) sa 2 vCPU, 2–4 GB RAM i diskom od 16 GB ili većim. Koristite VirtIO ili podrazumevane uređaje hipervizora, BIOS ili UEFI.
  2. Pokrenite je sa backupzit-appliance.iso. Posle 5 sekundi instalacija počinje sama, briše prvi disk i instalira. Preuzima pakete operativnog sistema, pa server tokom instalacije mora da ima pristup internetu. To traje oko 10–20 minuta, a zatim se server restartuje.
  3. Ekran servera prikazuje adresu web konzole i početnu lozinku korisnika admin. Otvorite adresu, prijavite se i promenite lozinku.

Uređaj (slika ili ISO)

Uređaj ima dva odvojena naloga:

  • admin u web konzoli (https://<adresa>:8443) za svakodnevni rad. Njegova početna lozinka se prikazuje na ekranu servera posle prvog pokretanja; promenite je u Moj nalog.
  • bzadmin na samom serveru (njegov ekran u konzoli hipervizora, ili SSH), početna lozinka backupzit. Morate da je promenite pri prvoj prijavi; korisnik može da koristi sudo. Root ne može da se prijavi.

Ažuriranjima BackupZit-a i operativnog sistema upravlja se iz konzole (vidi dole). VMware Tools i QEMU guest agent su uključeni, pa hipervizori prikazuju adresu uređaja.

Ista podešavanja mreže, imena servera, SSH-a i vremenske zone su u web konzoli pod Podešavanja → Mreža (samo za administratore). Tamo se statička adresa čiji gateway ne odgovori za pola minuta automatski poništava, pa greška u kucanju ne može da odseče uređaj od mreže; ako konzola ipak nije dostupna, koristite meni na ekranu servera, koji radi i sa isključenim SSH-om.

Agenti pamte sertifikat konzole, a ne njenu adresu. Ako se konzoli javljaju preko IP adrese, a adresa se promeni, usmerite ih na novu komandom backupzit-agent set-server (vidi Agenti), ili od početka koristite DNS ime. Uz DHCP, rezervišite adresu uređaja u DHCP serveru da se ne bi menjala.

SSH server uređaja nudi samo AES-GCM/CTR šifre i SHA-2 MAC-ove (bez chacha20-poly1305 i 64-bitnih MAC-ova, koje skeneri ranjivosti prijavljuju kao slabe).

3. Instalacioni skript

Na postojećem serveru sa Debian 12+, Ubuntu 22.04+, AlmaLinux ili Rocky Linux 9+ (x86-64), kao root:

curl -fsSL https://github.com/Max-Zit/backupzit/releases/latest/download/install.sh | sudo sh

Skript instalira PostgreSQL, preuzima najnovije izdanje, proverava njegov potpis BackupZit ključem za izdanja i kontrolni zbir paketa, instalira konzolu, pravi bazu sa nasumičnom lozinkom, piše /etc/backupzit/server.env, uključuje automatska bezbednosna ažuriranja, otvara port 8443 u firewalld-u ili ufw-u ako su aktivni, pokreće konzolu i ispisuje njenu adresu i početnu lozinku korisnika admin. Opcije (posle sh -s --):

OpcijaDejstvo
--version 0.32.0instalira ovo izdanje umesto najnovijeg
--db postgres://user:pw@host:5432/dbkoristi postojeću PostgreSQL bazu umesto lokalne
--hosts backup.example.local,10.0.0.10imena i adrese za sertifikat konzole (podrazumevano: adresa i ime servera)
--no-auto-updatesostavlja automatska bezbednosna ažuriranja kakva jesu

Primer: curl -fsSL …/install.sh | sudo sh -s -- --hosts backup.example.local. Ponovno pokretanje skripta na instaliranoj konzoli ažurira BackupZit i zadržava podešavanja i podatke. Da biste skript pročitali pre pokretanja, prvo ga preuzmite: curl -fsSLO …/install.sh; less install.sh; sudo sh install.sh.

4. Paketi ručno

Debian / Ubuntu

apt install postgresql
apt install ./backupzit-server_*.deb

AlmaLinux / Rocky Linux

dnf install postgresql-server && postgresql-setup --initdb && systemctl enable --now postgresql
dnf install ./backupzit-server-*.rpm

Na AlmaLinuxu i Rocky Linuxu, u /var/lib/pgsql/data/pg_hba.conf za redove 127.0.0.1 i ::1 promenite ident u scram-sha-256 i restartujte PostgreSQL, da bi konzola mogla da se prijavi lozinkom.

Pravljenje baze

sudo -u postgres psql -c "SET password_encryption = 'scram-sha-256'; CREATE USER backupzit WITH PASSWORD 'choose-a-strong-password'"
sudo -u postgres psql -c "CREATE DATABASE backupzit OWNER backupzit"

Upišite podatke za povezivanje u /etc/backupzit/server.env:

BACKUPZIT_DB=postgres://backupzit:choose-a-strong-password@localhost:5432/backupzit?sslmode=disable
BACKUPZIT_PUBLIC_URL=https://backup.example.local:8443
BACKUPZIT_TLS_HOSTS=backup.example.local,10.0.0.10
systemctl start backupzit-server

Prva prijava

Otvorite https://<server>:8443. Početni administrator je admin; lozinka je u /var/lib/backupzit/initial-admin-password.txt (ili postavite BACKUPZIT_ADMIN_PASSWORD pre prvog pokretanja). Promenite je posle prijave. Zaboravljenu lozinku resetujete na serveru:

set -a; . /etc/backupzit/server.env; set +a
backupzit-server --set-admin-password 'NOVA-LOZINKA'

Sertifikat

Pri prvom pokretanju konzola pravi samopotpisani sertifikat. Pregledač će jednom upozoriti na njega; agenti se uopšte ne oslanjaju na sertifikaciona tela — oni pri registraciji zapamte otisak sertifikata prikazan na stranici Agenti. To štiti agente od lažnog servera čak i na mreži kojoj se ne veruje.

Ne menjajte taj sertifikat (cert.pem/key.pem u folderu sa podacima): ranije registrovani agenti bi odbili da se povežu dok se ponovo ne registruju. Za pregledače umesto toga dodajte pouzdan sertifikat, kako je opisano dole.

Pouzdan sertifikat za pregledače

Da biste izbegli upozorenje pregledača, otvorite Podešavanja → Sertifikat. Konzola tada odgovara i na DNS imenu, na primer https://backup.example.com na portu 443, sa pouzdanim sertifikatom. Agenti i dalje koriste port 8443 i zapamćeni sertifikat, pa se na njih ovo ne odnosi.

  • Otpremi sertifikat iz CA vaše firme ili javnog CA, može i wildcard sertifikat kao *.example.com. Nalepite sertifikat (sa posredničkim sertifikatima) i privatni ključ u PEM formatu, ili izaberite fajlove. Konzola proverava da ključ pripada sertifikatu, da je sertifikat trenutno važeći i da pokriva DNS ime. Bez internog DNS-a unesite IP adresu konzole i koristite sertifikat izdat za tu IP adresu (subject alternative name IP:192.168.1.20); konzoli tada dajte fiksnu adresu. Email stiže 21 dan pre isteka.
  • Let's Encrypt: besplatni sertifikati, automatski se obnavljaju 30 dana pre isteka. Let's Encrypt mora da proveri da upravljate imenom, na jedan od dva načina:
    • DNS provera preko Cloudflare-a, preporučena za konzole koje nisu dostupne sa interneta. BackupZit pravi privremeni TXT zapis pomoću Cloudflare API tokena. U Cloudflare-u idite na My Profile → API Tokens → Create Token, koristite šablon Edit zone DNS i ograničite ga na svoju zonu.
    • HTTP provera: port 80 konzole mora da bude dostupan sa interneta pod DNS imenom. To se retko želi za server za bekap.
    Podešavanje prvo isprobajte sa Koristi Let's Encrypt test sistem. Njegovim sertifikatima pregledači ne veruju, ali nema ograničenja broja zahteva.
  • Koristi port 80 preusmerava http:// na https://.

DNS ime mora da pokazuje na IP adresu konzole, obično preko A zapisa u internom DNS-u. Fajlovi sertifikata se čuvaju u /var/lib/backupzit/web, a ključ može da čita samo servis. Na Linuxu servis sme da koristi portove 80 i 443 (CAP_NET_BIND_SERVICE); otvorite ih u firewall-u ako se pregledači povezuju iz drugih mreža.

Ažuriranje BackupZit-a

Podrazumevano konzola uzima ažuriranja iz zvaničnih BackupZit izdanja na GitHub-u (https://github.com/Max-Zit/backupzit/releases). U Podešavanja → Ažuriranja možete umesto toga uneti drugi izvor ažuriranja — svoj HTTPS mirror ili folder na serveru. Bez obzira na izvor, svako izdanje mora da ima ispravan BackupZit potpis. Konzola svakog dana proverava ima li novih izdanja i šalje email administratorima kada se pojavi novo. Za instalaciju kliknite Instaliraj:

  1. Konzola proverava potpis izdanja i kontrolni zbir paketa, i čeka da se ne izvršava nijedan bekap ni vraćanje.
  2. Sistemski servis (backupzit-update, radi kao root) ponovo proverava potpis ključevima za izdanja ugrađenim u BackupZit. Ni kompromitovana konzola ne može da instalira neki drugi paket.
  3. Pravi bekap baze (pg_dump), čuva trenutni program, instalira paket i restartuje konzolu.
  4. Ako nova verzija ne odgovori za dva minuta, prethodni program i baza kakva je bila automatski se vraćaju. Rezultat, sa logom neuspelog pokretanja, prikazuje se na stranici Ažuriranja, upisuje u audit log i šalje emailom.
  5. Posle uspešnog ažuriranja ažuriraju se i agenti: svaki instalira novu verziju kada je slobodan. To možete isključiti na istoj stranici ako agente želite da ažurirate sami.

Konzola je nedostupna oko jedan minut. Bekapi baze i prethodni programi poslednja tri ažuriranja čuvaju se u /var/lib/backupzit-update.

Bez pristupa internetu: fajlove izdanja (manifest.json, manifest.json.sig i serverski paket) preuzmite na drugom računaru. Zatim ih otpremite pod Instaliraj ažuriranje iz fajlova, ili ih kopirajte u folder na serveru i taj folder koristite kao izvor ažuriranja.

I dalje možete da ažurirate menadžerom paketa (apt install ./backupzit-server_….deb); baza se migrira kada se nova verzija pokrene.

Ažuriranja operativnog sistema

Ista stranica (Podešavanja → Ažuriranja) prikazuje operativni sistem servera konzole: koliko je ažuriranja dostupno, koliko su od njih bezbednosne ispravke, da li je potreban restart i da li su uključena automatska bezbednosna ažuriranja. Stanje se osvežava svakog dana, ili dugmetom Proveri sada. Možete:

  • Uključi automatska bezbednosna ažuriranja (preporučeno). Sopstveni alat sistema svakog dana instalira samo bezbednosne ispravke: unattended-upgrades na Debianu i Ubuntuu, dnf-automatic na AlmaLinuxu i Rocky Linuxu.
  • Instaliraj sva ažuriranja sada. Servisi kao PostgreSQL mogu kratko da se restartuju, a konzola se sama ponovo povezuje.
  • Restartuj server, na primer posle ažuriranja kernela. Konzola to odbija dok se izvršavaju bekapi ili vraćanja. Agenti zadržavaju svoje poslove i javljaju rezultate kada se konzola vrati.

Ovi zadaci rade preko istog root servisa kao ažuriranja konzole. Upisuju se u audit log, a izlaz poslednjeg zadatka se prikazuje na stranici.

Bekap same konzole

Bekapi na vašem skladištu ostaju čitljivi i bez konzole, pomoću listova za oporavak. Da biste posle gubitka servera vratili i samu konzolu, uključite Podešavanja → Bekap konzole. To obuhvata poslove, rasporede, agente, korisnike, podešavanja, istoriju pokretanja i sačuvane pristupne podatke. Konzola tada svakog dana pravi svoj bekap na mrežno skladište, u folder backupzit-console.

Bekap konzole sadrži:

  • celu bazu, izvezenu tabelu po tabelu, pa nije potrebna određena verzija pg_dump-a;
  • ključ za tajne koji dešifruje sačuvane pristupne podatke;
  • sertifikat konzole, koji agenti pamte.

Šifrovan je ključem za oporavak skladišta i dedupliciran. Čuvaju se najnoviji bekapi: podrazumevano 14.

Vraćanje konzole

  1. Instalirajte novu konzolu iste ili novije verzije, na primer sa ISO-a uređaja.
  2. Na novom serveru, kao root, pokrenite sledeće. Pristupni podaci su oni sa lista za oporavak skladišta, a adresa repozitorijuma je prikazana na stranici Bekap konzole. 
    systemctl stop backupzit-server
set -a; . /etc/backupzit/server.env; set +a
export BACKUPZIT_PASSWORD='<ključ za oporavak>'
export BACKUPZIT_SFTP_PASSWORD='…' BACKUPZIT_SFTP_HOSTKEY='SHA256:…'   # ili BACKUPZIT_S3_ACCESS_KEY/_SECRET_KEY, _SMB_PASSWORD, _AZURE_KEY, _HARDENED_KEY/_FINGERPRINT
backupzit-server --restore-console --repo 'sftp://backup@nas:22/backups/backupzit-console'
systemctl start backupzit-server
  3. Dajte novom serveru IP adresu ili DNS ime starog servera. Agenti veruju vraćenom sertifikatu i sami se ponovo povezuju.

Vraćanje zamenjuje bazu nove konzole bekapom i podiže bazu na instaliranu verziju. --snapshot ID vraća stariji bekap umesto najnovijeg.

Kopiju listova za oporavak i fajla secrets.key čuvajte i van servera, na primer u menadžeru lozinki.
