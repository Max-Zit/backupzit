Microsoft 365: Exchange Online, OneDrive i SharePoint

BackupZit pravi bekap sandučića (Exchange Online), kalendara, kontakata, OneDrive-a i SharePoint sajtova Microsoft 365 tenanta preko Microsoft Grapha. Samo čita: u tenantu se ništa ne menja niti briše. Podatke preuzima bilo koji agent sa pristupom internetu — na primer agent na mašini konzole — i čuva ih kao svaki bekap: deduplicirane, šifrovane, sa retencijom, poslovima kopiranja i testovima vraćanja.

1. Registracija aplikacije u Microsoft Entra ID

Jednom po tenantu, kao Global Administrator, u Microsoft Entra admin centru:

  1. App registrations → New registration: ime npr. BackupZit, Accounts in this organizational directory only, bez redirect URI-ja. Zapišite Application (client) ID i Directory (tenant) ID sa pregleda aplikacije.
  2. Certificates & secrets → New client secret: izaberite trajanje (npr. 24 meseca) i odmah kopirajte Value tajne — prikazuje se samo jednom. Secret ID nije tajna.
  3. API permissions → Add a permission → Microsoft Graph → Application permissions (ne delegated): User.Read.All, Mail.Read i Files.Read.All; za kalendare i kontakte još Calendars.Read i Contacts.Read, za SharePoint Sites.Read.All.
  4. Kliknite Grant admin consent for …. Do tada status pokazuje Not granted i bekapi se odbijaju.

Ovo su samo dozvole za čitanje. Kasnije vraćanje u sandučiće traži dozvole za pisanje, koje BackupZit ne traži.

Da biste aplikaciju ograničili na neke sandučiće, Exchange administrator može da doda application access policy ili RBAC for Applications scope; nalozi van njega se tada prijavljuju kao nečitljivi.

2. Pravljenje posla

U Poslovi bekapa napravite posao vrste Microsoft 365:

  • Agent: agent koji preuzima (Windows ili Linux, verzija 0.34.0 ili novija; 0.35.0 za kalendare, kontakte i SharePoint). Treba mu HTTPS pristup do login.microsoftonline.com, graph.microsoft.com i, za OneDrive i SharePoint fajlove, *.sharepoint.com.
  • ID direktorijuma (tenanta), ID aplikacije (klijenta) i Tajna klijenta iz koraka 1. Tajna se čuva šifrovana.
  • Šta se čuva: Pošta, OneDrive, Kalendari i kontakti, SharePoint sajtovi — u bilo kojoj kombinaciji.
  • Nalozi: jedna adresa po redu, ili prazno za svaki nalog tenanta koji ima sanduče ili OneDrive — nalozi dodati kasnije uključuju se automatski; nalozi bez licence se preskaču.
  • SharePoint sajtovi: jedna adresa sajta po redu (npr. https://contoso.sharepoint.com/sites/sales), ili prazno za svaki sajt tenanta — sajtovi dodati kasnije uključuju se automatski. Lični sajtovi (OneDrive) se izostavljaju; oni se čuvaju uz naloge. Posao samo za SharePoint ne traži naloge.

Umesto kucanja adresa kliknite Izaberi sa liste: konzola, preko gore unete aplikacije, čita naloge (i označava one bez licence, koji nemaju sanduče ni OneDrive) i SharePoint sajtove tenanta i prikazuje ih za označavanje; označeni popunjavaju polja. Pri izmeni posla koristi se sačuvana tajna.

Kada se posao sačuva, konzola se prijavljuje kao aplikacija i proverava dozvole, naloge i sajtove, pa se pogrešna tajna ili nedostajuća administratorska saglasnost vide odmah. Konzola bez pristupa internetu preskače proveru; tada prvi bekap pokazuje da li radi.

Šta se čuva

  • Pošta: svi folderi pošte sa podfolderima (Inbox, Sent Items, Deleted Items, Archive, vaši folderi…). Svaka poruka se čuva cela, sa prilozima, u MIME formatu kao fajl .eml, nazvan po vremenu prijema i naslovu, npr. 2026-10-07 0621 Ponuda za oktobar [3fa2c1d9e0].eml. Outlook, Thunderbird i većina programa za poštu otvaraju .eml fajlove.
  • OneDrive: svi fajlovi i folderi OneDrive-a naloga, sa vremenom izmene.
  • Kalendari: svaki kalendar naloga; svaki događaj kao iCalendar fajl (.ics) sa vremenom, mestom, opisom, organizatorom, učesnicima, podsetnikom i — za seriju — pravilom ponavljanja, nazvan po početku i naslovu, npr. 2026-10-08 1000 Sastanak uprave [8c1e…].ics. Outlook, Google Calendar i Thunderbird uvoze .ics fajlove. Vremena se čuvaju u UTC-u.
  • Kontakti: kontakti i folderi kontakata naloga, svaki kao vCard (.vcf) sa imenima, email adresama, brojevima telefona, adresama, firmom i beleškama.
  • SharePoint: svaka biblioteka dokumenata svakog sajta (Documents, Site Assets i biblioteke koje ste napravili), sa svim folderima i fajlovima.

Nije uključeno: prilozi događaja u kalendaru, fotografije kontakata, pojedinačno izmenjena ponavljanja serije, SharePoint liste i stranice (samo biblioteke dokumenata), Teams chat-ovi i poruke kanala (Teams fajlovi su na SharePoint-u i čuvaju se sa njim), i deljena sandučad bez korisničkog naloga.

Bekap sadrži po jedan folder za svaki nalog — ana@contoso.com/Mail/Inbox/…, …/OneDrive/…, …/Calendar/Calendar/…, …/Contacts/… — i SharePoint/<sajt>/<biblioteka>/…. Prvi bekap preuzima sve; svaki kasniji bekap ponovo izlistava foldere, ali preuzima samo poruke i fajlove koji su novi ili izmenjeni od prethodnog bekapa (pročitane, označene, premeštene ili izmenjene poruke računaju se kao izmenjene) — nepromenjeni podaci se uzimaju iz prethodnog bekapa. Microsoft ograničava koliko brzo aplikacija sme da čita; BackupZit čeka kada Microsoft to zatraži i nastavlja, pa prvi bekap velikih sandučića može da traje satima.

Bekapi jednog tenanta čuvaju se u sopstvenom repozitorijumu na skladištu (folder m365-<tenant ID>), pa agent koji preuzima može da se zameni bez počinjanja iznova.

Vraćanje

  • Pregledaj fajlove na pokretanju bekapa: otvorite foldere pošte, OneDrive, kalendare ili kontakte naloga, ili SharePoint sajt, označite poruke, događaje, fajlove ili foldere i preuzmite ih (jedan fajl kakav jeste, više kao ZIP) — otvorite .eml fajlove u Outlook-u ili ih prevucite u sanduče.
  • Vrati u folder na bilo kom agentu: poruke se upisuju kao .eml fajlovi, događaji kao .ics, kontakti kao .vcf, a OneDrive i SharePoint fajlovi kakvi su bili, ispod <folder>/<nalog>/… i <folder>/SharePoint/….

Vraćanje direktno u sanduče ili OneDrive je planirano; pisaće samo u nov folder i nikad neće prepisivati niti brisati.

Rešavanje problema

  • AADSTS7000215 / invalid client secret: nije kopiran Value tajne (nego njen ID), ili je istekla — napravite novu i unesite je u posao.
  • missing the application permissions ili Authorization_RequestDenied: dodajte dozvole kao application dozvole i kliknite Grant admin consent.
  • the account has no Exchange Online mailbox: nalog nema Exchange licencu (ili je kontakt); uklonite ga iz posla.
  • Pokretanje sa upozorenjima navodi poruke ili fajlove koji nisu mogli da se pročitaju (npr. OneNote beležnica); ostatak bekapa je potpun.
