Baze podataka: SQL Server, PostgreSQL, MySQL

BackupZit pravi bekap baza alatima samog servera baze, preko agenta na mašini sa bazom: Microsoft SQL Server na Windowsu, PostgreSQL i MySQL/MariaDB na Linuxu. Puni bekapi rade po rasporedu posla; bekapi logova na svakih nekoliko minuta omogućavaju vraćanje jedne baze u bilo koji trenutak — na primer na minut pre pogrešnog DELETE-a.

Pravljenje posla

U Poslovi bekapa napravite posao vrste Baze podataka, na agentu mašine sa bazom, i izaberite:

  • Server baze: Microsoft SQL Server, PostgreSQL ili MySQL/MariaDB. Kasnije ne može da se promeni.
  • Instanca ili port: SQL Server instanca (prazno za podrazumevanu instancu, npr. SQLEXPRESS) ili PostgreSQL port (prazno za 5432). Do MySQL/MariaDB-a se stiže preko lokalnog socketa.
  • Baze podataka: jedno ime po redu, ili prazno za sve korisničke baze — baze napravljene kasnije uključuju se automatski.
  • Bekap logova na svakih … minuta: npr. 15 — transakcioni logovi (SQL Server), arhivirani WAL (PostgreSQL) ili binarni logovi (MySQL). Ostavite prazno ako je dovoljno vraćanje na vreme punog bekapa.
  • Raspored je raspored punih bekapa, npr. svakog dana u 22:00.

Bekapi su deduplicirani — nepromenjeni podaci se ne šalju ponovo — i šifrovani kao svaki bekap. Retencija broji pune bekape; bekapi logova se čuvaju dok postoji puni bekap na koji se nastavljaju. Stranica pokretanja navodi šta svaki bekap sadrži.

Microsoft SQL Server

  1. Instalirajte agenta na Windows mašinu na kojoj radi SQL Server (bilo koje izdanje od 2012, uključujući Express).
  2. Agent radi kao NT AUTHORITY\SYSTEM i povezuje se Windows autentifikacijom. Dajte tom nalogu ulogu sysadmin, jednom po instanci: 
    sqlcmd -S .\SQLEXPRESS -E -Q "ALTER SERVER ROLE sysadmin ADD MEMBER [NT AUTHORITY\SYSTEM]"
  • Svako pokretanje upisuje po jedan fajl bekapa za svaku bazu (BACKUP DATABASE / BACKUP LOG … WITH CHECKSUM) u podrazumevani folder za bekape instance, čuva fajlove i briše ih. Folderu tokom pokretanja treba slobodnog prostora za najveću bazu.
  • Uz uključen bekap logova, puni bekapi započinju lanac logova. Bez njega, puni bekapi se prave kao COPY_ONLY, pa ne ometaju druge planove bekapa ili održavanja.
  • Bekap logova se pravi za baze u modelu oporavka full ili bulk-logged; baze u modelu simple dobijaju samo pune bekape. Označite sistemske baze da biste dodali master, model i msdb.

PostgreSQL

Agent radi kao nalog postgres preko lokalnog socketa — za bekape ništa ne treba podešavati. Puni bekap čuva ceo klaster (pg_basebackup), uloge (pg_dumpall --globals-only) i pg_dump svake baze.

Vraćanje u trenutak (point-in-time recovery) traži arhiviranje WAL-a. Uz uključen bekap logova, prvi puni bekap ga podešava komandom ALTER SYSTEM: archive_mode = on i archive_command koji kopira završene WAL segmente u /var/lib/backupzit-pg/wal; bekapi logova ih tamo čuvaju i brišu. archive_mode počinje da važi posle jednog restarta PostgreSQL-a (systemctl restart postgresql) — pokretanje vam to kaže. Ako neki drugi alat već koristi archive_command, BackupZit ga ne dira i pravi bekap bez vraćanja u trenutak. Ako bekapi logova prestanu (posao onemogućen ili obrisan), ponovo isključite arhiviranje (ALTER SYSTEM RESET archive_mode, restart) da se folder ne bi napunio.

  • Vraćanje baze u stanje iz punog bekapa: iz njenog pg_dump-a u server koji radi, pod novim imenom ili umesto postojeće baze.
  • U određenom trenutku (ili najnovije): agent raspakuje bekap klastera u privremenu instancu na slobodnom portu (samo socket, bez mreže, bez arhiviranja), ponavlja WAL do tog trenutka, iz nje pravi dump baze u server koji radi i uklanja privremenu instancu. Mašini na neko vreme treba slobodnog prostora za klaster.
  • Ceo klaster: vraća se na isti način, kao posebna instanca koja nastavlja da radi na slobodnom portu; pokretanje vam kaže njen port i folder sa podacima (ispod /var/lib/backupzit-pg) i kako da se povežete i da je zaustavite.

MySQL i MariaDB

Agent se povezuje kao root preko lokalnog socketa (socket autentifikacija, podrazumevana na Debianu i Ubuntuu), ili sa pristupnim podacima iz /root/.my.cnf. Puni bekap čuva mysqldump svake baze (konzistentan, sa rutinama, događajima i trigerima) zajedno sa pozicijom binarnog loga kojoj odgovara.

Vraćanje u trenutak traži binarni log. Uključite ga jednom u konfiguraciji servera i restartujte server, npr. /etc/mysql/mariadb.conf.d/60-binlog.cnf:

[mysqld]
server_id = 1
log_bin = /var/log/mysql/mysql-bin
binlog_format = ROW
expire_logs_days = 7

(napravite folder za log, sa nalogom mysql kao vlasnikom). Bekapi logova zatim čuvaju svaki zatvoreni binarni log. Neka sopstveni rok brisanja servera bude duži od intervala bekapa logova; praznina se prijavljuje, a vraćanja ne mogu da je pređu.

  • Vraćanje baze: njen dump se učitava u novu bazu (ili zamenjuje postojeću). U određenom trenutku ili najnovije, izmene te baze zabeležene u binarnim logovima posle dump-a ponavljaju se do tog trenutka — i kada baza dobije novo ime. Ponavljanje se ne upisuje u binarni log servera.
  • Korisnici i prava (sistemska baza mysql) nisu deo dump-ova.

Vraćanje

Otvorite pokretanje punog bekapa (ili koristite čarobnjak za vraćanje → Baza) i izaberite bazu, mašinu na koju se vraća (isti server ili drugi sa istim serverom baze) i:

  • Kao nova baza pod nazivom npr. sales_restored — original ostaje netaknut i redove možete da kopirate nazad — ili pod originalnim nazivom; označite zameni ga da biste prepisali postojeću bazu (njeni korisnici se prvo isključuju).
  • Stanje: stanje iz punog bekapa; najnovije stanje (puni bekap i svaki bekap logova posle njega); ili određeni trenutak između punog bekapa i najnovijeg upotrebljivog bekapa logova, kako tabela prikazuje. Unesite vreme kako ga prikazuje konzola, u vremenskoj zoni servera konzole (vidi Vremenska zona); agent ga pretvara u vremensku zonu servera baze.

Komandna linija

backupzit-agent sql list    [--instance SQLEXPRESS]
backupzit-agent sql backup  --repo ... [--instance I] [--db a,b] [--system] [--log] [--copy-only]
backupzit-agent sql restore --repo ... [--instance I] --db NAME [--as NEW] [--replace] [--at "2026-10-04 14:59:00"] SNAPSHOT|latest
backupzit-agent pg list     [--port 5432]
backupzit-agent pg backup   --repo ... [--port P] [--db a,b] [--pitr | --wal]
backupzit-agent pg restore  --repo ... --db NAME|"(cluster)" [--as NEW] [--replace] [--at TIME | --latest] SNAPSHOT|latest
backupzit-agent mysql list
backupzit-agent mysql backup  --repo ... [--db a,b] [--binlog]
backupzit-agent mysql restore --repo ... --db NAME [--as NEW] [--replace] [--at TIME | --latest] SNAPSHOT|latest

Nije uključeno

  • SQL Server diferencijalni bekapi i Always On availability groups; udaljeni serveri baza — agent pravi bekap servera na svojoj mašini.
  • Vraćanje pojedinačnih tabela: vratite bazu pod novim imenom i kopirajte redove.
