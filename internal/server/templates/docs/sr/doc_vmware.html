VMware ESXi virtuelne mašine

BackupZit pravi bekap virtuelnih mašina VMware ESXi hostova bez instaliranja bilo čega na ESXi ili u virtuelnim mašinama. BackupZit agent na bilo kojoj mašini u mreži radi kao proxy hosta. Pravi snimke, čita samo promenjene blokove virtuelnih diskova i upisuje ih na vaše skladište.

Zahtevi

  • ESXi 6.7, 7 ili 8 povezan direktno, ili vCenter Server 7 ili 8 sa svojim ESXi hostovima (vidi vCenter Server).
  • Korisnik sa administratorskim pravima na hostu, obično root.
  • SSH uključen na hostovima sa besplatnom licencom: Host → Actions → Services → Enable Secure Shell. Besplatna ESXi licenca drži API samo za čitanje, pa snimci i vraćanja idu preko SSH-a. Licencirani hostovi se menjaju preko vSphere API-ja i ne treba im SSH.
  • Proxy agent: bilo koji Windows ili Linux agent koji dolazi do hosta na portu 443 (i 22 kada se koristi SSH). Podaci bekapa prolaze kroz njega, pa ga postavite na brzu mrežu blizu hosta i skladišta.
  • Slobodan prostor na datastore-u VM-a dok se pravi bekap VM-a koja radi. BackupZit tamo na trenutak kopira disk (vidi dole). Kopija je thin, pa joj treba onoliko prostora koliko disk zaista koristi. Uz hot-add kopija se ne pravi.

Dodavanje hosta

  1. Otvorite Agenti → VMware ESXi hostovi → Dodavanje ESXi hosta ili vCenter Server-a.
  2. Unesite adresu, korisnika, lozinku i proxy agenta.
  3. Konzola se jednom povezuje da ih proveri. Čita listu virtuelnih mašina i licencu, i pamti HTTPS sertifikat i SSH ključ hosta. Ako se host kasnije zameni drugom mašinom sa istom adresom, BackupZit odbija da se poveže umesto da joj pošalje lozinku. Ako se sertifikat promeni iz poznatog razloga — host je ponovo instaliran, dobio je novi sertifikat ili je dodat u vCenter (koji zameni sertifikate svojih hostova) — na strani Agenti host prikazuje novi otisak i dugme Prihvati novi sertifikat. Pre prihvatanja uporedite otisak sa onim na hostu. Od verzije 0.62 konzola prikazuje otiske sertifikata i SSH ključa hosta pre nego što pošalje lozinku (i preko proxy agenta 0.62 ili novijeg, koji ih čita za nju), a povezuje se tek kada ih potvrdite.

Lozinka se čuva šifrovana, kao i sve druge tajne. Sama konzola se povezuje na host (HTTPS 443, a uz besplatnu licencu i SSH 22) kada se doda, na Osveži i svakih 10 minuta da osveži listu virtuelnih mašina, osim ako se do hosta stiže preko proxy agenta. Ukloni briše host zajedno sa njegovim poslovima bekapa; bekapi ostaju na skladištu. Tabela prikazuje režim svakog hosta:

  • vSphere API (licenciran host, SSH nije potreban): snimci, kopije diskova, vraćanja i instant recovery idu preko API-ja.
  • vCenter Server (vSphere API): vCenter sa svojim ESXi hostovima; sve ide preko vCenter API-ja.
  • besplatna licenca: snimci i vraćanja preko SSH-a: API hosta je samo za čitanje, pa ovi koraci idu preko SSH-a.
  • SSH (izabrano za ovaj host): host se menja preko SSH-a iako bi njegov API to mogao (Uvek SSH pri dodavanju hosta).

Preko proxy agenta (agent 0.56 ili noviji): pri dodavanju hosta označite Poveži preko proxy agenta, ili Poveži preko proxy-ja u njegovom redu, i konzola se nikad sama ne povezuje na host. Proxy agent proverava adresu i lozinku, čita listu VM-ova, verziju i licencu i javlja HTTPS sertifikat i SSH ključ hosta koje je video; konzola ih pamti pri prvom povezivanju, kao i kod direktne veze, a od tada proxy agent odbija host koji pokaže drugi sertifikat (red hosta tada nudi Prihvati novi sertifikat). Osveži i lista VM-ova na svakih 10 minuta takođe dolaze od proxy agenta; te provere se ne prikazuju u Aktivnosti. Samo proxy agent mora da dopre do hosta, baš kao za bekape i vraćanja, pa konzola može da bude u drugoj mreži, iza NAT-a ili u adresnom opsegu koji se preklapa. Pogrešna adresa ili lozinka prikazuje se kao greška hosta posle prve provere proxy agenta: uklonite host i dodajte ga ponovo. Dok je proxy agent offline ili zauzet, ostaje poslednja lista VM-ova.

Sa Automatski konzola sama bira, pa host koji kasnije dobije licencu prelazi na API bez dodatnog podešavanja. Kako se host menja u redu hosta (i pri dodavanju) može da nametne Uvek SSH ili Uvek vSphere API; promena se odmah proverava. Raniji bekapi i njihove tačke vraćanja ne zavise od načina.

vCenter Server

vCenter Server dodajte kao host: njegovu adresu, administrator@vsphere.local (ili korisnika sa ulogom Administrator) i proxy agenta. BackupZit tada kroz tu jednu vezu vidi VM-ove svih ESXi hostova i klastera datacentra; ništa se ne menja preko SSH-a i nije potrebna lozinka nijednog hosta.

  • VM premešten vMotion-om na drugi host i dalje se bekapuje: VM-ovi se prepoznaju po instance UUID-u, ne po hostu.
  • Pri vraćanju možete izabrati ESXi host na kome VM radi (podrazumevano: host originalne VM) i datastore.
  • Instant recovery pokreće VM na izabranom hostu; Završi ga premešta na datastore pomoću Storage vMotion-a dok radi, bez prekida.
  • vCenter sa više datacentara još ne može da se doda; hostove ostalih datacentara dodajte direktno.

Isti ESXi host nemojte dodati i direktno i preko vCenter-a: svaka veza ima svoj repozitorijum, pa bi se njegovi VM-ovi bekapovali dva puta. Ako se host koji BackupZit bekapuje direktno kasnije doda u vCenter, prihvatite njegov novi sertifikat na strani Agenti; njegovi poslovi nastavljaju da rade — vCenter VM-ovima napravljenim na samostalnom hostu dodeli novi ID, a BackupZit pri sledećem osvežavanju prebaci poslove na njega.

Poslovi bekapa

U Poslovi bekapa izaberite ESXi host (naveden pod VMware ESXi hostovi u listi agenata) i Virtuelne mašine. Čuvajte sve virtuelne mašine hosta (virtuelne mašine napravljene kasnije uključuju se automatski) ili označite pojedinačne. Posao radi na proxy agentu hosta. Ako promenite proxy, postojeći poslovi ga prate.

Da biste izostavili pojedine VM, npr. VM BackupZit konzole, izaberite Sve VM (i kontejneri) na hostu osim označenih i označite ih.

Kako se pravi bekap VM-a

  1. Changed block tracking (CBT) se uključuje za VM ako je isključen.
    • Na licenciranim hostovima to se dešava automatski.
    • Na besplatnim hostovima CBT može da se uključi samo dok je VM ugašena. BackupZit to radi pri prvom bekapu koji zatekne VM ugašenu. Do tada svaki bekap čita cele diskove, a pokretanje prikazuje upozorenje.
  2. Pravi se snimak backupzit_…. Kada u gostu rade VMware Tools, snimak je quiesced: aplikacije i fajl-sistemi prvo upisuju svoje podatke, pa je bekap konzistentan na nivou aplikacija. Bez VMware Tools-a konzistentan je kao posle nestanka struje. Instalirajte open-vm-tools u Linux virtuelne mašine i VMware Tools u Windows virtuelne mašine. Za gosta kod kog quiescing ne uspeva ili ne radi kako treba, uključite u poslu Crash-consistent snimci (bez quiescing-a preko VMware Tools-a): njegovi bekapi su tada crash-consistent, kao posle nestanka struje (agent 0.58). Na nekim hostovima (ESXi 6.7) disk quiesced snimka je mala delta koju je upisao sam quiescing; agent je čita zajedno sa snimkom (agent 0.58; stariji agenti su je odbijali kao delta disk snimka).
  3. CBT javlja koje blokove treba čitati:
    • za prvi bekap, samo blokove u upotrebi;
    • posle toga, samo blokove promenjene od prethodnog bekapa.
  4. VM koja radi drži svoje diskove zaključane. Zato se njeni diskovi kopiraju na datastore-u (thin), a snimak se odmah uklanja, obično posle nekoliko sekundi. Kopija se zatim čita preko HTTPS-a i briše. Ugašene virtuelne mašine se čitaju direktno. Uz hot-add se diskovi virtuelnih mašina koje rade umesto toga čitaju preko sopstvene virtuelne mašine proxy-ja, bez kopije.
  5. Konfiguracija VM-a (.vmx) i NVRAM se čuvaju uz bekap.

Primer iz test laboratorije: Debian VM sa diskom od 8 GB, od čega je 1,6 GB u upotrebi. Prvi bekap je pročitao 1,6 GB. Sledeći, posle 50 MB novih podataka, pročitao je 70 MB i trajao 23 sekunde.

Hot-add: bez kopije na datastore-u

Kopiranje diskova VM-a koja radi košta vreme i I/O na produkcionom datastore-u pri svakom bekapu, i inkrementalnom, i traži slobodan prostor za zauzete blokove diskova. Kod velikih virtuelnih mašina na sporim diskovima to je bitno. Uz Hot-add (Agenti → VMware ESXi hostovi, polje za potvrdu ispod proxy agenta) proxy ih umesto toga čita na licu mesta:

  • Uslovi: proxy je Linux agent u virtuelnoj mašini koja vidi datastore-ove te VM (na istom hostu ili na hostu istog vCenter-a sa pristupom njima), a host se menja preko vSphere API-ja (vCenter ili licencirani host). Proxy pronalazi svoju virtuelnu mašinu po njenom BIOS UUID-u.
  • Kako: dok snimak postoji, svaki disk se kači na virtuelnu mašinu proxy-ja kao independent-nonpersistent. Proxy ga otvara samo za čitanje; sve što bi se u njega upisalo išlo bi u redo log koji vSphere odbacuje kada se disk otkači, pa se disk VM-a nikada ne menja. Proxy čita samo blokove koje prijavi CBT, otkači disk, a zatim se snimak uklanja.
  • Šta se štedi: nema privremene kopije ni dodatnog prostora na datastore-u. Inkrementalni bekap VM-a od 2 TB sa 20 GB promena čita 20 GB. Snimak ostaje dok se diskovi čitaju (umesto samo za vreme kopiranja), pa VM upisuje u snimak nešto duže.
  • Rezervna varijanta: ako proxy nije virtuelna mašina tog hosta, ili kačenje ili čitanje diska ne uspe, taj disk se kopira na datastore-u kao ranije, a pokretanje prikazuje upozorenje sa razlogom. Hot-add je podrazumevano isključen; agenti pre 0.54 ga ignorišu. Stranica pokretanja pokazuje koliko je diskova pročitano preko hot-add-a.
  • Na proxy virtuelnoj mašini: sprečite da LVM aktivira volumene okačenih diskova pomoću LVM-ovog devices fajla (use_devicesfile = 1 u /etc/lvm/lvm.conf, sa sopstvenim diskovima proxy-ja upisanim pomoću lvmdevices). Volumeni koje LVM ipak aktivira uklanjaju se pre nego što se disk otkači. Ne kačite ručno diskove drugih virtuelnih mašina na proxy: independent-nonpersistent disk iz foldera druge VM smatra se diskom koji je ostavio prekinuti bekap, i otkači se.

Više proxy agenata (vCenter)

Jedan proxy agent čita diskove jedan za drugim, a preko hot-add samo na hostovima čije datastore-e vidi. Uz vCenter vezu dodajte Linux agenta u VM-u na svakom ESXi hostu kao dodatni proxy agent (Agenti → VMware ESXi hostovi, Dodatni proxy agenti ispod proxy agenta; agenti 0.55 ili noviji):

  • Podela po hostu: svaki bekap posla se deli. Svaki VM ide proxy agentu na ESXi hostu na kome radi (prema poslednjoj listi VM-ova), svaki drugi VM proxy agentu veze. Svaki proxy agent bekapuje svoj deo kao zaseban rad, istovremeno sa ostalima, preko hot-add na svom hostu. Učestvuju samo proxy agenti koji su na mreži: VM-ovi ugašenog proxy agenta idu proxy agentu veze. Prvi bekap u novi repozitorijum i bekapi na lokalni ili USB cilj se ne dele.
  • Jedno pokretanje: posao prikazuje delove jednog pokretanja kao celinu: radi dok radi neki deo, neuspešan ako je neki deo pao. RPO upozorenja i kontrolna tabla računaju bekap tek kad su svi delovi uspeli; posao u lancu ili kopija „posle svakog bekapa“ kreće jednom, posle poslednjeg dela.
  • Bez preklapanja: bekapi i vraćanja veze na različitim proxy agentima ne rade istovremeno (istovremeno rade samo delovi jednog pokretanja), pa VM premešten između hostova nikad ne obrađuju dva proxy agenta odjednom.
  • Zadržavanje po proxy agentu: svaki deo čuva podešeni broj bekapa svojih VM-ova, a poslovi kopiranja ih takođe kopiraju i čuvaju po delovima. Bekapi od pre podele posla i bekapi uklonjenog proxy agenta ostaju kakvi jesu: i dalje su tačke vraćanja svojih VM-ova. VM premešten na drugi host (vMotion) od sledećeg osvežavanja liste VM-ova ide proxy agentu tog hosta.
  • Host proxy agenta BackupZit nalazi po BIOS UUID-u koji njegov agent javlja; stranica Agenti ga prikazuje pored svakog agenta. ESXi host nije pronađen: agent nije VM ovog vCenter-a, ili je lista VM-ova starija od agenta (kliknite Osveži).

Otkazivanje VMware bekapa (Aktivnost → Otkaži) zaustavlja i kopiranje diska koje je u toku na datastore-u i briše nepotpunu kopiju; snimak se uklanja kao posle svakog bekapa. Na snimak koji se još pravi u trenutku otkazivanja čeka se (do pet minuta), pa se i on uklanja.

Snimci koji zaostanu. Proxy agent beleži svaki snimak i privremenu kopiju diska pre nego što ih napravi, a zapis briše tek kada vidi da objekta više nema: posle uklanjanja ponovo izlista snimke VM-a, pokušava do tri puta tokom desetak minuta, ponovo se prijavljuje kada se vSphere sesija završila (i pre svakog VM-a, pa jedna izgubljena sesija ne obara VM-ove posle nje) i konsoliduje diskove kada vSphere javi da im je to potrebno; VM bez snimaka čijim diskovima posle ranijeg uklanjanja još treba konsolidacija konsoliduje se pre svog sledećeg bekapa. Ako agent stane usred posla (pad, nestanak struje) ili uklanjanje stalno ne uspeva, zapis ostaje:

  • Konzola stavlja u red pokretanje čišćenja na proxy agentu (samo on ima pristupne podatke hosta), a proxy agent takve ostatke uklanja i posle svakog bekapa veze. VM-ovi na kojima upravo radi bekap ili vraćanje proxy agenta ostaju netaknuti. Zapis koji agent prijavi za vezu čiji nije proxy (na primer raniji proxy) prikazuje se bez pokretanja čišćenja; snimak se tada pojavljuje iz liste VM-ova, kako je opisano ispod.
  • Kontrolna tabla navodi svaki ostatak pod Zahteva pažnju (VM, od kada, zašto) sa Ukloni sada, a za svaki ostatak koji ostane jednom se šalje obaveštenje (email, chat).
  • Konzola takođe traži snimke backupzit_… starije od šest sati u listi VM-ova koju osvežava na svakih 10 minuta, dok nijedan bekap veze ne radi, pa se pojavljuju i ostaci starijih agenata. Uklanjaju se isključivo snimci nazvani backupzit_…; sopstveni snimci VM-a se nikad ne diraju. Zapis o VM-u koji nedostaje u listi VM-ova (njegov datastore nije dostupan, premešten je na drugi host) ostaje na proxy agentu sedam dana, tako da se njegov snimak ipak ukloni kada se VM vrati (agenti 0.63 i noviji).

Vraćanje VM-a

Koristite čarobnjak za vraćanje (Cela virtuelna mašina) ili stranicu bekapa u Aktivnosti. Izaberite:

  • Kao nova VM pored originala: kopija sa novim imenom, UUID-om i MAC adresama. Podrazumevano ime je ime originala uz -restored- i datum. Mrežna podešavanja gosta vezana za stare MAC adrese, kao netplan match: macaddress u cloud slikama, ne važe za kopiju.
  • Umesto originalne VM: uz isključi ga i zameni mu diskove, BackupZit:
    • gasi VM i briše njene snimke;
    • preimenuje trenutne diskove u ….replaced-DATUM.vmdk (obrišite ih kada vraćena VM proradi);
    • upisuje bekap u nove diskove sa originalnim imenima, i postavlja CPU i memoriju kao u bekapu.
    VM zadržava UUID, mrežne adaptere i MAC adrese. Ako je VM obrisana, ponovo se pravi sa svojim originalnim identitetom.
  • ESXi host i datastore: drugi host, ili drugi datastore istog hosta.
  • Pokreni VM posle vraćanja.

Diskovi se vraćaju kao thin, a upisuju se samo blokovi sa podacima. ISO slike koje su bile povezane na CD/DVD uređaje nisu deo bekapa, pa ti uređaji ostaju prazni.

Instant recovery

Izaberite Odmah, pokrenut iz bekapa da biste pokrenuli VM za nekoliko sekundi, bez prethodnog kopiranja diskova. Proxy agent hosta — mora da bude Linux agent — servira diskove VM-a direktno iz bekapa preko NFS-a; host to montira kao datastore backupzit-<agent> i pokreće VM sa njega. Izmene koje VM napravi čuvaju se na agentu (/var/lib/backupzit/instant-esxi, pa mu treba slobodnog prostora za njih); sam bekap se nikad ne menja, a retencija ga čuva dok VM radi iz njega. Ako originalna VM i dalje postoji, instant VM dobija nov UUID i nove MAC adrese.

Na stranici pokretanja, kada VM radi kako treba:

  • Završi je kopira na datastore hosta: VM se gasi (preko VMware Tools-a ako rade), njeni diskovi se kopiraju kao thin (preko API-ja na licenciranim hostovima, pomoću vmkfstools preko SSH-a na besplatnoj licenci), registruje se sa datastore-a i ponovo pokreće. Samostalan host nema Storage vMotion, pa ovo traži kratak prekid koji raste sa veličinom diska. Ako kopiranje ne uspe, VM nastavlja da radi iz bekapa.
  • Odbaci VM zaustavlja i briše VM sa svim njenim izmenama.

Agent odgovara na NFS na portu 2049 (i registruje ga u rpcbind-u mašine na portu 111, ili sam odgovara na portu 111) samo za adresu ESXi hosta; otvorite ove portove od hosta ka agentu ako je između njih firewall. Kada se poslednja instant VM završi ili odbaci, datastore se uklanja, a NFS server zaustavlja.

Pojedinačni fajlovi

Pregledaj fajlove na stranici bekapa (ili Fajlovi iz virtuelne mašine u čarobnjaku za vraćanje) otvara diskove VM-a. Možete da pregledate NTFS, ext2/3/4, XFS i btrfs, i na LVM-u, i da preuzmete fajlove ili ih vratite na bilo kog agenta.

Komandna linija

Ove komande rade na bilo kom agentu. ESXi lozinku postavite u BACKUPZIT_VMWARE_PASSWORD:

backupzit-agent vmware list    --host 192.168.1.20 [--user root]
backupzit-agent vmware backup  --host … --repo … [--vmid N,N]
backupzit-agent vmware restore --host … --repo … --vmid N [--new] [--name NAME] [--datastore DS] [--overwrite] [--start] SNAPSHOT|latest

vmware list prikazuje otiske sertifikata i SSH ključa hosta. Prosledite ih sa --thumbprint i --ssh-host-key da biste ih zapamtili i u komandnoj liniji.

Još nije uključeno

  • vCenter sa više datacentara. Može da se doda samo vCenter sa jednim datacentrom; hostove ostalih dodajte direktno.
  • Virtuelne mašine sa sopstvenim snimcima. Njihovi diskovi su delte; prvo obrišite ili konsolidujte snimke. (Mala delta koju upisuje quiesced snimak pripada samom bekapu i čita se zajedno s njim.)
  • Neke vrste diskova. Raw device mappings (RDM) i nezavisni diskovi.
  • Instant recovery preko Windows proxy agenta. Instant recovery traži Linux proxy agenta.
