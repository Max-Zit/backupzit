Macchine virtuali VMware ESXi

BackupZit esegue il backup delle macchine virtuali degli host VMware ESXi senza installare nulla su ESXi o nelle VM. Un agente BackupZit su una qualsiasi macchina della rete fa da proxy per l'host. Crea snapshot, legge solo i blocchi modificati dei dischi virtuali e li scrive sul tuo storage.

Requisiti

  • ESXi 6.7, 7 o 8 collegato direttamente, oppure vCenter Server 7 o 8 con i suoi host ESXi (vedi vCenter Server).
  • Un utente con diritti di amministratore sull'host, di solito root.
  • SSH attivato sugli host con licenza gratuita: Host → Actions → Services → Enable Secure Shell. La licenza ESXi gratuita rende l'API di sola lettura, quindi snapshot e ripristini passano tramite SSH. Gli host con licenza vengono modificati tramite l'API vSphere e non hanno bisogno di SSH.
  • Un agente proxy: qualsiasi agente Windows o Linux che raggiunga l'host sulla porta 443 (e sulla 22 quando si usa SSH). I dati di backup passano attraverso di esso, quindi mettilo su una rete veloce vicino all'host e allo storage.
  • Spazio libero sul datastore della VM mentre si esegue il backup di una VM accesa. BackupZit vi copia il disco per un momento (vedi sotto). La copia è thin, quindi richiede tanto spazio quanto il disco usa davvero. Con l'hot-add non viene fatta alcuna copia.

Aggiungere un host

  1. Apri Agenti → Host VMware ESXi → Aggiungi un host ESXi o vCenter Server.
  2. Inserisci indirizzo, utente, password e agente proxy.
  3. La console si collega una volta per verificarli. Legge l'elenco delle VM e la licenza e fissa il certificato HTTPS e la chiave host SSH dell'host. Se in seguito l'host viene sostituito da un'altra macchina con lo stesso indirizzo, BackupZit rifiuta la connessione invece di inviarle la password. Se il certificato cambia per un motivo noto — l'host è stato reinstallato, ha ricevuto un nuovo certificato o è stato aggiunto a vCenter (che sostituisce i certificati dei suoi host) — l'host mostra la nuova impronta con un pulsante Accetta il nuovo certificato nella pagina Agenti. Confronta l'impronta con quella dell'host prima di accettarla.

La password è memorizzata cifrata, come tutti gli altri segreti. È la console stessa a collegarsi all'host (HTTPS 443, e SSH 22 con la licenza gratuita) quando viene aggiunto, con Aggiorna e ogni 10 minuti per aggiornare l'elenco delle VM. Rimuovi elimina l'host insieme ai suoi job di backup; i backup restano sullo storage. La tabella mostra la modalità di ogni host:

  • API vSphere (host con licenza, SSH non necessario): snapshot, copie dei dischi, ripristini e ripristino istantaneo passano tramite l'API.
  • vCenter Server (API vSphere): un vCenter con i suoi host ESXi; tutto passa tramite l'API di vCenter.
  • licenza gratuita: snapshot e ripristini tramite SSH: l'API dell'host è di sola lettura, quindi questi passaggi passano tramite SSH.
  • SSH (scelto per questo host): l'host viene modificato tramite SSH anche se la sua API potrebbe farlo (Sempre SSH quando si aggiunge l'host).

Con Automatico la console sceglie da sola, quindi un host che ottiene una licenza in seguito passa all'API senza altre impostazioni. Come viene modificato l'host, nella riga dell'host (e quando lo si aggiunge), può imporre Sempre SSH o Sempre l'API vSphere; la modifica viene verificata subito. I backup precedenti e i loro punti di ripristino non dipendono dal metodo.

vCenter Server

Aggiungi un vCenter Server come un host: il suo indirizzo, administrator@vsphere.local (o un utente con il ruolo Administrator) e un agente proxy. BackupZit vede allora le VM di tutti gli host ESXi e cluster del datacenter tramite questa unica connessione; nulla viene modificato via SSH e non serve la password di alcun host.

  • Una VM spostata su un altro host con vMotion continua a essere salvata: le VM sono riconosciute dal loro UUID di istanza, non dall'host.
  • Un ripristino può scegliere l'host ESXi che esegue la VM (predefinito: l'host della VM originale) e il datastore.
  • Il ripristino istantaneo avvia la VM sull'host scelto; Completa la sposta su un datastore con Storage vMotion mentre continua a funzionare, senza fermo.
  • Un vCenter con più datacenter non può ancora essere aggiunto; aggiungi direttamente gli host degli altri datacenter.

Non aggiungere lo stesso host ESXi sia direttamente sia tramite vCenter: ogni connessione ha il proprio repository, quindi le sue VM verrebbero salvate due volte. Se un host di cui BackupZit esegue il backup direttamente viene poi aggiunto a vCenter, accetta il suo nuovo certificato nella pagina Agenti; i suoi job continuano a funzionare: vCenter assegna un nuovo ID alle VM create sull'host autonomo e BackupZit sposta i job su di esso al successivo aggiornamento.

Job di backup

In Job di backup, scegli l'host ESXi (elencato sotto Host VMware ESXi nell'elenco degli agenti) e Macchine virtuali. Esegui il backup di tutte le VM dell'host (le VM create in seguito sono incluse automaticamente) o selezionane alcune. Il job viene eseguito sull'agente proxy dell'host. Se cambi il proxy, i job esistenti lo seguono.

Per escludere singole VM, ad es. la VM della console BackupZit, scegliere Tutte le VM (e i container) dell’host tranne quelle selezionate e selezionarle.

Come viene salvata una VM

  1. Il Changed Block Tracking (CBT) viene attivato per la VM se è disattivato.
    • Sugli host con licenza avviene automaticamente.
    • Sugli host gratuiti il CBT si può attivare solo a VM spenta. BackupZit lo fa al primo backup che trova la VM spenta. Fino ad allora ogni backup legge i dischi interi e l'esecuzione mostra un avviso.
  2. Viene creato uno snapshot backupzit_…. Quando nel guest girano i VMware Tools, lo snapshot è quiesced: applicazioni e file system vengono prima svuotati, rendendo il backup coerente a livello applicativo. Senza VMware Tools è crash-consistent. Installa open-vm-tools nelle VM Linux e VMware Tools nelle VM Windows.
  3. Il CBT indica quali blocchi leggere:
    • per il primo backup, solo i blocchi in uso;
    • in seguito, solo i blocchi modificati dal backup precedente.
  4. Una VM accesa tiene bloccati i suoi dischi. I suoi dischi vengono quindi copiati sul datastore (thin) e lo snapshot viene rimosso subito, di solito dopo pochi secondi. La copia viene poi letta via HTTPS ed eliminata. Le VM spente vengono lette direttamente. Con l'hot-add i dischi delle VM accese vengono invece letti tramite la VM del proxy stesso, senza copia.
  5. La configurazione della VM (.vmx) e la NVRAM vengono salvate con il backup.

Esempio dal laboratorio di test: una VM Debian con un disco da 8 GB, di cui 1,6 GB in uso. Il primo backup ha letto 1,6 GB. Il successivo, dopo 50 MB di nuovi dati, ha letto 70 MB e ha richiesto 23 secondi.

Hot-add: nessuna copia sul datastore

Copiare i dischi di una VM accesa costa tempo e I/O sul datastore di produzione a ogni backup, anche a quelli incrementali, e richiede spazio libero per i blocchi usati dei dischi. Con VM grandi su dischi lenti la differenza si sente. Con Hot-add (Agenti → Host VMware ESXi, la casella sotto l'agente proxy) il proxy li legge invece direttamente dove si trovano:

  • Requisiti: il proxy è un agente Linux in una VM che vede i datastore della VM (sullo stesso host, o su un host dello stesso vCenter con accesso a essi), e l'host viene modificato tramite l'API vSphere (vCenter o un host con licenza). Il proxy trova la propria VM tramite il suo BIOS UUID.
  • Come: finché esiste lo snapshot, ogni disco viene collegato alla VM del proxy come independent-nonpersistent. Il proxy lo apre in sola lettura; qualsiasi scrittura finirebbe in un redo log che vSphere scarta quando il disco viene scollegato, quindi il disco della VM non viene mai modificato. Il proxy legge solo i blocchi indicati dal CBT, scollega il disco e poi lo snapshot viene rimosso.
  • Cosa si risparmia: nessuna copia temporanea e nessuno spazio aggiuntivo sul datastore. Un backup incrementale di una VM da 2 TB con 20 GB di modifiche legge 20 GB. Lo snapshot resta finché i dischi vengono letti (invece che solo per la copia), quindi la VM scrive nello snapshot un po' più a lungo.
  • Soluzione di riserva: se il proxy non è una VM dell'host, o se il collegamento o la lettura di un disco non riesce, quel disco viene copiato sul datastore come prima e l'esecuzione mostra un avviso con il motivo. Hot-add è disattivato per impostazione predefinita; gli agenti precedenti alla 0.54 lo ignorano. La pagina dell'esecuzione mostra quanti dischi sono stati letti tramite hot-add.
  • Sulla VM del proxy: impedisci a LVM di attivare i volumi dei dischi collegati, con il file dei dispositivi di LVM (use_devicesfile = 1 in /etc/lvm/lvm.conf, con i dischi del proxy stesso registrati tramite lvmdevices). I volumi che LVM attiva comunque vengono rimossi prima che il disco venga scollegato. Non collegare a mano al proxy dischi di altre VM: un disco independent-nonpersistent dalla cartella di un'altra VM viene scambiato per uno lasciato da un backup interrotto, e scollegato.

Più agenti proxy (vCenter)

Un agente proxy legge un disco dopo l'altro, e tramite hot-add solo sugli host di cui vede i datastore. Con una connessione vCenter, aggiungi un agente Linux in una VM su ogni host ESXi come agente proxy aggiuntivo (Agenti → Host VMware ESXi, Agenti proxy aggiuntivi sotto l'agente proxy; agenti 0.55 o successivi):

  • Suddivisione per host: ogni backup del job viene suddiviso. Ogni VM va all'agente proxy sull'host ESXi su cui gira (secondo l'ultimo elenco delle VM), ogni altra VM all'agente proxy della connessione. Ogni agente proxy salva la sua parte in un'esecuzione propria, insieme agli altri, tramite hot-add sul proprio host. Partecipano solo gli agenti proxy online: le VM di un agente proxy spento vanno all'agente proxy della connessione. Il primo backup in un nuovo repository e i backup verso una destinazione locale o USB non vengono suddivisi.
  • Un avvio: il job mostra le parti di un avvio come un tutt'uno: in esecuzione finché una parte è in corso, non riuscito se una parte non è riuscita. Gli avvisi RPO e la dashboard contano un backup solo quando tutte le parti sono riuscite; un job concatenato o una copia «dopo ogni backup» parte una volta sola, dopo l'ultima parte.
  • Nessuna sovrapposizione: backup e ripristini della connessione su agenti proxy diversi non girano contemporaneamente (solo le parti di uno stesso avvio), quindi una VM spostata tra host non viene mai gestita da due agenti proxy insieme.
  • Conservazione per agente proxy: ogni parte conserva il numero di backup del job per le sue VM, e anche i job di copia le copiano e le conservano per parte. I backup di prima della suddivisione del job e quelli di un agente proxy rimosso restano come sono: rimangono punti di ripristino delle loro VM. Una VM spostata su un altro host (vMotion) passa all'agente proxy di quell'host dal successivo aggiornamento dell'elenco delle VM.
  • BackupZit trova l'host di un agente proxy tramite il BIOS UUID che il suo agente segnala; la pagina Agenti lo mostra accanto a ogni agente. Host ESXi non trovato: l'agente non è una VM di questo vCenter, oppure l'elenco delle VM è più vecchio dell'agente (fai clic su Aggiorna).

Annullare un backup VMware (Attività → Annulla) ferma anche una copia del disco in corso sul datastore ed elimina la copia parziale; lo snapshot viene rimosso come dopo ogni backup.

Ripristinare una VM

Usa la procedura guidata di ripristino (Intera macchina virtuale) o la pagina del backup in Attività. Scegli:

  • Come nuova VM accanto all'originale: una copia con nuovo nome, UUID e indirizzi MAC. Il nome predefinito è quello dell'originale più -restored- e la data. Le impostazioni di rete del guest legate ai vecchi indirizzi MAC, come netplan match: macaddress nelle immagini cloud, non si applicano alla copia.
  • Al posto della VM originale: con spegnila e sostituisci i suoi dischi, BackupZit:
    • spegne la VM ed elimina i suoi snapshot;
    • rinomina i dischi attuali in ….replaced-DATE.vmdk (eliminali quando la VM ripristinata funziona);
    • scrive il backup in nuovi dischi con i nomi originali e imposta CPU e memoria come nel backup.
    La VM mantiene UUID, schede di rete e indirizzi MAC. Se la VM era stata eliminata, viene ricreata con la sua identità originale.
  • Host ESXi e datastore: un altro host, o un altro datastore dello stesso host.
  • Avvia la VM dopo il ripristino.

I dischi vengono ripristinati thin e si scrivono solo i blocchi con dati. Le immagini ISO collegate alle unità CD/DVD non fanno parte del backup, quindi quelle unità restano vuote.

Ripristino istantaneo

Scegli Subito, in esecuzione dal backup per avviare una VM in pochi secondi, senza prima copiarne i dischi. L'agente proxy dell'host — deve essere un agente Linux — fornisce i dischi della VM direttamente dal backup tramite NFS; l'host li monta come datastore backupzit-<agent> ed esegue la VM da lì. Le modifiche fatte dalla VM vengono conservate sull'agente (/var/lib/backupzit/instant-esxi, che deve quindi avere spazio libero); il backup in sé non viene mai modificato e la conservazione lo mantiene finché la VM gira da esso. Se la VM originale esiste ancora, la VM istantanea riceve un nuovo UUID e nuovi indirizzi MAC.

Nella pagina dell'esecuzione, quando la VM funziona come deve:

  • Completa la copia su un datastore dell'host: la VM viene spenta (tramite VMware Tools se presenti), i suoi dischi vengono copiati thin (tramite l'API sugli host con licenza, con vmkfstools via SSH con la licenza gratuita), viene registrata dal datastore e riavviata. Un host autonomo non ha Storage vMotion, quindi serve un breve fermo che cresce con la dimensione dei dischi. Se la copia non riesce, la VM continua a girare dal backup.
  • Scarta arresta ed elimina la VM con tutte le sue modifiche.

L'agente risponde in NFS sulla porta 2049 (e lo registra presso il rpcbind della macchina sulla porta 111, o risponde lui stesso sulla porta 111) solo per l'indirizzo dell'host ESXi; apri queste porte dall'host all'agente se c'è un firewall in mezzo. Quando l'ultima VM istantanea viene completata o scartata, il datastore viene rimosso e il server NFS si arresta.

Singoli file

Sfoglia file nella pagina del backup (o File da una macchina virtuale nella procedura guidata di ripristino) apre i dischi della VM. Puoi sfogliare NTFS, ext2/3/4 e XFS, anche su LVM, e scaricare file o ripristinarli su qualsiasi agente.

Riga di comando

Questi comandi girano su qualsiasi agente. Imposta la password ESXi in BACKUPZIT_VMWARE_PASSWORD:

backupzit-agent vmware list    --host 192.168.1.20 [--user root]
backupzit-agent vmware backup  --host … --repo … [--vmid N,N]
backupzit-agent vmware restore --host … --repo … --vmid N [--new] [--name NAME] [--datastore DS] [--overwrite] [--start] SNAPSHOT|latest

vmware list mostra le impronte del certificato e della chiave SSH dell'host. Passale con --thumbprint e --ssh-host-key per fissarle anche da riga di comando.

Non ancora incluso

  • vCenter con più datacenter. Si può aggiungere solo un vCenter con un datacenter; aggiungi direttamente gli host degli altri.
  • VM con snapshot propri. I loro dischi sono delta; elimina o consolida prima gli snapshot.
  • Alcuni tipi di disco. Raw device mapping (RDM) e dischi indipendenti.
  • Ripristino istantaneo tramite un agente proxy Windows. Il ripristino istantaneo richiede un agente proxy Linux.
