Macchine virtuali VMware ESXi

BackupZit esegue il backup delle macchine virtuali degli host VMware ESXi senza installare nulla su ESXi o nelle VM. Un agente BackupZit su una qualsiasi macchina della rete fa da proxy per l'host. Crea snapshot, legge solo i blocchi modificati dei dischi virtuali e li scrive sul tuo storage.

Requisiti

  • ESXi 6.7, 7 o 8, collegato direttamente. Gli host gestiti da vCenter si aggiungono uno per uno con il proprio indirizzo; vCenter stesso non è ancora supportato.
  • Un utente con diritti di amministratore sull'host, di solito root.
  • SSH attivato sull'host: Host → Actions → Services → Enable Secure Shell. I ripristini ne hanno sempre bisogno. Gli host con la licenza ESXi gratuita ne hanno bisogno anche per gli snapshot, perché la loro API è di sola lettura.
  • Un agente proxy: qualsiasi agente Windows o Linux che raggiunga l'host sulle porte 443 e 22. I dati di backup passano attraverso di esso, quindi mettilo su una rete veloce vicino all'host e allo storage.
  • Spazio libero sul datastore della VM mentre si esegue il backup di una VM accesa. BackupZit vi copia il disco per un momento (vedi sotto). La copia è thin, quindi richiede tanto spazio quanto il disco usa davvero.

Aggiungere un host

  1. Apri Agenti → Host VMware ESXi → Aggiungi un host ESXi.
  2. Inserisci indirizzo, utente, password e agente proxy.
  3. La console si collega una volta per verificarli. Legge l'elenco delle VM e la licenza e fissa il certificato HTTPS e la chiave host SSH dell'host. Se in seguito l'host viene sostituito da un'altra macchina con lo stesso indirizzo, BackupZit rifiuta la connessione invece di inviarle la password.

La password è memorizzata cifrata, come tutti gli altri segreti. L'elenco delle VM viene aggiornato ogni 10 minuti, o subito con Aggiorna. La tabella mostra la modalità di ogni host:

  • vSphere API: host con licenza.
  • Licenza gratuita: snapshot e ripristini passano tramite SSH.

Job di backup

In Job di backup, scegli l'host ESXi (elencato sotto Host VMware ESXi nell'elenco degli agenti) e Macchine virtuali. Esegui il backup di tutte le VM dell'host (le VM create in seguito sono incluse automaticamente) o selezionane alcune. Il job viene eseguito sull'agente proxy dell'host. Se cambi il proxy, i job esistenti lo seguono.

Come viene salvata una VM

  1. Il Changed Block Tracking (CBT) viene attivato per la VM se è disattivato.
    • Sugli host con licenza avviene automaticamente.
    • Sugli host gratuiti il CBT si può attivare solo a VM spenta. BackupZit lo fa al primo backup che trova la VM spenta. Fino ad allora ogni backup legge i dischi interi e l'esecuzione mostra un avviso.
  2. Viene creato uno snapshot backupzit_…. Quando nel guest girano i VMware Tools, lo snapshot è quiesced: applicazioni e file system vengono prima svuotati, rendendo il backup coerente a livello applicativo. Senza VMware Tools è crash-consistent. Installa open-vm-tools nelle VM Linux e VMware Tools nelle VM Windows.
  3. Il CBT indica quali blocchi leggere:
    • per il primo backup, solo i blocchi in uso;
    • in seguito, solo i blocchi modificati dal backup precedente.
  4. Una VM accesa tiene bloccati i suoi dischi. I suoi dischi vengono quindi copiati sul datastore (thin) e lo snapshot viene rimosso subito, di solito dopo pochi secondi. La copia viene poi letta via HTTPS ed eliminata. Le VM spente vengono lette direttamente.
  5. La configurazione della VM (.vmx) e la NVRAM vengono salvate con il backup.

Esempio dal laboratorio di test: una VM Debian con un disco da 8 GB, di cui 1,6 GB in uso. Il primo backup ha letto 1,6 GB. Il successivo, dopo 50 MB di nuovi dati, ha letto 70 MB e ha richiesto 23 secondi.

Ripristinare una VM

Usa la procedura guidata di ripristino (Intera macchina virtuale) o la pagina del backup in Attività. Scegli:

  • Come nuova VM accanto all'originale: una copia con nuovo nome, UUID e indirizzi MAC. Il nome predefinito è quello dell'originale più -restored- e la data. Le impostazioni di rete del guest legate ai vecchi indirizzi MAC, come netplan match: macaddress nelle immagini cloud, non si applicano alla copia.
  • Al posto della VM originale: con spegnila e sostituisci i suoi dischi, BackupZit:
    • spegne la VM ed elimina i suoi snapshot;
    • rinomina i dischi attuali in ….replaced-DATE.vmdk (eliminali quando la VM ripristinata funziona);
    • scrive il backup in nuovi dischi con i nomi originali e imposta CPU e memoria come nel backup.
    La VM mantiene UUID, schede di rete e indirizzi MAC. Se la VM era stata eliminata, viene ricreata con la sua identità originale.
  • Host ESXi e datastore: un altro host, o un altro datastore dello stesso host.
  • Avvia la VM dopo il ripristino.

I dischi vengono ripristinati thin e si scrivono solo i blocchi con dati. Le immagini ISO collegate alle unità CD/DVD non fanno parte del backup, quindi quelle unità restano vuote.

Ripristino istantaneo

Scegli Subito, in esecuzione dal backup per avviare una VM in pochi secondi, senza prima copiarne i dischi. L'agente proxy dell'host — deve essere un agente Linux — fornisce i dischi della VM direttamente dal backup tramite NFS; l'host li monta come datastore backupzit-<agent> ed esegue la VM da lì. Le modifiche fatte dalla VM vengono conservate sull'agente (/var/lib/backupzit/instant-esxi, che deve quindi avere spazio libero); il backup in sé non viene mai modificato e la conservazione lo mantiene finché la VM gira da esso. Se la VM originale esiste ancora, la VM istantanea riceve un nuovo UUID e nuovi indirizzi MAC.

Nella pagina dell'esecuzione, quando la VM funziona come deve:

  • Completa la copia su un datastore dell'host: la VM viene spenta (tramite VMware Tools se presenti), i suoi dischi vengono copiati thin con vmkfstools, viene registrata dal datastore e riavviata. La licenza ESXi gratuita non ha Storage vMotion, quindi serve un breve fermo che cresce con la dimensione dei dischi. Se la copia non riesce, la VM continua a girare dal backup.
  • Scarta arresta ed elimina la VM con tutte le sue modifiche.

L'agente risponde in NFS sulla porta 2049 (e lo registra presso il rpcbind della macchina sulla porta 111, o risponde lui stesso sulla porta 111) solo per l'indirizzo dell'host ESXi; apri queste porte dall'host all'agente se c'è un firewall in mezzo. Quando l'ultima VM istantanea viene completata o scartata, il datastore viene rimosso e il server NFS si arresta.

Singoli file

Sfoglia file nella pagina del backup (o File da una macchina virtuale nella procedura guidata di ripristino) apre i dischi della VM. Puoi sfogliare NTFS, ext2/3/4 e XFS, anche su LVM, e scaricare file o ripristinarli su qualsiasi agente.

Riga di comando

Questi comandi girano su qualsiasi agente. Imposta la password ESXi in BACKUPZIT_VMWARE_PASSWORD:

backupzit-agent vmware list    --host 192.168.1.20 [--user root]
backupzit-agent vmware backup  --host … --repo … [--vmid N,N]
backupzit-agent vmware restore --host … --repo … --vmid N [--new] [--name NAME] [--datastore DS] [--overwrite] [--start] SNAPSHOT|latest

vmware list mostra le impronte del certificato e della chiave SSH dell'host. Passale con --thumbprint e --ssh-host-key per fissarle anche da riga di comando.

Non ancora incluso

  • vCenter. Aggiungi ogni host ESXi direttamente.
  • VM con snapshot propri. I loro dischi sono delta; elimina o consolida prima gli snapshot.
  • Alcuni tipi di disco. Raw device mapping (RDM) e dischi indipendenti.
  • Ripristino istantaneo tramite un agente proxy Windows. Il ripristino istantaneo richiede un agente proxy Linux.
