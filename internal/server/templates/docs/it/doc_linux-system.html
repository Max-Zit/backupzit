Backup del sistema Linux e P2V

Un job Sistema Linux esegue il backup di un'intera macchina Linux, così da poterla ricreare su un disco vuoto — la stessa macchina dopo un guasto al disco, nuovo hardware o una macchina virtuale in Proxmox VE (da fisico a virtuale, P2V).

Cosa viene salvato

  • Ogni file system locale (ext2/3/4, xfs, vfat), anche su LVM, file per file con proprietari, permessi, bit setuid, ACL, attributi estesi (etichette SELinux, capability dei file), hard link e file di dispositivo. Ogni file system viene salvato separatamente; le condivisioni di rete e i file system virtuali (/proc, /sys, /run) vengono saltati.
  • Il layout dei dischi: tabelle delle partizioni GPT o MBR con i loro ID, gruppi di volumi LVM (vgcfgbackup), UUID, etichette e caratteristiche dei file system, e il codice di avvio (MBR e la partizione di avvio BIOS di GRUB).

Come Relax-and-Recover, BackupZit non copia il disco in uso blocco per blocco: Linux non ha uno snapshot integrato di un disco in funzione, quindi una copia grezza sarebbe incoerente. Ogni file viene letto per intero e il layout rende di nuovo avviabile il disco ripristinato. I database vanno esportati prima del backup o salvati con i loro strumenti.

Singoli file e cartelle si ripristinano da un backup di sistema come da qualsiasi backup di file (Ripristina file da questo backup nella pagina dell'esecuzione).

Non ancora supportato

Dischi cifrati (LUKS), RAID software (mdadm), btrfs e sistemi distribuiti su più dischi. Il job li segnala chiaramente invece di creare un backup incompleto.

Ripristinare l'intero sistema

Apri l'esecuzione del backup di sistema (pagina del job o Attività) e usa Ripristina l’intero sistema:

Come nuova VM Proxmox

Scegli il nodo Proxmox (il suo agente BackupZit esegue il lavoro), lo storage, l'ID della VM, il nome, la memoria e i core. BackupZit crea la VM con lo stesso firmware dell'originale (UEFI/OVMF o BIOS), un disco e una scheda di rete VirtIO SCSI, ricrea il disco, ripristina tutti i file e può avviare la VM. Poiché la VM è una copia che può girare accanto all'originale:

  • le impostazioni di rete legate ai vecchi indirizzi MAC (comuni nelle immagini cloud: netplan match: macaddress) vengono modificate per valere su qualsiasi interfaccia cablata,
  • l'agente BackupZit nella copia viene deregistrato, così non si presenta come la macchina originale.

Su un disco

Ripristina su un disco vuoto di un agente Linux, ad es. un secondo disco (/dev/sdb), oppure sulla nuova macchina stessa (bare metal):

  1. In Ripristino scarica la ISO di ripristino Linux e crea un codice di ripristino. Scrivi la ISO su una chiavetta USB (Rufus, balenaEtcher) o collegala a una VM. Si avvia su macchine BIOS e UEFI.
  2. Avvia la macchina da essa. Il sistema di ripristino avvia l'agente, che si collega alla console con backupzit/recovery.json presente su un'altra chiavetta USB o un altro disco, oppure chiede l'indirizzo del server e il codice di ripristino.
  3. La macchina compare come agente di ripristino. Nell'esecuzione del backup di sistema scegli Su un disco, quell'agente e il suo disco (di solito /dev/sda, /dev/nvme0n1 o /dev/vda).

Va bene anche qualsiasi sistema Linux live: avvia lì l'agente con sudo backupzit-agent recovery --server https://console:8443 --token CODE; gli strumenti necessari (gdisk, LVM, mkfs) vengono indicati se mancano. Seleziona Hardware diverso quando la macchina non è quella originale.

La destinazione può essere più grande o più piccola del disco originale: l'ultima partizione si espande per riempirla, o si riduce finché i suoi dati ci stanno. Gli UUID dei file system e gli ID delle partizioni restano uguali, quindi /etc/fstab e il boot loader non richiedono modifiche. Sui sistemi UEFI il boot loader viene installato anche nel percorso per supporti rimovibili \EFI\BOOT\BOOTX64.EFI, che ogni firmware UEFI avvia senza voce di avvio. I sistemi simili a RHEL (dracut) ricevono un nuovo initramfs con tutti i driver quando vengono spostati su hardware diverso.

Riga di comando

backupzit-agent system-backup  --repo ... [--exclude PATTERN]
backupzit-agent system-show    --repo ... latest
backupzit-agent system-restore --repo ... --target /dev/sdb [--new-hardware] --yes-erase-target latest
