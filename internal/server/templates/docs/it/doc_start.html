Per iniziare

BackupZit protegge macchine Windows e Linux, macchine virtuali Proxmox VE, Hyper-V e VMware ESXi, database (SQL Server, PostgreSQL, MySQL/MariaDB) e condivisioni NAS — file, dischi interi e sistemi interi — da un'unica console web che gira nella vostra rete.

Come funziona BackupZit

  • Console di gestione (questa applicazione web) — gira su un server Linux nella vostra rete. Memorizza la configurazione, pianifica i job, raccoglie i risultati e mostra i report. Non deve mai essere raggiungibile da Internet.
  • Agenti — un piccolo servizio su ogni macchina protetta (MSI Windows, deb/rpm Linux) e sugli host Proxmox e Hyper-V; gli host VMware ESXi vengono raggiunti tramite un agente che fa da proxy. Gli agenti contattano la console via HTTPS, ricevono i job e inviano i dati di backup direttamente allo storage. Su Windows l'agente mostra il suo stato accanto all'orologio.
  • Destinazioni di archiviazione — dove vengono conservati i backup: SFTP, object storage compatibile S3 (AWS, Wasabi, Backblaze B2, MinIO, Google Cloud…), Azure Blob Storage, una condivisione SMB/NAS, dischi USB a rotazione, un disco locale o montato, o un repository protetto BackupZit.

I dati di backup non passano mai dalla console. La console si limita a coordinare, quindi può girare su una piccola macchina virtuale.

Primi passi

Per configurare una nuova console, importate l'immagine dell'appliance pronta in una piccola VM, avviate la ISO dell'appliance o eseguite lo script di installazione su un server Linux esistente; vedete Installare il server.

  1. Aggiungete una destinazione di archiviazione in Archiviazione. Lasciate attivo Cifra i backup e conservate in un luogo sicuro il foglio di ripristino mostrato subito dopo. Vedete Destinazioni di archiviazione.
  2. Installate gli agenti: in Agenti fate clic su Crea token di registrazione, scaricate l'installer dalla stessa pagina e incollate il codice di registrazione quando l'installer Windows lo chiede (Linux: backupzit-agent enroll --code …). Per le VM installate l'agente sull'host Proxmox o Hyper-V; aggiungete gli host VMware ESXi in Agenti → Host VMware ESXi. Vedete Agenti.
  3. Create un job di backup in Job di backup: scegliete l'agente, lo storage, cosa salvare (file, una condivisione NAS, un'immagine disco, database, l'intero sistema Linux o le VM di un host Proxmox, Hyper-V o VMware ESXi), quando eseguirlo e quanti backup conservare. Vedete Job di backup e pianificazioni.
  4. Eseguitelo una volta manualmente con Esegui backup ora nella pagina del job e controllate il risultato in Attività.
  5. Provate un ripristino — un backup vale quanto il suo ripristino. I test di ripristino automatici vengono eseguiti ogni settimana; ripristinate anche una volta qualcosa a mano con la procedura guidata di ripristino. Vedete Ripristino.
  6. Preparatevi ai disastri: scaricate le ISO di ripristino e create un codice di ripristino in Supporti di ripristino.
  7. Configurate gli avvisi via email in Impostazioni → Notifiche e-mail per essere informati degli errori, e facoltativamente un report settimanale.

Lingua

La console è disponibile in 14 lingue: inglese, tedesco, francese, spagnolo, italiano, portoghese (Brasile), olandese, polacco, ceco, serbo (alfabeto latino), turco, russo, cinese (semplificato) e giapponese. Sceglietene una nell'elenco delle lingue in alto a destra o nella pagina di accesso; la scelta viene ricordata nel browser. Senza una scelta decide la lingua del browser (i browser croati, bosniaci e montenegrini ottengono il serbo, quelli slovacchi il ceco, le altre lingue l'inglese). Anche questa guida è tradotta (una pagina senza traduzione viene mostrata in inglese). Email, notifiche chat e messaggi inviati dagli agenti restano in inglese.

Le traduzioni si trovano nel codice sorgente, in internal/server/i18n/it.json: il testo inglese è la chiave, la traduzione il suo valore. go run ./tools/i18n missing it elenca i testi senza traduzione; i testi non tradotti vengono mostrati in inglese.

Concetti chiave

Snapshot e deduplicazione

Ogni backup crea uno snapshot: un'immagine completa e consultabile dei dati in quel momento. I file vengono suddivisi in frammenti di dimensione variabile e i dischi in blocchi, e ogni pezzo viene memorizzato una sola volta, così il secondo backup e i successivi caricano solo ciò che è cambiato — eppure ogni snapshot può essere ripristinato da solo. Non c'è alcuna «catena completo/incrementale» da gestire.

Repository

Ogni agente scrive nel proprio repository sotto la posizione della destinazione di archiviazione (<location>/<hostname>_<id>). Un repository è autonomo: con la posizione, le credenziali dello storage e la chiave di ripristino può essere ripristinato anche se la console non c'è più.

Conservazione

Ogni job conserva un certo numero di backup recenti, giornalieri, settimanali e mensili. Gli snapshot più vecchi vengono rimossi dopo ogni esecuzione e lo spazio che occupavano viene liberato.

Cosa controlla BackupZit per voi

  • Test di ripristino — il backup più recente di ogni job viene parzialmente ripristinato e verificato ogni settimana (Ripristino).
  • Rilevamento ransomware — i backup insoliti (modifiche di massa, dati cifrati, eliminazioni di massa, salti improvvisi del volume di dati) vengono segnalati e la conservazione viene sospesa (Protezione dal ransomware).
  • Avvisi e report — email per gli errori e un riepilogo giornaliero; report pianificati per la direzione (Notifiche e-mail, Monitoraggio).
