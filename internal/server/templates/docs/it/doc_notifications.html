Notifiche: e-mail, Slack, Teams, webhook

Ricevi un'e-mail quando un backup non riesce e un riepilogo giornaliero ogni mattina.

Configurare l'e-mail

In Impostazioni → Notifiche e-mail:

CampoEsempio
Server SMTP / portasmtp.office365.com / 587, smtp.gmail.com / 587, relay interno / 25
SicurezzaSTARTTLS (porta 587), TLS (porta 465) o nessuna (solo relay interno)
Utente / passwordLa casella usata per l'invio; lascia vuoto per un relay anonimo. Microsoft 365 e Gmail richiedono una password per le app.
Mittentebackup@example.com
DestinatariUno o più indirizzi, separati da virgole.

Usa Invia e-mail di test per verificare le impostazioni.

Cosa viene inviato

  • Errori (consigliato) — un'e-mail per ogni esecuzione non riuscita con il motivo: backup, copie, ripristini e test di ripristino non riusciti. Con questa opzione ricevi anche un avviso SUSPICIOUS quando un backup sembra ransomware o una cancellazione di massa.
  • Avvisi — esecuzioni in cui alcuni file non sono stati letti.
  • Successi — ogni esecuzione riuscita (di solito troppo; meglio il report giornaliero).
  • Report giornaliero — all'ora scelta: esecuzioni delle ultime 24 ore, problemi e agenti offline. L'oggetto inizia con OK, WARNINGS o ATTENTION, così le regole di posta possono smistarli.

Per riepiloghi settimanali o mensili usa i report pianificati; vengono inviati con le stesse impostazioni di posta e hanno destinatari propri. Gli oggetti iniziano con [BackupZit], così le regole di posta possono smistarli. La password SMTP è memorizzata cifrata.

Slack, Microsoft Teams e webhook

In Impostazioni → Chat e webhook aggiungi quanti canali vuoi; ognuno sceglie se ricevere errori, avvisi e successi. I backup insoliti (possibile ransomware) contano come errori. Invia test verifica subito un canale.

  • Slack: crea un incoming webhook per il canale (impostazioni dell'app Slack → Incoming Webhooks) e incolla il suo URL (https://hooks.slack.com/services/…).
  • Microsoft Teams: nel canale aggiungi il flusso di lavoro Post to a channel when a webhook request is received e incolla il suo URL. I messaggi arrivano come schede con un pulsante che apre l'esecuzione nella console.
  • Webhook: qualsiasi URL che accetta un POST JSON — sistema di ticket, monitoraggio o strumento di automazione. Con un segreto di firma, ogni richiesta porta X-BackupZit-Signature: sha256=<hex>, l'HMAC-SHA256 del corpo, così il destinatario può verificare che provenga dalla tua console.

Il JSON di un webhook:

{"event": "run.finished", "run_id": 412, "kind": "vm-backup", "kind_title": "VM backup",
 "status": "failed", "suspicious": "", "job": "Proxmox VMs", "job_id": 7, "agent": "pve1",
 "message": "…", "errors": ["…"], "started_at": "2026-10-04T22:00:03+02:00",
 "finished_at": "2026-10-04T22:04:41+02:00", "url": "https://backup.example/runs/412"}

I messaggi vengono inviati una volta per esecuzione, anche quando l'e-mail è disattivata. Un canale che non funziona (URL errato, servizio non disponibile) viene annotato nel log della console e non blocca gli altri. Gli URL dei webhook sono memorizzati cifrati.
