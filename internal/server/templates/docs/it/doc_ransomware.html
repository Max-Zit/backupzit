Protezione dal ransomware

Gli aggressori cercano di cancellare o cifrare i backup prima di cifrare i dati di produzione. BackupZit offre archiviazione in cui i backup non possono essere distrutti, nemmeno con credenziali rubate.

I livelli di protezione

LivelloProtegge da
Cifratura (AES-256)Lettura o manomissione dei backup sull'archiviazione. Ogni modifica viene rilevata.
S3 immutabile (Object Lock, modalità compliance)Cancellazione o sovrascrittura dei backup — da parte di un aggressore con le chiavi, di un amministratore infedele o per errore.
Repository protettoLo stesso, sul tuo server Linux: i file si scrivono una sola volta e ricevono il flag di immutabilità del file system.
Copia fuori sedeIncendio, furto, perdita totale della sede.
Approvazione a quattro occhi (facoltativa)Un account della console rubato o usato male che elimina job e destinazioni di archiviazione o accorcia la conservazione: un secondo utente deve approvare. Vedi Utenti, ruoli e LDAP.

Rilevamento automatico dei backup sospetti

Ogni backup viene confrontato con la cronologia recente del suo job. Viene contrassegnato come sospetto quando mostra tracce di ransomware o di cancellazione di massa:

  • molti più file modificati del solito (ad es. 95 % invece del solito 1 %),
  • i nuovi dati non si comprimono più — i file cifrati sembrano dati casuali,
  • il numero di file è calato improvvisamente di un terzo o più,
  • un salto improvviso nella quantità di nuovi dati (anche per immagini disco, sistemi Linux e VM).

BackupZit invia allora un'e-mail di avviso (con le notifiche di errore attive), mostra il backup nella dashboard tra i backup sospetti da esaminare e sospende la conservazione del job: nessun backup più vecchio viene eliminato, così gli ultimi backup puliti restano ripristinabili anche se continuano ad arrivare backup danneggiati. Dopo aver controllato la macchina, fai clic su Verificato — riprendi la conservazione nella pagina del job.

S3 immutabile con Object Lock

  1. Crea un bucket con Object Lock attivato (AWS, Wasabi, Backblaze B2, MinIO: mc mb --with-lock).
  2. Aggiungi una regola di lifecycle che elimini le versioni non correnti (noncurrent versions) dopo 1 giorno (MinIO: mc ilm rule add --noncurrent-expire-days 1 --expire-delete-marker).
  3. Aggiungi la destinazione S3 e seleziona Backup immutabili per N giorni. Scegli N almeno pari alla conservazione più lunga che vuoi proteggere, ad es. 30.

Ogni punto di ripristino resta bloccato per almeno N giorni dalla sua creazione; i dati condivisi con backup più recenti vengono prorogati automaticamente.

Repository protetto

Un server Linux dedicato che esegue backupzit-repo:

  • Agenti e console possono solo aggiungere file; i file esistenti non vengono mai sovrascritti.
  • Ogni file riceve l'attributo chattr +i per il periodo impostato su quel server. Nemmeno root può eliminarlo senza prima rimuovere il flag.
  • Le cancellazioni dai client si limitano a nascondere i file fino alla fine del loro periodo.
  • Il servizio gira come utente non privilegiato; il suo unico privilegio è impostare il flag di immutabilità.
apt install ./backupzit-repo_*.deb
vi /etc/backupzit-repo/repo.env        # BACKUPZIT_REPO_LOCK_DAYS=30
systemctl start backupzit-repo
backupzit-repo add-key office-console
backupzit-repo fingerprint

Dopo la configurazione disattiva SSH e ogni altro accesso remoto sul server del repository e proteggi l'accesso alla sua console locale / iDRAC / iLO / hypervisor. La protezione è forte quanto l'account root di quella macchina.

Ripristino dopo un attacco

Se un aggressore ha eliminato o sovrascritto dei backup, leggi l'archiviazione com'era prima dell'attacco — è in sola lettura e non modifica nulla:

backupzit-agent snapshots --repo <repository> --as-of 2026-10-01T14:30
backupzit-agent restore   --repo <repository> --as-of 2026-10-01T14:30 --target D:\Restore latest

Su un repository protetto l'amministratore può anche far riapparire i file nascosti, così i backup proseguono normalmente:

backupzit-repo status
backupzit-repo undelete --since 2026-10-01T14:00

Raccomandazioni

  • Usa per l'archiviazione un account separato che non faccia parte del tuo dominio Windows.
  • Mantieni almeno una copia immutabile (S3 Object Lock o repository protetto).
  • Conserva le schede di ripristino offline (stampate, in una cassaforte).
  • Attiva gli avvisi e-mail — un cambiamento improvviso negli errori o nel volume di dati inviati è spesso il primo segno di un attacco.
