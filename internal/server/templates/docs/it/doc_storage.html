Destinazioni di archiviazione

Una destinazione di archiviazione è il luogo in cui gli agenti scrivono i loro backup. Ogni agente usa il proprio repository sotto la posizione della destinazione.

Regola 3-2-1: conservate 3 copie dei dati, su 2 supporti diversi, di cui 1 fuori sede — ad esempio un job verso un NAS locale e un altro verso S3 o un repository protetto in un altro edificio.

Verificare la connessione

Quando si aggiunge una destinazione di archiviazione, la console la verifica subito con le credenziali inserite: scrive un piccolo file, lo rilegge e lo rimuove. Su archiviazione immutabile (S3 con Object Lock, repository protetto) si limita ad accedere ed elencare, così da non lasciare nulla di bloccato; per S3 verifica anche che il bucket abbia Object Lock quando è richiesta l'immutabilità. La destinazione viene salvata in ogni caso e il risultato viene mostrato: una password, chiave host, bucket o condivisione errati emergono subito e non al primo backup. Verifica connessione nella pagina Archiviazione ripete il test. La console esegue il test dalla propria rete; i backup li scrivono gli agenti, quindi una destinazione raggiungibile solo dagli agenti (un disco locale o USB) viene verificata dal primo backup.

SFTP

Posizione: sftp://user@host:22/path (usate /~/path per un percorso relativo alla home dell'utente). Inserite una password o una chiave privata, e l'impronta della chiave host del server, che ottenete sul server con:

ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub

Create un utente dedicato che possa scrivere solo nella cartella dei backup.

Compatibile S3

Inserite l'endpoint (ad es. s3.eu-central-1.amazonaws.com, s3.wasabisys.com, 10.0.0.5:9000), il bucket, una cartella facoltativa e una chiave di accesso con lettura/scrittura su quel bucket. Selezionate HTTP in chiaro solo per un MinIO locale senza certificato.

Backup immutabili (Object Lock)

Create il bucket con Object Lock abilitato e selezionate Backup immutabili … per N giorni. Ogni file scritto dagli agenti viene bloccato in modalità compliance per N giorni (+1 giorno di margine): nessuno — né un attaccante con le chiavi, né il proprietario del bucket — può eliminarlo o sovrascriverlo prima. Dopo ogni backup il blocco dei dati riutilizzati da backup precedenti viene esteso, così ogni punto di ripristino resta protetto per l'intero periodo.

L'eliminazione (dalla conservazione o da un attaccante) aggiunge solo un «marcatore di eliminazione». Aggiungete una regola del ciclo di vita che faccia scadere le versioni non correnti dopo un giorno, così lo spazio si libera quando i blocchi terminano. Vedete Protezione dal ransomware.

Google Cloud Storage

Google Cloud Storage funziona come destinazione compatibile S3 tramite la sua API di interoperabilità:

  1. Nella console Google Cloud aprite Cloud Storage → Settings → Interoperability e create una chiave HMAC per un account di servizio con il ruolo Storage Object Admin sul bucket.
  2. Aggiungete una destinazione S3 con endpoint storage.googleapis.com, il nome del bucket, la chiave di accesso e il segreto HMAC e la regione auto.

L'opzione S3 Object Lock non è disponibile su Google Cloud Storage; per l'immutabilità impostate un criterio di conservazione del bucket (e bloccatelo) in Google Cloud. I backup eliminati restano quindi fino alla fine del periodo di conservazione.

Azure Blob Storage

  1. Nel portale Azure create un account di archiviazione (StorageV2, qualsiasi ridondanza) e un contenitore, ad es. backups.
  2. Aggiungete una destinazione Azure Blob Storage con nome dell'account, contenitore e cartella facoltativa.
  3. Autenticatevi con una chiave di accesso (Account di archiviazione → Chiavi di accesso) o, in modo più restrittivo, con un token SAS per il contenitore con permessi di lettura, scrittura, eliminazione ed elenco e una scadenza adeguata.

Per la protezione dal ransomware abilitate sul contenitore l'immutabilità a livello di versione con un criterio di conservazione basato sul tempo; i backup eliminati o sovrascritti restano così recuperabili per quel periodo. Il campo endpoint in Avanzate serve solo per Azure Government/China, Azure Stack Hub o l'emulatore Azurite.

Dischi USB a rotazione

Dischi scollegati e portati fuori sede sono la protezione più semplice contro ransomware, incendi e furti per i piccoli uffici. BackupZit trova il disco tramite la sua etichetta di volume, qualunque sia la lettera di unità assegnata da Windows:

  1. Formattate due o più dischi in NTFS (Linux: ext4) e chiamateli BZBACKUP1, BZBACKUP2, … (Windows: clic destro sull'unità → Proprietà → nome).
  2. Aggiungete una destinazione di archiviazione di tipo Dischi USB / rimovibili a rotazione con l'etichetta BZBACKUP*.
  3. Create un job di backup verso di essa — o meglio un job di copia di backup che copia un job su NAS o cloud sul disco.
  4. Scambiate i dischi regolarmente (ad es. ogni settimana) e conservate quello scollegato in un luogo sicuro.
  • Ogni disco contiene un backup completo e indipendente con la propria conservazione; tutti i dischi sono cifrati con la chiave di ripristino della destinazione.
  • L'esecuzione mostra quale disco è stato usato (Disco BZBACKUP2). Un ripristino chiede esattamente quel disco e vi dice quale è collegato.
  • Se non è collegato alcun disco, l'esecuzione fallisce con un messaggio chiaro e un avviso — un promemoria per ricollegare il disco.
  • Collegate un solo disco alla volta.

Condivisione SMB

Server, condivisione, cartella facoltativa, utente, password e (per gli account di dominio) il dominio. Gli agenti si connettono da soli con queste credenziali, quindi funziona anche per i servizi eseguiti come SYSTEM.

Repository protetto

Installate il pacchetto backupzit-repo su un server Linux dedicato, poi su quel server:

backupzit-repo add-key office-console     # shows the access key once
backupzit-repo fingerprint                # certificate fingerprint

Inserite nella console l'indirizzo del server, la chiave di accesso e l'impronta. Il periodo di immutabilità si configura sul server del repository (/etc/backupzit-repo/repo.env) e non può essere modificato dalla console né dagli agenti. Dettagli in Protezione dal ransomware.

Cifratura e chiave di ripristino

Con Cifra i backup (impostazione predefinita), tutto ciò che è nel repository — contenuto e nomi dei file, struttura delle cartelle, elenchi degli snapshot — viene cifrato con AES-256-GCM prima di lasciare l'agente. Il fornitore dello storage vede solo dati casuali.

Quando create una destinazione cifrata, la console mostra una chiave di ripristino e offre un foglio di ripristino da scaricare.

Stampate il foglio di ripristino o conservatelo in un gestore di password, separato dai backup. Se la console va persa, la chiave di ripristino più la posizione e le credenziali dello storage sono tutto ciò che serve per ripristinare. Senza la chiave nessuno può leggere i backup cifrati — nemmeno il supporto BackupZit.

Potete mostrare di nuovo la chiave in seguito con Chiave di ripristino nell'elenco degli storage; l'operazione viene registrata.

L'elenco degli storage

L'elenco mostra per ogni destinazione tipo, posizione, cifratura (con accesso alla chiave di ripristino per gli amministratori) e immutabilità: il periodo di Object Lock per S3, o impostata sul server repository per i repository protetti. Le credenziali non vengono mai più mostrate dopo il salvataggio e sono archiviate cifrate. Solo gli amministratori possono aggiungere o rimuovere destinazioni e vedere le chiavi di ripristino.

Utilizzo dell'archiviazione e previsione

Dopo ogni backup (e la relativa conservazione) l'agente riporta quanto spazio occupa il suo repository e — per dischi locali e USB, server SFTP (estensione statvfs di OpenSSH) e condivisioni SMB — la dimensione e lo spazio libero dello storage. In Archiviazione → Utilizzo dell'archiviazione ogni destinazione mostra:

  • lo spazio usato da tutti i repository al suo interno (uno per agente; per i dischi USB a rotazione conta ogni disco);
  • per uno storage di dimensione nota, quanto è pieno (giallo dal 75 %, rosso dal 90 %), con la capacità come linea rossa tratteggiata nel grafico;
  • un grafico degli ultimi 90 giorni e, dopo una settimana di backup, la crescita giornaliera (trend lineare degli ultimi 30 giorni), tracciata 30 giorni in avanti come linea tratteggiata, e quando lo storage sarà pieno — oppure, senza dimensione nota, l'utilizzo previsto tra 90 giorni.

Richiede attenzione nella dashboard avvisa quando una destinazione è piena al 90 % o lo sarà entro 30 giorni. S3 e Azure non hanno una dimensione fissa; lì vengono mostrati solo lo spazio usato e la sua crescita. Lo spazio usato corrisponde ai dati archiviati (compressi, cifrati, deduplicati); i file che lo storage conserva per altri motivi (versioni degli oggetti, altri programmi) non vengono contati.

Rimuovere una destinazione

Rimuovere una destinazione di archiviazione dalla console non elimina alcun dato sullo storage. Con l'approvazione a quattro occhi attiva, un secondo utente deve prima approvare.
