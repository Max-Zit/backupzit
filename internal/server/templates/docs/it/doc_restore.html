Ripristino

Ogni backup riuscito può essere ripristinato: per intero o solo alcune cartelle, sulla stessa macchina, su un altro agente o come nuova macchina virtuale.

La procedura guidata di ripristino

Fate clic su Ripristina nel menu. La procedura pone quattro domande:

  1. Cosa volete ripristinare?
    • un'intera macchina virtuale
    • file da una macchina virtuale
    • file e cartelle
    • un'immagine disco / bare metal
    • file da un'immagine disco
    • un database (a un momento preciso)
    • un intero sistema Linux
    • posta di Microsoft 365 e OneDrive (vedete Microsoft 365)
    Ogni scelta mostra quanti punti di ripristino esistono.
  2. Origine: la macchina virtuale (su tutti gli hypervisor e i job), oppure il job di backup e la sua macchina.
  3. Punto di ripristino: il backup da cui ripristinare, prima il più recente, con stato, storage e dimensione.
    • I backup segnalati come sospetti (possibile ransomware) sono contrassegnati.
    • Le copie su uno storage secondario create da un job di copia di backup sono elencate come copia (backup di file e di VM).
  4. Opzioni: dove e come ripristinare. Sopra le opzioni viene mostrato un riepilogo delle scelte.

I passaggi in alto sono link, quindi potete tornare a qualsiasi passaggio precedente. Ogni passaggio ha un proprio indirizzo, così potete aggiungerlo ai preferiti o condividerlo.

Le opzioni sono le stesse della pagina di un backup in Attività, dove potete anche avviare direttamente un ripristino. Vedono la procedura guidata solo gli utenti il cui ruolo consente il ripristino.

Ripristinare da un backup di file

  1. Scegliete File e cartelle nella procedura guidata di ripristino, poi il job e il punto di ripristino. In alternativa aprite il backup in Attività o nella pagina del job.
  2. In Ripristina file da questo backup scegliete l'agente che riceverà i file. Può essere una macchina diversa da quella salvata — ad esempio un PC sostitutivo.
  3. Scegliete dove:
    • Ripristina in una cartella (consigliato) — ad es. D:\Restore. Al suo interno viene ricreata la struttura originale: D:\Restore\C\Users\ana\Documents\…. Nulla di esistente viene toccato.
    • Ripristina nella posizione originale — riscrive i file dove si trovavano, sovrascrivendo le versioni attuali. Per una condivisione NAS l'agente ricollega la condivisione in scrittura.
  4. Facoltativamente limitate a Solo questi percorsi, uno per riga, ad es. C:\Users\ana\Documents\Contracts — oppure selezionateli nel browser dei file (sotto).
  5. Lasciate attivo Verifica i file ripristinati: ogni file viene riletto e confrontato con il checksum del backup.
  6. Fate clic su Avvia ripristino. Avanzamento e risultati compaiono nella pagina dell'esecuzione di ripristino.

Vengono ripristinati anche gli orari dei file, gli attributi di Windows (nascosto, sola lettura, …) e, su Linux, proprietari, permessi (inclusi i bit setuid), ACL, attributi estesi (etichette SELinux, capability dei file), link simbolici e fisici. I proprietari vengono impostati solo se l'agente è eseguito come root/amministratore.

Sfogliare, scaricare e scegliere file

Nell'esecuzione di backup, Sfoglia file mostra le cartelle salvate com'erano (anche per condivisioni NAS e backup del sistema Linux). Aprite le cartelle, selezionate file e cartelle, poi:

  • Scarica — un file arriva così com'è, più file o cartelle come archivio ZIP, direttamente nel browser. I download vengono registrati nel log di audit.
  • Ripristinali su un agente — in una cartella o nella posizione originale, come un ripristino con Solo questi percorsi.

Un link simbolico a un file (ad es. /etc/os-release) viene scaricato come il file a cui punta, se quel file è nel backup; i link a cartelle vengono esclusi dagli archivi ZIP. Lo stesso vale per i file scaricati dai backup di macchine virtuali (ext4, XFS). Un ripristino su un agente ricrea i link come link.

La console legge il backup direttamente dallo storage, quindi la navigazione funziona per i backup su storage di rete (SFTP, S3, SMB, Azure, repository protetto); per un disco locale o USB di un agente, ripristinate con i percorsi. Gli utenti con un ruolo di ripristino possono sfogliare e scaricare.

Trovare il backup giusto: usate il Calendario per vedere quali backup sono stati eseguiti in quale giorno, o lo storico nella pagina del job.

Ripristinare singoli file da un'immagine disco

Per i backup di immagine, fate clic su Sfoglia file nell'esecuzione di backup. Potete navigare il file system NTFS dell'immagine direttamente nella console, selezionare file e cartelle e ripristinarli su qualsiasi agente — senza ripristinare l'intero disco.

Ripristinare singoli file da una VM (Proxmox VE, Hyper-V, VMware)

In un'esecuzione di backup di VM fate clic su Sfoglia file accanto al guest. La console mostra le partizioni e i volumi LVM dei suoi dischi e permette di sfogliare i file system NTFS, ext4 e XFS. Scaricate i file selezionati (più file come archivio ZIP) o ripristinateli su qualsiasi agente. Vedete Proxmox VE, Hyper-V e VMware ESXi.

Ripristinare intere macchine

  • Immagini disco Windows: su un disco o bare metal, anche su hardware diverso — Immagini disco.
  • Sistemi Linux: su un disco o bare metal, o come nuova VM Proxmox — Backup del sistema Linux.
  • VM e container Proxmox: come nuovo guest o sul posto — Proxmox VE. Le VM Proxmox possono anche essere eseguite istantaneamente dal backup e spostate su uno storage mentre sono in funzione (ripristino istantaneo).
  • Database (SQL Server, PostgreSQL, MySQL/MariaDB): con un nuovo nome o sul posto, a un momento preciso — Database.
  • VM Hyper-V: come nuova VM o sul posto (mantiene ID e indirizzi MAC) — Hyper-V.
  • VM VMware ESXi: come nuova VM o sul posto (mantiene UUID e indirizzi MAC), su qualsiasi host ESXi e datastore — VMware ESXi; anche istantaneamente dal backup tramite un agente proxy Linux, poi copiata su un datastore (ripristino istantaneo).

ISO di ripristino

I ripristini bare metal avviano la macchina da una ISO di ripristino (su una chiavetta USB o collegata a una VM), vedete Supporti di ripristino:

  • ISO di ripristino Linux — pubblicata con ogni versione (backupzit-recovery-linux.iso); la pagina Supporti di ripristino la collega dalla fonte degli aggiornamenti.
  • ISO di ripristino Windows — Windows PE non può essere ridistribuito, quindi si crea una volta su qualsiasi PC Windows 10/11 o Server:
    1. Installate il Windows ADK gratuito (funzionalità Deployment Tools) e il componente aggiuntivo Windows PE di Microsoft.
    2. Scaricate build-winpe.ps1 dalla versione (accanto ai pacchetti dell'agente) e prendete backupzit-agent.exe da C:\Program Files\backupzit Agent di una macchina con l'agente.
    3. In un PowerShell da amministratore: .\build-winpe.ps1 -AgentExe .\backupzit-agent.exe -Out .\backupzit-recovery.iso. Aggiungete -DriverDir C:\Drivers per driver di storage o di rete (ad es. VirtIO per le VM Proxmox) e -RecoveryJson .\recovery.json perché si colleghi senza digitare nulla.
    4. Facoltativamente copiate la ISO nella directory /var/lib/backupzit/dist della console; viene allora offerta nella pagina Supporti di ripristino.

La navigazione dei file nella console funziona per i backup su storage di rete (SFTP, S3, SMB, Azure, repository protetto); la console li legge direttamente. Per i backup su un disco locale di un agente usate la riga di comando.

Ripristinare senza la console

Se la console stessa va persa, qualsiasi macchina con l'agente installato può ripristinare direttamente dallo storage usando il foglio di ripristino della destinazione di archiviazione:

set BACKUPZIT_PASSWORD=<recovery key>
set BACKUPZIT_SFTP_PASSWORD=...           (or the S3/SMB/hardened credentials)
backupzit-agent snapshots --repo sftp://backup@nas:22/backups/pc1_1a2b3c4d
backupzit-agent restore   --repo sftp://backup@nas:22/backups/pc1_1a2b3c4d --target D:\Restore latest

Vedete Riferimento della riga di comando.

Test di ripristino automatici

BackupZit mette alla prova i vostri backup regolarmente senza che dobbiate fare nulla: ogni settimana (configurabile in Impostazioni → Test di ripristino) l'agente di ogni job ripristina un campione casuale di file dal backup più recente in una cartella temporanea, verifica ogni byte rispetto ai checksum memorizzati e lo elimina. Per le immagini disco vengono letti e verificati blocchi casuali. Così si mette alla prova l'intera catena — accesso allo storage, credenziali, chiave di cifratura e integrità dei dati.

  • I risultati compaiono in Attività e nello storico del job come esecuzioni di tipo Test di ripristino, e per job in Report (colonna Test di ripristino).
  • Un test fallito è un errore come gli altri e genera un avviso via email.
  • Testa ripristino nella pagina di un job avvia subito un test.
  • La dimensione del campione limita quanto viene letto dallo storage — tenetela piccola per uno storage cloud con costi di download.

Test di avvio per le VM Proxmox

Blocchi leggibili non dimostrano che una VM si avvii ancora. Con Test di avvio per i backup delle VM Proxmox attivo (Impostazioni → Test di ripristino), il test di ripristino di un job di VM Proxmox avvia anche ogni VM del backup più recente sul nodo del job, una dopo l'altra, con il ripristino istantaneo: viene eseguita dal backup con un nuovo ID e le schede di rete scollegate (così non entra in conflitto con l'originale) e viene eliminata subito dopo. Il test è superato quando l'agente guest QEMU della VM risponde entro il tempo configurato, il che significa che il sistema operativo si è avviato. Le VM senza agente guest superano il test se restano in esecuzione per un minuto; la pagina dell'esecuzione le mostra come in esecuzione invece di avviata.

  • Durante il test il nodo ha bisogno di memoria libera per una VM in più.
  • Installate l'agente guest QEMU nelle VM (qemu-guest-agent su Linux, gli strumenti guest VirtIO su Windows) e abilitatelo nelle opzioni della VM, così il test può confermare l'avvio.
  • La pagina dell'esecuzione elenca ogni VM con il risultato e il tempo impiegato dall'avvio.

In aggiunta, ripristinate a mano di tanto in tanto (ad es. ogni trimestre) una cartella reale e aprite qualche file — così si addestrano anche le persone che dovranno farlo in caso di emergenza.
