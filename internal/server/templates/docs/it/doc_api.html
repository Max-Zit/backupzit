REST API

Integra BackupZit con piattaforme RMM, monitoraggio (PRTG, Zabbix, Nagios, Uptime Kuma…) e i tuoi script.

Token

Crea un token in Il mio account → Token API. Assegnagli il ruolo più basso sufficiente: Visualizzatore per il monitoraggio, Operatore di ripristino per avviare anche backup e test di ripristino. Il token viene mostrato una sola volta; invialo in ogni richiesta:

Authorization: Bearer bzt_...

I token possono scadere, essere revocati dal proprietario o da un amministratore (Utenti) e smettono di funzionare quando il proprietario viene disattivato. Le azioni eseguite con un token compaiono nel registro di controllo con il nome del token.

Endpoint

Tutte le risposte sono in JSON. URL di base: https://<console>:8443.

Metodo e percorsoRuoloRestituisce
GET /api/v1/statusVisualizzatoreStato generale: agenti online, errori e avvisi nelle 24 h, esecuzioni attive, backup sospetti non esaminati, "ok": true|false
GET /api/v1/agentsVisualizzatoreAgenti con sistema operativo, versione, stato online e ultimo contatto
GET /api/v1/jobs, GET /api/v1/jobs/{id}VisualizzatoreJob con pianificazione, prossima esecuzione e ultimo risultato
POST /api/v1/jobs/{id}/runOperatore di ripristinoAvvia subito il job: {"run_id": 123} (202), oppure 409 se un'esecuzione è già attiva
POST /api/v1/jobs/{id}/testOperatore di ripristinoAvvia un test di ripristino del backup più recente del job
GET /api/v1/runs?job=&agent=&status=&limit=VisualizzatoreEsecuzioni recenti, dalla più nuova (predefinito 100, massimo 1000)
GET /api/v1/runs/{id}VisualizzatoreUn'esecuzione con messaggio, errori e statistiche
GET /api/v1/report?period=&from=&to=&agent=&job=VisualizzatoreIl report di un periodo: totali, percentuale di successo e dettagli per job
GET /api/v1/targetsVisualizzatoreDestinazioni di archiviazione (senza credenziali)
GET /api/v1/agents/{id}VisualizzatoreUn agent
POST /api/v1/agents/{id}/logOperatore di backupChiede all'agent il suo log: {"run_id": 124}; si legge con l'endpoint successivo quando l'agent l'ha inviato (agent 0.38.0 o successivi)
GET /api/v1/runs/{id}/logOperatore di backupIl log inviato dall'agent: {"log": "..."}, oppure 404 finché non arriva
POST /api/v1/runs/{id}/cancelOperatore di ripristinoAnnulla un'esecuzione in coda o ferma una in corso: {"state": "cancelled"} o "stopping"; 409 se è terminata
POST /api/v1/jobs/{id}/enable, /disableOperatore di backupAttiva o disattiva la pianificazione del job; con l'approvazione a quattro occhi la disattivazione è possibile solo nella console (409)
GET /api/v1/storageVisualizzatoreSpazio usato per destinazione di archiviazione, capacità e spazio libero se noti, crescita giornaliera e giorni prima del riempimento
GET /api/v1/search?q=&job=Operatore di ripristinoCerca nei backup un file, una cartella o l'oggetto di un'e-mail (vedi Cerca nei backup): ogni risultato con le sue versioni, più backups_searched, backups_skipped, partial e truncated
GET /api/v1/metricsVisualizzatoreMetriche nel formato testo di Prometheus (vedi sotto)

Periodi: today, yesterday, last7, last30, last90, thisweek, lastweek, thismonth, lastmonth, oppure custom con from=2026-09-01&to=2026-09-30.

Gli errori restituiscono {"error": "..."} con 400 (richiesta non valida), 401 (token mancante, non valido o scaduto), 403 (ruolo insufficiente), 404 o 409.

Esempi

curl

curl -sk -H "Authorization: Bearer $BZ_TOKEN" https://backup.example.local:8443/api/v1/status
curl -sk -X POST -H "Authorization: Bearer $BZ_TOKEN" https://backup.example.local:8443/api/v1/jobs/7/run

PowerShell

$h = @{ Authorization = "Bearer $env:BZ_TOKEN" }
$s = Invoke-RestMethod -Uri https://backup.example.local:8443/api/v1/status -Headers $h -SkipCertificateCheck
if (-not $s.ok) { Write-Warning "BackupZit needs attention: $($s.failed_24h) failed backups" }

Usa -k / -SkipCertificateCheck solo con il certificato autofirmato della console in una rete fidata, oppure installa il certificato della console sull'host di monitoraggio.

Controllo di monitoraggio

Interroga /api/v1/status ogni pochi minuti e genera un avviso quando ok è false. Per controlli per singolo job usa /api/v1/jobs e avvisa quando last_status è failed o last_finished è più vecchio del previsto.

I job con un RPO restituiscono anche rpo_hours, rpo_met e last_good_backup; gli agent restituiscono max_runs (job contemporanei). La metrica backupzit_job_rpo_met vale 1 per un job entro il suo RPO e 0 per uno che lo ha mancato.

Prometheus e Grafana

/api/v1/metrics restituisce lo stato nel formato testo di Prometheus: agent online, esecuzioni attive, errori e avvisi delle ultime 24 ore, backup sospetti e, per agent, job e destinazione, backupzit_agent_online, backupzit_job_last_status (0 riuscito, 1 avviso, 2 errore), backupzit_job_last_success_timestamp_seconds, backupzit_storage_used_bytes e backupzit_storage_free_bytes. Un job di scrape con un token Visualizzatore:

- job_name: backupzit
  scheme: https
  metrics_path: /api/v1/metrics
  authorization:
    credentials: bzt_...
  static_configs:
    - targets: ['backup.example.local:8443']

Imposta un allarme, ad esempio, quando time() - backupzit_job_last_success_timestamp_seconds > 2*86400 (nessun backup valido da due giorni).
