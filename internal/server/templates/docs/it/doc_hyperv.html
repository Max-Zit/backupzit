Macchine virtuali Hyper-V

BackupZit esegue il backup delle macchine virtuali Hyper-V tramite l'agente sull'host Hyper-V; nelle VM non viene installato nulla. I guest Windows e Linux vengono acquisiti mentre continuano a funzionare. Puoi ripristinarli come nuova VM o al posto dell'originale.

Configurazione

  1. Installa l'MSI dell'Agente Windows da Agenti sull'host Hyper-V e registralo. Host supportati: Windows Server 2016 o successivo con il ruolo Hyper-V, oppure Windows 10/11 con Hyper-V. In un cluster installa l'agente su ogni host.
  2. Entro un minuto l'host compare nella pagina Agenti con il badge Hyper-V · N VMs.
  3. In Job di backup seleziona quell'agente e scegli Macchine virtuali (Proxmox VE, Hyper-V, VMware). Poi scegli:
    • tutte le VM dell'host, che include anche le VM create in seguito;
    • singole VM, selezionandole.

L'agente lavora tramite le interfacce proprie di Hyper-V: il modulo PowerShell di Hyper-V e la Virtual Disk API di Windows. La console non memorizza credenziali Hyper-V.

Come viene salvata una VM

  1. Viene creato un checkpoint di ripristino temporaneo (backupzit_…). È il tipo di checkpoint che Hyper-V fornisce alle applicazioni di backup. Hyper-V chiede al guest di prepararsi:
    • I guest Windows svuotano i buffer delle applicazioni tramite VSS.
    • I guest Linux congelano i file system, se sono installati i daemon Hyper-V (hyperv-daemons / hv-vss-daemon).
    Se il guest non può fare né l'una né l'altra cosa, il checkpoint viene preso in modalità crash-consistent. La pagina dell'esecuzione mostra quale tipo è stato usato.
  2. Il checkpoint di ripristino attiva il Resilient Change Tracking (RCT) per i dischi della VM; accanto a essi vedrai file .rct e .mrt. Il primo backup legge i dischi interi. In seguito RCT indica quali blocchi sono cambiati dal backup precedente, e vengono letti solo quelli.
  3. I dischi vengono letti allo stato del checkpoint, tramite la Virtual Disk API, in blocchi da 1 MiB. Ciò comprende file VHDX e VHD, incluse le catene di checkpoint precedenti. I blocchi vuoti non vengono memorizzati e i blocchi già presenti nel repository non vengono ricaricati.
  4. Il checkpoint viene rimosso e Hyper-V lo unisce in background.
  5. La configurazione della VM viene salvata con il backup: generazione, CPU, memoria, schede di rete (switch, VLAN, indirizzo MAC), controller disco, avvio protetto e TPM.

Le VM spente vengono lette direttamente, senza checkpoint. Sugli host precedenti a Windows Server 2016 (senza checkpoint di ripristino) si usa un checkpoint di produzione e ogni backup legge i dischi interi.

Esempio dal laboratorio di test: una VM Linux con un disco da 3 GB. Il primo backup ha letto 3 GB. Il successivo, dopo 64 MB di nuovi dati, ha letto 96 MB.

Su Windows 10/11 Hyper-V crea un checkpoint automatico all'avvio di una VM, a meno che l'opzione non sia disattivata nelle impostazioni della VM. BackupZit gestisce questi checkpoint, ma per i server conviene disattivare i checkpoint automatici (impostazioni della VM → Checkpoint).

Ripristinare una VM

Apri l'esecuzione del backup della VM (dalla pagina del job o da Attività) e usa Ripristina una VM Hyper-V.

Come nuova VM accanto all'originale

Crea una seconda VM con nuovi indirizzi MAC, così può girare sulla stessa rete dell'originale. Per impostazione predefinita prende il nome dell'originale più "restored" e la data. I checkpoint automatici vengono disattivati su di essa (Windows li attiva per le nuove VM), così avviarla non lascia file di checkpoint. Se la copia gira accanto all'originale e contiene l'agente BackupZit, vedi Due macchine che usano lo stesso agente.

Le impostazioni di rete del guest legate a un indirizzo MAC non si applicano alle nuove schede. Un esempio è match: macaddress di netplan, usato dalle immagini cloud Linux.

Al posto della VM originale

Seleziona spegnila e sostituisci i suoi dischi. BackupZit quindi:

  • spegne la VM esistente;
  • unisce i suoi checkpoint;
  • sostituisce i suoi dischi con quelli ripristinati.

La VM mantiene ID, schede di rete e indirizzi MAC, quindi job, monitoraggio e rete del guest continuano a funzionare.

I vecchi file disco non vengono eliminati; vengono rinominati in ….replaced-DATE. Eliminali quando la VM ripristinata funziona.

Se la VM originale non esiste più, viene ricreata, con un nuovo ID Hyper-V.

Opzioni

  • Cartella per i dischi virtuali: la cartella predefinita dell'host o qualsiasi cartella che contenga dischi di VM. Un ripristino sul posto mette i nuovi dischi accanto a quelli originali.
  • Avvia la VM dopo il ripristino.

Cosa riceve una VM ripristinata

  • Gli switch virtuali vengono collegati per nome. Se uno switch non esiste sull'host, la scheda resta scollegata.
  • Ogni VM ripristinata riceve un nuovo ID di generazione, così i controller di dominio Active Directory rilevano il ripristino in sicurezza.

Ripristinare singoli file

Nella tabella delle VM dell'esecuzione, fai clic su Sfoglia file per vedere partizioni e volumi sui dischi della VM. Puoi sfogliare NTFS, ext2/3/4 e XFS, anche dentro LVM. Da lì puoi scaricare file o ripristinarli su qualsiasi agente. Funziona esattamente come per Proxmox VE.

Riga di comando

Esegui questi comandi sull'host Hyper-V, come amministratore:

backupzit-agent hyperv list
backupzit-agent hyperv backup  --repo ... [--vmid N,N]
backupzit-agent hyperv restore --repo ... --vmid N [--new] [--name NAME] [--folder D:\VMs] [--overwrite] [--start] SNAPSHOT|latest
  • --vmid è il numero mostrato da hyperv list. BackupZit lo ricava dal GUID della VM.
  • Senza --new, la VM viene ripristinata sul posto.
  • --overwrite conferma che i dischi di una VM esistente vanno sostituiti.

Le opzioni del repository sono le stesse di tutti i comandi; vedi Riferimento della riga di comando.

Non ancora incluso

  • Alcuni tipi di disco. VHDX condivisi, VHD Set e dischi pass-through non vengono salvati.
