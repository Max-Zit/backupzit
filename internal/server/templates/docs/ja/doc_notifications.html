通知: メール、Slack、Teams、Webhook

バックアップが失敗したときにメールを受け取り、毎朝日次サマリーを受け取れます。

メールの設定

設定 → メール通知 で設定します:

項目例
SMTP サーバー / ポートsmtp.office365.com / 587、smtp.gmail.com / 587、社内リレー / 25
セキュリティSTARTTLS（ポート 587）、TLS（ポート 465）、またはなし（社内リレーのみ）
ユーザー / パスワード送信に使うメールボックス。匿名リレーの場合は空欄。Microsoft 365 と Gmail ではアプリ パスワードが必要です。
送信者backup@example.com
受信者1 つ以上のアドレス（カンマ区切り）。

テストメールを送信 で設定を確認します。

送信される内容

  • 失敗（推奨）— 失敗した実行ごとに理由を記したメールを 1 通: バックアップ、コピー、復元、失敗した復元テスト。このオプションを有効にすると、バックアップがランサムウェアや大量削除のように見える場合に SUSPICIOUS アラートも届きます。
  • 警告 — 一部のファイルを読み取れなかった実行。
  • 成功 — 成功したすべての実行（通常は多すぎるため、日次レポートがおすすめ）。
  • 日次レポート — 選択した時刻に、過去 24 時間の実行、問題、オフラインのエージェントを送信。件名は OK、WARNINGS、ATTENTION のいずれかで始まるため、メールのルールで振り分けられます。

週次または月次のサマリーにはスケジュール レポートを使います。同じメール設定で送信され、独自の受信者を持ちます。件名は [BackupZit] で始まるため、メールのルールで振り分けられます。SMTP パスワードは暗号化して保存されます。

Slack、Microsoft Teams、Webhook

設定 → チャットと Webhook でチャネルをいくつでも追加できます。各チャネルで失敗、警告、成功を受け取るかを選びます。通常と異なるバックアップ（ランサムウェアの可能性）は失敗として扱われます。テスト送信 でチャネルをすぐに確認できます。

  • Slack: チャネル用の incoming webhook を作成し（Slack アプリの設定 → Incoming Webhooks）、その URL（https://hooks.slack.com/services/…）を貼り付けます。
  • Microsoft Teams: チャネルにワークフロー Post to a channel when a webhook request is received を追加し、その URL を貼り付けます。メッセージは、コンソールで実行を開くボタン付きのカードとして届きます。
  • Webhook: JSON の POST を受け付ける任意の URL — チケット システム、監視、自動化ツールなど。署名シークレットを設定すると、各リクエストに本文の HMAC-SHA256 である X-BackupZit-Signature: sha256=<hex> が付き、受信側はコンソールから来たことを確認できます。

Webhook の JSON:

{"event": "run.finished", "run_id": 412, "kind": "vm-backup", "kind_title": "VM backup",
 "status": "failed", "suspicious": "", "job": "Proxmox VMs", "job_id": 7, "agent": "pve1",
 "message": "…", "errors": ["…"], "started_at": "2026-10-04T22:00:03+02:00",
 "finished_at": "2026-10-04T22:04:41+02:00", "url": "https://backup.example/runs/412"}

メッセージは実行ごとに 1 回、メールがオフでも送信されます。失敗したチャネル（URL の誤り、サービス停止）はコンソールのログに記録され、ほかのチャネルを妨げません。Webhook の URL は暗号化して保存されます。
