コマンドライン リファレンス

エージェントはコマンドラインから単独でも動作します。スクリプト、コンソールなしでの復元、緊急時に使えます。概要は引数なしで backupzit-agent を、コマンドのオプションは backupzit-agent <command> -h を実行してください。

リポジトリと資格情報

すべてのコマンドは --repo（または BACKUPZIT_REPO）を受け取ります。シークレットには環境変数を使うことをお勧めします。エージェントのリポジトリは <ストレージの場所>/<hostname>_<id> です。「アクティビティ」の実行のリポジトリ列か、復旧シートを参照してください。

場所資格情報
D:\Backups\pc1, /mnt/backup/pc1—
sftp://user@host:22/pathBACKUPZIT_SFTP_PASSWORD または --sftp-key file、--sftp-hostkey SHA256:…（BACKUPZIT_SFTP_HOSTKEY）
s3://endpoint/bucket/prefix（HTTP の場合は ?tls=false）BACKUPZIT_S3_ACCESS_KEY、BACKUPZIT_S3_SECRET_KEY、--s3-region。--s3-lock-days N は Object Lock 付きで書き込みます
smb://[domain;]user@host/share/pathBACKUPZIT_SMB_PASSWORD、--smb-domain
azure://account/container/path（ソブリン クラウド、Azure Stack、Azurite には ?endpoint=URL）BACKUPZIT_AZURE_KEY または BACKUPZIT_AZURE_SAS
hardened://host:8500/pathBACKUPZIT_HARDENED_KEY、BACKUPZIT_HARDENED_FINGERPRINT
usb://LABEL/path（ワイルドカード: usb://BZBACKUP*/BackupZit）—（そのボリューム ラベルを持つ接続済みディスクが使われます）

暗号化されたリポジトリには BACKUPZIT_PASSWORD（または --password）で回復キーが必要です。

特定時点のビュー: Object Lock 付き S3 と強化リポジトリでは、--as-of 2026-10-01T14:30（または日付）でその時点のリポジトリを表示します。読み取り専用で、バックアップが削除または上書きされた後の復旧に使います。

ファイルとフォルダー

コマンド機能
init新しいリポジトリを作成します（パスワードを指定すると暗号化）。
backup [--vss] [--exclude PATTERN]… [--tag TAG]… [--force] [--host NAME] PATH…ファイルとフォルダーをバックアップします。--vss はボリューム シャドウ コピーから読み取ります（Windows、管理者）。--force は変更のないファイルも含めすべて読み取ります。
snapshotsスナップショットを時刻、ホスト、サイズ、パスとともに一覧表示します。
ls SNAPSHOT|latest [PATH]スナップショット内のファイルを一覧表示します。
restore --target DIR [--include PATH]… [--verify] SNAPSHOT|latestファイルを DIR の下に復元します（元のフォルダー構造が再作成されます）。--original では代わりに元の場所に書き戻し、既存のファイルを上書きします。
check [--read-data]リポジトリの構造を確認します。--read-data ではすべてのバイトをダウンロードして検証します。

ディスク イメージ（Windows）

コマンド機能
disks [--json]ディスクとパーティションを番号付きで表示します。
image-backup --disk N [--partitions 1,2] [--no-vss]
image-backup --all-disks		ディスク全体または選択したパーティション、あるいはすべての内蔵ディスクを 1 つのスナップショットにバックアップします。
image-restore --target-disk N --yes-erase-target [--keep-offline] [--source-disk N] SNAPSHOT|latestイメージをディスクに書き込みます。ディスクは消去されます。元のディスクが同じマシンにある場合は --keep-offline。--source-disk は全ディスク バックアップからディスクを選びます。
image-ls [--disk N] --partition N SNAPSHOT|latest [\path]イメージ内の NTFS パーティションのファイルを一覧表示します（--disk: 全ディスク バックアップでバックアップされたディスク）。
image-extract [--disk N] --partition N --target DIR SNAPSHOT|latest \path…イメージ内のパーティションからファイルとフォルダーをコピーします。

Linux システム（ベアメタル、P2V）

コマンド機能
system-backup [--exclude PATTERN]すべてのローカル ファイル システムとディスク レイアウトをバックアップします。Linux システム バックアップを参照してください。
system-show SNAPSHOT|latestシステム バックアップのディスク レイアウトを表示します。
system-restore --target DEVICE [--new-hardware] [--rebuild-initramfs] --yes-erase-target SNAPSHOT|latest空のディスク、論理ボリューム、またはイメージ ファイル上にシステムを再作成します。

Windows: 異なるハードウェア

コマンド機能
prepare-hardware --disk N [--drivers DIR]復元した Windows ディスクを異なるハードウェア用に準備します（ブート ドライバー、追加ドライバー、ブート ファイル）。復元オプションと同じで、たとえば復旧 ISO からやり直す場合に使います。

VMware ESXi（任意のエージェントをプロキシとして使用。パスワードは BACKUPZIT_VMWARE_PASSWORD）

コマンド機能
vmware list --host H [--user root]ホストの VM、ライセンス モード、証明書と SSH キーのフィンガープリント、データストアを表示します。
vmware backup --host H [--vmid N,N]スナップショットから VM（既定: すべて）をバックアップします。Changed Block Tracking では変更されたブロックのみ読み取ります。
vmware restore --host H --vmid N [--new] [--name X] [--datastore DS] [--overwrite] [--start] SNAPSHOT|latestVM をその場（既定）または --new で新しい VM として復元します。--overwrite は既存 VM のディスクを置き換え、古いものは名前を変えて保持します。VMware ESXi を参照してください。
esxi-nfs-serve/var/lib/backupzit/instant-esxi から NFS 経由で ESXi ホストにインスタント VM を提供します（Linux。インスタント リカバリが systemd ユニット backupzit-esxi-nfs として起動）。

ホストは --thumbprint SHA256:… と --ssh-host-key SHA256:… で固定します（vmware list で表示されます）。

Hyper-V（Hyper-V ホスト上のエージェント、管理者として）

コマンド機能
hyperv listホストの VM を BackupZit 番号付きで、復元ディスク用のフォルダーとともに一覧表示します。
hyperv backup [--vmid N,N]運用チェックポイントから VM（既定: すべて）をバックアップします。
hyperv restore --vmid N [--new] [--name X] [--folder DIR] [--overwrite] [--start] SNAPSHOT|latestVM をその場（既定）または --new で新しい VM として復元します。--overwrite は既存 VM のディスクを置き換えます。Hyper-V を参照してください。

pve show、pve ls、pve extract は Hyper-V バックアップでも使えます。

Proxmox VE（Proxmox ホスト上のエージェント）

コマンド機能
pve listクラスターの VM とコンテナー、および復元に使えるストレージを一覧表示します。
pve backup [--vmid 100,200] [--exclude 300]このノードのゲスト（既定: すべて）を Proxmox スナップショットからバックアップします。
pve show SNAPSHOT|latestVM バックアップ内のゲストとディスクを表示します。
pve ls --vmid N [--disk scsi0] [--volume ID] SNAPSHOT|latest [path]ゲスト ディスクのパーティションと論理ボリューム、またはフォルダー内のファイルを一覧表示します（NTFS、ext4、XFS、LVM 上も可）。
pve extract --vmid N --target DIR [--volume ID] SNAPSHOT|latest path...VM を復元せずにゲスト ディスクからファイルとフォルダーをコピーします。
pve restore --vmid N [--new-vmid -1|N] [--name X] [--storage S] [--overwrite] [--start] SNAPSHOT|latestゲストを再作成します。--new-vmid -1 は次の空き ID を使い、--overwrite は同じ ID の既存ゲストを置き換えます。Proxmox VE を参照してください。
pve instant --vmid N [--new-vmid N] [--name X] SNAPSHOT|latestインスタント リカバリ: ディスクをバックアップから読み取りながら数秒で VM を起動します（新しい VM、既定は次の空き ID）。
pve instant-finish --vmid N --storage S実行中のインスタント VM のディスクをストレージに移動します。その後はバックアップを使いません。
pve instant-discard --vmid Nインスタント VM を停止し、変更とともに削除します。
nbd-serve --snapshot ID --vmid N --socket PATHバックアップ内の VM のディスクを Unix ソケット上の NBD で読み取り専用で提供します（インスタント リカバリが systemd ユニットとして起動）。

Microsoft SQL Server（SQL Server マシン上のエージェント）

コマンド機能
sql list [--instance I]インスタンスのデータベースを復旧モデルとサイズ付きで一覧表示します。
sql backup [--instance I] [--db a,b] [--system] [--log] [--copy-only]完全バックアップ（既定: すべてのユーザー データベース）、または --log でトランザクション ログ バックアップをリポジトリに取ります。
sql showリポジトリ内の SQL Server バックアップを LSN 範囲付きで一覧表示します。
sql restore --db NAME [--as NEW] [--replace] [--at TIME] SNAPSHOT|latest完全バックアップとその後のログ バックアップからデータベースを復元します。特定時点への復元も可能です。SQL Server を参照してください。

PostgreSQL と MySQL/MariaDB（データベース サーバー上のエージェント）

コマンド機能
pg list [--port P]ローカル クラスターのデータベースと、WAL アーカイブが有効かどうか。
pg backup [--port P] [--db a,b] [--pitr | --wal]完全バックアップ（pg_basebackup、各データベースの pg_dump。--pitr で WAL アーカイブを設定）、または --wal でアーカイブ済み WAL。
pg restore --db NAME|"(cluster)" [--as NEW] [--replace] [--at TIME | --latest] SNAPSHOT|latestデータベース（ダンプから、または特定時点へ）、またはクラスター全体を別インスタンスとして復元します。
mysql listデータベースと、バイナリ ログが有効かどうか。
mysql backup [--db a,b] [--binlog]各データベースのバイナリ ログ位置付き mysqldump、または閉じたバイナリ ログ。
mysql restore --db NAME [--as NEW] [--replace] [--at TIME | --latest] SNAPSHOT|latestダンプを読み込み、特定時点までバイナリ ログを再生します。データベースを参照してください。

管理モード

コマンド機能
enroll --code BZ1-… [--force]「エージェント」ページの登録コードでエージェントをコンソールに接続します（--force は既存の登録を置き換えます）。旧形式の --server URL --token T --fingerprint F も引き続き使えます。
set-server https://address:8443登録済みエージェントをコンソールの新しいアドレス（同じ証明書）に向けます。その後エージェント サービスを再起動してください。エージェントを参照してください。
status実行中のエージェントの処理内容とバックアップ ジョブを表示します（Windows のトレイ アイコンも同じ内容を表示します）。
service install|uninstall|start|stop|status|runエージェント サービスを管理します（インストーラーが行います）。
recovery復旧モード。復旧 ISO が自動的に起動します。任意の Linux ライブ システムでは: sudo backupzit-agent recovery --server URL --token CODE。
versionバージョンを表示します。

例

set BACKUPZIT_PASSWORD=XXXX-XXXX-...
set BACKUPZIT_S3_ACCESS_KEY=...
set BACKUPZIT_S3_SECRET_KEY=...
backupzit-agent snapshots --repo s3://s3.wasabisys.com/company-backups/backupzit/pc1_1a2b3c4d
backupzit-agent restore --repo s3://s3.wasabisys.com/company-backups/backupzit/pc1_1a2b3c4d --target D:\Restore --include C:\Users\ana\Documents latest
backupzit-agent check --repo s3://... --read-data

backupzit-agent disks
backupzit-agent image-ls --repo usb://BZBACKUP1/BackupZit/pc1_1a2b3c4d --partition 3 latest \Users
backupzit-agent snapshots --repo hardened://vault:8500/backupzit/pc1_1a2b3c4d --as-of 2026-10-01T14:00

強化リポジトリ（backupzit-repo）

コマンド機能
backupzit-repo serveサービスを実行します（systemd が行います）。
backupzit-repo add-key NAMEアクセス キーを作成します（一度だけ表示）。
backupzit-repo keys / remove-key NAMEアクセス キーの一覧表示 / 失効。
backupzit-repo fingerprintコンソール用の証明書フィンガープリント。
backupzit-repo status保存済みのデータと非表示（削除済みだが保持中）のデータ。
backupzit-repo undelete --since TIMETIME 以降に削除されたファイルを再び表示可能にします。

構成: /etc/backupzit-repo/repo.env — BACKUPZIT_REPO_LOCK_DAYS、BACKUPZIT_REPO_DATA、BACKUPZIT_REPO_LISTEN、BACKUPZIT_REPO_TLS_HOSTS。

管理サーバー（backupzit-server）

オプション / 環境変数意味
--db / BACKUPZIT_DBPostgreSQL 接続文字列（必須）。
--listen / BACKUPZIT_LISTENHTTPS アドレス。既定は :8443。
--data-dir / BACKUPZIT_DATA_DIR証明書、secrets.key、エージェントのダウンロード（dist/）。
--public-url / BACKUPZIT_PUBLIC_URLエージェントとメールのリンクが使う URL。
--tls-hosts / BACKUPZIT_TLS_HOSTS自己署名証明書に追加する名前/IP。
BACKUPZIT_ADMIN_PASSWORD初期管理者パスワード（初回起動時のみ）。
BACKUPZIT_SECRETS_KEYsecrets.key ファイルの代わりのシークレット キー（base64）。
--set-admin-password NEWadmin のパスワードをリセットし（ローカル管理者として再有効化）、終了します。
--unblock-ip ADDRESS|allアドレスまたはすべてのアドレスのサインイン ブロック（ブルートフォース対策）を解除して終了します。
--restore-console --repo R [--snapshot ID]コンソール バックアップからコンソールを復元して終了します（サーバーのインストールを参照）。
--dev-embedded-db, --dev-http ADDR評価専用: データ ディレクトリ内のプライベート PostgreSQL、localhost 上の平文 HTTP。
--versionバージョンを表示します。
systemctl status backupzit-server
journalctl -u backupzit-server -f
