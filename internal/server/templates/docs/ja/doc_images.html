ディスク イメージとベアメタル復旧

イメージ バックアップはディスク全体 — パーティション テーブル、ブート パーティション、システム、データ — を取得するため、空のディスクや新しいディスクにマシンを元どおりに戻せます。

ディスク イメージ バックアップは Windows マシン（NTFS ボリューム、GPT と MBR ディスク）で利用できます。Linux マシンには Linux システム ジョブを使います。

イメージ ジョブの作成

  1. バックアップ ジョブ で ディスク イメージ を選びます。
  2. エージェントはディスクを自動的に報告します。マシンのすべての内蔵ディスクを 1 つのジョブでイメージ化するには すべてのディスク を選ぶか、1 台のディスクをオンにします — ディスク全体、または一部のパーティションのみ（例: ファイル ジョブで既に対象にしている大きなデータ パーティションを除外）。
  3. 保持とスケジュールは他のジョブと同様に設定します。週 1 回のイメージと毎日のファイル バックアップの組み合わせが一般的です。

すべてのディスク

すべてのディスク ジョブは、パーティション テーブルを持つすべての内蔵ディスクを 1 つのバックアップにまとめます。後から追加したディスクも含まれます。すべてのディスクのすべてのボリュームが 1 つの VSS スナップショットから読み取られるため、ディスク間の整合性が保たれます（例: D: のデータベースと E: のログ）。USB や SD のディスク、マウントされた VHD/VHDX ファイル、リムーバブル メディアは除外されます — 外付けのバックアップ ディスクが自分自身をイメージ化してはならないためです。必要な場合はそのディスクを単独で選んでください。実行ページには各ディスクとそのパーティションが表示され、それぞれからファイルを参照・復元できます。復元は 1 回に 1 台のディスクを書き込みます: 復元フォームで バックアップ内のディスク と復元先ディスクを選び、次のディスクについて繰り返します（ベアメタルの場合: まずリカバリー ISO からシステム ディスクを復元）。エージェントは 0.33.7 以降が必要です。古いエージェントは更新が必要であることを報告します。

使用中のブロックのみが読み取られ（NTFS 割り当てマップ）、稼働中のシステムの整合性を保つためにイメージは VSS スナップショットから取得され、変更されていないブロックは以前のイメージと重複排除されます — 同じマシンの 2 回目のイメージは通常、数パーセントしか送信しません。

イメージをディスクに復元

イメージ バックアップの実行で このイメージをディスクに復元 を使います:

  • エージェントに復元 — 復元先ディスクを持つマシン。空きディスクのある稼働中のマシン、またはリカバリー ISO から起動したマシンです。
  • 復元先ディスク — 元のディスクの使用領域以上のサイズが必要です。ディスク上のデータはすべて消去されます。
  • その後ディスクをオフラインのままにする — 元のディスクが同じマシンにある場合はオンにします。Windows がコピーのディスク ID を変更しないようにするためです。

GPT と MBR ディスク、EFI と BIOS ブートに対応しています。パーティション レイアウトと ID が再作成されるため、復元したディスクは以前と同じように起動します。

リカバリー ISO によるベアメタル復旧

  1. リカバリーメディア で（Windows の）リカバリー ISO をダウンロードします。USB メモリーに書き込む（Rufus、「DD イメージ」または「ISO」モード）か、仮想マシンに接続します。
  2. 必要に応じて リカバリー コード を作成し、recovery.json をダウンロードします。USB メモリーの backupzit フォルダーにコピーしておくと、入力なしで接続できます。
  3. 復元するマシンを USB メモリーから起動します。エージェントがリカバリー モードで起動し、コンソールに接続します（またはサーバーのアドレスとリカバリー コードを尋ねます）。
  4. マシンはディスクとともに リカバリー エージェントとして表示されます。
  5. アクティビティでイメージ バックアップを開き、このイメージをディスクに復元 を選び、リカバリー エージェントとそのディスクを選んで確定します。
  6. 実行が終わったら USB メモリーを外して再起動します。

異なるハードウェアへの復元

Windows は起動元のディスク コントローラーのドライバーがなければ起動せず、Windows セットアップは不要だったドライバーを無効にします。そのため、Intel コントローラーの PC のイメージは、AMD のマザーボード、NVMe ドライブ、Hyper-V、Proxmox VM では INACCESSIBLE_BOOT_DEVICE で停止します。復元フォームで 異なるハードウェアに復元 をオンにすると、BackupZit はイメージの書き込み後に復元した Windows を準備します:

  1. Windows に含まれる一般的なディスク コントローラーのドライバーが、起動時に再び読み込まれるようになります: AHCI/SATA、NVMe、Intel RST、LSI/Broadcom/Dell PERC SAS と RAID、HPE Smart Array、Hyper-V、VMware。
  2. 追加のドライバーを DISM で組み込みます: リカバリー ISO 上のドライバー（Proxmox/KVM 用の VirtIO ドライバーを含む）と、追加のドライバー に入力したフォルダー — 例: 新しいマザーボードのストレージとネットワークのドライバーを USB メモリーに展開したもの（E:\Drivers、サブフォルダーも検索されます）。
  3. 新しいマシン用にブート ファイルを再構築します（bcdboot）。

実行ページには有効化・追加されたドライバーが表示されます。残りの新しいデバイスは Windows が初回起動時に検出します。新しいハードウェアではライセンス認証のやり直しを求められることがあります。UEFI とレガシー BIOS の間での復元はできません — 復元先は元と同じ方式で起動する必要があります。

物理 PC やサーバーから Proxmox VE へ: GPT ディスクなら OVMF（UEFI）、MBR ディスクなら SeaBIOS の VM を作成し、元以上のサイズの VirtIO SCSI ディスクと VirtIO ネットワーク カードを付け、リカバリー ISO を接続して 異なるハードウェアに復元 で復元します。リカバリー ISO は VirtIO のディスクとネットワーク カードを自分で認識します。

仮想マシンへの復元

元以上のサイズの空の VM ディスクを作成し、VM をリカバリー ISO から起動して上記の手順に従います。これは、イメージが本当に起動するかをテストするいちばん簡単な方法でもあります。
