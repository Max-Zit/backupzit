VMware ESXi 仮想マシン

BackupZit は、ESXi にも VM 内にも何もインストールせずに、VMware ESXi ホストの仮想マシンをバックアップします。ネットワーク上の任意のマシンにある BackupZit エージェントが、ホストの プロキシ として動作します。スナップショットを作成し、仮想ディスクの変更されたブロックだけを読み取って、ストレージに書き込みます。

要件

  • 直接接続された ESXi 6.7、7、8、または ESXi ホストを含む vCenter Server 7、8（vCenter Server を参照）。
  • ホストの管理者権限を持つユーザー（通常は root）。
  • 無償ライセンスのホストでは SSH を有効化: Host → Actions → Services → Enable Secure Shell。無償の ESXi ライセンスでは API が読み取り専用のため、スナップショットと復元は SSH 経由で行われます。ライセンス済みのホストは vSphere API で変更され、SSH は不要です。
  • プロキシ エージェント: ポート 443（SSH を使う場合は 22 も）でホストに到達できる任意の Windows または Linux エージェント。バックアップ データはこれを経由するため、ホストとストレージに近い高速なネットワークに配置してください。
  • 稼働中の VM をバックアップする間、VM のデータストアに空き容量 が必要です。BackupZit はそこで一時的にディスクをコピーします（後述）。コピーはシン形式のため、ディスクが実際に使用している分の容量が必要です。ホットアド ではコピーは作成されません。

ホストの追加

  1. エージェント → VMware ESXi ホスト → ESXi ホストまたは vCenter Server を追加 を開きます。
  2. アドレス、ユーザー、パスワード、プロキシ エージェントを入力します。
  3. コンソールは確認のために一度接続します。VM の一覧とライセンスを読み取り、ホストの HTTPS 証明書と SSH ホスト キーをピン留め します。後でホストが同じアドレスの別のマシンに置き換えられた場合、BackupZit はパスワードを送らずに接続を拒否します。 既知の理由で証明書が変わった場合（ホストの再インストール、新しい証明書の取得、または vCenter への追加。vCenter はホストの証明書を置き換えます）、エージェント ページにホストの新しいフィンガープリントと新しい証明書を受け入れるボタンが表示されます。受け入れる前にホスト側のフィンガープリントと比較してください。 0.62 以降、コンソールはパスワードを送信する前に証明書と SSH ホスト キーのフィンガープリントを表示し（0.62 以降のプロキシ エージェント経由でも、エージェントが代わりに読み取ります）、確認後にだけ接続します。

パスワードは、ほかのシークレットと同様に暗号化して保存されます。ホストにはコンソール自体が接続します（HTTPS 443、無償ライセンスでは SSH 22 も）。接続するのは、追加時、更新 のとき、および VM の一覧を更新するための 10 分ごとです（プロキシエージェント経由でホストに接続する場合を除きます）。削除 はホストをそのバックアップ ジョブとともに削除します。バックアップはストレージに残ります。表には各ホストのモードが表示されます:

  • vSphere API（ライセンス済みホスト、SSH 不要）: スナップショット、ディスクのコピー、復元、インスタント リカバリは API 経由で行われます。
  • vCenter Server（vSphere API）: vCenter とその ESXi ホスト。すべて vCenter API 経由で行われます。
  • 無償ライセンス: スナップショットと復元は SSH 経由: ホストの API が読み取り専用のため、これらの手順は SSH 経由で行われます。
  • SSH（このホストで選択）: ホストの API で可能な場合でも、ホストは SSH 経由で変更されます（ホストの追加時に 常に SSH を選択）。

プロキシエージェント経由（エージェント 0.56 以降）: ホストの追加時に プロキシエージェント経由で接続 を、またはホストの行で プロキシ経由で接続 をオンにすると、コンソールがホストに直接接続することはなくなります。プロキシエージェントがアドレスとパスワードを確認し、VM の一覧、バージョン、ライセンスを読み取り、確認した HTTPS 証明書と SSH ホスト キーを報告します。コンソールは直接接続の場合と同様に初回にそれらをピン留めし、以降、プロキシエージェントは別の証明書を提示するホストを拒否します（その場合、ホストの行に 新しい証明書を受け入れる が表示されます）。更新 と 10 分ごとの VM 一覧もプロキシエージェントから取得され、これらの確認はアクティビティには表示されません。ホストに到達する必要があるのは、バックアップや復元と同じくプロキシエージェントだけなので、コンソールは別のネットワーク、NAT の内側、または重複するアドレス範囲に置くことができます。アドレスやパスワードが間違っている場合は、プロキシエージェントの最初の確認後にホストのエラーとして表示されます。ホストを削除して追加し直してください。プロキシエージェントがオフラインまたはビジーの間は、最後の VM 一覧がそのまま残ります。

自動 ではコンソールが自分で選ぶため、後からライセンスを取得したホストも追加の設定なしで API に切り替わります。ホストの行（および追加時）の ホストの変更方法 で 常に SSH または 常に vSphere API を強制でき、変更はすぐに確認されます。以前のバックアップとその復元ポイントは方法に左右されません。

vCenter Server

vCenter Server はホストと同じように追加します。アドレス、administrator@vsphere.local（または Administrator ロールのユーザー）、プロキシ エージェントを指定します。これにより BackupZit は、この 1 つの接続でデータセンター内のすべての ESXi ホストとクラスターの VM を把握します。SSH で何かを変更することはなく、ホストのパスワードも不要です。

  • vMotion で別のホストに移動した VM も引き続きバックアップされます。VM はホストではなくインスタンス UUID で識別されます。
  • 復元時には、VM を実行する ESXi ホスト（既定: 元の VM のホスト）とデータストアを選べます。
  • インスタント リカバリは選んだホストで VM を起動し、完了 では 稼働したまま Storage vMotion でデータストアへ移動するため、ダウンタイムがありません。
  • 複数のデータセンターを持つ vCenter はまだ追加できません。他のデータセンターのホストは直接追加してください。

同じ ESXi ホストを直接と vCenter 経由の両方で追加しないでください。接続ごとに独自のリポジトリがあるため、その VM が 2 回バックアップされます。 BackupZit が直接バックアップしているホストを後から vCenter に追加した場合は、エージェント ページで新しい証明書を受け入れてください。ジョブはそのまま動作します。vCenter はスタンドアロン ホストで作成された VM に新しい ID を付与し、BackupZit は次回の更新時にジョブをその ID に切り替えます。

バックアップ ジョブ

バックアップ ジョブ で ESXi ホスト（エージェント一覧の VMware ESXi ホスト に表示）と 仮想マシン を選びます。ホストのすべての VM（後から作成した VM も自動的に含まれます）をバックアップするか、個別にチェックします。ジョブはホストのプロキシ エージェントで実行されます。プロキシを変更すると、既存のジョブも追従します。

BackupZit コンソールの VM など一部の VM を除外するには、チェックしたもの以外のホスト上のすべての VM (およびコンテナー) を選び、それらにチェックを付けます。

VM のバックアップ方法

  1. VM の 変更ブロック トラッキング（CBT） がオフの場合はオンにします。
    • ライセンスのあるホストでは自動で行われます。
    • 無償のホストでは、CBT は VM の電源がオフのときにしかオンにできません。BackupZit は、VM がオフになっている最初のバックアップでこれを行います。それまでは毎回ディスク全体を読み取り、実行に警告が表示されます。
  2. スナップショット backupzit_… を作成します。ゲストで VMware Tools が動作している場合、スナップショットは 静止化（quiesce）されます。先にアプリケーションとファイル システムがフラッシュされ、バックアップはアプリケーション整合性を持ちます。VMware Tools がない場合はクラッシュ整合性です。Linux VM には open-vm-tools、Windows VM には VMware Tools をインストールしてください。静止化が失敗する、または正しく動作しないゲストには、ジョブで クラッシュ整合性のスナップショット（VMware Tools による静止化なし） をオンにします。そのバックアップは停電後と同じくクラッシュ整合性になります（エージェント 0.58）。一部のホスト（ESXi 6.7）では、静止化されたスナップショットのディスクが、静止化自体が書き込んだ小さな差分になります。エージェントはこれをスナップショットとともに読み取ります（エージェント 0.58。古いエージェントはスナップショットの差分ディスクとして拒否していました）。
  3. CBT が読み取るブロックを報告します:
    • 初回のバックアップでは使用中のブロックのみ;
    • 以降は前回のバックアップ以降に変更されたブロックのみ。
  4. 稼働中の VM はディスクをロックしています。そのため、ディスクをデータストア上でコピーし（シン）、スナップショットはすぐに削除 されます（通常は数秒後）。その後、コピーを HTTPS で読み取って削除します。電源がオフの VM は直接読み取られます。ホットアド では、稼働中の VM のディスクを代わりにプロキシ自身の VM 経由で読み取るため、コピーは作成されません。
  5. VM の構成（.vmx）と NVRAM がバックアップとともに保存されます。

テスト環境での例: 8 GB ディスク（使用中 1.6 GB）の Debian VM。最初のバックアップは 1.6 GB を読み取りました。50 MB の新しいデータの後の次のバックアップは 70 MB を読み取り、23 秒かかりました。

ホットアド: データストア上にコピーを作成しない

稼働中の VM のディスクをコピーすると、増分バックアップを含むすべてのバックアップのたびに、本番データストアで時間と I/O がかかり、ディスクの使用済みブロック分の空き容量も必要です。低速なディスク上の大きな VM では、これが問題になります。ホットアド（エージェント → VMware ESXi ホスト、プロキシエージェントの下のチェックボックス）を使うと、プロキシが代わりにディスクをその場で読み取ります:

  • 要件: プロキシが、VM のデータストアが見える VM 内の Linux エージェント であること（同じホスト上、またはそれらのデータストアにアクセスできる同じ vCenter のホスト上）、そしてホストが vSphere API で変更されること（vCenter またはライセンスのあるホスト）。プロキシは BIOS UUID で自身の VM を見つけます。
  • 仕組み: スナップショットが存在する間、各ディスクは independent-nonpersistent としてプロキシの VM に接続されます。プロキシはディスクを読み取り専用で開きます。書き込まれたものはすべて、ディスクの切断時に vSphere が破棄する redo log に送られるため、VM のディスクが変更されることはありません。プロキシは CBT が報告したブロックだけを読み取ってディスクを切断し、その後スナップショットが削除されます。
  • 節約できるもの: 一時コピーも、データストア上の追加容量も不要です。変更が 20 GB ある 2 TB の VM の増分バックアップでは、読み取りは 20 GB です。スナップショットはディスクを読み取っている間ずっと残る（コピーの間だけではない）ため、VM がスナップショットに書き込む時間が少し長くなります。
  • フォールバック: プロキシがホストの VM でない場合、またはディスクの接続や読み取りに失敗した場合、そのディスクは従来どおりデータストア上でコピーされ、実行に理由付きの警告が表示されます。ホットアドは既定でオフです。0.54 より前のエージェントはこの設定を無視します。実行のページには、ホットアドで読み取ったディスクの数が表示されます。
  • プロキシ VM 上: LVM のデバイス ファイル（/etc/lvm/lvm.conf の use_devicesfile = 1、プロキシ自身のディスクは lvmdevices で登録）を使って、接続されたディスクのボリュームを LVM が有効化しないようにしてください。それでも有効化されたボリュームは、ディスクの切断前に削除されます。他の VM のディスクを手動でプロキシに接続しないでください。他の VM のフォルダーにある independent-nonpersistent ディスクは、中断されたバックアップが残したものと見なされ、切断されます。

複数のプロキシエージェント（vCenter）

1 つのプロキシエージェントはディスクを 1 つずつ読み取り、ホットアドはデータストアが見えるホストでしか使えません。vCenter 接続では、各 ESXi ホスト上の VM で動く Linux エージェントを追加のプロキシエージェントとして追加します（エージェント → VMware ESXi ホスト、プロキシエージェントの下の追加のプロキシエージェント。エージェント 0.55 以降）:

  • ホストごとの分割: ジョブの各バックアップは分割されます。各 VM は、それが動いている ESXi ホスト上のプロキシエージェントに（最新の VM 一覧に基づいて）、その他の VM は接続のプロキシエージェントに割り当てられます。各プロキシエージェントは自分の分担を独立した実行として、他と同時に、自分のホストでホットアドを使ってバックアップします。参加するのはオンラインのプロキシエージェントだけです。停止しているプロキシエージェントの VM は接続のプロキシエージェントが担当します。新しいリポジトリへの最初のバックアップと、ローカルまたは USB の保存先へのバックアップは分割されません。
  • 1 回の開始: ジョブは 1 回の開始の各部分をまとめて表示します。いずれかの部分が実行中なら実行中、いずれかの部分が失敗したら失敗です。RPO アラートとダッシュボードは、すべての部分が成功した時点でバックアップとして数えます。チェーンされたジョブや「各バックアップの後」のコピーは、最後の部分の後に 1 回だけ開始します。
  • 重複しない: 接続のバックアップと復元は、異なるプロキシエージェントで同時には実行されません（同時に動くのは 1 回の開始の各部分だけ）。そのため、ホスト間で移動した VM を 2 つのプロキシエージェントが同時に扱うことはありません。
  • プロキシエージェントごとの保持: 各部分は自分の VM のバックアップをジョブの設定数だけ保持し、コピージョブも部分ごとにコピーして保持します。ジョブが分割される前のバックアップと、外したプロキシエージェントのバックアップはそのまま残り、その VM の復元ポイントであり続けます。別のホストへ移動した VM（vMotion）は、次回の VM 一覧の更新からそのホストのプロキシエージェントが担当します。
  • BackupZit は、エージェントが報告する BIOS UUID でプロキシエージェントのホストを見つけます。エージェントページでは各エージェントの横に表示されます。ESXi ホストが見つかりません: エージェントがこの vCenter の VM ではないか、VM 一覧がエージェントより古い状態です（更新をクリック）。

VMware バックアップをキャンセルすると（アクティビティ → キャンセル）、データストア上で実行中のディスクのコピーも停止し、途中までのコピーを削除します。スナップショットは通常のバックアップ後と同じく削除されます。キャンセルした時点でまだ作成中のスナップショットは、作成の完了を待って（最大 5 分）同様に削除されます。

残ったスナップショット。プロキシエージェントは、スナップショットと一時ディスク コピーを作成する前にそれぞれを記録し、対象がなくなったことを確認してから記録を消します。削除後に VM のスナップショットを再度一覧表示し、約 10 分間で最大 3 回試行し、vSphere セッションが終了していれば再度サインインし（各 VM の前にも行うため、1 つのセッションが失われても後続の VM は失敗しません）、vSphere がディスクの統合が必要と報告した場合はディスクを統合します。スナップショットがなく、以前の削除によるディスクの統合がまだ必要な VM は、次回のバックアップの前に統合されます。エージェントが途中で停止した場合（クラッシュ、停電）や削除が失敗し続ける場合、記録は残ります:

  • コンソールはプロキシエージェントにクリーンアップの実行をキューに入れ（ホストの認証情報を持つのはプロキシエージェントだけです）、プロキシエージェントは接続のバックアップのたびにもこうした残留物を削除します。プロキシエージェントのバックアップまたは復元が処理中の VM には手を付けません。エージェントが自分がプロキシではない接続（以前のプロキシなど）について報告した記録は、クリーンアップの実行なしで一覧に表示されます。そのスナップショットは、下で説明するように VM 一覧から表示されます。
  • ダッシュボードの要対応に、残留物ごとに（VM、いつから、理由）今すぐ削除とともに表示され、残り続ける残留物ごとに 1 回だけ通知（メール、チャット）が送られます。
  • コンソールは、接続のバックアップが実行されていない間、10 分ごとに更新する VM 一覧から 6 時間より古い backupzit_… スナップショットも探すため、古いエージェントの残留物も表示されます。削除されるのは backupzit_… という名前のスナップショットだけで、VM 自身のスナップショットには決して触れません。VM 一覧にない VM（データストアが停止している、別のホストに移動された）の記録はプロキシエージェントに 7 日間残るため、VM が戻ってきたときにもそのスナップショットは削除されます（エージェント 0.63 以降）。

VM の復元

復元ウィザード（仮想マシン全体）か、アクティビティのバックアップのページを使います。次を選びます:

  • 元の VM と並ぶ新しい VM として: 新しい名前、UUID、MAC アドレスを持つコピー。既定の名前は元の名前に -restored- と日付を付けたものです。クラウド イメージの netplan match: macaddress など、古い MAC アドレスに結び付いたゲストのネットワーク設定はコピーには適用されません。
  • 元の VM の代わりに: 電源を切ってディスクを置き換える を選ぶと、BackupZit は次を行います:
    • VM の電源を切り、スナップショットを削除する;
    • 現在のディスクの名前を ….replaced-DATE.vmdk に変更する（復元した VM が動作したら削除してください）;
    • 元の名前の新しいディスクにバックアップを書き込み、CPU とメモリをバックアップと同じに設定する。
    VM の UUID、ネットワーク アダプター、MAC アドレスは保持されます。VM が削除されていた場合は、元の ID で作成し直されます。
  • ESXi ホストとデータストア: 別のホスト、または同じホストの別のデータストア。
  • 復元後に VM を起動。

ディスクはシン形式で復元され、データのあるブロックだけが書き込まれます。CD/DVD ドライブに接続していた ISO イメージはバックアップに含まれないため、それらのドライブは空のままになります。

インスタント リカバリー

すぐに、バックアップから実行 を選ぶと、先にディスクをコピーせずに数秒で VM を起動できます。ホストのプロキシ エージェント（Linux エージェントである必要があります）が VM のディスクをバックアップから直接 NFS で提供し、ホストがそれをデータストア backupzit-<agent> としてマウントして VM を実行します。VM による変更はエージェント上（/var/lib/backupzit/instant-esxi、そのための空き容量が必要）に保持されます。バックアップ自体は変更されず、VM がそこから実行されている間は保持によって残されます。元の VM がまだ存在する場合、インスタント VM には新しい UUID と新しい MAC アドレスが付きます。

実行ページで、VM が正しく動作したら:

  • 完了する と、ホストのデータストアにコピーされます。VM がシャットダウンされ（VMware Tools が動作していればそれを使用）、ディスクがシン形式でコピーされ（ライセンス済みホストでは API、無償ライセンスでは SSH 経由の vmkfstools）、データストアから登録されて再起動します。単独のホストには Storage vMotion がないため、ディスク サイズに応じて短いダウンタイムが必要です。コピーに失敗した場合、VM はバックアップから実行され続けます。
  • 破棄 すると、VM はすべての変更とともに停止・削除されます。

エージェントは ESXi ホストのアドレスに対してのみ、ポート 2049 で NFS に応答します（マシンのポート 111 の rpcbind に登録するか、ポート 111 に自分で応答します）。間にファイアウォールがある場合は、ホストからエージェントへのこれらのポートを開いてください。最後のインスタント VM が完了または破棄されると、データストアは削除され、NFS サーバーは停止します。

個別ファイル

バックアップのページの ファイルを参照（または復元ウィザードの 仮想マシン内のファイル）で VM のディスクを開きます。NTFS、ext2/3/4、XFS、btrfs（LVM 上も含む）を参照し、ファイルをダウンロードしたり、任意のエージェントに復元したりできます。

コマンドライン

これらのコマンドは任意のエージェントで実行できます。ESXi のパスワードは BACKUPZIT_VMWARE_PASSWORD に設定します:

backupzit-agent vmware list    --host 192.168.1.20 [--user root]
backupzit-agent vmware backup  --host … --repo … [--vmid N,N]
backupzit-agent vmware restore --host … --repo … --vmid N [--new] [--name NAME] [--datastore DS] [--overwrite] [--start] SNAPSHOT|latest

vmware list はホストの証明書と SSH キーのフィンガープリントを表示します。--thumbprint と --ssh-host-key で渡すと、コマンドラインでもピン留めできます。

未対応

  • 複数のデータセンターを持つ vCenter。 追加できるのはデータセンターが 1 つの vCenter だけです。他のデータセンターのホストは直接追加してください。
  • 独自のスナップショットを持つ VM。 ディスクが差分になっているため、先にスナップショットを削除または統合してください。（静止化されたスナップショットが書き込む小さな差分はバックアップ自身のもので、スナップショットとともに読み取られます。）
  • 一部のディスクの種類。 RDM（Raw Device Mapping）と独立型ディスク。
  • Windows プロキシ エージェントによるインスタント リカバリー。 インスタント リカバリーには Linux プロキシ エージェントが必要です。
