VMware ESXi 仮想マシン

BackupZit は、ESXi にも VM 内にも何もインストールせずに、VMware ESXi ホストの仮想マシンをバックアップします。ネットワーク上の任意のマシンにある BackupZit エージェントが、ホストの プロキシ として動作します。スナップショットを作成し、仮想ディスクの変更されたブロックだけを読み取って、ストレージに書き込みます。

要件

  • 直接接続された ESXi 6.7、7、8。vCenter で管理されているホストは、それぞれのアドレスで 1 台ずつ追加します。vCenter 自体はまだ対応していません。
  • ホストの管理者権限を持つユーザー（通常は root）。
  • ホストで SSH を有効化: Host → Actions → Services → Enable Secure Shell。復元には常に必要です。無償の ESXi ライセンスのホストでは、API が読み取り専用のため、スナップショットにも必要です。
  • プロキシ エージェント: ポート 443 と 22 でホストに到達できる任意の Windows または Linux エージェント。バックアップ データはこれを経由するため、ホストとストレージに近い高速なネットワークに配置してください。
  • 稼働中の VM をバックアップする間、VM のデータストアに空き容量 が必要です。BackupZit はそこで一時的にディスクをコピーします（後述）。コピーはシン形式のため、ディスクが実際に使用している分の容量が必要です。

ホストの追加

  1. エージェント → VMware ESXi ホスト → ESXi ホストを追加 を開きます。
  2. アドレス、ユーザー、パスワード、プロキシ エージェントを入力します。
  3. コンソールは確認のために一度接続します。VM の一覧とライセンスを読み取り、ホストの HTTPS 証明書と SSH ホスト キーをピン留め します。後でホストが同じアドレスの別のマシンに置き換えられた場合、BackupZit はパスワードを送らずに接続を拒否します。

パスワードは、ほかのシークレットと同様に暗号化して保存されます。VM の一覧は 10 分ごと、または 更新 ですぐに更新されます。表には各ホストのモードが表示されます:

  • vSphere API: ライセンスのあるホスト。
  • 無償ライセンス: スナップショットと復元は SSH 経由で行われます。

バックアップ ジョブ

バックアップ ジョブ で ESXi ホスト（エージェント一覧の VMware ESXi ホスト に表示）と 仮想マシン を選びます。ホストのすべての VM（後から作成した VM も自動的に含まれます）をバックアップするか、個別にチェックします。ジョブはホストのプロキシ エージェントで実行されます。プロキシを変更すると、既存のジョブも追従します。

VM のバックアップ方法

  1. VM の 変更ブロック トラッキング（CBT） がオフの場合はオンにします。
    • ライセンスのあるホストでは自動で行われます。
    • 無償のホストでは、CBT は VM の電源がオフのときにしかオンにできません。BackupZit は、VM がオフになっている最初のバックアップでこれを行います。それまでは毎回ディスク全体を読み取り、実行に警告が表示されます。
  2. スナップショット backupzit_… を作成します。ゲストで VMware Tools が動作している場合、スナップショットは 静止化（quiesce）されます。先にアプリケーションとファイル システムがフラッシュされ、バックアップはアプリケーション整合性を持ちます。VMware Tools がない場合はクラッシュ整合性です。Linux VM には open-vm-tools、Windows VM には VMware Tools をインストールしてください。
  3. CBT が読み取るブロックを報告します:
    • 初回のバックアップでは使用中のブロックのみ;
    • 以降は前回のバックアップ以降に変更されたブロックのみ。
  4. 稼働中の VM はディスクをロックしています。そのため、ディスクをデータストア上でコピーし（シン）、スナップショットはすぐに削除 されます（通常は数秒後）。その後、コピーを HTTPS で読み取って削除します。電源がオフの VM は直接読み取られます。
  5. VM の構成（.vmx）と NVRAM がバックアップとともに保存されます。

テスト環境での例: 8 GB ディスク（使用中 1.6 GB）の Debian VM。最初のバックアップは 1.6 GB を読み取りました。50 MB の新しいデータの後の次のバックアップは 70 MB を読み取り、23 秒かかりました。

VM の復元

復元ウィザード（仮想マシン全体）か、アクティビティのバックアップのページを使います。次を選びます:

  • 元の VM と並ぶ新しい VM として: 新しい名前、UUID、MAC アドレスを持つコピー。既定の名前は元の名前に -restored- と日付を付けたものです。クラウド イメージの netplan match: macaddress など、古い MAC アドレスに結び付いたゲストのネットワーク設定はコピーには適用されません。
  • 元の VM の代わりに: 電源を切ってディスクを置き換える を選ぶと、BackupZit は次を行います:
    • VM の電源を切り、スナップショットを削除する;
    • 現在のディスクの名前を ….replaced-DATE.vmdk に変更する（復元した VM が動作したら削除してください）;
    • 元の名前の新しいディスクにバックアップを書き込み、CPU とメモリをバックアップと同じに設定する。
    VM の UUID、ネットワーク アダプター、MAC アドレスは保持されます。VM が削除されていた場合は、元の ID で作成し直されます。
  • ESXi ホストとデータストア: 別のホスト、または同じホストの別のデータストア。
  • 復元後に VM を起動。

ディスクはシン形式で復元され、データのあるブロックだけが書き込まれます。CD/DVD ドライブに接続していた ISO イメージはバックアップに含まれないため、それらのドライブは空のままになります。

インスタント リカバリー

すぐに、バックアップから実行 を選ぶと、先にディスクをコピーせずに数秒で VM を起動できます。ホストのプロキシ エージェント（Linux エージェントである必要があります）が VM のディスクをバックアップから直接 NFS で提供し、ホストがそれをデータストア backupzit-<agent> としてマウントして VM を実行します。VM による変更はエージェント上（/var/lib/backupzit/instant-esxi、そのための空き容量が必要）に保持されます。バックアップ自体は変更されず、VM がそこから実行されている間は保持によって残されます。元の VM がまだ存在する場合、インスタント VM には新しい UUID と新しい MAC アドレスが付きます。

実行ページで、VM が正しく動作したら:

  • 完了する と、ホストのデータストアにコピーされます。VM がシャットダウンされ（VMware Tools が動作していればそれを使用）、ディスクが vmkfstools でシン形式でコピーされ、データストアから登録されて再起動します。無償の ESXi ライセンスには Storage vMotion がないため、ディスク サイズに応じて短いダウンタイムが必要です。コピーに失敗した場合、VM はバックアップから実行され続けます。
  • 破棄 すると、VM はすべての変更とともに停止・削除されます。

エージェントは ESXi ホストのアドレスに対してのみ、ポート 2049 で NFS に応答します（マシンのポート 111 の rpcbind に登録するか、ポート 111 に自分で応答します）。間にファイアウォールがある場合は、ホストからエージェントへのこれらのポートを開いてください。最後のインスタント VM が完了または破棄されると、データストアは削除され、NFS サーバーは停止します。

個別ファイル

バックアップのページの ファイルを参照（または復元ウィザードの 仮想マシン内のファイル）で VM のディスクを開きます。NTFS、ext2/3/4、XFS（LVM 上も含む）を参照し、ファイルをダウンロードしたり、任意のエージェントに復元したりできます。

コマンドライン

これらのコマンドは任意のエージェントで実行できます。ESXi のパスワードは BACKUPZIT_VMWARE_PASSWORD に設定します:

backupzit-agent vmware list    --host 192.168.1.20 [--user root]
backupzit-agent vmware backup  --host … --repo … [--vmid N,N]
backupzit-agent vmware restore --host … --repo … --vmid N [--new] [--name NAME] [--datastore DS] [--overwrite] [--start] SNAPSHOT|latest

vmware list はホストの証明書と SSH キーのフィンガープリントを表示します。--thumbprint と --ssh-host-key で渡すと、コマンドラインでもピン留めできます。

未対応

  • vCenter。 各 ESXi ホストを直接追加してください。
  • 独自のスナップショットを持つ VM。 ディスクが差分になっているため、先にスナップショットを削除または統合してください。
  • 一部のディスクの種類。 RDM（Raw Device Mapping）と独立型ディスク。
  • Windows プロキシ エージェントによるインスタント リカバリー。 インスタント リカバリーには Linux プロキシ エージェントが必要です。
