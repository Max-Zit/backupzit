バックアップ ジョブとスケジュール

ジョブは、どのエージェントで何をバックアップし、どこに保存し、いつ実行し、バックアップをいくつ保持するかを定義します。

ジョブの作成

  1. バックアップ ジョブに移動し、新しいバックアップ ジョブに入力します。
  2. エージェントとストレージ ターゲットを選びます。
  3. バックアップ対象を選びます:
    • ファイルとフォルダー — エージェント上のパスを 1 行に 1 つ。例: C:\Users、D:\Data、/home、/etc。
    • ディスク イメージ — ディスク全体または選択したパーティション。空のディスクや新しいハードウェアに復元できます。ディスク イメージを参照してください。
    • Linux システム — Linux マシンのすべてのファイル システムとディスク レイアウト。空のディスクへ、または Proxmox VM として復元できます。Linux システム バックアップを参照してください。
    • 仮想マシン（Proxmox VE、Hyper-V、VMware） — ハイパーバイザー ホストの VM（と Proxmox コンテナー）を、ゲストにエージェントを入れずにバックアップします。Proxmox または Hyper-V ホスト上のエージェントが、VMware ESXi ではホストのプロキシ エージェントがバックアップします（エージェント一覧で ESXi ホストを選択）。Proxmox VE、Hyper-V、VMware ESXi を参照してください。
    • データベース — エージェントのマシン上の SQL Server、PostgreSQL、MySQL/MariaDB。ログ バックアップにより任意の時点に復元できます。データベースを参照してください。
    • NAS / ファイル共有 — エージェントが読み取る SMB または NFS 共有。下記を参照してください。
    • Microsoft 365 — Exchange Online のメールボックス、予定表、連絡先、OneDrive、SharePoint サイト。任意のエージェントが Microsoft Graph 経由で読み取ります。Microsoft 365 を参照してください。
  4. 必要に応じて除外を 1 行に 1 つ追加します。すべてのフォルダーで有効な名前パターン（*.tmp、node_modules、Thumbs.db、*.iso）、またはそのファイルやフォルダーだけに有効な完全パス（C:\Data\Temp、/srv/www/cache、ワイルドカードも可: D:\VMs\*.iso）。Windows では完全パスの大文字と小文字は区別されません。
  5. バックアップの保持とスケジュールを設定し、ジョブを作成します。

NAS とファイル共有（SMB、NFS）

NAS / ファイル共有ジョブは、NAS（Synology、QNAP、TrueNAS、Windows ファイル サーバーなど）に何もインストールせずにネットワーク共有をバックアップします。共有に到達できる任意のエージェントを選び（そのエージェントが共有を読み取ってバックアップを書き込みます）、次を入力します:

  • 共有: smb://nas01/data（フォルダー付きも可: smb://nas01/data/Office）または nfs://nas01/volume1/data（エクスポート パス）。
  • SMB の場合はアカウント（ユーザー、任意のドメイン、パスワード — 暗号化して保存）。空欄はゲスト アクセスです。NFS はエージェント マシンのエクスポートへのアクセス権を使います（NAS でそのアドレスを許可してください）。
  • バックアップする共有内のフォルダーを 1 行に 1 つ（空欄: 共有全体）と、#recycle、@eaDir、.snapshot などの除外。

実行のたびに、エージェントは共有に接続し（Windows エージェントは UNC パス \\nas01\data 経由、SMB のみ。Linux エージェントは /mnt/backupzit-nas の下に読み取り専用でマウント。SMB には cifs-utils、NFS には nfs-common または nfs-utils が必要で、Proxmox VE には両方あります）、終了後に切断します。バックアップは通常のファイル バックアップです。重複排除された増分バックアップで、保持、コピー ジョブ、復元テスト、参照、ファイル復元が使えます。元の場所に復元は共有を書き込み可能で再接続してファイルを書き戻します。または任意のエージェント上のフォルダーに復元するか、ダウンロードします。

開いているファイルとロックされたファイル（VSS）

Windows では、エージェントはボリューム シャドウ コピー サービスを使います。ボリュームの一貫したある時点のスナップショットを作成してそこからバックアップするため、開いているファイル（Outlook の PST、データベース、編集中のドキュメント）も一貫してバックアップされます。VSS に対応したアプリケーション（SQL Server など）は、スナップショットの作成前にデータをディスクに書き出します。

スケジュール

オプション例
指定した時刻平日の毎日 22:00、または毎日 12:00 と 18:00。チェックした曜日に 1 日最大 3 回。
繰り返し月曜～金曜の 08:00～18:00 に 2 時間ごと。間隔は 15 分～12 時間。
月 1 回毎月 1 日 23:00。
手動のみ今すぐバックアップを実行をクリックしたときだけ実行されます。

時刻はコンソール サーバーのタイムゾーンです（アプライアンスでは 設定 → ネットワーク → タイムゾーン、またはセットアップ メニューの項目 9。初期値は UTC）。予定時刻にエージェントがオフラインの場合、バックアップはキューで待機し、エージェントが戻るとすぐに開始されます。予定されているすべての実行はカレンダーで確認できます。

保持: バックアップをいくつ残すか

スナップショットは、いずれかのルールで選ばれれば保持されます:

  • 最新 — 最新の N 個のバックアップ。
  • 毎日 — バックアップがある直近 N 日の各日の最新バックアップ。
  • 毎週 — 直近 N 週の各週の最新バックアップ。
  • 毎月 — 直近 N か月の各月の最新バックアップ。

例: 最新 3、毎日 7、毎週 4、毎月 6 で、約 20 の復元ポイントで約半年分の履歴を保持します。実行が成功するたびに、選ばれなくなったスナップショットは削除され（アクティビティでは期限切れと表示）、どのスナップショットも使わなくなったデータはストレージから削除されます。すべて 0 にするとすべて保持されます。

重複排除のおかげで長期保持は低コストです。変更されていないデータは、何個のスナップショットが参照していても一度だけ保存されます。

バックアップ コピー ジョブ（3-2-1）

バックアップ コピー ジョブは、別のジョブのバックアップを 2 つ目のストレージ ターゲットにコピーします。たとえば、オフィスの NAS への夜間バックアップを、S3 やオフサイトの強化リポジトリにコピーします。ジョブ フォームでバックアップ コピーを選び、コピー元のジョブとコピー先のストレージを選択します。

  • コピーはソース ジョブのエージェントが行います。保護対象のマシンを再度読み取ることはありません。
  • コピー先にまだないデータだけを転送し、コピー先のキーで再暗号化します。
  • スケジュールソース ジョブの各バックアップ後（既定）でコピーを最新に保ちます。通常のスケジュールも使えます。たとえば低速なインターネット回線なら毎晩 1 回。
  • コピーには独自の保持設定があります。例: NAS では毎日 7、クラウドでは毎月 12。
  • コピーされたファイル バックアップと VM バックアップ（Proxmox VE、Hyper-V、VMware）は、元のバックアップと同様にコピー実行のページまたは復元ウィザードから復元できます。VM 全体、VM ディスクの個別ファイル、Proxmox のインスタント リカバリが可能です。0.29 より古いエージェントがコピーした VM バックアップはこの方法では復元できません。新しいエージェントによる次回のコピー実行で、最新のコピーが復元可能になります。ディスク イメージのコピーはコマンドライン エージェントで復元します。

ジョブの変更

ジョブを開き、ジョブを編集を展開します。名前、フォルダーと除外（ファイル ジョブ）、VM（VM ジョブ）、スケジュール、保持、速度制限、圧縮レベル、コマンドを変更できます。ジョブのバックアップが 1 つのチェーンのままになるよう、エージェント、ストレージ ターゲット、イメージ ジョブのディスクは変更できません。ジョブを移すには新しいジョブを作成します。古いバックアップも移す必要がある場合はコピー ジョブを併用します。変更は次回の実行から適用され、監査ログに記録されます。4 アイズ承認が有効な場合、保持期間の短縮は 2 人目のユーザーの承認を待ちます。それ以外の変更はすぐに保存されます。

レプリカ（Proxmox VE）

Proxmox の VM ジョブは、ゲストの停止状態の最新コピーを任意のノードに保持でき、ゲストが失われた場合はワンクリックで起動できます。Proxmox VE → レプリケーションを参照してください。

速度制限

ジョブ フォームの詳細設定にあるアップロード速度の上限は、エージェントがストレージにデータを送る速度を MB/s 単位で制限します。たとえば 08:00～18:00 は 10 MB/s にすれば、業務時間中のバックアップでもオフィスの回線を使えます。時間帯外ではジョブは全速で実行されます。時刻はエージェントのローカル時刻で、時間帯は深夜 0 時をまたいでも構いません（22:00～06:00）。制限はバックアップとコピー ジョブ（2 つ目のストレージへのアップロード）に適用され、復元には適用されません。復元は常に全速で実行されます。

圧縮と重複排除

すべてのバックアップは重複排除されます。リポジトリにすでにあるデータ（同じジョブの以前のバックアップや、同じストレージ ターゲット上の他のジョブのもの）は再保存されません。新しいデータはその後 zstd で圧縮されます。小さくならない部分（動画、アーカイブ、暗号化ファイル）はそのまま保存されます。暗号化は圧縮の後に行われます。

圧縮レベルはジョブの設定です（ジョブを編集 → 詳細設定）:

レベル使用する場面
標準（推奨）高速で良好な圧縮。ほぼすべてのジョブに適しています。
高速負荷の高いマシンや性能の低いマシンで CPU 使用量を抑えます。バックアップはやや大きくなります。
最大通常は標準より 5～15 % 小さくなりますが、圧縮は数倍遅くなります。低速な上り回線や有料のクラウド ストレージで、マシンの CPU に余裕がある場合に。
オフすでに圧縮されたデータ向け。バックアップを大きくせずに CPU を節約します。

レベルは次回の実行から新しいデータに適用されます。既存のバックアップは変わらず、復元がレベルに依存することはありません。実行ページには結果が表示されます: 新しいデータの圧縮率（例: 2.4×）と、読み取ったデータのうちすでに保存されていた割合（重複排除）。

バックアップ前後のコマンド

管理者は、各バックアップの前後にエージェント上でコマンドを実行するようジョブを設定できます。たとえばデータベースのダンプ、一貫したコピーのためのサービス停止、通知など:

pg_dump -U postgres app > /var/backups/app.sql          # Linux, before
sqlcmd -S . -Q "BACKUP DATABASE app TO DISK='D:\dump\app.bak'"   # Windows, before
  • コマンドはエージェントのサービス アカウント（Linux では root、Windows では SYSTEM）で sh または cmd により実行されます。複数行も使えます。表示と変更ができるのは管理者だけです。そうでないと、バックアップ オペレーターがすべてのマシンで何でも実行できてしまいます。
  • 前のコマンドが失敗した場合（終了コードが 0 以外）、または時間制限（既定 30 分）を超えた場合、バックアップは実行されず、コマンドの出力とともに実行が失敗します。
  • 後のコマンドはバックアップが失敗した場合にも実行されるため、最初のコマンドが停止したものを再開できます。バックアップ後のコマンドが失敗すると、実行は警告になります。
  • どちらも BACKUPZIT_STAGE（pre または post）、BACKUPZIT_JOB、BACKUPZIT_JOB_ID、BACKUPZIT_RUN_ID を受け取り、バックアップ後には BACKUPZIT_STATUS（success、warning、failed）も受け取ります。
  • VM ジョブでは、コマンドは VM 内ではなくハイパーバイザー ホスト（または VMware プロキシ）で実行されます。コピー ジョブにはコマンドがありません。

実行、無効化、削除

  • 今すぐバックアップを実行（コピー ジョブでは今すぐコピー）でジョブがすぐにキューに入ります。
  • 復元をテストは最新バックアップからランダムなサンプルを復元して検証します（復元を参照）。
  • 無効にするはジョブを失わずにスケジュールを一時停止します（4 アイズ承認が有効な場合は 2 人目のユーザーの承認が必要）。
  • 削除はジョブを削除します。既存のバックアップはストレージに残り、アクティビティから引き続き復元できます。

保持の一時停止

ジョブのバックアップがランサムウェアや大量削除のように見えた場合、ジョブ ページに保持は一時停止中ですと表示されます。誰かがマシンを確認して確認済み — 保持を再開をクリックするまで、バックアップは削除されません（4 アイズ承認が有効な場合は 2 人目のユーザーの承認が必要）。ランサムウェア対策を参照してください。

バックアップ実行で報告される内容

アクティビティで実行を開くと、ファイル数、新規/変更ファイル、読み取ったデータ、アップロードした新しいデータ（重複排除と圧縮の後。圧縮率とすでに保存済みの割合を含む。圧縮を参照）、所要時間、読み取れなかったファイルが表示されます。読み取れないファイルがある実行は警告のステータスで終了します。残りのデータはバックアップされています。
