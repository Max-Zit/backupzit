トラブルシューティングと FAQ

エージェントがオフラインと表示される

  • マシンの電源は入っていて、サービスは動作していますか？ Windows: Get-Service backupzit-agent、Linux: systemctl status backupzit-agent。
  • マシンからコンソールに到達できますか？ Test-NetConnection backup-server -Port 8443 または curl -k https://backup-server:8443/login。
  • エージェントのログ: C:\ProgramData\backupzit\agent.log、Linux では /etc/backupzit/agent.log または journalctl -u backupzit-agent。「fingerprint mismatch」はコンソールの証明書が変わったことを意味します — エージェントを登録し直してください。

バックアップが失敗した

アクティビティで実行を開くと、メッセージに原因が表示されます。よくある原因:

メッセージに含まれる語対処
host key mismatch / fingerprintSFTP サーバーのキーが変わったか、フィンガープリントの入力が誤っています。サーバーで ssh-keygen -lf を使って確認してください。
permission denied / access deniedストレージの資格情報またはフォルダーの権限です。SFTP/SMB クライアントでログインを試してください。
no space left / quotaストレージがいっぱいです。保持期間を短くするか容量を追加してください。期限切れのバックアップは次の実行後に領域を解放します。
repository is locked同じリポジトリで別の処理（例: クリーンアップ）が実行中です。実行は 30 分間再試行します。古いロックは自動的に解除されます。
wrong password / recovery keyリポジトリが別のキーで作成されています — ジョブが正しいストレージ先を使っているか確認してください。
bucket has no Object Lock enabledObject Lock なしで作成されたバケットに変更不可が要求されました。Object Lock を有効にした新しいバケットを作成してください。

その他のメッセージ

状況対処
「no matching backup disk is connected」ローテーション用 USB ディスクのいずれかを接続してください（メッセージに必要なラベルと、接続されているラベル付きディスクが表示されます）。復元には、バックアップの実行に表示されたディスクそのものが必要です。
「several backup disks are connected」ローテーション用ディスクは一度に 1 台だけ接続してください。
復元テストが失敗した実行を開くと、メッセージに破損したファイルやブロック、または理由（例: ストレージ上でバックアップが削除された）が表示されます。リポジトリに対して backupzit-agent check --read-data を実行し、ストレージを確認して新しいバックアップを開始してください。変更不可のストレージでバックアップが削除された場合は、ランサムウェア対策 を参照してください。
バックアップが 不審 とマークされたマシンにランサムウェアや大量削除（例: 同期フォルダーが空になった）がないか確認してください。問題がなければ（例: 計画的な移行）、ジョブのページで 確認済み — 保持を再開 をクリックします。
Let's Encrypt: 「could not verify … is port 80 … reachable」HTTP 確認にはインターネットからポート 80 に到達できる必要があります。社内のコンソールでは Cloudflare 経由の DNS 確認を使ってください。
Let's Encrypt: 「no Cloudflare zone … is accessible with this token」トークンには、コンソールの名前を含むゾーンに対する Zone → DNS → Edit の権限が必要です。
「HTTPS port 443: … permission denied」または「address already in use」別のプログラムがポートを使っているか、サービスが 1024 未満のポートを使えません（パッケージと同様に CAP_NET_BIND_SERVICE 付きで実行してください）。設定 → 証明書 で別のポートを選んでください。
更新: 「updates from the console need the Linux package of the console」コンソールが deb/rpm パッケージからインストールされていません（例: 評価モード）。インストールしたのと同じ方法で更新してください。
更新: 「the release is not signed with a BackupZit release key」更新元に公式リリースがないか、途中でファイルが改変されています。公式のアドレスから再度ダウンロードしてください。
更新: 状態が rolled-back新しいバージョンが起動しなかったため、以前のバージョンとそのデータベースが復元されました。起動に失敗したときのログは更新ページにあります。サポートに送ってください。
オペレーティング システム: 「no supported package manager」オペレーティング システムの更新は Debian、Ubuntu（apt）と AlmaLinux、Rocky Linux、RHEL（dnf）でサポートされています。
コンソールのバックアップ: 「the backup was made by a newer BackupZit」復元する前に、新しいコンソールにバックアップを作成したバージョン以降をインストールしてください。
コンソールのバックアップ: 「console backups need network storage」SFTP、S3、SMB、Azure、または強化リポジトリのストレージ先を選んでください。エージェントのローカル パスにはコンソールから到達できません。
「サインインの失敗が多すぎます」誤ったパスワードが繰り返されたため、アドレスがブロックされました: 既定では 30 分、繰り返すとさらに長くなります。管理者は 設定 → サインインとセキュリティ でブロックを解除できます。サーバー上では backupzit-server --unblock-ip all ですべてのブロックを解除できます。アカウントが恒久的にロックされることはありません。
2 要素サインイン用の電話を紛失したリカバリー コードのいずれかを使います。ない場合は、管理者がユーザーのページで 2 要素をリセットします。最後の管理者は、サーバー上で backupzit-server --set-admin-password を使って自分のパスワードをリセットできます。
「your directory account is not in any BackupZit group」設定 → LDAP / Active Directory で対応付けたグループのいずれかにユーザーを追加するか、さらにグループを対応付けてください。そのページの テスト で、ユーザーに対して見つかったグループを確認できます。
API が 401 / 403 を返す401: トークンがない、失効している、期限切れ、または所有者が無効化されている。403: トークンのロールが要求に対して低すぎます。
Azure: AuthenticationFailed / AuthorizationPermissionMismatchアカウント キーが誤っているか、SAS トークンに読み取り、書き込み、削除、一覧表示の権限がないか、期限が切れています。
復元した Windows Server 2012 R2 / Windows 8.1 の VM が Hyper-V 第 2 世代で起動しない（「hash was denied (DBX)」）Microsoft がセキュア ブート用の古いブートローダーを失効させました。その VM のセキュア ブートをオフにするか、バックアップ前にシステムを更新してください。

仮想マシン、Linux システム、新しいハードウェア

状況対処
Proxmox: 「the guest is running and one of its disks is on storage without snapshot support」稼働中のゲストには LVM-thin、ZFS、Ceph RBD、qcow2 のディスクが必要です。ディスクを移動する（Disk Action → Move Storage）か、ゲストを停止した状態でバックアップしてください。
Hyper-V: 実行に「crash-consistent」と表示されるゲストがチェックポイントの準備をできませんでした。Windows ゲストでは、VM の設定で Hyper-V 統合サービス（Backup (volume shadow copy)）が有効か確認してください。Linux ゲストには hyperv-daemons（RHEL）または linux-cloud-tools / hyperv-daemons（Debian/Ubuntu）をインストールしてください。
VMware: 「SSH off」または「SSH to …: connection refused」ESXi ホストで SSH を有効にしてください: Host → Actions → Services → Enable Secure Shell（ホストと一緒に起動するよう設定）。復元、および無償ライセンスでのバックアップに必要です。
VMware: 「changed block tracking is off and can be enabled … only while the VM is off」無償の ESXi ライセンス: VM を一度シャットダウンしてからジョブを実行してください。BackupZit が変更ブロック トラッキングを有効にし、以降のバックアップは変更されたブロックだけを読み取ります。
VMware: 「copy the disk on the datastore (needs free space …)」稼働中の VM はデータストア上で一時的にコピーされます。そこに（ディスクの使用量分の）空き容量を作るか、VM を停止した状態でバックアップしてください。
VMware: 「… is a snapshot delta disk」VM に独自のスナップショットがあります。ESXi Host Client で削除または統合してください（Snapshots → Delete all）。
VMware: 「the ESXi certificate changed」ホストが再インストールされたか、別のマシンがそのアドレスで応答しています。想定どおりであれば、エージェントでホストを削除して再度追加し、新しい証明書をピン留めしてください。
VMware: VM ディスクの横に *.replaced-DATE.vmdk ファイルがある元の場所に復元した VM の古いディスクです。復元した VM が動作したら、データストア ブラウザーで削除してください。
Hyper-V: VM ディスクの横に *.replaced-DATE ファイルがある元の場所に復元した VM の古いディスクです。復元した VM が動作したら削除してください。
Proxmox のインスタント リカバリー: VM が起動しない、またはハングするディスク サーバーを確認してください: ノードで systemctl status backupzit-instant-ID と journalctl -u backupzit-instant-ID。バックアップ ストレージに到達できる状態を保つ必要があります。リポジトリを読み取れないと、VM のディスク読み取りが止まります。
Proxmox のインスタント リカバリー: 「efidisk0 stays on storage backupzit-instant」VM の稼働中は QEMU が EFI 変数ストアを移動できません。VM をシャットダウンして qm disk move ID efidisk0 STORAGE --delete 1 を実行してください。これはバックアップに依存しません。
Proxmox: 「runs on node X; install the BackupZit agent on X」ゲストが移行されました。すべてのノードにエージェントをインストールし、各ノードのゲストはそのノードのエージェントでバックアップしてください。
Proxmox のバックアップや復元が遅い、ストレージ サーバーで SFTP「connection lost」「message authentication code incorrect」Proxmox ホストの Intel e1000e ネットワーク カードの既知の問題です（ログ: 「Detected Hardware Unit Hang」「Reset adapter unexpectedly」）。オフロードを無効にしてください: ethtool -K eno1 tso off gso off gro off を、/etc/network/interfaces のインターフェイスに post-up 行として追加します。
ファイルの参照: 「stored on a local path of the agent」コンソールが読み取れるのはネットワーク ストレージ上のバックアップだけです。エージェントで backupzit-agent pve ls/extract または image-ls/image-extract を使ってください。
Linux システムの復元: 「missing programs …」復元を行うマシンに表示されたパッケージをインストールするか、それらを含む BackupZit の Linux リカバリ ISO から起動してください。
復元した Linux マシンがネットワークに接続できないネットワーク設定が古い MAC アドレスに結び付いていました（netplan match: macaddress）。別のハードウェア で復元するか、/etc/netplan/ の match 行を削除してください。
復元した Windows が INACCESSIBLE_BOOT_DEVICE で停止する異なるハードウェアに復元 で再度復元するか、リカバリー ISO から起動して backupzit-agent prepare-hardware --disk 0 [--drivers E:\Drivers] を実行してください。
復元したマシンのコピーが元のエージェントとして表示される新しい Proxmox VM への復元では、コピー内のエージェントの登録が自動的に解除されます。それ以外のコピーでは、コピー内の agent.json を削除し、新しいマシンとして登録してください。
エージェントの更新が完了しないC:\ProgramData\backupzit\updates または /var/tmp/backupzit-updates のインストーラーのログを確認してください。0.21 より前のエージェントは一度手動で更新する必要があります。
トレイ アイコンが表示されない時計の横の ^ 矢印をクリックして BackupZit のアイコンをタスク バーにドラッグするか、スタート メニューから BackupZit Agent を起動してください。

バックアップが「警告」で終わる

一部のファイルを読み取れませんでした — 通常は、VSS が使えないときにアプリケーションがロックしているファイルや、エージェントに権限のないファイルです。一覧は実行ページにあります。それ以外はすべてバックアップされています。

バックアップが遅い

  • 最初のバックアップはすべてを読み取って送信します。以降は変更されたファイルだけを読み取り、新しいデータだけを送信します。
  • ストレージまでのネットワーク経路（Wi-Fi、VPN、クラウド ストレージの場合はインターネットのアップロード速度）を確認してください。
  • キャッシュ、一時ファイル、不要なメディアを除外してください。

FAQ

NFS は使えますか？

NFS（または SMB）共有を バックアップ するには、NAS / ファイル共有 ジョブを作成します。Linux エージェントが実行のたびにエクスポートをマウントします。バックアップを NFS に 保存 するには、エージェントでエクスポートをマウントし（Linux: /etc/fstab）、/mnt/nfs-backup のような ローカル / マウント済みパス のストレージ先を使います。Windows マシンには SMB のストレージ先が適しています。

バックアップを別のストレージに移動できますか？

リポジトリ フォルダー（またはバケットのプレフィックス）をそのままコピーし — それ自体で完結しています — 同じリカバリー キーで新しい場所を指すストレージ先を追加してください。

ジョブを削除するとバックアップも削除されますか？

いいえ。バックアップはストレージに残り、アクティビティやコマンドラインから復元できます。

コンソールが停止するとどうなりますか？

復旧するまで新しいスケジュール バックアップは開始されず、キューの実行はその後に続行されます。復元はリカバリーシートを使えば、コマンドラインからいつでも可能です。

バックアップにはどれくらいの容量が必要ですか？

最初のバックアップでは、圧縮後のデータ量とほぼ同じ容量に、保持する日数分の日々の変更が加わります。レポート ページで、ジョブごとの送信量を確認できます。
