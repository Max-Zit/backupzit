macOS エージェント（Apple シリコン）

macOS エージェントは、Apple シリコン搭載 Mac のファイルとフォルダーをバックアップします。最初の起動からサービスとして動作し、起動ディスクのバックアップはすべて APFS ローカル スナップショットから読み取り、Mac のファイル メタデータを保持します。メニュー バー アプリが状態を表示し、Mac のユーザーにしか許可できないアクセス権の設定を案内します。

要件

  • Apple シリコン（M1 以降、arm64）搭載で macOS 13 以降の Mac。Intel Mac 用のパッケージはありません。
  • インストールと登録のための、Mac の管理者アカウント。
  • フルディスクアクセスを許可する Mac のユーザー: macOS はほかの誰にも、スクリプトにもコンソールにもそれを許しません。
  • 他のエージェントと同様に、Mac はコンソールのエージェント用アドレス（通常はポート 8443）とストレージに到達できる必要があります。

インストール

  1. エージェントページで macOS エージェント — Apple シリコン（backupzit-agent_version_darwin_arm64.pkg）をダウンロードします。Windows と Linux のインストーラーと同様に、コンソール パッケージに同梱されています。
  2. Mac で .pkg を開き、インストーラーの指示に従います。Apple Developer ID で署名されていないパッケージの場合、macOS はまず確認を求めます: パッケージを右クリックして開くを選びます（新しい macOS では システム設定 → プライバシーとセキュリティ → このまま開く）。
  3. インストーラーの最後のページで許可すべきアクセス権が説明され、メニュー バー アプリが開きます。

パッケージがインストールするもの:

内容場所
エージェント プログラム/Library/BackupZit/bin/backupzit-agent
アンインストーラー/Library/BackupZit/uninstall.sh
メニュー バー アプリ/Applications/BackupZit.app
エージェント サービス（LaunchDaemon: root として動作し、起動時に開始、停止すると再起動）/Library/LaunchDaemons/com.backupzit.agent.plist
ログイン時のメニュー バー アプリ（LaunchAgent）/Library/LaunchAgents/com.backupzit.tray.plist
構成（root のみ、登録時に作成）/Library/Application Support/BackupZit/agent.json
ログ/Library/Logs/BackupZit/agent.log

プログラムは PATH に追加されません。ターミナルではフル パスで呼び出してください。

登録

サービスは Mac が登録される前からインストールされて動作しており、登録されるとすぐに作業を始めます。エージェントページの登録トークンを作成で、Windows と Linux のコマンドの隣に macOS のコマンドが表示されます。次の 3 つの方法から 1 つを選びます:

  1. インストール後にターミナルで（通常の方法）: 
    sudo /Library/BackupZit/bin/backupzit-agent enroll --code "BZ1-..."
  2. MDM で（Jamf、Intune、Mosyle…）: パッケージをインストールする前に、スクリプトでコードを root 所有のファイルに書き込みます: 
    echo "BZ1-..." | sudo sh -c 'umask 077; mkdir -p "/Library/Application Support/BackupZit"; cat > "/Library/Application Support/BackupZit/enroll-code"'
    その後パッケージを配布します。インストール時にこのコードで Mac が登録され、ファイルは削除されます。root 所有でないファイルは無視されます。登録済みの Mac を別のコンソールに移すのもこの方法です。
  3. パッケージの隣のファイル: コードを書いた backupzit-enroll.txt を、Mac の起動ディスク上の .pkg と同じフォルダーに置きます (たとえば /Users/Shared。USB メモリーやネットワーク共有からは、先に両方を Mac にコピーしてください。そのようなボリュームでは、どのファイルでも root のものだと称することができます)。Mac がまだ登録されていない間だけ、しかもほかの誰も書き込めなかった場合だけ使われます。ファイルは root または Mac の管理者のもので、名前は 1 つだけ、変更できるのは所有者だけであり、そのフォルダーは root または管理者のもので、ほかのユーザーは書き込めません (または /Users/Shared のようにスティッキー ビットがあります)。

インストール中にコンソールに接続できない場合、エージェントはコードを保持して再試行します。登録に失敗した場合、理由は /Library/Application Support/BackupZit/enroll-error.log にあります。その後ターミナルで登録してください。アップグレードと再インストールでは登録が保持されます。

アクセス権

macOS は一部のデータを、root として動作するものも含むすべてのプログラムから保護し、ユーザーがシステム設定で許可するまで読ませません。これらのアクセス権を許可できるのは Mac の前にいるユーザーだけです。インストーラーの最後のページとメニュー バー アプリがその手順を案内します。

エージェントのフルディスクアクセス

これがないと、バックアップから macOS が保護するフォルダーが抜け、APFS スナップショットも作成されません（バックアップされるものを参照）。

  1. システム設定 → プライバシーとセキュリティ → フルディスクアクセスを開きます。
  2. 一覧の下の + をクリックし、パスワードを入力します。
  3. Command-Shift-G を押し、/Library/BackupZit/bin/backupzit-agent と入力して return キーを押し、開くをクリックします。
  4. backupzit-agent の横のスイッチがオンになっていることを確認します。

+ の代わりにファイルを一覧にドラッグすることもできます: Finder で 移動 → フォルダへ移動… を選び、/Library/BackupZit/bin と入力して、backupzit-agent を一覧にドラッグします。

バックグラウンドのエージェント

インストール後、macOS は バックグラウンド項目が追加されました と表示します。システム設定 → 一般 → ログイン項目と機能拡張のバックグラウンドでの実行を許可で、backupzit-agent と BackupZit をオンのままにしてください。オフにするとエージェントは動作せず、バックアップは開始されません。

通知とログイン時に開く

  • 通知: メニュー バー アプリが求めたときに許可するか、後でシステム設定 → 通知 → BackupZit（通知を許可）で許可します。バックアップが失敗すると、アプリがそこでユーザーに知らせます。
  • ログイン時に開く: ログイン項目と機能拡張 → バックグラウンドでの実行を許可で BackupZit がオンである限り、メニュー バー アプリはログインのたびに開きます。

メニュー バー アプリとそのアシスタント

メニュー バーの BackupZit アイコンはエージェントの状態を表示します。そのメニューには、Mac の各ジョブの Back up now、Open console in browser、Hide this icon（次回のログインまで。バックアップは続行されます）があります。Permissions セクションには、バックグラウンドのエージェント、フルディスクアクセス、通知、ログイン時に開くが、それぞれ ✅ または ❌ 付きで一覧表示されます。項目をクリックすると、システム設定の該当ページが開きます。足りない許可は、ログインごとに一度、手順を示すダイアログでも説明されます。足りないものがある間は数秒ごとに自動で再確認するため、アクセス権が許可されるとすぐに ✅ が表示されます。エージェントは、フルディスクアクセスがないことを実行レポートでコンソールにも報告します。

ターミナルでの確認

/Library/BackupZit/bin/backupzit-agent status

通常のユーザーでも動作し、コンソール、ジョブ、full disk access: granted または denied（オンにすべきプログラムとともに）を表示します。

更新後のフルディスクアクセス

macOS はフルディスクアクセスをプログラムの署名に結び付けます。Apple Developer ID で署名されたパッケージは更新後もそれを保持します。Developer ID なしでビルドされた（アドホック署名の）パッケージは、自己更新のたびにそれを失います: バックアップが再び警告し、メニュー バー アプリは更新以降フルディスクアクセスがなくなったことを伝えます。もう一度許可してください: フルディスクアクセスの一覧で backupzit-agent を選び、− をクリックして削除し（オフにしてオンに戻すだけでは不十分です）、上記のとおり + で再度追加します。

バックアップされるもの

Mac エージェントは、他のエージェントと同様にファイルとフォルダーのジョブを実行します: /Users、/Applications、/ などのパス、{users} パス（/Users/<name>/Documents）とワイルドカード。すべての macOS エージェント を使った複数エージェント用のジョブでも同様です。

APFS ローカル スナップショット

起動ディスクのデータ ボリュームのファイル バックアップはすべて、Windows の VSS に相当する macOS の仕組みである APFS ローカル スナップショットから読み取られます: バックアップはすべてのファイルを同じ瞬間の状態で扱い、プログラムが書き込み続けているファイルも同様です。エージェントはスナップショットを作成し（tmutil localsnapshot）、読み取り専用でマウントしてそこからファイルを読み、バックアップ後にアンマウントして削除します。クラッシュで残ったスナップショットは次回の起動時に片付けられます。Time Machine 自身のスナップショットには一切触れません。実行レポートには Read from an APFS local snapshot of /System/Volumes/Data. と表示されます。

スナップショットにはサービス（root）とフルディスクアクセスが必要です。フルディスクアクセスがない場合や、ほかのボリューム上のパス（/Volumes: 外部ディスク、ネットワーク共有）では、ファイルはスナップショットなしで読み取られ、実行レポートにその旨が表示されます。

メタデータ

すべてのファイルとフォルダーとともに保存されるもの: 所有者とグループ、アクセス権、拡張属性（macOS 自身が管理する com.apple.provenance を除く）、ハード リンク、シンボリック リンク、BSD ファイル フラグ（不可視、ロック、nodump、append-only…。システム フラグはサービスのようにエージェントが root として動作する場合のみ）、作成日時、ナノ秒単位の変更日時。スパース ファイルはスパースのまま保たれ、APFS 上で穴が再び開けられます。

空のまま保存されるフォルダー

バックアップするフォルダーの下にある一部のシステム フォルダーは、空のフォルダーとして保存されます: ほかのボリューム（/Volumes）、スワップ（/System/Volumes/VM、/private/var/vm）、/System/Volumes 内のサポート ボリューム、/dev、一時ファイル（/private/tmp、/private/var/folders）、キャッシュ（/Library/Caches、/System/Library/Caches、~/Library/Caches）、ゴミ箱（~/.Trash、.Trashes）、Spotlight、FSEvents、書類のバージョン、ローカルおよび HFS+ の Time Machine バックアップ。/ をソースにした場合、/ がすでに表示しているデータ ボリュームのフォルダー（/Users、/Applications…）は二重に読み取られません。ジョブのソースとして指定したフォルダーは常に読み取られます（例: /Volumes/USB や ~/.Trash）。

実行レポートの警告

フルディスクアクセスがないと、macOS が保護するフォルダーは読み取れません: メール、メッセージ、Safari、デスクトップと書類、ほかのアプリのデータ、リムーバブル ボリュームとネットワーク ボリューム。ソースが /Users（/Users/Shared を除く）、/Library、/Volumes、またはそれらより上のフォルダー（/ など）に及ぶバックアップは、その場合 Full Disk Access is not granted to the BackupZit agent という警告で終わります。ほかのフォルダー（例: /opt/data）のバックアップでは警告は出ません。

復元

Mac のファイルは、すべてのファイル バックアップと同様に復元します: バックアップ全体または一部のパスだけを、フォルダーまたは元の場所へ、その Mac または別のエージェント上に。個別のファイルはコンソールからダウンロードできます。Mac 上での復元では、上記のメタデータが再び設定されます。Windows や Linux と同様に、復元は開いたフォルダーを通してのみ書き込み、パスでは書き込まないため、復元中に途中に置かれたリンクはたどられません。ロックされたファイルに上書きで復元する場合は、まずロックと append-only のフラグを解除し、保存されていたフラグを再び設定します（システム フラグは稼働中の Mac では解除できません）。

更新とアンインストール

エージェントページでは、他のエージェントと同様に Mac にも更新: version が表示されます（エージェントを参照）。エージェントはコンソールから .pkg をダウンロードし、署名済みのエージェント インストーラー一覧と SHA-256 チェックサムで検証し、1 回限りの launchd ジョブで Apple の installer を使ってインストールし、新しいバージョンで再起動します。launchd がそのジョブを拒否した場合、更新の実行は launchd のメッセージとともに失敗します。インストーラーのログは /Library/Application Support/BackupZit/updates にあります。署名されていないパッケージの更新後は、フルディスクアクセスを確認してください。

エージェント ページの削除でコンピューターからエージェントをアンインストールを選ぶと、プログラム、メニュー バー アプリ、LaunchDaemon と LaunchAgent、パッケージのレシートが削除されます。構成とログは残ります。手動でアンインストールするには:

sudo /Library/BackupZit/uninstall.sh            # keeps configuration and log
sudo /Library/BackupZit/uninstall.sh --purge    # deletes them too

--purge なしでは登録が退避される（agent.json.removed-date）ため、新しくインストールすると再びコードを求められます。アンインストール後は、プライバシーとセキュリティ → フルディスクアクセスから backupzit-agent を手動で削除してください。macOS はプログラムにそれをさせません。

Mac エージェントにできないこと

Mac では不可代わりに
Linux システム / ベアメタル バックアップコンソールは Mac 用のシステム ジョブを拒否します（is a Mac: back it up with a files job）: Mac のシステム ボリュームは Apple によって封印・署名されており、復元ではなく再インストールするものです。データはファイル ジョブでバックアップしてください。
ディスク イメージWindows のみ。
Hyper-V、Proxmox VE ホスト、VMware ESXi プロキシHyper-V ホスト（Windows）、Proxmox ノード（Linux）上のエージェント、または Linux のプロキシ エージェント。
NAS / ファイル共有ジョブ（SMB、NFS）当面は Windows または Linux のエージェント: Mac エージェントはまだ共有をマウントしません。
PostgreSQL / MySQL ジョブmacOS ではまだ検証されていません: Mac では復元をテストしてから使ってください。

Microsoft 365 ジョブは、インターネットにアクセスできる任意のエージェントで動作し、Mac でも同様です。

トラブルシューティング

状況対処
Mac が表示されない、またはオフラインと表示される登録されていること（backupzit-agent status、登録）と、ログイン項目と機能拡張 → バックグラウンドでの実行を許可で backupzit-agent がオンであることを確認してください。sudo launchctl print system/com.backupzit.agent でサービスを表示し、sudo /Library/BackupZit/bin/backupzit-agent service start で開始します。その後、他のエージェントと同様にコンソールへのネットワーク経路を確認してください（トラブルシューティング）。
「Full Disk Access is not granted to the BackupZit agent」、full disk access: deniedフルディスクアクセスのとおりに許可してください。
更新後にフルディスクアクセスがなくなったパッケージが Apple Developer ID で署名されていません: 一覧から − で backupzit-agent を削除し、再度追加してください（更新後のフルディスクアクセス）。
実行でファイルが「without a snapshot」で読み取られたと表示される「No APFS local snapshot … was taken」: フルディスクアクセスを許可してください。「Not on the startup disk's data volume」: パスが外部ディスクまたは共有上にあり、APFS ローカル スナップショットの対象外です。それでもバックアップはされます。その他の理由はメッセージに表示されます。
更新の実行が失敗した実行に理由が表示されます（例: launchd によるインストーラー ジョブの拒否）。インストーラーの出力は /Library/Application Support/BackupZit/updates にあります（エージェント ページのログを取得にも含まれます）。新しい .pkg を手動でインストールしても構いません。登録は保持されます。
Mac のシステム ジョブが拒否される想定どおりです: Mac エージェントにできないことを参照してください。

ログ

  • エージェント: /Library/Logs/BackupZit/agent.log（Console.app にも表示されます）。クラッシュのトレースは /Library/Logs/BackupZit/launchd.log に書き込まれます。
  • インストーラーによる登録: /Library/Application Support/BackupZit/enroll-error.log とインストーラーのログ /var/log/install.log。
  • 更新: /Library/Application Support/BackupZit/updates。
  • エージェントページのログを取得で、ログの末尾をコンソールに取り込めます（ログを参照）。
