Hyper-V 仮想マシン

BackupZit は Hyper-V ホスト上のエージェントから Hyper-V 仮想マシンをバックアップします。VM 内には何もインストールしません。Windows と Linux のゲストは稼働したまま取得されます。新しい VM として、または元の VM の代わりに復元できます。

セットアップ

  1. エージェント から Windows エージェント の MSI を Hyper-V ホストにインストールし、登録します。対応ホスト: Hyper-V の役割を持つ Windows Server 2016 以降、または Hyper-V を有効にした Windows 10/11。クラスターではすべてのホストにエージェントをインストールします。
  2. 1 分以内に、ホストが Hyper-V · N VMs のバッジ付きでエージェント ページに表示されます。
  3. バックアップ ジョブ でそのエージェントを選び、仮想マシン（Proxmox VE、Hyper-V、VMware） を選びます。次にいずれかを選択します:
    • ホストのすべての VM（後から作成した VM も対象）;
    • チェックを付けた個別の VM。

エージェントは Hyper-V 自身のインターフェイス（Hyper-V PowerShell モジュールと Windows Virtual Disk API）を使って動作します。コンソールは Hyper-V の資格情報を保存しません。

VM のバックアップ方法

  1. 一時的な 回復チェックポイント（backupzit_…）を作成します。これは Hyper-V がバックアップ アプリケーション向けに用意しているチェックポイントの種類です。Hyper-V はゲストに準備を求めます:
    • Windows ゲストは VSS を通じてアプリケーションのバッファーをフラッシュします。
    • Linux ゲストは、Hyper-V デーモン（hyperv-daemons / hv-vss-daemon）がインストールされていればファイル システムをフリーズします。
    ゲストがどちらもできない場合、チェックポイントはクラッシュ整合性で作成されます。実行ページにどちらが使われたかが表示されます。
  2. 回復チェックポイントにより、VM のディスクで Resilient Change Tracking（RCT）が有効になります。ディスクの隣に .rct と .mrt ファイルが作られます。最初のバックアップはディスク全体を読み取ります。その後は、前回のバックアップ以降に変更されたブロックを RCT が報告し、そのブロックだけを読み取ります。
  3. ディスクはチェックポイント時点の状態で、Virtual Disk API を通じて 1 MiB 単位で読み取られます。以前のチェックポイントのチェーンを含む VHDX と VHD ファイルが対象です。空のブロックは保存されず、リポジトリに既にあるブロックは再送信されません。
  4. チェックポイントは削除され、Hyper-V がバックグラウンドでマージします。
  5. VM の構成がバックアップとともに保存されます: 世代、CPU、メモリ、ネットワーク アダプター（スイッチ、VLAN、MAC アドレス）、ディスク コントローラー、セキュア ブート、TPM。

電源がオフの VM はチェックポイントなしで直接読み取られます。Windows Server 2016 より古いホスト（回復チェックポイントなし）では運用チェックポイントが使われ、毎回ディスク全体を読み取ります。

テスト環境での例: 3 GB ディスクの Linux VM。最初のバックアップは 3 GB を読み取りました。64 MB の新しいデータの後の次のバックアップは 96 MB を読み取りました。

Windows 10/11 では、VM の設定でオプションをオフにしていない限り、Hyper-V は VM の起動時に自動チェックポイントを作成します。BackupZit はこうしたチェックポイントにも対応しますが、サーバーでは自動チェックポイントをオフにすることをおすすめします（VM の設定 → チェックポイント）。

VM の復元

VM バックアップの実行（ジョブのページまたは アクティビティ）を開き、Hyper-V VM を復元 を使います。

元の VM と並ぶ新しい VM として

新しい MAC アドレスを持つ 2 台目の VM を作成し、元の VM と同じネットワークで稼働できるようにします。既定では、元の名前に「restored」と日付を付けた名前になります。この VM では自動チェックポイントがオフになり（Windows は新しい VM でオンにします）、起動してもチェックポイント ファイルが残りません。コピーが元の VM と並んで稼働し、中に BackupZit エージェントがある場合は 1 つのエージェントを使う 2 台のマシン を参照してください。

MAC アドレスに結び付いたゲストのネットワーク設定は、新しいアダプターには適用されません。たとえば Linux のクラウド イメージが使う netplan の match: macaddress です。

元の VM の代わりに

電源を切ってディスクを置き換える をオンにします。BackupZit は次を行います:

  • 既存の VM の電源を切る;
  • チェックポイントをマージする;
  • ディスクを復元したものと入れ替える。

VM の ID、ネットワーク アダプター、MAC アドレスは保持されるため、ジョブ、監視、ゲストのネットワークはそのまま動作します。

古いディスク ファイルは削除されず、….replaced-DATE に名前が変更されます。復元した VM が動作したら削除してください。

元の VM が存在しない場合は、新しい Hyper-V ID で作成し直されます。

オプション

  • 仮想ディスクのフォルダー: ホストの既定のフォルダー、または VM ディスクを置く任意のフォルダー。元の場所への復元では、新しいディスクは元のディスクの隣に置かれます。
  • 復元後に VM を起動。

復元した VM に適用されるもの

  • 仮想スイッチは名前で接続されます。ホストにそのスイッチがない場合、アダプターは未接続のままです。
  • 復元した VM にはすべて新しい世代 ID が付与され、Active Directory のドメイン コントローラーが復元を安全に検出できます。

個別ファイルの復元

実行の VM 一覧で ファイルを参照 をクリックすると、VM のディスク上のパーティションとボリュームが表示されます。NTFS、ext2/3/4、XFS（LVM 内も含む）を参照できます。そこからファイルをダウンロードしたり、任意のエージェントに復元したりできます。Proxmox VE とまったく同じように動作します。

コマンドライン

Hyper-V ホストで管理者として実行します:

backupzit-agent hyperv list
backupzit-agent hyperv backup  --repo ... [--vmid N,N]
backupzit-agent hyperv restore --repo ... --vmid N [--new] [--name NAME] [--folder D:\VMs] [--overwrite] [--start] SNAPSHOT|latest
  • --vmid は hyperv list が表示する番号です。BackupZit は VM の GUID から算出します。
  • --new を付けない場合、VM は元の場所に復元されます。
  • --overwrite は、既存 VM のディスクを置き換えることを確認します。

リポジトリのオプションはすべてのコマンドで共通です。コマンドライン リファレンス を参照してください。

未対応

  • 一部のディスクの種類。 共有 VHDX、VHD セット、パススルー ディスクはバックアップされません。
