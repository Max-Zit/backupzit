データベース: SQL Server、PostgreSQL、MySQL

BackupZit は、データベース マシン上のエージェントから、データベース サーバー自身のツールを使ってデータベースをバックアップします: Windows の Microsoft SQL Server、Linux の PostgreSQL と MySQL/MariaDB。完全バックアップはジョブのスケジュールで実行され、数分ごとのログ バックアップにより、1 つのデータベースを任意の時点 — たとえば誤った DELETE の 1 分前 — に復元できます。

ジョブの作成

バックアップ ジョブ で、データベース マシンのエージェントに種類 データベース のジョブを作成し、次を選びます:

  • データベース サーバー: Microsoft SQL Server、PostgreSQL、MySQL/MariaDB。後から変更できません。
  • インスタンスまたはポート: SQL Server のインスタンス（既定のインスタンスなら空欄、例: SQLEXPRESS）または PostgreSQL のポート（5432 なら空欄）。MySQL/MariaDB にはローカル ソケットで接続します。
  • データベース: 1 行に 1 つの名前、または空欄ですべてのユーザー データベース — 後から作成したデータベースも自動的に含まれます。
  • ログを … 分ごとにバックアップ: 例: 15 — トランザクション ログ（SQL Server）、アーカイブ済み WAL（PostgreSQL）、バイナリ ログ（MySQL）。完全バックアップの時点への復元で十分なら空欄にします。
  • スケジュール は完全バックアップのスケジュールです（例: 毎日 22:00）。

バックアップは重複排除され（変更のないデータは再送信されません）、ほかのバックアップと同様に暗号化されます。保持は完全バックアップを数えます。ログ バックアップは、基になる完全バックアップがある限り保持されます。実行ページには各バックアップの内容が表示されます。

Microsoft SQL Server

  1. SQL Server が動作する Windows マシンにエージェントをインストールします（2012 以降の任意のエディション、Express を含む）。
  2. エージェントは NT AUTHORITY\SYSTEM として動作し、Windows 認証で接続します。インスタンスごとに 1 回、このアカウントに sysadmin ロールを付与します: 
    sqlcmd -S .\SQLEXPRESS -E -Q "ALTER SERVER ROLE sysadmin ADD MEMBER [NT AUTHORITY\SYSTEM]"
  • 各実行は、データベースごとに 1 つのバックアップ ファイル（BACKUP DATABASE / BACKUP LOG … WITH CHECKSUM）をインスタンスの既定のバックアップ フォルダーに書き込み、保存してから削除します。実行中、フォルダーには最大のデータベース分の空き容量が必要です。
  • ログ バックアップを有効にすると、完全バックアップがログ チェーンを開始します。無効の場合、完全バックアップは COPY_ONLY で取得され、ほかのバックアップ計画やメンテナンス計画を妨げません。
  • ログ バックアップは復旧モデルが full または bulk-logged のデータベースで取得されます。simple モデルのデータベースは完全バックアップのみです。master、model、msdb を含めるには システム データベース をオンにします。

PostgreSQL

エージェントはローカル ソケットで postgres アカウントとして動作します — バックアップのための設定は不要です。完全バックアップは、クラスター全体（pg_basebackup）、ロール（pg_dumpall --globals-only）、各データベースの pg_dump を保存します。

ポイントインタイム リカバリー には WAL アーカイブが必要です。ログ バックアップを有効にすると、最初の完全バックアップが ALTER SYSTEM で設定します: archive_mode = on と、完了した WAL セグメントを /var/lib/backupzit-pg/wal にコピーする archive_command。ログ バックアップがそこに保存して削除します。archive_mode は PostgreSQL の 再起動 1 回（systemctl restart postgresql）の後に有効になり、実行でその旨が表示されます。ほかのツールが既に archive_command を使っている場合、BackupZit はそれに手を触れず、ポイントインタイム リカバリーなしでバックアップします。ログ バックアップを止めた場合（ジョブの無効化や削除）は、フォルダーがいっぱいにならないようアーカイブを再びオフにしてください（ALTER SYSTEM RESET archive_mode、再起動）。

  • データベースを復元（完全バックアップの時点）: pg_dump から稼働中のサーバーへ、新しい名前で、またはデータベースを置き換えて。
  • 特定の時点（または最新）: エージェントはクラスターのバックアップを空きポートの一時インスタンス（ソケットのみ、ネットワークなし、アーカイブなし）に展開し、その時点まで WAL を再生して、そこからデータベースを稼働中のサーバーにダンプし、一時インスタンスを削除します。マシンにはしばらくクラスター分の空き容量が必要です。
  • クラスター全体: 同じ方法で、空きポートで稼働し続ける別インスタンスとして復元されます。実行ではそのポートとデータ ディレクトリ（/var/lib/backupzit-pg 配下）、接続と停止の方法が表示されます。

MySQL と MariaDB

エージェントはローカル ソケットで root として接続するか（ソケット認証、Debian と Ubuntu の既定）、/root/.my.cnf の資格情報を使います。完全バックアップは、各データベースの mysqldump（整合性あり、ルーチン、イベント、トリガーを含む）を、対応するバイナリ ログの位置とともに保存します。

ポイントインタイム リカバリー にはバイナリ ログが必要です。サーバーの構成で一度有効にしてサーバーを再起動します。例: /etc/mysql/mariadb.conf.d/60-binlog.cnf:

[mysqld]
server_id = 1
log_bin = /var/log/mysql/mysql-bin
binlog_format = ROW
expire_logs_days = 7

（ログ用のフォルダーを mysql アカウントの所有で作成します）。その後、ログ バックアップが閉じた各バイナリ ログを保存します。サーバー自身の保存期限はログ バックアップの間隔より長くしてください。欠落があると報告され、復元はそれを越えられません。

  • データベースを復元: ダンプが新しいデータベースに読み込まれます（または既存のものを置き換えます）。特定の時点 または 最新 では、ダンプ以降にバイナリ ログに記録されたそのデータベースの変更をその時点まで再生します — データベースに新しい名前を付けた場合も同様です。再生はサーバーのバイナリ ログには書き込まれません。
  • ユーザーと権限（mysql システム データベース）はダンプに含まれません。

復元

完全バックアップの実行を開き（または 復元ウィザード → データベース を使い）、データベース、復元先のマシン（同じサーバー、または同じデータベース サーバーを持つ別のマシン）と次を選びます:

  • 新しいデータベースとして（例: sales_restored）— 元のデータベースはそのままで、行をコピーして戻せます — または 元の名前で。既存のデータベースを上書きするには 置き換える をオンにします（先にユーザーの接続が切断されます）。
  • 状態: 完全バックアップの時点、最新の状態（完全バックアップとその後のすべてのログ バックアップ）、または表に示される、完全バックアップから使用可能な最新のログ バックアップまでの間の 特定の時点。時刻はコンソールの表示どおり、コンソール サーバーのタイムゾーンで入力します（タイムゾーン を参照）。エージェントがデータベース サーバーのタイムゾーンに変換します。

コマンドライン

backupzit-agent sql list    [--instance SQLEXPRESS]
backupzit-agent sql backup  --repo ... [--instance I] [--db a,b] [--system] [--log] [--copy-only]
backupzit-agent sql restore --repo ... [--instance I] --db NAME [--as NEW] [--replace] [--at "2026-10-04 14:59:00"] SNAPSHOT|latest
backupzit-agent pg list     [--port 5432]
backupzit-agent pg backup   --repo ... [--port P] [--db a,b] [--pitr | --wal]
backupzit-agent pg restore  --repo ... --db NAME|"(cluster)" [--as NEW] [--replace] [--at TIME | --latest] SNAPSHOT|latest
backupzit-agent mysql list
backupzit-agent mysql backup  --repo ... [--db a,b] [--binlog]
backupzit-agent mysql restore --repo ... --db NAME [--as NEW] [--replace] [--at TIME | --latest] SNAPSHOT|latest

対象外

  • SQL Server の差分バックアップと Always On 可用性グループ、リモートのデータベース サーバー — エージェントは自身のマシン上のサーバーをバックアップします。
  • 個別テーブルの復元: データベースを新しい名前で復元し、行をコピーしてください。
