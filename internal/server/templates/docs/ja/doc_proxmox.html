Proxmox VE 仮想マシン

BackupZit は、ゲスト内に何もインストールせずに Proxmox VE の仮想マシン（QEMU）とコンテナー（LXC）をバックアップします。エージェントは Proxmox ホスト上で動作し、各ゲストのスナップショットを取り、ディスクを読み取って、任意のストレージ先に重複排除して保存します。

セットアップ

  1. エージェント から Linux エージェント — Debian / Ubuntu パッケージを各 Proxmox ノードにインストールします（Proxmox VE 7 と 8 は Debian ベースです）: 
    apt install ./backupzit-agent_*.deb
backupzit-agent enroll --code "BZ1-..."
systemctl enable --now backupzit-agent
  2. 1 分以内に、ノードが Proxmox VE · N guests のバッジ付きでエージェント ページに表示されます。
  3. バックアップ ジョブ でそのエージェントを選び、仮想マシン（Proxmox VE、Hyper-V、VMware） を選びます。ノードのすべてのゲスト（後から作成したゲストも自動的に含まれます）をバックアップするか、個別にチェックします。

エージェントはノード自身のツール（qm、pct、pvesm、LVM、ZFS、Ceph）を使います。コンソールには API トークンもパスワードも保存されません。

ゲストのバックアップ方法

  1. 一時的な Proxmox スナップショット（backupzit_…、数秒から数分間 Snapshots に表示）が作成されます。ゲストは稼働したままです。
  2. VM で QEMU ゲスト エージェント が動作していて（VM のオプションで有効になっていれば）、Proxmox はスナップショットのためにファイル システムをフリーズし、バックアップはアプリケーション整合性を持ちます。ない場合、バックアップは停電時と同じクラッシュ整合性になります。Linux VM には qemu-guest-agent、Windows VM には VirtIO ゲスト ツールをインストールしてください。
  3. 各ディスクはスナップショットから 1 MiB 単位で読み取られます。空のブロックは保存されず、リポジトリに既にあるブロックは再送信されないため、初回以降は変更されたデータだけが転送されます。
  4. スナップショットは削除されます。ゲストの構成（CPU、メモリ、ネットワーク、ディスク）がバックアップとともに保存されます。

実行ページには各ゲスト、そのディスク、取得方法が表示されます。復元テストは、ディスク イメージと同様に VM バックアップのランダムなブロックを確認し、起動テスト を有効にすると、各 VM をネットワークから隔離した状態でバックアップから起動し、起動できることを証明します。

対応ストレージ

ストレージの種類稼働中のゲスト停止中のゲスト
LVM-thin（既定の local-lvm）可、スナップショット可
ZFS（VM ディスク / zvol）可、スナップショット可
Ceph RBD可、スナップショット可
qcow2 ディスクのディレクトリ、NFS、CIFS可、スナップショット可
raw ディスクのディレクトリ、NFS、CIFS、シック LVM不可 — ゲストを停止するかディスクを移動可
コンテナーの ZFS サブボリューム未対応

Proxmox で Backup: no（backup=0）とマークされたディスク、パススルーした物理ディスク、バインド マウントはスキップされ、警告として表示されます。Cloud-init ドライブは保存されず、復元時に構成から再作成されます。

VM またはコンテナーの復元

VM バックアップの実行（ジョブのページまたは アクティビティ）を開き、VM またはコンテナーを復元 を使います:

  • ゲスト — そのバックアップに含まれるゲストの 1 つ。
  • Proxmox ノードに復元 — BackupZit エージェントがある任意のノード。別のクラスターのノードも可。
  • 次の空き ID の新しいゲストとして（既定）または ID … — 元のゲストは稼働したままです。両方が存在するため、コピーのネットワーク カードには新しい MAC アドレスが付きます。
  • 元の ID で — ゲストが削除された後。まだ存在する場合は 停止して削除 をオンにすると、バックアップで置き換えます。既存のゲストとそのディスクが先に削除されます。
  • 名前 と ディスク用のストレージ — 例: 元とは別のストレージに復元。
  • 復元後にゲストを起動。

復元のたびに VM には新しい世代 ID（vmgenid）が付与され、Windows のドメイン コントローラーなどのソフトウェアがロールバックを安全に検出できます。ディスクは選んだストレージ上に pvesm で割り当てられ、ディレクトリ ストレージでは raw ファイルとして復元されます。

インスタント リカバリー

大きな VM の復元には、ディスクのコピーと同じだけ時間がかかります。復元フォームで すぐに、バックアップから実行 を選ぶと、ディスクがまだバックアップ内にあるまま、VM が数秒で稼働します:

  1. エージェントは VM のディスクをバックアップから読み取り専用で提供し（systemd ユニット backupzit-instant-<ID> として動作する小さな NBD サーバー）、次の空き ID で新しい VM を作成します。そのディスクは、ディレクトリ ストレージ backupzit-instant（/var/lib/backupzit-instant、自動で追加）上の qcow2 オーバーレイです。データは必要に応じてバックアップから読み取られ、VM が書き込んだものはすべてオーバーレイに残ります。ファームウェア変数（EFI ディスク）と TPM の状態は小さいためコピーされます。
  2. VM が起動します。確認してください — ほかのコピーと同様に新しい MAC アドレスが付きます。ダッシュボードには、まだバックアップから稼働しているすべての VM が表示されます。
  3. 実行ページで 完了する を選ぶと、VM を稼働させたままディスクを選んだストレージに移動し（qm disk move）、以後バックアップは使われません。破棄 を選ぶと、VM は停止され、変更とともに削除されます。

VM がバックアップから稼働している間、保持によってそのバックアップが削除されることはありません。VM の速度はバックアップ ストレージ次第です。ローカル ディスクや高速なネットワーク共有上のリポジトリが最適で、遠隔地から SFTP や S3 で読み取ると、完了するまで遅くなります。インスタント リカバリーは VM 用（コンテナーは不可）で、新しい VM を作成します — 元の場所への復元は通常の復元で行います。EFI ディスクは VM の稼働中は移動できず、backupzit-instant に残ります（実行メッセージを参照）。VM をシャットダウンした後に移動できます: qm disk move ID efidisk0 STORAGE --delete 1。

レプリケーション

数分で復旧させる必要があるゲストのために、VM ジョブは レプリカ を維持できます。ジョブ フォームの 詳細設定 で VM のレプリカを維持 をオンにし、ノード（BackupZit エージェントがある任意のノード。別のクラスターも可）とストレージを選びます。バックアップのたびに、そのノードのエージェントがジョブの各ゲストの 停止したコピー を最新にします:

  • 初回は、レプリカを新しいゲストと同じように復元します（次の空き ID、名前 original-replica、新しい MAC アドレス、ノードと一緒に起動しない）。
  • 以降は、レプリカが保持するバックアップから変更されたブロックだけを書き込みます — 通常はバックアップごとに数秒です。
  • ジョブのページには、レプリカ、それぞれが保持するバックアップ、状態が表示されます。ゲストが失われたら レプリカを起動 をクリックします。復元なしで、最後のバックアップのデータで稼働します。元のゲストが本当に失われた場合にのみ起動してください — 両方が同時にネットワーク上にあると競合することがあります。
  • レプリカが稼働している間は更新されません（実行で報告されます）。再びレプリケートするには、Proxmox でレプリカのゲストを削除します。次のバックアップで新しいレプリカが作成されます。Proxmox のスナップショットを持つレプリカも更新されません。
  • 後からゲストに追加したディスクはレプリケートされません（やり直すにはレプリカを削除）。拡張したディスクはレプリカでも拡張されます。構成の変更（メモリ、CPU）はレプリカ作成時に反映されます。
  • レプリケーションは復元と同じようにバックアップを読み取るため、レプリカのノードがストレージに到達できる必要があります。レプリケーションをオフにしても、レプリカはそのまま残ります。

コマンドライン

backupzit-agent pve list
backupzit-agent pve backup  --repo ... [--vmid 100,200] [--exclude 300]
backupzit-agent pve show    --repo ... latest
backupzit-agent pve restore --repo ... --vmid 100 [--new-vmid -1|N] [--name copy] [--storage local-lvm] [--overwrite] [--start] SNAPSHOT|latest
backupzit-agent pve instant --repo ... --vmid 100 [--new-vmid N] [--name X] SNAPSHOT|latest
backupzit-agent pve instant-finish --vmid 101 --storage local-lvm
backupzit-agent pve instant-discard --vmid 101

リポジトリのオプションはすべてのコマンドで共通です（コマンドライン リファレンス を参照）。コマンドラインはコンソールなしでも動作します。たとえば障害後にノード全体を復元する場合です。

クラスター

すべてのノードにエージェントをインストールします。ジョブは、そのエージェントのノードで稼働しているゲストをバックアップします。ジョブに含まれていて別のノードに移行されたゲストは、そのノード名とともに警告として報告されます — 各ノードをそれぞれのジョブでバックアップするか、すべてのノードで ノードのすべてのゲスト を使えば、移行したゲストも常に対象になります。

個別ファイルの復元

VM バックアップの実行のゲスト一覧で ファイルを参照 をクリックします。コンソールはバックアップから直接ディスクを読み取り（事前の復元は不要）、パーティションと LVM 論理ボリュームを表示します。NTFS（Windows）、ext2/3/4、XFS（Linux）を LVM 内も含めて参照できます。ファイルやフォルダーにチェックを付けて、次のいずれかを行います:

  • ダウンロード — 1 つのファイルはそのまま、複数のファイルやフォルダーは ZIP アーカイブとしてブラウザーに直接ダウンロード。
  • エージェントに復元 — 任意のエージェント上のフォルダーにコピー。例: VM に戻す（VM で BackupZit エージェントが動作している場合）、またはファイル サーバーへ。

コマンドラインでは: backupzit-agent pve ls --vmid 100 latest /etc と backupzit-agent pve extract --vmid 100 --target /srv/restore latest /etc/nginx。--volume でパーティションまたは論理ボリュームを選びます（パスなしの pve ls で一覧表示）。コンソールで参照するには、バックアップがネットワーク ストレージ（SFTP、S3、SMB、Azure、強化リポジトリ）上にある必要があります。
