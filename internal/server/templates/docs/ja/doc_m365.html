Microsoft 365: Exchange Online、OneDrive、SharePoint

BackupZit は Microsoft Graph を通じて、Microsoft 365 テナントのメールボックス（Exchange Online）、予定表、連絡先、OneDrive、SharePoint サイトをバックアップします。読み取りのみで、テナント内の何も変更・削除しません。インターネットにアクセスできる任意のエージェント（たとえばコンソール マシン上のエージェント）がデータをダウンロードし、ほかのバックアップと同様に保存します: 重複排除、暗号化、保持、コピー ジョブ、復元テスト付きです。

1. Microsoft Entra ID にアプリを登録

テナントごとに 1 回、グローバル管理者として Microsoft Entra 管理センター で行います:

  1. App registrations → New registration: 名前は例えば BackupZit、Accounts in this organizational directory only、リダイレクト URI なし。概要ページの Application (client) ID と Directory (tenant) ID を控えます。
  2. Certificates & secrets → New client secret: 有効期間（例: 24 か月）を選び、シークレットの Value をすぐにコピーします — 一度しか表示されません。Secret ID はシークレットではありません。
  3. API permissions → Add a permission → Microsoft Graph → Application permissions（delegated ではない）: User.Read.All、Mail.Read、Files.Read.All。予定表と連絡先には Calendars.Read と Contacts.Read、SharePoint には Sites.Read.All も追加します。
  4. Grant admin consent for … をクリックします。それまではステータスが Not granted と表示され、バックアップは拒否されます。

これらは読み取り権限のみです。将来メールボックスへ復元するには書き込み権限が必要ですが、BackupZit はそれを要求しません。

アプリを一部のメールボックスに限定するには、Exchange 管理者が application access policy または RBAC for Applications のスコープを追加できます。スコープ外のアカウントは読み取れないものとして報告されます。

2. ジョブの作成

バックアップ ジョブ で種類 Microsoft 365 のジョブを作成します:

  • エージェント: ダウンロードを行うエージェント（Windows または Linux、バージョン 0.34.0 以降。予定表、連絡先、SharePoint には 0.35.0）。login.microsoftonline.com、graph.microsoft.com、OneDrive と SharePoint のファイルには *.sharepoint.com への HTTPS アクセスが必要です。
  • 手順 1 の ディレクトリ (テナント) ID、アプリケーション (クライアント) ID、クライアントシークレット。シークレットは暗号化して保存されます。
  • バックアップ対象: メール、OneDrive、予定表と連絡先、SharePoint サイト — 任意の組み合わせ。
  • アカウント: 1 行に 1 つのアドレス、または空欄でメールボックスか OneDrive を持つテナントのすべてのアカウント — 後から追加したアカウントも自動的に含まれます。ライセンスのないアカウントはスキップされます。
  • SharePoint サイト: 1 行に 1 つのサイト アドレス（例: https://contoso.sharepoint.com/sites/sales）、または空欄でテナントのすべてのサイト — 後から追加したサイトも自動的に含まれます。個人用サイト（OneDrive）は除外され、アカウントとともにバックアップされます。SharePoint のみのジョブにはアカウントは不要です。

アドレスを入力する代わりに 一覧から選択 をクリックすると、コンソールが上で入力したアプリを使ってテナントのアカウント（メールボックスも OneDrive もないライセンスなしのアカウントには印を付けます）と SharePoint サイトを読み取り、チェックできる一覧を表示します。チェックしたものがフィールドに入力されます。ジョブの編集時は保存済みのシークレットが使われます。

ジョブを保存すると、コンソールはアプリとしてサインインし、権限、アカウント、サイトを確認します。そのため、シークレットの誤りや管理者の同意の不足がすぐにわかります。インターネットにアクセスできないコンソールは確認をスキップし、最初のバックアップで動作するかがわかります。

バックアップされるもの

  • メール: すべてのメール フォルダーとそのサブフォルダー（受信トレイ、送信済みアイテム、削除済みアイテム、アーカイブ、独自のフォルダーなど）。各メッセージは添付ファイルを含めて MIME 形式の .eml ファイルとして完全に保存され、受信日時と件名で名前が付けられます（例: 2026-10-07 0621 10 月のお見積もり [3fa2c1d9e0].eml）。Outlook、Thunderbird、ほとんどのメール ソフトで .eml ファイルを開けます。
  • OneDrive: アカウントの OneDrive のすべてのファイルとフォルダー（更新日時付き）。
  • 予定表: アカウントのすべての予定表。各予定は、日時、場所、説明、開催者、出席者、アラーム、定期的な予定の場合は繰り返しを含む iCalendar ファイル（.ics）として、開始日時と件名で名前が付けられます（例: 2026-10-08 1000 取締役会 [8c1e…].ics）。Outlook、Google カレンダー、Thunderbird で .ics ファイルをインポートできます。時刻は UTC で保存されます。
  • 連絡先: アカウントの連絡先と連絡先フォルダー。それぞれ名前、メール アドレス、電話番号、住所、会社、メモを含む vCard（.vcf）として保存されます。
  • SharePoint: 各サイトのすべてのドキュメント ライブラリ（ドキュメント、サイトのアセット、作成したライブラリ）と、そのすべてのフォルダーとファイル。

含まれないもの: 予定の添付ファイル、連絡先の写真、定期的な予定の個別に変更された回、SharePoint のリストとページ（ドキュメント ライブラリのみ対象）、Teams のチャットとチャネルのメッセージ（Teams のファイルは SharePoint にあり、一緒にバックアップされます）、ユーザー アカウントのない共有メールボックス。

バックアップにはアカウントごとに 1 つのフォルダー — ana@contoso.com/Mail/Inbox/…、…/OneDrive/…、…/Calendar/Calendar/…、…/Contacts/… — と SharePoint/<site>/<library>/… が含まれます。最初のバックアップはすべてをダウンロードします。以降のバックアップはフォルダーを再度一覧しますが、前回のバックアップ以降に新しく追加または変更されたメッセージとファイルだけをダウンロードします（既読、フラグ付け、移動、編集されたメッセージは変更扱い）。変更のないデータは前回のバックアップから引き継がれます。Microsoft はアプリの読み取り速度を制限しています。BackupZit は Microsoft の要求に応じて待機してから続行するため、大きなメールボックスの初回バックアップには数時間かかることがあります。

テナントのバックアップは、ストレージ先の専用リポジトリ（フォルダー m365-<tenant ID>）に保存されるため、ダウンロードするエージェントを交換しても最初からやり直す必要はありません。

復元

  • バックアップの実行で ファイルを参照: アカウントのメール フォルダー、OneDrive、予定表、連絡先、または SharePoint サイトを開き、メッセージ、予定、ファイル、フォルダーにチェックを付けて ダウンロード します（1 つのファイルはそのまま、複数は ZIP）。.eml ファイルは Outlook で開くか、メールボックスにドラッグします。
  • 任意のエージェントで フォルダーに復元: メッセージは .eml ファイル、予定は .ics、連絡先は .vcf、OneDrive と SharePoint のファイルは元のまま、<folder>/<account>/… と <folder>/SharePoint/… の下に書き込まれます。

メールボックスや OneDrive への直接の復元は予定されています。新しいフォルダーにのみ書き込み、上書きや削除は一切行いません。

トラブルシューティング

  • AADSTS7000215 / invalid client secret: シークレットの Value ではなく ID をコピーしたか、期限切れです — 新しいシークレットを作成してジョブに入力してください。
  • missing the application permissions または Authorization_RequestDenied: 権限を アプリケーション の許可として追加し、Grant admin consent をクリックしてください。
  • the account has no Exchange Online mailbox: アカウントに Exchange のライセンスがない（または連絡先である）ため、ジョブから削除してください。
  • 警告のある実行には、読み取れなかったメッセージやファイル（例: OneNote ノートブック）が表示されます。バックアップのそれ以外の部分は完全です。
