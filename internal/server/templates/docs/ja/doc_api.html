REST API

BackupZit を RMM プラットフォーム、監視ツール（PRTG、Zabbix、Nagios、Uptime Kuma など）、独自のスクリプトと連携できます。

トークン

マイ アカウント → API トークン でトークンを作成します。必要最小限のロールを付与してください — 監視には 閲覧者、バックアップや復元テストも開始するなら 復元オペレーター。トークンは一度だけ表示されます。すべてのリクエストで送信してください:

Authorization: Bearer bzt_...

トークンには有効期限を設定でき、所有者または管理者が失効させることができ（ユーザー）、所有者が無効化されると使えなくなります。トークンで行った操作は、トークン名とともに監査ログに記録されます。

エンドポイント

すべての応答は JSON です。ベース URL: https://<コンソール>:8443。

メソッドとパスロール返す内容
GET /api/v1/status閲覧者全体の状態: オンラインのエージェント、24 時間以内の失敗と警告、実行中の処理、未確認の不審なバックアップ、"ok": true|false
GET /api/v1/agents閲覧者OS、バージョン、オンライン状態、最終接続時刻を含むエージェント
GET /api/v1/jobs, GET /api/v1/jobs/{id}閲覧者スケジュール、次回実行、最終結果を含むジョブ
POST /api/v1/jobs/{id}/run復元オペレータージョブを今すぐ開始: {"run_id": 123}（202）、すでに実行中なら 409
POST /api/v1/jobs/{id}/test復元オペレータージョブの最新バックアップの復元テストを開始
GET /api/v1/runs?job=&agent=&status=&limit=閲覧者最近の実行、新しい順（既定 100、最大 1000）
GET /api/v1/runs/{id}閲覧者メッセージ、エラー、統計を含む 1 件の実行
GET /api/v1/report?period=&from=&to=&agent=&job=閲覧者期間のレポート: 合計、成功率、ジョブごとの詳細
GET /api/v1/targets閲覧者ストレージ先（資格情報を除く）

期間: today、yesterday、last7、last30、last90、thisweek、lastweek、thismonth、lastmonth、または custom と from=2026-09-01&to=2026-09-30。

エラーは {"error": "..."} を返し、ステータスは 400（不正なリクエスト）、401（トークンがない、無効、または期限切れ）、403（ロールの権限不足）、404、409 です。

例

curl

curl -sk -H "Authorization: Bearer $BZ_TOKEN" https://backup.example.local:8443/api/v1/status
curl -sk -X POST -H "Authorization: Bearer $BZ_TOKEN" https://backup.example.local:8443/api/v1/jobs/7/run

PowerShell

$h = @{ Authorization = "Bearer $env:BZ_TOKEN" }
$s = Invoke-RestMethod -Uri https://backup.example.local:8443/api/v1/status -Headers $h -SkipCertificateCheck
if (-not $s.ok) { Write-Warning "BackupZit needs attention: $($s.failed_24h) failed backups" }

-k / -SkipCertificateCheck は、信頼できるネットワークでコンソールの自己署名証明書を使う場合にのみ使用するか、監視ホストにコンソールの証明書をインストールしてください。

監視チェック

数分ごとに /api/v1/status をポーリングし、ok が false のときにアラートを出します。ジョブ単位のチェックには /api/v1/jobs を使い、last_status が failed のとき、または last_finished が想定より古いときにアラートを出します。
