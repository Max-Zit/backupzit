はじめに

BackupZit は、自社ネットワーク内で動作する 1 つの Web コンソールから、Windows と Linux のマシン、Proxmox VE・Hyper-V・VMware ESXi の仮想マシン、データベース（SQL Server、PostgreSQL、MySQL/MariaDB）、NAS 共有を、ファイル、ディスク全体、システム全体の単位で保護します。

BackupZit が保護するもの

データベース: SQL Server、PostgreSQL、MySQL/MariaDBデータベース マシン上のエージェント。サーバー自身のツールで完全バックアップとログ バックアップ。データベース個別のデータベースを新しい名前またはその場に、ログ バックアップでカバーされる任意の時点へ。
Proxmox VE の VM とコンテナーProxmox ホスト上のエージェント、ゲスト内にエージェント不要。Proxmox スナップショットから、変更されたブロックのみアップロード。Proxmox VEゲスト全体を新規またはその場に、任意のノードとストレージへ。バックアップから VM を即座に起動（インスタント リカバリ、VMware ESXi でも可）。VM ディスク（NTFS、ext4、XFS、LVM）から個別ファイルをダウンロードまたはエージェントへ。

BackupZit のしくみ

  • 管理コンソール（この Web アプリケーション）— ネットワーク内の Linux サーバーで動作します。構成を保存し、ジョブをスケジュールし、結果を収集してレポートを表示します。インターネットから到達可能にする必要はありません。
  • エージェント — 保護対象の各マシン（Windows MSI、Linux deb/rpm）と Proxmox・Hyper-V ホストで動く小さなサービスです。VMware ESXi ホストにはプロキシとして動作するエージェント経由で接続します。エージェントは HTTPS でコンソールに接続してジョブを受け取り、バックアップ データをストレージに直接送ります。Windows ではエージェントが時計の横に状態を表示します。
  • ストレージ ターゲット — バックアップの保存先: SFTP、S3 互換オブジェクト ストレージ（AWS、Wasabi、Backblaze B2、MinIO、Google Cloud…）、Azure Blob Storage、SMB 共有/NAS、ローテーションする USB ディスク、ローカルまたはマウントされたディスク、BackupZit 強化リポジトリ。

バックアップ データがコンソールを経由することはありません。コンソールは調整役にすぎないため、小さな仮想マシンで十分です。

最初の手順

新しいコンソールを用意するには、既製のアプライアンス イメージを小さな VM にインポートするか、アプライアンス ISO から起動するか、既存の Linux サーバーでインストール スクリプトを実行します。サーバーのインストールを参照してください。

  1. ストレージでストレージ ターゲットを追加します。バックアップを暗号化は有効のままにし、その後表示される復旧シートを安全な場所に保管してください。ストレージ ターゲットを参照してください。
  2. エージェントをインストールします: エージェントで登録トークンを作成をクリックし、同じページからインストーラーをダウンロードして、Windows インストーラーが求めたら登録コードを貼り付けます（Linux: backupzit-agent enroll --code …）。VM の場合は Proxmox または Hyper-V ホストにエージェントをインストールし、VMware ESXi ホストはエージェント → VMware ESXi ホストで追加します。エージェントを参照してください。
  3. バックアップ ジョブでバックアップ ジョブを作成します: エージェント、ストレージ、バックアップ対象（ファイル、NAS 共有、ディスク イメージ、データベース、Linux システム全体、または Proxmox・Hyper-V・VMware ESXi ホストの VM）、実行タイミング、保持するバックアップ数を選びます。バックアップ ジョブとスケジュールを参照してください。
  4. ジョブ ページの今すぐバックアップを実行で一度手動で実行し、アクティビティで結果を確認します。
  5. 復元をテストします — バックアップの価値は復元できるかどうかで決まります。自動復元テストは毎週実行されます。復元ウィザードで一度は手動でも復元してみてください。復元を参照してください。
  6. 障害に備えます: リカバリーメディアで復旧 ISO をダウンロードし、復旧コードを作成します。
  7. 失敗を把握できるよう、設定 → メール通知でメール アラートを設定します。必要に応じて週次レポートも設定します。

言語

コンソールは 14 言語で利用できます: 英語、ドイツ語、フランス語、スペイン語、イタリア語、ポルトガル語（ブラジル）、オランダ語、ポーランド語、チェコ語、セルビア語（ラテン文字）、トルコ語、ロシア語、中国語（簡体字）、日本語。右上の言語リストまたはサインイン ページで選択してください。選択はブラウザーに記憶されます。選択しない場合はブラウザーの言語で決まります（クロアチア語・ボスニア語・モンテネグロ語のブラウザーはセルビア語、スロバキア語のブラウザーはチェコ語、その他の言語は英語）。このガイドも翻訳されています（翻訳のないページは英語で表示されます）。メール、チャット通知、エージェントが報告するメッセージは英語のままです。

翻訳はソース コードの internal/server/i18n/ja.json にあります。英語のテキストがキー、翻訳がその値です。go run ./tools/i18n missing ja で未翻訳のテキストを一覧表示できます。未翻訳のテキストは英語で表示されます。

主要な概念

スナップショットと重複排除

各バックアップはスナップショットを作成します。これはその時点のデータの完全で参照可能な姿です。ファイルは可変サイズのチャンクに、ディスクはブロックに分割され、各断片は一度だけ保存されるため、2 回目以降のバックアップは変更分だけをアップロードします。それでも、各スナップショットは単独で復元できます。「完全/増分チェーン」を管理する必要はありません。

リポジトリ

各エージェントは、ストレージ ターゲットの場所の下にある自分専用のリポジトリに書き込みます（<location>/<hostname>_<id>）。リポジトリは自己完結しています。場所、ストレージの資格情報、回復キーがあれば、コンソールがなくなっても復元できます。

保持

各ジョブは、直近・日次・週次・月次のバックアップを一定数保持します。古いスナップショットは実行ごとに削除され、使っていた領域が解放されます。

BackupZit が代わりに確認すること

  • 復元テスト — 各ジョブの最新バックアップを毎週部分的に復元して検証します（復元）。
  • ランサムウェア検出 — 異常なバックアップ（大量の変更、暗号化されたデータ、大量削除、データ量の急増）にフラグを付け、保持処理を一時停止します（ランサムウェア対策）。
  • アラートとレポート — 失敗時のメールと日次サマリー、経営層向けのスケジュール レポート（メール通知、監視）。
