エージェント

保護するすべてのマシンにエージェントをインストールします。エージェントはサービスとして動作し、30 秒ごとにコンソールに作業を問い合わせ、ストレージと直接通信します。

サポートされるシステム

  • Windows 10、11、Windows Server 2016 以降 — Windows エージェント MSI。
  • Windows 7 SP1、Windows Server 2008 R2 SP1、2012 R2 — Windows エージェント — 旧システム MSI（…-legacy.msi）。VSS やディスク イメージを含め同じ機能を備えます。
  • Debian、Ubuntu、AlmaLinux、Rocky Linux（64 ビット）。
  • Proxmox VE 7 および 8 のノード — Debian パッケージ。エージェントはノードの VM とコンテナーもバックアップします（Proxmox VE を参照）。
  • Hyper-V ホスト（Windows Server 2016 以降、Hyper-V を有効にした Windows 10/11）: Windows MSI。エージェントはホストの VM もバックアップします（Hyper-V を参照）。
  • VMware ESXi ホスト — ESXi には何もインストールしません。VMware ESXi ホストでホストを追加し、プロキシとなるエージェントを選びます（VMware ESXi を参照）。

エージェントの登録

  1. エージェントページで登録トークンを作成をクリックします。コンソールに登録コード（BZ1-…）が表示されます。有効期間は 7 日で、何台のマシンにも使えます。エージェント用のコンソール アドレス（ページを Web ポート 443 で開いていても、エージェント用ポート、通常は 8443）、トークン、証明書のフィンガープリントが含まれます。0.33.6 以降のエージェントは、古いコンソールが Web ポートで作成したコードでも登録できます。
  2. Windows: MSI を実行し、インストーラーが求めたらコードを貼り付けます。Linux: 表示されたコマンドを実行します。
  3. 1 分以内にマシンがエージェント一覧に表示されます。

インストール中にコンソールに接続できない場合、エージェントはコードを保持し、登録できるまで再試行します。アップグレードでは登録が保持され、再度尋ねられることはありません。登録済みのマシンで ENROLLCODE を指定してサイレント インストールすると、コードが同じコンソールのものなら登録を保持し（GPO や RMM で安全に繰り返せます）、別のコンソールのものならマシンを移行します。以前の登録は agent.json の隣に agent.json.replaced-日付 として保存されるため、名前を元に戻せばマシンは同じエージェントとして元のコンソールに戻ります。

Windows、サイレント（GPO、Intune、RMM）

msiexec /i backupzit-agent.msi /qn ENROLLCODE="BZ1-..."

旧形式の SERVER="..." TOKEN="..." FINGERPRINT="SHA256:..." も引き続き使えます。これらのプロパティなしでサイレント インストールするとサービスが設定され、管理者のコマンド プロンプトで backupzit-agent enroll --code "BZ1-..." により登録されるまで待機します。

Linux

apt install ./backupzit-agent_*.deb        # or: dnf install ./backupzit-agent-*.rpm
backupzit-agent enroll --code "BZ1-..."
systemctl enable --now backupzit-agent

コンソールからのエージェントのインストール

インストーラーを各マシンにコピーする代わりに、コンソールにエージェントをインストールさせることができます。エージェントでここからマシンにインストールを開き、Linux または Windows を選んで、マシンのアドレスと管理者アカウントを入力します。

  • Linux（Debian、Ubuntu、AlmaLinux、Rocky Linux、64 ビット）: コンソールは SSH で root として、または sudo 権限を持つユーザーとして接続します（パスワードは sudo にも使われます。キーを使う場合はパスワードなしの sudo が必要です）。パスワードでも秘密キーでも構いません。コンソールが正しいマシンと通信していることを確かめるため、マシンの SSH ホスト キーのフィンガープリント（マシン上で ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub）を入力してください。入力しない場合、フィンガープリントはインストール ログに表示されます。
  • Windows（64 ビット）: コンソールは WinRM（ポート 5985、メッセージは NTLM で暗号化。HTTPS リスナーは 5986）でローカル管理者またはドメイン管理者として接続します。WinRM は Windows Server では既定で有効です。Windows 10/11 では管理者として一度 winrm quickconfig を実行してください。組み込みの Administrator 以外のローカル アカウントにはリモート管理権限（LocalAccountTokenFilterPolicy）が必要です。またはドメイン アカウントを使ってください。旧システム（Windows 7、Server 2008 R2/2012 R2）には legacy MSI が使われます。

マシンは、このインストール専用のリンク（30 分、3 回までダウンロード可）でコンソールから最新のエージェント パッケージをダウンロードし、SHA-256 チェックサムを確認してインストールし、登録します。インストール ページには各手順が表示されます。アカウントとパスワードはこの目的にのみ使われ、保存されません。マシンがすでにこのコンソールに登録されている場合は登録を保持してパッケージを更新し、コンソールが知らない登録（以前に削除したエージェントや別のコンソール）は置き換えます。すべてのインストールは監査ログに記録されます。マシンは、他のエージェントと同様にコンソールのエージェント用アドレスに到達できる必要があります。

エージェントの状態

  • online — エージェントが直近 3 分以内にコンソールに接続しました。
  • offline — マシンの電源が切れている、サービスが停止している、またはネットワークがブロックされています。スケジュールされたバックアップはキューに入り、エージェントが戻るとすぐに開始されます。
  • リカバリー — 復旧 ISO（Windows または Linux）から起動したマシンで、ディスク イメージまたは Linux システムの復元を受け入れる準備ができています。リカバリー エージェントは一時的なものです。復元が終わったら削除してください。

IP アドレス列には、エージェントが最後に報告したマシン自身のアドレスが表示されます。接続元は接続が届くアドレスです。ローカル ネットワークでは同じアドレス、NAT の内側のマシン（自宅のノート PC など）ではルーターのパブリック アドレスになります。コンソールはそのために外部サービスに問い合わせることはありません。

デスクトップ上のエージェント（Windows）

Windows エージェントは時計の横にアイコンを表示します（非表示のアイコンの ^ 矢印の下にある場合があります。常に表示するにはタスク バーにドラッグしてください）。アイコン上の点が状態を示します:

点意味
緑バックアップは正常です（または最初のスケジュール バックアップを待っています）。
青バックアップ、復元、または復元テストを実行中です。
オレンジ最後のバックアップは警告付きで終了しました（読み取れなかったファイル）。
赤バックアップ ジョブが失敗しました。
灰色コンソールに接続できないか、エージェント サービスが実行されていません。

アイコンをクリックする（またはスタート メニューから BackupZit Agent を開く）と状態ウィンドウが表示されます: 保護状態、実行中のバックアップの進行状況、前回と次回のバックアップ、そして今すぐバックアップ付きのコンピューターのすべてのバックアップ ジョブ。右クリックでメニューが開きます: ジョブごとの Back up now、Open console in browser、Hide this icon（次回のサインインまで。バックアップは続行されます）。このウィンドウには Windows 10 と 11 に含まれる Microsoft Edge WebView2 が必要です。旧システムではアイコンとメニューが動作し、Open でブラウザーにコンソールが表示されます。

ユーザーはこうして自分のコンピューターのバックアップを開始できます。ジョブ、スケジュール、保持期間はコンソールでのみ設定します。どのシステムでも、backupzit-agent status（管理者または root として）で同じ情報が表示されます。

アップグレード

エージェントが実行しているものより新しいエージェント インストーラーがコンソールにある場合、エージェント ページではそのバージョンの横に更新: x.y.z、一覧の下にすべてのエージェントを更新が表示されます。エージェントはその後:

  1. アイドルになるまで待ちます（実行中のバックアップが中断されることはありません）。
  2. 固定された接続でコンソールから対応するインストーラーをダウンロードし（Windows 10/11/2016+ には MSI、Windows 7/2008 R2/2012 R2 には旧システムの MSI、Linux では deb または rpm パッケージ）、SHA-256 を確認します。
  3. インストールして再起動します。数分以内に新しいバージョンが一覧に表示されます。登録とすべての設定は保持されます。

コンソールは dist ディレクトリにある最新のインストーラーを提供します。サーバー パッケージには同じバージョンのエージェント インストーラーが同梱されています。設定 → 更新からコンソールを更新すると、エージェントは自動的に更新されます（そこで無効にできます）。コンソールからの更新はバージョン 0.21 以降のエージェントで動作します。それより古いエージェントは、新しい MSI / パッケージを古いものの上にインストールして一度更新します（登録は保持されます）。インストーラーのログは C:\ProgramData\backupzit\updates または /var/tmp/backupzit-updates にあります。

エージェントの削除

エージェント ページの削除で、エージェントとそのジョブがコンソールから削除されます。4 アイズ承認が有効な場合は、先に 2 人目のユーザーの承認が必要です。ストレージ上のバックアップは削除されません。マシン上のソフトウェアは別途アンインストールしてください。

1 つのエージェントを使う 2 台のマシン

登録済みマシンのコピーは、エージェントと登録も一緒に持ち出します: 新しい VM として復元した VM、インスタント リカバリ、起動したレプリカ、クローンしたディスクやテンプレート。コピーが元のマシンと並行して動くと、どちらも同じエージェントとして接続します。コンソールは 1～2 分以内にこれを検出し、次のようにします:

  • エージェント ページに両方の名前とアドレスとともに 2 台のマシンと表示し、ダッシュボードの要対応にそのエージェントを表示します。
  • 誤ったマシンで何も実行されないよう、エージェントのバックアップと復元を保留します（そうしないと、元の場所への復元が元のマシンではなくコピーを上書きするおそれがあります）。
  • 管理者に一度メールを送り、監査ログに agent.duplicate エントリを書き込みます。

コピーを停止するか、残す場合はコピー上で新しいマシンとして登録してください: backupzit-agent enroll --force --code "BZ1-..."（コードはエージェント ページから）。マシンが 1 台だけになってから数分後に、保留された実行が開始されます。システム全体を復元で Linux システムを復元すると、復元されたコピーのエージェント登録はすでに解除されます。また、復元テストは VM をネットワークなしで起動するため、どちらもこの状況を引き起こしません。

コンソールのアドレスが変わったとき

エージェントはコンソールを証明書で信頼します。証明書は IP アドレスや名前が変わっても同じですが、エージェントは登録時のアドレスに接続します。変更後は、各エージェント マシンで（管理者 / root として）次を実行します:

backupzit-agent set-server https://192.168.1.20:8443

このコマンドは、コンソールが新しいアドレスで同じ証明書を使って応答することを確認して保存します。エージェントはサービスの再起動後にそれを使います（systemctl restart backupzit-agent、または Windows では BackupZit Agent サービスを再起動）。最初からコンソールに DNS 名を使えば、この手順は不要です。

エージェントの構成の保存場所

  • Windows: C:\ProgramData\backupzit\agent.json（SYSTEM と Administrators のみアクセス可）。
  • Linux: /etc/backupzit/agent.json（root のみ）。

このファイルにはエージェントのシークレットが含まれます。読み取れる人は誰でもそのエージェントになりすませるため、これらのアクセス許可を維持してください。

エージェントのログ

  • Windows: C:\ProgramData\backupzit\agent.log
  • Linux: /etc/backupzit/agent.log と journalctl -u backupzit-agent
  • 復旧システムでは画面にログが表示されます。

アンインストール

Windows: 設定 → アプリ → BackupZit Agent → アンインストール（または msiexec /x）。Linux: apt remove backupzit-agent / dnf remove backupzit-agent。その後、コンソールでエージェントを削除します。バックアップはストレージに残ります。

Windows ではアンインストール時に登録が退避される（C:\ProgramData\backupzit\agent.json.removed-日付）ため、エージェントを再インストールすると登録コードを求められます。インストーラーが以前のバージョンの登録を見つけた場合はその旨を表示します。保持するにはコードを空のままにし、コンピューターを再登録する（たとえば別のコンソールに）には新しいコードを貼り付けます。
