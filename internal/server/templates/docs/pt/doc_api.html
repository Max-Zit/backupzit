REST API

Integre o BackupZit a plataformas RMM, monitoramento (PRTG, Zabbix, Nagios, Uptime Kuma…) e seus próprios scripts.

Tokens

Crie um token em Minha conta → Tokens de API. Dê a ele a função mais baixa que seja suficiente — Visualizador para monitoramento, Operador de restauração para também iniciar backups e testes de restauração. O token é mostrado uma única vez; envie-o em cada requisição:

Authorization: Bearer bzt_...

Tokens podem expirar, ser revogados pelo dono ou por um administrador (Usuários) e param de funcionar quando o dono é desativado. Ações feitas com um token aparecem no log de auditoria com o nome do token. Uma nova senha definida por um administrador também revoga os tokens do proprietário.

Endpoints

Todas as respostas são JSON. URL base: https://<console>:8443.

Método e caminhoFunçãoRetorna
GET /api/v1/statusVisualizadorEstado geral: agentes online, falhas e avisos em 24 h, execuções ativas, backups suspeitos não revisados, "ok": true|false
GET /api/v1/agentsVisualizadorAgentes com sistema operacional, versão, estado online e último contato
GET /api/v1/jobs, GET /api/v1/jobs/{id}VisualizadorTarefas com agendamento, próxima execução e último resultado
POST /api/v1/jobs/{id}/runOperador de restauraçãoInicia a tarefa agora: {"run_id": 123} (202), ou 409 se já houver uma execução ativa
POST /api/v1/jobs/{id}/testOperador de restauraçãoInicia um teste de restauração do backup mais recente da tarefa
GET /api/v1/runs?job=&agent=&status=&limit=VisualizadorExecuções recentes, da mais nova (padrão 100, máximo 1000)
GET /api/v1/runs/{id}VisualizadorUma execução com mensagem, erros e estatísticas
GET /api/v1/report?period=&from=&to=&agent=&job=VisualizadorO relatório de um período: totais, taxa de sucesso e detalhes por tarefa
GET /api/v1/targetsVisualizadorDestinos de armazenamento (sem credenciais); agents_only marca o armazenamento acessível somente pelos agentes
GET /api/v1/agents/{id}VisualizadorUm agente
POST /api/v1/agents/{id}/logOperador de backupPede o log ao agente: {"run_id": 124}; leia-o com o próximo endpoint quando o agente o tiver enviado (agentes 0.38.0 ou mais novos)
GET /api/v1/runs/{id}/logOperador de backupO log enviado pelo agente: {"log": "..."}, ou 404 até que chegue
POST /api/v1/runs/{id}/cancelOperador de restauraçãoCancela uma execução na fila ou para uma em andamento: {"state": "cancelled"} ou "stopping"; 409 se já terminou
POST /api/v1/jobs/{id}/enable, /disableOperador de backupLiga ou desliga o agendamento da tarefa; com a aprovação de quatro olhos, desativar só é possível no console (409)
GET /api/v1/storageVisualizadorEspaço usado por destino de armazenamento, capacidade e espaço livre quando conhecidos, crescimento por dia e dias até encher
GET /api/v1/metricsVisualizadorMétricas no formato de texto do Prometheus (veja abaixo)
POST /api/v1/runs/{id}/restoreOperador de restauraçãoRestaura arquivos de um backup com um agente: corpo {"target": "D:/Restore"} ou {"original": true}, opcionalmente "paths", "agent_id" e "verify": true; retorna {"run_id": 125}
GET /api/v1/openapi.jsonsem tokenA especificação OpenAPI 3 desta API, para ferramentas e geradores de clientes (também no repositório: internal/server/openapi.json)

Períodos: today, yesterday, last7, last30, last90, thisweek, lastweek, thismonth, lastmonth, ou custom com from=2026-09-01&to=2026-09-30.

Erros retornam {"error": "..."} com 400 (requisição inválida), 401 (token ausente, inválido ou expirado), 403 (função insuficiente), 404 (não encontrado), 409 (não é possível agora: a tarefa já está em execução, o agente é antigo demais para a requisição ou a aprovação de quatro olhos está ativada), 429 (muitas tentativas de token com falha a partir do endereço; aguarde o fim do bloqueio) ou 500 (erro interno; veja o log do console).

Exemplos

curl

curl -sk -H "Authorization: Bearer $BZ_TOKEN" https://backup.example.local:8443/api/v1/status
curl -sk -X POST -H "Authorization: Bearer $BZ_TOKEN" https://backup.example.local:8443/api/v1/jobs/7/run

PowerShell

$h = @{ Authorization = "Bearer $env:BZ_TOKEN" }
$s = Invoke-RestMethod -Uri https://backup.example.local:8443/api/v1/status -Headers $h -SkipCertificateCheck
if (-not $s.ok) { Write-Warning "BackupZit needs attention: $($s.failed_24h) failed backups" }

Use -k / -SkipCertificateCheck somente com o certificado autoassinado do console em uma rede confiável, ou instale o certificado do console no host de monitoramento.

Verificação de monitoramento

Consulte /api/v1/status a cada poucos minutos e alerte quando ok for false. Para verificar cada tarefa use /api/v1/jobs e alerte quando last_status for failed ou last_finished for mais antigo que o esperado.

Tarefas com RPO também retornam rpo_hours, rpo_met e last_good_backup; os agentes retornam max_runs (tarefas ao mesmo tempo). A métrica backupzit_job_rpo_met é 1 para uma tarefa dentro do RPO e 0 para uma que não o cumpriu.

Prometheus e Grafana

/api/v1/metrics retorna o estado no formato de texto do Prometheus: agentes online, execuções ativas, falhas e avisos das últimas 24 horas, backups suspeitos e, por agente, tarefa e destino, backupzit_agent_online, backupzit_job_last_status (0 sucesso, 1 aviso, 2 falha), backupzit_job_last_success_timestamp_seconds, backupzit_storage_used_bytes e backupzit_storage_free_bytes. Um job de coleta com um token de Visualizador:

- job_name: backupzit
  scheme: https
  metrics_path: /api/v1/metrics
  authorization:
    credentials: bzt_...
  static_configs:
    - targets: ['backup.example.local:8443']
