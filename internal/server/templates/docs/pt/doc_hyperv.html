Máquinas virtuais Hyper-V

O BackupZit faz backup de máquinas virtuais Hyper-V a partir do agente no host Hyper-V; nada é instalado dentro das VMs. Convidados Windows e Linux são capturados enquanto continuam rodando. Você pode restaurá-los como uma nova VM ou no lugar da original.

Configuração

  1. Instale o MSI do Agente Windows a partir de Agentes no host Hyper-V e registre-o. Hosts suportados: Windows Server 2016 ou mais novo com a função Hyper-V, ou Windows 10/11 com Hyper-V. Em um cluster, instale o agente em cada host.
  2. Em até um minuto o host aparece na página Agentes com o selo Hyper-V · N VMs.
  3. Em Tarefas de backup selecione esse agente e escolha Máquinas virtuais (Proxmox VE, Hyper-V, VMware). Depois escolha:
    • todas as VMs do host, o que também cobre VMs criadas depois;
    • VMs individuais, marcando-as.

O agente trabalha pelas interfaces do próprio Hyper-V: o módulo PowerShell do Hyper-V e a Virtual Disk API do Windows. O console não armazena credenciais do Hyper-V.

Como uma VM é copiada

  1. Um ponto de verificação de recuperação temporário (backupzit_…) é criado. É o tipo de ponto de verificação que o Hyper-V oferece a aplicativos de backup. O Hyper-V pede ao convidado que se prepare:
    • Convidados Windows descarregam os buffers de seus aplicativos via VSS.
    • Convidados Linux congelam seus sistemas de arquivos, se os daemons do Hyper-V estiverem instalados (hyperv-daemons / hv-vss-daemon).
    Se o convidado não puder fazer nenhum dos dois, o ponto de verificação é feito com consistência de falha (crash-consistent). A página da execução mostra qual tipo foi usado.
  2. O ponto de verificação de recuperação liga o Resilient Change Tracking (RCT) para os discos da VM; você verá arquivos .rct e .mrt ao lado deles. O primeiro backup lê os discos inteiros. Depois disso, o RCT informa quais blocos mudaram desde o backup anterior, e só esses são lidos.
  3. Os discos são lidos no estado do ponto de verificação, pela Virtual Disk API, em blocos de 1 MiB. Isso abrange arquivos VHDX e VHD, incluindo cadeias de pontos de verificação anteriores. Blocos vazios não são armazenados, e blocos que já estão no repositório não são enviados de novo.
  4. O ponto de verificação é removido e o Hyper-V o mescla em segundo plano.
  5. A configuração da VM é armazenada com o backup: geração, CPU, memória, adaptadores de rede (switch, VLAN, endereço MAC), controladoras de disco, inicialização segura e TPM.

VMs desligadas são lidas diretamente, sem ponto de verificação. Em hosts anteriores ao Windows Server 2016 (sem pontos de verificação de recuperação) é usado um ponto de verificação de produção, e todo backup lê os discos inteiros.

Exemplo do laboratório de testes: uma VM Linux com um disco de 3 GB. O primeiro backup leu 3 GB. O seguinte, após 64 MB de dados novos, leu 96 MB.

No Windows 10/11, o Hyper-V cria um ponto de verificação automático quando uma VM inicia, a menos que essa opção esteja desligada nas configurações da VM. O BackupZit lida com esses pontos de verificação, mas em servidores é melhor desligar os pontos de verificação automáticos (configurações da VM → Pontos de verificação).

Restaurar uma VM

Abra a execução do backup da VM (pela página da tarefa ou Atividade) e use Restaurar uma VM Hyper-V.

Como nova VM ao lado da original

Cria uma segunda VM com novos endereços MAC, para que ela possa rodar na mesma rede que a original. Por padrão ela recebe o nome da original mais "restored" e a data. Os pontos de verificação automáticos são desligados nela (o Windows os liga em VMs novas), então iniciá-la não deixa arquivos de ponto de verificação. Se a cópia roda ao lado da original e tem o agente BackupZit dentro, veja Duas máquinas usando o mesmo agente.

Configurações de rede do convidado vinculadas a um endereço MAC não se aplicam aos novos adaptadores. Um exemplo é o match: macaddress do netplan, usado por imagens de nuvem Linux.

No lugar da VM original

Marque desligá-la e substituir seus discos. O BackupZit então:

  • desliga a VM existente;
  • mescla seus pontos de verificação;
  • troca seus discos pelos restaurados.

A VM mantém seu ID, adaptadores de rede e endereços MAC, então tarefas, monitoramento e a rede do convidado continuam funcionando.

Os arquivos de disco antigos não são excluídos; eles são renomeados para ….replaced-DATE. Exclua-os quando a VM restaurada estiver funcionando.

Se a VM original não existir mais, ela é criada de novo, com um novo ID do Hyper-V.

Opções

  • Pasta para os discos virtuais: a pasta padrão do host ou qualquer pasta que contenha discos de VM. Uma restauração no local coloca os novos discos ao lado dos originais.
  • Iniciar a VM após a restauração.

O que uma VM restaurada recebe

  • Switches virtuais são conectados pelo nome. Se um switch não existir no host, o adaptador fica desconectado.
  • Toda VM restaurada recebe um novo ID de geração, para que controladores de domínio do Active Directory detectem a restauração com segurança.

Restaurar arquivos avulsos

Na tabela de VMs da execução, clique em Navegar pelos arquivos para ver as partições e volumes dos discos da VM. Você pode navegar em NTFS, ext2/3/4 e XFS, também dentro de LVM. A partir dali pode baixar arquivos ou restaurá-los em qualquer agente. Funciona exatamente como no Proxmox VE.

Linha de comando

Execute no host Hyper-V, como administrador:

backupzit-agent hyperv list
backupzit-agent hyperv backup  --repo ... [--vmid N,N]
backupzit-agent hyperv restore --repo ... --vmid N [--new] [--name NAME] [--folder D:\VMs] [--overwrite] [--start] SNAPSHOT|latest
  • --vmid é o número mostrado por hyperv list. O BackupZit o deriva do GUID da VM.
  • Sem --new, a VM é restaurada no local.
  • --overwrite confirma que os discos de uma VM existente devem ser substituídos.

As opções de repositório são as mesmas de todos os comandos; veja Referência da linha de comando.

Ainda não incluído

  • Alguns tipos de disco. VHDX compartilhado, VHD Set e discos pass-through não são copiados.
