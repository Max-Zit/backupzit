Imagens de disco e recuperação bare-metal

Um backup de imagem captura um disco inteiro — tabela de partições, partições de boot, sistema e dados — para que uma máquina possa voltar em um disco vazio ou novo exatamente como era.

O backup de imagem de disco está disponível para máquinas Windows (volumes NTFS, discos GPT e MBR). Para máquinas Linux use uma tarefa Sistema Linux.

Criar uma tarefa de imagem

  1. Em Tarefas de backup escolha Imagem de disco.
  2. O agente informa seus discos automaticamente. Escolha Todos os discos para gerar a imagem de cada disco interno da máquina em uma só tarefa, ou marque um único disco — inteiro ou apenas algumas partições (por ex. pular uma grande partição de dados que uma tarefa de arquivos já cobre).
  3. Defina retenção e agendamento como em qualquer tarefa; uma imagem semanal mais backups diários de arquivos é uma combinação comum.

Todos os discos

Uma tarefa Todos os discos faz backup de cada disco interno com tabela de partições em um único backup, também dos discos adicionados depois. Todos os volumes de todos os discos são lidos de um único snapshot VSS, então os discos ficam consistentes entre si (por ex. um banco de dados em D: com seus logs em E:). Discos USB e SD, arquivos VHD/VHDX montados e mídias removíveis ficam de fora — um disco de backup externo não deve incluir a si mesmo; escolha esse disco sozinho se precisar. A página da execução lista cada disco com suas partições; é possível navegar e restaurar arquivos de cada um. A restauração grava um disco por vez: no formulário de restauração escolha o Disco do backup e o disco de destino, e repita para o próximo disco (em bare metal: restaure primeiro o disco do sistema, pela ISO de recuperação). O agente deve ser 0.33.7 ou mais novo; um mais antigo informa que precisa ser atualizado.

Apenas os blocos usados são lidos (mapa de alocação NTFS), a imagem é tirada de um snapshot VSS para que o sistema em execução fique consistente, e blocos inalterados são deduplicados em relação às imagens anteriores — a segunda imagem da mesma máquina normalmente envia só uma pequena porcentagem.

Restaurar uma imagem em um disco

Na execução do backup de imagem, use Restaurar esta imagem em um disco:

  • Restaurar no agente — a máquina que tem o disco de destino. Pode ser uma máquina em funcionamento com um disco livre ou uma máquina iniciada pela ISO de recuperação.
  • Disco de destino — deve ser pelo menos tão grande quanto a área usada do original. Todos os dados nele são destruídos.
  • Deixar o disco offline depois — marque quando o disco original estiver na mesma máquina, para que o Windows não altere os IDs de disco da cópia.

Discos GPT e MBR, boot EFI e BIOS são suportados. O layout de partições e os IDs são recriados, então o disco restaurado inicia como antes.

Recuperação bare-metal com a ISO de recuperação

  1. Em Mídia de recuperação baixe a ISO de recuperação (Windows). Grave-a em um pendrive (Rufus, modo "imagem DD" ou "ISO") ou anexe-a a uma máquina virtual.
  2. Opcionalmente crie um código de recuperação e baixe recovery.json; copie-o para uma pasta backupzit no pendrive para que a máquina se conecte sem digitar nada.
  3. Inicie pelo pendrive a máquina a ser restaurada. Ela inicia o agente em modo de recuperação e se conecta ao console (ou pede o endereço do servidor e o código de recuperação).
  4. A máquina aparece como agente de recuperação com seus discos.
  5. Abra o backup de imagem em Atividade, escolha Restaurar esta imagem em um disco, selecione o agente de recuperação e o disco dele, confirme.
  6. Quando a execução terminar, remova o pendrive e reinicie.

Restaurar em hardware diferente

O Windows só inicia com um driver para a controladora de disco de onde ele dá boot, e a instalação do Windows desativa os drivers de que não precisou. Por isso a imagem de um PC com controladora Intel para com INACCESSIBLE_BOOT_DEVICE em uma placa AMD, um drive NVMe, no Hyper-V ou em uma VM do Proxmox. Marque Restaurar em hardware diferente no formulário de restauração e o BackupZit prepara o Windows restaurado após gravar a imagem:

  1. Os drivers das controladoras de disco comuns que fazem parte do Windows voltam a iniciar no boot: AHCI/SATA, NVMe, Intel RST, LSI/Broadcom/Dell PERC SAS e RAID, HPE Smart Array, Hyper-V e VMware.
  2. Drivers adicionais são incluídos com o DISM: os drivers da ISO de recuperação (ela traz os drivers VirtIO para Proxmox/KVM) e as pastas que você informar em Drivers adicionais — por ex. os drivers de armazenamento e rede da nova placa-mãe, extraídos em um pendrive (E:\Drivers; as subpastas são pesquisadas).
  3. Os arquivos de boot são recriados para a nova máquina (bcdboot).

A página da execução lista os drivers ativados e adicionados. O Windows detecta os demais dispositivos novos na primeira inicialização; a ativação pode pedir para ser repetida em hardware novo. Não é possível restaurar entre UEFI e BIOS legado — o destino deve dar boot da mesma forma que o original.

De PC ou servidor físico para o Proxmox VE: crie uma VM com OVMF (UEFI) para discos GPT ou SeaBIOS para discos MBR, um disco VirtIO SCSI pelo menos tão grande quanto o original e uma placa de rede VirtIO, anexe a ISO de recuperação e restaure com Restaurar em hardware diferente. A ISO de recuperação reconhece sozinha discos e placas de rede VirtIO.

Restaurar em uma máquina virtual

Crie um disco de VM vazio pelo menos tão grande quanto o original, inicie a VM pela ISO de recuperação e siga os passos acima. Essa também é a maneira mais fácil de testar se suas imagens realmente iniciam.
