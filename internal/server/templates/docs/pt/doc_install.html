Instalar o servidor

A console funciona em Linux (Debian, Ubuntu, AlmaLinux, Rocky Linux) com PostgreSQL. Cada organização executa a sua própria console na sua própria rede.

Requisitos

  • Uma VM ou um servidor Linux: 2 vCPU, 2–4 GB de RAM e 20 GB de disco chegam para centenas de agentes (os dados de backup não são guardados nele).
  • PostgreSQL 13 ou mais recente (local ou noutro servidor).
  • Rede: os agentes precisam alcançar a console por TCP 8443 (HTTPS). Os agentes também precisam alcançar diretamente o armazenamento.

1. Imagem de VM pronta

Um appliance pronto (Debian, PostgreSQL, a console, atualizações de segurança automáticas) que inicia em menos de um minuto e não precisa de acesso à internet:

HipervisorComo
VMware ESXiHost Client: Create / Register VM → Deploy a virtual machine from an OVF or OVA file, escolha backupzit-appliance.ova. vSphere: Deploy OVF Template. Workstation e VirtualBox: File → Open / Import.
Proxmox VECopie backupzit-appliance.qcow2 para o nó, crie uma VM sem disco (2 vCPU, 2–4 GB de RAM, rede VirtIO), depois
qm importdisk <vmid> backupzit-appliance.qcow2 local-lvm
anexe o disco importado como SCSI, torne-o o disco de arranque e ative o agente convidado QEMU.
Hyper-VDescompacte backupzit-appliance-vhdx.zip, depois Novo → Máquina Virtual, geração 1, 2–4 GB de RAM, Usar um disco rígido virtual existente: o VHDX.

Inicie a VM. A tela dela mostra o endereço da console web e a senha inicial de admin (veja Primeiro login). Dê à VM 2 vCPU e 2–4 GB de RAM; pode aumentar o disco de 16 GB a qualquer momento — o appliance passa a usar o novo espaço no arranque seguinte (o sistema de arquivos raiz cresce a quente). No primeiro arranque cada cópia cria as suas próprias chaves SSH, senha do banco de dados e chave de segredos, por isso a mesma imagem pode ser implantada muitas vezes. A placa de rede obtém o endereço por DHCP.

2. ISO do appliance

A ISO do appliance instala tudo sem perguntas: Debian, PostgreSQL, a console e as atualizações de segurança automáticas.

  1. Crie uma VM (ou use um servidor) com 2 vCPU, 2–4 GB de RAM e um disco de 16 GB ou mais. Use VirtIO ou os dispositivos padrão do hipervisor, BIOS ou UEFI.
  2. Inicie-a a partir de backupzit-appliance.iso. Após 5 segundos a instalação começa sozinha, apaga o primeiro disco e instala. Ela baixa os pacotes do sistema operacional, por isso o servidor precisa de acesso à internet durante a instalação. Demora cerca de 10–20 minutos e depois o servidor reinicia.
  3. A tela do servidor mostra o endereço da console web e a senha inicial de admin. Abra o endereço, faça login e altere a senha.

O appliance (imagem ou ISO)

O appliance tem duas contas separadas:

  • admin na console web (https://<address>:8443) para o trabalho diário. A sua senha inicial aparece na tela do servidor após o primeiro arranque; altere-a em Minha conta.
  • bzadmin no próprio servidor (a sua tela na console do hipervisor, ou SSH), senha inicial backupzit. Tem de alterá-la no primeiro login; o usuário pode usar sudo. O root não pode fazer login.

As atualizações do BackupZit e do sistema operacional são geridas a partir da console (veja abaixo). O VMware Tools e o agente convidado QEMU estão incluídos, para que os hipervisores mostrem o endereço do appliance.

Menu de configuração na tela do servidor

Quando o bzadmin faz login na própria tela do servidor (não por SSH), abre-se um menu:

ItemO que faz
1 NetworkDHCP ou um endereço estático com comprimento de prefixo (p. ex. 192.168.1.20/24), gateway e até três servidores DNS.
2 Server nameO nome do host (letras, dígitos e -).
3 SSHLiga ou desliga o servidor SSH e altera a sua porta. As portas da console (80, 443, 8443), do PostgreSQL (5432) e da recuperação instantânea (111, 2049) não podem ser usadas.
4 Reset the password of "admin"Para uma senha esquecida da console web; também remove bloqueios de login. Depois a tela deixa de mostrar a senha inicial gerada (o mesmo acontece a partir do arranque seguinte, depois de a senha de admin ser alterada na console web).
5 Lift sign-in blocks and web console limitsQuando demasiados logins falhados bloquearam um endereço, ou a console web está limitada a endereços que já não pode usar (veja Segurança).
6–8Reiniciar a console web, reiniciar ou desligar o servidor.
9 Time zoneO appliance começa em UTC. Defina o seu fuso, p. ex. Europe/Belgrade: a console mostra todas as horas, executa os agendamentos e lê os pontos de restauração (também o momento de uma restauração de banco de dados) nesse fuso. A console reinicia para o aplicar.
0 Command lineSai do menu. Abra-o de novo com sudo backupzit-server --setup (também por SSH).

As mesmas configurações de rede, nome do servidor, SSH e fuso horário estão em Configurações → Rede na console web (só administradores). Aí, um endereço estático cujo gateway não responde em meio minuto é desfeito automaticamente, para que um erro de digitação não deixe o appliance sem rede; se mesmo assim não conseguir alcançar a console, use o menu na tela do servidor, que funciona mesmo com o SSH desligado.

Os agentes lembram-se do certificado da console, não do seu endereço. Se alcançam a console pelo endereço IP e este muda, aponte-os para o novo com backupzit-agent set-server (veja Agentes), ou use um nome DNS desde o início. Com DHCP, reserve o endereço do appliance no servidor DHCP para que não mude.

O servidor SSH do appliance só oferece cifras AES-GCM/CTR e MACs SHA-2 (nada de chacha20-poly1305 nem MACs de 64 bits, que os scanners de vulnerabilidades apontam como fracos).

3. Script de instalação

Num servidor existente com Debian 12+, Ubuntu 22.04+, AlmaLinux ou Rocky Linux 9+ (x86-64), como root:

curl -fsSL https://github.com/Max-Zit/backupzit/releases/latest/download/install.sh | sudo sh

O script instala o PostgreSQL, baixa a versão mais recente, verifica a sua assinatura com a chave de publicação do BackupZit e a soma de verificação do pacote, instala a console, cria o banco de dados com uma senha aleatória, grava /etc/backupzit/server.env, ativa as atualizações de segurança automáticas, abre a porta 8443 no firewalld ou ufw se estiverem ativos, inicia a console e mostra o seu endereço e a senha inicial de admin. Opções (depois de sh -s --):

OpçãoEfeito
--version 0.32.0instalar esta versão em vez da mais recente
--db postgres://user:pw@host:5432/dbusar um banco PostgreSQL existente em vez de um local
--hosts backup.example.local,10.0.0.10nomes e endereços para o certificado da console (padrão: o endereço e o nome do servidor)
--no-auto-updatesdeixar as atualizações de segurança automáticas como estão

Exemplo: curl -fsSL …/install.sh | sudo sh -s -- --hosts backup.example.local. Executar o script de novo numa console instalada atualiza o BackupZit e mantém a configuração e os dados. Para ler o script antes de o executar, baixe-o primeiro: curl -fsSLO …/install.sh; less install.sh; sudo sh install.sh.

4. Pacotes à mão

Debian / Ubuntu

apt install postgresql
apt install ./backupzit-server_*.deb

AlmaLinux / Rocky Linux

dnf install postgresql-server && postgresql-setup --initdb && systemctl enable --now postgresql
dnf install ./backupzit-server-*.rpm

No AlmaLinux e no Rocky Linux, troque ident por scram-sha-256 nas linhas 127.0.0.1 e ::1 de /var/lib/pgsql/data/pg_hba.conf e reinicie o PostgreSQL, para que a console possa fazer login com senha.

Criar o banco de dados

sudo -u postgres psql -c "SET password_encryption = 'scram-sha-256'; CREATE USER backupzit WITH PASSWORD 'choose-a-strong-password'"
sudo -u postgres psql -c "CREATE DATABASE backupzit OWNER backupzit"

Coloque a string de conexão em /etc/backupzit/server.env:

BACKUPZIT_DB=postgres://backupzit:choose-a-strong-password@localhost:5432/backupzit?sslmode=disable
BACKUPZIT_PUBLIC_URL=https://backup.example.local:8443
BACKUPZIT_TLS_HOSTS=backup.example.local,10.0.0.10
systemctl start backupzit-server

Primeiro login

Abra https://<server>:8443. O administrador inicial é admin; a senha está em /var/lib/backupzit/initial-admin-password.txt (ou defina BACKUPZIT_ADMIN_PASSWORD antes do primeiro arranque). Altere-a depois de fazer login. Para redefinir uma senha esquecida no servidor:

set -a; . /etc/backupzit/server.env; set +a
backupzit-server --set-admin-password 'NEW-PASSWORD'

O certificado

No primeiro arranque a console cria um certificado autoassinado. O navegador avisará uma vez; os agentes não dependem de autoridades de certificação — eles fixam a impressão digital do certificado mostrada na página Agentes quando se registram. Isso protege os agentes contra um servidor falso mesmo numa rede não confiável.

Não substitua esse certificado (cert.pem/key.pem no diretório de dados): os agentes registrados antes recusariam a conexão até serem registrados de novo. Para os navegadores, adicione em vez disso um certificado confiável como descrito abaixo.

Um certificado confiável para os navegadores

Para evitar o aviso do navegador, abra Configurações → Certificado. A console passa então a responder também num nome DNS, por exemplo https://backup.example.com na porta 443, com um certificado confiável. Os agentes continuam a usar a porta 8443 e o certificado fixado, por isso não são afetados.

  • Enviar um certificado da CA da sua empresa ou de uma CA pública, também um certificado curinga como *.example.com. Cole o certificado (com os certificados intermediários) e a chave privada em PEM, ou escolha os arquivos. A console verifica que a chave pertence ao certificado, que este é válido agora e que cobre o nome DNS. Sem DNS interno, informe em vez disso o endereço IP da console e use um certificado emitido para esse IP (nome alternativo IP:192.168.1.20); nesse caso dê à console um endereço fixo. Receberá um e-mail 21 dias antes de expirar.
  • Let's Encrypt: certificados gratuitos, renovados automaticamente 30 dias antes de expirarem. O Let's Encrypt tem de verificar que controla o nome, de uma de duas formas:
    • Verificação DNS via Cloudflare, recomendada para consoles que não são acessíveis pela internet. O BackupZit cria um registro TXT temporário com um token de API do Cloudflare. No Cloudflare, vá a My Profile → API Tokens → Create Token, use o modelo Edit zone DNS e limite-o à sua zona.
    • Verificação HTTP: a porta 80 da console tem de estar acessível pela internet com o nome DNS. Raramente se quer isso num servidor de backup.
    Experimente primeiro a configuração com Usar o sistema de testes do Let's Encrypt. Os navegadores não confiam nos seus certificados, mas não tem limites de taxa.
  • Atender na porta 80 redireciona http:// para https://.

O nome DNS tem de apontar para o endereço IP da console, normalmente através de um registro A no seu DNS interno. Os arquivos do certificado ficam em /var/lib/backupzit/web e a chave só pode ser lida pelo serviço. No Linux o serviço pode usar as portas 80 e 443 (CAP_NET_BIND_SERVICE); abra-as no firewall se houver navegadores a conectar-se de outras redes.

Atualizar o BackupZit

Por padrão a console obtém as atualizações das versões oficiais do BackupZit no GitHub (https://github.com/Max-Zit/backupzit/releases). Em Configurações → Atualizações pode indicar outra origem de atualizações — o seu próprio espelho HTTPS ou uma pasta no servidor. Seja qual for a origem, cada versão tem de ter uma assinatura válida do BackupZit. A console verifica diariamente se há novas versões e envia um e-mail aos administradores quando há uma disponível. Para instalá-la, clique em Instalar:

  1. A console verifica a assinatura da versão e a soma de verificação do pacote, e espera até não haver nenhum backup ou restauração em curso.
  2. Um serviço do sistema (backupzit-update, executado como root) volta a verificar a assinatura com as chaves de publicação incorporadas no BackupZit. Nem mesmo uma console comprometida consegue fazer instalar outro pacote.
  3. Faz backup do banco de dados (pg_dump), mantém o programa atual, instala o pacote e reinicia a console.
  4. Se a nova versão não responder em dois minutos, o programa anterior e o banco de dados como estava são restaurados automaticamente. O resultado, com o log do arranque falhado, aparece na página Atualizações, fica no log de auditoria e é enviado por e-mail.
  5. Após uma atualização bem-sucedida os agentes também são atualizados: cada um instala a nova versão quando está ocioso. Desative isso na mesma página se preferir atualizá-los você mesmo.

A console fica indisponível durante cerca de um minuto. Os backups do banco de dados e os programas anteriores das últimas três atualizações são mantidos em /var/lib/backupzit-update.

Sem acesso à internet: baixe os arquivos da versão (manifest.json, manifest.json.sig e o pacote do servidor) noutro computador. Depois envie-os em Instalar uma atualização a partir de arquivos, ou copie-os para uma pasta no servidor e use essa pasta como origem de atualizações.

Ainda pode atualizar com o gerenciador de pacotes (apt install ./backupzit-server_….deb); o banco de dados é migrado quando a nova versão inicia.

Atualizações do sistema operacional

A mesma página (Configurações → Atualizações) mostra o sistema operacional do servidor da console: quantas atualizações estão disponíveis, quantas são correções de segurança, se é preciso reiniciar e se as atualizações de segurança automáticas estão ativas. O estado é atualizado diariamente, ou com Verificar agora. Pode:

  • Ativar as atualizações de segurança automáticas (recomendado). A ferramenta do próprio sistema instala diariamente só correções de segurança: unattended-upgrades no Debian e Ubuntu, dnf-automatic no AlmaLinux e Rocky Linux.
  • Instalar agora todas as atualizações. Serviços como o PostgreSQL podem reiniciar brevemente, e a console reconecta-se sozinha.
  • Reiniciar servidor, por exemplo após uma atualização do kernel. A console recusa enquanto houver backups ou restaurações em curso. Os agentes mantêm as suas tarefas e reportam os resultados quando a console voltar.

Estas tarefas passam pelo mesmo serviço root que as atualizações da console. Ficam registradas no log de auditoria, e a saída da última tarefa aparece na página.

Fazer backup da própria console

Os backups no seu armazenamento continuam legíveis sem a console, graças às fichas de recuperação. Para recuperar também a própria console depois de perder o seu servidor, ative Configurações → Backup do console. Isso inclui tarefas, agendamentos, agentes, usuários, configurações, histórico de execuções e credenciais guardadas. A console passa então a fazer backup de si mesma diariamente para um destino de armazenamento de rede, na pasta backupzit-console.

Um backup da console contém:

  • todo o banco de dados, exportado tabela a tabela, para não ser preciso nenhuma versão específica de pg_dump;
  • a chave de segredos que descriptografa as credenciais guardadas;
  • o certificado da console, que os agentes fixam.

É criptografado com a chave de recuperação do destino e desduplicado. Os backups mais recentes são mantidos: 14 por padrão.

Restaurar a console

  1. Instale uma nova console com a mesma versão ou uma mais recente, por exemplo a partir da ISO do appliance.
  2. No novo servidor, como root, execute o seguinte. As credenciais são as da ficha de recuperação do destino de armazenamento, e o endereço do repositório aparece na página Backup do console. 
    systemctl stop backupzit-server
set -a; . /etc/backupzit/server.env; set +a
export BACKUPZIT_PASSWORD='<recovery key>'
export BACKUPZIT_SFTP_PASSWORD='…' BACKUPZIT_SFTP_HOSTKEY='SHA256:…'   # or BACKUPZIT_S3_ACCESS_KEY/_SECRET_KEY, _SMB_PASSWORD, _AZURE_KEY, _HARDENED_KEY/_FINGERPRINT
backupzit-server --restore-console --repo 'sftp://backup@nas:22/backups/backupzit-console'
systemctl start backupzit-server
  3. Dê ao novo servidor o endereço IP ou o nome DNS do antigo. Os agentes confiam no certificado restaurado e reconectam-se sozinhos.

A restauração substitui o banco de dados da nova console pelo do backup e atualiza-o para a versão instalada. --snapshot ID restaura um backup mais antigo em vez do mais recente.

Guarde também uma cópia das fichas de recuperação e de secrets.key fora do servidor, por exemplo no seu gerenciador de senhas.
