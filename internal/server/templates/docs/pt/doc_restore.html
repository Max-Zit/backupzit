Restauração

Qualquer backup bem-sucedido pode ser restaurado: por completo ou só pastas selecionadas, na mesma máquina, noutro agente ou como nova máquina virtual.

O assistente de restauração

Clique em Restaurar no menu. O assistente faz quatro perguntas:

  1. O que quer restaurar?
    • uma máquina virtual inteira
    • arquivos de uma máquina virtual
    • arquivos e pastas
    • uma imagem de disco / bare metal
    • arquivos de uma imagem de disco
    • um banco de dados (para um momento)
    • um sistema Linux inteiro
    • e-mail do Microsoft 365, OneDrive, calendários e contatos e arquivos do SharePoint (veja Microsoft 365)
    Cada opção mostra quantos pontos de restauração existem.
  2. Origem: a máquina virtual (em todos os hipervisores e tarefas), ou a tarefa de backup e a sua máquina.
  3. Ponto de restauração: o backup a partir do qual restaurar, o mais recente primeiro, com estado, armazenamento e tamanho.
    • Backups sinalizados como suspeitos (possível ransomware) aparecem marcados.
    • Cópias em armazenamento secundário feitas por uma tarefa de cópia de backup aparecem como cópia (backups de arquivos e de VMs).
  4. Opções: onde e como restaurar. Um resumo do que escolheu aparece acima das opções.

Os passos no topo são links, por isso pode voltar a qualquer passo anterior. Cada passo tem o seu próprio endereço, para o guardar nos favoritos ou partilhar.

As opções são as mesmas da página de um backup em Atividade, onde também pode iniciar uma restauração diretamente. Só os usuários cuja função permite restaurar veem o assistente.

Restaurar a partir de um backup de arquivos

  1. Escolha Arquivos e pastas no assistente de restauração e depois a tarefa e o ponto de restauração. Em alternativa, abra o backup em Atividade ou na página da tarefa.
  2. Em Restaurar arquivos deste backup escolha o agente que deve receber os arquivos. Pode ser uma máquina diferente da que foi copiada — por exemplo um PC de substituição.
  3. Escolha onde:
    • Restaurar em uma pasta (recomendado) — p. ex. D:\Restore. A estrutura original é recriada por baixo: D:\Restore\C\Users\ana\Documents\…. Nada do que existe é tocado.
    • Restaurar no local original — grava os arquivos onde estavam, sobrescrevendo as versões atuais. Num compartilhamento NAS o agente volta a conectar o compartilhamento com escrita. Arquivos esparsos (imagens de VM, bancos de dados) voltam esparsos. No Windows só um arquivo que era esparso é marcado como esparso de novo; os outros, como discos VHD/VHDX (o Hyper-V recusa discos esparsos), voltam como arquivos normais, assim como todos os arquivos de backups feitos com agentes anteriores à 0.57, que não registravam o atributo. Nunca se grava através de um link simbólico ou junção (junction) que esteja no caminho: restaurar em uma pasta o substitui por uma pasta, e toda restauração grava somente nas pastas que abriu, mesmo quando um link aparece durante a execução (0.58: também em backups de arquivos e no local original; a raiz de um volume como / ou C: não pode ser escolhida como pasta para arquivos de backups de VM e de imagem). No local original só são seguidos os links do sistema (de propriedade do root ou do usuário do agente no Linux, do SYSTEM, do TrustedInstaller ou de um administrador no Windows, e que ninguém mais pode alterar nem substituir: os antigos links de compatibilidade nos perfis de usuário, como Application Data, não são seguidos); um link para uma pasta que não existe é um erro, e nada é criado onde ele aponta. Proprietário, permissões e atributos são definidos no próprio arquivo restaurado, nunca através de um link colocado no lugar dele. Desde a 0.59 um link assim também precisa ter um único nome: um link físico para ele, que outro usuário poderia criar, não é seguido.
  4. Opcionalmente limite a Somente estes caminhos, um por linha, p. ex. C:\Users\ana\Documents\Contracts — ou escolha-os no navegador de arquivos (abaixo).
  5. Mantenha Verificar arquivos restaurados ativado: cada arquivo é lido de volta e comparado com a soma de verificação do backup.
  6. Clique em Iniciar restauração. O progresso e os resultados aparecem na página da execução de restauração.

Também são restaurados os horários dos arquivos, os atributos do Windows (oculto, somente leitura, …) e, no Linux, proprietários, permissões (incluindo bits setuid), ACLs, atributos estendidos (rótulos SELinux, capacidades de arquivo), links simbólicos e físicos. No macOS também as flags de arquivo BSD (oculto, bloqueado…), a data de criação e os atributos estendidos (veja Agentes macOS). Os proprietários só são definidos quando o agente é executado como root/administrador.

Navegar, baixar e escolher arquivos

Na execução de backup, Navegar pelos arquivos mostra as pastas copiadas como estavam (também para compartilhamentos NAS e backups de sistema Linux). Abra pastas, marque arquivos e pastas e depois:

  • Baixar — um arquivo vem como está, vários arquivos ou pastas como arquivo ZIP, diretamente no navegador. Os downloads ficam registrados no log de auditoria.
  • Restaurá-los num agente — numa pasta ou no local original, como uma restauração com Somente estes caminhos.

Início do backup, no começo do caminho, volta ao primeiro nível, e a linha .. no topo da lista sobe uma pasta; a navegação pelos arquivos de um disco de VM funciona da mesma forma.

Um link simbólico para um arquivo (p. ex. /etc/os-release) é baixado como o arquivo para onde aponta, se esse arquivo estiver no backup; links para pastas são omitidos dos arquivos ZIP. O mesmo vale para arquivos baixados de backups de máquinas virtuais (ext4, XFS). Uma restauração num agente recria os links como links.

O console lê o backup do armazenamento por conta própria, então a navegação funciona para backups em armazenamento de rede (SFTP, S3, SMB, Azure, repositório reforçado); o armazenamento acessível somente por agentes é lido por meio de um agente que o usa (agentes 0.61 e mais recentes). Para um disco local ou um disco USB de um agente, restaure com os caminhos. Usuários com uma função de restauração podem navegar e baixar.

Encontrar o backup certo: use o Calendário para ver que backups foram executados em que dia, ou o histórico na página da tarefa.

Restaurar arquivos individuais de uma imagem de disco

Em backups de imagem, clique em Navegar pelos arquivos na execução de backup. Pode navegar no sistema de arquivos NTFS da imagem diretamente na console, marcar arquivos e pastas e restaurá-los em qualquer agente — sem restaurar o disco inteiro. Restaurados numa pasta, os arquivos ficam com a mesma estrutura de um backup de arquivos: a letra da unidade passa a ser a primeira pasta (D:\Restore\C\Users\…).

Também pode transferir os ficheiros marcados diretamente para o navegador: um ficheiro chega tal como está, vários ficheiros ou pastas num arquivo ZIP — útil para um único documento de uma cópia de imagem grande. Tal como a navegação, funciona para cópias de imagem em armazenamento de rede, requer a permissão Restaurar, e o registo de auditoria regista os caminhos transferidos.

Restaurar arquivos individuais de uma VM (Proxmox VE, Hyper-V, VMware)

Numa execução de backup de VM clique em Navegar pelos arquivos ao lado do convidado. A console mostra as partições e volumes LVM dos seus discos e permite navegar em sistemas de arquivos NTFS, ext4 e XFS. Baixe os arquivos marcados (vários como arquivo ZIP) ou restaure-os em qualquer agente. Veja Proxmox VE, Hyper-V e VMware ESXi. Os arquivos restaurados em um agente mantêm as permissões Unix que tinham na VM (ext4, XFS), então segredos restaurados como /etc/shadow continuam privados; no Linux, arquivos de volumes NTFS só podem ser lidos pelo proprietário. Restaurados em um agente Windows, nomes com : de convidados Linux (ext4, XFS) são ignorados e listados: o Windows leria a parte depois dos dois-pontos como um fluxo de outro arquivo. Fluxos de dados alternativos do NTFS são restaurados como fluxos.

Restaurar máquinas inteiras

  • Imagens de disco do Windows: num disco ou bare metal, também em hardware diferente — Imagens de disco.
  • Sistemas Linux: num disco ou bare metal, ou como nova VM do Proxmox — Backup do sistema Linux.
  • VMs e contêineres do Proxmox: como novo convidado ou no local — Proxmox VE. As VMs do Proxmox também podem ser executadas instantaneamente a partir do backup e movidas para um armazenamento enquanto funcionam (recuperação instantânea).
  • Bancos de dados (SQL Server, PostgreSQL, MySQL/MariaDB): com um novo nome ou no local, para um momento — Bancos de dados.
  • VMs Hyper-V: como nova VM ou no local (mantém o ID e os endereços MAC) — Hyper-V.
  • VMs VMware ESXi: como nova VM ou no local (mantém o UUID e os endereços MAC), em qualquer host ESXi e datastore — VMware ESXi; também instantaneamente a partir do backup através de um agente proxy Linux, e depois copiada para um datastore (recuperação instantânea).

ISOs de recuperação

As restaurações bare metal iniciam a máquina a partir de uma ISO de recuperação (num pendrive USB ou anexada a uma VM), veja Mídia de recuperação:

  • ISO de recuperação Linux — publicada com cada versão (backupzit-recovery-linux.iso); a página Mídia de recuperação faz link para ela a partir da origem de atualizações.
  • ISO de recuperação Windows — o Windows PE não pode ser redistribuído, por isso é gerada uma vez em qualquer PC com Windows 10/11 ou Server:
    1. Instale o Windows ADK gratuito (recurso Deployment Tools) e o complemento Windows PE da Microsoft.
    2. Baixe build-winpe.ps1 da versão (ao lado dos pacotes do agente) e copie backupzit-agent.exe de C:\Program Files\backupzit Agent numa máquina com o agente.
    3. Num PowerShell de administrador: .\build-winpe.ps1 -AgentExe .\backupzit-agent.exe -Out .\backupzit-recovery.iso. Adicione -DriverDir C:\Drivers para drivers de armazenamento ou rede (p. ex. VirtIO para VMs do Proxmox) e -RecoveryJson .\recovery.json para que se conecte sem digitar nada.
    4. No arranque, a ISO procura \backupzit\recovery.json em todas as unidades. Se o encontrar, o agente de recuperação liga-se a esta consola e o restauro é iniciado aqui, pelo que no local basta arrancar a pen. Sem ele, abre-se o programa gráfico de recuperação (backupzit-recovery.exe, instalado junto ao agente): restaurar uma imagem de disco ou partições individuais, também para um disco menor ou maior, reparar o arranque, carregar controladores. A linha de comandos do suporte inicia o outro (backupzit-recovery ou backupzit-agent recovery). Com -AccessPackage .\backupzit.bzaccess (criado em Suportes de recuperação) o programa abre as cópias de segurança sem esta consola; só é necessária a frase-passe. Esta precisa de 12 caracteres de três tipos (16 de dois, 20 de um), e as palavras-passe comuns são recusadas; a página propõe uma gerada que se escreve da mesma forma em teclados QWERTY, QWERTZ e AZERTY.
    5. O idioma e o teclado do Windows PE são os do PC que cria a ISO, tal como o fuso horário (-Language de-de, -KeyboardLayout e -TimeZone escolhem outros), para que um endereço de servidor ou uma frase-passe se escreva como nesse PC. O programa de recuperação fala os 14 idiomas da consola. -NoUi inclui só o agente de consola. O suporte contém os textos das licenças e SOURCE-CODE.txt em \backupzit\.
    6. Antes de gravar, o programa verifica de novo o disco de destino por tamanho, modelo, número de série e ID da tabela de partições: um disco que entretanto recebeu o número escolhido (um disco USB ligado de novo) é recusado, tal como os discos com as cópias de segurança, o suporte de recuperação e um pacote de acesso. Um restauro para o disco original mantém o layout do backup quando cabe (nenhuma partição cresce para um espaço vazio); Ajustar ao disco de destino é proposto para um disco menor ou quando escolhido. Um disco convertido para GPT ou MBR não pode ficar offline. A reparação do arranque guarda antes os dados de arranque em \backupzit noutra unidade.
    7. O programa funciona só com o teclado (Tab, Enter, Espaço, Esc) e em ecrãs até 800×600, onde as suas páginas se deslocam. O resumo indica a vermelho o disco que será apagado (número, modelo, tamanho); a restauração só começa depois de esse número ser digitado. Uma localização SFTP sem pacote de acesso mostra a chave de host do servidor e pergunta antes de confiar nela: compare-a com ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub no servidor.
    8. Opcionalmente copie a ISO para o diretório /var/lib/backupzit/dist da console; ela passa então a ser oferecida na página Mídia de recuperação.

Navegar por arquivos no console funciona para backups em armazenamento de rede (SFTP, S3, SMB, Azure, repositório reforçado): o console os lê diretamente ou, para armazenamento acessível somente por agentes, por meio de um agente que o usa (também com uma chave SSH; agentes 0.61 e mais recentes). Para backups em um disco local de um agente ou em SFTP com uma chave SSH, uma restauração com Somente estes caminhos continua funcionando a partir do console; para ver o conteúdo, use a linha de comando.

Restaurar sem a console

Se a própria console se perder, qualquer máquina com o agente instalado pode restaurar diretamente do armazenamento usando a ficha de recuperação do destino de armazenamento:

set BACKUPZIT_PASSWORD=<recovery key>
set BACKUPZIT_SFTP_PASSWORD=...           (or the S3/SMB/hardened credentials)
set BACKUPZIT_SFTP_HOSTKEY=SHA256:...      (the SFTP host key, on the recovery sheet)
backupzit-agent snapshots --repo sftp://backup@nas:22/backups/pc1_1a2b3c4d
backupzit-agent restore   --repo sftp://backup@nas:22/backups/pc1_1a2b3c4d --target D:\Restore latest

latest é o backup mais recente de qualquer tarefa daquele computador; para restaurar uma tarefa específica, use um ID de snapshot obtido com snapshots. Veja Referência da linha de comandos.

Testes de restauração automáticos

O BackupZit põe os seus backups à prova regularmente sem que tenha de fazer nada: semanalmente (configurável em Configurações → Testes de restauração) o agente de cada tarefa restaura uma amostra aleatória de arquivos do backup mais recente numa pasta temporária, verifica cada byte contra as somas de verificação guardadas e volta a apagá-la. Em imagens de disco, blocos aleatórios são lidos e verificados. Assim se testa toda a cadeia — acesso ao armazenamento, credenciais, chave de criptografia e integridade dos dados.

  • Os resultados aparecem em Atividade e no histórico da tarefa como execuções de Teste de restauração, e por tarefa em Relatórios (coluna Teste de restauração).
  • Um teste com falha é uma falha como qualquer outra e gera um alerta por e-mail.
  • Testar restauração na página de uma tarefa inicia um teste imediatamente.
  • O tamanho da amostra limita quanto é lido do armazenamento — mantenha-o pequeno em armazenamento em nuvem com taxas de download.

Teste de inicialização para VMs do Proxmox

Blocos legíveis não provam que uma VM ainda inicia. Com Teste de inicialização para backups de VMs do Proxmox ativado (Configurações → Testes de restauração), o teste de restauração de uma tarefa de VM do Proxmox também inicia cada VM do backup mais recente no nó da tarefa, uma após a outra, com recuperação instantânea: ela é executada a partir do backup com um novo ID e as placas de rede desconectadas (para não entrar em conflito com a original) e é excluída logo a seguir. O teste passa quando o agente convidado QEMU da VM responde dentro do tempo configurado, o que significa que o sistema operacional iniciou. VMs sem agente convidado passam se continuarem em execução durante um minuto; a página da execução mostra-as como em execução em vez de iniciada. A cópia também deixa de fora as configurações que chegam fora da VM: um script hook, argumentos brutos do QEMU (args), dispositivos PCI e USB repassados, compartilhamentos do host (virtiofs) e portas seriais ou paralelas em dispositivos do host; a página da execução mostra o que foi deixado de fora. Uma VM que não consegue iniciar sem eles falha no teste de inicialização.

  • O nó precisa de memória livre para mais uma VM durante o teste.
  • Instale o agente convidado QEMU nas VMs (qemu-guest-agent no Linux, as ferramentas de convidado VirtIO no Windows) e ative-o nas opções da VM, para que o teste possa confirmar a inicialização.
  • A página da execução lista cada VM com o seu resultado e quanto tempo demorou a inicialização.

Verificações dentro da VM (agentes 0.61 e mais recentes): uma VM que inicializa ainda pode estar com defeito, ou já comprometida quando o backup foi feito. Em uma tarefa de VM do Proxmox, Verificações do teste de inicialização lista o que precisa funcionar na cópia inicializada, uma por linha: service sshd (o serviço está em execução), file /var/www/index.html (o arquivo existe), port 443 (um programa escuta na porta TCP) ou command … (seu próprio comando termina com código de saída 0; sh no Linux, cmd no Windows). Uma linha que começa com o ID de uma VM e dois-pontos, p. ex. 101: service nginx, vale só para essa VM. As verificações são executadas pelo agente convidado do QEMU como root ou SYSTEM dentro da cópia isolada e repetidas até passarem ou terminar a espera do teste de inicialização; a página da execução mostra cada uma. Somente usuários que podem alterar comandos as definem.

Testar também a inicialização do backup mais antigo mantido pela tarefa inicia também as VMs do ponto de restauração mantido mais antigo, para que você saiba que o ponto ao qual voltaria após um comprometimento não percebido ainda inicializa. Um backup de VM cujas VMs inicializaram e passaram nas verificações aparece como verificado na sua página de execução, de onde é restaurado.

Verificação de todos os dados armazenados

Os testes de restauração leem uma amostra. Além disso, um agente lê todos os dados de cada repositório, verifica-os pela soma de verificação e confere se as pastas e os dados de cada backup estão presentes — mensalmente por padrão (Configurações → Testes de restauração: Verificar os dados armazenados: mensal, a cada três meses ou nunca). Isso encontra danos no próprio armazenamento, como um disco falhando em um NAS ou degradação de dados, antes que você precise do backup. Cada repositório é verificado uma vez (as tarefas de um agente em um armazenamento o compartilham), pelo agente que grava nele. A verificação lê tudo o que o repositório contém; no armazenamento em nuvem (S3, Azure) ela só roda com Também em armazenamento na nuvem. Problemas fazem a execução Verificação de dados falhar e enviam uma notificação de falha; Verificar dados na página de uma tarefa inicia uma verificação na hora. Requer agentes 0.39.0 ou mais novos. Em S3, Azure e armazenamento reforçado a verificação lê vários pacotes de dados de uma vez (agentes 0.54.2 e mais recentes). Enquanto uma verificação é executada, Atividade e a página da execução mostram quantos pacotes de dados do repositório ela já verificou. Uma verificação que encontra pacotes de dados danificados oferece Reparo na página da sua execução (Solução de problemas).

Além disso, restaure à mão de vez em quando (p. ex. trimestralmente) uma pasta real e abra alguns arquivos — isto também treina as pessoas que terão de o fazer numa emergência.
