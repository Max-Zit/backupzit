Agentes

Em cada máquina protegida é instalado um agente. Ele funciona como serviço, pede trabalho à console a cada 30 segundos e comunica diretamente com o armazenamento.

Sistemas suportados

  • Windows 10, 11 e Windows Server 2016 e posteriores — MSI Agente Windows.
  • Windows 7 SP1, Windows Server 2008 R2 SP1 e 2012 R2 — MSI Agente Windows — sistemas antigos (…-legacy.msi), com as mesmas funções, incluindo VSS e imagens de disco.
  • Debian, Ubuntu, AlmaLinux, Rocky Linux (64 bits).
  • Nós Proxmox VE 7 e 8 — o pacote Debian; o agente faz então também backup das VMs e contêineres do nó (veja Proxmox VE).
  • Hosts Hyper-V (Windows Server 2016 e posteriores, Windows 10/11 com Hyper-V): o MSI Windows. O agente faz então também backup das VMs do host (veja Hyper-V).
  • Hosts VMware ESXi — nada é instalado no ESXi: adicione o host em Hosts VMware ESXi e escolha um agente como proxy (veja VMware ESXi).

Registrar agentes

  1. Na página Agentes clique em Criar token de registro. A console mostra um código de registro (BZ1-…), válido por 7 dias e utilizável em qualquer número de máquinas. Contém o endereço da console para agentes (com a porta dos agentes, geralmente 8443, mesmo quando a página está aberta na porta web 443), o token e a impressão digital do certificado. Agentes a partir da 0.33.6 também se registram com códigos criados por consoles mais antigas na porta web.
  2. Windows: execute o MSI e cole o código quando o instalador pedir. Linux: execute o comando mostrado.
  3. A máquina aparece na lista de agentes em menos de um minuto.

Se a console não estiver acessível durante a instalação, o agente guarda o código e tenta novamente até conseguir se registrar. As atualizações mantêm o registro e não perguntam de novo. Uma instalação silenciosa com ENROLLCODE numa máquina já registrada mantém o registro quando o código é da mesma console (GPO ou RMM podem repeti-la com segurança), e move a máquina quando o código é de outra console; o registro anterior é guardado como agent.json.replaced-data ao lado de agent.json, de modo que renomeá-lo de volta devolve a máquina à console antiga como o mesmo agente.

Windows, silenciosa (GPO, Intune, RMM)

msiexec /i backupzit-agent.msi /qn ENROLLCODE="BZ1-..."

A forma antiga SERVER="..." TOKEN="..." FINGERPRINT="SHA256:..." continua a funcionar. Uma instalação silenciosa sem essas propriedades configura o serviço, que espera até que você o registre com backupzit-agent enroll --code "BZ1-..." num prompt de administrador.

Linux

apt install ./backupzit-agent_*.deb        # or: dnf install ./backupzit-agent-*.rpm
backupzit-agent enroll --code "BZ1-..."
systemctl enable --now backupzit-agent

Instalar agentes a partir da console

Em vez de copiar instaladores para cada máquina, deixe a console instalar o agente: em Agentes abra Instalar em uma máquina a partir daqui, escolha Linux ou Windows e informe o endereço da máquina e uma conta de administrador.

  • Linux (Debian, Ubuntu, AlmaLinux, Rocky Linux; 64 bits): a console conecta-se por SSH como root, ou como usuário com direitos de sudo (a senha também é usada para o sudo; com uma chave, é necessário sudo sem senha). Funciona uma senha ou uma chave privada. Informe a impressão digital da chave de host SSH da máquina (ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub na máquina) para garantir que a console fala com a máquina certa; sem ela, a impressão digital aparece no log de instalação.
  • Windows (64 bits): a console conecta-se por WinRM (porta 5985, mensagens criptografadas com NTLM; 5986 para um listener HTTPS) como administrador local ou de domínio. O WinRM está ativo por padrão no Windows Server; no Windows 10/11 execute uma vez winrm quickconfig como administrador. Contas locais diferentes do Administrador integrado precisam de direitos de administração remota (LocalAccountTokenFilterPolicy) — ou use uma conta de domínio. Sistemas antigos (Windows 7, Server 2008 R2/2012 R2) recebem o MSI legacy.

A máquina baixa o pacote de agente mais recente da console por um link que só serve para esta instalação (30 minutos, três downloads), verifica a soma SHA-256, instala-o e registra-se. A página de instalação mostra cada passo; a conta e a senha só são usadas para isso e não são guardadas. Se a máquina já estiver registrada nesta console, o registro é mantido e o pacote atualizado; um registro que a console não conhece (um agente removido antes, ou outra console) é substituído. Cada instalação fica no log de auditoria. A máquina precisa alcançar o endereço de agentes da console, como qualquer agente.

Estado do agente

  • online — o agente contactou a console nos últimos 3 minutos.
  • offline — a máquina está desligada, o serviço parado ou a rede bloqueada. Os backups agendados ficam em fila e começam assim que o agente voltar.
  • recuperação — uma máquina iniciada a partir de uma ISO de recuperação (Windows ou Linux), pronta para receber a restauração de uma imagem de disco ou de um sistema Linux. Os agentes de recuperação são temporários; remova-os quando a restauração terminar.

A coluna Endereços IP lista os endereços próprios da máquina conforme o agente os informou por último. visto de é o endereço de onde chegam as suas conexões: numa rede local o mesmo endereço, numa máquina atrás de NAT (p. ex. um notebook em casa) o endereço público do roteador. A console não consulta nenhum serviço externo para isso.

O agente na área de trabalho (Windows)

O agente Windows mostra um ícone ao lado do relógio (pode estar sob a seta ^ dos ícones ocultos — arraste-o para a barra de tarefas para que fique visível). O ponto no ícone mostra o estado:

PontoSignificado
verdeOs backups estão bem (ou aguardam o primeiro backup agendado).
azulUm backup, restauração ou teste de restauração está em execução.
laranjaO último backup terminou com avisos (arquivos que não puderam ser lidos).
vermelhoUm trabalho de backup falhou.
cinzaA console não está acessível ou o serviço do agente não está em execução.

Clique no ícone (ou abra BackupZit Agent no menu Iniciar) para a janela de estado: estado de proteção, progresso de um backup em execução, último e próximo backup, e todos os trabalhos de backup do computador com Fazer backup agora. O clique direito abre o menu: Back up now por trabalho, Open console in browser, Hide this icon (até o próximo login; os backups continuam). A janela precisa do Microsoft Edge WebView2, que faz parte do Windows 10 e 11; em sistemas antigos o ícone e o menu funcionam e Open mostra a console no navegador.

Os usuários podem assim iniciar um backup do seu computador; os trabalhos, agendamentos e retenção só são definidos na console. Em qualquer sistema, backupzit-agent status (como administrador ou root) mostra a mesma informação.

Atualização

Quando a console tem um instalador de agente mais recente do que o que um agente executa, a página Agentes mostra Atualizar para x.y.z ao lado da sua versão, e Atualizar todos os agentes abaixo da lista. O agente então:

  1. espera até estar ocioso (um backup em execução nunca é interrompido),
  2. baixa o instalador correspondente da console pela sua conexão fixada — o MSI para Windows 10/11/2016+, o MSI sistemas antigos para Windows 7/2008 R2/2012 R2, o pacote deb ou rpm no Linux — e verifica o SHA-256,
  3. instala-o e reinicia; a nova versão aparece na lista em poucos minutos. O registro e todas as configurações são mantidos.

A console oferece os instaladores mais recentes do seu diretório dist; o pacote do servidor inclui os instaladores de agente da sua própria versão. Depois de a console ser atualizada em Configurações → Atualizações, os agentes são atualizados automaticamente (pode ser desativado lá). As atualizações a partir da console funcionam para agentes a partir da versão 0.21; agentes mais antigos são atualizados uma vez instalando o MSI / pacote mais recente por cima do antigo (o registro é mantido). O log do instalador fica em C:\ProgramData\backupzit\updates ou /var/tmp/backupzit-updates.

Remover um agente

Remover na página Agentes exclui o agente e os seus trabalhos da console. Com a aprovação de quatro olhos ativada, um segundo usuário tem de aprovar primeiro. Os backups no armazenamento não são excluídos. Desinstale o software na máquina separadamente.

Duas máquinas a usar um agente

Uma cópia de uma máquina registrada leva consigo o seu agente e registro: uma VM restaurada como nova VM, uma recuperação instantânea, uma réplica iniciada, um disco ou modelo clonado. Quando a cópia funciona ao lado do original, ambas se conectam como o mesmo agente. A console percebe isso em um ou dois minutos e então:

  • mostra duas máquinas com ambos os nomes e endereços na página Agentes, e o agente em Requer atenção no painel;
  • retém os backups e restaurações do agente, para que nada seja executado na máquina errada (uma restauração para o local original poderia, de outra forma, sobrescrever a cópia em vez do original);
  • envia uma vez um e-mail aos administradores e escreve uma entrada agent.duplicate no log de auditoria.

Pare a cópia ou — se ela deve ficar — registre-a como nova máquina na cópia: backupzit-agent enroll --force --code "BZ1-..." (código da página Agentes). As execuções retidas começam alguns minutos depois de restar apenas uma máquina. Restaurar um sistema Linux com Restaurar o sistema inteiro já cancela o registro do agente na cópia restaurada, e os testes de restauração iniciam as suas VMs sem rede, por isso nenhum dos dois causa isto.

Quando a console muda de endereço

Os agentes confiam na console pelo seu certificado, que se mantém quando o endereço IP ou o nome mudam, mas conectam-se ao endereço com que foram registrados. Depois de uma mudança, execute em cada máquina com agente (como administrador / root):

backupzit-agent set-server https://192.168.1.20:8443

O comando verifica que a console responde no novo endereço com o mesmo certificado, guarda-o, e o agente usa-o depois de reiniciar o seu serviço (systemctl restart backupzit-agent, ou reinicie o serviço BackupZit Agent no Windows). Usar um nome DNS para a console desde o início evita este passo.

Onde o agente guarda a configuração

  • Windows: C:\ProgramData\backupzit\agent.json (acessível apenas a SYSTEM e Administradores).
  • Linux: /etc/backupzit/agent.json (apenas root).

O arquivo contém o segredo do agente. Quem puder lê-lo pode agir como esse agente, por isso mantenha estas permissões.

Log do agente

  • Windows: C:\ProgramData\backupzit\agent.log
  • Linux: /etc/backupzit/agent.log e journalctl -u backupzit-agent
  • Os sistemas de recuperação mostram o log na tela.

Desinstalar

Windows: Configurações → Apps → BackupZit Agent → Desinstalar (ou msiexec /x). Linux: apt remove backupzit-agent / dnf remove backupzit-agent. Depois remova o agente na console. Os backups permanecem no armazenamento.

No Windows, a desinstalação põe o registro de lado (C:\ProgramData\backupzit\agent.json.removed-data), de modo que ao instalar o agente novamente é pedido um código de registro. Se o instalador encontrar um registro de uma versão anterior, ele avisa: deixe o código vazio para mantê-lo, ou cole um novo código para registrar o computador de novo (por exemplo noutra console).
