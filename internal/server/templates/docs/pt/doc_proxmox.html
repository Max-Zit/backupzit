Máquinas virtuais do Proxmox VE

O BackupZit faz backup de máquinas virtuais (QEMU) e contêineres (LXC) do Proxmox VE sem instalar nada dentro dos convidados. O agente roda no host Proxmox, tira um snapshot de cada convidado, lê seus discos e os armazena deduplicados em qualquer destino de armazenamento.

Configuração

  1. Instale o pacote Agente Linux — Debian / Ubuntu a partir de Agentes em cada nó Proxmox (Proxmox VE 7 e 8 são baseados em Debian): 
    apt install ./backupzit-agent_*.deb
backupzit-agent enroll --code "BZ1-..."
systemctl enable --now backupzit-agent
  2. Em até um minuto o nó aparece na página Agentes com o selo Proxmox VE · N guests.
  3. Em Tarefas de backup selecione esse agente e escolha Máquinas virtuais (Proxmox VE, Hyper-V, VMware). Faça backup de todos os convidados do nó (convidados criados depois são incluídos automaticamente) ou marque alguns.

O agente usa as ferramentas do próprio nó (qm, pct, pvesm, LVM, ZFS, Ceph); nenhum token de API ou senha é armazenado no console.

Como um convidado é copiado

  1. Um snapshot temporário do Proxmox é criado (backupzit_…, visível em Snapshots por alguns segundos a minutos). O convidado continua rodando.
  2. Se o QEMU guest agent roda na VM (e está ativado nas opções da VM), o Proxmox congela os sistemas de arquivos para o snapshot — o backup fica então consistente com as aplicações. Sem ele, o backup tem consistência de falha, como uma queda de energia. Instale qemu-guest-agent nas VMs Linux e as ferramentas de convidado VirtIO nas VMs Windows.
  3. Cada disco é lido do snapshot em blocos de 1 MiB. Blocos vazios não são armazenados e blocos que já estão no repositório não são enviados de novo, então após o primeiro backup só os dados alterados são transferidos.
  4. O snapshot é removido. A configuração do convidado (CPU, memória, rede, discos) é armazenada com o backup.

A página da execução lista cada convidado, seus discos e como foi capturado. Testes de restauração verificam blocos aleatórios dos backups de VM como nas imagens de disco e, com o teste de boot ligado, iniciam cada VM a partir do backup, isolada da rede, para provar que ela inicia.

Discos marcados como Backup: no (backup=0) no Proxmox, discos físicos em passthrough e bind mounts são ignorados e listados como avisos. Drives cloud-init não são armazenados; eles são recriados a partir da configuração na restauração.

Restaurar uma VM ou contêiner

Abra uma execução de backup de VM (pela página da tarefa ou Atividade) e use Restaurar uma VM ou contêiner:

  • Convidado — um dos convidados desse backup.
  • Restaurar no nó do Proxmox — qualquer nó com o agente BackupZit, inclusive um nó de outro cluster.
  • Como novo convidado com o próximo ID livre (padrão) ou com o ID … — o original continua rodando. Como os dois existem, as placas de rede da cópia recebem novos endereços MAC.
  • Com o ID original — depois que o convidado foi excluído. Se ele ainda existir, marque pará-lo e excluí-lo para substituí-lo pelo backup; o convidado existente e seus discos são excluídos primeiro.
  • Nome e Armazenamento para os discos — por ex. restaurar em um armazenamento diferente do original.
  • Iniciar o convidado após a restauração.

Toda restauração dá às VMs um novo ID de geração (vmgenid), para que controladores de domínio Windows e outros softwares detectem a reversão com segurança. Os discos são alocados com pvesm no armazenamento escolhido; em armazenamento do tipo diretório eles são restaurados como arquivos raw.

Recuperação instantânea

Restaurar uma VM grande leva tanto tempo quanto copiar seus discos. Com Instantaneamente, rodando a partir do backup no formulário de restauração, a VM roda em segundos, enquanto seus discos ainda estão no backup:

  1. O agente serve os discos da VM somente leitura a partir do backup (um pequeno servidor NBD rodando como a unidade systemd backupzit-instant-<ID>) e cria uma nova VM com o próximo ID livre cujos discos são overlays qcow2 no armazenamento de diretório backupzit-instant (/var/lib/backupzit-instant, adicionado automaticamente). Os dados são lidos do backup sob demanda; tudo o que a VM grava fica nos overlays. Variáveis de firmware (disco EFI) e estado do TPM são pequenos e copiados.
  2. A VM inicia. Verifique-a — ela recebe novos endereços MAC como qualquer cópia. O painel lista toda VM que ainda roda a partir de um backup.
  3. Na página da execução, ou Concluir: os discos são movidos para o armazenamento escolhido enquanto a VM continua rodando (qm disk move), e então o backup não é mais usado. Ou Descartar: a VM é parada e excluída junto com suas alterações.

Enquanto uma VM roda a partir de um backup, a retenção nunca remove esse backup. A VM é tão rápida quanto o armazenamento de backup permite: um repositório em disco local ou em um compartilhamento de rede rápido funciona melhor; leituras via SFTP ou S3 de longe a deixam lenta até ser concluída. A recuperação instantânea é para VMs (não contêineres) e cria uma nova VM — para restaurar no local use uma restauração normal. O disco EFI não pode ser movido com a VM rodando; ele fica então em backupzit-instant (veja a mensagem da execução) e pode ser movido após desligar a VM: qm disk move ID efidisk0 STORAGE --delete 1.

Replicação

Para convidados que precisam voltar em minutos, uma tarefa de VM pode manter réplicas: em Avançado no formulário da tarefa marque Manter réplicas das VMs e escolha o nó (qualquer nó com o agente BackupZit, inclusive em outro cluster) e o armazenamento. Após cada backup, o agente nesse nó atualiza uma cópia parada de cada convidado da tarefa:

  • Na primeira vez, a réplica é restaurada como um novo convidado (próximo ID livre, nome original-replica, novos endereços MAC, nunca iniciada com o nó).
  • Depois só são gravados os blocos que mudaram desde o backup que a réplica contém — normalmente alguns segundos por backup.
  • A página da tarefa lista as réplicas, o backup que cada uma contém e seu estado. Se um convidado for perdido, clique em Iniciar réplica: ela roda com os dados do último backup, sem restauração. Inicie-a somente quando o original realmente não existir mais — os dois na rede ao mesmo tempo podem entrar em conflito.
  • Enquanto uma réplica roda, ela não é mais atualizada (a execução informa). Para replicar de novo, exclua o convidado réplica no Proxmox; o próximo backup cria um novo. Réplicas com snapshots do Proxmox também não são atualizadas.
  • Discos adicionados depois a um convidado não são replicados (exclua a réplica para recomeçar); discos que cresceram também crescem na réplica. Alterações de configuração (memória, CPUs) são aplicadas quando a réplica é criada.
  • A replicação lê os backups como uma restauração: o nó da réplica precisa alcançar o armazenamento. Desligar a replicação deixa as réplicas como estão.

Linha de comando

backupzit-agent pve list
backupzit-agent pve backup  --repo ... [--vmid 100,200] [--exclude 300]
backupzit-agent pve show    --repo ... latest
backupzit-agent pve restore --repo ... --vmid 100 [--new-vmid -1|N] [--name copy] [--storage local-lvm] [--overwrite] [--start] SNAPSHOT|latest
backupzit-agent pve instant --repo ... --vmid 100 [--new-vmid N] [--name X] SNAPSHOT|latest
backupzit-agent pve instant-finish --vmid 101 --storage local-lvm
backupzit-agent pve instant-discard --vmid 101

As opções de repositório são as mesmas de todos os comandos (veja Referência da linha de comando). A linha de comando funciona sem o console, por exemplo para restaurar um nó inteiro após um desastre.

Clusters

Instale o agente em cada nó. Uma tarefa faz backup dos convidados que rodam no nó do seu agente; um convidado listado em uma tarefa e migrado para outro nó é informado como aviso com o nome desse nó — faça backup de cada nó com sua própria tarefa, ou use todos os convidados do nó em cada nó para que convidados migrados estejam sempre cobertos.

Restaurar arquivos avulsos

Na tabela de convidados de uma execução de backup de VM, clique em Navegar pelos arquivos. O console lê o disco diretamente do backup — nada é restaurado antes — e mostra suas partições e volumes lógicos LVM; NTFS (Windows), ext2/3/4 e XFS (Linux) podem ser navegados, também dentro de LVM. Marque arquivos e pastas e:

  • Baixar — um arquivo como está, vários arquivos ou pastas como arquivo ZIP, direto para o navegador;
  • Restaurar no agente — copiá-los para uma pasta em qualquer agente, por ex. de volta à VM (se ela roda o agente BackupZit) ou para um servidor de arquivos.

Na linha de comando: backupzit-agent pve ls --vmid 100 latest /etc e backupzit-agent pve extract --vmid 100 --target /srv/restore latest /etc/nginx; --volume seleciona uma partição ou volume lógico (pve ls sem caminho os lista). Navegar no console exige o backup em armazenamento de rede (SFTP, S3, SMB, Azure, repositório protegido).
