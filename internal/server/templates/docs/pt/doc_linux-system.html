Backup do sistema Linux e P2V

Uma tarefa Sistema Linux faz backup de uma máquina Linux inteira para que ela possa ser recriada em um disco vazio — a mesma máquina após uma falha de disco, hardware novo ou uma máquina virtual no Proxmox VE (físico para virtual, P2V).

O que é copiado

  • Cada sistema de arquivos local (ext2/3/4, xfs, vfat), também sobre LVM, arquivo por arquivo com donos, permissões, bits setuid, ACLs, atributos estendidos (rótulos SELinux, capabilities de arquivo), links físicos e arquivos de dispositivo. Cada sistema de arquivos é copiado separadamente; compartilhamentos de rede e sistemas de arquivos virtuais (/proc, /sys, /run) são ignorados.
  • O layout dos discos: tabelas de partição GPT ou MBR com seus IDs, grupos de volumes LVM (vgcfgbackup), UUIDs, rótulos e recursos dos sistemas de arquivos, e o código de boot (MBR e a partição de boot BIOS do GRUB).

Assim como o Relax-and-Recover, o BackupZit não copia o disco em uso bloco a bloco: o Linux não tem snapshot embutido de um disco em funcionamento, então uma cópia bruta seria inconsistente. Cada arquivo é lido inteiro, e o layout torna o disco restaurado inicializável de novo. Bancos de dados devem ser exportados antes do backup ou copiados com suas próprias ferramentas.

Arquivos e pastas avulsos são restaurados de um backup de sistema como de qualquer backup de arquivos (Restaurar arquivos deste backup na página da execução).

Ainda não suportado

Discos criptografados (LUKS), RAID por software (mdadm), btrfs e sistemas espalhados por vários discos. A tarefa informa isso claramente em vez de criar um backup incompleto.

Restaurar o sistema inteiro

Abra a execução do backup do sistema (página da tarefa ou Atividade) e use Restaurar o sistema inteiro:

Como nova VM do Proxmox

Escolha o nó Proxmox (o agente BackupZit dele faz o trabalho), o armazenamento, o ID da VM, o nome, a memória e os núcleos. O BackupZit cria a VM com o mesmo firmware do original (UEFI/OVMF ou BIOS), um disco e uma placa de rede VirtIO SCSI, recria o disco, restaura todos os arquivos e pode iniciar a VM. Como a VM é uma cópia que pode rodar ao lado do original:

  • configurações de rede vinculadas aos endereços MAC antigos (comuns em imagens de nuvem: netplan match: macaddress) são alteradas para valer para qualquer interface cabeada,
  • o agente BackupZit dentro da cópia tem o registro cancelado, para não se apresentar como a máquina original.

Em um disco

Restaure em um disco vazio de um agente Linux, por ex. um segundo disco (/dev/sdb), ou na própria máquina nova (bare metal):

  1. Em Recuperação baixe a ISO de recuperação Linux e crie um código de recuperação. Grave a ISO em um pendrive (Rufus, balenaEtcher) ou anexe-a a uma VM. Ela inicia em máquinas BIOS e UEFI.
  2. Inicie a máquina por ela. O sistema de recuperação inicia o agente, que se conecta ao console com backupzit/recovery.json de outro pendrive ou disco, ou pede o endereço do servidor e o código de recuperação.
  3. A máquina aparece como agente de recuperação. Na execução do backup do sistema escolha Em um disco, esse agente e o disco dele (geralmente /dev/sda, /dev/nvme0n1 ou /dev/vda).

Qualquer sistema Linux live também serve: inicie o agente nele com sudo backupzit-agent recovery --server https://console:8443 --token CODE; as ferramentas necessárias (gdisk, LVM, mkfs) são indicadas se faltarem. Marque Hardware diferente quando a máquina não for a original.

O destino pode ser maior ou menor que o disco original: a última partição cresce para preenchê-lo, ou diminui desde que seus dados caibam. Os UUIDs dos sistemas de arquivos e os IDs das partições continuam os mesmos, então /etc/fstab e o carregador de boot não precisam de alterações. Em sistemas UEFI, o carregador de boot também é instalado no caminho de mídia removível \EFI\BOOT\BOOTX64.EFI, que todo firmware UEFI inicia sem entrada de boot. Sistemas do tipo RHEL (dracut) recebem um novo initramfs com todos os drivers ao serem movidos para hardware diferente.

Linha de comando

backupzit-agent system-backup  --repo ... [--exclude PATTERN]
backupzit-agent system-show    --repo ... latest
backupzit-agent system-restore --repo ... --target /dev/sdb [--new-hardware] --yes-erase-target latest
