Máquinas virtuais do VMware ESXi

O BackupZit faz backup das máquinas virtuais de hosts VMware ESXi sem instalar nada no ESXi nem dentro das VMs. Um agente BackupZit em qualquer máquina da rede funciona como proxy do host. Ele tira snapshots, lê só os blocos alterados dos discos virtuais e os grava no seu armazenamento.

Requisitos

  • ESXi 6.7, 7 ou 8, conectado diretamente. Hosts gerenciados pelo vCenter são adicionados um a um com seu próprio endereço; o vCenter em si ainda não é suportado.
  • Um usuário com direitos de administrador no host, normalmente root.
  • SSH ativado no host: Host → Actions → Services → Enable Secure Shell. Restaurações sempre precisam dele. Hosts com a licença gratuita do ESXi também precisam dele para snapshots, porque a API deles é somente leitura.
  • Um agente proxy: qualquer agente Windows ou Linux que alcance o host nas portas 443 e 22. Os dados do backup passam por ele, então coloque-o em uma rede rápida, perto do host e do armazenamento.
  • Espaço livre no datastore da VM enquanto uma VM ligada é copiada. O BackupZit copia o disco ali por um momento (veja abaixo). A cópia é thin, então precisa de tanto espaço quanto o disco realmente usa.

Adicionar um host

  1. Abra Agentes → Hosts VMware ESXi → Adicionar um host ESXi.
  2. Informe o endereço, o usuário, a senha e o agente proxy.
  3. O console se conecta uma vez para verificá-los. Ele lê a lista de VMs e a licença, e fixa o certificado HTTPS e a chave de host SSH do host. Se mais tarde o host for substituído por outra máquina com o mesmo endereço, o BackupZit se recusa a conectar em vez de enviar a senha a ela.

A senha é armazenada criptografada, como todos os outros segredos. A lista de VMs é atualizada a cada 10 minutos, ou na hora com Atualizar. A tabela mostra o modo de cada host:

  • vSphere API: hosts licenciados.
  • Licença gratuita: snapshots e restaurações passam por SSH.

Tarefas de backup

Em Tarefas de backup, escolha o host ESXi (listado em Hosts VMware ESXi na lista de agentes) e Máquinas virtuais. Faça backup de todas as VMs do host (VMs criadas depois são incluídas automaticamente) ou marque algumas. A tarefa roda no agente proxy do host. Se você trocar o proxy, as tarefas existentes acompanham.

Como uma VM é copiada

  1. O rastreamento de blocos alterados (CBT) é ligado para a VM se estiver desligado.
    • Em hosts licenciados isso acontece automaticamente.
    • Em hosts gratuitos o CBT só pode ser ligado com a VM desligada. O BackupZit faz isso no primeiro backup que encontrar a VM desligada. Até lá, todo backup lê os discos inteiros e a execução mostra um aviso.
  2. Um snapshot backupzit_… é criado. Quando o VMware Tools roda no convidado, o snapshot é quiesced: aplicações e sistemas de arquivos são descarregados antes, o que torna o backup consistente com as aplicações. Sem VMware Tools, ele tem consistência de falha. Instale open-vm-tools em VMs Linux e o VMware Tools em VMs Windows.
  3. O CBT informa quais blocos ler:
    • no primeiro backup, só os blocos em uso;
    • depois, só os blocos alterados desde o backup anterior.
  4. Uma VM ligada mantém seus discos bloqueados. Por isso seus discos são copiados no datastore (thin) e o snapshot é removido na hora, normalmente após segundos. A cópia é então lida por HTTPS e excluída. VMs desligadas são lidas diretamente.
  5. A configuração da VM (.vmx) e a NVRAM são armazenadas com o backup.

Exemplo do laboratório de testes: uma VM Debian com um disco de 8 GB, 1,6 GB em uso. O primeiro backup leu 1,6 GB. O seguinte, após 50 MB de dados novos, leu 70 MB e levou 23 segundos.

Restaurar uma VM

Use o assistente de restauração (Máquina virtual inteira) ou a página do backup em Atividade. Escolha:

  • Como nova VM ao lado da original: uma cópia com novo nome, UUID e endereços MAC. O nome padrão é o do original mais -restored- e a data. Configurações de rede do convidado vinculadas aos endereços MAC antigos, como netplan match: macaddress em imagens de nuvem, não se aplicam à cópia.
  • No lugar da VM original: com desligá-la e substituir seus discos, o BackupZit:
    • desliga a VM e exclui seus snapshots;
    • renomeia os discos atuais para ….replaced-DATE.vmdk (exclua-os quando a VM restaurada estiver funcionando);
    • grava o backup em discos novos com os nomes originais e define CPU e memória como no backup.
    A VM mantém seu UUID, adaptadores de rede e endereços MAC. Se a VM foi excluída, ela é recriada com sua identidade original.
  • Host ESXi e datastore: outro host, ou outro datastore do mesmo host.
  • Iniciar a VM após a restauração.

Os discos são restaurados thin, e só os blocos com dados são gravados. Imagens ISO conectadas a unidades de CD/DVD não fazem parte do backup, então essas unidades ficam vazias.

Recuperação instantânea

Escolha Instantaneamente, rodando a partir do backup para iniciar uma VM em segundos, sem copiar seus discos antes. O agente proxy do host — ele precisa ser um agente Linux — serve os discos da VM direto do backup via NFS; o host monta isso como o datastore backupzit-<agent> e roda a VM a partir dele. As alterações que a VM faz ficam no agente (/var/lib/backupzit/instant-esxi, que precisa de espaço livre para elas); o backup em si nunca é alterado, e a retenção o mantém enquanto a VM roda a partir dele. Se a VM original ainda existir, a VM instantânea recebe um novo UUID e novos endereços MAC.

Na página da execução, quando a VM estiver funcionando como deve:

  • Concluir a copia para um datastore do host: a VM é desligada (pelo VMware Tools, se estiver rodando), seus discos são copiados thin com vmkfstools, ela é registrada a partir do datastore e iniciada de novo. A licença gratuita do ESXi não tem Storage vMotion, então isso exige uma breve parada que cresce com o tamanho dos discos. Se a cópia falhar, a VM continua rodando a partir do backup.
  • Descartar para e exclui a VM com todas as suas alterações.

O agente responde NFS na porta 2049 (e o registra no rpcbind da máquina na porta 111, ou responde ele mesmo na porta 111) apenas para o endereço do host ESXi; abra essas portas do host para o agente se houver um firewall no meio. Quando a última VM instantânea é concluída ou descartada, o datastore é removido e o servidor NFS para.

Arquivos avulsos

Navegar pelos arquivos na página do backup (ou Arquivos de uma máquina virtual no assistente de restauração) abre os discos da VM. Você pode navegar em NTFS, ext2/3/4 e XFS, também sobre LVM, e baixar arquivos ou restaurá-los em qualquer agente.

Linha de comando

Estes comandos rodam em qualquer agente. Defina a senha do ESXi em BACKUPZIT_VMWARE_PASSWORD:

backupzit-agent vmware list    --host 192.168.1.20 [--user root]
backupzit-agent vmware backup  --host … --repo … [--vmid N,N]
backupzit-agent vmware restore --host … --repo … --vmid N [--new] [--name NAME] [--datastore DS] [--overwrite] [--start] SNAPSHOT|latest

vmware list mostra as impressões digitais do certificado e da chave SSH do host. Passe-as com --thumbprint e --ssh-host-key para fixá-las também na linha de comando.

Ainda não incluído

  • vCenter. Adicione cada host ESXi diretamente.
  • VMs com snapshots próprios. Seus discos são deltas; exclua ou consolide os snapshots antes.
  • Alguns tipos de disco. Mapeamentos de dispositivo bruto (RDM) e discos independentes.
  • Recuperação instantânea por um agente proxy Windows. A recuperação instantânea precisa de um agente proxy Linux.
