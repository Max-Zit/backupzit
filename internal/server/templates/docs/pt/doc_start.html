Primeiros passos

O BackupZit protege máquinas Windows e Linux, máquinas virtuais Proxmox VE, Hyper-V e VMware ESXi, bancos de dados (SQL Server, PostgreSQL, MySQL/MariaDB) e compartilhamentos NAS — arquivos, discos inteiros e sistemas inteiros — a partir de uma console web que funciona na sua própria rede.

Como o BackupZit funciona

  • Console de gerenciamento (esta aplicação web) — funciona num servidor Linux da sua rede. Guarda a configuração, agenda tarefas, recolhe resultados e mostra relatórios. Nunca precisa de ser acessível pela Internet.
  • Agentes — um pequeno serviço em cada máquina protegida (MSI do Windows, deb/rpm do Linux) e nos hosts Proxmox e Hyper-V; os hosts VMware ESXi são alcançados através de um agente que funciona como proxy. Os agentes contactam a console por HTTPS, recebem tarefas e enviam os dados de backup diretamente para o armazenamento. No Windows, o agente mostra o seu estado ao lado do relógio.
  • Destinos de armazenamento — onde os backups ficam guardados: SFTP, armazenamento de objetos compatível com S3 (AWS, Wasabi, Backblaze B2, MinIO, Google Cloud…), Azure Blob Storage, um compartilhamento SMB/NAS, discos USB em rotação, um disco local ou montado, ou um repositório protegido do BackupZit.

Os dados de backup nunca passam pela console. A console apenas coordena, por isso pode funcionar numa pequena máquina virtual.

Primeiros passos

Para configurar uma nova console, importe a imagem de appliance pronta para uma VM pequena, inicie a ISO do appliance ou execute o script de instalação num servidor Linux existente; veja Instalar o servidor.

  1. Adicione um destino de armazenamento em Armazenamento. Mantenha Criptografar backups ativado e guarde num lugar seguro a ficha de recuperação mostrada a seguir. Veja Destinos de armazenamento.
  2. Instale agentes: em Agentes clique em Criar token de registro, baixe o instalador da mesma página e cole o código de registro quando o instalador do Windows pedir (Linux: backupzit-agent enroll --code …). Para VMs, instale o agente no host Proxmox ou Hyper-V; adicione hosts VMware ESXi em Agentes → Hosts VMware ESXi. Veja Agentes.
  3. Crie uma tarefa de backup em Tarefas de backup: escolha o agente, o armazenamento, o que copiar (arquivos, um compartilhamento NAS, uma imagem de disco, bancos de dados, o sistema Linux inteiro ou as VMs de um host Proxmox, Hyper-V ou VMware ESXi), quando executar e quantos backups manter. Veja Tarefas de backup e agendamentos.
  4. Execute-a uma vez manualmente com Executar backup agora na página da tarefa e verifique o resultado em Atividade.
  5. Teste uma restauração — um backup só vale o que vale a sua restauração. Os testes de restauração automáticos são executados semanalmente; restaure também algo à mão uma vez, com o assistente de restauração. Veja Restauração.
  6. Prepare-se para desastres: baixe as ISOs de recuperação e crie um código de recuperação em Mídia de recuperação.
  7. Configure alertas por e-mail em Configurações → Notificações por e-mail para saber das falhas e, opcionalmente, um relatório semanal.

Idioma

A console está disponível em 14 idiomas: inglês, alemão, francês, espanhol, italiano, português (Brasil), holandês, polonês, tcheco, sérvio (alfabeto latino), turco, russo, chinês (simplificado) e japonês. Escolha um na lista de idiomas no canto superior direito ou na página de login; a escolha fica guardada no navegador. Sem escolha, decide o idioma do navegador (navegadores croatas, bósnios e montenegrinos recebem sérvio, eslovacos recebem tcheco, outros idiomas inglês). Este guia também está traduzido (uma página sem tradução é mostrada em inglês). E-mails, notificações de chat e mensagens enviadas pelos agentes permanecem em inglês.

As traduções estão no código-fonte, em internal/server/i18n/pt.json: o texto em inglês é a chave e a tradução o seu valor. go run ./tools/i18n missing pt lista os textos sem tradução; textos não traduzidos são mostrados em inglês.

Conceitos-chave

Snapshots e desduplicação

Cada backup cria um snapshot: uma imagem completa e navegável dos dados naquele momento. Os arquivos são divididos em pedaços de tamanho variável e os discos em blocos, e cada pedaço é guardado só uma vez, de modo que o segundo backup e os seguintes só enviam o que mudou — e mesmo assim cada snapshot pode ser restaurado sozinho. Não há nenhuma «cadeia completa/incremental» para gerenciar.

Repositórios

Cada agente grava no seu próprio repositório sob o local do destino de armazenamento (<location>/<hostname>_<id>). Um repositório é autossuficiente: com o local, as credenciais do armazenamento e a chave de recuperação, pode ser restaurado mesmo que a console já não exista.

Retenção

Cada tarefa mantém um número de backups recentes, diários, semanais e mensais. Os snapshots mais antigos são removidos após cada execução e o espaço que usavam é liberado.

O que o BackupZit verifica por você

  • Testes de restauração — o backup mais recente de cada tarefa é parcialmente restaurado e verificado semanalmente (Restauração).
  • Detecção de ransomware — backups incomuns (alterações em massa, dados criptografados, exclusão em massa, saltos súbitos do volume de dados) são sinalizados e a retenção é pausada (Proteção contra ransomware).
  • Alertas e relatórios — e-mails em caso de falha e um resumo diário; relatórios agendados para a gestão (Notificações por e-mail, Monitoramento).
