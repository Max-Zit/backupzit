Solução de problemas e perguntas frequentes

Um agente aparece offline

  • A máquina está ligada e o serviço está rodando? Windows: Get-Service backupzit-agent; Linux: systemctl status backupzit-agent.
  • A máquina alcança o console? Test-NetConnection backup-server -Port 8443 ou curl -k https://backup-server:8443/login.
  • Log do agente: C:\ProgramData\backupzit\agent.log, no Linux /etc/backupzit/agent.log ou journalctl -u backupzit-agent. "fingerprint mismatch" significa que o certificado do console mudou — registre o agente de novo.

Um backup falhou

Abra a execução em Atividade; a mensagem informa a causa. Causas comuns:

A mensagem contémSolução
host key mismatch / fingerprintA chave do servidor SFTP mudou ou a impressão digital foi digitada errada. Confira com ssh-keygen -lf no servidor.
permission denied / access deniedCredenciais do armazenamento ou permissões da pasta. Teste o login com um cliente SFTP/SMB.
no space left / quotaO armazenamento está cheio. Reduza a retenção ou adicione espaço; backups expirados liberam espaço após a próxima execução.
repository is lockedOutra operação (por ex. uma limpeza) está rodando no mesmo repositório; a execução tenta de novo por 30 minutos. Bloqueios antigos expiram automaticamente.
wrong password / recovery keyO repositório foi criado com outra chave — verifique se a tarefa usa o destino de armazenamento correto.
bucket has no Object Lock enabledFoi solicitada imutabilidade em um bucket criado sem Object Lock. Crie um novo bucket com Object Lock.

"no matching backup disk is connected"Conecte um dos discos USB em rodízio (a mensagem informa o rótulo necessário e quais discos rotulados estão conectados). Uma restauração precisa exatamente do disco mostrado na execução do backup.
"several backup disks are connected"Conecte só um dos discos em rodízio por vez.

Execute backupzit-agent check --read-data no repositório, verifique o armazenamento e inicie um novo backup. Se backups foram excluídos em armazenamento imutável, veja Proteção contra ransomware.
Backup marcado como suspeitoVerifique a máquina quanto a ransomware ou exclusão em massa (por ex. uma pasta sincronizada esvaziada). Se estiver tudo bem (por ex. uma migração planejada), clique em Revisado — retomar a retenção na página da tarefa.
Let's Encrypt: "could not verify … is port 80 … reachable"A verificação HTTP precisa da porta 80 acessível pela internet. Para consoles internos use a verificação DNS pelo Cloudflare.
Let's Encrypt: "no Cloudflare zone … is accessible with this token"O token precisa da permissão Zone → DNS → Edit para a zona que contém o nome do console.
"HTTPS port 443: … permission denied" ou "address already in use"Outro programa usa a porta, ou o serviço não pode abrir portas abaixo de 1024 (execute-o com CAP_NET_BIND_SERVICE, como o pacote faz). Escolha outra porta em Configurações → Certificado.
Atualizações: "updates from the console need the Linux package of the console"O console não foi instalado pelo pacote deb/rpm (por exemplo, o modo de avaliação). Atualize-o da mesma forma que foi instalado.
Atualizações: "the release is not signed with a BackupZit release key"A origem da atualização não contém uma versão oficial, ou os arquivos foram alterados no caminho. Baixe-os de novo do endereço oficial.
Atualizações: status rolled-backA nova versão não iniciou, então a anterior e o banco de dados dela foram restaurados. O log da inicialização com falha está na página Atualizações; envie-o ao suporte.
Sistema operacional: "no supported package manager"Atualizações do sistema operacional são suportadas no Debian, Ubuntu (apt) e AlmaLinux, Rocky Linux, RHEL (dnf).
Backup do console: "the backup was made by a newer BackupZit"Antes de restaurar, instale no novo console a versão que fez o backup, ou uma mais nova.
Backup do console: "console backups need network storage"Escolha um destino SFTP, S3, SMB, Azure ou repositório protegido; um caminho local de um agente não é acessível pelo console.
"Muitas tentativas de login com falha"Seu endereço foi bloqueado após senhas erradas repetidas: por padrão por 30 minutos, mais tempo em bloqueios repetidos. Um administrador pode remover o bloqueio em Configurações → Login e segurança. No servidor, backupzit-server --unblock-ip all remove todos os bloqueios. As contas nunca são bloqueadas permanentemente.
Telefone perdido para o login de dois fatoresUse um dos códigos de recuperação; caso contrário, um administrador redefine os dois fatores na sua página de usuário. O último administrador pode redefinir a própria senha no servidor com backupzit-server --set-admin-password.
"your directory account is not in any BackupZit group"Adicione o usuário a um dos grupos associados em Configurações → LDAP / Active Directory, ou associe mais grupos. Use Teste ali para ver os grupos encontrados para um usuário.
A API retorna 401 / 403401: token ausente, revogado, expirado ou com o dono desativado. 403: a função do token é baixa demais para a requisição.
Azure: AuthenticationFailed / AuthorizationPermissionMismatchChave de conta errada, ou falta ao token SAS a permissão de leitura, gravação, exclusão ou listagem, ou ele expirou.
Uma VM restaurada com Windows Server 2012 R2 / Windows 8.1 não inicia no Hyper-V Gen 2 ("hash was denied (DBX)")A Microsoft revogou o carregador de boot antigo para o Secure Boot. Desligue o Secure Boot nessa VM, ou atualize o sistema antes de fazer o backup.

Máquinas virtuais, sistemas Linux e hardware novo

SituaçãoO que fazer
Proxmox: "the guest is running and one of its disks is on storage without snapshot support"Convidados em execução precisam de discos LVM-thin, ZFS, Ceph RBD ou qcow2. Mova o disco (Disk Action → Move Storage) ou faça o backup do convidado com ele parado.
Hyper-V: a execução diz "crash-consistent"O convidado não conseguiu se preparar para o ponto de verificação. Em convidados Windows verifique se os serviços de integração do Hyper-V (Backup (volume shadow copy)) estão ativados nas configurações da VM. Em convidados Linux instale hyperv-daemons (RHEL) ou linux-cloud-tools / hyperv-daemons (Debian/Ubuntu).
VMware: "SSH off" ou "SSH to …: connection refused"Ative o SSH no host ESXi: Host → Actions → Services → Enable Secure Shell (e configure para iniciar com o host). Restaurações, e backups na licença gratuita, precisam dele.
VMware: "changed block tracking is off and can be enabled … only while the VM is off"Licença gratuita do ESXi: desligue a VM uma vez e depois execute a tarefa; o BackupZit ativa o rastreamento de blocos alterados e os backups seguintes só leem blocos alterados.
VMware: "copy the disk on the datastore (needs free space …)"VMs ligadas são copiadas rapidamente no próprio datastore. Libere espaço lá (tanto quanto o disco usa), ou faça o backup com a VM desligada.
VMware: "… is a snapshot delta disk"A VM tem snapshots próprios. Exclua-os ou consolide-os no ESXi Host Client (Snapshots → Delete all).
VMware: "the ESXi certificate changed"O host foi reinstalado ou outra máquina responde no endereço dele. Se for esperado, remova o host em Agentes e adicione-o de novo para fixar o novo certificado.
VMware: arquivos *.replaced-DATE.vmdk ao lado dos discos da VMOs discos antigos de uma VM restaurada no local. Exclua-os no navegador do datastore quando a VM restaurada estiver funcionando.
Hyper-V: arquivos *.replaced-DATE ao lado dos discos da VMOs discos antigos de uma VM restaurada no local. Exclua-os quando a VM restaurada estiver funcionando.
Recuperação instantânea do Proxmox: a VM não inicia ou travaVerifique o servidor de discos: systemctl status backupzit-instant-ID e journalctl -u backupzit-instant-ID no nó. O armazenamento de backup precisa continuar acessível; quando o repositório não pode ser lido, as leituras de disco da VM param.
Recuperação instantânea do Proxmox: "efidisk0 stays on storage backupzit-instant"O QEMU não consegue mover o armazenamento de variáveis EFI com a VM rodando. Desligue a VM e execute qm disk move ID efidisk0 STORAGE --delete 1; isso não depende do backup.
Proxmox: "runs on node X; install the BackupZit agent on X"O convidado foi migrado. Instale o agente em cada nó e faça o backup dos convidados de cada nó com o agente daquele nó.
Backups ou restaurações do Proxmox lentos, SFTP "connection lost", "message authentication code incorrect" no servidor de armazenamentoProblema conhecido das placas de rede Intel e1000e em hosts Proxmox (log: "Detected Hardware Unit Hang", "Reset adapter unexpectedly"). Desligue o offloading: ethtool -K eno1 tso off gso off gro off e adicione isso como linha post-up da interface em /etc/network/interfaces.
Navegar pelos arquivos: "stored on a local path of the agent"O console só consegue ler backups em armazenamento de rede. Use backupzit-agent pve ls/extract ou image-ls/image-extract no agente.
Restauração de sistema Linux: "missing programs …"Instale os pacotes indicados na máquina que está restaurando, ou dê boot pela ISO de recuperação Linux do BackupZit, que já os tem.
A máquina Linux restaurada não tem redeAs configurações de rede estavam vinculadas ao endereço MAC antigo (netplan match: macaddress). Restaure com Hardware diferente, ou remova as linhas match em /etc/netplan/.
O Windows restaurado para com INACCESSIBLE_BOOT_DEVICERestaure de novo com Restaurar em hardware diferente, ou dê boot pela ISO de recuperação e execute backupzit-agent prepare-hardware --disk 0 [--drivers E:\Drivers].
Uma cópia restaurada de uma máquina aparece como o agente originalRestaurações em uma nova VM do Proxmox cancelam automaticamente o registro do agente na cópia. Em outras cópias, remova agent.json na cópia e registre-a como uma máquina nova.
A atualização do agente não terminaVeja o log do instalador em C:\ProgramData\backupzit\updates ou /var/tmp/backupzit-updates; agentes anteriores à 0.21 precisam ser atualizados uma vez manualmente.
O ícone da bandeja sumiuClique na seta ^ ao lado do relógio e arraste o ícone do BackupZit para a barra de tarefas, ou inicie BackupZit Agent pelo menu Iniciar.

Um backup termina com "aviso"

Alguns arquivos não puderam ser lidos — geralmente arquivos bloqueados por um aplicativo enquanto o VSS não está disponível, ou arquivos para os quais o agente não tem permissão. A lista está na página da execução. Todo o resto foi copiado.

Os backups estão lentos

  • O primeiro backup lê e envia tudo; os seguintes só leem arquivos alterados e só enviam dados novos.
  • Verifique o caminho de rede até o armazenamento (Wi-Fi, VPN, velocidade de upload da internet para armazenamento em nuvem).
  • Exclua caches, arquivos temporários e mídias de que você não precisa.

Perguntas frequentes

Posso usar NFS?

Para fazer backup de um compartilhamento NFS (ou SMB), crie uma tarefa NAS / compartilhamento de arquivos; um agente Linux monta o export a cada execução. Para armazenar backups em NFS, monte o export no agente (Linux: /etc/fstab) e use um destino Caminho local / montado como /mnt/nfs-backup; para máquinas Windows um destino SMB é a melhor escolha.

Posso mover os backups para outro armazenamento?

Copie a pasta do repositório (ou o prefixo do bucket) como está — ela é autossuficiente — e adicione um destino de armazenamento apontando para o novo local com a mesma chave de recuperação.

Excluir uma tarefa exclui os backups?

Não. Os backups continuam no armazenamento e podem ser restaurados pela Atividade ou pela linha de comando.

O que acontece se o console cair?

Nenhum novo backup agendado começa até ele voltar; execuções na fila continuam depois. Restaurações são sempre possíveis pela linha de comando com a folha de recuperação.

Quanto espaço os backups vão precisar?

No primeiro backup, aproximadamente o tamanho dos dados após a compactação, mais as alterações diárias de cada dia mantido. A página Relatórios mostra quanto foi enviado por tarefa.
