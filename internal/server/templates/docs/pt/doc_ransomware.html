Proteção contra ransomware

Atacantes tentam apagar ou criptografar os backups antes de criptografar os dados de produção. O BackupZit oferece armazenamento onde os backups não podem ser destruídos, nem mesmo com credenciais roubadas.

As camadas

CamadaProtege contra
Criptografia (AES-256)Leitura ou adulteração dos backups no armazenamento. Toda alteração é detectada.
S3 imutável (Object Lock, modo compliance)Exclusão ou sobrescrita de backups — por um atacante com as chaves, um administrador mal-intencionado ou um erro.
Repositório protegidoO mesmo, no seu próprio servidor Linux: os arquivos são gravados uma única vez e recebem o atributo de imutabilidade do sistema de arquivos.
Cópia externaIncêndio, roubo, perda total do local.
Aprovação a quatro olhos (opcional)Uma conta do console roubada ou mal usada que exclui tarefas e destinos de armazenamento ou encurta a retenção: um segundo usuário precisa aprovar. Veja Usuários, funções e LDAP.

Detecção automática de backups suspeitos

Cada backup é comparado com o histórico recente da sua tarefa. Ele é marcado como suspeito quando mostra sinais de ransomware ou exclusão em massa:

  • muito mais arquivos alterados que o normal (por ex. 95 % em vez do 1 % habitual),
  • os novos dados não se compactam mais — arquivos criptografados parecem dados aleatórios,
  • o número de arquivos caiu de repente em um terço ou mais,
  • um salto repentino na quantidade de dados novos (também para imagens de disco, sistemas Linux e VMs).

Então o BackupZit envia um e-mail de alerta (com as notificações de falha ativadas), mostra o backup no painel como backups suspeitos para revisar e pausa a retenção da tarefa: nenhum backup mais antigo é excluído, de modo que os últimos backups limpos continuam restauráveis mesmo que backups danificados continuem chegando. Depois de verificar a máquina, clique em Revisado — retomar a retenção na página da tarefa.

S3 imutável com Object Lock

  1. Crie um bucket com Object Lock ativado (AWS, Wasabi, Backblaze B2, MinIO: mc mb --with-lock).
  2. Adicione uma regra de ciclo de vida que exclua as versões não atuais (noncurrent versions) após 1 dia (MinIO: mc ilm rule add --noncurrent-expire-days 1 --expire-delete-marker).
  3. Adicione o destino S3 e marque Backups imutáveis por N dias. Escolha N pelo menos tão longo quanto a maior retenção que você precisa proteger, por ex. 30.

Cada ponto de restauração fica bloqueado por pelo menos N dias após sua criação; dados compartilhados com backups mais novos são prorrogados automaticamente.

Repositório protegido

Um servidor Linux dedicado executando backupzit-repo:

  • Agentes e console só podem adicionar arquivos; arquivos existentes nunca são sobrescritos.
  • Cada arquivo recebe o atributo chattr +i pelo período definido naquele servidor. Nem o root pode excluí-lo sem antes remover o atributo.
  • Exclusões feitas pelos clientes apenas ocultam arquivos até o fim do período.
  • O serviço roda como usuário sem privilégios; seu único privilégio é definir o atributo de imutabilidade.
apt install ./backupzit-repo_*.deb
vi /etc/backupzit-repo/repo.env        # BACKUPZIT_REPO_LOCK_DAYS=30
systemctl start backupzit-repo
backupzit-repo add-key office-console
backupzit-repo fingerprint

Após a configuração, desative o SSH e outros acessos remotos no servidor do repositório e proteja o acesso ao console local / iDRAC / iLO / hipervisor. A proteção é tão forte quanto a conta root dessa máquina.

Recuperação após um ataque

Se um atacante excluiu ou sobrescreveu backups, leia o armazenamento como ele era antes do ataque — é somente leitura e não altera nada:

backupzit-agent snapshots --repo <repositório> --as-of 2026-10-01T14:30
backupzit-agent restore   --repo <repositório> --as-of 2026-10-01T14:30 --target D:\Restore latest

Em um repositório protegido, o administrador também pode trazer de volta os arquivos ocultos para que os backups continuem normalmente:

backupzit-repo status
backupzit-repo undelete --since 2026-10-01T14:00

Recomendações

  • Use para o armazenamento uma conta separada que não faça parte do seu domínio Windows.
  • Mantenha pelo menos uma cópia imutável (S3 Object Lock ou repositório protegido).
  • Guarde as folhas de recuperação offline (impressas, em um cofre).
  • Ative os alertas por e-mail — uma mudança repentina nas falhas ou no volume de dados enviados costuma ser o primeiro sinal de um ataque.
