Databases: SQL Server, PostgreSQL, MySQL

BackupZit maakt back-ups van databases met de eigen tools van de databaseserver, via de agent op de databasemachine: Microsoft SQL Server op Windows, PostgreSQL en MySQL/MariaDB op Linux. Volledige back-ups volgen het schema van de taak; logback-ups om de paar minuten maken het mogelijk één database naar elk willekeurig tijdstip te herstellen — bijvoorbeeld naar één minuut vóór een verkeerde DELETE.

Een taak maken

Maak onder Back-uptaken een taak van het type Databases op de agent van de databasemachine en kies:

  • Databaseserver: Microsoft SQL Server, PostgreSQL of MySQL/MariaDB. Dit kan later niet worden gewijzigd.
  • Instantie of poort: de SQL Server-instantie (leeg voor de standaardinstantie, bijv. SQLEXPRESS) of de PostgreSQL-poort (leeg voor 5432). MySQL/MariaDB wordt via de lokale socket bereikt.
  • Databases: één naam per regel, of leeg voor alle gebruikersdatabases — later aangemaakte databases worden automatisch opgenomen.
  • Logboeken elke … minuten back-uppen: bijv. 15 — transactielogboeken (SQL Server), gearchiveerde WAL (PostgreSQL) of binaire logboeken (MySQL). Laat leeg als herstel naar het tijdstip van een volledige back-up volstaat.
  • Het schema is dat van de volledige back-ups, bijv. dagelijks om 22:00.

Back-ups worden gededupliceerd — ongewijzigde gegevens worden niet opnieuw geüpload — en versleuteld zoals elke back-up. Het bewaarbeleid telt de volledige back-ups; logback-ups worden bewaard zolang de volledige back-up waarop ze voortbouwen bestaat. De runpagina toont wat elke back-up bevat.

Microsoft SQL Server

  1. Installeer de agent op de Windows-machine waarop SQL Server draait (elke editie vanaf 2012, inclusief Express).
  2. De agent draait als NT AUTHORITY\SYSTEM en maakt verbinding met Windows-verificatie. Geef dat account de rol sysadmin, één keer per instantie: 
    sqlcmd -S .\SQLEXPRESS -E -Q "ALTER SERVER ROLE sysadmin ADD MEMBER [NT AUTHORITY\SYSTEM]"
  • Elke run schrijft één back-upbestand per database (BACKUP DATABASE / BACKUP LOG … WITH CHECKSUM) in de standaard back-upmap van de instantie, slaat de bestanden op en verwijdert ze. De map heeft tijdens de run vrije ruimte nodig voor de grootste database.
  • Met logback-ups ingeschakeld starten de volledige back-ups de logketen. Zonder logback-ups worden volledige back-ups als COPY_ONLY gemaakt, zodat ze andere back-up- of onderhoudsplannen niet verstoren.
  • Logback-ups worden gemaakt voor databases in het herstelmodel full of bulk-logged; databases in het model simple krijgen alleen volledige back-ups. Vink systeemdatabases aan om master, model en msdb toe te voegen.

PostgreSQL

De agent werkt als het account postgres via de lokale socket — voor back-ups hoeft niets te worden ingesteld. Een volledige back-up slaat het hele cluster op (pg_basebackup), de rollen (pg_dumpall --globals-only) en een pg_dump van elke database.

Herstel naar een tijdstip vereist WAL-archivering. Met logback-ups ingeschakeld stelt de eerste volledige back-up die in met ALTER SYSTEM: archive_mode = on en een archive_command die voltooide WAL-segmenten naar /var/lib/backupzit-pg/wal kopieert; de logback-ups slaan ze daar op en verwijderen ze. archive_mode wordt actief na één herstart van PostgreSQL (systemctl restart postgresql) — de run meldt het. Gebruikt een andere tool al archive_command, dan laat BackupZit die met rust en maakt back-ups zonder herstel naar een tijdstip. Als de logback-ups stoppen (taak uitgeschakeld of verwijderd), schakel de archivering dan weer uit (ALTER SYSTEM RESET archive_mode, herstart) zodat de map niet volloopt.

  • Een database herstellen in de staat van de volledige back-up: vanuit de pg_dump naar de draaiende server, onder een nieuwe naam of ter vervanging van de database.
  • Naar een tijdstip (of de nieuwste staat): de agent pakt de clusterback-up uit in een tijdelijke instantie op een vrije poort (alleen socket, geen netwerk, geen archivering), speelt de WAL af tot dat tijdstip, dumpt de database daaruit naar de draaiende server en verwijdert de tijdelijke instantie. De machine heeft een tijdje vrije ruimte nodig voor het cluster.
  • Heel cluster: wordt op dezelfde manier hersteld als aparte instantie die op een vrije poort blijft draaien; de run vertelt u de poort en de datamap (onder /var/lib/backupzit-pg) en hoe u verbinding maakt en hem stopt.

MySQL en MariaDB

De agent maakt verbinding als root via de lokale socket (socketverificatie, standaard op Debian en Ubuntu), of met de inloggegevens in /root/.my.cnf. Een volledige back-up slaat een mysqldump van elke database op (consistent, met routines, events en triggers) samen met de bijbehorende positie in het binaire logboek.

Herstel naar een tijdstip vereist het binaire logboek. Schakel het één keer in in de serverconfiguratie en herstart de server, bijv. /etc/mysql/mariadb.conf.d/60-binlog.cnf:

[mysqld]
server_id = 1
log_bin = /var/log/mysql/mysql-bin
binlog_format = ROW
expire_logs_days = 7

(maak de map voor het logboek aan, met het account mysql als eigenaar). De logback-ups slaan daarna elk gesloten binair logboek op. Houd de eigen vervaltermijn van de server langer dan het interval van de logback-ups; een gat wordt gemeld en herstel kan het niet overbruggen.

  • Een database herstellen: de dump wordt in een nieuwe database geladen (of vervangt een bestaande). Naar een tijdstip of nieuwste: de wijzigingen van die database die na de dump in de binaire logboeken zijn vastgelegd, worden tot dat tijdstip afgespeeld — ook als de database een nieuwe naam krijgt. Het afspelen wordt niet in het binaire logboek van de server geschreven.
  • Gebruikers en rechten (de systeemdatabase mysql) maken geen deel uit van de dumps.

Herstellen

Open een run van een volledige back-up (of gebruik de herstelwizard → Database) en kies de database, de machine om op te herstellen (dezelfde server of een andere met dezelfde databaseserver) en:

  • Als nieuwe database met bijv. de naam sales_restored — het origineel blijft onaangeroerd en u kunt rijen terugkopiëren — of onder de oorspronkelijke naam; vink vervangen aan om een bestaande database te overschrijven (de gebruikers worden eerst losgekoppeld).
  • Status: die van de volledige back-up; de nieuwste staat (de volledige back-up en elke logback-up daarna); of een tijdstip tussen de volledige back-up en de nieuwste bruikbare logback-up, zoals de tabel toont. Voer de tijd in zoals de console die toont, in de tijdzone van de consoleserver (zie Tijdzone); de agent rekent hem om naar de tijdzone van de databaseserver.

Opdrachtregel

backupzit-agent sql list    [--instance SQLEXPRESS]
backupzit-agent sql backup  --repo ... [--instance I] [--db a,b] [--system] [--log] [--copy-only]
backupzit-agent sql restore --repo ... [--instance I] --db NAME [--as NEW] [--replace] [--at "2026-10-04 14:59:00"] SNAPSHOT|latest
backupzit-agent pg list     [--port 5432]
backupzit-agent pg backup   --repo ... [--port P] [--db a,b] [--pitr | --wal]
backupzit-agent pg restore  --repo ... --db NAME|"(cluster)" [--as NEW] [--replace] [--at TIME | --latest] SNAPSHOT|latest
backupzit-agent mysql list
backupzit-agent mysql backup  --repo ... [--db a,b] [--binlog]
backupzit-agent mysql restore --repo ... --db NAME [--as NEW] [--replace] [--at TIME | --latest] SNAPSHOT|latest

Niet inbegrepen

  • Differentiële SQL Server-back-ups en Always On-beschikbaarheidsgroepen; externe databaseservers — de agent maakt back-ups van servers op zijn eigen machine.
  • Losse tabellen herstellen: herstel de database onder een nieuwe naam en kopieer de rijen.
