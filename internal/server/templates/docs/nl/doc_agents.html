Agents

Op elke beschermde machine wordt een agent geïnstalleerd. Hij draait als service, vraagt de console elke 30 seconden om werk en communiceert rechtstreeks met de opslag.

Ondersteunde systemen

  • Windows 10, 11 en Windows Server 2016 en nieuwer — MSI Windows-agent.
  • Windows 7 SP1, Windows Server 2008 R2 SP1 en 2012 R2 — MSI Windows-agent — oudere systemen (…-legacy.msi), met dezelfde functies inclusief VSS en schijfimages.
  • Debian, Ubuntu, AlmaLinux, Rocky Linux (64-bit).
  • Proxmox VE 7- en 8-knooppunten — het Debian-pakket; de agent maakt dan ook back-ups van de VM's en containers van het knooppunt (zie Proxmox VE).
  • Hyper-V-hosts (Windows Server 2016 en nieuwer, Windows 10/11 met Hyper-V): de Windows-MSI. De agent maakt dan ook back-ups van de VM's van de host (zie Hyper-V).
  • VMware ESXi-hosts — op ESXi wordt niets geïnstalleerd: voeg de host toe onder VMware ESXi-hosts en kies een agent als proxy (zie VMware ESXi).

Agents registreren

  1. Klik op de pagina Agents op Registratietoken maken. De console toont een registratiecode (BZ1-…), 7 dagen geldig en bruikbaar voor een willekeurig aantal machines. Hij bevat het consoleadres voor agents (met de agentpoort, meestal 8443, ook als de pagina via webpoort 443 is geopend), het token en de certificaatvingerafdruk. Agents vanaf 0.33.6 registreren zich ook met codes die oudere consoles op de webpoort maakten.
  2. Windows: voer de MSI uit en plak de code wanneer het installatieprogramma erom vraagt. Linux: voer de getoonde opdracht uit.
  3. De machine verschijnt binnen een minuut in de lijst met agents.

Als de console tijdens de installatie onbereikbaar is, bewaart de agent de code en probeert hij het opnieuw tot hij zich kan registreren. Upgrades behouden de registratie en vragen niet opnieuw. Een stille installatie met ENROLLCODE op een al geregistreerde machine behoudt de registratie als de code voor dezelfde console is (GPO of RMM kunnen hem veilig herhalen), en verplaatst de machine als de code voor een andere console is; de vorige registratie blijft bewaard als agent.json.replaced-datum naast agent.json, zodat terughernoemen de machine als dezelfde agent naar haar oude console terugbrengt.

Windows, stil (GPO, Intune, RMM)

msiexec /i backupzit-agent.msi /qn ENROLLCODE="BZ1-..."

De oudere vorm SERVER="..." TOKEN="..." FINGERPRINT="SHA256:..." werkt nog steeds. Een stille installatie zonder deze eigenschappen richt de service in, die wacht tot u hem registreert met backupzit-agent enroll --code "BZ1-..." in een beheerdersprompt.

Linux

apt install ./backupzit-agent_*.deb        # or: dnf install ./backupzit-agent-*.rpm
backupzit-agent enroll --code "BZ1-..."
systemctl enable --now backupzit-agent

Agents installeren vanuit de console

In plaats van installatieprogramma's naar elke machine te kopiëren, laat u de console de agent installeren: open op Agents Vanaf hier op een machine installeren, kies Linux of Windows en voer het adres van de machine en een beheerdersaccount in.

  • Linux (Debian, Ubuntu, AlmaLinux, Rocky Linux; 64-bit): de console maakt verbinding via SSH als root, of als gebruiker met sudo-rechten (het wachtwoord wordt ook voor sudo gebruikt; met een sleutel is sudo zonder wachtwoord nodig). Een wachtwoord of een privésleutel werkt. Voer de SSH-hostsleutelvingerafdruk van de machine in (ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub op de machine) om zeker te zijn dat de console met de juiste machine praat; zonder die wordt de vingerafdruk in het installatielogboek getoond.
  • Windows (64-bit): de console maakt verbinding via WinRM (poort 5985, berichten versleuteld met NTLM; 5986 voor een HTTPS-listener) als lokale of domeinbeheerder. WinRM staat standaard aan op Windows Server; voer op Windows 10/11 eenmalig winrm quickconfig uit als beheerder. Andere lokale accounts dan de ingebouwde Administrator hebben externe beheerdersrechten nodig (LocalAccountTokenFilterPolicy) — of gebruik een domeinaccount. Oudere systemen (Windows 7, Server 2008 R2/2012 R2) krijgen de legacy-MSI.

De machine downloadt het nieuwste agentpakket van de console via een link die alleen voor deze installatie werkt (30 minuten, drie downloads), controleert de SHA-256-controlesom, installeert het en registreert zich. De installatiepagina toont elke stap; account en wachtwoord worden alleen hiervoor gebruikt en niet opgeslagen. Is de machine al bij deze console geregistreerd, dan blijft de registratie behouden en wordt het pakket bijgewerkt; een registratie die de console niet kent (een eerder verwijderde agent, of een andere console) wordt vervangen. Elke installatie staat in het auditlogboek. De machine moet het agentadres van de console kunnen bereiken, zoals elke agent.

Agentstatus

  • online — de agent heeft de console in de laatste 3 minuten gecontacteerd.
  • offline — de machine staat uit, de service is gestopt of het netwerk is geblokkeerd. Geplande back-ups worden in de wachtrij gezet en starten zodra de agent terug is.
  • herstel — een machine die is opgestart vanaf een herstel-ISO (Windows of Linux), klaar om een schijfimage of Linux-systeemherstel te ontvangen. Herstelagents zijn tijdelijk; verwijder ze als het herstel klaar is.

De kolom IP-adressen toont de eigen adressen van de machine zoals de agent ze het laatst meldde. gezien vanaf is het adres waarvandaan zijn verbindingen binnenkomen: op een lokaal netwerk hetzelfde adres, voor een machine achter NAT (bijv. een laptop thuis) het openbare adres van de router. De console vraagt daarvoor geen externe dienst.

De agent op het bureaublad (Windows)

De Windows-agent toont een pictogram naast de klok (het kan onder de pijl ^ van verborgen pictogrammen staan — sleep het naar de taakbalk zodat het zichtbaar blijft). De stip op het pictogram toont de status:

StipBetekenis
groenBack-ups zijn in orde (of wachten op de eerste geplande back-up).
blauwEr loopt een back-up, herstel of hersteltest.
oranjeDe laatste back-up eindigde met waarschuwingen (bestanden die niet gelezen konden worden).
roodEen back-uptaak is mislukt.
grijsDe console is niet bereikbaar of de agentservice draait niet.

Klik op het pictogram (of open BackupZit Agent in het menu Start) voor het statusvenster: beschermingsstatus, voortgang van een lopende back-up, laatste en volgende back-up, en alle back-uptaken van de computer met Nu back-uppen. Rechtsklik opent het menu: Back up now per taak, Open console in browser, Hide this icon (tot de volgende aanmelding; back-ups gaan door). Het venster heeft Microsoft Edge WebView2 nodig, dat deel uitmaakt van Windows 10 en 11; op oudere systemen werken pictogram en menu en toont Open de console in de browser.

Gebruikers kunnen zo een back-up van hun computer starten; taken, planningen en bewaring worden alleen in de console ingesteld. Op elk systeem toont backupzit-agent status (als beheerder of root) dezelfde informatie.

Bijwerken

Als de console een nieuwer agentinstallatieprogramma heeft dan een agent draait, toont de pagina Agents Bijwerken naar x.y.z naast zijn versie, en Alle agents bijwerken onder de lijst. De agent dan:

  1. wacht tot hij inactief is (een lopende back-up wordt nooit onderbroken),
  2. downloadt het passende installatieprogramma van de console via zijn vastgepinde verbinding — de MSI voor Windows 10/11/2016+, de MSI oudere systemen voor Windows 7/2008 R2/2012 R2, het deb- of rpm-pakket op Linux — en controleert de SHA-256,
  3. installeert het en start opnieuw; de nieuwe versie verschijnt binnen enkele minuten in de lijst. Registratie en alle instellingen blijven behouden.

De console biedt de nieuwste installatieprogramma's in haar map dist aan; het serverpakket levert de agentinstallatieprogramma's van zijn eigen versie mee. Nadat de console is bijgewerkt via Instellingen → Updates, worden de agents automatisch bijgewerkt (daar uit te schakelen). Updates vanuit de console werken voor agents vanaf versie 0.21; oudere agents worden eenmalig bijgewerkt door de nieuwere MSI / het nieuwere pakket over de oude te installeren (de registratie blijft behouden). Het logboek van het installatieprogramma staat in C:\ProgramData\backupzit\updates of /var/tmp/backupzit-updates.

Een agent verwijderen

Verwijderen op de pagina Agents verwijdert de agent en zijn taken uit de console. Met vier-ogengoedkeuring ingeschakeld moet eerst een tweede gebruiker goedkeuren. Back-ups op de opslag worden niet verwijderd. Verwijder de software op de machine apart.

Twee machines die één agent gebruiken

Een kopie van een geregistreerde machine neemt haar agent en registratie mee: een VM die als nieuwe VM is hersteld, een direct herstel, een gestarte replica, een gekloonde schijf of sjabloon. Als de kopie naast het origineel draait, maken beide verbinding als dezelfde agent. De console merkt dit binnen een à twee minuten en dan:

  • toont ze twee machines met beide namen en adressen op de pagina Agents, en de agent onder Vraagt aandacht op het dashboard;
  • houdt ze de back-ups en herstelacties van de agent vast, zodat niets op de verkeerde machine draait (een herstel naar de oorspronkelijke locatie zou anders de kopie in plaats van het origineel kunnen overschrijven);
  • mailt ze de beheerders één keer en schrijft ze een item agent.duplicate in het auditlogboek.

Stop de kopie of — als die moet blijven — registreer haar op de kopie als nieuwe machine: backupzit-agent enroll --force --code "BZ1-..." (code van de pagina Agents). De vastgehouden uitvoeringen starten enkele minuten nadat er nog maar één machine over is. Een Linux-systeem herstellen met Het hele systeem herstellen heft de registratie in de herstelde kopie al op, en hersteltests starten hun VM's zonder netwerk, dus geen van beide veroorzaakt dit.

Als de console een nieuw adres krijgt

Agents vertrouwen de console op haar certificaat, dat gelijk blijft als haar IP-adres of naam verandert, maar ze verbinden met het adres waarmee ze zijn geregistreerd. Voer na een wijziging op elke agentmachine uit (als beheerder / root):

backupzit-agent set-server https://192.168.1.20:8443

De opdracht controleert dat de console op het nieuwe adres antwoordt met hetzelfde certificaat, slaat het op, en de agent gebruikt het na een herstart van zijn service (systemctl restart backupzit-agent, of herstart de service BackupZit Agent op Windows). Een DNS-naam voor de console vanaf het begin bespaart deze stap.

Waar de agent zijn configuratie bewaart

  • Windows: C:\ProgramData\backupzit\agent.json (alleen toegankelijk voor SYSTEM en Administrators).
  • Linux: /etc/backupzit/agent.json (alleen root).

Het bestand bevat het geheim van de agent. Wie het kan lezen, kan zich als die agent voordoen, dus behoud deze rechten.

Agentlogboek

  • Windows: C:\ProgramData\backupzit\agent.log
  • Linux: /etc/backupzit/agent.log en journalctl -u backupzit-agent
  • Herstelsystemen tonen het logboek op hun scherm.

Verwijderen van de software

Windows: Instellingen → Apps → BackupZit Agent → Verwijderen (of msiexec /x). Linux: apt remove backupzit-agent / dnf remove backupzit-agent. Verwijder daarna de agent in de console. Back-ups blijven op de opslag.

Op Windows zet het verwijderen de registratie opzij (C:\ProgramData\backupzit\agent.json.removed-datum), zodat bij een nieuwe installatie van de agent om een registratiecode wordt gevraagd. Vindt het installatieprogramma een registratie van een eerdere versie, dan meldt het dat: laat de code leeg om haar te behouden, of plak een nieuwe code om de computer opnieuw te registreren (bijvoorbeeld bij een andere console).
