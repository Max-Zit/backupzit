Virtuele machines in VMware ESXi

BackupZit maakt back-ups van de virtuele machines van VMware ESXi-hosts zonder iets op ESXi of in de VM's te installeren. Een BackupZit-agent op een willekeurige machine in het netwerk werkt als proxy van de host. Hij maakt snapshots, leest alleen de gewijzigde blokken van de virtuele schijven en schrijft ze naar uw opslag.

Vereisten

  • ESXi 6.7, 7 of 8 rechtstreeks verbonden, of vCenter Server 7 of 8 met zijn ESXi-hosts (zie vCenter Server).
  • Een gebruiker met beheerdersrechten op de host, meestal root.
  • SSH ingeschakeld op hosts met de gratis licentie: Host → Actions → Services → Enable Secure Shell. De gratis ESXi-licentie maakt de API alleen-lezen, dus snapshots en herstelbewerkingen lopen via SSH. Gelicentieerde hosts worden via de vSphere-API gewijzigd en hebben geen SSH nodig.
  • Een proxy-agent: een willekeurige Windows- of Linux-agent die de host bereikt op poort 443 (en 22 als SSH wordt gebruikt). De back-upgegevens lopen erdoorheen, zet hem dus op een snel netwerk dicht bij de host en de opslag.
  • Vrije ruimte op de datastore van de VM terwijl een draaiende VM wordt geback-upt. BackupZit kopieert de schijf daar even (zie hieronder). De kopie is thin, dus hij heeft zoveel ruimte nodig als de schijf werkelijk gebruikt.

Een host toevoegen

  1. Open Agents → VMware ESXi-hosts → Een ESXi-host toevoegen.
  2. Voer het adres, de gebruiker, het wachtwoord en de proxy-agent in.
  3. De console maakt één keer verbinding om ze te controleren. Hij leest de VM-lijst en de licentie, en pint het HTTPS-certificaat en de SSH-hostsleutel van de host. Als de host later wordt vervangen door een andere machine met hetzelfde adres, weigert BackupZit verbinding te maken in plaats van die het wachtwoord te sturen. Wijzigt het certificaat om een bekende reden — de host is opnieuw geïnstalleerd, heeft een nieuw certificaat gekregen of is aan vCenter toegevoegd (dat de certificaten van zijn hosts vervangt) —, dan toont de host op de pagina Agents de nieuwe vingerafdruk met een knop Nieuw certificaat accepteren. Vergelijk de vingerafdruk met de host voordat u hem accepteert.

Het wachtwoord wordt versleuteld opgeslagen, zoals alle andere geheimen. De VM-lijst wordt elke 10 minuten vernieuwd, of direct met Vernieuwen. De tabel toont de modus van elke host:

  • vSphere-API (gelicentieerde host, geen SSH nodig): snapshots, schijfkopieën, herstel en direct herstel lopen via de API.
  • gratis licentie: snapshots en herstel via SSH: de API van de host is alleen-lezen, dus deze stappen lopen via SSH.

Met Automatisch kiest de console zelf, dus een host die later een licentie krijgt, schakelt zonder verdere instellingen over op de API. Hoe de host wordt gewijzigd in de rij van de host (en bij het toevoegen) kan Altijd SSH of Altijd de vSphere-API afdwingen; de wijziging wordt meteen gecontroleerd. Eerdere back-ups en hun herstelpunten hangen niet af van de methode.

vCenter Server

Voeg een vCenter Server toe zoals een host: het adres, administrator@vsphere.local (of een gebruiker met de rol Administrator) en een proxy-agent. BackupZit ziet dan de VM's van alle ESXi-hosts en clusters van het datacenter via deze ene verbinding; er wordt niets via SSH gewijzigd en geen hostwachtwoord is nodig.

  • Een VM die met vMotion naar een andere host is verplaatst, wordt verder geback-upt: VM's worden herkend aan hun instance-UUID, niet aan hun host.
  • Bij herstel kunt u de ESXi-host kiezen waarop de VM draait (standaard: de host van de oorspronkelijke VM) en de datastore.
  • Direct herstel start de VM op de gekozen host; Voltooien verplaatst hem met Storage vMotion terwijl hij blijft draaien naar een datastore, zonder onderbreking.
  • Een vCenter met meerdere datacenters kan nog niet worden toegevoegd; voeg de hosts van de andere datacenters rechtstreeks toe.

Voeg dezelfde ESXi-host niet zowel rechtstreeks als via vCenter toe: elke verbinding heeft een eigen repository, dus zijn VM's zouden twee keer worden geback-upt.

Back-uptaken

Kies in Back-uptaken de ESXi-host (vermeld onder VMware ESXi-hosts in de agentlijst) en Virtuele machines. Maak een back-up van alle VM's van de host (later gemaakte VM's worden automatisch opgenomen) of vink er enkele aan. De taak draait op de proxy-agent van de host. Als u de proxy wijzigt, volgen de bestaande taken.

Hoe een VM wordt geback-upt

  1. Changed block tracking (CBT) wordt voor de VM ingeschakeld als het uit staat.
    • Op gelicentieerde hosts gebeurt dat automatisch.
    • Op gratis hosts kan CBT alleen worden ingeschakeld terwijl de VM uit staat. BackupZit doet het bij de eerste back-up die de VM uitgeschakeld aantreft. Tot dan leest elke back-up de volledige schijven en toont de run een waarschuwing.
  2. Er wordt een snapshot backupzit_… gemaakt. Als VMware Tools in de gast draaien, wordt de snapshot gequiesced: toepassingen en bestandssystemen worden eerst geleegd, wat de back-up applicatieconsistent maakt. Zonder VMware Tools is hij crash-consistent. Installeer open-vm-tools in Linux-VM's en VMware Tools in Windows-VM's.
  3. CBT meldt welke blokken gelezen moeten worden:
    • bij de eerste back-up alleen de gebruikte blokken;
    • daarna alleen de blokken die sinds de vorige back-up zijn gewijzigd.
  4. Een draaiende VM houdt zijn schijven vergrendeld. Zijn schijven worden daarom op de datastore gekopieerd (thin) en de snapshot wordt meteen verwijderd, meestal na enkele seconden. De kopie wordt daarna via HTTPS gelezen en verwijderd. Uitgeschakelde VM's worden direct gelezen.
  5. De configuratie van de VM (.vmx) en de NVRAM worden met de back-up opgeslagen.

Voorbeeld uit het testlab: een Debian-VM met een schijf van 8 GB, waarvan 1,6 GB in gebruik. De eerste back-up las 1,6 GB. De volgende, na 50 MB nieuwe gegevens, las 70 MB en duurde 23 seconden.

Een VM herstellen

Gebruik de herstelwizard (Volledige virtuele machine) of de pagina van de back-up in Activiteit. Kies:

  • Als nieuwe VM naast het origineel: een kopie met een nieuwe naam, UUID en MAC-adressen. De standaardnaam is die van het origineel plus -restored- en de datum. Netwerkinstellingen in de gast die aan de oude MAC-adressen gebonden zijn, zoals netplan match: macaddress in cloud-images, gelden niet voor de kopie.
  • In plaats van de originele VM: met uitschakelen en de schijven vervangen zal BackupZit:
    • de VM uitschakelen en de snapshots verwijderen;
    • de huidige schijven hernoemen naar ….replaced-DATE.vmdk (verwijder ze zodra de herstelde VM werkt);
    • de back-up naar nieuwe schijven met de oorspronkelijke namen schrijven, en CPU en geheugen instellen zoals in de back-up.
    De VM behoudt zijn UUID, netwerkadapters en MAC-adressen. Als de VM was verwijderd, wordt hij opnieuw gemaakt met zijn oorspronkelijke identiteit.
  • ESXi-host en datastore: een andere host, of een andere datastore van dezelfde host.
  • De VM na het herstel starten.

Schijven worden thin hersteld en alleen blokken met gegevens worden geschreven. ISO-images die aan cd/dvd-stations gekoppeld waren, maken geen deel uit van de back-up, dus die stations blijven leeg.

Direct herstel

Kies Direct, draaiend vanuit de back-up om een VM binnen enkele seconden te starten, zonder eerst zijn schijven te kopiëren. De proxy-agent van de host — dat moet een Linux-agent zijn — biedt de schijven van de VM rechtstreeks vanuit de back-up aan via NFS; de host koppelt dat als datastore backupzit-<agent> en draait de VM daarvandaan. Wijzigingen die de VM maakt, worden op de agent bewaard (/var/lib/backupzit/instant-esxi, die daarvoor vrije ruimte nodig heeft); de back-up zelf wordt nooit gewijzigd, en het bewaarbeleid houdt hem vast zolang de VM ervan draait. Als de originele VM nog bestaat, krijgt de directe VM een nieuwe UUID en nieuwe MAC-adressen.

Op de runpagina, wanneer de VM werkt zoals het hoort:

  • Voltooien kopieert hem naar een datastore van de host: de VM wordt afgesloten (via VMware Tools als die draaien), zijn schijven worden thin gekopieerd (via de API op gelicentieerde hosts, met vmkfstools via SSH bij de gratis licentie), hij wordt vanaf de datastore geregistreerd en weer gestart. Een losse host heeft geen Storage vMotion, dus dit vraagt een korte onderbreking die met de schijfgrootte toeneemt. Mislukt het kopiëren, dan blijft de VM vanuit de back-up draaien.
  • Verwerpen stopt en verwijdert de VM met al zijn wijzigingen.

De agent beantwoordt NFS op poort 2049 (en registreert het bij de rpcbind van de machine op poort 111, of beantwoordt poort 111 zelf) alleen voor het adres van de ESXi-host; open deze poorten van de host naar de agent als er een firewall tussen zit. Wanneer de laatste directe VM is voltooid of verworpen, wordt de datastore verwijderd en stopt de NFS-server.

Losse bestanden

Bestanden bladeren op de pagina van de back-up (of Bestanden uit een virtuele machine in de herstelwizard) opent de schijven van de VM. U kunt NTFS, ext2/3/4 en XFS bladeren, ook op LVM, en bestanden downloaden of naar elke agent herstellen.

Opdrachtregel

Deze opdrachten draaien op elke agent. Zet het ESXi-wachtwoord in BACKUPZIT_VMWARE_PASSWORD:

backupzit-agent vmware list    --host 192.168.1.20 [--user root]
backupzit-agent vmware backup  --host … --repo … [--vmid N,N]
backupzit-agent vmware restore --host … --repo … --vmid N [--new] [--name NAME] [--datastore DS] [--overwrite] [--start] SNAPSHOT|latest

vmware list toont de vingerafdrukken van het certificaat en de SSH-sleutel van de host. Geef ze mee met --thumbprint en --ssh-host-key om ze ook op de opdrachtregel te pinnen.

Nog niet inbegrepen

  • vCenter met meerdere datacenters. Alleen een vCenter met één datacenter kan worden toegevoegd; voeg de hosts van de andere rechtstreeks toe.
  • VM's met eigen snapshots. Hun schijven zijn delta's; verwijder of consolideer de snapshots eerst.
  • Sommige schijftypen. Raw device mappings (RDM) en onafhankelijke schijven.
  • Direct herstel via een Windows-proxy-agent. Direct herstel vereist een Linux-proxy-agent.
