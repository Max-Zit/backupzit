Hyper-V virtuele machines

BackupZit maakt back-ups van virtuele Hyper-V-machines via de agent op de Hyper-V-host; in de VM's wordt niets geïnstalleerd. Windows- en Linux-gasten worden vastgelegd terwijl ze blijven draaien. U kunt ze herstellen als nieuwe VM of in plaats van het origineel.

Instellen

  1. Installeer de MSI van de Windows-agent vanuit Agents op de Hyper-V-host en registreer hem. Ondersteunde hosts: Windows Server 2016 of nieuwer met de Hyper-V-rol, of Windows 10/11 met Hyper-V. Installeer in een cluster de agent op elke host.
  2. Binnen een minuut verschijnt de host op de pagina Agents met het label Hyper-V · N VMs.
  3. Selecteer in Back-uptaken die agent en kies Virtuele machines (Proxmox VE, Hyper-V, VMware). Kies daarna:
    • alle VM's van de host, wat ook later gemaakte VM's omvat;
    • afzonderlijke VM's, door ze aan te vinken.

De agent werkt via de eigen interfaces van Hyper-V: de Hyper-V PowerShell-module en de Windows Virtual Disk API. De console slaat geen Hyper-V-inloggegevens op.

Hoe een VM wordt geback-upt

  1. Er wordt een tijdelijk herstelcontrolepunt (backupzit_…) gemaakt. Dat is het type controlepunt dat Hyper-V voor back-uptoepassingen biedt. Hyper-V vraagt de gast zich voor te bereiden:
    • Windows-gasten legen de buffers van hun toepassingen via VSS.
    • Linux-gasten bevriezen hun bestandssystemen, als de Hyper-V-daemons zijn geïnstalleerd (hyperv-daemons / hv-vss-daemon).
    Kan de gast geen van beide, dan wordt het controlepunt crash-consistent gemaakt. De runpagina toont welk type is gebruikt.
  2. Het herstelcontrolepunt schakelt Resilient Change Tracking (RCT) in voor de schijven van de VM; u ziet .rct- en .mrt-bestanden ernaast. De eerste back-up leest de volledige schijven. Daarna meldt RCT welke blokken sinds de vorige back-up zijn gewijzigd, en alleen die worden gelezen.
  3. De schijven worden in de staat van het controlepunt gelezen, via de Virtual Disk API, in blokken van 1 MiB. Dat omvat VHDX- en VHD-bestanden, inclusief ketens van eerdere controlepunten. Lege blokken worden niet opgeslagen, en blokken die al in de repository staan worden niet opnieuw geüpload.
  4. Het controlepunt wordt verwijderd en Hyper-V voegt het op de achtergrond samen.
  5. De configuratie van de VM wordt met de back-up opgeslagen: generatie, CPU, geheugen, netwerkadapters (switch, VLAN, MAC-adres), schijfcontrollers, secure boot en TPM.

Uitgeschakelde VM's worden direct gelezen, zonder controlepunt. Op hosts ouder dan Windows Server 2016 (geen herstelcontrolepunten) wordt een productiecontrolepunt gebruikt en leest elke back-up de volledige schijven.

Voorbeeld uit het testlab: een Linux-VM met een schijf van 3 GB. De eerste back-up las 3 GB. De volgende, na 64 MB nieuwe gegevens, las 96 MB.

Op Windows 10/11 maakt Hyper-V een automatisch controlepunt wanneer een VM start, tenzij die optie in de VM-instellingen is uitgeschakeld. BackupZit kan met zulke controlepunten omgaan, maar voor servers wilt u automatische controlepunten uitschakelen (VM-instellingen → Controlepunten).

Een VM herstellen

Open de run van de VM-back-up (vanaf de taakpagina of Activiteit) en gebruik Een Hyper-V-VM herstellen.

Als nieuwe VM naast het origineel

Maakt een tweede VM met nieuwe MAC-adressen, zodat die op hetzelfde netwerk als het origineel kan draaien. Standaard krijgt hij de naam van het origineel plus "restored" en de datum. Automatische controlepunten worden erop uitgeschakeld (Windows schakelt ze in voor nieuwe VM's), zodat het starten geen controlepuntbestanden achterlaat. Als de kopie naast het origineel draait en de BackupZit-agent bevat, zie Twee machines met één agent.

Netwerkinstellingen in de gast die aan een MAC-adres gebonden zijn, gelden niet voor de nieuwe adapters. Een voorbeeld is match: macaddress van netplan, dat Linux-cloud-images gebruiken.

In plaats van de originele VM

Vink uitschakelen en de schijven vervangen aan. BackupZit dan:

  • schakelt de bestaande VM uit;
  • voegt de controlepunten samen;
  • verwisselt de schijven voor de herstelde.

De VM behoudt zijn ID, netwerkadapters en MAC-adressen, zodat taken, monitoring en het netwerk van de gast blijven werken.

De oude schijfbestanden worden niet verwijderd; ze worden hernoemd naar ….replaced-DATE. Verwijder ze zodra de herstelde VM werkt.

Bestaat de originele VM niet meer, dan wordt hij opnieuw gemaakt, met een nieuwe Hyper-V-ID.

Opties

  • Map voor de virtuele schijven: de standaardmap van de host of een willekeurige map met VM-schijven. Een herstel ter plaatse zet de nieuwe schijven naast de originele.
  • De VM na het herstel starten.

Wat een herstelde VM krijgt

  • Virtuele switches worden op naam gekoppeld. Bestaat een switch niet op de host, dan blijft de adapter losgekoppeld.
  • Elke herstelde VM krijgt een nieuwe generatie-ID, zodat Active Directory-domeincontrollers het herstel veilig detecteren.

Losse bestanden herstellen

Klik in de VM-tabel van de run op Bestanden bladeren om de partities en volumes op de schijven van de VM te zien. U kunt NTFS, ext2/3/4 en XFS bladeren, ook binnen LVM. Van daaruit kunt u bestanden downloaden of naar elke agent herstellen. Het werkt precies zoals bij Proxmox VE.

Opdrachtregel

Voer dit uit op de Hyper-V-host, als beheerder:

backupzit-agent hyperv list
backupzit-agent hyperv backup  --repo ... [--vmid N,N]
backupzit-agent hyperv restore --repo ... --vmid N [--new] [--name NAME] [--folder D:\VMs] [--overwrite] [--start] SNAPSHOT|latest
  • --vmid is het nummer dat hyperv list toont. BackupZit leidt het af van de GUID van de VM.
  • Zonder --new wordt de VM ter plaatse hersteld.
  • --overwrite bevestigt dat de schijven van een bestaande VM vervangen moeten worden.

De repository-opties zijn dezelfde als bij alle opdrachten; zie Opdrachtregelreferentie.

Nog niet inbegrepen

  • Sommige schijftypen. Gedeelde VHDX, VHD Sets en pass-through-schijven worden niet geback-upt.
