Server installeren

De console draait op Linux (Debian, Ubuntu, AlmaLinux, Rocky Linux) met PostgreSQL. Elke organisatie draait haar eigen console in haar eigen netwerk.

Vereisten

  • Een Linux-VM of -server: 2 vCPU, 2–4 GB RAM en 20 GB schijf is ruim voldoende voor honderden agents (back-upgegevens worden er niet op opgeslagen).
  • PostgreSQL 13 of nieuwer (lokaal of op een andere server).
  • Netwerk: agents moeten de console bereiken via TCP 8443 (HTTPS). Agents moeten ook de opslag rechtstreeks bereiken.

1. Kant-en-klare VM-image

Een kant-en-klare appliance (Debian, PostgreSQL, de console, automatische beveiligingsupdates) die in minder dan een minuut start en geen internettoegang nodig heeft:

HypervisorHoe
VMware ESXiHost Client: Create / Register VM → Deploy a virtual machine from an OVF or OVA file, kies backupzit-appliance.ova. vSphere: Deploy OVF Template. Workstation en VirtualBox: File → Open / Import.
Proxmox VEKopieer backupzit-appliance.qcow2 naar het knooppunt, maak een VM zonder schijf (2 vCPU, 2–4 GB RAM, VirtIO-netwerk) en daarna
qm importdisk <vmid> backupzit-appliance.qcow2 local-lvm
koppel de geïmporteerde schijf als SCSI, maak er de opstartschijf van en schakel de QEMU-gastagent in.
Hyper-VPak backupzit-appliance-vhdx.zip uit, daarna Nieuw → Virtuele machine, generatie 1, 2–4 GB RAM, Een bestaande virtuele harde schijf gebruiken: de VHDX.

Start de VM. Het scherm toont het adres van de webconsole en het initiële wachtwoord van admin (zie Eerste aanmelding). Geef de VM 2 vCPU en 2–4 GB RAM; u kunt de schijf van 16 GB op elk moment vergroten — de appliance neemt de nieuwe ruimte bij de volgende start in gebruik (het root-bestandssysteem groeit tijdens het draaien). Bij de eerste start maakt elke kopie eigen SSH-sleutels, een eigen databasewachtwoord en een eigen geheimensleutel, zodat één image vele keren kan worden uitgerold. De netwerkadapter krijgt zijn adres via DHCP.

2. Appliance-ISO

De appliance-ISO installeert alles zonder vragen: Debian, PostgreSQL, de console en automatische beveiligingsupdates.

  1. Maak een VM (of gebruik een server) met 2 vCPU, 2–4 GB RAM en een schijf van 16 GB of groter. Gebruik VirtIO of de standaardapparaten van de hypervisor, BIOS of UEFI.
  2. Start vanaf backupzit-appliance.iso. Na 5 seconden begint de installatie vanzelf, wist de eerste schijf en installeert. Ze downloadt de pakketten van het besturingssysteem, dus de server heeft tijdens de installatie internettoegang nodig. Dit duurt ongeveer 10–20 minuten, daarna start de server opnieuw.
  3. Het scherm van de server toont het adres van de webconsole en het initiële wachtwoord van admin. Open het adres, meld u aan en wijzig het wachtwoord.

De appliance (image of ISO)

De appliance heeft twee aparte accounts:

  • admin in de webconsole (https://<address>:8443) voor het dagelijkse werk. Het initiële wachtwoord wordt na de eerste start op het scherm van de server getoond; wijzig het onder Mijn account.
  • bzadmin op de server zelf (het scherm in de hypervisorconsole, of SSH), initieel wachtwoord backupzit. U moet het bij de eerste aanmelding wijzigen; de gebruiker kan sudo gebruiken. Root kan zich niet aanmelden.

Updates van BackupZit en van het besturingssysteem worden vanuit de console beheerd (zie hieronder). VMware Tools en de QEMU-gastagent zijn inbegrepen, zodat hypervisors het adres van de appliance tonen.

Setupmenu op het scherm van de server

Wanneer bzadmin zich op het eigen scherm van de server aanmeldt (niet via SSH), opent een menu:

Dezelfde instellingen voor netwerk, servernaam, SSH en tijdzone staan onder Instellingen → Netwerk in de webconsole (alleen beheerders). Daar wordt een statisch adres waarvan de gateway niet binnen een halve minuut antwoordt automatisch teruggedraaid, zodat een typefout de appliance niet van het netwerk kan afsnijden; is de console toch niet bereikbaar, gebruik dan het menu op het scherm van de server, dat ook werkt met SSH uitgeschakeld.

Agents onthouden het certificaat van de console, niet haar adres. Bereiken ze de console via haar IP-adres en verandert dat adres, wijs ze dan naar het nieuwe met backupzit-agent set-server (zie Agents), of gebruik vanaf het begin een DNS-naam. Reserveer bij DHCP het adres van de appliance in de DHCP-server zodat het niet verandert.

De SSH-server van de appliance biedt alleen AES-GCM/CTR-cijfers en SHA-2-MAC's aan (geen chacha20-poly1305 en geen 64-bits MAC's, die kwetsbaarheidsscanners als zwak melden).

3. Installatiescript

Op een bestaande server met Debian 12+, Ubuntu 22.04+, AlmaLinux of Rocky Linux 9+ (x86-64), als root:

curl -fsSL https://github.com/Max-Zit/backupzit/releases/latest/download/install.sh | sudo sh

Het script installeert PostgreSQL, downloadt de nieuwste versie, controleert de handtekening met de BackupZit-releasesleutel en de controlesom van het pakket, installeert de console, maakt de database met een willekeurig wachtwoord, schrijft /etc/backupzit/server.env, schakelt automatische beveiligingsupdates in, opent poort 8443 in firewalld of ufw als die actief zijn, start de console en toont het adres en het initiële admin-wachtwoord. Opties (na sh -s --):

OptieEffect
--version 0.32.0deze versie installeren in plaats van de nieuwste
--db postgres://user:pw@host:5432/dbeen bestaande PostgreSQL-database gebruiken in plaats van een lokale
--hosts backup.example.local,10.0.0.10namen en adressen voor het certificaat van de console (standaard: adres en naam van de server)
--no-auto-updatesautomatische beveiligingsupdates laten zoals ze zijn

Voorbeeld: curl -fsSL …/install.sh | sudo sh -s -- --hosts backup.example.local. Het script opnieuw uitvoeren op een geïnstalleerde console werkt BackupZit bij en behoudt configuratie en gegevens. Om het script te lezen voordat u het uitvoert, downloadt u het eerst: curl -fsSLO …/install.sh; less install.sh; sudo sh install.sh.

4. Pakketten met de hand

Debian / Ubuntu

apt install postgresql
apt install ./backupzit-server_*.deb

AlmaLinux / Rocky Linux

dnf install postgresql-server && postgresql-setup --initdb && systemctl enable --now postgresql
dnf install ./backupzit-server-*.rpm

Wijzig op AlmaLinux en Rocky Linux ident in scram-sha-256 voor de regels 127.0.0.1 en ::1 in /var/lib/pgsql/data/pg_hba.conf en herstart PostgreSQL, zodat de console zich met een wachtwoord kan aanmelden.

De database maken

sudo -u postgres psql -c "SET password_encryption = 'scram-sha-256'; CREATE USER backupzit WITH PASSWORD 'choose-a-strong-password'"
sudo -u postgres psql -c "CREATE DATABASE backupzit OWNER backupzit"

Zet de verbindingsreeks in /etc/backupzit/server.env:

BACKUPZIT_DB=postgres://backupzit:choose-a-strong-password@localhost:5432/backupzit?sslmode=disable
BACKUPZIT_PUBLIC_URL=https://backup.example.local:8443
BACKUPZIT_TLS_HOSTS=backup.example.local,10.0.0.10
systemctl start backupzit-server

Eerste aanmelding

Open https://<server>:8443. De initiële beheerder is admin; het wachtwoord staat in /var/lib/backupzit/initial-admin-password.txt (of stel BACKUPZIT_ADMIN_PASSWORD in vóór de eerste start). Wijzig het na het aanmelden. Een vergeten wachtwoord stelt u op de server zo opnieuw in:

set -a; . /etc/backupzit/server.env; set +a
backupzit-server --set-admin-password 'NEW-PASSWORD'

Het certificaat

Bij de eerste start maakt de console een zelfondertekend certificaat. Uw browser waarschuwt er één keer voor; agents vertrouwen helemaal niet op certificeringsinstanties — ze pinnen de certificaatvingerafdruk die bij de registratie op de pagina Agents wordt getoond. Dat beschermt agents tegen een valse server, zelfs op een onbetrouwbaar netwerk.

Vervang dat certificaat niet (cert.pem/key.pem in de gegevensmap): eerder geregistreerde agents zouden de verbinding weigeren tot ze opnieuw zijn geregistreerd. Voeg voor browsers in plaats daarvan een vertrouwd certificaat toe zoals hieronder beschreven.

Een vertrouwd certificaat voor browsers

Om de browserwaarschuwing te vermijden, opent u Instellingen → Certificaat. De console antwoordt dan ook op een DNS-naam, bijvoorbeeld https://backup.example.com op poort 443, met een vertrouwd certificaat. Agents blijven poort 8443 en het vastgepinde certificaat gebruiken, dus zij merken er niets van.

  • Een certificaat uploaden van uw bedrijfs-CA of een publieke CA, ook een wildcardcertificaat zoals *.example.com. Plak het certificaat (met de tussencertificaten) en de privésleutel als PEM, of kies de bestanden. De console controleert dat de sleutel bij het certificaat hoort, dat het nu geldig is en dat het de DNS-naam dekt. Zonder interne DNS voert u in plaats daarvan het IP-adres van de console in en gebruikt u een certificaat dat voor dat IP-adres is uitgegeven (alternatieve naam IP:192.168.1.20); geef de console dan een vast adres. U krijgt 21 dagen voor het verlopen een e-mail.
  • Let's Encrypt: gratis certificaten, automatisch vernieuwd 30 dagen voordat ze verlopen. Let's Encrypt moet controleren dat u de naam beheert, op een van twee manieren:
    • DNS-controle via Cloudflare, aanbevolen voor consoles die niet vanaf internet bereikbaar zijn. BackupZit maakt met een Cloudflare-API-token een tijdelijk TXT-record. Ga in Cloudflare naar My Profile → API Tokens → Create Token, gebruik de sjabloon Edit zone DNS en beperk het tot uw zone.
    • HTTP-controle: poort 80 van de console moet onder de DNS-naam vanaf internet bereikbaar zijn. Dat wilt u zelden voor een back-upserver.
    Probeer de instelling eerst met Het testsysteem van Let's Encrypt gebruiken. Browsers vertrouwen de certificaten daarvan niet, maar het heeft geen snelheidslimieten.
  • Poort 80 bedienen leidt http:// om naar https://.

De DNS-naam moet naar het IP-adres van de console wijzen, meestal via een A-record in uw interne DNS. De certificaatbestanden staan in /var/lib/backupzit/web, en de sleutel is alleen leesbaar voor de service. Op Linux mag de service de poorten 80 en 443 gebruiken (CAP_NET_BIND_SERVICE); open ze in de firewall als browsers vanaf andere netwerken verbinden.

BackupZit bijwerken

Standaard haalt de console updates uit de officiële BackupZit-versies op GitHub (https://github.com/Max-Zit/backupzit/releases). Onder Instellingen → Updates kunt u in plaats daarvan een andere updatebron invoeren — uw eigen HTTPS-mirror of een map op de server. Welke bron ook, elke versie moet een geldige BackupZit-handtekening dragen. De console controleert dagelijks op nieuwe versies en mailt de beheerders als er een beschikbaar is. Klik op Installeren om hem te installeren:

  1. De console controleert de handtekening van de versie en de controlesom van het pakket, en wacht tot er geen back-up of herstel loopt.
  2. Een systeemservice (backupzit-update, draait als root) controleert de handtekening opnieuw met de releasesleutels die in BackupZit zijn ingebouwd. Zelfs een gecompromitteerde console kan zo geen ander pakket laten installeren.
  3. Hij maakt een back-up van de database (pg_dump), bewaart het huidige programma, installeert het pakket en herstart de console.
  4. Antwoordt de nieuwe versie niet binnen twee minuten, dan worden het vorige programma en de database zoals die was automatisch hersteld. Het resultaat, met het logboek van de mislukte start, wordt op de pagina Updates getoond, vastgelegd in het auditlogboek en gemaild.
  5. Na een geslaagde update worden ook de agents bijgewerkt: elke agent installeert de nieuwe versie zodra hij inactief is. Schakel dat op dezelfde pagina uit als u ze liever zelf bijwerkt.

De console is ongeveer een minuut niet beschikbaar. De databaseback-ups en vorige programma's van de laatste drie updates worden bewaard in /var/lib/backupzit-update.

Zonder internettoegang: download de versiebestanden (manifest.json, manifest.json.sig en het serverpakket) op een andere computer. Upload ze daarna onder Een update uit bestanden installeren, of kopieer ze naar een map op de server en gebruik die map als updatebron.

U kunt nog steeds bijwerken met de pakketbeheerder (apt install ./backupzit-server_….deb); de database wordt gemigreerd wanneer de nieuwe versie start.

Updates van het besturingssysteem

Dezelfde pagina (Instellingen → Updates) toont het besturingssysteem van de consoleserver: hoeveel updates er beschikbaar zijn, hoeveel daarvan beveiligingsfixes zijn, of een herstart nodig is en of automatische beveiligingsupdates aan staan. De status wordt dagelijks vernieuwd, of met Nu controleren. U kunt:

  • Automatische beveiligingsupdates inschakelen (aanbevolen). Het eigen hulpmiddel van het systeem installeert dagelijks alleen beveiligingsfixes: unattended-upgrades op Debian en Ubuntu, dnf-automatic op AlmaLinux en Rocky Linux.
  • Nu alle updates installeren. Services zoals PostgreSQL kunnen kort herstarten, en de console maakt vanzelf opnieuw verbinding.
  • Server herstarten, bijvoorbeeld na een kernelupdate. De console weigert dat zolang er back-ups of herstelacties lopen. Agents behouden hun taken en melden de resultaten zodra de console terug is.

Deze taken lopen via dezelfde root-service als console-updates. Ze worden vastgelegd in het auditlogboek, en de uitvoer van de laatste taak wordt op de pagina getoond.

Een back-up van de console zelf maken

Back-ups op uw opslag blijven zonder de console leesbaar met de herstelbladen. Om ook de console zelf terug te krijgen na verlies van haar server, schakelt u Instellingen → Consoleback-up in. Dat omvat taken, schema's, agents, gebruikers, instellingen, uitvoeringsgeschiedenis en opgeslagen referenties. De console maakt dan dagelijks een back-up van zichzelf naar een netwerkopslagdoel, in de map backupzit-console.

Een consoleback-up bevat:

  • de hele database, tabel voor tabel geëxporteerd, zodat er geen specifieke pg_dump-versie nodig is;
  • de geheimensleutel die de opgeslagen referenties ontsleutelt;
  • het certificaat van de console, dat de agents vastpinnen.

Ze is versleuteld met de herstelsleutel van het doel en gededupliceerd. De nieuwste back-ups worden bewaard: standaard 14.

De console herstellen

  1. Installeer een nieuwe console met dezelfde of een nieuwere versie, bijvoorbeeld vanaf de appliance-ISO.
  2. Voer op de nieuwe server als root het volgende uit. De referenties zijn die van het herstelblad van het opslagdoel, en het repositoryadres staat op de pagina Consoleback-up. 
    systemctl stop backupzit-server
set -a; . /etc/backupzit/server.env; set +a
export BACKUPZIT_PASSWORD='<recovery key>'
export BACKUPZIT_SFTP_PASSWORD='…' BACKUPZIT_SFTP_HOSTKEY='SHA256:…'   # or BACKUPZIT_S3_ACCESS_KEY/_SECRET_KEY, _SMB_PASSWORD, _AZURE_KEY, _HARDENED_KEY/_FINGERPRINT
backupzit-server --restore-console --repo 'sftp://backup@nas:22/backups/backupzit-console'
systemctl start backupzit-server
  3. Geef de nieuwe server het IP-adres of de DNS-naam van de oude. De agents vertrouwen het herstelde certificaat en maken vanzelf opnieuw verbinding.

Het herstel vervangt de database van de nieuwe console door die uit de back-up en brengt de database op het niveau van de geïnstalleerde versie. --snapshot ID herstelt een oudere back-up in plaats van de nieuwste.

Bewaar ook een kopie van de herstelbladen en van secrets.key buiten de server, bijvoorbeeld in uw wachtwoordmanager.
