Řešení potíží a časté dotazy

Agent se zobrazuje jako offline

  • Je počítač zapnutý a běží služba? Windows: Get-Service backupzit-agent; Linux: systemctl status backupzit-agent.
  • Dosáhne počítač na konzoli? Test-NetConnection backup-server -Port 8443 nebo curl -k https://backup-server:8443/login.
  • Protokol agenta: C:\ProgramData\backupzit\agent.log, v Linuxu /etc/backupzit/agent.log nebo journalctl -u backupzit-agent. „fingerprint mismatch“ znamená, že se certifikát konzole změnil — zaregistrujte agenta znovu.

Záloha selhala

Otevřete běh v Aktivita; zpráva uvádí příčinu. Časté příčiny:

Zpráva obsahujeŘešení
host key mismatch / fingerprintKlíč serveru SFTP se změnil nebo byl otisk zadán špatně. Ověřte příkazem ssh-keygen -lf na serveru.
permission denied / access deniedPřihlašovací údaje úložiště nebo oprávnění ke složce. Vyzkoušejte přihlášení klientem SFTP/SMB.
no space left / quotaÚložiště je plné. Zkraťte uchovávání nebo přidejte místo; vypršené zálohy uvolní místo po dalším běhu.
repository is lockedNa stejném úložišti běží jiná operace (např. úklid); běh to zkouší znovu 30 minut. Zastaralé zámky vyprší automaticky.
wrong password / recovery keyÚložiště bylo vytvořeno jiným klíčem — ověřte, že úloha používá správné cílové úložiště.
bucket has no Object Lock enabledNeměnnost byla požadována u bucketu vytvořeného bez Object Lock. Vytvořte nový bucket s Object Lock.

Další zprávy

SituaceCo dělat
„no matching backup disk is connected“Připojte jeden z rotujících USB disků (zpráva uvádí požadovaný štítek a které označené disky jsou připojené). Obnova potřebuje přesně ten disk, který je uveden v běhu zálohy.
„several backup disks are connected“Připojujte vždy jen jeden z rotujících disků.
Test obnovy selhalOtevřete běh: zpráva uvádí poškozený soubor nebo blok nebo důvod (např. záloha smazaná na úložišti). Spusťte backupzit-agent check --read-data nad úložištěm, zkontrolujte úložiště a spusťte novou zálohu. Pokud byly zálohy smazány na neměnném úložišti, viz Ochrana proti ransomwaru.
Záloha označená jako podezřeláZkontrolujte počítač kvůli ransomwaru nebo hromadnému mazání (např. vyprázdněná synchronizovaná složka). Pokud je vše v pořádku (např. plánovaná migrace), klikněte na stránce úlohy na Zkontrolováno — obnovit uchovávání.
Let's Encrypt: „could not verify … is port 80 … reachable“Kontrola HTTP vyžaduje port 80 dostupný z internetu. Pro interní konzole použijte kontrolu DNS přes Cloudflare.
Let's Encrypt: „no Cloudflare zone … is accessible with this token“Token musí mít oprávnění Zone → DNS → Edit pro zónu, která obsahuje název konzole.
„HTTPS port 443: … permission denied“ nebo „address already in use“Port používá jiný program, nebo služba nesmí otevírat porty pod 1024 (spusťte ji s CAP_NET_BIND_SERVICE, jak to dělá balíček). Zvolte jiný port v Nastavení → Certifikát.
Aktualizace: „updates from the console need the Linux package of the console“Konzole nebyla nainstalována z balíčku deb/rpm (například zkušební režim). Aktualizujte ji stejně, jak byla nainstalována.
Aktualizace: „the release is not signed with a BackupZit release key“Zdroj aktualizací neobsahuje oficiální vydání, nebo byly soubory cestou změněny. Stáhněte je znovu z oficiální adresy.
Aktualizace: stav rolled-backNová verze se nespustila, proto byla obnovena předchozí verze i její databáze. Protokol neúspěšného startu je na stránce Aktualizace; pošlete ho podpoře.
Operační systém: „no supported package manager“Aktualizace operačního systému jsou podporované v Debianu, Ubuntu (apt) a AlmaLinuxu, Rocky Linuxu, RHEL (dnf).
Záloha konzole: „the backup was made by a newer BackupZit“Před obnovou nainstalujte na novou konzoli verzi, která zálohu vytvořila, nebo novější.
Záloha konzole: „console backups need network storage“Zvolte cíl SFTP, S3, SMB, Azure nebo zabezpečené úložiště; místní cesta agenta není z konzole dostupná.
„Příliš mnoho neúspěšných přihlášení“Vaše adresa byla zablokována po opakovaně špatných heslech: ve výchozím stavu na 30 minut, při opakovaných blokacích déle. Správce může blokaci zrušit v Nastavení → Přihlášení a zabezpečení. Na serveru zruší všechny blokace backupzit-server --unblock-ip all. Účty se nikdy nezamykají trvale.
Ztracený telefon pro dvoufázové přihlášeníPoužijte jeden z kódů obnovy; jinak správce dvoufázové přihlášení resetuje na stránce vašeho uživatele. Poslední správce si může heslo resetovat na serveru příkazem backupzit-server --set-admin-password.
„your directory account is not in any BackupZit group“Přidejte uživatele do jedné ze skupin přiřazených v Nastavení → LDAP / Active Directory, nebo přiřaďte více skupin. Pomocí Test tam uvidíte skupiny nalezené pro uživatele.
API vrací 401 / 403401: token chybí, je odvolaný, vypršel nebo je jeho vlastník zakázán. 403: role tokenu je pro požadavek příliš nízká.
Azure: AuthenticationFailed / AuthorizationPermissionMismatchŠpatný klíč účtu, nebo SAS tokenu chybí oprávnění ke čtení, zápisu, mazání či výpisu, nebo vypršel.
Obnovený VM s Windows Server 2012 R2 / Windows 8.1 se nespustí v Hyper-V Gen 2 („hash was denied (DBX)“)Microsoft odvolal starý zavaděč pro Secure Boot. Vypněte pro tento VM Secure Boot, nebo systém před zálohou aktualizujte.

Virtuální počítače, systémy Linux a nový hardware

SituaceCo dělat
Proxmox: „the guest is running and one of its disks is on storage without snapshot support“Běžící hosté potřebují disky LVM-thin, ZFS, Ceph RBD nebo qcow2. Přesuňte disk (Disk Action → Move Storage) nebo hosta zálohujte, když je zastavený.
Hyper-V: běh hlásí „crash-consistent“Host se nedokázal připravit na kontrolní bod. U hostů s Windows ověřte, že integrační služby Hyper-V (Backup (volume shadow copy)) jsou v nastavení VM zapnuté. Do hostů s Linuxem nainstalujte hyperv-daemons (RHEL) nebo linux-cloud-tools / hyperv-daemons (Debian/Ubuntu).
VMware: „SSH off“ nebo „SSH to …: connection refused“Zapněte SSH na hostiteli ESXi: Host → Actions → Services → Enable Secure Shell (a nastavte spouštění s hostitelem). Potřebují ho obnovy a při bezplatné licenci i zálohy.
VMware: „changed block tracking is off and can be enabled … only while the VM is off“Bezplatná licence ESXi: jednou VM vypněte a pak spusťte úlohu; BackupZit zapne sledování změněných bloků a další zálohy čtou jen změněné bloky.
VMware: „copy the disk on the datastore (needs free space …)“Běžící VM se nakrátko kopírují na svém datastoru. Uvolněte tam místo (tolik, kolik disk zabírá), nebo VM zálohujte vypnutý.
VMware: „… is a snapshot delta disk“VM má vlastní snímky. Smažte je nebo je konsolidujte v ESXi Host Clientu (Snapshots → Delete all).
VMware: „the ESXi certificate changed“Hostitel byl přeinstalován nebo na jeho adrese odpovídá jiný počítač. Pokud je to očekávané, odeberte hostitele v Agenti a znovu ho přidejte, aby se připnul nový certifikát.
VMware: soubory *.replaced-DATE.vmdk vedle disků VMStaré disky VM obnoveného na místo. Smažte je v prohlížeči datastoru, jakmile obnovený VM funguje.
Hyper-V: soubory *.replaced-DATE vedle disků VMStaré disky VM obnoveného na místo. Smažte je, jakmile obnovený VM funguje.
Okamžitá obnova v Proxmoxu: VM se nespustí nebo zamrzneZkontrolujte diskový server: systemctl status backupzit-instant-ID a journalctl -u backupzit-instant-ID na uzlu. Úložiště záloh musí zůstat dostupné; když nelze úložiště číst, čtení disků VM se zastaví.
Okamžitá obnova v Proxmoxu: „efidisk0 stays on storage backupzit-instant“QEMU nemůže přesunout úložiště proměnných EFI, dokud VM běží. Vypněte VM a spusťte qm disk move ID efidisk0 STORAGE --delete 1; nezávisí to na záloze.
Proxmox: „runs on node X; install the BackupZit agent on X“Host byl migrován. Nainstalujte agenta na každý uzel a hosty každého uzlu zálohujte agentem daného uzlu.
Pomalé zálohy nebo obnovy v Proxmoxu, SFTP „connection lost“, „message authentication code incorrect“ na serveru úložištěZnámý problém síťových karet Intel e1000e v hostitelích Proxmox (protokol: „Detected Hardware Unit Hang“, „Reset adapter unexpectedly“). Vypněte offloading: ethtool -K eno1 tso off gso off gro off a přidejte to jako řádek post-up rozhraní v /etc/network/interfaces.
Procházení souborů: „stored on a local path of the agent“Konzole umí číst jen zálohy na síťovém úložišti. Použijte backupzit-agent pve ls/extract nebo image-ls/image-extract na agentovi.
Obnova systému Linux: „missing programs …“Nainstalujte uvedené balíčky na obnovující počítač, nebo nastartujte obnovovací ISO BackupZit pro Linux, které je obsahuje.
Obnovený linuxový počítač nemá síťSíťová nastavení byla vázaná na starou MAC adresu (netplan match: macaddress). Obnovte s volbou Jiný hardware, nebo odstraňte řádky match v /etc/netplan/.
Obnovené Windows se zastaví s INACCESSIBLE_BOOT_DEVICEObnovte znovu s volbou Obnovit na jiný hardware, nebo nastartujte obnovovací ISO a spusťte backupzit-agent prepare-hardware --disk 0 [--drivers E:\Drivers].
Obnovená kopie počítače se zobrazuje jako původní agentObnovy do nového VM v Proxmoxu agenta v kopii automaticky odregistrují. U jiných kopií odstraňte v kopii agent.json a zaregistrujte ji jako nový počítač.
Aktualizace agenta se nedokončíPodívejte se do protokolu instalátoru v C:\ProgramData\backupzit\updates nebo /var/tmp/backupzit-updates; agenty starší než 0.21 je třeba jednou aktualizovat ručně.
Chybí ikona v oznamovací oblastiKlikněte na šipku ^ vedle hodin a přetáhněte ikonu BackupZit na hlavní panel, nebo spusťte BackupZit Agent z nabídky Start.

Záloha skončí „varováním“

Některé soubory nešlo přečíst — obvykle soubory zamčené aplikací, když není k dispozici VSS, nebo soubory, ke kterým agent nemá oprávnění. Seznam je na stránce běhu. Vše ostatní je zálohováno.

Zálohy jsou pomalé

  • První záloha čte a odesílá vše; další čtou jen změněné soubory a odesílají jen nová data.
  • Zkontrolujte síťovou cestu k úložišti (Wi-Fi, VPN, rychlost odesílání do internetu u cloudového úložiště).
  • Vylučte mezipaměti, dočasné soubory a média, která nepotřebujete.

Časté dotazy

Mohu použít NFS?

Chcete-li zálohovat sdílenou složku NFS (nebo SMB), vytvořte úlohu NAS / sdílená složka; linuxový agent připojí export pro každý běh. Chcete-li zálohy na NFS ukládat, připojte export na agentovi (Linux: /etc/fstab) a použijte cíl Místní / připojená cesta, např. /mnt/nfs-backup; pro počítače s Windows je lepší volbou cíl SMB.

Mohu zálohy přesunout na jiné úložiště?

Zkopírujte složku úložiště (nebo prefix bucketu) tak, jak je — je soběstačná — a přidejte cílové úložiště, které ukazuje na nové umístění se stejným klíčem pro obnovu.

Smaže smazání úlohy i zálohy?

Ne. Zálohy zůstávají na úložišti a lze je obnovit z Aktivita nebo z příkazového řádku.

Co se stane, když konzole neběží?

Dokud se nevrátí, nezačínají žádné nové plánované zálohy; běhy ve frontě pak pokračují. Obnovy jsou vždy možné z příkazového řádku s listem pro obnovu.

Kolik místa budou zálohy potřebovat?

Pro první zálohu zhruba velikost dat po kompresi, plus denní změny za každý uchovávaný den. Stránka Sestavy ukazuje, kolik se odeslalo za každou úlohu.
