Virtuální počítače VMware ESXi

BackupZit zálohuje virtuální počítače hostitelů VMware ESXi, aniž by cokoli instaloval na ESXi nebo do VM. Agent BackupZit na libovolném počítači v síti funguje jako proxy hostitele. Pořizuje snímky, čte jen změněné bloky virtuálních disků a zapisuje je na vaše úložiště.

Požadavky

  • ESXi 6.7, 7 nebo 8 připojený přímo, nebo vCenter Server 7 nebo 8 s jeho hostiteli ESXi (viz vCenter Server).
  • Uživatel s právy správce na hostiteli, obvykle root.
  • SSH zapnuté na hostitelích s bezplatnou licencí: Host → Actions → Services → Enable Secure Shell. Bezplatná licence ESXi dělá API jen pro čtení, takže snímky a obnovy jdou přes SSH. Licencovaní hostitelé se mění přes vSphere API a SSH nepotřebují.
  • Proxy agent: libovolný agent pro Windows nebo Linux, který dosáhne na hostitele na portu 443 (a 22, když se používá SSH). Data záloh tečou přes něj, proto ho umístěte do rychlé sítě blízko hostitele a úložiště.
  • Volné místo na datastoru VM při zálohování běžícího VM. BackupZit tam disk na chvíli zkopíruje (viz níže). Kopie je thin, takže potřebuje tolik místa, kolik disk skutečně zabírá.

Přidání hostitele

  1. Otevřete Agenti → Hostitelé VMware ESXi → Přidat hostitele ESXi.
  2. Zadejte adresu, uživatele, heslo a proxy agenta.
  3. Konzole se jednou připojí, aby je ověřila. Načte seznam VM a licenci a připne HTTPS certifikát a SSH klíč hostitele. Pokud bude hostitel později nahrazen jiným počítačem se stejnou adresou, BackupZit odmítne připojení místo toho, aby mu poslal heslo. Pokud se certifikát změní ze známého důvodu — hostitel byl přeinstalován, dostal nový certifikát nebo byl přidán do vCenter (který certifikáty svých hostitelů nahrazuje) —, zobrazí hostitel na stránce Agenti nový otisk s tlačítkem Přijmout nový certifikát. Před přijetím otisk porovnejte s hostitelem.

Heslo se ukládá šifrovaně, jako všechna ostatní tajemství. Seznam VM se obnovuje každých 10 minut, nebo hned tlačítkem Obnovit. Tabulka ukazuje režim každého hostitele:

  • vSphere API (licencovaný hostitel, SSH není potřeba): snímky, kopie disků, obnovy i okamžitá obnova jdou přes API.
  • bezplatná licence: snímky a obnovy přes SSH: API hostitele je jen pro čtení, takže tyto kroky jdou přes SSH.

S volbou Automaticky konzole vybírá sama, takže hostitel, který později dostane licenci, přejde na API bez dalšího nastavování. Jak se hostitel mění v řádku hostitele (a při přidání) může vynutit Vždy SSH nebo Vždy vSphere API; změna se hned ověří. Dřívější zálohy a jejich body obnovy na způsobu nezávisí.

vCenter Server

vCenter Server přidejte jako hostitele: jeho adresu, administrator@vsphere.local (nebo uživatele s rolí Administrator) a proxy agenta. BackupZit pak přes toto jediné připojení vidí VM všech hostitelů ESXi a clusterů datacentra; přes SSH se nic nemění a není potřeba heslo žádného hostitele.

  • VM přesunutý pomocí vMotion na jiného hostitele se dál zálohuje: VM se poznávají podle UUID instance, ne podle hostitele.
  • Při obnově lze zvolit hostitele ESXi, na kterém VM poběží (výchozí: hostitel původního VM), a datastore.
  • Okamžitá obnova spustí VM na zvoleném hostiteli; Dokončit ho přesune na datastore pomocí Storage vMotion za běhu, bez výpadku.
  • vCenter s více datacentry zatím přidat nelze; hostitele ostatních datacenter přidejte přímo.

Nepřidávejte stejného hostitele ESXi přímo a zároveň přes vCenter: každé připojení má vlastní repozitář, takže by se jeho VM zálohovaly dvakrát. Pokud se hostitel, kterého BackupZit zálohuje přímo, později přidá do vCenter, přijměte jeho nový certifikát na stránce Agenti; jeho úlohy dál fungují — vCenter dá VM vytvořeným na samostatném hostiteli nové ID a BackupZit na něj úlohy při příštím obnovení převede.

Úlohy zálohování

V Úlohy zálohování zvolte hostitele ESXi (uvedeného v části Hostitelé VMware ESXi v seznamu agentů) a Virtuální počítače. Zálohujte všechny VM hostitele (VM vytvořené později se zahrnou automaticky) nebo zaškrtněte jednotlivé. Úloha běží na proxy agentovi hostitele. Pokud proxy změníte, existující úlohy ho následují.

Jak se VM zálohuje

  1. Sledování změněných bloků (CBT) se pro VM zapne, pokud je vypnuté.
    • Na licencovaných hostitelích se to děje automaticky.
    • Na bezplatných hostitelích lze CBT zapnout jen při vypnutém VM. BackupZit to udělá při první záloze, která najde VM vypnutý. Do té doby každá záloha čte celé disky a běh ukazuje varování.
  2. Pořídí se snímek backupzit_…. Když v hostovi běží VMware Tools, snímek se uklidní (quiesced): aplikace a souborové systémy se nejdřív vyprázdní, takže záloha je konzistentní na úrovni aplikací. Bez VMware Tools je konzistentní jako při havárii. Do linuxových VM nainstalujte open-vm-tools a do VM s Windows VMware Tools.
  3. CBT hlásí, které bloky číst:
    • při první záloze jen používané bloky;
    • potom jen bloky změněné od předchozí zálohy.
  4. Běžící VM drží své disky zamčené. Jeho disky se proto zkopírují na datastoru (thin) a snímek se hned odstraní, obvykle po několika sekundách. Kopie se pak přečte přes HTTPS a smaže. Vypnuté VM se čtou přímo.
  5. Konfigurace VM (.vmx) a NVRAM se uloží se zálohou.

Příklad z testovací laboratoře: VM s Debianem a diskem 8 GB, z toho 1,6 GB použito. První záloha přečetla 1,6 GB. Další, po 50 MB nových dat, přečetla 70 MB a trvala 23 sekund.

Obnova VM

Použijte průvodce obnovou (Celý virtuální počítač) nebo stránku zálohy v Aktivita. Zvolte:

  • Jako nový VM vedle originálu: kopie s novým názvem, UUID a MAC adresami. Výchozí název je název originálu plus -restored- a datum. Síťová nastavení hosta vázaná na staré MAC adresy, například netplan match: macaddress v cloudových obrazech, se na kopii nevztahují.
  • Místo původního VM: s volbou vypnout ho a nahradit jeho disky BackupZit:
    • vypne VM a smaže jeho snímky;
    • přejmenuje současné disky na ….replaced-DATE.vmdk (smažte je, jakmile obnovený VM funguje);
    • zapíše zálohu do nových disků s původními názvy a nastaví CPU a paměť jako v záloze.
    VM si ponechá UUID, síťové adaptéry a MAC adresy. Pokud byl VM smazán, vytvoří se znovu s původní identitou.
  • Hostitel ESXi a datastore: jiný hostitel, nebo jiný datastore stejného hostitele.
  • Po obnově spustit VM.

Disky se obnovují jako thin a zapisují se jen bloky s daty. ISO obrazy připojené k jednotkám CD/DVD nejsou součástí zálohy, takže tyto jednotky zůstanou prázdné.

Okamžitá obnova

Zvolte Okamžitě, běží ze zálohy a VM se spustí během několika sekund, aniž by se nejdřív kopírovaly jeho disky. Proxy agent hostitele — musí to být agent pro Linux — poskytuje disky VM přímo ze zálohy přes NFS; hostitel to připojí jako datastore backupzit-<agent> a spustí z něj VM. Změny, které VM provede, se ukládají na agentovi (/var/lib/backupzit/instant-esxi, takže pro ně potřebuje volné místo); samotná záloha se nikdy nemění a uchovávání ji drží, dokud z ní VM běží. Pokud původní VM stále existuje, okamžitý VM dostane nové UUID a nové MAC adresy.

Na stránce běhu, když VM funguje, jak má:

  • Dokončit ho zkopíruje na datastore hostitele: VM se vypne (přes VMware Tools, pokud běží), jeho disky se zkopírují jako thin (přes API na licencovaných hostitelích, pomocí vmkfstools přes SSH u bezplatné licence), zaregistruje se z datastoru a znovu spustí. Samostatný hostitel nemá Storage vMotion, takže je potřeba krátký výpadek, který roste s velikostí disků. Pokud kopírování selže, VM dál běží ze zálohy.
  • Zahodit zastaví a smaže VM se všemi jeho změnami.

Agent odpovídá na NFS na portu 2049 (a registruje ho v rpcbind počítače na portu 111, nebo sám odpovídá na portu 111) jen pro adresu hostitele ESXi; pokud je mezi nimi firewall, otevřete tyto porty od hostitele k agentovi. Když se poslední okamžitý VM dokončí nebo zahodí, datastore se odstraní a server NFS se zastaví.

Jednotlivé soubory

Procházet soubory na stránce zálohy (nebo Soubory z virtuálního počítače v průvodci obnovou) otevře disky VM. Procházet lze NTFS, ext2/3/4 a XFS, i na LVM, a soubory stáhnout nebo obnovit na libovolného agenta.

Příkazový řádek

Tyto příkazy běží na libovolném agentovi. Heslo ESXi nastavte v BACKUPZIT_VMWARE_PASSWORD:

backupzit-agent vmware list    --host 192.168.1.20 [--user root]
backupzit-agent vmware backup  --host … --repo … [--vmid N,N]
backupzit-agent vmware restore --host … --repo … --vmid N [--new] [--name NAME] [--datastore DS] [--overwrite] [--start] SNAPSHOT|latest

vmware list ukazuje otisky certifikátu a SSH klíče hostitele. Předejte je pomocí --thumbprint a --ssh-host-key, abyste je připnuli i na příkazovém řádku.

Zatím nezahrnuto

  • vCenter s více datacentry. Přidat lze jen vCenter s jedním datacentrem; hostitele ostatních přidejte přímo.
  • VM s vlastními snímky. Jejich disky jsou delty; snímky nejdřív smažte nebo konsolidujte.
  • Některé typy disků. Raw device mapping (RDM) a nezávislé disky.
  • Okamžitá obnova přes proxy agenta pro Windows. Okamžitá obnova potřebuje proxy agenta pro Linux.
