Cíle úložiště

Cíl úložiště je místo, kam agenti zapisují své zálohy. Každý agent používá vlastní repozitář pod umístěním cíle.

Výběr typu úložiště

Pravidlo 3-2-1: mějte 3 kopie dat na 2 různých médiích, z toho 1 mimo pracoviště — například jednu úlohu na místní NAS a druhou do S3 nebo na zabezpečené úložiště v jiné budově.

Test připojení

Při přidání cíle úložiště jej konzole hned otestuje se zadanými přihlašovacími údaji: zapíše malý soubor, přečte ho zpět a odstraní. Na neměnném úložišti (S3 s Object Lock, zabezpečené úložiště) se jen přihlásí a vypíše obsah, aby nezůstalo nic uzamčeného; u S3 také ověří, že bucket má Object Lock, pokud je požadována neměnnost. Cíl se uloží v každém případě a výsledek se zobrazí — špatné heslo, hostitelský klíč, bucket nebo sdílená složka se ukáže hned, ne až při první záloze. Otestovat připojení na stránce Úložiště test zopakuje. Konzole testuje ze své sítě; zálohy zapisují agenti, takže cíl dostupný jen agentům (místní disk nebo USB) otestuje první záloha.

SFTP

Umístění: sftp://user@host:22/path (pro cestu relativní k domovskému adresáři uživatele použijte /~/path). Zadejte heslo nebo soukromý klíč a otisk hostitelského klíče serveru, který na serveru získáte příkazem:

ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub

Vytvořte vyhrazeného uživatele, který smí zapisovat jen do složky záloh.

Kompatibilní s S3

Zadejte koncový bod (např. s3.eu-central-1.amazonaws.com, s3.wasabisys.com, 10.0.0.5:9000), bucket, volitelnou složku a přístupový klíč s právy čtení/zápisu do tohoto bucketu. Nešifrované HTTP zaškrtněte jen pro místní MinIO bez certifikátu.

Neměnné zálohy (Object Lock)

Vytvořte bucket se zapnutým Object Lock a zaškrtněte Neměnné zálohy … na N dní. Každý soubor, který agenti zapíší, se uzamkne v režimu compliance na N dní (+1 den rezerva): nikdo — ani útočník s klíči, ani vlastník bucketu — jej předtím nesmaže ani nepřepíše. Po každé záloze se prodlouží zámek dat znovu použitých ze starších záloh, takže každý bod obnovy je chráněn po celou dobu.

Smazání (uchováváním nebo útočníkem) jen přidá „značku smazání“. Přidejte pravidlo životního cyklu, které nechá neaktuální verze vypršet po jednom dni, aby se místo uvolnilo, jakmile zámky skončí. Viz Ochrana proti ransomwaru.

Google Cloud Storage

Google Cloud Storage funguje jako cíl kompatibilní s S3 přes své API pro interoperabilitu:

  1. V konzoli Google Cloud otevřete Cloud Storage → Settings → Interoperability a vytvořte klíč HMAC pro servisní účet s rolí Storage Object Admin na bucketu.
  2. Přidejte cíl S3 s koncovým bodem storage.googleapis.com, názvem bucketu, přístupovým klíčem a tajným klíčem HMAC a oblastí auto.

Volba S3 Object Lock není v Google Cloud Storage dostupná; pro neměnnost nastavte v Google Cloud zásadu uchovávání bucketu (a uzamkněte ji). Smazané zálohy pak zůstanou až do konce doby uchovávání.

Azure Blob Storage

  1. Na portálu Azure vytvořte účet úložiště (StorageV2, libovolná redundance) a kontejner, např. backups.
  2. Přidejte cíl Azure Blob Storage s názvem účtu, kontejnerem a volitelnou složkou.
  3. Ověřte se přístupovým klíčem (Účet úložiště → Přístupové klíče) nebo, s užšími právy, tokenem SAS pro kontejner s oprávněním ke čtení, zápisu, mazání a výpisu a vhodnou platností.

Pro ochranu proti ransomwaru zapněte na kontejneru neměnnost na úrovni verzí s časovou zásadou uchovávání; smazané nebo přepsané zálohy pak zůstanou po tuto dobu obnovitelné. Pole koncového bodu v části Pokročilé je potřeba jen pro Azure Government/China, Azure Stack Hub nebo emulátor Azurite.

Rotující disky USB

Disky, které se odpojují a odvážejí mimo pracoviště, jsou pro malé kanceláře nejjednodušší ochranou proti ransomwaru, požáru a krádeži. BackupZit najde disk podle jmenovky svazku, ať mu Windows přidělí jakékoli písmeno:

  1. Naformátujte dva nebo více disků na NTFS (Linux: ext4) a pojmenujte je BZBACKUP1, BZBACKUP2, … (Windows: pravé tlačítko na jednotce → Vlastnosti → název).
  2. Přidejte cíl úložiště typu Rotující disky USB / vyměnitelné disky se jmenovkou BZBACKUP*.
  3. Vytvořte do něj úlohu zálohování — nebo lépe úlohu kopie zálohy, která zkopíruje úlohu z NAS nebo cloudu na disk.
  4. Disky pravidelně střídejte (např. jednou týdně) a odpojený uchovávejte na bezpečném místě.
  • Každý disk obsahuje úplnou, nezávislou zálohu s vlastním uchováváním; všechny disky jsou šifrovány klíčem pro obnovení daného cíle.
  • Běh ukazuje, který disk byl použit (Disk BZBACKUP2). Obnova si vyžádá přesně tento disk a řekne vám, který je připojen.
  • Pokud není připojen žádný disk, běh selže s jasnou zprávou a upozorněním — připomínkou, abyste disk znovu připojili.
  • Připojujte vždy jen jeden z disků.

Sdílená složka SMB

Server, sdílená složka, volitelná složka, uživatel, heslo a (u doménových účtů) doména. Agenti se s těmito údaji připojují sami, takže to funguje i pro služby běžící jako SYSTEM.

Zabezpečené úložiště

Nainstalujte balíček backupzit-repo na vyhrazený linuxový server a pak na tomto serveru spusťte:

backupzit-repo add-key office-console     # shows the access key once
backupzit-repo fingerprint                # certificate fingerprint

Do konzole zadejte adresu serveru, přístupový klíč a otisk. Doba neměnnosti se nastavuje na serveru repozitáře (/etc/backupzit-repo/repo.env) a z konzole ani z agentů ji nelze změnit. Podrobnosti v Ochrana proti ransomwaru.

Šifrování a klíč pro obnovení

Se zapnutým Šifrovat zálohy (výchozí) se vše v repozitáři — obsah a názvy souborů, struktura složek, seznamy snímků — zašifruje pomocí AES-256-GCM dřív, než opustí agenta. Poskytovatel úložiště vidí jen náhodná data.

Když vytvoříte šifrovaný cíl, konzole zobrazí klíč pro obnovení a nabídne ke stažení list pro obnovu.

List pro obnovu vytiskněte nebo uložte do správce hesel, odděleně od záloh. Pokud o konzoli přijdete, k obnově stačí klíč pro obnovení plus umístění a přihlašovací údaje úložiště. Bez klíče šifrované zálohy nikdo nepřečte — ani podpora BackupZit.

Klíč můžete později znovu zobrazit tlačítkem Klíč obnovy v seznamu úložišť; zaznamená se to.

Seznam úložišť

Seznam ukazuje u každého cíle typ, umístění, šifrování (s přístupem ke klíči pro obnovení pro správce) a neměnnost: dobu Object Lock u S3, nebo nastaveno na serveru repozitáře u zabezpečených úložišť. Přihlašovací údaje se po uložení už nikdy nezobrazí a ukládají se šifrovaně. Cíle může přidávat a odebírat a klíče pro obnovení vidět jen správce.

Využití úložiště a prognóza

Po každé záloze (a jejím uchovávání) agent hlásí, kolik místa zabírá jeho repozitář, a — u místních disků a USB, serverů SFTP (rozšíření statvfs OpenSSH) a sdílených složek SMB — velikost a volné místo úložiště. V části Úložiště → Využití úložiště každý cíl ukazuje:

  • místo zabrané všemi repozitáři na něm (jeden na agenta; u rotujících disků USB se počítá každý disk);
  • u úložiště se známou velikostí, jak je zaplněné (žlutě od 75 %, červeně od 90 %), s kapacitou jako červenou přerušovanou čárou v grafu;
  • graf posledních 90 dní a po týdnu záloh denní růst (lineární trend posledních 30 dní), vykreslený 30 dní dopředu přerušovanou čárou, a kdy se úložiště zaplní — nebo, bez známé velikosti, očekávané využití za 90 dní.

Vyžaduje pozornost na řídicím panelu varuje, když je cíl úložiště zaplněn z 90 % nebo se zaplní do 30 dní. S3 a Azure nemají pevnou velikost; tam se zobrazuje jen využité místo a jeho růst. Využité místo jsou uložená (komprimovaná, šifrovaná, deduplikovaná) data; soubory, které úložiště drží z jiných důvodů (verze objektů, jiné programy), se nezapočítávají.

Odebrání cíle

Odebrání cíle úložiště z konzole nesmaže na úložišti žádná data. Se zapnutým schválením čtyř očí to musí nejprve schválit druhý uživatel.
