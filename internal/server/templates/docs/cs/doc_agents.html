Agenti

Na každý chráněný počítač se instaluje agent. Běží jako služba, každých 30 sekund se ptá konzole na práci a komunikuje přímo s úložištěm.

Podporované systémy

  • Windows 10, 11 a Windows Server 2016 a novější — MSI Agent pro Windows.
  • Windows 7 SP1, Windows Server 2008 R2 SP1 a 2012 R2 — MSI Agent pro Windows — starší systémy (…-legacy.msi), se stejnými funkcemi včetně VSS a obrazů disků.
  • Debian, Ubuntu, AlmaLinux, Rocky Linux (64bitové).
  • Uzly Proxmox VE 7 a 8 — balíček pro Debian; agent pak zálohuje i VM a kontejnery uzlu (viz Proxmox VE).
  • Hostitelé Hyper-V (Windows Server 2016 a novější, Windows 10/11 s Hyper-V): MSI pro Windows. Agent pak zálohuje i VM hostitele (viz Hyper-V).
  • Hostitelé VMware ESXi — na ESXi se nic neinstaluje: přidejte hostitele v části Hostitelé VMware ESXi a zvolte agenta jako proxy (viz VMware ESXi).

Registrace agentů

  1. Na stránce Agenti klikněte na Vytvořit registrační token. Konzole zobrazí registrační kód (BZ1-…), platný 7 dní a použitelný pro libovolný počet počítačů. Obsahuje adresu konzole pro agenty (s portem agentů, obvykle 8443, i když je stránka otevřená na webovém portu 443), token a otisk certifikátu. Agenti od 0.33.6 se registrují i kódy, které starší konzole vytvořily na webovém portu.
  2. Windows: spusťte MSI a vložte kód, když o něj instalátor požádá. Linux: spusťte zobrazený příkaz.
  3. Počítač se do minuty objeví v seznamu agentů.

Pokud konzole během instalace není dostupná, agent si kód ponechá a zkouší to znovu, dokud se nezaregistruje. Upgrady registraci zachovávají a znovu se neptají. Tichá instalace s ENROLLCODE na již registrovaném počítači registraci zachová, když je kód pro stejnou konzoli (GPO nebo RMM ji mohou bezpečně opakovat), a přesune počítač, když je kód pro jinou konzoli; předchozí registrace se uchová jako agent.json.replaced-datum vedle agent.json, takže jejím přejmenováním zpět se počítač vrátí ke staré konzoli jako tentýž agent.

Windows, tiše (GPO, Intune, RMM)

msiexec /i backupzit-agent.msi /qn ENROLLCODE="BZ1-..."

Starší forma SERVER="..." TOKEN="..." FINGERPRINT="SHA256:..." stále funguje. Tichá instalace bez těchto vlastností nainstaluje službu, která čeká, dokud ji nezaregistrujete příkazem backupzit-agent enroll --code "BZ1-..." v příkazovém řádku správce.

Linux

apt install ./backupzit-agent_*.deb        # or: dnf install ./backupzit-agent-*.rpm
backupzit-agent enroll --code "BZ1-..."
systemctl enable --now backupzit-agent

Instalace agentů z konzole

Místo kopírování instalátorů na každý počítač nechte agenta nainstalovat konzoli: na stránce Agenti otevřete Nainstalovat na počítač odsud, zvolte Linux nebo Windows a zadejte adresu počítače a účet správce.

  • Linux (Debian, Ubuntu, AlmaLinux, Rocky Linux; 64bitové): konzole se připojí přes SSH jako root nebo jako uživatel s právy sudo (heslo se použije i pro sudo; s klíčem je nutné sudo bez hesla). Funguje heslo i soukromý klíč. Zadejte otisk hostitelského klíče SSH počítače (ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub na počítači), aby bylo jisté, že konzole mluví se správným počítačem; bez něj se otisk zobrazí v protokolu instalace.
  • Windows (64bitové): konzole se připojí přes WinRM (port 5985, zprávy šifrované pomocí NTLM; 5986 pro naslouchací proces HTTPS) jako místní nebo doménový správce. WinRM je ve Windows Serveru ve výchozím stavu zapnutý; ve Windows 10/11 spusťte jednou winrm quickconfig jako správce. Jiné místní účty než vestavěný Administrator potřebují práva vzdálené správy (LocalAccountTokenFilterPolicy) — nebo použijte doménový účet. Starší systémy (Windows 7, Server 2008 R2/2012 R2) dostanou legacy MSI.

Počítač stáhne nejnovější balíček agenta z konzole přes odkaz, který platí jen pro tuto instalaci (30 minut, tři stažení), ověří jeho kontrolní součet SHA-256, nainstaluje ho a zaregistruje se. Stránka instalace ukazuje každý krok; účet a heslo se použijí jen k tomu a neukládají se. Pokud je počítač u této konzole už registrován, registrace se zachová a balíček se aktualizuje; registrace, kterou konzole nezná (dříve odebraný agent nebo jiná konzole), se nahradí. Každá instalace je v protokolu auditu. Počítač musí dosáhnout na adresu konzole pro agenty, jako každý agent.

Stav agenta

  • online — agent kontaktoval konzoli během posledních 3 minut.
  • offline — počítač je vypnutý, služba zastavená nebo síť blokovaná. Plánované zálohy se zařadí do fronty a spustí se, jakmile se agent vrátí.
  • obnova — počítač spuštěný z ISO pro obnovu (Windows nebo Linux), připravený přijmout obnovu obrazu disku nebo systému Linux. Agenti obnovy jsou dočasní; po dokončení obnovy je odeberte.

Sloupec IP adresy uvádí vlastní adresy počítače, jak je agent naposledy nahlásil. viděn z je adresa, ze které přicházejí jeho spojení: v místní síti stejná adresa, u počítače za NAT (např. notebooku doma) veřejná adresa routeru. Konzole se kvůli tomu neptá žádné externí služby.

Agent na ploše (Windows)

Agent pro Windows zobrazuje ikonu vedle hodin (může být pod šipkou ^ skrytých ikon — přetáhněte ji na hlavní panel, aby zůstala vidět). Tečka na ikoně ukazuje stav:

TečkaVýznam
zelenáZálohy jsou v pořádku (nebo čekají na první plánovanou zálohu).
modráProbíhá záloha, obnova nebo test obnovy.
oranžováPoslední záloha skončila s varováními (soubory, které nešlo přečíst).
červenáÚloha zálohování selhala.
šedáKonzole není dostupná nebo služba agenta neběží.

Klikněte na ikonu (nebo otevřete BackupZit Agent z nabídky Start) pro okno stavu: stav ochrany, průběh běžící zálohy, poslední a příští záloha a všechny úlohy zálohování počítače s tlačítkem Zálohovat nyní. Pravé tlačítko otevře nabídku: Back up now pro každou úlohu, Open console in browser, Hide this icon (do příštího přihlášení; zálohy pokračují). Okno potřebuje Microsoft Edge WebView2, který je součástí Windows 10 a 11; na starších systémech ikona a nabídka fungují a Open zobrazí konzoli v prohlížeči.

Uživatelé tak mohou spustit zálohu svého počítače; úlohy, plány a uchovávání se nastavují jen v konzoli. Na každém systému vypíše backupzit-agent status (jako správce nebo root) stejné informace.

Aktualizace

Když má konzole novější instalátor agenta, než na jakém agent běží, stránka Agenti zobrazí Aktualizovat na x.y.z vedle jeho verze a Aktualizovat všechny agenty pod seznamem. Agent pak:

  1. počká, až bude nečinný (běžící záloha se nikdy nepřeruší),
  2. stáhne odpovídající instalátor z konzole přes své připnuté spojení — MSI pro Windows 10/11/2016+, MSI starší systémy pro Windows 7/2008 R2/2012 R2, balíček deb nebo rpm v Linuxu — a ověří jeho SHA-256,
  3. nainstaluje ho a restartuje se; nová verze se objeví v seznamu během několika minut. Registrace i všechna nastavení se zachovají.

Konzole nabízí nejnovější instalátory ze svého adresáře dist; balíček serveru obsahuje instalátory agentů své vlastní verze. Po aktualizaci konzole v Nastavení → Aktualizace se agenti aktualizují automaticky (lze tam vypnout). Aktualizace z konzole fungují pro agenty od verze 0.21; starší agenti se jednou aktualizují instalací novějšího MSI / balíčku přes starý (registrace se zachová). Protokol instalátoru je v C:\ProgramData\backupzit\updates nebo /var/tmp/backupzit-updates.

Odebrání agenta

Odebrat na stránce Agenti smaže agenta a jeho úlohy z konzole. Se zapnutým schválením čtyř očí to musí nejprve schválit druhý uživatel. Zálohy na úložišti se nemažou. Software na počítači odinstalujte zvlášť.

Dva počítače používající jednoho agenta

Kopie registrovaného počítače si s sebou nese svého agenta a registraci: VM obnovená jako nová VM, okamžitá obnova, spuštěná replika, klonovaný disk nebo šablona. Když kopie běží vedle originálu, oba se připojují jako tentýž agent. Konzole si toho všimne během minuty či dvou a poté:

  • zobrazí dva počítače s oběma názvy a adresami na stránce Agenti a agenta v části Vyžaduje pozornost na řídicím panelu;
  • pozdrží zálohy a obnovy agenta, aby nic neběželo na špatném počítači (obnova na původní místo by jinak mohla přepsat kopii místo originálu);
  • jednou pošle e-mail správcům a zapíše záznam agent.duplicate do protokolu auditu.

Zastavte kopii nebo — pokud má zůstat — ji na kopii zaregistrujte jako nový počítač: backupzit-agent enroll --force --code "BZ1-..." (kód ze stránky Agenti). Pozdržené běhy se spustí pár minut poté, co zůstane jen jeden počítač. Obnova systému Linux pomocí Obnovit celý systém už v obnovené kopii agenta odregistruje a testy obnovy spouštějí své VM bez sítě, takže ani jedno to nezpůsobí.

Když konzole dostane novou adresu

Agenti důvěřují konzoli podle jejího certifikátu, který zůstává stejný i při změně IP adresy nebo názvu, ale připojují se k adrese, se kterou byli zaregistrováni. Po změně spusťte na každém počítači s agentem (jako správce / root):

backupzit-agent set-server https://192.168.1.20:8443

Příkaz ověří, že konzole na nové adrese odpovídá se stejným certifikátem, uloží ji a agent ji použije po restartu své služby (systemctl restart backupzit-agent, nebo ve Windows restartujte službu BackupZit Agent). Použití názvu DNS pro konzoli od začátku tento krok ušetří.

Kde agent uchovává konfiguraci

  • Windows: C:\ProgramData\backupzit\agent.json (přístupné jen pro SYSTEM a Administrators).
  • Linux: /etc/backupzit/agent.json (jen root).

Soubor obsahuje tajný údaj agenta. Kdo ho může číst, může vystupovat jako tento agent, proto tato oprávnění zachovejte.

Protokol agenta

  • Windows: C:\ProgramData\backupzit\agent.log
  • Linux: /etc/backupzit/agent.log a journalctl -u backupzit-agent
  • Systémy pro obnovu vypisují protokol na obrazovku.

Odinstalace

Windows: Nastavení → Aplikace → BackupZit Agent → Odinstalovat (nebo msiexec /x). Linux: apt remove backupzit-agent / dnf remove backupzit-agent. Pak agenta odeberte v konzoli. Zálohy zůstanou na úložišti.

Ve Windows odinstalace odloží registraci stranou (C:\ProgramData\backupzit\agent.json.removed-datum), takže nová instalace agenta požádá o registrační kód. Pokud instalátor najde registraci starší verze, oznámí to: nechte kód prázdný, chcete-li ji zachovat, nebo vložte nový kód a počítač znovu zaregistrujte (například u jiné konzole).
