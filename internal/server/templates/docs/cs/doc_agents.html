Agenti

Na každý chráněný počítač se instaluje agent. Běží jako služba, každých 30 sekund se ptá konzole na práci a komunikuje přímo s úložištěm.

Podporované systémy

  • Windows 10, 11 a Windows Server 2016 a novější — MSI Agent pro Windows.
  • Windows 7 SP1, Windows Server 2008 R2 SP1 a 2012 R2 — MSI Agent pro Windows — starší systémy (…-legacy.msi), se stejnými funkcemi včetně VSS a obrazů disků.
  • Debian, Ubuntu, AlmaLinux, Rocky Linux (64bitové).
  • Macy s čipem Apple nebo s procesorem Intel, macOS 13 a novější — balíček Agent pro macOS (…_darwin_universal.pkg), pro soubory a složky (viz Agenti pro macOS).
  • Uzly Proxmox VE 7, 8 a 9 — balíček pro Debian; agent pak zálohuje i VM a kontejnery uzlu (viz Proxmox VE).
  • Hostitelé Hyper-V (Windows Server 2016 a novější, Windows 10/11 s Hyper-V): MSI pro Windows. Agent pak zálohuje i VM hostitele (viz Hyper-V).
  • Hostitelé VMware ESXi — na ESXi se nic neinstaluje: přidejte hostitele v části Hostitelé VMware ESXi a zvolte agenta jako proxy (viz VMware ESXi).

Registrace agentů

  1. Na stránce Agenti klikněte na Vytvořit registrační token. Konzole zobrazí registrační kód (BZ1-…), platný 7 dní a použitelný pro libovolný počet počítačů. Obsahuje adresu konzole pro agenty (s portem agentů, obvykle 8443, i když je stránka otevřená na webovém portu 443), token a otisk certifikátu. Agenti od 0.33.6 se registrují i kódy, které starší konzole vytvořily na webovém portu. Kód, který konzole vytvoří pro instalaci ze stránky Agenti, platí jednou a po skončení instalace se odstraní. Odvolat všechny kódy pro registraci odstraní všechny kódy (i ty na médiích pro obnovu), např. když byl některý omylem sdílen; registrovaní agenti dál fungují.
  2. Windows: spusťte MSI a vložte kód, když o něj instalátor požádá. Linux: spusťte zobrazený příkaz. macOS: nainstalujte balíček a vložte kód, když o něj aplikace v řádku nabídek požádá, nebo spusťte zobrazený příkaz v Terminálu (viz Agenti pro macOS).
  3. Počítač se do minuty objeví v seznamu agentů.

Pokud konzole během instalace není dostupná, agent si kód ponechá a zkouší to znovu, dokud se nezaregistruje. Upgrady registraci zachovávají a znovu se neptají. Tichá instalace s ENROLLCODE na již registrovaném počítači registraci zachová, když je kód pro stejnou konzoli (GPO nebo RMM ji mohou bezpečně opakovat), a přesune počítač, když je kód pro jinou konzoli; předchozí registrace se uchová jako agent.json.replaced-datum vedle agent.json, takže jejím přejmenováním zpět se počítač vrátí ke staré konzoli jako tentýž agent.

Windows, tiše (GPO, Intune, RMM)

msiexec /i backupzit-agent.msi /qn ENROLLCODE="BZ1-..."

Starší forma SERVER="..." TOKEN="..." FINGERPRINT="SHA256:..." stále funguje. Tichá instalace bez těchto vlastností nainstaluje službu, která čeká, dokud ji nezaregistrujete příkazem backupzit-agent enroll --code "BZ1-..." v příkazovém řádku správce.

Linux

apt install ./backupzit-agent_*.deb        # or: dnf install ./backupzit-agent-*.rpm
backupzit-agent enroll --code "BZ1-..."
systemctl enable --now backupzit-agent

macOS

sudo /Library/BackupZit/bin/backupzit-agent enroll --code "BZ1-..."

Spusťte ho po instalaci .pkg, nebo vložte kód do aplikace BackupZit v řádku nabídek, která o něj po instalaci požádá (později: Enroll this Mac… v její nabídce). MDM místo toho zapíše kód do /Library/Application Support/BackupZit/enroll-code ještě před instalací balíčku. Plný přístup k disku pak musí udělit uživatel Macu; viz Agenti pro macOS.

Instalace agentů z konzole

Místo kopírování instalátorů na každý počítač nechte agenta nainstalovat konzoli: na stránce Agenti otevřete Nainstalovat na počítač odsud, zvolte Linux nebo Windows a zadejte adresu počítače a účet správce.

  • Linux (Debian, Ubuntu, AlmaLinux, Rocky Linux; 64bitové): konzole se připojí přes SSH jako root nebo jako uživatel s právy sudo, heslem nebo soukromým klíčem (heslová fráze klíče patří do pole Heslová fráze klíče a slouží jen k otevření klíče). Konzole nejprve zkusí sudo bez hesla (sudo -n); heslo mu předá jen tehdy, když o ně sudo požádá — heslo uživatele, nebo Heslo pro sudo, pokud se liší nebo se používá klíč — a heslo nikdy není součástí instalačního skriptu. Hesla a heslové fráze jsou v protokolu instalace skryté. Zadejte otisk hostitelského klíče SSH počítače (ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub na počítači), aby bylo jisté, že konzole mluví se správným počítačem; bez něj se otisk zobrazí v protokolu instalace.
  • Windows (64bitové): konzole se připojí přes WinRM (port 5985, zprávy šifrované pomocí NTLM; 5986 pro naslouchací proces HTTPS) jako místní nebo doménový správce. WinRM je ve Windows Serveru ve výchozím stavu zapnutý; ve Windows 10/11 spusťte jednou winrm quickconfig jako správce. Jiné místní účty než vestavěný Administrator potřebují práva vzdálené správy (LocalAccountTokenFilterPolicy) — nebo použijte doménový účet. Starší systémy (Windows 7, Server 2008 R2/2012 R2) dostanou legacy MSI.

Když formulář neobsahuje otisk klíče hostitele ani certifikátu, konzole nejprve bez přihlášení načte klíč SSH hostitele (Linux) nebo certifikát naslouchacího procesu WinRM HTTPS (Windows, port 5986), ukáže ho a heslo odešle až po vašem potvrzení; instalace pak přijme jen tento klíč nebo certifikát. Porovnejte ho s počítačem (na Linuxu ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub). WinRM přes HTTP (port 5985) nemá certifikát ke kontrole; kde síť mezi konzolí a počítačem není důvěryhodná, použijte naslouchací proces HTTPS.

Macy se odsud neinstalují: nasaďte .pkg ručně nebo přes MDM (Agenti pro macOS).

Počítač stáhne nejnovější balíček agenta z konzole přes odkaz, který platí jen pro tuto instalaci (30 minut, tři stažení), ověří jeho kontrolní součet SHA-256, nainstaluje ho a zaregistruje se. Konzole předtím ověří balíček podle podepsaného seznamu instalačních balíčků agenta svého vydání, stejně jako u aktualizací agentů; na Linuxu čte nový agent registrační kód ze svého vstupu, takže se kód neobjeví v seznamu procesů. Stránka instalace ukazuje každý krok; účet a heslo se použijí jen k tomu a neukládají se. Pokud je počítač u této konzole už registrován, registrace se zachová a balíček se aktualizuje; registrace, kterou konzole nezná (dříve odebraný agent nebo jiná konzole), se nahradí. Každá instalace je v protokolu auditu. Počítač musí dosáhnout na adresu konzole pro agenty, jako každý agent.

Stav agenta

  • online — agent kontaktoval konzoli během posledních 3 minut.
  • offline — počítač je vypnutý, služba zastavená nebo síť blokovaná. Plánované zálohy se zařadí do fronty a spustí se, jakmile se agent vrátí.
  • obnova — počítač spuštěný z ISO pro obnovu (Windows nebo Linux), připravený přijmout obnovu obrazu disku nebo systému Linux. Agenti obnovy jsou dočasní; po dokončení obnovy je odeberte. Jinak se odeberou automaticky týden po posledním spojení.
  • hodiny nesouhlasí — hodiny počítače se od hodin konzole liší o 2 minuty nebo více (agenti 0.44.0 a novější hlásí svůj čas při každém dotazu); upozorní i nástěnka. Zapněte na tomto počítači synchronizaci času: od 15 minut odmítají úložiště S3 a Azure jeho zálohy (viz Řešení problémů). Pokud to ukazují všichni agenti, chybné jsou hodiny samotné konzole.
  • Obnovit způsobí, že agent pošle své disky a VM (Proxmox VE, Hyper-V) při příštím dotazu, například po přidání úložiště nebo hosta na hostiteli. Jinak je agenti posílají každých 15 minut, když nic nedělají, a po každém běhu s VM (agenti 0.54.1 a novější).
  • žádná úloha zálohování — tento počítač nezálohuje žádná zapnutá úloha (jako jeho agent ani jako proxy úlohy VMware), počítáno hodinu po registraci; přehled tyto agenty uvádí v části Vyžaduje pozornost. Přidejte počítač do úlohy, např. do úlohy pro více agentů.

Sloupec IP adresy uvádí vlastní adresy počítače, jak je agent naposledy nahlásil. viděn z je adresa, ze které přicházejí jeho spojení: v místní síti stejná adresa, u počítače za NAT (např. notebooku doma) veřejná adresa routeru. Konzole se kvůli tomu neptá žádné externí služby.

Názvy a štítky

Servery různých zákazníků nebo poboček mají často stejný název hostitele. Klikněte na agenta na stránce Agenti a dejte mu název zobrazený v konzoli a štítky — volné popisky, např. zákazník nebo pobočka, oddělené čárkami. Název se používá ve formulářích úloh, při obnově, v Aktivitě, v reportech a e-mailech; název hostitele hlášený počítačem zůstává vidět vedle něj a stránka agenta upozorní, když jiní agenti hlásí stejný název hostitele. Kliknutím na štítek zobrazíte jen agenty, kteří ho mají.

Přejmenování mění jen to, co ukazuje konzole: agent, jeho repozitář a zálohy zůstávají beze změny a počítač nemůže změnit svůj název ani štítky. Jejich změna vyžaduje oprávnění pro agenty a zaznamená se do protokolu auditu. Štítky pomáhají agenty najít; nedávají ani neomezují přístup a nepřidávají agenty do úloh. Každý, kdo se může přihlásit do konzole, vidí všechny agenty a konzole drží klíče všech jejich záloh — zákazníci, kteří musí být striktně odděleni, potřebují každý vlastní konzoli.

Agent na ploše (Windows)

Agent pro Windows zobrazuje ikonu vedle hodin (může být pod šipkou ^ skrytých ikon — přetáhněte ji na hlavní panel, aby zůstala vidět). Tečka na ikoně ukazuje stav:

TečkaVýznam
zelenáZálohy jsou v pořádku (nebo čekají na první plánovanou zálohu).
modráProbíhá záloha, obnova nebo test obnovy.
oranžováPoslední záloha skončila s varováními (soubory, které nešlo přečíst).
červenáÚloha zálohování selhala.
šedáKonzole není dostupná nebo služba agenta neběží.

Klikněte na ikonu (nebo otevřete BackupZit Agent z nabídky Start) pro okno stavu: stav ochrany, průběh běžící zálohy, poslední a příští záloha a všechny úlohy zálohování počítače s tlačítkem Zálohovat nyní. Pravé tlačítko otevře nabídku: Back up now pro každou úlohu, Open console in browser, Hide this icon (do příštího přihlášení; zálohy pokračují). Okno potřebuje Microsoft Edge WebView2, který je součástí Windows 10 a 11; na starších systémech ikona a nabídka fungují a Open zobrazí konzoli v prohlížeči. Open console in browser otevře webovou adresu konzole, i když port 8443 slouží jen agentům (agent i konzole 0.61 a novější).

Na Macu dělá totéž aplikace v řádku nabídek a navíc kontroluje oprávnění, o která macOS uživatele žádá (viz Agenti pro macOS).

Uživatelé tak mohou spustit zálohu svého počítače; úlohy, plány a uchovávání se nastavují jen v konzoli. Na každém systému vypíše backupzit-agent status (jako správce nebo root) stejné informace.

Více úloh současně

Agent ve výchozím stavu spouští jednu úlohu najednou; ostatní čekají ve frontě. Ve sloupci Úloh současně na stránce Agenti můžete povolit až 8 — užitečné pro agenty, kteří zálohují více věcí, například proxy agenta pro ESXi, Proxmox, Microsoft 365 nebo sdílené složky NAS. Dva běhy stejné úlohy nikdy neběží současně a aktualizace agenta čekají, až bude volný. Souběžné běhy sdílejí procesor, disky a síť počítače; zvyšujte počet postupně. Ve Windows se snímky VSS vytvářejí jeden po druhém. Vyžaduje agenty 0.39.0 nebo novější.

Aktualizace

Když má konzole novější instalátor agenta, než na jakém agent běží, stránka Agenti zobrazí Aktualizovat na x.y.z vedle jeho verze a Aktualizovat všechny agenty pod seznamem. Agent pak:

  1. počká, až bude nečinný (běžící záloha se nikdy nepřeruší),
  2. stáhne odpovídající instalátor z konzole přes své připnuté spojení — MSI pro Windows 10/11/2016+, MSI starší systémy pro Windows 7/2008 R2/2012 R2, balíček deb nebo rpm v Linuxu, .pkg na Macu — a ověří ho: od 0.56 musí být instalátor v seznamu instalátorů agenta podepsaném klíčem vydání BackupZit, který agent ověří klíčem zabudovaným v sobě, takže instalátor změněný na konzoli odmítne,
  3. nainstaluje ho a restartuje se; nová verze se objeví v seznamu během několika minut. Registrace i všechna nastavení se zachovají.

Konzole nabízí nejnovější instalátory ze svého adresáře dist; balíček serveru obsahuje instalátory agentů své vlastní verze. Po aktualizaci konzole v Nastavení → Aktualizace se agenti aktualizují automaticky (lze tam vypnout). Aktualizace z konzole fungují pro agenty od verze 0.21; starší agenti se jednou aktualizují instalací novějšího MSI / balíčku přes starý (registrace se zachová). Agenti 0.56 a novější přijmou aktualizaci jen od konzole 0.56 nebo novější (její balíček nese podepsaný seznam) a nikdy ne na starší verzi, než je jejich vlastní. Protokol instalátoru je v C:\ProgramData\backupzit\updates, /var/lib/backupzit-agent/updates nebo na Macu v /Library/Application Support/BackupZit/updates. Aktualizace agenta na Macu, jehož balíček není podepsaný identifikátorem Apple Developer ID, mu odebere plný přístup k disku (viz Agenti pro macOS).

Odebrání agenta

Odebrat na stránce Agenti otevře stránku se dvěma volbami; se zapnutým schvalováním čtyř očí musí nejprve schválit druhý uživatel.

  • Odinstalovat agenta z počítače (online agenti od verze 0.42.7): agent se ohlásí, sám se odinstaluje a poté se odebere z konzole i se svými úlohami. Offline agent se odebere jen z konzole — odinstalujte ho na počítači (viz níže).
  • Jeho zálohy: ponechat všechny (výchozí — zůstanou na úložišti a lze je dál obnovit), ponechat jen nejnovější zálohu každé úlohy (každá záloha je úplná, takže nejnovější obnoví vše k svému datu) nebo smazat všechny. Pro smazání je nutné zadat název počítače; konzole maže na pozadí a zapíše výsledek do protokolu auditu. Neměnné úložiště uchovává uzamčená data do vypršení zámku; zálohy na disku samotného počítače a kopie úloh kopírování se nemažou. Agent, který zálohuje jiné systémy (Proxmox, VMware, Hyper-V, Microsoft 365, NAS), vezme jejich zálohy s sebou. Smazání je odmítnuto, dokud je uchovávání některé úlohy v těchto repozitářích pozastaveno po podezřelé záloze nebo dokud z některé jejich zálohy běží VM (okamžitá obnova). Další agenti proxy připojení vCenter ukládají své části do repozitáře připojení: odebrání vlastního agenta proxy připojení s jeho zálohami smaže stejně i jejich a stránka je spočítá a vyjmenuje.

Mazání záloh vyžaduje také vaše heslo — nebo aktuální kód z ověřovací aplikace, když je zapnuté dvoufázové přihlášení —, aby ukradená relace prohlížeče sama nestačila k jejich smazání. Druhý uživatel, který odebrání schvaluje, potvrzuje stejně. Uživatelé přihlašující se přes SSO k tomu potřebují dvoufázové přihlášení.

Ponechané zálohy zůstávají v Aktivitě (označené jako odebrán) a v průvodci obnovou a lze je obnovit na libovolného jiného agenta. Stránka Agenti uvádí odebrané agenty s ponechanými zálohami: Smazat zálohy je smaže později (ponechat nejnovější z každé úlohy, nebo vše). Když počítač znovu dostane agenta, Připojit k aktuálnímu agentovi je přesune k novému agentovi se stejným názvem: ten je zobrazí a jeho úlohy pokračují ve stejných repozitářích s deduplikací vůči starým zálohám. Agent, který už má vlastní zálohy, převezme jen historii; jeho úlohy si ponechají své repozitáře. Zálohy nalezené na úložišti (viz Vyhledání záloh na úložišti) se zobrazují a připojují stejně.

Dva počítače používající jednoho agenta

Kopie registrovaného počítače si s sebou nese svého agenta a registraci: VM obnovená jako nová VM, okamžitá obnova, spuštěná replika, klonovaný disk nebo šablona. Když kopie běží vedle originálu, oba se připojují jako tentýž agent. Konzole si toho všimne během minuty či dvou a poté:

  • zobrazí dva počítače s oběma názvy a adresami na stránce Agenti a agenta v části Vyžaduje pozornost na řídicím panelu;
  • pozdrží zálohy a obnovy agenta, aby nic neběželo na špatném počítači (obnova na původní místo by jinak mohla přepsat kopii místo originálu);
  • jednou pošle e-mail správcům a zapíše záznam agent.duplicate do protokolu auditu.

Zastavte kopii nebo — pokud má zůstat — ji na kopii zaregistrujte jako nový počítač: backupzit-agent enroll --force --code "BZ1-..." (kód ze stránky Agenti). Pozdržené běhy se spustí pár minut poté, co zůstane jen jeden počítač. Obnova systému Linux pomocí Obnovit celý systém už v obnovené kopii agenta odregistruje a testy obnovy spouštějí své VM bez sítě, takže ani jedno to nezpůsobí.

Když konzole dostane novou adresu

Agenti důvěřují konzoli podle jejího certifikátu, který zůstává stejný i při změně IP adresy nebo názvu, ale připojují se k adrese, se kterou byli zaregistrováni. Po změně spusťte na každém počítači s agentem (jako správce / root):

backupzit-agent set-server https://192.168.1.20:8443

Příkaz ověří, že konzole na nové adrese odpovídá se stejným certifikátem, uloží ji a agent ji použije po restartu své služby (systemctl restart backupzit-agent, nebo ve Windows restartujte službu BackupZit Agent). Použití názvu DNS pro konzoli od začátku tento krok ušetří.

Kde agent uchovává konfiguraci

  • Windows: C:\ProgramData\backupzit\agent.json (přístupné jen pro SYSTEM a Administrators). Agent složku použije, jen když je to skutečná složka, jejímž vlastníkem je SYSTEM nebo Administrators: složku, kterou před instalací vytvořil jiný uživatel, nebo odkaz (junction) na jinou složku odloží nepřečtenou stranou jako C:\ProgramData\backupzit.untrusted-datum a spustí se neregistrovaný (agenti 0.63 a novější).
  • Linux: /etc/backupzit/agent.json (jen root).
  • macOS: /Library/Application Support/BackupZit/agent.json (jen root).

Soubor obsahuje tajný údaj agenta. Kdo ho může číst, může vystupovat jako tento agent, proto tato oprávnění zachovejte.

Protokol agenta

  • Windows: C:\ProgramData\backupzit\agent.log
  • Linux: /var/log/backupzit/agent.log a journalctl -u backupzit-agent
  • macOS: /Library/Logs/BackupZit/agent.log
  • Systémy pro obnovu vypisují protokol na obrazovku.
  • Protokol uchovává až 4 soubory po 10 MB (agent.log a agent.log.1 až .3); starší záznamy se mažou.
  • Získat protokol na stránce Agenti přenese konec protokolu do konzole — viz Protokoly.

Odinstalace

Windows: Nastavení → Aplikace → BackupZit Agent → Odinstalovat (nebo msiexec /x). Linux: apt remove backupzit-agent / dnf remove backupzit-agent. macOS: sudo /Library/BackupZit/uninstall.sh (viz Agenti pro macOS). Pak agenta odeberte v konzoli. Zálohy zůstanou na úložišti.

Ve Windows odinstalace odloží registraci stranou (C:\ProgramData\backupzit\agent.json.removed-datum), takže nová instalace agenta požádá o registrační kód. Pokud instalátor najde registraci starší verze, oznámí to: nechte kód prázdný, chcete-li ji zachovat, nebo vložte nový kód a počítač znovu zaregistrujte (například u jiné konzole).
