Virtuální počítače Hyper-V

BackupZit zálohuje virtuální počítače Hyper-V přes agenta na hostiteli Hyper-V; do VM se nic neinstaluje. Hosté s Windows i Linuxem se zachytí za běhu. Obnovit je můžete jako nový VM nebo místo originálu.

Nastavení

  1. Nainstalujte MSI Agent pro Windows z Agenti na hostitele Hyper-V a zaregistrujte ho. Podporovaní hostitelé: Windows Server 2016 nebo novější s rolí Hyper-V, nebo Windows 10/11 s Hyper-V. V clusteru nainstalujte agenta na každého hostitele.
  2. Do minuty se hostitel objeví na stránce Agenti se štítkem Hyper-V · N VMs.
  3. V Úlohy zálohování vyberte tohoto agenta a zvolte Virtuální počítače (Proxmox VE, Hyper-V, VMware). Pak zvolte:
    • všechny VM hostitele, což zahrnuje i později vytvořené VM;
    • jednotlivé VM jejich zaškrtnutím.

Agent pracuje přes vlastní rozhraní Hyper-V: modul PowerShell pro Hyper-V a rozhraní Windows Virtual Disk API. Konzole neukládá žádné přihlašovací údaje k Hyper-V.

Jak se VM zálohuje

  1. Vytvoří se dočasný kontrolní bod pro obnovu (backupzit_…). To je typ kontrolního bodu, který Hyper-V poskytuje zálohovacím aplikacím. Hyper-V požádá hosta, aby se připravil:
    • Hosté s Windows vyprázdní vyrovnávací paměti aplikací přes VSS.
    • Hosté s Linuxem zmrazí své souborové systémy, pokud jsou nainstalovaní démoni Hyper-V (hyperv-daemons / hv-vss-daemon).
    Pokud host nezvládne ani jedno, kontrolní bod se pořídí v konzistenci jako při havárii (crash-consistent). Stránka běhu ukazuje, který druh byl použit.
  2. Kontrolní bod pro obnovu zapne pro disky VM Resilient Change Tracking (RCT); vedle nich uvidíte soubory .rct a .mrt. První záloha čte celé disky. Potom RCT hlásí, které bloky se od předchozí zálohy změnily, a čtou se jen ty.
  3. Disky se čtou ve stavu kontrolního bodu přes Virtual Disk API v blocích po 1 MiB. To zahrnuje soubory VHDX a VHD včetně řetězců dřívějších kontrolních bodů. Prázdné bloky se neukládají a bloky, které už jsou v úložišti, se znovu neodesílají.
  4. Kontrolní bod se odstraní a Hyper-V ho na pozadí sloučí.
  5. Konfigurace VM se uloží se zálohou: generace, CPU, paměť, síťové adaptéry (přepínač, VLAN, MAC adresa), řadiče disků, zabezpečené spouštění a TPM.

Vypnuté VM se čtou přímo, bez kontrolního bodu. Na hostitelích starších než Windows Server 2016 (bez kontrolních bodů pro obnovu) se použije produkční kontrolní bod a každá záloha čte celé disky.

Příklad z testovací laboratoře: linuxový VM s diskem 3 GB. První záloha přečetla 3 GB. Další, po 64 MB nových dat, přečetla 96 MB.

Ve Windows 10/11 vytváří Hyper-V při startu VM automatický kontrolní bod, pokud tato volba není v nastavení VM vypnutá. BackupZit si s takovými kontrolními body poradí, ale u serverů je vhodné automatické kontrolní body vypnout (nastavení VM → Kontrolní body).

Obnova VM

Otevřete běh zálohy VM (ze stránky úlohy nebo z Aktivita) a použijte Obnovit VM Hyper-V.

Jako nový VM vedle originálu

Vytvoří druhý VM s novými MAC adresami, aby mohl běžet ve stejné síti jako originál. Ve výchozím stavu dostane název originálu s dodatkem „restored“ a datem. Automatické kontrolní body se u něj vypnou (Windows je u nových VM zapínají), takže jeho spuštění nezanechá soubory kontrolních bodů. Pokud kopie běží vedle originálu a obsahuje agenta BackupZit, viz Dva počítače s jedním agentem.

Síťová nastavení hosta vázaná na MAC adresu se na nové adaptéry nevztahují. Příkladem je match: macaddress v netplan, který používají linuxové cloudové obrazy.

Místo původního VM

Zaškrtněte vypnout ho a nahradit jeho disky. BackupZit pak:

  • vypne existující VM;
  • sloučí jeho kontrolní body;
  • vymění jeho disky za obnovené.

VM si ponechá své ID, síťové adaptéry a MAC adresy, takže úlohy, monitoring i síť hosta dál fungují.

Staré soubory disků se nemažou; přejmenují se na ….replaced-DATE. Smažte je, jakmile obnovený VM funguje.

Pokud původní VM už neexistuje, vytvoří se znovu, s novým ID Hyper-V.

Možnosti

  • Složka pro virtuální disky: výchozí složka hostitele nebo jakákoli složka s disky VM. Obnova na místo uloží nové disky vedle původních.
  • Po obnově spustit VM.

Co obnovený VM dostane

  • Virtuální přepínače se připojí podle názvu. Pokud přepínač na hostiteli neexistuje, adaptér zůstane odpojený.
  • Každý obnovený VM dostane nové ID generace, aby řadiče domény Active Directory obnovu bezpečně rozpoznaly.

Obnova jednotlivých souborů

V tabulce VM v běhu klikněte na Procházet soubory a uvidíte oddíly a svazky na discích VM. Procházet lze NTFS, ext2/3/4 a XFS, i uvnitř LVM. Odtud můžete soubory stáhnout nebo je obnovit na libovolného agenta. Funguje to přesně jako u Proxmox VE.

Příkazový řádek

Spouštějte na hostiteli Hyper-V jako správce:

backupzit-agent hyperv list
backupzit-agent hyperv backup  --repo ... [--vmid N,N]
backupzit-agent hyperv restore --repo ... --vmid N [--new] [--name NAME] [--folder D:\VMs] [--overwrite] [--start] SNAPSHOT|latest
  • --vmid je číslo, které ukazuje hyperv list. BackupZit ho odvozuje z GUID VM.
  • Bez --new se VM obnoví na místo.
  • --overwrite potvrzuje, že se mají nahradit disky existujícího VM.

Volby úložiště jsou stejné jako u všech příkazů; viz Příkazový řádek — reference.

Zatím nezahrnuto

  • Některé typy disků. Sdílené VHDX, VHD Set a průchozí (pass-through) disky se nezálohují.
