Virtuální počítače Hyper-V

BackupZit zálohuje virtuální počítače Hyper-V přes agenta na hostiteli Hyper-V; do VM se nic neinstaluje. Hosté s Windows i Linuxem se zachytí za běhu. Obnovit je můžete jako nový VM nebo místo originálu.

Nastavení

  1. Nainstalujte MSI Agent pro Windows z Agenti na hostitele Hyper-V a zaregistrujte ho. Podporovaní hostitelé: Windows Server 2016 nebo novější s rolí Hyper-V, nebo Windows 10/11 s Hyper-V. V clusteru nainstalujte agenta na každého hostitele.
  2. Do minuty se hostitel objeví na stránce Agenti se štítkem Hyper-V · N VMs.
  3. V Úlohy zálohování vyberte tohoto agenta a zvolte Virtuální počítače (Proxmox VE, Hyper-V, VMware). Pak zvolte:
    • Všechny VM (a kontejnery) na hostiteli, což zahrnuje i později vytvořené VM;
    • jednotlivé VM jejich zaškrtnutím.

Agent pracuje přes vlastní rozhraní Hyper-V: modul PowerShell pro Hyper-V a rozhraní Windows Virtual Disk API. Konzole neukládá žádné přihlašovací údaje k Hyper-V.

Jak se VM zálohuje

  1. Vytvoří se dočasný kontrolní bod pro obnovu (backupzit_…). To je typ kontrolního bodu, který Hyper-V poskytuje zálohovacím aplikacím. Hyper-V požádá hosta, aby se připravil:
    • Hosté s Windows vyprázdní vyrovnávací paměti aplikací přes VSS.
    • Hosté s Linuxem zmrazí své souborové systémy, pokud jsou nainstalovaní démoni Hyper-V (hyperv-daemons / hv-vss-daemon).
    Pokud host nezvládne ani jedno, kontrolní bod se pořídí v konzistenci jako při havárii (crash-consistent). Stránka běhu ukazuje, který druh byl použit.
  2. Kontrolní bod pro obnovu zapne pro disky VM Resilient Change Tracking (RCT); vedle nich uvidíte soubory .rct a .mrt. První záloha čte celé disky. Potom RCT hlásí, které bloky se od předchozí zálohy změnily, a čtou se jen ty.
  3. Disky se čtou ve stavu kontrolního bodu přes Virtual Disk API v blocích po 1 MiB. To zahrnuje soubory VHDX a VHD včetně řetězců dřívějších kontrolních bodů. Prázdné bloky se neukládají a bloky, které už jsou v úložišti, se znovu neodesílají.
  4. Kontrolní bod se odstraní a Hyper-V ho na pozadí sloučí.
  5. Konfigurace VM se uloží se zálohou: generace, CPU, paměť, síťové adaptéry (přepínač, VLAN, MAC adresa), řadiče disků, zabezpečené spouštění a TPM.

Vypnuté VM se čtou přímo, bez kontrolního bodu. Na hostitelích starších než Windows Server 2016 (bez kontrolních bodů pro obnovu) se použije produkční kontrolní bod a každá záloha čte celé disky.

Jen aplikačně konzistentní. Pro Active Directory, SQL Server, Exchange a jiné databáze zaškrtněte v úloze Vyžadovat aplikačně konzistentní kontrolní body (také v úloze pro cluster). Běžící VM se pak zálohuje jen z kontrolního bodu, který host připravil pomocí VSS; pokud to selže, VM se nezálohuje a běh selže (s upozorněním) místo pořízení kontrolního bodu konzistentního jen při pádu. Ostatní VM úlohy se zálohují dál a lze je z tohoto běhu obnovit. Zkontrolujte integrační službu Backup (volume shadow copy) v nastavení VM a VSS uvnitř hosta (vssadmin list writers). Vyžaduje agenty 0.48.0 nebo novější; u starších agentů běh selže s výzvou k aktualizaci.

vTPM a BitLocker. U VM 2. generace s virtuálním TPM záloha uchová i vTPM (soubor stavu hosta a ochranu klíče). Při obnově jako nový VM na stejném hostiteli nebo na hostiteli s certifikátem guardianu původního hostitele dostane VM svůj vTPM zpět a BitLocker nežádá klíč pro obnovení. Na jiných hostitelích dostane VM nový prázdný vTPM a obnova to uvede; tomu předejdete importem certifikátu UntrustedGuardian původního hostitele. Obnova přes existující VM jeho vTPM zachová. Stíněné VM (Host Guardian Service) nejsou podporovány. Klíče pro obnovení BitLockeru si přesto uschovejte.

Kontrola integrity úložiště ověřuje také uložený stav hosta. Po aktualizaci zkontrolujte existující úložiště a jejich kopie; aktualizace nemůže obnovit již odstraněný stav hosta. Pokud chybí, použijte nepoškozenou kopii nebo vytvořte novou zálohu.

Příklad z testovací laboratoře: linuxový VM s diskem 3 GB. První záloha přečetla 3 GB. Další, po 64 MB nových dat, přečetla 96 MB.

Ve Windows 10/11 vytváří Hyper-V při startu VM automatický kontrolní bod, pokud tato volba není v nastavení VM vypnutá. BackupZit si s takovými kontrolními body poradí, ale u serverů je vhodné automatické kontrolní body vypnout (nastavení VM → Kontrolní body).

Obnova VM

Otevřete běh zálohy VM (ze stránky úlohy nebo z Aktivita) a použijte Obnovit VM Hyper-V.

Jako nový VM vedle originálu

Vytvoří druhý VM s novými MAC adresami, aby mohl běžet ve stejné síti jako originál. Ve výchozím stavu dostane název originálu s dodatkem „restored“ a datem. Automatické kontrolní body se u něj vypnou (Windows je u nových VM zapínají), takže jeho spuštění nezanechá soubory kontrolních bodů. Pokud kopie běží vedle originálu a obsahuje agenta BackupZit, viz Dva počítače s jedním agentem.

Síťová nastavení hosta vázaná na MAC adresu se na nové adaptéry nevztahují. Příkladem je match: macaddress v netplan, který používají linuxové cloudové obrazy.

Místo původního VM

Zaškrtněte vypnout ho a nahradit jeho disky. BackupZit pak:

  • vypne existující VM;
  • sloučí jeho kontrolní body;
  • vymění jeho disky za obnovené.

VM si ponechá své ID, síťové adaptéry a MAC adresy, takže úlohy, monitoring i síť hosta dál fungují.

Před zastavením původní VM nebo sloučením jejích kontrolních bodů BackupZit obnoví všechny disky v jedinečné podsložce backupzit-restore-* vybrané složky disků (ve výchozím stavu původní složky). Chyba přípravy ponechá VM beze změn. Staré soubory disků zůstávají na původních cestách; odstraňte je až po ověření obnovené VM. Chyba po zahájení přepnutí může vyžadovat ruční obnovu: nové disky zůstanou zachovány, chyba uvede jejich složku a nastavení ani kontrolní body se automaticky nevracejí.

Pokud původní VM už neexistuje, vytvoří se znovu, s novým ID Hyper-V.

Možnosti

  • Složka pro virtuální disky: výchozí složka hostitele nebo jakákoli složka s disky VM. Obnova na místo uloží nové disky vedle původních.
  • Po obnově spustit VM.

Co obnovený VM dostane

  • Virtuální přepínače se připojí podle názvu. Pokud přepínač na hostiteli neexistuje, adaptér zůstane odpojený.
  • Každý obnovený VM dostane nové ID generace, aby řadiče domény Active Directory obnovu bezpečně rozpoznaly.

Clustery s převzetím služeb

Virtuální počítače clusteru Hyper-V s převzetím služeb se zálohují jednou úlohou pro celý cluster. Tři kroky:

1. Nainstalujte agenta na každý uzel

Nainstalujte agenta pro Windows na každý uzel clusteru (ne do virtuálních počítačů). Počítač vždy zálohuje agent uzlu, na kterém právě běží: kontrolní body a sledování změn Hyper-V fungují jen tam. Dokud počítač běží na uzlu bez agenta, nezálohuje se; jakmile přejde na uzel s agentem, zálohuje se znovu.

2. Konzole rozpozná cluster sama

Pro cluster není třeba nic nastavovat, ani v BackupZit, ani ve Windows. Každý agent (verze 0.47.0 nebo novější) hlásí cluster svého uzlu a které počítače jsou v clusteru. Zhruba minutu po instalaci nebo aktualizaci agentů:

  • stránka Agents označí každý uzel jako cluster NÁZEV;
  • cluster se objeví ve formuláři úlohy (další krok) s počtem svých uzlů.

Uzly přidané do clusteru později se rozpoznají stejně a připojí se k úloze automaticky, jakmile se na ně nainstaluje agent.

3. Vytvořte úlohu pro cluster

  1. Otevřete Backup jobs a formulář New backup job.
  2. Otevřete seznam Agent a přejděte na jeho konec: ve skupině Hyper-V failover clusters (virtual machines) zvolte cluster, např. HVC01 — 2 nodes. Zvolte cluster, ne jednotlivý uzel.
  3. Druh je nastaven na Virtual machines. Zvolte All clustered VMs (i počítače přidané do clusteru později) nebo Only these; u každého počítače je uzel, na kterém teď běží.
  4. Zvolte úložiště, plán a počet uchovávaných záloh a klikněte na Create job.

Stránka úlohy ukazuje každý uzel s posledním výsledkem; Run backup now on all agents spustí všechny. Uzel, na kterém v tu chvíli neběží žádný počítač úlohy, hlásí None of the job's VMs runs on this node now — to je úspěch.

Úlohy virtuálních počítačů vytvořené dříve pro jednotlivé uzly: po první záloze úlohy clusteru je vypněte nebo smažte, jinak se počítače clusteru zálohují dvakrát; jejich zálohy zůstávají na úložišti. Počítače mimo cluster (patří jednomu uzlu) do úlohy clusteru nepatří; zálohujte je úlohou toho uzlu.

Jak to funguje

  • Každý uzel zálohuje počítače clusteru, které na něm právě běží, všechny do jednoho repozitáře clusteru na úložišti.
  • Když se počítač přesune na jiný uzel (živá migrace nebo převzetí služeb), jeho historie pokračuje tam a Resilient Change Tracking dál čte jen změněné bloky: žádná nová úplná záloha.
  • VM, který se přesune během zálohování, se i tak zálohuje celý. Uzel, na který se přesunul, odstraní kontrolní bod zálohy během několika minut, jakmile záloha dočte data; běh uvádí, že se VM přesunul.

Obnovení

  • Na místo originálu probíhá na uzlu, který počítač právě vlastní (konzole ho vybere). Počítač se zastaví a spustí přes cluster, aby cluster zastavení nepovažoval za poruchu.
  • Jako nový počítač: zvolte složku na Cluster Shared Volume (C:\ClusterStorage\…). Tam jde i konfigurace počítače a počítač se přidá do clusteru jako role.

Obnova jednotlivých souborů

V tabulce VM v běhu klikněte na Procházet soubory a uvidíte oddíly a svazky na discích VM. Procházet lze NTFS, ext2/3/4 a XFS, i uvnitř LVM. Odtud můžete soubory stáhnout nebo je obnovit na libovolného agenta. Funguje to přesně jako u Proxmox VE.

Příkazový řádek

Spouštějte na hostiteli Hyper-V jako správce:

Obnova Hyper-V z příkazového řádku získá sdílený zámek úložiště před výběrem snímku a drží jej až do dokončení obnovy. Čeká na dokončení údržby s výhradním zámkem; pokud zámek nezíská, skončí chybou bez změny virtuálního počítače.

backupzit-agent hyperv list
backupzit-agent hyperv backup  --repo ... [--vmid N,N]
backupzit-agent hyperv restore --repo ... --vmid N [--new] [--name NAME] [--folder D:\VMs] [--overwrite] [--start] SNAPSHOT|latest
  • --vmid je číslo, které ukazuje hyperv list. BackupZit ho odvozuje z GUID VM.
  • Bez --new se VM obnoví na místo.
  • --overwrite potvrzuje, že se mají nahradit disky existujícího VM.

Volby úložiště jsou stejné jako u všech příkazů; viz Příkazový řádek — reference.

Zatím nezahrnuto

  • Některé typy disků. Sdílené VHDX, VHD Set a průchozí (pass-through) disky se nezálohují.
