Microsoft 365: Exchange Online, OneDrive a SharePoint

BackupZit zálohuje poštovní schránky (Exchange Online), kalendáře, kontakty, OneDrive a weby SharePoint tenanta Microsoft 365 přes Microsoft Graph. Pouze čte: v tenantovi se nic nemění ani nemaže. Data stáhne libovolný agent s přístupem k internetu — například agent na počítači konzole — a uloží je jako každou zálohu: deduplikovaně, šifrovaně, s uchováváním, úlohami kopírování a testy obnovy.

1. Registrace aplikace v Microsoft Entra ID

Jednou pro každého tenanta, jako globální správce, v centru pro správu Microsoft Entra:

  1. App registrations → New registration: název např. BackupZit, Accounts in this organizational directory only, bez URI přesměrování. Poznamenejte si Application (client) ID a Directory (tenant) ID z přehledu.
  2. Certificates & secrets → New client secret: zvolte platnost (např. 24 měsíců) a hned zkopírujte Value tajného klíče — zobrazí se jen jednou. Secret ID není tajný klíč.
  3. API permissions → Add a permission → Microsoft Graph → Application permissions (ne delegated): User.Read.All, Mail.Read a Files.Read.All; pro kalendáře a kontakty také Calendars.Read a Contacts.Read, pro SharePoint Sites.Read.All.
  4. Klikněte na Grant admin consent for …. Do té doby stav ukazuje Not granted a zálohy se odmítají.

Jde jen o oprávnění ke čtení. Pozdější obnova do schránek potřebuje oprávnění k zápisu, o která BackupZit nežádá.

Chcete-li aplikaci omezit na některé schránky, může správce Exchange přidat application access policy nebo obor RBAC for Applications; účty mimo něj se pak hlásí jako nečitelné.

2. Vytvoření úlohy

V Úlohy zálohování vytvořte úlohu typu Microsoft 365:

  • Agent: agent, který stahuje (Windows nebo Linux, verze 0.34.0 nebo novější; 0.35.0 pro kalendáře, kontakty a SharePoint). Potřebuje přístup HTTPS k login.microsoftonline.com, graph.microsoft.com a pro soubory OneDrive a SharePoint k *.sharepoint.com.
  • ID adresáře (tenanta), ID aplikace (klienta) a Tajný klíč klienta z kroku 1. Tajný klíč se ukládá šifrovaně.
  • Co zálohovat: Pošta, OneDrive, Kalendáře a kontakty, Weby SharePoint — v libovolné kombinaci.
  • Účty: jedna adresa na řádek, nebo prázdné pro každý účet tenanta se schránkou nebo OneDrive — účty přidané později se zahrnou automaticky; účty bez licence se přeskočí.
  • Weby SharePoint: jedna adresa webu na řádek (např. https://contoso.sharepoint.com/sites/sales), nebo prázdné pro každý web tenanta — weby přidané později se zahrnou automaticky. Osobní weby (OneDrive) se vynechávají; zálohují se s účty. Úloha jen pro SharePoint nepotřebuje účty.

Místo psaní adres klikněte na Vybrat ze seznamu: konzole pomocí výše zadané aplikace načte účty (a označí ty bez licence, které nemají schránku ani OneDrive) a weby SharePoint tenanta a zobrazí je k zaškrtnutí; zaškrtnuté vyplní pole. Při úpravě úlohy se použije uložený tajný klíč.

Při uložení úlohy se konzole přihlásí jako aplikace a zkontroluje oprávnění, účty a weby, takže špatný tajný klíč nebo chybějící souhlas správce se ukáže hned. Konzole bez přístupu k internetu kontrolu přeskočí; první záloha pak ukáže, zda vše funguje.

Co se zálohuje

  • Pošta: všechny poštovní složky s podsložkami (Doručená pošta, Odeslaná pošta, Odstraněná pošta, Archiv, vlastní složky…). Každá zpráva se uloží celá s přílohami ve formátu MIME jako soubor .eml, pojmenovaný podle času doručení a předmětu, např. 2026-10-07 0621 Nabídka na říjen [3fa2c1d9e0].eml. Outlook, Thunderbird a většina poštovních programů soubory .eml otevřou.
  • OneDrive: všechny soubory a složky OneDrive účtu, s časem změny.
  • Kalendáře: každý kalendář účtu; každá událost jako soubor iCalendar (.ics) s časem, místem, popisem, organizátorem, účastníky, připomenutím a — u série — jejím opakováním, pojmenovaná podle začátku a předmětu, např. 2026-10-08 1000 Zasedání představenstva [8c1e…].ics. Outlook, Kalendář Google a Thunderbird soubory .ics importují. Časy se ukládají v UTC.
  • Kontakty: kontakty a složky kontaktů účtu, každý jako vCard (.vcf) se jmény, e-mailovými adresami, telefonními čísly, adresami, firmou a poznámkami.
  • SharePoint: každá knihovna dokumentů každého webu (Dokumenty, Prostředky webu a knihovny, které jste vytvořili), se všemi složkami a soubory.

Nezahrnuto: přílohy událostí kalendáře, fotografie kontaktů, jednotlivě změněné výskyty série, seznamy a stránky SharePoint (jen knihovny dokumentů), chaty Teams a zprávy kanálů (soubory Teams jsou na SharePointu a zálohují se s ním) a sdílené schránky bez uživatelského účtu.

Záloha obsahuje jednu složku na účet — ana@contoso.com/Mail/Inbox/…, …/OneDrive/…, …/Calendar/Calendar/…, …/Contacts/… — a SharePoint/<site>/<library>/…. První záloha stáhne vše; každá další znovu vypíše složky, ale stáhne jen zprávy a soubory nové nebo změněné od předchozí zálohy (přečtené, označené, přesunuté nebo upravené zprávy se počítají jako změněné) — nezměněná data se převezmou z předchozí zálohy. Microsoft omezuje, jak rychle smí aplikace číst; BackupZit počká, když o to Microsoft požádá, a pokračuje, takže první záloha velkých schránek může trvat hodiny.

Zálohy tenanta se ukládají do vlastního úložiště na cílovém úložišti (složka m365-<tenant ID>), takže stahujícího agenta lze vyměnit, aniž by se začínalo znovu.

Obnova

  • Procházet soubory v běhu zálohy: otevřete poštovní složky, OneDrive, kalendáře nebo kontakty účtu, nebo web SharePoint, zaškrtněte zprávy, události, soubory nebo složky a stáhněte je (jeden soubor tak, jak je, více jako ZIP) — soubory .eml otevřete v Outlooku nebo je přetáhněte do schránky.
  • Obnovit do složky na libovolném agentovi: zprávy se zapíšou jako soubory .eml, události jako .ics, kontakty jako .vcf a soubory OneDrive a SharePoint tak, jak byly, pod <folder>/<account>/… a <folder>/SharePoint/….

Přímá obnova do schránky nebo OneDrive je plánovaná; bude zapisovat jen do nové složky a nikdy nic nepřepíše ani nesmaže.

Řešení potíží

  • AADSTS7000215 / invalid client secret: nebyl zkopírován Value tajného klíče (ale jeho ID), nebo vypršel — vytvořte nový a zadejte ho do úlohy.
  • missing the application permissions nebo Authorization_RequestDenied: přidejte oprávnění jako oprávnění aplikace a klikněte na Grant admin consent.
  • the account has no Exchange Online mailbox: účet nemá licenci Exchange (nebo je to kontakt); odeberte ho z úlohy.
  • Běh s varováními vypíše zprávy nebo soubory, které nešlo přečíst (např. poznámkový blok OneNote); zbytek zálohy je úplný.
