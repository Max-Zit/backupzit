Databáze: SQL Server, PostgreSQL, MySQL

BackupZit zálohuje databáze vlastními nástroji databázového serveru, přes agenta na databázovém počítači: Microsoft SQL Server ve Windows, PostgreSQL a MySQL/MariaDB v Linuxu. Úplné zálohy běží podle plánu úlohy; zálohy protokolů každých pár minut umožňují obnovit jednu databázi k libovolnému okamžiku — například minutu před chybným DELETE.

Vytvoření úlohy

V Úlohy zálohování vytvořte úlohu typu Databáze na agentovi databázového počítače a zvolte:

  • Databázový server: Microsoft SQL Server, PostgreSQL nebo MySQL/MariaDB. Později ho nelze změnit.
  • Instance nebo port: instance SQL Serveru (prázdné pro výchozí instanci, např. SQLEXPRESS) nebo port PostgreSQL (prázdné pro 5432). K MySQL/MariaDB se agent připojuje přes místní socket.
  • Databáze: jeden název na řádek, nebo prázdné pro všechny uživatelské databáze — později vytvořené databáze se zahrnou automaticky.
  • Zálohovat protokoly každých … minut: např. 15 — transakční protokoly (SQL Server), archivovaný WAL (PostgreSQL) nebo binární protokoly (MySQL). Nechte prázdné, pokud stačí obnova k času úplné zálohy.
  • Plán je plánem úplných záloh, např. denně ve 22:00.

Zálohy jsou deduplikované — nezměněná data se znovu neodesílají — a šifrované jako každá záloha. Uchovávání počítá úplné zálohy; zálohy protokolů se uchovávají, dokud existuje úplná záloha, na kterou navazují. Stránka běhu vypisuje, co každá záloha obsahuje.

Microsoft SQL Server

  1. Nainstalujte agenta na počítač s Windows, na kterém běží SQL Server (libovolná edice od 2012 včetně Express).
  2. Agent běží jako NT AUTHORITY\SYSTEM a připojuje se ověřováním Windows. Dejte tomuto účtu roli sysadmin, jednou pro každou instanci: 
    sqlcmd -S .\SQLEXPRESS -E -Q "ALTER SERVER ROLE sysadmin ADD MEMBER [NT AUTHORITY\SYSTEM]"
  • Každý běh zapíše jeden soubor zálohy na databázi (BACKUP DATABASE / BACKUP LOG … WITH CHECKSUM) do výchozí složky záloh instance, uloží soubory a smaže je. Složka potřebuje po dobu běhu volné místo pro největší databázi.
  • Se zapnutými zálohami protokolů zahajují úplné zálohy řetězec protokolů. Bez nich se úplné zálohy pořizují jako COPY_ONLY, takže neruší jiné plány záloh nebo údržby.
  • Zálohy protokolů se pořizují pro databáze v modelu obnovení full nebo bulk-logged; databáze v modelu simple dostávají jen úplné zálohy. Zaškrtněte systémové databáze a přidáte master, model a msdb.

PostgreSQL

Agent pracuje jako účet postgres přes místní socket — pro zálohy není co nastavovat. Úplná záloha uloží celý cluster (pg_basebackup), role (pg_dumpall --globals-only) a pg_dump každé databáze.

Obnova k okamžiku vyžaduje archivaci WAL. Se zapnutými zálohami protokolů ji první úplná záloha nastaví pomocí ALTER SYSTEM: archive_mode = on a archive_command, který kopíruje dokončené segmenty WAL do /var/lib/backupzit-pg/wal; zálohy protokolů je tam ukládají a odstraňují. archive_mode začne platit po jednom restartu PostgreSQL (systemctl restart postgresql) — běh vám to řekne. Pokud archive_command už používá jiný nástroj, BackupZit ho nechá být a zálohuje bez obnovy k okamžiku. Pokud zálohy protokolů přestanou (úloha zakázána nebo smazána), archivaci zase vypněte (ALTER SYSTEM RESET archive_mode, restart), aby se složka nezaplnila.

  • Obnovit databázi ve stavu úplné zálohy: z jejího pg_dump do běžícího serveru, pod novým názvem nebo místo databáze.
  • K určitému okamžiku (nebo nejnovější): agent rozbalí zálohu clusteru do dočasné instance na volném portu (jen socket, bez sítě, bez archivace), přehraje WAL do tohoto okamžiku, vyexportuje z ní databázi do běžícího serveru a dočasnou instanci odstraní. Počítač na chvíli potřebuje volné místo pro cluster.
  • Celý cluster: obnoví se stejně jako samostatná instance, která dál běží na volném portu; běh vám sdělí její port a datový adresář (pod /var/lib/backupzit-pg) a jak se k ní připojit a zastavit ji.

MySQL a MariaDB

Agent se připojuje jako root přes místní socket (ověřování socketem, výchozí v Debianu a Ubuntu), nebo s přihlašovacími údaji z /root/.my.cnf. Úplná záloha uloží mysqldump každé databáze (konzistentní, s rutinami, událostmi a triggery) spolu s odpovídající pozicí binárního protokolu.

Obnova k okamžiku vyžaduje binární protokol. Zapněte ho jednou v konfiguraci serveru a server restartujte, např. /etc/mysql/mariadb.conf.d/60-binlog.cnf:

[mysqld]
server_id = 1
log_bin = /var/log/mysql/mysql-bin
binlog_format = ROW
expire_logs_days = 7

(vytvořte složku pro protokol s vlastníkem mysql). Zálohy protokolů pak ukládají každý uzavřený binární protokol. Vlastní dobu vypršení na serveru držte delší než interval záloh protokolů; mezera se ohlásí a obnovy ji nemohou překročit.

  • Obnovit databázi: její dump se načte do nové databáze (nebo nahradí existující). K určitému okamžiku nebo nejnovější: změny této databáze zaznamenané v binárních protokolech po dumpu se přehrají do tohoto okamžiku — i když databáze dostane nový název. Přehrávání se nezapisuje do binárního protokolu serveru.
  • Uživatelé a oprávnění (systémová databáze mysql) nejsou součástí dumpů.

Obnova

Otevřete běh úplné zálohy (nebo použijte průvodce obnovou → Databáze) a zvolte databázi, počítač pro obnovu (stejný server nebo jiný se stejným databázovým serverem) a:

  • Jako novou databázi pojmenovanou např. sales_restored — originál zůstane nedotčený a řádky můžete zkopírovat zpět — nebo pod původním názvem; zaškrtněte nahradit ji a přepíšete existující databázi (její uživatelé se nejprve odpojí).
  • Stav: stav úplné zálohy; nejnovější stav (úplná záloha a každá záloha protokolů po ní); nebo určitý okamžik mezi úplnou zálohou a nejnovější použitelnou zálohou protokolů, jak ukazuje tabulka. Zadejte čas tak, jak ho ukazuje konzole, v časovém pásmu serveru konzole (viz Časové pásmo); agent ho převede do časového pásma databázového serveru.

Příkazový řádek

backupzit-agent sql list    [--instance SQLEXPRESS]
backupzit-agent sql backup  --repo ... [--instance I] [--db a,b] [--system] [--log] [--copy-only]
backupzit-agent sql restore --repo ... [--instance I] --db NAME [--as NEW] [--replace] [--at "2026-10-04 14:59:00"] SNAPSHOT|latest
backupzit-agent pg list     [--port 5432]
backupzit-agent pg backup   --repo ... [--port P] [--db a,b] [--pitr | --wal]
backupzit-agent pg restore  --repo ... --db NAME|"(cluster)" [--as NEW] [--replace] [--at TIME | --latest] SNAPSHOT|latest
backupzit-agent mysql list
backupzit-agent mysql backup  --repo ... [--db a,b] [--binlog]
backupzit-agent mysql restore --repo ... --db NAME [--as NEW] [--replace] [--at TIME | --latest] SNAPSHOT|latest

Nezahrnuto

  • Rozdílové zálohy SQL Serveru a skupiny dostupnosti Always On; vzdálené databázové servery — agent zálohuje servery na svém vlastním počítači.
  • Obnova jednotlivých tabulek: obnovte databázi pod novým názvem a zkopírujte řádky.
