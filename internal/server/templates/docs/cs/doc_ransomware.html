Ochrana proti ransomwaru

Útočníci se snaží smazat nebo zašifrovat zálohy dřív, než zašifrují produkční data. BackupZit nabízí úložiště, na kterém zálohy nelze zničit ani s ukradenými přihlašovacími údaji.

Vrstvy ochrany

VrstvaChrání před
Šifrování (AES-256)Čtením nebo úpravou záloh na úložišti. Každá změna se odhalí.
Neměnné S3 (Object Lock, režim compliance)Smazáním nebo přepsáním záloh — útočníkem s klíči, nepoctivým správcem nebo omylem.
Zabezpečené úložištěTotéž na vašem vlastním linuxovém serveru: soubory se zapisují jen jednou a dostanou příznak neměnnosti souborového systému.
Kopie mimo lokalituPožárem, krádeží, úplnou ztrátou lokality.
Schválení čtyř očí (volitelné)Jedním ukradeným nebo zneužitým účtem konzole, který maže úlohy a cílová úložiště nebo zkracuje uchovávání: musí schválit druhý uživatel. Viz Uživatelé, role a LDAP.

Automatické odhalení podezřelých záloh

Každá záloha se porovná s nedávnou historií své úlohy. Označí se jako podezřelá, když nese stopy ransomwaru nebo hromadného mazání:

  • změnilo se mnohem více souborů než obvykle (např. 95 % místo obvyklého 1 %),
  • nová data se už nekomprimují — zašifrované soubory vypadají jako náhodná data,
  • počet souborů náhle klesl o třetinu nebo více,
  • náhlý skok v množství nových dat (i u obrazů disků, systémů Linux a VM).

Pak BackupZit pošle varovný e-mail (při zapnutých oznámeních o chybách), zobrazí zálohu na přehledu jako podezřelé zálohy ke kontrole a pozastaví uchovávání úlohy: žádná starší záloha se nesmaže, takže poslední čisté zálohy zůstanou obnovitelné, i když poškozené zálohy dál přicházejí. Po kontrole počítače klikněte na stránce úlohy na Zkontrolováno — obnovit uchovávání.

Neměnné S3 s Object Lock

  1. Vytvořte bucket se zapnutým Object Lock (AWS, Wasabi, Backblaze B2, MinIO: mc mb --with-lock).
  2. Přidejte pravidlo životního cyklu, které maže neaktuální verze (noncurrent versions) po 1 dni (MinIO: mc ilm rule add --noncurrent-expire-days 1 --expire-delete-marker).
  3. Přidejte cíl S3 a zaškrtněte Neměnné zálohy na N dní. Zvolte N alespoň tak dlouhé jako nejdelší uchovávání, které chcete chránit, např. 30.

Každý bod obnovy zůstane zamčený alespoň N dní od vytvoření; data sdílená s novějšími zálohami se prodlužují automaticky.

Zabezpečené úložiště

Samostatný linuxový server s backupzit-repo:

  • Agenti a konzole mohou soubory jen přidávat; existující soubory se nikdy nepřepisují.
  • Každý soubor dostane atribut chattr +i na dobu nastavenou na tom serveru. Ani root ho nemůže smazat, aniž by nejdřív příznak odstranil.
  • Mazání od klientů soubory jen skryje, dokud jejich doba neuplyne.
  • Služba běží jako neprivilegovaný uživatel; jejím jediným oprávněním je nastavit příznak neměnnosti.
apt install ./backupzit-repo_*.deb
vi /etc/backupzit-repo/repo.env        # BACKUPZIT_REPO_LOCK_DAYS=30
systemctl start backupzit-repo
backupzit-repo add-key office-console
backupzit-repo fingerprint

Po nastavení vypněte SSH a jiný vzdálený přístup na serveru úložiště a chraňte přístup k jeho místní konzoli / iDRAC / iLO / hypervizoru. Ochrana je jen tak silná jako účet root tohoto počítače.

Obnova po útoku

Pokud útočník smazal nebo přepsal zálohy, čtěte úložiště ve stavu před útokem — je to jen pro čtení a nic nemění:

backupzit-agent snapshots --repo <úložiště> --as-of 2026-10-01T14:30
backupzit-agent restore   --repo <úložiště> --as-of 2026-10-01T14:30 --target D:\Restore latest

Na zabezpečeném úložišti může správce skryté soubory také vrátit, aby zálohy normálně pokračovaly:

backupzit-repo status
backupzit-repo undelete --since 2026-10-01T14:00

Doporučení

  • Pro úložiště používejte samostatný účet, který není součástí vaší domény Windows.
  • Mějte alespoň jednu neměnnou kopii (S3 Object Lock nebo zabezpečené úložiště).
  • Listy pro obnovu uchovávejte offline (vytištěné, v trezoru).
  • Zapněte e-mailová upozornění — náhlá změna v počtu chyb nebo v objemu odesílaných dat bývá prvním znakem útoku.
