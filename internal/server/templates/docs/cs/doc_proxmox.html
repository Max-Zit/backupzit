Virtuální počítače Proxmox VE

BackupZit zálohuje virtuální počítače (QEMU) a kontejnery (LXC) Proxmox VE, aniž by cokoli instaloval do hostů. Agent běží na hostiteli Proxmox, pořídí snímek každého hosta, přečte jeho disky a uloží je deduplikovaně na libovolné cílové úložiště.

Nastavení

  1. Nainstalujte balíček Agent pro Linux — Debian / Ubuntu z Agenti na každý uzel Proxmoxu (Proxmox VE 7 a 8 vycházejí z Debianu): 
    apt install ./backupzit-agent_*.deb
backupzit-agent enroll --code "BZ1-..."
systemctl enable --now backupzit-agent
  2. Do minuty se uzel objeví na stránce Agenti se štítkem Proxmox VE · N guests.
  3. V Úlohy zálohování vyberte tohoto agenta a zvolte Virtuální počítače (Proxmox VE, Hyper-V, VMware). Zálohujte všechny hosty uzlu (hosté vytvoření později se zahrnou automaticky) nebo zaškrtněte jednotlivé.

Agent používá vlastní nástroje uzlu (qm, pct, pvesm, LVM, ZFS, Ceph); v konzoli se neukládá žádný API token ani heslo.

Jak se host zálohuje

  1. Pořídí se dočasný snímek Proxmoxu (backupzit_…, viditelný v Snapshots několik sekund až minut). Host dál běží.
  2. Pokud ve VM běží QEMU guest agent (a je zapnutý v možnostech VM), Proxmox pro snímek zmrazí souborové systémy — záloha je pak konzistentní na úrovni aplikací. Bez něj je záloha konzistentní jako při havárii, jako po výpadku proudu. Do linuxových VM nainstalujte qemu-guest-agent a do VM s Windows nástroje hosta VirtIO.
  3. Každý disk se čte ze snímku po blocích 1 MiB. Prázdné bloky se neukládají a bloky, které už jsou v úložišti, se znovu neodesílají, takže po první záloze se přenášejí jen změněná data.
  4. Snímek se odstraní. Konfigurace hosta (CPU, paměť, síť, disky) se uloží se zálohou.

Stránka běhu vypisuje každého hosta, jeho disky a způsob zachycení. Testy obnovy kontrolují náhodné bloky záloh VM stejně jako u obrazů disků a se zapnutým testem spuštění spustí každý VM ze zálohy, izolovaný od sítě, aby prokázaly, že startuje.

Disky označené v Proxmoxu Backup: no (backup=0), průchozí fyzické disky a bind mounty se přeskočí a uvedou jako varování. Jednotky cloud-init se neukládají; při obnově se znovu vytvoří z konfigurace.

Obnova VM nebo kontejneru

Otevřete běh zálohy VM (ze stránky úlohy nebo z Aktivita) a použijte Obnovit VM nebo kontejner:

  • Host — jeden z hostů v této záloze.
  • Obnovit na uzlu Proxmox — libovolný uzel s agentem BackupZit, i uzel jiného clusteru.
  • Jako nového hosta s dalším volným ID (výchozí) nebo s ID … — originál dál běží. Protože existují oba, síťové karty kopie dostanou nové MAC adresy.
  • S původním ID — poté, co byl host smazán. Pokud ještě existuje, zaškrtněte zastavit a smazat ho a nahraďte ho zálohou; nejdřív se smaže existující host a jeho disky.
  • Název a Úložiště pro disky — např. obnova na jiné úložiště než originál.
  • Po obnově spustit hosta.

Každá obnova dá VM nové ID generace (vmgenid), aby řadiče domény Windows a další software bezpečně rozpoznaly návrat do minulosti. Disky se alokují pomocí pvesm na zvoleném úložišti; na adresářovém úložišti se obnoví jako soubory raw.

Okamžitá obnova

Obnova velkého VM trvá tak dlouho jako kopírování jeho disků. S volbou Okamžitě, běží ze zálohy ve formuláři obnovy VM naopak běží během několika sekund, zatímco jeho disky jsou stále v záloze:

  1. Agent poskytuje disky VM ze zálohy jen pro čtení (malý server NBD běžící jako jednotka systemd backupzit-instant-<ID>) a vytvoří nový VM s dalším volným ID, jehož disky jsou překryvy qcow2 na adresářovém úložišti backupzit-instant (/var/lib/backupzit-instant, přidá se automaticky). Data se čtou ze zálohy podle potřeby; vše, co VM zapíše, zůstává v překryvech. Proměnné firmwaru (disk EFI) a stav TPM jsou malé a kopírují se.
  2. VM se spustí. Zkontrolujte ho — jako každá kopie dostane nové MAC adresy. Přehled vypisuje každý VM, který stále běží ze zálohy.
  3. Na stránce běhu buď Dokončit: disky se přesunou na zvolené úložiště, zatímco VM dál běží (qm disk move), a pak se záloha už nepoužívá. Nebo Zahodit: VM se zastaví a smaže i se svými změnami.

Dokud VM běží ze zálohy, uchovávání tuto zálohu nikdy neodstraní. VM je tak rychlý, jak dovolí úložiště záloh: nejlépe funguje úložiště na místním disku nebo rychlé síťové sdílené složce; čtení přes SFTP nebo S3 z dálky ho zpomalí, dokud se nedokončí. Okamžitá obnova je pro VM (ne kontejnery) a vytváří nový VM — obnovu na místo proveďte běžnou obnovou. Disk EFI nelze přesunout, dokud VM běží; zůstane pak na backupzit-instant (viz zpráva běhu) a lze ho přesunout po vypnutí VM: qm disk move ID efidisk0 STORAGE --delete 1.

Replikace

Pro hosty, kteří musí být zpět během minut, může úloha VM udržovat repliky: v části Pokročilé formuláře úlohy zaškrtněte Udržovat repliky VM a zvolte uzel (libovolný uzel s agentem BackupZit, i v jiném clusteru) a úložiště. Po každé záloze agent na tomto uzlu aktualizuje zastavenou kopii každého hosta úlohy:

  • Poprvé se replika obnoví jako nový host (další volné ID, název original-replica, nové MAC adresy, nikdy se nespouští s uzlem).
  • Později se zapisují jen bloky změněné od zálohy, kterou replika obsahuje — obvykle pár sekund na zálohu.
  • Stránka úlohy vypisuje repliky, zálohu, kterou každá obsahuje, a jejich stav. Pokud se host ztratí, klikněte na Spustit repliku: poběží s daty poslední zálohy, bez obnovy. Spusťte ji jen tehdy, když originál opravdu zmizel — oba v síti současně mohou kolidovat.
  • Dokud replika běží, už se neaktualizuje (běh to ohlásí). Chcete-li znovu replikovat, smažte hosta repliky v Proxmoxu; další záloha vytvoří novou. Repliky se snímky Proxmoxu se také neaktualizují.
  • Disky přidané k hostovi později se nereplikují (smažte repliku a začněte znovu); zvětšené disky se zvětší i na replice. Změny konfigurace (paměť, CPU) se převezmou při vytvoření repliky.
  • Replikace čte zálohy jako obnova: uzel repliky musí dosáhnout na úložiště. Vypnutí replikace ponechá repliky, jak jsou.

Příkazový řádek

backupzit-agent pve list
backupzit-agent pve backup  --repo ... [--vmid 100,200] [--exclude 300]
backupzit-agent pve show    --repo ... latest
backupzit-agent pve restore --repo ... --vmid 100 [--new-vmid -1|N] [--name copy] [--storage local-lvm] [--overwrite] [--start] SNAPSHOT|latest
backupzit-agent pve instant --repo ... --vmid 100 [--new-vmid N] [--name X] SNAPSHOT|latest
backupzit-agent pve instant-finish --vmid 101 --storage local-lvm
backupzit-agent pve instant-discard --vmid 101

Volby úložiště jsou stejné jako u všech příkazů (viz Příkazový řádek — reference). Příkazový řádek funguje bez konzole, například pro obnovu celého uzlu po havárii.

Clustery

Nainstalujte agenta na každý uzel. Úloha zálohuje hosty běžící na uzlu svého agenta; host uvedený v úloze, který byl migrován na jiný uzel, se ohlásí jako varování s názvem toho uzlu — zálohujte každý uzel vlastní úlohou, nebo na každém uzlu použijte všechny hosty uzlu, aby byli migrovaní hosté vždy pokryti.

Obnova jednotlivých souborů

V tabulce hostů běhu zálohy VM klikněte na Procházet soubory. Konzole čte disk přímo ze zálohy — nic se předem neobnovuje — a ukáže jeho oddíly a logické svazky LVM; procházet lze NTFS (Windows), ext2/3/4 a XFS (Linux), i uvnitř LVM. Zaškrtněte soubory a složky a:

  • Stáhnout — jeden soubor tak, jak je, více souborů nebo složek jako archiv ZIP, přímo do prohlížeče;
  • Obnovit na agentovi — zkopírovat je do složky na libovolném agentovi, např. zpět do VM (pokud v něm běží agent BackupZit) nebo na souborový server.

Na příkazovém řádku: backupzit-agent pve ls --vmid 100 latest /etc a backupzit-agent pve extract --vmid 100 --target /srv/restore latest /etc/nginx; --volume vybere oddíl nebo logický svazek (pve ls bez cesty je vypíše). Procházení v konzoli vyžaduje zálohu na síťovém úložišti (SFTP, S3, SMB, Azure, zabezpečené úložiště).
