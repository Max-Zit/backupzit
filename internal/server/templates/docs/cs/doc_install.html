Instalace serveru

Konzole běží na Linuxu (Debian, Ubuntu, AlmaLinux, Rocky Linux) s PostgreSQL. Každá organizace provozuje vlastní konzoli ve vlastní síti.

Požadavky

  • Linuxový VM nebo server: 2 vCPU, 2–4 GB RAM a 20 GB disku bohatě stačí pro stovky agentů (data záloh se na něm neukládají).
  • PostgreSQL 13 nebo novější (místně nebo na jiném serveru).
  • Síť: agenti musí na konzoli dosáhnout přes TCP 8443 (HTTPS). Agenti musí také přímo dosáhnout na úložiště.

1. Hotový obraz VM

Hotová appliance (Debian, PostgreSQL, konzole, automatické bezpečnostní aktualizace), která naběhne za méně než minutu a nepotřebuje přístup k internetu:

HypervizorJak
VMware ESXiHost Client: Create / Register VM → Deploy a virtual machine from an OVF or OVA file, zvolte backupzit-appliance.ova. vSphere: Deploy OVF Template. Workstation a VirtualBox: File → Open / Import.
Proxmox VEZkopírujte backupzit-appliance.qcow2 na uzel, vytvořte VM bez disku (2 vCPU, 2–4 GB RAM, síť VirtIO), pak
qm importdisk <vmid> backupzit-appliance.qcow2 local-lvm
připojte importovaný disk jako SCSI, nastavte ho jako zaváděcí disk a zapněte agenta hosta QEMU.
Hyper-VRozbalte backupzit-appliance-vhdx.zip, pak Nový → Virtuální počítač, generace 1, 2–4 GB RAM, Použít existující virtuální pevný disk: soubor VHDX.

Spusťte VM. Jeho obrazovka ukáže adresu webové konzole a počáteční heslo účtu admin (viz První přihlášení). Dejte VM 2 vCPU a 2–4 GB RAM; 16GB disk můžete kdykoli zvětšit — appliance nové místo využije při dalším spuštění (kořenový souborový systém se zvětší za běhu). Při prvním spuštění si každá kopie vytvoří vlastní klíče SSH, heslo databáze a klíč tajných údajů, takže jeden obraz lze nasadit mnohokrát. Síťový adaptér získá adresu přes DHCP.

2. ISO appliance

ISO appliance nainstaluje vše bez dotazů: Debian, PostgreSQL, konzoli a automatické bezpečnostní aktualizace.

  1. Vytvořte VM (nebo použijte server) se 2 vCPU, 2–4 GB RAM a diskem o velikosti 16 GB nebo větším. Použijte VirtIO nebo výchozí zařízení hypervizoru, BIOS nebo UEFI.
  2. Spusťte ho z backupzit-appliance.iso. Po 5 sekundách se instalace spustí sama, vymaže první disk a nainstaluje se. Stahuje balíčky operačního systému, takže server potřebuje během instalace přístup k internetu. Trvá to zhruba 10–20 minut a server se pak restartuje.
  3. Obrazovka serveru ukáže adresu webové konzole a počáteční heslo účtu admin. Otevřete adresu, přihlaste se a změňte heslo.

Appliance (obraz nebo ISO)

Appliance má dva oddělené účty:

  • admin ve webové konzoli (https://<address>:8443) pro každodenní práci. Jeho počáteční heslo se po prvním spuštění zobrazí na obrazovce serveru; změňte ho v části Můj účet.
  • bzadmin přímo na serveru (jeho obrazovka v konzoli hypervizoru, nebo SSH), počáteční heslo backupzit. Při prvním přihlášení ho musíte změnit; uživatel může používat sudo. Root se přihlásit nemůže.

Aktualizace BackupZit a operačního systému se spravují z konzole (viz níže). VMware Tools a agent hosta QEMU jsou součástí, takže hypervizory zobrazují adresu appliance.

Stejná nastavení sítě, názvu serveru, SSH a časového pásma jsou ve webové konzoli v části Nastavení → Síť (jen správci). Tam se statická adresa, jejíž brána neodpoví do půl minuty, automaticky vrátí, takže překlep nemůže appliance odříznout od sítě; pokud konzole přesto není dostupná, použijte nabídku na obrazovce serveru, která funguje i s vypnutým SSH.

Agenti si pamatují certifikát konzole, ne její adresu. Pokud konzoli dosahují přes IP adresu a ta se změní, nasměrujte je na novou příkazem backupzit-agent set-server (viz Agenti), nebo od začátku používejte název DNS. S DHCP si adresu appliance v serveru DHCP rezervujte, aby se neměnila.

Server SSH appliance nabízí jen šifry AES-GCM/CTR a MAC SHA-2 (žádné chacha20-poly1305 ani 64bitové MAC, které skenery zranitelností hlásí jako slabé).

3. Instalační skript

Na existujícím serveru s Debianem 12+, Ubuntu 22.04+, AlmaLinuxem nebo Rocky Linuxem 9+ (x86-64), jako root:

curl -fsSL https://github.com/Max-Zit/backupzit/releases/latest/download/install.sh | sudo sh

Skript nainstaluje PostgreSQL, stáhne nejnovější vydání, ověří jeho podpis klíčem vydání BackupZit a kontrolní součet balíčku, nainstaluje konzoli, vytvoří databázi s náhodným heslem, zapíše /etc/backupzit/server.env, zapne automatické bezpečnostní aktualizace, otevře port 8443 ve firewalld nebo ufw, pokud jsou aktivní, spustí konzoli a vypíše její adresu a počáteční heslo admina. Volby (za sh -s --):

VolbaÚčinek
--version 0.32.0nainstaluje toto vydání místo nejnovějšího
--db postgres://user:pw@host:5432/dbpoužije existující databázi PostgreSQL místo místní
--hosts backup.example.local,10.0.0.10názvy a adresy pro certifikát konzole (výchozí: adresa a název serveru)
--no-auto-updatesponechá automatické bezpečnostní aktualizace beze změny

Příklad: curl -fsSL …/install.sh | sudo sh -s -- --hosts backup.example.local. Opětovné spuštění skriptu na nainstalované konzoli aktualizuje BackupZit a zachová konfiguraci i data. Chcete-li si skript před spuštěním přečíst, nejdřív ho stáhněte: curl -fsSLO …/install.sh; less install.sh; sudo sh install.sh.

4. Balíčky ručně

Debian / Ubuntu

apt install postgresql
apt install ./backupzit-server_*.deb

AlmaLinux / Rocky Linux

dnf install postgresql-server && postgresql-setup --initdb && systemctl enable --now postgresql
dnf install ./backupzit-server-*.rpm

V AlmaLinuxu a Rocky Linuxu změňte v souboru /var/lib/pgsql/data/pg_hba.conf u řádků 127.0.0.1 a ::1 ident na scram-sha-256 a restartujte PostgreSQL, aby se konzole mohla přihlásit heslem.

Vytvoření databáze

sudo -u postgres psql -c "SET password_encryption = 'scram-sha-256'; CREATE USER backupzit WITH PASSWORD 'choose-a-strong-password'"
sudo -u postgres psql -c "CREATE DATABASE backupzit OWNER backupzit"

Zapište připojovací řetězec do /etc/backupzit/server.env:

BACKUPZIT_DB=postgres://backupzit:choose-a-strong-password@localhost:5432/backupzit?sslmode=disable
BACKUPZIT_PUBLIC_URL=https://backup.example.local:8443
BACKUPZIT_TLS_HOSTS=backup.example.local,10.0.0.10
systemctl start backupzit-server

První přihlášení

Otevřete https://<server>:8443. Počátečním správcem je admin; heslo je v /var/lib/backupzit/initial-admin-password.txt (nebo před prvním spuštěním nastavte BACKUPZIT_ADMIN_PASSWORD). Po přihlášení ho změňte. Zapomenuté heslo obnovíte na serveru takto:

set -a; . /etc/backupzit/server.env; set +a
backupzit-server --set-admin-password 'NEW-PASSWORD'

Certifikát

Při prvním spuštění konzole vytvoří certifikát podepsaný sám sebou. Prohlížeč na to jednou upozorní; agenti se na certifikační autority vůbec nespoléhají — připínají otisk certifikátu, který se zobrazí na stránce Agenti při registraci. To agenty chrání před falešným serverem i v nedůvěryhodné síti.

Tento certifikát nenahrazujte (cert.pem/key.pem v datovém adresáři): dříve registrovaní agenti by odmítli připojení, dokud by nebyli znovu zaregistrováni. Pro prohlížeče místo toho přidejte důvěryhodný certifikát, jak je popsáno níže.

Důvěryhodný certifikát pro prohlížeče

Abyste se vyhnuli varování prohlížeče, otevřete Nastavení → Certifikát. Konzole pak odpovídá i na názvu DNS, například https://backup.example.com na portu 443, s důvěryhodným certifikátem. Agenti dál používají port 8443 a připnutý certifikát, takže se jich to netýká.

  • Nahrát certifikát z firemní CA nebo veřejné CA, i certifikát se zástupným znakem, například *.example.com. Vložte certifikát (s mezilehlými certifikáty) a soukromý klíč ve formátu PEM, nebo vyberte soubory. Konzole ověří, že klíč patří k certifikátu, že je certifikát nyní platný a pokrývá název DNS. Bez interního DNS zadejte místo toho IP adresu konzole a použijte certifikát vydaný pro tuto IP adresu (alternativní název IP:192.168.1.20); konzoli pak dejte pevnou adresu. 21 dní před vypršením dostanete e-mail.
  • Let's Encrypt: bezplatné certifikáty, automaticky obnovované 30 dní před vypršením. Let's Encrypt musí ověřit, že název ovládáte, jedním ze dvou způsobů:
    • Ověření DNS přes Cloudflare, doporučeno pro konzole nedostupné z internetu. BackupZit vytvoří dočasný záznam TXT pomocí tokenu API Cloudflare. V Cloudflare přejděte do My Profile → API Tokens → Create Token, použijte šablonu Edit zone DNS a omezte ji na svou zónu.
    • Ověření HTTP: port 80 konzole musí být pod názvem DNS dostupný z internetu. U zálohovacího serveru to bývá nežádoucí.
    Nastavení si nejdřív vyzkoušejte s Použít testovací systém Let's Encrypt. Jeho certifikátům prohlížeče nedůvěřují, ale nemá omezení počtu požadavků.
  • Obsluhovat port 80 přesměruje http:// na https://.

Název DNS musí ukazovat na IP adresu konzole, obvykle přes záznam A v interním DNS. Soubory certifikátu jsou v /var/lib/backupzit/web a klíč může číst jen služba. V Linuxu smí služba používat porty 80 a 443 (CAP_NET_BIND_SERVICE); pokud se prohlížeče připojují z jiných sítí, otevřete je ve firewallu.

Aktualizace BackupZit

Ve výchozím stavu konzole stahuje aktualizace z oficiálních vydání BackupZit na GitHubu (https://github.com/Max-Zit/backupzit/releases). V Nastavení → Aktualizace můžete místo toho zadat jiný zdroj aktualizací — vlastní zrcadlo HTTPS nebo složku na serveru. Ať je zdroj jakýkoli, každé vydání musí mít platný podpis BackupZit. Konzole denně kontroluje nová vydání a pošle správcům e-mail, když je některé k dispozici. Pro instalaci klikněte na Instalovat:

  1. Konzole ověří podpis vydání a kontrolní součet balíčku a počká, až neběží žádná záloha ani obnova.
  2. Systémová služba (backupzit-update, běží jako root) ověří podpis znovu pomocí klíčů vydání zabudovaných v BackupZit. Ani kompromitovaná konzole tak nemůže nechat nainstalovat jiný balíček.
  3. Zazálohuje databázi (pg_dump), ponechá si aktuální program, nainstaluje balíček a restartuje konzoli.
  4. Pokud nová verze do dvou minut neodpoví, předchozí program a databáze v původním stavu se automaticky obnoví. Výsledek s protokolem neúspěšného spuštění se zobrazí na stránce Aktualizace, zapíše se do protokolu auditu a odešle e-mailem.
  5. Po úspěšné aktualizaci se aktualizují i agenti: každý nainstaluje novou verzi, když je nečinný. Pokud je chcete aktualizovat sami, vypněte to na stejné stránce.

Konzole je asi minutu nedostupná. Zálohy databáze a předchozí programy z posledních tří aktualizací se uchovávají v /var/lib/backupzit-update.

Bez přístupu k internetu: stáhněte soubory vydání (manifest.json, manifest.json.sig a balíček serveru) na jiném počítači. Pak je nahrajte v části Nainstalovat aktualizaci ze souborů, nebo je zkopírujte do složky na serveru a tuto složku použijte jako zdroj aktualizací.

Aktualizovat můžete i nadále správcem balíčků (apt install ./backupzit-server_….deb); databáze se převede při spuštění nové verze.

Aktualizace operačního systému

Stejná stránka (Nastavení → Aktualizace) ukazuje operační systém serveru konzole: kolik aktualizací je k dispozici, kolik z nich jsou bezpečnostní opravy, zda je potřeba restart a zda jsou zapnuté automatické bezpečnostní aktualizace. Stav se obnovuje denně, nebo tlačítkem Zkontrolovat nyní. Můžete:

  • Zapnout automatické bezpečnostní aktualizace (doporučeno). Nástroj samotného systému denně instaluje jen bezpečnostní opravy: unattended-upgrades v Debianu a Ubuntu, dnf-automatic v AlmaLinuxu a Rocky Linuxu.
  • Nainstalovat nyní všechny aktualizace. Služby jako PostgreSQL se mohou krátce restartovat a konzole se znovu připojí sama.
  • Restartovat server, například po aktualizaci jádra. Konzole to odmítne, dokud běží zálohy nebo obnovy. Agenti si ponechají své úlohy a výsledky nahlásí, až bude konzole zpět.

Tyto úlohy běží přes stejnou službu root jako aktualizace konzole. Zaznamenávají se do protokolu auditu a výstup poslední úlohy se zobrazí na stránce.

Záloha samotné konzole

Zálohy na vašem úložišti zůstávají čitelné i bez konzole díky listům pro obnovu. Chcete-li po ztrátě serveru získat zpět i samotnou konzoli, zapněte Nastavení → Záloha konzole. To zahrnuje úlohy, rozvrhy, agenty, uživatele, nastavení, historii běhů a uložené přihlašovací údaje. Konzole se pak denně zálohuje na síťový cíl úložiště do složky backupzit-console.

Záloha konzole obsahuje:

  • celou databázi, exportovanou tabulku po tabulce, takže není potřeba žádná konkrétní verze pg_dump;
  • klíč tajných údajů, který dešifruje uložené přihlašovací údaje;
  • certifikát konzole, který si agenti připínají.

Je šifrována klíčem pro obnovení daného cíle a deduplikována. Uchovávají se nejnovější zálohy: ve výchozím stavu 14.

Obnova konzole

  1. Nainstalujte novou konzoli ve stejné nebo novější verzi, například z ISO appliance.
  2. Na novém serveru jako root spusťte následující. Přihlašovací údaje jsou z listu pro obnovu cíle úložiště a adresa repozitáře je zobrazena na stránce Záloha konzole. 
    systemctl stop backupzit-server
set -a; . /etc/backupzit/server.env; set +a
export BACKUPZIT_PASSWORD='<recovery key>'
export BACKUPZIT_SFTP_PASSWORD='…' BACKUPZIT_SFTP_HOSTKEY='SHA256:…'   # or BACKUPZIT_S3_ACCESS_KEY/_SECRET_KEY, _SMB_PASSWORD, _AZURE_KEY, _HARDENED_KEY/_FINGERPRINT
backupzit-server --restore-console --repo 'sftp://backup@nas:22/backups/backupzit-console'
systemctl start backupzit-server
  3. Dejte novému serveru IP adresu nebo název DNS starého serveru. Agenti důvěřují obnovenému certifikátu a připojí se sami.

Obnova nahradí databázi nové konzole databází ze zálohy a převede ji na nainstalovanou verzi. --snapshot ID obnoví místo nejnovější zálohy starší.

Kopii listů pro obnovu a souboru secrets.key uchovávejte i mimo server, například ve správci hesel.
