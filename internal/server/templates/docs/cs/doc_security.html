Zabezpečení a doporučení

Jak BackupZit chrání vaše data a konzoli a co byste měli udělat na své straně.

Vestavěná ochrana

  • Šifrování u zdroje — AES-256-GCM v agentovi; úložiště vidí jen šifrovaná data. Klíče se odvozují pomocí Argon2id.
  • Připnutá spojení — agenti připínají certifikát konzole; připínají se i klíče hostitele SFTP a certifikáty zabezpečených úložišť. Žádnou certifikační autoritu nelze zneužít k vydávání se za ně.
  • Důvěryhodný certifikát pro prohlížeče — volitelně nahraný certifikát nebo certifikát Let's Encrypt (TLS 1.2+) na samostatné adrese, obnovovaný automaticky; viz Instalace serveru.
  • Tajemství v klidu — hesla a klíče úložišť, klíče pro obnovu, hesla SMTP/LDAP a dvoufázová tajemství se v databázi šifrují klíčem drženým mimo ni (secrets.key).
  • Tajemství agentů — každý agent má vlastní tajemství, uložené na konzoli jen jako hash a na agentovi v souboru, který mohou číst jen správci.
  • Webová konzole — relační cookies HttpOnly a SameSite=Strict; ochrana proti cross-site požadavkům a clickjackingu; přísná Content-Security-Policy; hesla hashovaná bcryptem; citlivé stránky se nikdy neukládají do mezipaměti.
  • Ochrana proti hrubé síle — adresy, jejichž přihlášení příliš často selže, se blokují: hesla, dvoufázové kódy i tokeny API. Blokace přežijí restart, opakovaní útočníci se blokují déle a správci dostanou e-mail. Viz níže.
  • Účty — role s nejmenšími oprávněními, volitelné dvoufázové ověření (TOTP) a přihlášení LDAPS; tokeny API s vlastní, nižší rolí a platností.
  • Schválení čtyř očí (volitelné) — mazání nebo zakázání úloh, mazání agentů, hostitelů ESXi, cílových úložišť a uživatelů, zkracování uchovávání, vypnutí schvalování a vše, co by správci mohlo dát druhého schvalovatele (noví schvalovatelé, více práv, reset hesla a dvoufázového přihlášení, změny LDAP a SSO), vyžaduje schválení druhým uživatelem. Viz Uživatelé, role a LDAP.
  • Auditní stopa — přihlášení, neúspěšná přihlášení, změny uživatelů a rolí, úlohy, cílová úložiště, obnovy, zobrazené klíče pro obnovu, změny nastavení a akce API se zaznamenávají do protokolu auditu; záznamy jsou zřetězené, takže změny a mazání v databázi se odhalí, a lze je kopírovat na server syslog nebo SIEM (Ochrana proti změnám); mazání na zabezpečeném úložišti se zaznamenává na tom serveru.
  • Aktualizace konzole — vydání jsou podepsaná klíčem vydání BackupZit (Ed25519). Konzole i služba root, která je instaluje, ověřují podpis, databáze se nejdřív zazálohuje a neúspěšná aktualizace se vrátí zpět.
  • Aktualizace agentů — agenti stahují nové verze jen ze své konzole přes připnuté spojení a instalují je jen tehdy, když sedí kontrolní součet SHA-256.
  • Místní stavový kanál — aplikace v oznamovací oblasti komunikuje se službou agenta přes místní pojmenovanou rouru (Windows) nebo socket přístupný jen rootovi (Linux). Přihlášení uživatelé počítače mohou číst stav a spouštět zálohovací úlohy tohoto počítače; nic dalšího (úlohy, plány, úložiště a obnovy se spravují jen v konzoli).
  • Zálohy hypervizorů — agent na hostiteli Proxmox nebo Hyper-V používá vlastní nástroje hostitele; hesla hypervizoru se pro ně neukládají. U VMware ESXi konzole ukládá heslo hostitele šifrovaně, připíná jeho HTTPS certifikát a SSH klíč hostitele a spojení předává jen proxy agentovi hostitele pro jeho běhy.
  • Integrita záloh — každý blok se při obnově ověřuje podle svého hashe SHA-256; automatické testy obnovy a detekce ransomwaru zálohy průběžně hlídají.

Ochrana proti hrubé síle

Nastavuje se v Nastavení → Přihlášení a zabezpečení. Výchozí hodnoty jsou bezpečné pro většinu instalací:

NastaveníVýchozíVýznam
Neúspěšné pokusy na adresu5Neúspěšná přihlášení z jedné IP adresy během doby počítání tuto adresu zablokují. Počítají se špatná hesla, špatné dvoufázové kódy a neplatné tokeny API.
Doba počítání15 minutStarší neúspěchy se zapomínají.
Blokovat na30 minutZablokovaná adresa se nemůže přihlásit, ani se správným heslem. Přihlašovací stránka odpoví „Příliš mnoho neúspěšných přihlášení“ a API odpoví HTTP 429.
Opakované útočníky blokovat délezapnutoKaždá další blokace adresy během dne trvá dvakrát déle: 30 minut, 1 hodina, 2 hodiny, … až 7 dní.
Neúspěšné pokusy na uživatelské jméno20Neúspěchy pro jedno uživatelské jméno, z libovolných adres, pozastaví přihlašování tohoto jména, dokud neuplyne doba počítání. To zastaví hádání rozložené na mnoho adres. Účty se nikdy nezamykají trvale, takže útočník nemůže správce vyřadit.
Tyto sítě nikdy neblokovatžádnéVolitelné sítě, např. podsíť správců, které se nikdy neblokují. Limit na uživatelské jméno pro ně stále platí.
Reverzní proxyžádnéPokud konzole běží za nginx, Traefikem nebo jinou proxy, zadejte její adresu: adresa klienta se pak bere z X-Forwarded-For (jinak by všichni klienti vypadali jako proxy) a když proxy posílá X-Forwarded-Proto: https, přihlašovací cookies se označí jako Secure. Obě hlavičky se z jakékoli jiné adresy ignorují, takže je nelze podvrhnout.
E-mail při zablokování adresyzapnutoPosílá se příjemcům z nastavení e-mailu.

Stejná stránka vypisuje zablokované adresy s důvodem a dobou trvání každé blokace a umožňuje blokaci zrušit. Blokace a jejich zrušení se zaznamenávají do protokolu auditu.

Pokud jste se zablokovali sami, přihlaste se z jiné adresy, nebo na serveru spusťte se stejnými volbami databáze jako služba:

backupzit-server --unblock-ip all

Chcete-li zrušit jednu blokaci, zadejte místo all adresu.

Přístup k webové konzoli (veřejná adresa)

Agenti se ke konzoli připojují na portu 8443. Chcete-li konzoli nabídnout na veřejné adrese — pro agenty v jiných lokalitách nebo u zákazníků — a přitom webovou konzoli nechat otevírat jen své správce, použijte Nastavení → Přihlášení a zabezpečení → Přístup k webové konzoli:

NastaveníÚčinek
Povolené adresyIP adresy nebo sítě (např. 203.0.113.10, 10.0.0.0/24). Webová konzole, REST API a každá stránka odpovídají jen těmto adresám; ostatní dostanou „not found“, jako by žádná konzole neexistovala. Agenti se ke svému API dostanou vždy (registrace, dotazování, výsledky, stahování, vzdálená instalace). Prázdné: všichni. Konzole odmítne seznam, který neobsahuje vaši vlastní adresu.
Port 8443 jen pro agentyWebová konzole je pak dostupná jen na webovém portu s důvěryhodným certifikátem (Nastavení → Certifikát, obvykle 443), takže firewall může otevřít 8443 všem a 443 jen vašim adresám. K dispozici, jakmile webový port běží; měňte to z webového portu, ne z 8443.

Typický firewall pro veřejnou konzoli: 8443 otevřený všem (agenti), 443 a 80 (HTTP kontrola Let's Encrypt) jen z vašich adres, SSH jen z vašich adres nebo vypnuté, vše ostatní zavřené.

Zablokovali jste se? Na samotném serveru (localhost) konzole odpovídá vždy. Na appliance položka 5 nastavovací nabídky na jeho obrazovce zruší blokace přihlášení a tato omezení.

Doporučení

Konzole

  • Držte konzoli ve vnitřní síti; nepublikujte port 8443 do internetu. Pro vzdálenou správu použijte VPN.
  • Používejte dlouhé, jedinečné heslo správce a změňte počáteční.
  • Vyžadujte dvoufázové ověření pro správce (Nastavení → Přihlášení a zabezpečení).
  • Dejte každé osobě vlastní účet s nejnižší funkční rolí; pro monitoring používejte tokeny API s rolí Čtenář.
  • Zálohujte secrets.key odděleně od databáze (Instalace serveru).
  • Zvolte v Nastavení → Přihlášení a zabezpečení vhodnou délku relace (kratší je bezpečnější).
  • Udržujte server aktuální (apt upgrade / dnf upgrade), včetně PostgreSQL.

Úložiště

  • Dejte každému cílovému úložišti vlastní účet s přístupem jen ke složce nebo bucketu záloh.
  • Nepřipojujte úložiště záloh do domény Windows; používejte přihlašovací údaje, které se nikde jinde nepoužívají.
  • Mějte alespoň jednu neměnnou kopii (S3 Object Lock nebo zabezpečené úložiště) a jednu kopii mimo lokalitu.

Klíče

  • Listy pro obnovu uchovávejte offline. Bez nich nelze šifrované zálohy obnovit, pokud se konzole ztratí.
  • Jednou otestujte obnovu z příkazového řádku jen s listem pro obnovu, abyste věděli, že postup funguje.
  • S USB diskem s recovery.json zacházejte jako s klíčem: dokud kód obnovy nevyprší (30 dní), umožňuje počítači připojit se ke konzoli jako agent obnovy. Když potřebujete, vytvořte nový kód, místo abyste uchovávali staré disky.
  • Obnovovací ISO dávají příkazový řádek root / správce každému, kdo z nich nastartuje — jako každé zaváděcí médium. Chraňte servery heslem firmwaru (BIOS/UEFI) a nastavením zabezpečeného spouštění.

Agenti a hypervizory

  • Konzole může na agenty instalovat software (aktualizace agentů) a obnovovat na ně data. Chraňte podle toho účty správců: dvoufázové ověření, málo správců.
  • Soubory z disků VM analyzují konzole a agenti při procházení; poškozená nebo škodlivá data souborového systému vedou k chybě, ne k pádu.
