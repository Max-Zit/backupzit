Disk-Images & Bare-Metal-Wiederherstellung

Eine Abbildsicherung erfasst eine ganze Festplatte — Partitionstabelle, Boot-Partitionen, System und Daten —, sodass eine Maschine auf einer leeren oder neuen Festplatte genau so wiederhergestellt werden kann, wie sie war.

Festplattenabbild-Sicherungen gibt es für Windows-Maschinen (NTFS-Volumes, GPT- und MBR-Festplatten). Für Linux-Maschinen verwenden Sie einen Auftrag Linux-System.

Einen Abbildauftrag erstellen

  1. Wählen Sie unter Sicherungsaufträge Festplattenabbild.
  2. Der Agent meldet seine Festplatten automatisch. Wählen Sie Alle Datenträger, um jede interne Festplatte der Maschine in einem Auftrag abzubilden, oder markieren Sie eine einzelne Festplatte — ganz oder nur einige Partitionen (z. B. eine große Datenpartition auslassen, die bereits ein Dateiauftrag abdeckt).
  3. Stellen Sie Aufbewahrung und Zeitplan wie bei jedem Auftrag ein; ein wöchentliches Abbild plus tägliche Dateisicherungen ist eine gängige Kombination.

Alle Datenträger

Ein Auftrag Alle Datenträger sichert jede interne Festplatte mit Partitionstabelle in einer Sicherung, auch später hinzugefügte Festplatten. Alle Volumes aller Festplatten werden aus einem VSS-Snapshot gelesen, sodass die Festplatten zueinander konsistent sind (z. B. eine Datenbank auf D: mit ihren Logs auf E:). USB- und SD-Festplatten, eingebundene VHD/VHDX-Dateien und Wechselmedien werden ausgelassen — eine externe Sicherungsfestplatte darf sich nicht selbst abbilden; wählen Sie eine solche Festplatte einzeln, wenn Sie sie brauchen. Die Laufseite listet jede Festplatte mit ihren Partitionen auf; aus jeder können Dateien durchsucht und wiederhergestellt werden. Die Wiederherstellung schreibt jeweils eine Festplatte: Wählen Sie im Wiederherstellungsformular den Datenträger der Sicherung und die Zielfestplatte und wiederholen Sie das für die nächste Festplatte (bei Bare Metal: zuerst die Systemfestplatte vom Wiederherstellungs-ISO wiederherstellen). Der Agent muss 0.33.7 oder neuer sein; ein älterer meldet, dass er aktualisiert werden muss.

Es werden nur belegte Blöcke gelesen (NTFS-Belegungstabelle), das Abbild wird aus einem VSS-Snapshot erstellt, damit das laufende System konsistent ist, und unveränderte Blöcke werden gegen frühere Abbilder dedupliziert — das zweite Abbild derselben Maschine lädt meist nur wenige Prozent hoch.

Ein Abbild auf eine Festplatte wiederherstellen

Verwenden Sie im Lauf der Abbildsicherung Dieses Abbild auf eine Festplatte wiederherstellen:

  • Auf Agent wiederherstellen — die Maschine mit der Zielfestplatte. Das kann eine laufende Maschine mit einer freien Festplatte sein oder eine vom Wiederherstellungs-ISO gestartete Maschine.
  • Zieldatenträger — muss mindestens so groß sein wie der belegte Bereich des Originals. Alle Daten darauf werden gelöscht.
  • Festplatte danach offline lassen — aktivieren Sie dies, wenn sich die Originalfestplatte in derselben Maschine befindet, damit Windows die Datenträger-IDs der Kopie nicht ändert.

GPT- und MBR-Festplatten, EFI- und BIOS-Boot werden unterstützt. Partitionslayout und IDs werden neu erstellt, sodass die wiederhergestellte Festplatte wie zuvor startet.

Bare-Metal-Wiederherstellung mit dem Wiederherstellungs-ISO

  1. Laden Sie unter Wiederherstellungsmedien das (Windows-)Wiederherstellungs-ISO herunter. Schreiben Sie es auf einen USB-Stick (Rufus, Modus „DD-Image“ oder „ISO“) oder hängen Sie es an eine virtuelle Maschine.
  2. Erstellen Sie optional einen Wiederherstellungscode und laden Sie recovery.json herunter; kopieren Sie die Datei in einen Ordner backupzit auf dem Stick, damit die Maschine sich ohne Eingaben verbindet.
  3. Starten Sie die wiederherzustellende Maschine vom Stick. Sie startet den Agenten im Wiederherstellungsmodus und verbindet sich mit der Konsole (oder fragt nach Serveradresse und Wiederherstellungscode).
  4. Die Maschine erscheint als Wiederherstellung-Agent mit ihren Festplatten.
  5. Öffnen Sie die Abbildsicherung in Aktivität, wählen Sie Dieses Abbild auf eine Festplatte wiederherstellen, wählen Sie den Wiederherstellungsagenten und seine Festplatte, bestätigen Sie.
  6. Wenn der Lauf abgeschlossen ist, entfernen Sie den Stick und starten Sie neu.

Auf andere Hardware wiederherstellen

Windows startet nur mit einem Treiber für den Festplattencontroller, von dem es bootet, und Windows Setup deaktiviert die Treiber, die es nicht brauchte. Ein Abbild eines PCs mit Intel-Controller bleibt deshalb auf einem AMD-Board, einem NVMe-Laufwerk, in Hyper-V oder in einer Proxmox-VM mit INACCESSIBLE_BOOT_DEVICE stehen. Aktivieren Sie im Wiederherstellungsformular Auf andere Hardware wiederherstellen, und BackupZit bereitet das wiederhergestellte Windows nach dem Schreiben des Abbilds vor:

  1. Die zu Windows gehörenden Treiber für gängige Festplattencontroller starten wieder beim Booten: AHCI/SATA, NVMe, Intel RST, LSI/Broadcom/Dell PERC SAS und RAID, HPE Smart Array, Hyper-V und VMware.
  2. Zusätzliche Treiber werden mit DISM hinzugefügt: die Treiber auf dem Wiederherstellungs-ISO (es enthält die VirtIO-Treiber für Proxmox/KVM) und die Ordner, die Sie unter Zusätzliche Treiber angeben — z. B. die Speicher- und Netzwerktreiber des neuen Mainboards, entpackt auf einen USB-Stick (E:\Drivers; Unterordner werden durchsucht).
  3. Die Bootdateien werden für die neue Maschine neu erstellt (bcdboot).

Die Laufseite listet die aktivierten und hinzugefügten Treiber auf. Windows erkennt die übrigen neuen Geräte beim ersten Start; die Aktivierung muss auf neuer Hardware eventuell wiederholt werden. Eine Wiederherstellung zwischen UEFI und Legacy-BIOS ist nicht möglich — das Ziel muss auf dieselbe Weise booten wie das Original.

Physischer PC oder Server nach Proxmox VE: Erstellen Sie eine VM mit OVMF (UEFI) für GPT-Festplatten oder SeaBIOS für MBR-Festplatten, eine VirtIO-SCSI-Festplatte, mindestens so groß wie das Original, und eine VirtIO-Netzwerkkarte, hängen Sie das Wiederherstellungs-ISO an und stellen Sie mit Auf andere Hardware wiederherstellen wieder her. Das Wiederherstellungs-ISO erkennt VirtIO-Festplatten und -Netzwerkkarten selbst.

Auf eine virtuelle Maschine wiederherstellen

Erstellen Sie eine leere VM-Festplatte, mindestens so groß wie das Original, starten Sie die VM vom Wiederherstellungs-ISO und folgen Sie den Schritten oben. Das ist auch der einfachste Weg zu testen, ob Ihre Abbilder wirklich starten.
