Microsoft 365: Exchange Online, OneDrive und SharePoint

BackupZit sichert die Postfächer (Exchange Online), Kalender, Kontakte, OneDrive und SharePoint-Websites eines Microsoft-365-Mandanten über Microsoft Graph. Es liest nur: Im Mandanten wird nichts geändert oder gelöscht. Ein beliebiger Agent mit Internetzugang lädt die Daten herunter — zum Beispiel der Agent auf der Konsolenmaschine — und speichert sie wie jede Sicherung: dedupliziert, verschlüsselt, mit Aufbewahrung, Kopieraufträgen und Wiederherstellungstests.

1. Eine App in Microsoft Entra ID registrieren

Einmal pro Mandant, als Globaler Administrator, im Microsoft Entra Admin Center:

  1. App registrations → New registration: Name z. B. BackupZit, Accounts in this organizational directory only, keine Umleitungs-URI. Notieren Sie die Application (client) ID und die Directory (tenant) ID aus der Übersicht.
  2. Certificates & secrets → New client secret: Wählen Sie eine Laufzeit (z. B. 24 Monate) und kopieren Sie sofort den Value des Geheimnisses — er wird nur einmal angezeigt. Die Secret ID ist nicht das Geheimnis.
  3. API permissions → Add a permission → Microsoft Graph → Application permissions (nicht delegated): User.Read.All, Mail.Read und Files.Read.All; für Kalender und Kontakte zusätzlich Calendars.Read und Contacts.Read, für SharePoint Sites.Read.All.
  4. Klicken Sie auf Grant admin consent for …. Bis dahin zeigt der Status Not granted, und Sicherungen werden abgelehnt.

Das sind nur Leseberechtigungen. Eine spätere Wiederherstellung in Postfächer braucht Schreibberechtigungen, die BackupZit nicht anfordert.

Um die App auf einige Postfächer zu beschränken, kann ein Exchange-Administrator eine Application Access Policy oder einen RBAC-for-Applications-Bereich hinzufügen; Konten außerhalb davon werden dann als nicht lesbar gemeldet.

2. Den Auftrag erstellen

Erstellen Sie unter Sicherungsaufträge einen Auftrag der Art Microsoft 365:

  • Agent: der Agent, der herunterlädt (Windows oder Linux, Version 0.34.0 oder neuer; 0.35.0 für Kalender, Kontakte und SharePoint). Er braucht HTTPS-Zugriff auf login.microsoftonline.com, graph.microsoft.com und, für OneDrive- und SharePoint-Dateien, *.sharepoint.com.
  • Verzeichnis-ID (Mandant), Anwendungs-ID (Client) und Clientgeheimnis aus Schritt 1. Das Geheimnis wird verschlüsselt gespeichert.
  • Was gesichert wird: E-Mail, OneDrive, Kalender und Kontakte, SharePoint-Websites — in beliebiger Kombination.
  • Konten: eine Adresse pro Zeile, oder leer für jedes Konto des Mandanten, das ein Postfach oder OneDrive hat — später hinzugefügte Konten werden automatisch einbezogen; Konten ohne Lizenz werden übersprungen.
  • SharePoint-Websites: eine Website-Adresse pro Zeile (z. B. https://contoso.sharepoint.com/sites/sales), oder leer für jede Website des Mandanten — später hinzugefügte Websites werden automatisch einbezogen. Persönliche Websites (OneDrive) werden ausgelassen; sie werden mit den Konten gesichert. Ein Auftrag nur für SharePoint braucht keine Konten.

Statt Adressen einzutippen, klicken Sie auf Aus der Liste wählen: Die Konsole liest mit der oben eingegebenen App die Konten (und markiert die ohne Lizenz, die kein Postfach und kein OneDrive haben) und die SharePoint-Websites des Mandanten und listet sie zum Ankreuzen auf; die angekreuzten füllen die Felder. Beim Bearbeiten eines Auftrags wird das gespeicherte Geheimnis verwendet.

Beim Speichern des Auftrags meldet sich die Konsole als die App an und prüft die Berechtigungen, die Konten und die Websites, sodass ein falsches Geheimnis oder eine fehlende Administratorzustimmung sofort auffällt. Eine Konsole ohne Internetzugang überspringt die Prüfung; die erste Sicherung zeigt dann, ob es funktioniert.

Was gesichert wird

  • E-Mail: alle E-Mail-Ordner mit ihren Unterordnern (Posteingang, Gesendete Elemente, Gelöschte Elemente, Archiv, eigene Ordner…). Jede Nachricht wird vollständig mit Anhängen im MIME-Format als .eml-Datei gespeichert, benannt nach Eingangszeit und Betreff, z. B. 2026-10-07 0621 Angebot für Oktober [3fa2c1d9e0].eml. Outlook, Thunderbird und die meisten Mailprogramme öffnen .eml-Dateien.
  • OneDrive: alle Dateien und Ordner des OneDrive des Kontos, mit ihrer Änderungszeit.
  • Kalender: jeder Kalender des Kontos; jeder Termin als iCalendar-Datei (.ics) mit Zeit, Ort, Beschreibung, Organisator, Teilnehmern, Erinnerung und — bei einer Serie — ihrer Wiederholung, benannt nach Beginn und Betreff, z. B. 2026-10-08 1000 Vorstandssitzung [8c1e…].ics. Outlook, Google Kalender und Thunderbird importieren .ics-Dateien. Zeiten werden in UTC gespeichert.
  • Kontakte: die Kontakte und Kontaktordner des Kontos, jeweils als vCard (.vcf) mit Namen, E-Mail-Adressen, Telefonnummern, Adressen, Firma und Notizen.
  • SharePoint: jede Dokumentbibliothek jeder Website (Dokumente, Websiteobjekte und selbst erstellte Bibliotheken), mit allen Ordnern und Dateien.

Nicht enthalten: Anhänge von Kalenderterminen, Kontaktfotos, einzeln geänderte Vorkommen einer Serie, SharePoint-Listen und -Seiten (nur Dokumentbibliotheken), Teams-Chats und Kanalnachrichten (Teams-Dateien liegen in SharePoint und werden mit gesichert) sowie freigegebene Postfächer ohne Benutzerkonto.

Eine Sicherung enthält einen Ordner pro Konto — ana@contoso.com/Mail/Inbox/…, …/OneDrive/…, …/Calendar/Calendar/…, …/Contacts/… — und SharePoint/<site>/<library>/…. Die erste Sicherung lädt alles herunter; jede spätere Sicherung listet die Ordner erneut auf, lädt aber nur Nachrichten und Dateien herunter, die seit der vorigen Sicherung neu oder geändert sind (gelesene, markierte, verschobene oder bearbeitete Nachrichten gelten als geändert) — unveränderte Daten werden aus der vorigen Sicherung übernommen. Microsoft begrenzt, wie schnell eine App lesen darf; BackupZit wartet, wenn Microsoft darum bittet, und macht weiter, daher kann eine erste Sicherung großer Postfächer Stunden dauern.

Die Sicherungen eines Mandanten werden in einem eigenen Repository auf dem Speicherziel abgelegt (Ordner m365-<tenant ID>), sodass der herunterladende Agent ersetzt werden kann, ohne neu zu beginnen.

Wiederherstellen

  • Dateien durchsuchen in einem Sicherungslauf: Öffnen Sie die E-Mail-Ordner, OneDrive, Kalender oder Kontakte eines Kontos oder eine SharePoint-Website, markieren Sie Nachrichten, Termine, Dateien oder Ordner und laden Sie sie herunter (eine Datei unverändert, mehrere als ZIP) — öffnen Sie die .eml-Dateien in Outlook oder ziehen Sie sie in ein Postfach.
  • In einen Ordner wiederherstellen auf einem beliebigen Agenten: Nachrichten werden als .eml-Dateien geschrieben, Termine als .ics, Kontakte als .vcf und OneDrive- und SharePoint-Dateien so, wie sie waren, unter <folder>/<account>/… und <folder>/SharePoint/….

Die direkte Wiederherstellung in ein Postfach oder OneDrive ist geplant; sie wird nur in einen neuen Ordner schreiben und nie überschreiben oder löschen.

Fehlerbehebung

  • AADSTS7000215 / invalid client secret: Es wurde nicht der Value des Geheimnisses kopiert (sondern seine ID), oder es ist abgelaufen — erstellen Sie ein neues und tragen Sie es im Auftrag ein.
  • missing the application permissions oder Authorization_RequestDenied: Fügen Sie die Berechtigungen als Application-Berechtigungen hinzu und klicken Sie auf Grant admin consent.
  • the account has no Exchange Online mailbox: Das Konto hat keine Exchange-Lizenz (oder ist ein Kontakt); entfernen Sie es aus dem Auftrag.
  • Ein Lauf mit Warnungen listet Nachrichten oder Dateien auf, die nicht gelesen werden konnten (z. B. ein OneNote-Notizbuch); der Rest der Sicherung ist vollständig.
