Fehlerbehebung & FAQ

Ein Agent wird als offline angezeigt

  • Ist die Maschine eingeschaltet und läuft der Dienst? Windows: Get-Service backupzit-agent; Linux: systemctl status backupzit-agent.
  • Erreicht die Maschine die Konsole? Test-NetConnection backup-server -Port 8443 oder curl -k https://backup-server:8443/login.
  • Agentenprotokoll: C:\ProgramData\backupzit\agent.log, unter Linux /etc/backupzit/agent.log oder journalctl -u backupzit-agent. „fingerprint mismatch“ bedeutet, dass sich das Konsolenzertifikat geändert hat — registrieren Sie den Agenten erneut.

Eine Sicherung ist fehlgeschlagen

Öffnen Sie den Lauf in Aktivität; die Meldung nennt die Ursache. Häufige Ursachen:

Meldung enthältLösung
host key mismatch / fingerprintDer Schlüssel des SFTP-Servers hat sich geändert oder der Fingerabdruck wurde falsch eingegeben. Prüfen Sie mit ssh-keygen -lf auf dem Server.
permission denied / access deniedZugangsdaten des Speichers oder Ordnerberechtigungen. Testen Sie die Anmeldung mit einem SFTP-/SMB-Client.
no space left / quotaDer Speicher ist voll. Verkürzen Sie die Aufbewahrung oder fügen Sie Platz hinzu; abgelaufene Sicherungen geben nach dem nächsten Lauf Platz frei.
repository is lockedEin anderer Vorgang (z. B. Bereinigung) läuft auf demselben Repository; der Lauf versucht es 30 Minuten lang erneut. Veraltete Sperren laufen automatisch ab.
wrong password / recovery keyDas Repository wurde mit einem anderen Schlüssel angelegt — prüfen Sie, ob der Auftrag das richtige Speicherziel verwendet.
bucket has no Object Lock enabledUnveränderlichkeit wurde für einen Bucket ohne Object Lock angefordert. Erstellen Sie einen neuen Bucket mit Object Lock.

„no matching backup disk is connected“Schließen Sie eine der rotierenden USB-Festplatten an (die Meldung nennt das benötigte Label und welche beschrifteten Festplatten angeschlossen sind). Eine Wiederherstellung braucht genau die Festplatte, die im Sicherungslauf angezeigt wird.
„several backup disks are connected“Schließen Sie jeweils nur eine der rotierenden Festplatten an.
Wiederherstellungstest fehlgeschlagenÖffnen Sie den Lauf: Die Meldung nennt die beschädigte Datei bzw. den Block oder den Grund (z. B. Sicherung auf dem Speicher gelöscht). Führen Sie backupzit-agent check --read-data für das Repository aus, prüfen Sie den Speicher und starten Sie eine neue Sicherung. Wurden Sicherungen auf unveränderlichem Speicher gelöscht, siehe Schutz vor Ransomware.
Sicherung als verdächtig markiertPrüfen Sie die Maschine auf Ransomware oder eine Massenlöschung (z. B. ein geleerter synchronisierter Ordner). Ist alles in Ordnung (z. B. eine geplante Migration), klicken Sie auf der Auftragsseite auf Geprüft – Aufbewahrung fortsetzen.
Let's Encrypt: „could not verify … is port 80 … reachable“Die HTTP-Prüfung braucht Port 80 aus dem Internet erreichbar. Verwenden Sie für interne Konsolen die DNS-Prüfung über Cloudflare.
Let's Encrypt: „no Cloudflare zone … is accessible with this token“Das Token braucht die Berechtigung Zone → DNS → Edit für die Zone, die den Namen der Konsole enthält.
„HTTPS port 443: … permission denied“ oder „address already in use“Ein anderes Programm nutzt den Port, oder der Dienst darf keine Ports unter 1024 belegen (starten Sie ihn mit CAP_NET_BIND_SERVICE, wie es das Paket tut). Wählen Sie unter Einstellungen → Zertifikat einen anderen Port.
Updates: „updates from the console need the Linux package of the console“Die Konsole wurde nicht aus dem deb/rpm-Paket installiert (zum Beispiel der Testmodus). Aktualisieren Sie sie so, wie sie installiert wurde.
Updates: „the release is not signed with a BackupZit release key“Die Update-Quelle enthält kein offizielles Release, oder die Dateien wurden unterwegs verändert. Laden Sie sie erneut von der offiziellen Adresse herunter.
Updates: Status rolled-backDie neue Version ist nicht gestartet, daher wurden die vorherige Version und ihre Datenbank wiederhergestellt. Das Protokoll des fehlgeschlagenen Starts steht auf der Seite Updates; senden Sie es an den Support.
Betriebssystem: „no supported package manager“Betriebssystem-Updates werden unter Debian, Ubuntu (apt) und AlmaLinux, Rocky Linux, RHEL (dnf) unterstützt.
Konsolensicherung: „the backup was made by a newer BackupZit“Installieren Sie vor der Wiederherstellung auf der neuen Konsole die Version, mit der die Sicherung erstellt wurde, oder eine neuere.
Konsolensicherung: „console backups need network storage“Wählen Sie ein SFTP-, S3-, SMB-, Azure- oder gehärtetes Repository-Ziel; ein lokaler Pfad eines Agenten ist von der Konsole aus nicht erreichbar.
„Zu viele fehlgeschlagene Anmeldungen“Ihre Adresse wurde nach wiederholt falschen Passwörtern gesperrt: standardmäßig für 30 Minuten, bei wiederholten Sperren länger. Ein Administrator kann die Sperre unter Einstellungen → Anmeldung & Sicherheit aufheben. Auf dem Server hebt backupzit-server --unblock-ip all alle Sperren auf. Konten werden nie dauerhaft gesperrt.
Telefon für die Zwei-Faktor-Anmeldung verlorenVerwenden Sie einen der Wiederherstellungscodes; andernfalls setzt ein Administrator die Zwei-Faktor-Anmeldung auf Ihrer Benutzerseite zurück. Der letzte Administrator kann sein Passwort auf dem Server mit backupzit-server --set-admin-password zurücksetzen.
„your directory account is not in any BackupZit group“Fügen Sie den Benutzer einer der unter Einstellungen → LDAP / Active Directory zugeordneten Gruppen hinzu oder ordnen Sie weitere Gruppen zu. Mit Test sehen Sie dort die für einen Benutzer gefundenen Gruppen.
API liefert 401 / 403401: Token fehlt, wurde widerrufen, ist abgelaufen oder sein Besitzer ist deaktiviert. 403: Die Rolle des Tokens ist für die Anfrage zu niedrig.
Azure: AuthenticationFailed / AuthorizationPermissionMismatchFalscher Kontoschlüssel, oder dem SAS-Token fehlt die Berechtigung zum Lesen, Schreiben, Löschen oder Auflisten, oder es ist abgelaufen.
Eine wiederhergestellte VM mit Windows Server 2012 R2 / Windows 8.1 startet nicht unter Hyper-V Gen 2 („hash was denied (DBX)“)Microsoft hat den alten Bootloader für Secure Boot widerrufen. Schalten Sie Secure Boot für diese VM aus oder aktualisieren Sie das System vor der Sicherung.

Virtuelle Maschinen, Linux-Systeme und neue Hardware

SituationWas tun
Proxmox: „the guest is running and one of its disks is on storage without snapshot support“Laufende Gäste brauchen LVM-thin-, ZFS-, Ceph-RBD- oder qcow2-Festplatten. Verschieben Sie die Festplatte (Disk Action → Move Storage) oder sichern Sie den Gast, während er gestoppt ist.
Hyper-V: Der Lauf meldet „crash-consistent“Der Gast konnte sich nicht auf den Prüfpunkt vorbereiten. Prüfen Sie in Windows-Gästen, dass die Hyper-V-Integrationsdienste (Backup (volume shadow copy)) in den VM-Einstellungen aktiviert sind. In Linux-Gästen installieren Sie hyperv-daemons (RHEL) bzw. linux-cloud-tools / hyperv-daemons (Debian/Ubuntu).
VMware: „SSH off“ oder „SSH to …: connection refused“Aktivieren Sie SSH auf dem ESXi-Host: Host → Actions → Services → Enable Secure Shell (und lassen Sie es mit dem Host starten). Wiederherstellungen und Sicherungen mit der kostenlosen Lizenz brauchen es.
VMware: „changed block tracking is off and can be enabled … only while the VM is off“Kostenlose ESXi-Lizenz: Fahren Sie die VM einmal herunter und führen Sie dann den Auftrag aus; BackupZit aktiviert Changed Block Tracking, und spätere Sicherungen lesen nur geänderte Blöcke.
VMware: „copy the disk on the datastore (needs free space …)“Laufende VMs werden kurz auf ihrem Datastore kopiert. Schaffen Sie dort Platz (so viel, wie die Festplatte belegt), oder sichern Sie die VM im ausgeschalteten Zustand.
VMware: „… is a snapshot delta disk“Die VM hat eigene Snapshots. Löschen oder konsolidieren Sie sie im ESXi Host Client (Snapshots → Delete all).
VMware: „the ESXi certificate changed“Der Host wurde neu installiert oder eine andere Maschine antwortet unter seiner Adresse. Ist das erwartet, entfernen Sie den Host unter Agenten und fügen Sie ihn erneut hinzu, um das neue Zertifikat zu pinnen.
VMware: Dateien *.replaced-DATE.vmdk neben VM-FestplattenDie alten Festplatten einer an Ort und Stelle wiederhergestellten VM. Löschen Sie sie im Datastore-Browser, sobald die wiederhergestellte VM funktioniert.
Hyper-V: Dateien *.replaced-DATE neben VM-FestplattenDie alten Festplatten einer an Ort und Stelle wiederhergestellten VM. Löschen Sie sie, sobald die wiederhergestellte VM funktioniert.
Proxmox-Sofortwiederherstellung: Die VM startet nicht oder hängtPrüfen Sie den Festplattenserver: systemctl status backupzit-instant-ID und journalctl -u backupzit-instant-ID auf dem Knoten. Der Sicherungsspeicher muss erreichbar bleiben; kann das Repository nicht gelesen werden, stocken die Lesezugriffe der VM auf ihre Festplatten.
Proxmox-Sofortwiederherstellung: „efidisk0 stays on storage backupzit-instant“QEMU kann den EFI-Variablenspeicher nicht verschieben, während die VM läuft. Fahren Sie die VM herunter und führen Sie qm disk move ID efidisk0 STORAGE --delete 1 aus; das hängt nicht von der Sicherung ab.
Proxmox: „runs on node X; install the BackupZit agent on X“Der Gast wurde migriert. Installieren Sie den Agenten auf jedem Knoten und sichern Sie die Gäste jedes Knotens mit dessen Agenten.
Proxmox-Sicherungen oder -Wiederherstellungen langsam, SFTP „connection lost“, „message authentication code incorrect“ auf dem SpeicherserverBekanntes Problem von Intel-e1000e-Netzwerkkarten in Proxmox-Hosts (Protokoll: „Detected Hardware Unit Hang“, „Reset adapter unexpectedly“). Schalten Sie das Offloading aus: ethtool -K eno1 tso off gso off gro off und tragen Sie es als post-up-Zeile der Schnittstelle in /etc/network/interfaces ein.
Dateien durchsuchen: „stored on a local path of the agent“Die Konsole kann nur Sicherungen auf Netzwerkspeicher lesen. Verwenden Sie backupzit-agent pve ls/extract oder image-ls/image-extract auf dem Agenten.
Linux-System-Wiederherstellung: „missing programs …“Installieren Sie die genannten Pakete auf der wiederherstellenden Maschine, oder starten Sie das BackupZit-Linux-Wiederherstellungs-ISO, das sie enthält.
Die wiederhergestellte Linux-Maschine hat kein NetzwerkDie Netzwerkeinstellungen waren an die alte MAC-Adresse gebunden (netplan match: macaddress). Stellen Sie mit Andere Hardware wieder her oder entfernen Sie die match-Zeilen in /etc/netplan/.
Wiederhergestelltes Windows bleibt mit INACCESSIBLE_BOOT_DEVICE stehenStellen Sie erneut mit Auf andere Hardware wiederherstellen wieder her, oder starten Sie das Wiederherstellungs-ISO und führen Sie backupzit-agent prepare-hardware --disk 0 [--drivers E:\Drivers] aus.
Eine wiederhergestellte Kopie einer Maschine erscheint als der ursprüngliche AgentWiederherstellungen in eine neue Proxmox-VM melden den Agenten in der Kopie automatisch ab. Bei anderen Kopien entfernen Sie agent.json in der Kopie und registrieren Sie sie als neue Maschine.
Das Agenten-Update wird nicht abgeschlossenSiehe das Installationsprotokoll in C:\ProgramData\backupzit\updates bzw. /var/tmp/backupzit-updates; Agenten vor 0.21 müssen einmal von Hand aktualisiert werden.
Das Tray-Symbol fehltKlicken Sie auf den Pfeil ^ neben der Uhr und ziehen Sie das BackupZit-Symbol auf die Taskleiste, oder starten Sie BackupZit Agent aus dem Startmenü.

Eine Sicherung endet mit „Warnung“

Einige Dateien konnten nicht gelesen werden — meist Dateien, die von einer Anwendung gesperrt sind, während VSS nicht verfügbar ist, oder Dateien, für die der Agent keine Berechtigung hat. Die Liste steht auf der Laufseite. Alles andere ist gesichert.

Sicherungen sind langsam

  • Die erste Sicherung liest und lädt alles hoch; spätere lesen nur geänderte Dateien und laden nur neue Daten hoch.
  • Prüfen Sie den Netzwerkweg zum Speicher (WLAN, VPN, Upload-Geschwindigkeit ins Internet bei Cloud-Speicher).
  • Schließen Sie Caches, temporäre Dateien und nicht benötigte Medien aus.

FAQ

Kann ich NFS verwenden?

Um eine NFS- (oder SMB-)Freigabe zu sichern, erstellen Sie einen Auftrag NAS / Dateifreigabe; ein Linux-Agent bindet den Export für jeden Lauf ein. Um Sicherungen auf NFS zu speichern, binden Sie den Export auf dem Agenten ein (Linux: /etc/fstab) und verwenden ein Ziel Lokaler / eingebundener Pfad wie /mnt/nfs-backup; für Windows-Maschinen ist ein SMB-Ziel die bessere Wahl.

Kann ich Sicherungen auf einen anderen Speicher verschieben?

Kopieren Sie den Repository-Ordner (oder Bucket-Präfix) unverändert — er ist in sich geschlossen — und fügen Sie ein Speicherziel hinzu, das mit demselben Wiederherstellungsschlüssel auf den neuen Ort zeigt.

Löscht das Löschen eines Auftrags die Sicherungen?

Nein. Die Sicherungen bleiben auf dem Speicher und lassen sich über Aktivität oder die Befehlszeile wiederherstellen.

Was passiert, wenn die Konsole ausfällt?

Bis sie wieder da ist, starten keine neuen geplanten Sicherungen; eingereihte Läufe werden danach fortgesetzt. Wiederherstellungen sind über die Befehlszeile mit dem Wiederherstellungsblatt immer möglich.

Wie viel Platz brauchen die Sicherungen?

Für die erste Sicherung ungefähr die Datenmenge nach Komprimierung, plus die täglichen Änderungen für jeden aufbewahrten Tag. Die Seite Berichte zeigt, wie viel pro Auftrag hochgeladen wurde.
