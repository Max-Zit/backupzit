Fehlerbehebung & FAQ

Ein Agent wird als offline angezeigt

  • Ist die Maschine eingeschaltet und läuft der Dienst? Windows: Get-Service backupzit-agent; Linux: systemctl status backupzit-agent; macOS: sudo launchctl print system/com.backupzit.agent (siehe macOS-Agenten).
  • Erreicht die Maschine die Konsole? Test-NetConnection backup-server -Port 8443 oder curl -k https://backup-server:8443/login.
  • Agentenprotokoll: C:\ProgramData\backupzit\agent.log, unter Linux /var/log/backupzit/agent.log oder journalctl -u backupzit-agent, unter macOS /Library/Logs/BackupZit/agent.log. „fingerprint mismatch“ bedeutet, dass sich das Konsolenzertifikat geändert hat — registrieren Sie den Agenten erneut.

Eine Sicherung ist fehlgeschlagen

Öffnen Sie den Lauf in Aktivität; die Meldung nennt die Ursache. Häufige Ursachen:

Meldung enthältLösung
host key mismatch / fingerprintDer Schlüssel des SFTP-Servers hat sich geändert oder der Fingerabdruck wurde falsch eingegeben. Prüfen Sie mit ssh-keygen -lf auf dem Server.
permission denied / access deniedZugangsdaten des Speichers oder Ordnerberechtigungen. Testen Sie die Anmeldung mit einem SFTP-/SMB-Client.
no space left / quotaDer Speicher ist voll. Verkürzen Sie die Aufbewahrung oder fügen Sie Platz hinzu; abgelaufene Sicherungen geben nach dem nächsten Lauf Platz frei.
repository is lockedEin anderer Vorgang (z. B. Bereinigung) läuft auf demselben Repository; der Lauf versucht es 30 Minuten lang erneut. Veraltete Sperren laufen automatisch ab.
wrong password / recovery keyDas Repository wurde mit einem anderen Schlüssel angelegt — prüfen Sie, ob der Auftrag das richtige Speicherziel verwendet.
bucket has no Object Lock enabledUnveränderlichkeit wurde für einen Bucket ohne Object Lock angefordert. Erstellen Sie einen neuen Bucket mit Object Lock.
S3 / Azure: "the clock of this computer differs from the storage's by more than 15 minutes" (RequestTimeTooSkewed, Request date header too old)Cloud-Speicher signiert jede Anfrage mit der Uhrzeit und lehnt sie ab, wenn die Uhr um mehr als etwa 15 Minuten abweicht. Korrigieren Sie die Zeit des im Lauf genannten Computers (der Agent; bei Verbindung testen die Konsole) und schalten Sie die Zeitsynchronisierung ein: Windows-Einstellungen → Zeit und Sprache → Uhrzeit automatisch festlegen; Linux timedatectl set-ntp true oder chrony. Virtuelle Maschinen können nach längerem Ausschalten oder über eine Zeitumstellung hinweg eine falsche Zeit haben.

Andere Meldungen

SituationWas tun
„no matching backup disk is connected“Schließen Sie eine der rotierenden USB-Festplatten an (die Meldung nennt das benötigte Label und welche beschrifteten Festplatten angeschlossen sind). Eine Wiederherstellung braucht genau die Festplatte, die im Sicherungslauf angezeigt wird.
„several backup disks are connected“Schließen Sie jeweils nur eine der rotierenden Festplatten an.
Wiederherstellungstest fehlgeschlagenÖffnen Sie den Lauf: Die Meldung nennt die beschädigte Datei bzw. den Block oder den Grund (z. B. Sicherung auf dem Speicher gelöscht). Führen Sie backupzit-agent check --read-data für das Repository aus, prüfen Sie den Speicher und starten Sie eine neue Sicherung. Wurden Sicherungen auf unveränderlichem Speicher gelöscht, siehe Schutz vor Ransomware.
Datenprüfung hat beschädigte Datenpakete gefundenDer Speicher hat Daten verloren oder verändert (etwa durch einen Fehler beim Anbieter). Solange die beschädigten Pakete im Index stehen, verwenden neue Sicherungen ihre Daten weiter. Klicken Sie auf der Seite des Prüflaufs auf Reparieren: beschädigte Daten aus dem Index nehmen oder führen Sie backupzit-agent repair --repo … aus (--dry-run listet nur auf): Der Speicher wird unter exklusiver Sperre erneut gelesen, die beschädigten Pakete verlassen den Index, und der Lauf listet die Sicherungen auf, die die verlorenen Daten brauchen. Sie bleiben und stellen her, was übrig ist; mit Auch die Sicherungen entfernen, die die verlorenen Daten brauchen werden sie entfernt, damit spätere Datenprüfungen und das Freigeben von Speicher nach der Aufbewahrung wieder funktionieren. Das Entfernen verlangt Ihr Passwort oder den Zwei-Faktor-Code, bei aktiver Vier-Augen-Freigabe die Freigabe eines zweiten Benutzers, behält Sicherungen, aus denen eine VM läuft (Sofortwiederherstellung), und wird abgelehnt, solange die Aufbewahrung nach einer verdächtigen Sicherung pausiert ist. Die nächsten Sicherungen speichern diese Daten erneut. Agenten 0.55 und neuer. Seit 0.55 werden nur nachweislich beschädigte Pakete herausgenommen: fehlende oder solche, die beim vollständigen Lesen nicht zu ihrem Inhalt passen. Ein Paket, das bei diesem Agenten nur gekürzt ankommt, während der Speicher es vollständig hat, wird nach einer Pause erneut gelesen, dann aufgeführt und in Ruhe gelassen; prüfen Sie den Netzwerkweg (Proxy, Firewall, IPS, NAT). Die Paketdateien selbst entfernt die nächste Bereinigung. Sicherungen, deren Ordnerlisten von diesem Agenten aus nicht lesbar sind, bleiben erhalten und werden nie als betroffen entfernt. Können 20 Datenpakete hintereinander nicht gelesen werden, endet die Prüfung mit „the storage stopped answering“ und beurteilt nichts: prüfen Sie den Speicher und den Netzwerkweg und starten Sie sie erneut. Seit 0.56 wird ein Paket, das in der Dateiliste des Speichers fehlt, einzeln und mit mehreren Versuchen nachgeschlagen, bevor es als fehlend gilt; eine Liste, die leer ist oder in der die meisten Pakete auf einmal fehlen, führt zu keinem Urteil, und die Prüfung schlägt mit dem Grund fehl, sodass ein Aussetzer des Speichers nie Daten aus dem Index nimmt.
Eine Indexdatei des Repositorys ist beschädigtSeit 0.59 laufen Sicherungen und Wiederherstellungen weiter: Die Pakete, die diese Datei aufführte, werden aus ihren eigenen Kopfdaten gelesen, und neue Sicherungen verwenden deren Daten nicht wieder, bis der Index neu aufgebaut ist. Aufbewahrung, Platzfreigabe und das Entfernen der Sicherungen eines Agenten warten so lange (ältere Wiederherstellungspunkte bleiben, der Lauf warnt). Reparieren baut den Index neu auf: Es listet die Pakete erneut, prüft jedes Paket, das die beschädigte Datei aufführte (drei Versuche), stellt sicher, dass jeder Block, den eine Sicherung verwendet, im neuen Index oder in einem nachweislich beschädigten Paket ist, und schreibt erst dann den neuen Index; die beschädigte Datei bleibt unter index-damaged/, mit dem Schlüssel des Repositorys versiegelt. Verwenden Sicherungen Daten, die kein Paket enthält, nennt die Reparatur sie und hält an: Prüfen Sie, ob alle Datenordner des Speichers da sind, oder aktivieren Sie Auch die Sicherungen entfernen, die die verlorenen Daten brauchen, um sie zu entfernen (nur wenn zwei Auflistungen des Speichers übereinstimmen). Ein Paket, das während der Reparatur verschwindet, hält sie an, ohne etwas zu ändern. Die Platzfreigabe löscht nie ein Paket, das im Index fehlt, wenn es Daten enthält, die eine Sicherung verwendet und die der Index sonst nirgends hat (eine verlorene oder von Hand gelöschte Indexdatei): Sie prüft das Paket und nimmt es wieder in den Index auf. Eine Datenprüfung, die beim Lesen die meisten Pakete nicht mehr findet, obwohl der Speicher sie gerade aufgelistet hat, beurteilt nichts.
Sicherung als verdächtig markiertPrüfen Sie die Maschine auf Ransomware oder eine Massenlöschung (z. B. ein geleerter synchronisierter Ordner). Ist alles in Ordnung (z. B. eine geplante Migration), klicken Sie auf der Auftragsseite auf Geprüft – Aufbewahrung fortsetzen.
Let's Encrypt: „could not verify … is port 80 … reachable“Die HTTP-Prüfung braucht Port 80 aus dem Internet erreichbar. Verwenden Sie für interne Konsolen die DNS-Prüfung über Cloudflare.
Let's Encrypt: „no Cloudflare zone … is accessible with this token“Das Token braucht die Berechtigung Zone → DNS → Edit für die Zone, die den Namen der Konsole enthält.
„HTTPS port 443: … permission denied“ oder „address already in use“Ein anderes Programm nutzt den Port, oder der Dienst darf keine Ports unter 1024 belegen (starten Sie ihn mit CAP_NET_BIND_SERVICE, wie es das Paket tut). Wählen Sie unter Einstellungen → Zertifikat einen anderen Port.
Updates: „updates from the console need the Linux package of the console“Die Konsole wurde nicht aus dem deb/rpm-Paket installiert (zum Beispiel der Testmodus). Aktualisieren Sie sie so, wie sie installiert wurde.
Updates: „the release is not signed with a BackupZit release key“Die Update-Quelle enthält kein offizielles Release, oder die Dateien wurden unterwegs verändert. Laden Sie sie erneut von der offiziellen Adresse herunter.
Updates: Status rolled-backDie neue Version ist nicht gestartet, daher wurden die vorherige Version und ihre Datenbank wiederhergestellt. Das Protokoll des fehlgeschlagenen Starts steht auf der Seite Updates; senden Sie es an den Support.
"The agent is no longer running this"Der Agent wurde während des Laufs neu gestartet oder beendet (zum Beispiel durch einen Neustart des Rechners oder des Dienstes) oder konnte das Ergebnis nicht übermitteln. Agenten ab 0.52.0 melden die Läufe, an denen sie arbeiten, sodass die Konsole einen solchen Lauf nach etwa zwei Minuten als fehlgeschlagen markiert, statt ihn als laufend anzuzeigen, bis jemand ihn stoppt; bei älteren Agenten stoppen Sie ihn auf seiner Seite. Protokoll holen auf der Seite Agenten zeigt, was passiert ist. Der nächste geplante Lauf startet wie gewohnt. Fährt der Agent normal herunter (Dienst gestoppt, Neustart für Updates), endet der Lauf stattdessen mit "The agent was stopped during the run". Unter Windows nehmen Agenten ab 0.62 die Vorab-Meldung zum Herunterfahren an: Windows wartet bis zu drei Minuten, während der Agent den Lauf beendet, das Repository entsperrt und es meldet, bevor das Netzwerk wegfällt.
"agent stopped responding while the run was in progress"Der Agent hat sich während des Laufs länger als 10 Minuten nicht bei der Konsole gemeldet (Netzwerkausfall oder angehaltener Agent-Rechner). Die Zeit, in der die Konsole selbst nicht lief, zählt nicht. Der Agent versucht zwei Stunden lang, sein Ergebnis zu liefern; kommt es an, zeigt der Lauf das echte Ergebnis und seine Sicherung lässt sich wiederherstellen.
Betriebssystem: „no supported package manager“Betriebssystem-Updates werden unter Debian, Ubuntu (apt) und AlmaLinux, Rocky Linux, RHEL (dnf) unterstützt.
Konsolensicherung: „the backup was made by a newer BackupZit“Installieren Sie vor der Wiederherstellung auf der neuen Konsole die Version, mit der die Sicherung erstellt wurde, oder eine neuere.
Konsolensicherung: „console backups need network storage“Wählen Sie ein SFTP-, S3-, SMB-, Azure- oder gehärtetes Repository-Ziel; ein lokaler Pfad eines Agenten ist von der Konsole aus nicht erreichbar.
„Zu viele fehlgeschlagene Anmeldungen“Ihre Adresse wurde nach wiederholt falschen Passwörtern gesperrt: standardmäßig für 30 Minuten, bei wiederholten Sperren länger. Ein Administrator kann die Sperre unter Einstellungen → Anmeldung & Sicherheit aufheben. Auf dem Server hebt backupzit-server --unblock-ip all alle Sperren auf. Konten werden nie dauerhaft gesperrt.
Telefon für die Zwei-Faktor-Anmeldung verlorenVerwenden Sie einen der Wiederherstellungscodes; andernfalls setzt ein Administrator die Zwei-Faktor-Anmeldung auf Ihrer Benutzerseite zurück. Kann sich kein Administrator mehr anmelden, führen Sie auf dem Server backupzit-server --reset-two-factor USER aus (Docker: docker compose exec backupzit backupzit-server --reset-two-factor USER): Das schaltet die Zwei-Faktor-Anmeldung dieses Benutzers aus, meldet ihn ab und wird im Audit-Log festgehalten; melden Sie sich dann mit dem Passwort an und richten Sie sie neu ein.
„your directory account is not in any BackupZit group“Fügen Sie den Benutzer einer der unter Einstellungen → LDAP / Active Directory zugeordneten Gruppen hinzu oder ordnen Sie weitere Gruppen zu. Mit Test sehen Sie dort die für einen Benutzer gefundenen Gruppen.
API liefert 401 / 403401: Token fehlt, wurde widerrufen, ist abgelaufen oder sein Besitzer ist deaktiviert. 403: Die Rolle des Tokens ist für die Anfrage zu niedrig.
Azure: AuthenticationFailed / AuthorizationPermissionMismatchFalscher Kontoschlüssel, oder dem SAS-Token fehlt die Berechtigung zum Lesen, Schreiben, Löschen oder Auflisten, oder es ist abgelaufen.
Eine wiederhergestellte VM mit Windows Server 2012 R2 / Windows 8.1 startet nicht unter Hyper-V Gen 2 („hash was denied (DBX)“)Microsoft hat den alten Bootloader für Secure Boot widerrufen. Schalten Sie Secure Boot für diese VM aus oder aktualisieren Sie das System vor der Sicherung.

Virtuelle Maschinen, Linux-Systeme und neue Hardware

SituationWas tun
Proxmox: „the guest is running and one of its disks is on storage without snapshot support“Laufende Gäste brauchen LVM-thin-, ZFS-, Ceph-RBD- oder qcow2-Festplatten. Verschieben Sie die Festplatte (Disk Action → Move Storage) oder sichern Sie den Gast, während er gestoppt ist.
Proxmox: „container volumes that are directories on dir storage are not supported yet“Das Volume des Containers ist ein Verzeichnis auf einem Verzeichnis-, NFS- oder btrfs-Speicher. Nur Verzeichnisse auf ZFS (Subvolumes) werden Datei für Datei gesichert; verschieben Sie das Volume auf ZFS, LVM-thin oder Ceph RBD (Volume Action → Move Storage).
Hyper-V: Der Lauf meldet „crash-consistent“Der Gast konnte sich nicht auf den Prüfpunkt vorbereiten. Prüfen Sie in Windows-Gästen, dass die Hyper-V-Integrationsdienste (Backup (volume shadow copy)) in den VM-Einstellungen aktiviert sind. In Linux-Gästen installieren Sie hyperv-daemons (RHEL) bzw. linux-cloud-tools / hyperv-daemons (Debian/Ubuntu).
VMware: „SSH off“ oder „SSH to …: connection refused“Aktivieren Sie SSH auf dem ESXi-Host: Host → Actions → Services → Enable Secure Shell (und lassen Sie es mit dem Host starten). Wiederherstellungen und Sicherungen mit der kostenlosen Lizenz brauchen es.
VMware: „changed block tracking is off and can be enabled … only while the VM is off“Kostenlose ESXi-Lizenz: Fahren Sie die VM einmal herunter und führen Sie dann den Auftrag aus; BackupZit aktiviert Changed Block Tracking, und spätere Sicherungen lesen nur geänderte Blöcke.
VMware: „copy the disk on the datastore (needs free space …)“Laufende VMs werden kurz auf ihrem Datastore kopiert. Schaffen Sie dort Platz (so viel, wie die Festplatte belegt), oder sichern Sie die VM im ausgeschalteten Zustand.
VMware: „… is a snapshot delta disk“Die VM hat eigene Snapshots. Löschen oder konsolidieren Sie sie im ESXi Host Client (Snapshots → Delete all); BackupZit rührt sie nie an. Eine VM ohne Snapshots, deren Festplatten nur eine Konsolidierung brauchen (ein Entfernen eines Snapshots, das nicht fertig wurde), konsolidiert der Agent vor ihrer Sicherung (Agent 0.57, vSphere-API); bei der kostenlosen Lizenz führen Sie im Host Client Snapshots → Consolidate aus. Agenten vor 0.58 lehnten außerdem das kleine Delta ab, das ein stillgelegter Snapshot auf manchen Hosts schreibt (ESXi 6.7, VMware Tools laufen), obwohl die VM keine Snapshots hatte: Aktualisieren Sie den Agenten.
VMware: „The session is not authenticated“ oder „401 Unauthorized“Die vSphere-Sitzung endete während des Laufs: bei Agenten vor 0.55 nach einem langen Lesen einer Festplatte, oder wenn die Verwaltungsdienste des Hosts neu starten. Agenten 0.57 melden sich erneut an und machen mit der nächsten VM und dem Entfernen des Snapshots weiter; aktualisieren Sie ältere Agenten. Ein zurückgebliebener Snapshot wird im Dashboard mit Jetzt entfernen aufgeführt.
Dashboard: „Sicherungs-Snapshot … ist auf … zurückgeblieben“, „Sicherungsprüfpunkt …“, „temporäre Festplattenkopie …“ oder „Sicherungssperre“Eine Sicherung konnte nicht entfernen, was sie auf dem Hypervisor erstellt hat (der Agent wurde mittendrin gestoppt, oder das Entfernen schlug fehl); solange der Überrest bleibt, wachsen die Festplatten der VM, oder der Gast lässt sich wegen der Sperre nicht starten. Der Agent versucht es von selbst erneut (Proxmox VE und Hyper-V alle 15 Minuten, VMware bei der nächsten Sicherung der Verbindung). Klicken Sie auf Jetzt entfernen, damit er es sofort versucht; der Bereinigungslauf auf der Seite Aktivität zeigt, was entfernt wurde und warum der Rest fehlschlug (etwa ein ausgelasteter Datastore oder Speicher, eine von einem anderen Programm gesperrte Datei). Schlägt es weiter fehl, entfernen Sie den Überrest mit den Werkzeugen des Hypervisors: vSphere Client (Snapshots → Delete, dann Consolidate), Proxmox VE (qm delsnapshot ID NAME --force, qm unlock ID), Hyper-V-Manager (Checkpoints → Delete). Siehe VMware, Proxmox VE und Hyper-V.
Proxmox: „guest … already has the backup lock“Eine andere Sicherung des Gastes läuft (BackupZit oder vzdump), oder ein unterbrochener Lauf hat die Sperre hinterlassen. Eine selbst gesetzte Sperre entfernt der Agent innerhalb von 15 Minuten; jede andere wird, sobald keine Sicherung läuft, mit qm unlock ID entfernt (Container: pct unlock ID).
VMware: „the ESXi certificate changed“Der Host wurde neu installiert oder eine andere Maschine antwortet unter seiner Adresse. Ist das erwartet, prüfen Sie den Fingerabdruck und klicken Sie auf der Seite Agenten neben dem Host auf Neues Zertifikat akzeptieren.
VMware: Dateien *.replaced-DATE.vmdk neben VM-FestplattenDie alten Festplatten einer an Ort und Stelle wiederhergestellten VM. Löschen Sie sie im Datastore-Browser, sobald die wiederhergestellte VM funktioniert.
Hyper-V: alte VHDX-Dateien nach einer Wiederherstellung an Ort und StelleDie Wiederherstellung trennt die alten Festplatten der VM und lässt sie, wo sie waren (der Lauf listet jede auf: old disk kept at …); die wiederhergestellten Festplatten liegen in einem Unterordner backupzit-restore-…. Löschen Sie die alten Dateien, sobald die wiederhergestellte VM funktioniert.
Proxmox-Sofortwiederherstellung: Die VM startet nicht oder hängtPrüfen Sie den Festplattenserver: systemctl status backupzit-instant-ID und journalctl -u backupzit-instant-ID auf dem Knoten. Der Sicherungsspeicher muss erreichbar bleiben; kann das Repository nicht gelesen werden, stocken die Lesezugriffe der VM auf ihre Festplatten.
Proxmox-Sofortwiederherstellung: „efidisk0 stays on storage backupzit-instant“QEMU kann den EFI-Variablenspeicher nicht verschieben, während die VM läuft. Fahren Sie die VM herunter und führen Sie qm disk move ID efidisk0 STORAGE --delete 1 aus; das hängt nicht von der Sicherung ab.
Proxmox: „runs on node X; install the BackupZit agent on X“Der Gast wurde migriert. Installieren Sie den Agenten auf jedem Knoten und sichern Sie die Gäste jedes Knotens mit dessen Agenten.
Proxmox-Sicherungen oder -Wiederherstellungen langsam, SFTP „connection lost“, „message authentication code incorrect“ auf dem SpeicherserverBekanntes Problem von Intel-e1000e-Netzwerkkarten in Proxmox-Hosts (Protokoll: „Detected Hardware Unit Hang“, „Reset adapter unexpectedly“). Schalten Sie das Offloading aus: ethtool -K eno1 tso off gso off gro off und tragen Sie es als post-up-Zeile der Schnittstelle in /etc/network/interfaces ein.
Dateien durchsuchen: „stored on a local path of the agent“Die Konsole kann nur Sicherungen auf Netzwerkspeicher lesen. Verwenden Sie backupzit-agent pve ls/extract oder image-ls/image-extract auf dem Agenten.
Speicherziel hinzufügen oder testen: „Verbindungstest fehlgeschlagen … ob die Konsole den Speicher erreicht“, obwohl die Sicherungen der Agenten funktionierenDie Konsole erreicht den Speicher nicht, zum Beispiel ein NAS im Netzwerk eines Kunden, während die Konsole auf einem VPS läuft. Testen Sie ihn von einem Agenten an diesem Standort aus (Verbindung testen, dann den Agenten wählen), und markieren Sie das Ziel als nur für Agenten erreichbar, damit sich die Konsole nicht mehr damit verbindet. Das Durchsuchen von Dateien liest seine Sicherungen dann über einen Agenten an diesem Standort (Agenten ab 0.61).
Linux-System-Wiederherstellung: „missing programs …“Installieren Sie die genannten Pakete auf der wiederherstellenden Maschine, oder starten Sie das BackupZit-Linux-Wiederherstellungs-ISO, das sie enthält.
Die wiederhergestellte Linux-Maschine hat kein NetzwerkDie Netzwerkeinstellungen waren an die alte MAC-Adresse gebunden (netplan match: macaddress). Stellen Sie mit Andere Hardware wieder her oder entfernen Sie die match-Zeilen in /etc/netplan/.
Wiederhergestelltes Windows bleibt mit INACCESSIBLE_BOOT_DEVICE stehenStellen Sie erneut mit Auf andere Hardware wiederherstellen wieder her, oder starten Sie das Wiederherstellungs-ISO und führen Sie backupzit-agent prepare-hardware --disk 0 [--drivers E:\Drivers] aus.
Eine wiederhergestellte Kopie einer Maschine erscheint als der ursprüngliche AgentEin als neue VM wiederhergestelltes Linux-System wird automatisch abgemeldet. Bei anderen Kopien (eine als neue VM wiederhergestellte VM, Sofortwiederherstellung, ein Replikat, eine geklonte Festplatte) hält die Konsole die Läufe des Agenten an und zeigt zwei Rechner; registrieren Sie die Kopie als neue Maschine (siehe Zwei Rechner mit einem Agenten).
Das Agenten-Update wird nicht abgeschlossenSiehe das Installationsprotokoll in C:\ProgramData\backupzit\updates, /var/lib/backupzit-agent/updates bzw. /Library/Application Support/BackupZit/updates (macOS); Agenten vor 0.21 müssen einmal von Hand aktualisiert werden.
Mac: „Full Disk Access is not granted“, Dateien „without a snapshot“ gelesen, Festplattenvollzugriff nach einem Update verlorenSiehe macOS-Agenten: Nur der Benutzer des Macs kann den Festplattenvollzugriff erteilen, und ein nicht signiertes Paket verliert ihn bei jedem Update.
„… is a Mac: back it up with a files job“Ein Mac lässt sich nicht als System sichern; verwenden Sie einen Dateiauftrag (macOS-Agenten).
Das Tray-Symbol fehltKlicken Sie auf den Pfeil ^ neben der Uhr und ziehen Sie das BackupZit-Symbol auf die Taskleiste, oder starten Sie BackupZit Agent aus dem Startmenü.

Eine Sicherung endet mit „Warnung“

Einige Dateien konnten nicht gelesen werden — meist Dateien, die von einer Anwendung gesperrt sind, während VSS nicht verfügbar ist, oder Dateien, für die der Agent keine Berechtigung hat. Die Liste steht auf der Laufseite. Alles andere ist gesichert. Auf einem Mac führt auch ein fehlender Festplattenvollzugriff zu einer Warnung (macOS-Agenten).

Dateien nur in der Cloud. iCloud Drive auf einem Mac (Mac-Speicher optimieren) und OneDrive unter Windows (Dateien bei Bedarf, als nur online verfügbar markierte Dateien) behalten den Inhalt vieler Dateien nur in der Cloud. Eine Sicherung kann sie nicht lesen, und seit 0.60 versucht der Agent es nicht. Eine Datei, die in der vorherigen Sicherung unverändert enthalten ist, behält ihren Inhalt von dort. Die anderen werden ausgelassen und getrennt von den Lesefehlern pro Ordner unter Nur in der Cloud, nicht gesichert auf der Laufseite aufgeführt. Der Lauf endet mit einer Warnung, weil dieser Inhalt nicht in der Sicherung ist. Laden Sie die Dateien vor der Sicherung auf den Computer (Mac: Finder → Jetzt laden; Windows: Rechtsklick → Immer auf diesem Gerät beibehalten) oder schalten Sie Mac-Speicher optimieren aus. OneDrive für Arbeit oder Schule lässt sich auch mit einem Microsoft 365-Auftrag aus der Cloud sichern, nur online verfügbare Dateien eingeschlossen. Siehe auch Dateien in iCloud Drive.

Sicherungen sind langsam

  • Die erste Sicherung liest und lädt alles hoch; spätere lesen nur geänderte Dateien und laden nur neue Daten hoch.
  • Prüfen Sie den Netzwerkweg zum Speicher (WLAN, VPN, Upload-Geschwindigkeit ins Internet bei Cloud-Speicher).
  • Schließen Sie Caches, temporäre Dateien und nicht benötigte Medien aus.

FAQ

Kann ich NFS verwenden?

Um eine NFS- (oder SMB-)Freigabe zu sichern, erstellen Sie einen Auftrag NAS / Dateifreigabe; ein Linux-Agent bindet den Export für jeden Lauf ein. Um Sicherungen auf NFS zu speichern, binden Sie den Export auf dem Agenten ein (Linux: /etc/fstab) und verwenden ein Ziel Lokaler / eingebundener Pfad wie /mnt/nfs-backup; für Windows-Maschinen ist ein SMB-Ziel die bessere Wahl.

Kann ich Sicherungen auf einen anderen Speicher verschieben?

Kopieren Sie den Repository-Ordner (oder Bucket-Präfix) unverändert — er ist in sich geschlossen — und fügen Sie ein Speicherziel hinzu, das mit demselben Wiederherstellungsschlüssel auf den neuen Ort zeigt.

Löscht das Löschen eines Auftrags die Sicherungen?

Nein. Die Sicherungen bleiben auf dem Speicher und lassen sich über Aktivität oder die Befehlszeile wiederherstellen. Kopieraufträge des gelöschten Auftrags werden mit ihm gelöscht; die von ihnen erstellten Kopien bleiben auf ihrem Speicher.

Was passiert, wenn die Konsole ausfällt?

Bis sie wieder da ist, starten keine neuen geplanten Sicherungen; danach läuft jeder Auftrag, dessen geplante Zeit verstrichen ist, einmal (sofern sein Sicherungsfenster nicht vorbei ist), und eingereihte Läufe werden fortgesetzt. Wiederherstellungen sind über die Befehlszeile mit dem Wiederherstellungsblatt immer möglich.

Wie viel Platz brauchen die Sicherungen?

Für die erste Sicherung ungefähr die Datenmenge nach Komprimierung, plus die täglichen Änderungen für jeden aufbewahrten Tag. Die Seite Berichte zeigt, wie viel pro Auftrag hochgeladen wurde.
