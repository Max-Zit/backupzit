Virtuelle Hyper-V-Maschinen

BackupZit sichert virtuelle Hyper-V-Maschinen über den Agenten auf dem Hyper-V-Host; in den VMs wird nichts installiert. Windows- und Linux-Gäste werden erfasst, während sie weiterlaufen. Sie können sie als neue VM oder anstelle des Originals wiederherstellen.

Einrichtung

  1. Installieren Sie das MSI des Windows-Agent von Agenten auf dem Hyper-V-Host und registrieren Sie ihn. Unterstützte Hosts: Windows Server 2016 oder neuer mit der Hyper-V-Rolle oder Windows 10/11 mit Hyper-V. In einem Cluster installieren Sie den Agenten auf jedem Host.
  2. Innerhalb einer Minute erscheint der Host auf der Seite Agenten mit dem Kennzeichen Hyper-V · N VMs.
  3. Wählen Sie unter Sicherungsaufträge diesen Agenten und Virtuelle Maschinen (Proxmox VE, Hyper-V, VMware). Wählen Sie dann eines:
    • alle VMs des Hosts, was auch später erstellte VMs abdeckt;
    • einzelne VMs, indem Sie sie markieren.

Der Agent arbeitet über die eigenen Schnittstellen von Hyper-V: das Hyper-V-PowerShell-Modul und die Windows Virtual Disk API. Die Konsole speichert keine Hyper-V-Zugangsdaten.

Wie eine VM gesichert wird

  1. Ein temporärer Wiederherstellungsprüfpunkt (recovery checkpoint, backupzit_…) wird erstellt. Das ist der Prüfpunkttyp, den Hyper-V für Sicherungsanwendungen bereitstellt. Hyper-V bittet den Gast, sich darauf vorzubereiten:
    • Windows-Gäste leeren ihre Anwendungspuffer über VSS.
    • Linux-Gäste frieren ihre Dateisysteme ein, wenn die Hyper-V-Daemons installiert sind (hyperv-daemons / hv-vss-daemon).
    Kann der Gast keines von beiden, wird der Prüfpunkt absturzkonsistent erstellt. Die Laufseite zeigt, welche Art verwendet wurde.
  2. Der Wiederherstellungsprüfpunkt schaltet Resilient Change Tracking (RCT) für die Festplatten der VM ein; daneben sehen Sie .rct- und .mrt-Dateien. Die erste Sicherung liest die ganzen Festplatten. Danach meldet RCT, welche Blöcke sich seit der vorigen Sicherung geändert haben, und nur diese werden gelesen.
  3. Die Festplatten werden im Stand des Prüfpunkts über die Virtual Disk API in Blöcken zu 1 MiB gelesen. Das umfasst VHDX- und VHD-Dateien, einschließlich Ketten früherer Prüfpunkte. Leere Blöcke werden nicht gespeichert, und Blöcke, die bereits im Repository liegen, werden nicht erneut hochgeladen.
  4. Der Prüfpunkt wird entfernt, und Hyper-V führt ihn im Hintergrund zusammen.
  5. Die Konfiguration der VM wird mit der Sicherung gespeichert: Generation, CPU, Arbeitsspeicher, Netzwerkadapter (Switch, VLAN, MAC-Adresse), Festplattencontroller, Secure Boot und TPM.

Ausgeschaltete VMs werden direkt gelesen, ohne Prüfpunkt. Auf Hosts älter als Windows Server 2016 (keine Wiederherstellungsprüfpunkte) wird ein Produktionsprüfpunkt verwendet, und jede Sicherung liest die ganzen Festplatten.

Beispiel aus dem Testlabor: eine Linux-VM mit einer 3-GB-Festplatte. Die erste Sicherung las 3 GB. Die nächste, nach 64 MB neuen Daten, las 96 MB.

Unter Windows 10/11 erstellt Hyper-V beim Start einer VM einen automatischen Prüfpunkt, sofern diese Option in den VM-Einstellungen nicht ausgeschaltet ist. BackupZit kommt mit solchen Prüfpunkten zurecht, aber bei Servern sollten Sie automatische Prüfpunkte ausschalten (VM-Einstellungen → Prüfpunkte).

Eine VM wiederherstellen

Öffnen Sie den Lauf der VM-Sicherung (über die Auftragsseite oder Aktivität) und verwenden Sie Eine Hyper-V-VM wiederherstellen.

Als neue VM neben dem Original

Erstellt eine zweite VM mit neuen MAC-Adressen, sodass sie im selben Netz wie das Original laufen kann. Standardmäßig wird sie nach dem Original plus „restored“ und dem Datum benannt. Automatische Prüfpunkte werden bei ihr ausgeschaltet (Windows schaltet sie für neue VMs ein), sodass ihr Start keine Prüfpunktdateien hinterlässt. Läuft die Kopie neben dem Original und enthält sie den BackupZit-Agenten, siehe Zwei Maschinen mit einem Agenten.

Netzwerkeinstellungen im Gast, die an eine MAC-Adresse gebunden sind, gelten nicht für die neuen Adapter. Ein Beispiel ist match: macaddress von netplan, das Linux-Cloud-Images verwenden.

Anstelle der Original-VM

Aktivieren Sie ausschalten und ihre Datenträger ersetzen. BackupZit dann:

  • schaltet die vorhandene VM aus;
  • führt ihre Prüfpunkte zusammen;
  • tauscht ihre Festplatten gegen die wiederhergestellten.

Die VM behält ihre ID, Netzwerkadapter und MAC-Adressen, sodass Aufträge, Überwachung und das Netzwerk des Gasts weiter funktionieren.

Die alten Festplattendateien werden nicht gelöscht, sondern in ….replaced-DATE umbenannt. Löschen Sie sie, sobald die wiederhergestellte VM funktioniert.

Existiert die Original-VM nicht mehr, wird sie neu erstellt, mit einer neuen Hyper-V-ID.

Optionen

  • Ordner für die virtuellen Festplatten: der Standardordner des Hosts oder ein beliebiger Ordner mit VM-Festplatten. Eine Wiederherstellung an Ort und Stelle legt die neuen Festplatten neben die ursprünglichen.
  • VM nach der Wiederherstellung starten.

Was eine wiederhergestellte VM erhält

  • Virtuelle Switches werden nach Namen verbunden. Gibt es einen Switch auf dem Host nicht, bleibt der Adapter getrennt.
  • Jede wiederhergestellte VM erhält eine neue Generations-ID, sodass Active-Directory-Domänencontroller die Wiederherstellung sicher erkennen.

Einzelne Dateien wiederherstellen

Klicken Sie in der VM-Tabelle des Laufs auf Dateien durchsuchen, um die Partitionen und Volumes auf den Festplatten der VM zu sehen. Sie können NTFS, ext2/3/4 und XFS durchsuchen, auch innerhalb von LVM. Von dort laden Sie Dateien herunter oder stellen sie auf einem beliebigen Agenten wieder her. Es funktioniert genau wie bei Proxmox VE.

Befehlszeile

Führen Sie dies auf dem Hyper-V-Host als Administrator aus:

backupzit-agent hyperv list
backupzit-agent hyperv backup  --repo ... [--vmid N,N]
backupzit-agent hyperv restore --repo ... --vmid N [--new] [--name NAME] [--folder D:\VMs] [--overwrite] [--start] SNAPSHOT|latest
  • --vmid ist die von hyperv list angezeigte Nummer. BackupZit leitet sie aus der GUID der VM ab.
  • Ohne --new wird die VM an Ort und Stelle wiederhergestellt.
  • --overwrite bestätigt, dass die Festplatten einer vorhandenen VM ersetzt werden sollen.

Die Repository-Optionen sind dieselben wie bei allen Befehlen; siehe Befehlszeilenreferenz.

Noch nicht enthalten

  • Einige Festplattentypen. Freigegebene VHDX (Shared VHDX), VHD-Sets und Pass-Through-Festplatten werden nicht gesichert.
