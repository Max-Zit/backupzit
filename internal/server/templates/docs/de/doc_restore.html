Wiederherstellen

Jede erfolgreiche Sicherung lässt sich wiederherstellen: vollständig oder nur ausgewählte Ordner, auf denselben Rechner, auf einen anderen Agenten oder als neue virtuelle Maschine.

Der Wiederherstellungsassistent

Klicken Sie im Menü auf Wiederherstellen. Der Assistent stellt vier Fragen:

  1. Was möchten Sie wiederherstellen?
    • eine ganze virtuelle Maschine
    • Dateien aus einer virtuellen Maschine
    • Dateien und Ordner
    • ein Festplattenabbild / Bare Metal
    • Dateien aus einem Festplattenabbild
    • eine Datenbank (zu einem Zeitpunkt)
    • ein ganzes Linux-System
    • Microsoft-365-E-Mail, OneDrive, Kalender und Kontakte sowie SharePoint-Dateien (siehe Microsoft 365)
    Jede Auswahl zeigt, wie viele Wiederherstellungspunkte es dafür gibt.
  2. Quelle: die virtuelle Maschine (über alle Hypervisoren und Aufträge hinweg) oder der Sicherungsauftrag und sein Rechner.
  3. Wiederherstellungspunkt: die Sicherung, aus der wiederhergestellt wird, die neueste zuerst, mit Status, Speicher und Größe.
    • Als verdächtig markierte Sicherungen (mögliche Ransomware) sind gekennzeichnet.
    • Kopien auf sekundärem Speicher, die ein Sicherungskopie-Auftrag erstellt hat, sind als Kopie aufgeführt (Datei- und VM-Sicherungen).
  4. Optionen: wohin und wie wiederhergestellt wird. Über den Optionen wird eine Zusammenfassung Ihrer Auswahl angezeigt.

Die Schritte oben sind Links, sodass Sie zu jedem früheren Schritt zurückkehren können. Jeder Schritt hat seine eigene Adresse, sodass Sie ihn als Lesezeichen speichern oder teilen können.

Die Optionen sind dieselben wie auf der Seite einer Sicherung in Aktivität, wo Sie eine Wiederherstellung auch direkt starten können. Nur Benutzer, deren Rolle wiederherstellen darf, sehen den Assistenten.

Aus einer Dateisicherung wiederherstellen

  1. Wählen Sie im Wiederherstellungsassistenten Dateien und Ordner, dann den Auftrag und den Wiederherstellungspunkt. Alternativ öffnen Sie die Sicherung in Aktivität oder auf der Auftragsseite.
  2. Wählen Sie unter Dateien aus dieser Sicherung wiederherstellen den Agenten, der die Dateien erhalten soll. Das kann ein anderer Rechner sein als der gesicherte — zum Beispiel ein Ersatz-PC.
  3. Wählen Sie, wohin:
    • In einen Ordner wiederherstellen (empfohlen) — z. B. D:\Restore. Darunter wird die ursprüngliche Struktur nachgebildet: D:\Restore\C\Users\ana\Documents\…. Nichts Vorhandenes wird angetastet.
    • Am ursprünglichen Ort wiederherstellen — schreibt die Dateien dorthin zurück, wo sie waren, und überschreibt aktuelle Versionen. Bei einer NAS-Freigabe verbindet der Agent die Freigabe erneut, beschreibbar. Sparse-Dateien (VM-Abbilder, Datenbanken) werden wieder als Sparse-Dateien angelegt. Unter Windows wird nur eine Datei wieder als sparse markiert, die sparse war; andere, etwa VHD/VHDX-Festplatten (Hyper-V lehnt Sparse-Festplatten ab), werden als normale Dateien wiederhergestellt, ebenso alle Dateien von Sicherungen, die mit Agenten vor 0.57 erstellt wurden, da diese das Attribut nicht festgehalten haben. Durch eine symbolische Verknüpfung oder Junction, die im Weg liegt, wird nie geschrieben: Beim Wiederherstellen in einen Ordner wird sie durch einen Ordner ersetzt, und jede Wiederherstellung schreibt nur in die Ordner, die sie geöffnet hat, auch wenn währenddessen eine Verknüpfung auftaucht (0.58: auch bei Dateisicherungen und am ursprünglichen Ort; das Stammverzeichnis eines Volumes wie / oder C: kann nicht als Ordner für Dateien aus VM- und Abbildsicherungen gewählt werden). Am ursprünglichen Ort werden nur Verknüpfungen des Systems verfolgt (Eigentümer root oder der Benutzer des Agenten unter Linux, SYSTEM, TrustedInstaller oder ein Administrator unter Windows, und niemand sonst darf sie ändern oder ersetzen: Die alten Kompatibilitätsverknüpfungen in Benutzerprofilen wie Application Data werden nicht verfolgt); eine Verknüpfung auf einen Ordner, der nicht existiert, ist ein Fehler, und an ihrem Ziel wird nichts angelegt. Eigentümer, Berechtigungen und Attribute werden an der wiederhergestellten Datei selbst gesetzt, nie über eine Verknüpfung, die an ihre Stelle gelegt wurde. Seit 0.59 muss eine solche Verknüpfung außerdem nur einen Namen haben: ein harter Link darauf, den ein anderer Benutzer anlegen könnte, wird nicht verfolgt.
  4. Beschränken Sie optional auf Nur diese Pfade, einen pro Zeile, z. B. C:\Users\ana\Documents\Contracts — oder wählen Sie sie im Dateibrowser aus (siehe unten).
  5. Lassen Sie Wiederhergestellte Dateien prüfen eingeschaltet: Jede Datei wird zurückgelesen und mit der Prüfsumme in der Sicherung verglichen.
  6. Klicken Sie auf Wiederherstellung starten. Fortschritt und Ergebnisse erscheinen auf der Seite des Wiederherstellungslaufs.

Dateizeiten, Windows-Attribute (versteckt, schreibgeschützt, …) und unter Linux Besitzer, Berechtigungen (einschließlich setuid-Bits), ACLs, erweiterte Attribute (SELinux-Labels, Datei-Capabilities), symbolische und harte Links werden ebenfalls wiederhergestellt. Unter macOS außerdem die BSD-Datei-Flags (versteckt, geschützt…), die Erstellungszeit und die erweiterten Attribute (siehe macOS-Agenten). Besitzer werden nur gesetzt, wenn der Agent als root/Administrator läuft.

Dateien durchsuchen, herunterladen und auswählen

Beim Sicherungslauf zeigt Dateien durchsuchen die gesicherten Ordner so, wie sie waren (auch bei NAS-Freigaben und Linux-Systemsicherungen). Öffnen Sie Ordner, haken Sie Dateien und Ordner an und dann:

  • Herunterladen — eine Datei kommt unverändert, mehrere Dateien oder Ordner als ZIP-Archiv, direkt im Browser. Downloads werden im Audit-Protokoll festgehalten.
  • Oder auf einem Agenten wiederherstellen — in einen Ordner oder an den ursprünglichen Ort, wie eine Wiederherstellung mit Nur diese Pfade.

Ein symbolischer Link auf eine Datei (z. B. /etc/os-release) wird als die Datei heruntergeladen, auf die er zeigt, wenn diese in der Sicherung ist; Links auf Ordner werden in ZIP-Archiven ausgelassen. Dasselbe gilt für Dateien, die aus VM-Sicherungen heruntergeladen werden (ext4, XFS). Eine Wiederherstellung auf einem Agenten legt Links wieder als Links an.

Die Konsole liest die Sicherung selbst vom Speicher, daher funktioniert das Durchsuchen für Sicherungen auf Netzwerkspeicher (SFTP, S3, SMB, Azure, gehärtetes Repository); Speicher, der nur für Agenten erreichbar ist, liest sie über einen Agenten, der ihn verwendet (Agenten ab 0.61). Bei einem lokalen Datenträger oder einem USB-Datenträger eines Agenten stellen Sie mit den Pfaden wieder her. Benutzer mit einer Wiederherstellungsrolle dürfen durchsuchen und herunterladen.

Die richtige Sicherung finden: Im Kalender sehen Sie, welche Sicherungen an welchem Tag liefen, oder nutzen Sie den Verlauf auf der Auftragsseite.

Einzelne Dateien aus einem Festplattenabbild wiederherstellen

Bei Abbildsicherungen klicken Sie im Sicherungslauf auf Dateien durchsuchen. Sie können das NTFS-Dateisystem im Abbild direkt in der Konsole durchsuchen, Dateien und Ordner anhaken und sie auf einen beliebigen Agenten wiederherstellen — ohne die ganze Festplatte wiederherzustellen. Beim Wiederherstellen in einen Ordner erhalten die Dateien dieselbe Struktur wie bei einer Dateisicherung: Der Laufwerksbuchstabe wird zum ersten Ordner (D:\Restore\C\Users\…).

Sie können die angehakten Dateien auch direkt im Browser herunterladen: eine Datei kommt unverändert, mehrere Dateien oder Ordner als ZIP-Archiv — praktisch für ein einzelnes Dokument aus einer großen Image-Sicherung. Wie das Durchsuchen funktioniert es für Image-Sicherungen auf Netzwerkspeicher, erfordert die Berechtigung Wiederherstellen, und das Audit-Log hält fest, welche Pfade heruntergeladen wurden.

Einzelne Dateien aus einer VM wiederherstellen (Proxmox VE, Hyper-V, VMware)

Klicken Sie in einem VM-Sicherungslauf neben dem Gast auf Dateien durchsuchen. Die Konsole zeigt die Partitionen und LVM-Volumes seiner Festplatten und lässt Sie NTFS-, ext4- und XFS-Dateisysteme durchsuchen. Laden Sie die angehakten Dateien herunter (mehrere als ZIP-Archiv) oder stellen Sie sie auf einem beliebigen Agenten wieder her. Siehe Proxmox VE, Hyper-V und VMware ESXi. Auf einem Agenten wiederhergestellte Dateien behalten die Unix-Rechte aus der VM (ext4, XFS), sodass wiederhergestellte Geheimnisse wie /etc/shadow privat bleiben; Dateien von NTFS-Volumes kann unter Linux nur ihr Besitzer lesen. Bei der Wiederherstellung auf einem Windows-Agenten werden Namen mit : aus Linux-Gästen (ext4, XFS) übersprungen und aufgeführt: Windows würde den Teil nach dem Doppelpunkt als Datenstrom einer anderen Datei lesen. Alternative NTFS-Datenströme werden als Datenströme wiederhergestellt.

Ganze Rechner wiederherstellen

  • Windows-Festplattenabbilder: auf eine Festplatte oder Bare Metal, auch auf andere Hardware — Festplattenabbilder.
  • Linux-Systeme: auf eine Festplatte oder Bare Metal oder als neue Proxmox-VM — Linux-Systemsicherung.
  • Proxmox-VMs und -Container: als neuer Gast oder an Ort und Stelle — Proxmox VE. Proxmox-VMs können auch sofort aus der Sicherung laufen und während des Betriebs auf Speicher verschoben werden (Sofortwiederherstellung).
  • Datenbanken (SQL Server, PostgreSQL, MySQL/MariaDB): unter neuem Namen oder an Ort und Stelle, zu einem Zeitpunkt — Datenbanken.
  • Hyper-V-VMs: als neue VM oder an Ort und Stelle (behält ID und MAC-Adressen) — Hyper-V.
  • VMware-ESXi-VMs: als neue VM oder an Ort und Stelle (behält UUID und MAC-Adressen), auf jedem ESXi-Host und Datastore — VMware ESXi; auch sofort aus der Sicherung über einen Linux-Proxy-Agenten, danach auf einen Datastore kopiert (Sofortwiederherstellung).

Wiederherstellungs-ISOs

Bare-Metal-Wiederherstellungen starten den Rechner von einem Wiederherstellungs-ISO (auf einem USB-Stick oder an eine VM angehängt), siehe Wiederherstellungsmedien:

  • Linux-Wiederherstellungs-ISO — wird mit jeder Version veröffentlicht (backupzit-recovery-linux.iso); die Seite Wiederherstellungsmedien verlinkt es aus der Update-Quelle.
  • Windows-Wiederherstellungs-ISO — Windows PE darf nicht weitergegeben werden, daher wird es einmal auf einem beliebigen Windows-10/11- oder Server-PC erstellt:
    1. Installieren Sie das kostenlose Windows ADK (Funktion Deployment Tools) und das Windows-PE-Add-on von Microsoft.
    2. Laden Sie build-winpe.ps1 aus der Version herunter (neben den Agentenpaketen) und nehmen Sie backupzit-agent.exe aus C:\Program Files\backupzit Agent eines Rechners mit dem Agenten.
    3. In einer Administrator-PowerShell: .\build-winpe.ps1 -AgentExe .\backupzit-agent.exe -Out .\backupzit-recovery.iso. Fügen Sie -DriverDir C:\Drivers für Speicher- oder Netzwerktreiber hinzu (z. B. VirtIO für Proxmox-VMs) und -RecoveryJson .\recovery.json, damit es ohne Eingabe verbindet.
    4. Beim Start sucht das ISO auf jedem Laufwerk nach der Datei \backupzit\recovery.json. Mit ihr verbindet sich der Wiederherstellungsagent mit dieser Konsole, und die Wiederherstellung wird hier gestartet; jemand vor Ort muss also nur den Stick booten. Ohne sie öffnet sich das grafische Wiederherstellungsprogramm (backupzit-recovery.exe, neben dem Agenten installiert): Datenträgerabbild oder einzelne Partitionen wiederherstellen, auch auf eine kleinere oder größere Festplatte, Boot reparieren, Treiber laden. Über die Eingabeaufforderung des Mediums lässt sich das jeweils andere starten (backupzit-recovery oder backupzit-agent recovery). Mit -AccessPackage .\backupzit.bzaccess (erstellt unter Wiederherstellungsmedien) öffnet das Programm die Sicherungen ohne diese Konsole; nötig ist nur die Passphrase. Sie braucht 12 Zeichen aus drei Zeichenarten (16 aus zwei, 20 aus einer), und gängige Passwörter werden abgelehnt; die Seite bietet eine erzeugte an, die sich auf QWERTY-, QWERTZ- und AZERTY-Tastaturen gleich tippt.
    5. Sprache und Tastatur von Windows PE sind wie die Zeitzone die des PCs, der das ISO erstellt (-Language de-de, -KeyboardLayout und -TimeZone wählen andere), sodass sich eine Serveradresse oder Passphrase wie auf diesem PC tippt. Das Wiederherstellungsprogramm spricht die 14 Sprachen der Konsole. -NoUi baut nur den Konsolen-Agenten ein. Das Medium enthält die Lizenztexte und SOURCE-CODE.txt in \backupzit\.
    6. Vor dem Schreiben prüft das Programm die Zielfestplatte erneut nach Größe, Modell, Seriennummer und ID der Partitionstabelle: Eine Festplatte, die inzwischen die gewählte Nummer bekommen hat (ein wieder eingesteckter USB-Datenträger), wird abgelehnt, ebenso die Festplatten mit den Sicherungen, dem Wiederherstellungsmedium und einem Zugangspaket. Eine Wiederherstellung auf die Originalfestplatte behält das Layout der Sicherung, wenn es passt (keine Partition wächst in eine Lücke); An Zieldisk anpassen wird bei einer kleineren Festplatte oder auf Wunsch vorgeschlagen. Eine nach GPT oder MBR umgewandelte Festplatte kann nicht offline bleiben. Die Bootreparatur sichert die Bootdaten vorher nach \backupzit auf einem anderen Laufwerk.
    7. Das Programm lässt sich allein mit der Tastatur bedienen (Tab, Enter, Leertaste, Esc) und funktioniert auf Bildschirmen bis 800×600, wo seine Seiten scrollen. Die Zusammenfassung nennt in Rot die Festplatte, die gelöscht wird (Nummer, Modell, Größe); die Wiederherstellung startet erst, wenn diese Nummer eingetippt ist. Ein SFTP-Ort ohne Zugangspaket zeigt den Hostschlüssel des Servers und fragt, bevor er ihm vertraut: Vergleichen Sie ihn mit ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub auf dem Server.
    8. Kopieren Sie das ISO optional in das Verzeichnis /var/lib/backupzit/dist der Konsole; es wird dann auf der Seite Wiederherstellungsmedien angeboten.

Das Durchsuchen von Dateien in der Konsole funktioniert für Sicherungen auf Netzwerkspeicher (SFTP, S3, SMB, Azure, gehärtetes Repository): Die Konsole liest sie direkt oder, bei Speicher, der nur für Agenten erreichbar ist, über einen Agenten, der ihn verwendet (auch mit SSH-Schlüssel; Agenten ab 0.61). Für Sicherungen auf einem lokalen Datenträger eines Agenten oder auf SFTP mit SSH-Schlüssel funktioniert eine Wiederherstellung mit Nur diese Pfade aus der Konsole weiterhin; um hineinzusehen, verwenden Sie die Befehlszeile.

Ohne die Konsole wiederherstellen

Geht die Konsole selbst verloren, kann jeder Rechner mit installiertem Agenten mit dem Wiederherstellungsblatt des Speicherziels direkt vom Speicher wiederherstellen:

set BACKUPZIT_PASSWORD=<recovery key>
set BACKUPZIT_SFTP_PASSWORD=...           (or the S3/SMB/hardened credentials)
set BACKUPZIT_SFTP_HOSTKEY=SHA256:...      (the SFTP host key, on the recovery sheet)
backupzit-agent snapshots --repo sftp://backup@nas:22/backups/pc1_1a2b3c4d
backupzit-agent restore   --repo sftp://backup@nas:22/backups/pc1_1a2b3c4d --target D:\Restore latest

latest ist die neueste Sicherung eines beliebigen Auftrags dieses Computers; um einen bestimmten Auftrag wiederherzustellen, verwenden Sie eine Snapshot-ID aus snapshots. Siehe Befehlszeilenreferenz.

Automatische Wiederherstellungstests

BackupZit prüft Ihre Sicherungen regelmäßig, ohne dass Sie etwas tun: Wöchentlich (einstellbar unter Einstellungen → Wiederherstellungstests) stellt der Agent jedes Auftrags eine Zufallsstichprobe von Dateien aus der neuesten Sicherung in einen temporären Ordner wieder her, prüft jedes Byte gegen die gespeicherten Prüfsummen und löscht sie wieder. Bei Festplattenabbildern werden zufällige Blöcke gelesen und geprüft. So wird die ganze Kette geprüft — Speicherzugriff, Zugangsdaten, Verschlüsselungsschlüssel und Datenintegrität.

  • Die Ergebnisse erscheinen in Aktivität und im Auftragsverlauf als Läufe vom Typ Wiederherstellungstest und pro Auftrag in Berichte (Spalte Wiederherstellungstest).
  • Ein fehlgeschlagener Test ist ein Fehler wie jeder andere und löst eine E-Mail-Warnung aus.
  • Wiederherstellung testen auf der Seite eines Auftrags startet sofort einen Test.
  • Die Stichprobengröße begrenzt, wie viel vom Speicher gelesen wird — halten Sie sie bei Cloud-Speicher mit Downloadgebühren klein.

Starttest für Proxmox-VMs

Lesbare Blöcke beweisen nicht, dass eine VM noch startet. Mit eingeschaltetem Starttest für Proxmox-VM-Sicherungen (Einstellungen → Wiederherstellungstests) startet der Wiederherstellungstest eines Proxmox-VM-Auftrags zusätzlich jede VM der neuesten Sicherung auf dem Knoten des Auftrags, eine nach der anderen, mit Sofortwiederherstellung: Sie läuft aus der Sicherung mit neuer ID und getrennten Netzwerkkarten (damit sie nicht mit dem Original kollidiert) und wird gleich danach wieder gelöscht. Der Test ist bestanden, wenn der QEMU-Gast-Agent der VM innerhalb der eingestellten Zeit antwortet, also das Betriebssystem gestartet ist. VMs ohne Gast-Agent bestehen, wenn sie eine Minute lang weiterlaufen; die Laufseite zeigt sie dann als läuft statt gestartet. Die Kopie lässt außerdem Einstellungen weg, die aus der VM hinausreichen: ein Hook-Skript, rohe QEMU-Argumente (args), durchgereichte PCI- und USB-Geräte, Freigaben des Hosts (virtiofs) sowie serielle oder parallele Schnittstellen auf Host-Geräten; die Laufseite nennt, was weggelassen wurde. Eine VM, die ohne sie nicht startet, besteht den Starttest nicht.

  • Der Knoten braucht während des Tests freien Speicher für eine weitere VM.
  • Installieren Sie den QEMU-Gast-Agenten in den VMs (qemu-guest-agent unter Linux, die VirtIO-Gastwerkzeuge unter Windows) und aktivieren Sie ihn in den VM-Optionen, damit der Test den Start bestätigen kann.
  • Die Laufseite listet jede VM mit ihrem Ergebnis und der Startdauer auf.

Prüfungen in der VM (Agenten ab 0.61): Eine VM, die startet, kann trotzdem defekt sein oder zum Zeitpunkt der Sicherung bereits kompromittiert. In einem Proxmox-VM-Auftrag listet Prüfungen beim Starttest, was in der gestarteten Kopie funktionieren muss, eine pro Zeile: service sshd (der Dienst läuft), file /var/www/index.html (die Datei existiert), port 443 (ein Programm lauscht auf dem TCP-Port) oder command … (ein eigener Befehl endet mit Exit-Code 0; sh unter Linux, cmd unter Windows). Eine Zeile, die mit VM-ID und Doppelpunkt beginnt, z. B. 101: service nginx, gilt nur für diese VM. Die Prüfungen laufen über den QEMU-Gastagenten als root oder SYSTEM in der isolierten Kopie und werden wiederholt, bis sie bestehen oder die Wartezeit des Starttests endet; die Laufseite zeigt jede einzeln. Nur Benutzer, die Befehle ändern dürfen, legen sie fest.

Auch die älteste aufbewahrte Sicherung des Auftrags starten startet zusätzlich die VMs des ältesten aufbewahrten Wiederherstellungspunkts, damit Sie wissen, dass der Punkt, auf den Sie nach einer unbemerkten Kompromittierung zurückgreifen würden, noch startet. Eine VM-Sicherung, deren VMs gestartet sind und ihre Prüfungen bestanden haben, ist auf ihrer Laufseite, von der aus sie wiederhergestellt wird, als geprüft markiert.

Prüfung aller gespeicherten Daten

Wiederherstellungstests lesen eine Stichprobe. Zusätzlich liest ein Agent alle Daten jedes Repositorys, prüft sie gegen ihre Prüfsumme und kontrolliert, dass Ordner und Daten jeder Sicherung vorhanden sind — standardmäßig monatlich (Einstellungen → Wiederherstellungstests: Gespeicherte Daten prüfen: monatlich, alle drei Monate oder nie). So werden Schäden am Speicher selbst gefunden, etwa eine ausfallende Festplatte im NAS oder schleichender Datenverfall, bevor Sie die Sicherung brauchen. Jedes Repository wird einmal geprüft (die Aufträge eines Agenten auf einem Speicher teilen es), vom Agenten, der hineinschreibt. Die Prüfung liest so viel, wie das Repository enthält; auf Cloud-Speicher (S3, Azure) läuft sie daher nur mit Auch auf Cloud-Speicher. Probleme lassen den Lauf Datenprüfung fehlschlagen und senden eine Fehlerbenachrichtigung; Daten prüfen auf der Auftragsseite startet sofort eine Prüfung. Benötigt Agenten ab 0.39.0. Auf S3, Azure und gehärtetem Speicher liest die Prüfung mehrere Datenpakete gleichzeitig (Agenten 0.54.2 und neuer). Während eine Prüfung läuft, zeigen Aktivität und ihre Laufseite, wie viele Datenpakete des Repositorys sie bereits geprüft hat. Eine Prüfung, die beschädigte Datenpakete findet, bietet auf ihrer Laufseite Reparatur an (Fehlerbehebung).

Stellen Sie zusätzlich ab und zu (z. B. vierteljährlich) einen echten Ordner von Hand wieder her und öffnen Sie ein paar Dateien — das schult auch die Personen, die es im Notfall tun müssen.
