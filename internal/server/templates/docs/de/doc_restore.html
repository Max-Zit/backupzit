Wiederherstellen

Jede erfolgreiche Sicherung lässt sich wiederherstellen: vollständig oder nur ausgewählte Ordner, auf denselben Rechner, auf einen anderen Agenten oder als neue virtuelle Maschine.

Der Wiederherstellungsassistent

Klicken Sie im Menü auf Wiederherstellen. Der Assistent stellt vier Fragen:

  1. Was möchten Sie wiederherstellen?
    • eine ganze virtuelle Maschine
    • Dateien aus einer virtuellen Maschine
    • Dateien und Ordner
    • ein Festplattenabbild / Bare Metal
    • Dateien aus einem Festplattenabbild
    • eine Datenbank (zu einem Zeitpunkt)
    • ein ganzes Linux-System
    • Microsoft-365-E-Mail und OneDrive (siehe Microsoft 365)
    Jede Auswahl zeigt, wie viele Wiederherstellungspunkte es dafür gibt.
  2. Quelle: die virtuelle Maschine (über alle Hypervisoren und Aufträge hinweg) oder der Sicherungsauftrag und sein Rechner.
  3. Wiederherstellungspunkt: die Sicherung, aus der wiederhergestellt wird, die neueste zuerst, mit Status, Speicher und Größe.
    • Als verdächtig markierte Sicherungen (mögliche Ransomware) sind gekennzeichnet.
    • Kopien auf sekundärem Speicher, die ein Sicherungskopie-Auftrag erstellt hat, sind als Kopie aufgeführt (Datei- und VM-Sicherungen).
  4. Optionen: wohin und wie wiederhergestellt wird. Über den Optionen wird eine Zusammenfassung Ihrer Auswahl angezeigt.

Die Schritte oben sind Links, sodass Sie zu jedem früheren Schritt zurückkehren können. Jeder Schritt hat seine eigene Adresse, sodass Sie ihn als Lesezeichen speichern oder teilen können.

Die Optionen sind dieselben wie auf der Seite einer Sicherung in Aktivität, wo Sie eine Wiederherstellung auch direkt starten können. Nur Benutzer, deren Rolle wiederherstellen darf, sehen den Assistenten.

Aus einer Dateisicherung wiederherstellen

  1. Wählen Sie im Wiederherstellungsassistenten Dateien und Ordner, dann den Auftrag und den Wiederherstellungspunkt. Alternativ öffnen Sie die Sicherung in Aktivität oder auf der Auftragsseite.
  2. Wählen Sie unter Dateien aus dieser Sicherung wiederherstellen den Agenten, der die Dateien erhalten soll. Das kann ein anderer Rechner sein als der gesicherte — zum Beispiel ein Ersatz-PC.
  3. Wählen Sie, wohin:
    • In einen Ordner wiederherstellen (empfohlen) — z. B. D:\Restore. Darunter wird die ursprüngliche Struktur nachgebildet: D:\Restore\C\Users\ana\Documents\…. Nichts Vorhandenes wird angetastet.
    • Am ursprünglichen Ort wiederherstellen — schreibt die Dateien dorthin zurück, wo sie waren, und überschreibt aktuelle Versionen. Bei einer NAS-Freigabe verbindet der Agent die Freigabe erneut, beschreibbar.
  4. Beschränken Sie optional auf Nur diese Pfade, einen pro Zeile, z. B. C:\Users\ana\Documents\Contracts — oder wählen Sie sie im Dateibrowser aus (siehe unten).
  5. Lassen Sie Wiederhergestellte Dateien prüfen eingeschaltet: Jede Datei wird zurückgelesen und mit der Prüfsumme in der Sicherung verglichen.
  6. Klicken Sie auf Wiederherstellung starten. Fortschritt und Ergebnisse erscheinen auf der Seite des Wiederherstellungslaufs.

Dateizeiten, Windows-Attribute (versteckt, schreibgeschützt, …) und unter Linux Besitzer, Berechtigungen (einschließlich setuid-Bits), ACLs, erweiterte Attribute (SELinux-Labels, Datei-Capabilities), symbolische und harte Links werden ebenfalls wiederhergestellt. Besitzer werden nur gesetzt, wenn der Agent als root/Administrator läuft.

Dateien durchsuchen, herunterladen und auswählen

Beim Sicherungslauf zeigt Dateien durchsuchen die gesicherten Ordner so, wie sie waren (auch bei NAS-Freigaben und Linux-Systemsicherungen). Öffnen Sie Ordner, haken Sie Dateien und Ordner an und dann:

  • Herunterladen — eine Datei kommt unverändert, mehrere Dateien oder Ordner als ZIP-Archiv, direkt im Browser. Downloads werden im Audit-Protokoll festgehalten.
  • Oder auf einem Agenten wiederherstellen — in einen Ordner oder an den ursprünglichen Ort, wie eine Wiederherstellung mit Nur diese Pfade.

Ein symbolischer Link auf eine Datei (z. B. /etc/os-release) wird als die Datei heruntergeladen, auf die er zeigt, wenn diese in der Sicherung ist; Links auf Ordner werden in ZIP-Archiven ausgelassen. Dasselbe gilt für Dateien, die aus VM-Sicherungen heruntergeladen werden (ext4, XFS). Eine Wiederherstellung auf einem Agenten legt Links wieder als Links an.

Die Konsole liest die Sicherung selbst vom Speicher, daher funktioniert das Durchsuchen für Sicherungen auf Netzwerkspeicher (SFTP, S3, SMB, Azure, gehärtetes Repository); bei einer lokalen oder USB-Festplatte eines Agenten stellen Sie mit den Pfaden wieder her. Benutzer mit einer Wiederherstellungsrolle dürfen durchsuchen und herunterladen.

Die richtige Sicherung finden: Im Kalender sehen Sie, welche Sicherungen an welchem Tag liefen, oder nutzen Sie den Verlauf auf der Auftragsseite.

Einzelne Dateien aus einem Festplattenabbild wiederherstellen

Bei Abbildsicherungen klicken Sie im Sicherungslauf auf Dateien durchsuchen. Sie können das NTFS-Dateisystem im Abbild direkt in der Konsole durchsuchen, Dateien und Ordner anhaken und sie auf einen beliebigen Agenten wiederherstellen — ohne die ganze Festplatte wiederherzustellen.

Einzelne Dateien aus einer VM wiederherstellen (Proxmox VE, Hyper-V, VMware)

Klicken Sie in einem VM-Sicherungslauf neben dem Gast auf Dateien durchsuchen. Die Konsole zeigt die Partitionen und LVM-Volumes seiner Festplatten und lässt Sie NTFS-, ext4- und XFS-Dateisysteme durchsuchen. Laden Sie die angehakten Dateien herunter (mehrere als ZIP-Archiv) oder stellen Sie sie auf einem beliebigen Agenten wieder her. Siehe Proxmox VE, Hyper-V und VMware ESXi.

Ganze Rechner wiederherstellen

  • Windows-Festplattenabbilder: auf eine Festplatte oder Bare Metal, auch auf andere Hardware — Festplattenabbilder.
  • Linux-Systeme: auf eine Festplatte oder Bare Metal oder als neue Proxmox-VM — Linux-Systemsicherung.
  • Proxmox-VMs und -Container: als neuer Gast oder an Ort und Stelle — Proxmox VE. Proxmox-VMs können auch sofort aus der Sicherung laufen und während des Betriebs auf Speicher verschoben werden (Sofortwiederherstellung).
  • Datenbanken (SQL Server, PostgreSQL, MySQL/MariaDB): unter neuem Namen oder an Ort und Stelle, zu einem Zeitpunkt — Datenbanken.
  • Hyper-V-VMs: als neue VM oder an Ort und Stelle (behält ID und MAC-Adressen) — Hyper-V.
  • VMware-ESXi-VMs: als neue VM oder an Ort und Stelle (behält UUID und MAC-Adressen), auf jedem ESXi-Host und Datastore — VMware ESXi; auch sofort aus der Sicherung über einen Linux-Proxy-Agenten, danach auf einen Datastore kopiert (Sofortwiederherstellung).

Wiederherstellungs-ISOs

Bare-Metal-Wiederherstellungen starten den Rechner von einem Wiederherstellungs-ISO (auf einem USB-Stick oder an eine VM angehängt), siehe Wiederherstellungsmedien:

  • Linux-Wiederherstellungs-ISO — wird mit jeder Version veröffentlicht (backupzit-recovery-linux.iso); die Seite Wiederherstellungsmedien verlinkt es aus der Update-Quelle.
  • Windows-Wiederherstellungs-ISO — Windows PE darf nicht weitergegeben werden, daher wird es einmal auf einem beliebigen Windows-10/11- oder Server-PC erstellt:
    1. Installieren Sie das kostenlose Windows ADK (Funktion Deployment Tools) und das Windows-PE-Add-on von Microsoft.
    2. Laden Sie build-winpe.ps1 aus der Version herunter (neben den Agentenpaketen) und nehmen Sie backupzit-agent.exe aus C:\Program Files\backupzit Agent eines Rechners mit dem Agenten.
    3. In einer Administrator-PowerShell: .\build-winpe.ps1 -AgentExe .\backupzit-agent.exe -Out .\backupzit-recovery.iso. Fügen Sie -DriverDir C:\Drivers für Speicher- oder Netzwerktreiber hinzu (z. B. VirtIO für Proxmox-VMs) und -RecoveryJson .\recovery.json, damit es ohne Eingabe verbindet.
    4. Kopieren Sie das ISO optional in das Verzeichnis /var/lib/backupzit/dist der Konsole; es wird dann auf der Seite Wiederherstellungsmedien angeboten.

Das Durchsuchen von Dateien in der Konsole funktioniert für Sicherungen auf Netzwerkspeicher (SFTP, S3, SMB, Azure, gehärtetes Repository); die Konsole liest sie direkt. Für Sicherungen auf einer lokalen Festplatte eines Agenten verwenden Sie die Befehlszeile.

Ohne die Konsole wiederherstellen

Geht die Konsole selbst verloren, kann jeder Rechner mit installiertem Agenten mit dem Wiederherstellungsblatt des Speicherziels direkt vom Speicher wiederherstellen:

set BACKUPZIT_PASSWORD=<recovery key>
set BACKUPZIT_SFTP_PASSWORD=...           (or the S3/SMB/hardened credentials)
backupzit-agent snapshots --repo sftp://backup@nas:22/backups/pc1_1a2b3c4d
backupzit-agent restore   --repo sftp://backup@nas:22/backups/pc1_1a2b3c4d --target D:\Restore latest

Siehe Befehlszeilenreferenz.

Automatische Wiederherstellungstests

BackupZit prüft Ihre Sicherungen regelmäßig, ohne dass Sie etwas tun: Wöchentlich (einstellbar unter Einstellungen → Wiederherstellungstests) stellt der Agent jedes Auftrags eine Zufallsstichprobe von Dateien aus der neuesten Sicherung in einen temporären Ordner wieder her, prüft jedes Byte gegen die gespeicherten Prüfsummen und löscht sie wieder. Bei Festplattenabbildern werden zufällige Blöcke gelesen und geprüft. So wird die ganze Kette geprüft — Speicherzugriff, Zugangsdaten, Verschlüsselungsschlüssel und Datenintegrität.

  • Die Ergebnisse erscheinen in Aktivität und im Auftragsverlauf als Läufe vom Typ Wiederherstellungstest und pro Auftrag in Berichte (Spalte Wiederherstellungstest).
  • Ein fehlgeschlagener Test ist ein Fehler wie jeder andere und löst eine E-Mail-Warnung aus.
  • Wiederherstellung testen auf der Seite eines Auftrags startet sofort einen Test.
  • Die Stichprobengröße begrenzt, wie viel vom Speicher gelesen wird — halten Sie sie bei Cloud-Speicher mit Downloadgebühren klein.

Starttest für Proxmox-VMs

Lesbare Blöcke beweisen nicht, dass eine VM noch startet. Mit eingeschaltetem Starttest für Proxmox-VM-Sicherungen (Einstellungen → Wiederherstellungstests) startet der Wiederherstellungstest eines Proxmox-VM-Auftrags zusätzlich jede VM der neuesten Sicherung auf dem Knoten des Auftrags, eine nach der anderen, mit Sofortwiederherstellung: Sie läuft aus der Sicherung mit neuer ID und getrennten Netzwerkkarten (damit sie nicht mit dem Original kollidiert) und wird gleich danach wieder gelöscht. Der Test ist bestanden, wenn der QEMU-Gast-Agent der VM innerhalb der eingestellten Zeit antwortet, also das Betriebssystem gestartet ist. VMs ohne Gast-Agent bestehen, wenn sie eine Minute lang weiterlaufen; die Laufseite zeigt sie dann als läuft statt gestartet.

  • Der Knoten braucht während des Tests freien Speicher für eine weitere VM.
  • Installieren Sie den QEMU-Gast-Agenten in den VMs (qemu-guest-agent unter Linux, die VirtIO-Gastwerkzeuge unter Windows) und aktivieren Sie ihn in den VM-Optionen, damit der Test den Start bestätigen kann.
  • Die Laufseite listet jede VM mit ihrem Ergebnis und der Startdauer auf.

Stellen Sie zusätzlich ab und zu (z. B. vierteljährlich) einen echten Ordner von Hand wieder her und öffnen Sie ein paar Dateien — das schult auch die Personen, die es im Notfall tun müssen.
