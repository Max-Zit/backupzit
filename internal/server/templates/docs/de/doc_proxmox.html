Virtuelle Maschinen in Proxmox VE

BackupZit sichert virtuelle Maschinen (QEMU) und Container (LXC) von Proxmox VE, ohne etwas in den Gästen zu installieren. Der Agent läuft auf dem Proxmox-Host, erstellt einen Snapshot jedes Gasts, liest dessen Festplatten und speichert sie dedupliziert auf einem beliebigen Speicherziel.

Einrichtung

  1. Installieren Sie das Paket Linux-Agent — Debian / Ubuntu von Agenten auf jedem Proxmox-Knoten (Proxmox VE 7 und 8 basieren auf Debian): 
    apt install ./backupzit-agent_*.deb
backupzit-agent enroll --code "BZ1-..."
systemctl enable --now backupzit-agent
  2. Innerhalb einer Minute erscheint der Knoten auf der Seite Agenten mit dem Kennzeichen Proxmox VE · N guests.
  3. Wählen Sie unter Sicherungsaufträge diesen Agenten und Virtuelle Maschinen (Proxmox VE, Hyper-V, VMware). Sichern Sie alle Gäste des Knotens (später erstellte Gäste werden automatisch einbezogen) oder markieren Sie einzelne.

Der Agent verwendet die eigenen Werkzeuge des Knotens (qm, pct, pvesm, LVM, ZFS, Ceph); in der Konsole wird weder API-Token noch Passwort gespeichert.

Wie ein Gast gesichert wird

  1. Ein temporärer Proxmox-Snapshot wird erstellt (backupzit_…, für einige Sekunden bis Minuten unter Snapshots sichtbar). Der Gast läuft weiter.
  2. Läuft der QEMU-Gastagent in der VM (und ist er in den VM-Optionen aktiviert), friert Proxmox die Dateisysteme für den Snapshot ein — die Sicherung ist dann anwendungskonsistent. Ohne ihn ist die Sicherung absturzkonsistent, wie bei einem Stromausfall. Installieren Sie qemu-guest-agent in Linux-VMs und die VirtIO-Gastwerkzeuge in Windows-VMs.
  3. Jede Festplatte wird aus dem Snapshot in Blöcken zu 1 MiB gelesen. Leere Blöcke werden nicht gespeichert und Blöcke, die bereits im Repository liegen, nicht erneut hochgeladen; nach der ersten Sicherung werden also nur geänderte Daten übertragen.
  4. Der Snapshot wird entfernt. Die Gastkonfiguration (CPU, Arbeitsspeicher, Netzwerk, Festplatten) wird mit der Sicherung gespeichert.

Die Laufseite listet jeden Gast, seine Festplatten und die Art der Erfassung auf. Wiederherstellungstests prüfen zufällige Blöcke von VM-Sicherungen wie bei Festplattenabbildern und starten — mit aktiviertem Boot-Test — jede VM vom Netzwerk isoliert aus der Sicherung, um zu beweisen, dass sie startet.

In Proxmox mit Backup: no (backup=0) markierte Festplatten, durchgereichte physische Festplatten und Bind-Mounts werden übersprungen und als Warnungen aufgeführt. Cloud-Init-Laufwerke werden nicht gespeichert; sie werden bei der Wiederherstellung aus der Konfiguration neu erstellt.

Eine VM oder einen Container wiederherstellen

Öffnen Sie einen Lauf einer VM-Sicherung (über die Auftragsseite oder Aktivität) und verwenden Sie Eine VM oder einen Container wiederherstellen:

  • Gast — einer der Gäste in dieser Sicherung.
  • Auf Proxmox-Knoten wiederherstellen — jeder Knoten mit dem BackupZit-Agenten, auch ein Knoten eines anderen Clusters.
  • Als neuer Gast mit der nächsten freien ID (Standard) oder mit ID … — das Original läuft weiter. Da beide existieren, erhalten die Netzwerkkarten der Kopie neue MAC-Adressen.
  • Mit seiner ursprünglichen ID — nachdem der Gast gelöscht wurde. Existiert er noch, aktivieren Sie stoppen und löschen, um ihn durch die Sicherung zu ersetzen; der vorhandene Gast und seine Festplatten werden zuerst gelöscht.
  • Name und Speicher für die Datenträger — z. B. auf einen anderen Speicher als das Original wiederherstellen.
  • Gast nach der Wiederherstellung starten.

Jede Wiederherstellung gibt VMs eine neue Generations-ID (vmgenid), sodass Windows-Domänencontroller und andere Software das Zurücksetzen sicher erkennen. Festplatten werden mit pvesm auf dem gewählten Speicher angelegt; auf Verzeichnisspeicher werden sie als Raw-Dateien wiederhergestellt.

Sofortige Wiederherstellung

Das Wiederherstellen einer großen VM dauert so lange wie das Kopieren ihrer Festplatten. Mit Sofort, aus der Sicherung laufend im Wiederherstellungsformular läuft die VM stattdessen innerhalb von Sekunden, während ihre Festplatten noch in der Sicherung liegen:

  1. Der Agent stellt die Festplatten der VM schreibgeschützt aus der Sicherung bereit (ein kleiner NBD-Server, der als systemd-Unit backupzit-instant-<ID> läuft) und erstellt eine neue VM mit der nächsten freien ID, deren Festplatten qcow2-Overlays auf dem Verzeichnisspeicher backupzit-instant sind (/var/lib/backupzit-instant, automatisch hinzugefügt). Daten werden bei Bedarf aus der Sicherung gelesen; alles, was die VM schreibt, bleibt in den Overlays. Firmware-Variablen (EFI-Festplatte) und TPM-Zustand sind klein und werden kopiert.
  2. Die VM startet. Prüfen Sie sie — sie erhält wie jede Kopie neue MAC-Adressen. Das Dashboard listet jede VM auf, die noch aus einer Sicherung läuft.
  3. Auf der Laufseite entweder Abschließen: Die Festplatten werden auf den gewählten Speicher verschoben, während die VM weiterläuft (qm disk move); danach wird die Sicherung nicht mehr verwendet. Oder Verwerfen: Die VM wird gestoppt und samt ihren Änderungen gelöscht.

Solange eine VM aus einer Sicherung läuft, entfernt die Aufbewahrung diese Sicherung nie. Die VM ist so schnell, wie es der Sicherungsspeicher erlaubt: Ein Repository auf einer lokalen Festplatte oder einer schnellen Netzwerkfreigabe funktioniert am besten; Lesezugriffe über SFTP oder S3 aus der Ferne machen sie langsam, bis sie abgeschlossen ist. Die sofortige Wiederherstellung gilt für VMs (nicht für Container) und erstellt eine neue VM — an Ort und Stelle stellen Sie mit einer normalen Wiederherstellung wieder her. Die EFI-Festplatte kann nicht verschoben werden, während die VM läuft; sie bleibt dann auf backupzit-instant (siehe Laufmeldung) und kann nach dem Herunterfahren der VM verschoben werden: qm disk move ID efidisk0 STORAGE --delete 1.

Replikation

Für Gäste, die innerhalb von Minuten wieder da sein müssen, kann ein VM-Auftrag Replikate vorhalten: Aktivieren Sie unter Erweitert im Auftragsformular Replikate der VMs vorhalten und wählen Sie den Knoten (jeder Knoten mit dem BackupZit-Agenten, auch in einem anderen Cluster) und den Speicher. Nach jeder Sicherung bringt der Agent auf diesem Knoten eine gestoppte Kopie jedes Gasts des Auftrags auf den neuesten Stand:

  • Beim ersten Mal wird das Replikat wie ein neuer Gast wiederhergestellt (nächste freie ID, Name original-replica, neue MAC-Adressen, startet nie mit dem Knoten).
  • Danach werden nur die Blöcke geschrieben, die sich seit der Sicherung des Replikats geändert haben — typischerweise einige Sekunden pro Sicherung.
  • Die Auftragsseite listet die Replikate, die jeweils enthaltene Sicherung und ihren Zustand auf. Geht ein Gast verloren, klicken Sie auf Replikat starten: Es läuft mit den Daten der letzten Sicherung, ohne Wiederherstellung. Starten Sie es nur, wenn das Original wirklich weg ist — beide gleichzeitig im Netzwerk können Konflikte verursachen.
  • Solange ein Replikat läuft, wird es nicht mehr aktualisiert (der Lauf meldet das). Um erneut zu replizieren, löschen Sie den Replikat-Gast in Proxmox; die nächste Sicherung erstellt ein neues. Replikate mit Proxmox-Snapshots werden ebenfalls nicht aktualisiert.
  • Später zu einem Gast hinzugefügte Festplatten werden nicht repliziert (löschen Sie das Replikat, um neu zu beginnen); vergrößerte Festplatten werden auch auf dem Replikat vergrößert. Konfigurationsänderungen (Arbeitsspeicher, CPUs) werden beim Erstellen des Replikats übernommen.
  • Die Replikation liest die Sicherungen wie eine Wiederherstellung: Der Replikatknoten muss den Speicher erreichen. Das Ausschalten der Replikation lässt die Replikate unverändert.

Befehlszeile

backupzit-agent pve list
backupzit-agent pve backup  --repo ... [--vmid 100,200] [--exclude 300]
backupzit-agent pve show    --repo ... latest
backupzit-agent pve restore --repo ... --vmid 100 [--new-vmid -1|N] [--name copy] [--storage local-lvm] [--overwrite] [--start] SNAPSHOT|latest
backupzit-agent pve instant --repo ... --vmid 100 [--new-vmid N] [--name X] SNAPSHOT|latest
backupzit-agent pve instant-finish --vmid 101 --storage local-lvm
backupzit-agent pve instant-discard --vmid 101

Die Repository-Optionen sind dieselben wie bei allen Befehlen (siehe Befehlszeilenreferenz). Die Befehlszeile funktioniert ohne Konsole, zum Beispiel um nach einem Desaster einen ganzen Knoten wiederherzustellen.

Cluster

Installieren Sie den Agenten auf jedem Knoten. Ein Auftrag sichert die Gäste, die auf dem Knoten seines Agenten laufen; ein in einem Auftrag aufgeführter Gast, der auf einen anderen Knoten migriert wurde, wird als Warnung mit dem Namen dieses Knotens gemeldet — sichern Sie jeden Knoten mit einem eigenen Auftrag, oder verwenden Sie alle Gäste des Knotens auf jedem Knoten, damit migrierte Gäste immer abgedeckt sind.

Einzelne Dateien wiederherstellen

Klicken Sie in der Gasttabelle eines VM-Sicherungslaufs auf Dateien durchsuchen. Die Konsole liest die Festplatte direkt aus der Sicherung — nichts wird vorher wiederhergestellt — und zeigt ihre Partitionen und logischen LVM-Volumes; NTFS (Windows), ext2/3/4 und XFS (Linux) können durchsucht werden, auch innerhalb von LVM. Markieren Sie Dateien und Ordner und:

  • Herunterladen — eine Datei unverändert, mehrere Dateien oder Ordner als ZIP-Archiv, direkt in Ihren Browser;
  • Auf Agent wiederherstellen — in einen Ordner auf einem beliebigen Agenten kopieren, z. B. zurück in die VM (wenn dort der BackupZit-Agent läuft) oder auf einen Dateiserver.

In der Befehlszeile: backupzit-agent pve ls --vmid 100 latest /etc und backupzit-agent pve extract --vmid 100 --target /srv/restore latest /etc/nginx; --volume wählt eine Partition oder ein logisches Volume (pve ls ohne Pfad listet sie auf). Das Durchsuchen in der Konsole erfordert die Sicherung auf Netzwerkspeicher (SFTP, S3, SMB, Azure, gehärtetes Repository).

Noch nicht enthalten

  • XCP-ng-Hosts. Hyper-V und VMware ESXi: siehe Hyper-V und VMware ESXi.
