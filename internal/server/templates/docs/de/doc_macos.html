macOS-Agenten

Der macOS-Agent sichert die Dateien und Ordner eines Macs, mit Apple Silicon oder Intel. Er läuft ab dem ersten Start als Dienst, liest jede Sicherung des Startlaufwerks aus einem lokalen APFS-Snapshot und behält die Dateimetadaten des Macs bei. Eine Menüleisten-App zeigt seinen Zustand und führt den Benutzer durch die Berechtigungen, die nur er erteilen kann.

Vorschau. Der macOS-Agent ist neu in 0.59. Ein Mitwirkender hat ihn geschrieben und auf Macs getestet; unsere eigenen Tests laufen in der Build-Pipeline auf macOS. Bitte melden Sie, was nicht funktioniert, in den GitHub Issues.

Voraussetzungen

  • Ein Mac mit Apple Silicon (M1 und neuer) oder einem Intel-Prozessor und macOS 13 oder neuer. Ein universelles Paket dient beiden (seit 0.60; 0.59 war nur für Apple Silicon).
  • Ein Administratorkonto auf dem Mac, für Installation und Registrierung.
  • Den Benutzer des Macs, um den Festplattenvollzugriff zu erteilen: macOS lässt das niemand anderen tun, weder ein Skript noch die Konsole.
  • Wie jeder Agent muss der Mac die Agentenadresse der Konsole (meist Port 8443) und den Speicher erreichen.

Installieren

  1. Laden Sie auf der Seite Agenten macOS-Agent herunter (backupzit-agent_version_darwin_universal.pkg). Das Konsolenpaket enthält es, wie die Installationsprogramme für Windows und Linux.
  2. Öffnen Sie das .pkg auf dem Mac und folgen Sie dem Installationsprogramm. Bei einem Paket, das nicht mit einer Apple Developer ID signiert ist, fragt macOS zuerst nach einer Bestätigung: Klicken Sie mit der rechten Maustaste darauf und wählen Sie Öffnen (bei neueren macOS-Versionen: Systemeinstellungen → Datenschutz & Sicherheit → Dennoch öffnen).
  3. Die letzte Seite des Installationsprogramms erklärt die zu erteilenden Berechtigungen, und die Menüleisten-App öffnet sich.

Das Paket installiert:

Das Programm wird nicht zum PATH hinzugefügt: Rufen Sie es im Terminal mit seinem vollständigen Pfad auf.

Registrieren

Der Dienst ist installiert und läuft schon, bevor der Mac registriert ist; er beginnt zu arbeiten, sobald er es ist. Auf der Seite Agenten zeigt Registrierungstoken erstellen den Code und die Befehle für macOS neben denen für Windows und Linux. Wählen Sie einen von vier Wegen:

  1. In der Menüleisten-App, nach der Installation (der übliche Weg, Agenten ab 0.60): Solange der Mac nicht registriert ist, fragt die BackupZit-Menüleisten-App direkt nach der Installation nach dem Code. Fügen Sie ihn ein, klicken Sie auf Enroll und geben Sie Namen und Passwort eines Administrators ein, wenn macOS danach fragt. Die App meldet dann, ob die Registrierung geklappt hat, und wenn nicht, warum. Später oder nach Later wählen Sie Enroll this Mac… in ihrem Menü; der Eintrag ist da, solange der Mac nicht registriert ist.
  2. Im Terminal, nach der Installation: 
    sudo /Library/BackupZit/bin/backupzit-agent enroll --code "BZ1-..."
  3. Mit einem MDM (Jamf, Intune, Mosyle…): Vor der Installation des Pakets schreibt ein Skript den Code in eine Datei, die root gehört: 
    echo "BZ1-..." | sudo sh -c 'umask 077; mkdir -p "/Library/Application Support/BackupZit"; cat > "/Library/Application Support/BackupZit/enroll-code"'
    Verteilen Sie dann das Paket. Seine Installation registriert den Mac mit dem Code und löscht die Datei. Eine Datei, die nicht root gehört, wird ignoriert. So wird auch ein registrierter Mac zu einer anderen Konsole umgezogen.
  4. Eine Datei neben dem Paket: backupzit-enroll.txt mit dem Code, im selben Ordner wie das .pkg auf dem Startvolume des Mac (zum Beispiel in /Users/Shared; von einem USB-Stick oder einer Netzwerkfreigabe kopieren Sie beide zuerst dorthin: auf einem solchen Volume kann jede Datei behaupten, root zu gehören). Sie wird nur verwendet, solange der Mac noch nicht registriert ist, und nur, wenn niemand anderes sie geschrieben haben kann: Die Datei gehört root oder einem Administrator des Mac, hat nur einen Namen und nur ihr Besitzer darf sie ändern, und ihr Ordner gehört root oder einem Administrator und ist für andere Benutzer nicht beschreibbar (oder hat das Sticky-Bit, wie /Users/Shared).

Ist die Konsole während der Installation nicht erreichbar, behält der Agent den Code und versucht es erneut. Schlägt die Registrierung fehl, steht der Grund in /Library/Application Support/BackupZit/enroll-error.log; registrieren Sie den Mac danach über die Menüleisten-App oder im Terminal. Upgrades und Neuinstallationen behalten die Registrierung.

Berechtigungen

macOS schützt manche Daten vor jedem Programm, auch vor einem, das als root läuft, bis der Benutzer es in den Systemeinstellungen erlaubt. Nur der Benutzer am Mac kann diese Berechtigungen erteilen; die letzte Seite des Installationsprogramms und die Menüleisten-App führen ihn hindurch.

Festplattenvollzugriff für den Agenten

Ohne ihn fehlen in den Sicherungen die Ordner, die macOS schützt, und es wird kein APFS-Snapshot erstellt (siehe Was gesichert wird).

  1. Öffnen Sie Systemeinstellungen → Datenschutz & Sicherheit → Festplattenvollzugriff.
  2. Klicken Sie unter der Liste auf + und geben Sie Ihr Passwort ein.
  3. Drücken Sie Befehl-Umschalt-G, geben Sie /Library/BackupZit/bin/backupzit-agent ein, drücken Sie die Eingabetaste und klicken Sie auf Öffnen.
  4. Prüfen Sie, dass der Schalter neben backupzit-agent eingeschaltet ist.

Statt + können Sie die Datei in die Liste ziehen: Wählen Sie im Finder Gehe zu → Gehe zum Ordner …, geben Sie /Library/BackupZit/bin ein und ziehen Sie backupzit-agent auf die Liste.

Der Agent im Hintergrund

Nach der Installation zeigt macOS Hintergrundobjekte hinzugefügt. In Systemeinstellungen → Allgemein → Anmeldeobjekte & Erweiterungen müssen unter Im Hintergrund erlauben backupzit-agent und BackupZit eingeschaltet bleiben: Ausgeschaltet läuft der Agent nicht, und keine Sicherung startet.

Mitteilungen und Öffnen bei der Anmeldung

  • Mitteilungen: Erlauben Sie sie, wenn die Menüleisten-App fragt, oder später in Systemeinstellungen → Mitteilungen → BackupZit (Mitteilungen erlauben). Die App informiert den Benutzer dort, wenn eine Sicherung fehlschlägt.
  • Öffnen bei der Anmeldung: Die Menüleisten-App öffnet sich bei jeder Anmeldung, solange BackupZit unter Anmeldeobjekte & Erweiterungen → Im Hintergrund erlauben eingeschaltet ist.

Die Menüleisten-App und ihr Assistent

Das BackupZit-Symbol in der Menüleiste zeigt den Zustand des Agenten; sein Menü bietet Back up now für jeden Auftrag des Macs, Open console in browser und Hide this icon (bis zur nächsten Anmeldung; Sicherungen laufen weiter). Sein Abschnitt Permissions listet den Agenten im Hintergrund, den Festplattenvollzugriff, Mitteilungen und das Öffnen bei der Anmeldung, jeweils mit ✅ oder ❌. Ein Klick auf einen Eintrag öffnet seine Seite der Systemeinstellungen; eine fehlende Berechtigung erklärt die App zudem einmal pro Anmeldung in einem Dialog mit den nötigen Schritten. Solange etwas fehlt, prüft sie selbst alle paar Sekunden erneut, sodass ✅ erscheint, sobald die Berechtigung erteilt ist. Der Agent meldet einen fehlenden Festplattenvollzugriff auch an die Konsole, im Laufbericht. Open console in browser öffnet die Webadresse der Konsole, auch wenn Port 8443 nur Agenten bedient (Agent und Konsole 0.61 und neuer).

Prüfen im Terminal

/Library/BackupZit/bin/backupzit-agent status

Der Befehl funktioniert als normaler Benutzer und zeigt die Konsole, die Aufträge und full disk access: granted oder denied (mit dem einzuschaltenden Programm).

Festplattenvollzugriff nach einem Update

macOS bindet den Festplattenvollzugriff an die Signatur des Programms. Mit einer Apple Developer ID signierte Pakete behalten ihn über Updates hinweg. Ein ohne sie gebautes Paket (ad hoc signiert) verliert ihn bei jedem Selbst-Update: Sicherungen warnen dann wieder, und die Menüleisten-App meldet, dass der Festplattenvollzugriff seit dem Update fehlt. Erteilen Sie ihn erneut: Wählen Sie in der Liste Festplattenvollzugriff backupzit-agent aus, klicken Sie auf −, um ihn zu entfernen (Aus- und Einschalten genügt nicht), und fügen Sie ihn dann wie oben mit + wieder hinzu.

Was gesichert wird

Ein Mac-Agent führt Aufträge für Dateien und Ordner aus wie jeder Agent: Pfade wie /Users, /Applications oder /, {users}-Pfade (/Users/<name>/Documents) und Platzhalter, auch in einem Auftrag für mehrere Agenten mit Alle macOS-Agenten.

Lokaler APFS-Snapshot

Jede Dateisicherung des Datenvolumes des Startlaufwerks wird aus einem lokalen APFS-Snapshot gelesen, dem macOS-Gegenstück zu VSS unter Windows: Die Sicherung sieht jede Datei zum selben Zeitpunkt, auch solche, in die ein Programm weiter schreibt. Der Agent erstellt den Snapshot (tmutil localsnapshot), bindet ihn schreibgeschützt ein, liest die Dateien daraus und hängt ihn nach der Sicherung aus und löscht ihn. Nach einem Absturz übrig gebliebene Snapshots werden beim nächsten Start bereinigt; die eigenen Snapshots von Time Machine werden nie angetastet. Der Laufbericht meldet Read from an APFS local snapshot of /System/Volumes/Data.

Der Snapshot braucht den Dienst (root) und den Festplattenvollzugriff. Ohne Festplattenvollzugriff und für Pfade auf anderen Volumes (/Volumes: externe Festplatten, Netzwerkfreigaben) werden die Dateien ohne Snapshot gelesen, und der Laufbericht sagt es.

Metadaten

Mit jeder Datei und jedem Ordner erhalten: Besitzer und Gruppe, Berechtigungen, erweiterte Attribute (außer com.apple.provenance, das macOS selbst verwaltet), harte Links, symbolische Links, BSD-Datei-Flags (versteckt, geschützt, nodump, nur anhängen…; die System-Flags nur, wenn der Agent als root läuft, wie der Dienst), die Erstellungszeit und Änderungszeiten auf die Nanosekunde. Dünn besetzte Dateien (Sparse-Dateien) bleiben es: Ihre Lücken werden auf APFS wieder ausgestanzt.

Leer gesicherte Ordner

Einige Systemordner unterhalb eines gesicherten Ordners werden als leere Ordner gesichert: andere Volumes (/Volumes), Swap (/System/Volumes/VM, /private/var/vm), die Hilfsvolumes in /System/Volumes, /dev, temporäre Dateien (/private/tmp, /private/var/folders), Caches (/Library/Caches, /System/Library/Caches, ~/Library/Caches), der Papierkorb (~/.Trash, .Trashes), Spotlight, FSEvents, Dokumentversionen sowie lokale und HFS+-Time-Machine-Backups. Mit / als Quelle werden die Ordner des Datenvolumes, die / bereits zeigt (/Users, /Applications…), nicht doppelt gelesen. Ein Ordner, der als Quelle des Auftrags angegeben ist, wird immer gelesen, z. B. /Volumes/USB oder ~/.Trash.

Warnungen im Laufbericht

Ohne Festplattenvollzugriff können die Ordner, die macOS schützt, nicht gelesen werden: Mail, Nachrichten, Safari, Schreibtisch und Dokumente, Daten anderer Apps, Wechsel- und Netzwerkvolumes. Eine Sicherung, deren Quellen /Users (außer /Users/Shared), /Library oder /Volumes erreichen, oder einen Ordner darüber wie /, endet dann mit der Warnung Full Disk Access is not granted to the BackupZit agent. Sicherungen anderer Ordner (z. B. /opt/data) warnen nicht.

Dateien in iCloud Drive

Mit Schreibtisch & Dokumente in iCloud Drive und eingeschaltetem Mac-Speicher optimieren behält macOS den Inhalt von Dateien, die eine Weile nicht benutzt wurden, nur in iCloud. Die Datei bleibt mit Namen und Größe im Finder, aber ihre Daten liegen nicht auf dem Mac (eine „dataless“-Datei, angezeigt mit dem iCloud-Downloadpfeil). Eine Sicherung kann eine solche Datei nicht lesen: Ein APFS-Snapshot enthält ihren Inhalt nicht, und ein Lesen direkt auf dem Datenträger würde iCloud dazu bringen, sie in der Sitzung ihres Eigentümers zu laden, was fehlschlägt, solange dieser Benutzer nicht angemeldet ist. Seit 0.60 öffnet der Agent diese Dateien nie und lässt iCloud keine davon laden:

  • Eine Datei, die in der vorherigen Sicherung war und sich seitdem nicht geändert hat (gleiche Größe und Änderungszeit), behält ihren Inhalt von dort; eine Datei, die erst nach einer Sicherung nur noch in iCloud liegt, bleibt also in den Sicherungen.
  • Jede andere solche Datei wird aus der Sicherung ausgelassen und getrennt von den Lesefehlern gezählt. Der Lauf endet mit einer Warnung wie 3360 files (1.2 GiB) are in iCloud Drive but not downloaded on this Mac, und die Laufseite listet sie pro Ordner auf (z. B. /Users/anna/Documents), mit der Anzahl der Dateien und ihrer Größe.

Damit sie gesichert werden, laden Sie sie vor der Sicherung auf den Mac: im Finder Rechtsklick auf den Ordner → Jetzt laden, oder im Terminal als dieser Benutzer find ~/Documents -type f -exec brctl download {} \;. Um sie dauerhaft auf dem Mac zu behalten, schalten Sie Mac-Speicher optimieren unter Systemeinstellungen → Ihr Name → iCloud aus. Dateien eines Benutzers, der nicht am Mac angemeldet ist, lassen sich erst laden, wenn sich dieser Benutzer anmeldet.

Wiederherstellen

Dateien eines Macs werden wie alle Dateisicherungen wiederhergestellt: die ganze Sicherung oder nur einige Pfade, in einen Ordner oder an den ursprünglichen Ort, auf dem Mac oder auf einem anderen Agenten; einzelne Dateien lassen sich aus der Konsole herunterladen. Eine Wiederherstellung auf einem Mac setzt die oben genannten Metadaten wieder. Wie unter Windows und Linux schreibt sie nur über die Ordner, die sie geöffnet hat, nie über einen Pfad, sodass einem während der Wiederherstellung in den Weg gelegten Link nicht gefolgt wird. Eine Wiederherstellung über geschützte Dateien entfernt zuerst deren Flags „geschützt“ und „nur anhängen“ und setzt danach die gespeicherten wieder (System-Flags lassen sich auf einem laufenden Mac nicht entfernen).

Aktualisieren und deinstallieren

Die Seite Agenten bietet für einen Mac wie für andere Agenten Aktualisieren auf Version an (siehe Agenten). Der Agent lädt das .pkg von der Konsole, prüft es gegen die signierte Liste der Agenten-Installationsprogramme und seine SHA-256-Prüfsumme, installiert es mit Apples installer in einem einmaligen launchd-Auftrag und startet mit der neuen Version neu. Lehnt launchd diesen Auftrag ab, schlägt der Update-Lauf mit der Meldung von launchd fehl. Das Protokoll des Installationsprogramms liegt in /Library/Application Support/BackupZit/updates. Prüfen Sie nach dem Update eines nicht signierten Pakets den Festplattenvollzugriff.

Entfernen auf der Seite Agenten mit Agent vom Computer deinstallieren entfernt das Programm, die Menüleisten-App, den LaunchDaemon und den LaunchAgent sowie den Paketbeleg; Konfiguration und Protokoll bleiben. Von Hand deinstallieren:

sudo /Library/BackupZit/uninstall.sh            # keeps configuration and log
sudo /Library/BackupZit/uninstall.sh --purge    # deletes them too

Ohne --purge wird die Registrierung beiseitegelegt (agent.json.removed-date), sodass eine neue Installation wieder nach einem Code fragt. Entfernen Sie nach der Deinstallation backupzit-agent von Hand aus Datenschutz & Sicherheit → Festplattenvollzugriff: macOS lässt das kein Programm tun.

Protokolle

  • Agent: /Library/Logs/BackupZit/agent.log (auch in der App Konsole aufgeführt); ein Absturzprotokoll geht nach /Library/Logs/BackupZit/launchd.log.
  • Registrierung durch das Installationsprogramm: /Library/Application Support/BackupZit/enroll-error.log und das Installationsprotokoll /var/log/install.log.
  • Updates: /Library/Application Support/BackupZit/updates.
  • Protokoll holen auf der Seite Agenten ruft das Ende des Protokolls aus der Konsole ab (siehe Protokolle).
