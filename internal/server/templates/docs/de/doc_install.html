Server installieren

Die Konsole läuft unter Linux (Debian, Ubuntu, AlmaLinux, Rocky Linux) mit PostgreSQL. Jede Organisation betreibt ihre eigene Konsole in ihrem eigenen Netzwerk.

Voraussetzungen

  • Eine Linux-VM oder ein Server: 2 vCPU, 2–4 GB RAM, 20 GB Festplatte reichen für Hunderte Agenten (Sicherungsdaten werden dort nicht gespeichert).
  • PostgreSQL 13 oder neuer (lokal oder auf einem anderen Server).
  • Netzwerk: Agenten müssen die Konsole über TCP 8443 (HTTPS) erreichen. Agenten müssen außerdem den Speicher direkt erreichen.

1. Fertiges VM-Image

Eine fertige Appliance (Debian, PostgreSQL, die Konsole, automatische Sicherheitsupdates), die in weniger als einer Minute startet und keinen Internetzugang braucht:

HypervisorWie
VMware ESXiHost Client: Create / Register VM → Deploy a virtual machine from an OVF or OVA file, wählen Sie backupzit-appliance.ova. vSphere: Deploy OVF Template. Workstation und VirtualBox: File → Open / Import.
Proxmox VEKopieren Sie backupzit-appliance.qcow2 auf den Knoten, erstellen Sie eine VM ohne Festplatte (2 vCPU, 2–4 GB RAM, VirtIO-Netzwerk), dann
qm importdisk <vmid> backupzit-appliance.qcow2 local-lvm
hängen Sie die importierte Festplatte als SCSI an, machen Sie sie zur Bootfestplatte und aktivieren Sie den QEMU-Gast-Agenten.
Hyper-VEntpacken Sie backupzit-appliance-vhdx.zip, dann Neu → Virtueller Computer, Generation 1, 2–4 GB RAM, Vorhandene virtuelle Festplatte verwenden: die VHDX.

Starten Sie die VM. Ihr Bildschirm zeigt die Adresse der Webkonsole und das Anfangspasswort von admin (siehe Erste Anmeldung). Geben Sie der VM 2 vCPU und 2–4 GB RAM; die 16-GB-Festplatte können Sie jederzeit vergrößern — die Appliance nimmt den neuen Platz beim nächsten Start in Gebrauch (das Root-Dateisystem wächst im laufenden Betrieb). Beim ersten Start erzeugt jede Kopie eigene SSH-Schlüssel, ein eigenes Datenbankpasswort und einen eigenen Geheimnisschlüssel, sodass ein Image beliebig oft bereitgestellt werden kann. Der Netzwerkadapter bezieht seine Adresse per DHCP.

2. Appliance-ISO

Das Appliance-ISO installiert alles ohne Rückfragen: Debian, PostgreSQL, die Konsole und automatische Sicherheitsupdates.

  1. Erstellen Sie eine VM (oder nehmen Sie einen Server) mit 2 vCPU, 2–4 GB RAM und einer Festplatte von 16 GB oder mehr. Verwenden Sie VirtIO oder die Standardgeräte des Hypervisors, BIOS oder UEFI.
  2. Starten Sie von backupzit-appliance.iso. Nach 5 Sekunden beginnt die Installation von selbst, löscht die erste Festplatte und installiert. Sie lädt die Betriebssystempakete herunter, daher braucht der Server während der Installation Internetzugang. Das dauert etwa 10–20 Minuten, danach startet der Server neu.
  3. Der Bildschirm des Servers zeigt die Adresse der Webkonsole und das Anfangspasswort von admin. Öffnen Sie die Adresse, melden Sie sich an und ändern Sie das Passwort.

Die Appliance (Image oder ISO)

Die Appliance hat zwei getrennte Konten:

  • admin in der Webkonsole (https://<address>:8443) für die tägliche Arbeit. Sein Anfangspasswort wird nach dem ersten Start auf dem Bildschirm des Servers angezeigt; ändern Sie es unter Mein Konto.
  • bzadmin auf dem Server selbst (sein Bildschirm in der Hypervisor-Konsole oder SSH), Anfangspasswort backupzit. Sie müssen es bei der ersten Anmeldung ändern; der Benutzer kann sudo verwenden. Root kann sich nicht anmelden.

Updates von BackupZit und dem Betriebssystem werden aus der Konsole verwaltet (siehe unten). VMware Tools und der QEMU-Gast-Agent sind enthalten, sodass Hypervisoren die Adresse der Appliance anzeigen.

Setup-Menü auf dem Bildschirm des Servers

Wenn sich bzadmin am eigenen Bildschirm des Servers anmeldet (nicht über SSH), öffnet sich ein Menü:

PunktWas er tut

Dieselben Einstellungen für Netzwerk, Servername, SSH und Zeitzone finden Sie in der Webkonsole unter Einstellungen → Netzwerk (nur Administratoren). Dort wird eine statische Adresse, deren Gateway nicht innerhalb einer halben Minute antwortet, automatisch zurückgenommen, sodass ein Tippfehler die Appliance nicht vom Netzwerk trennen kann; ist die Konsole trotzdem nicht erreichbar, verwenden Sie das Menü auf dem Bildschirm des Servers, das auch bei ausgeschaltetem SSH funktioniert.

Agenten merken sich das Zertifikat der Konsole, nicht ihre Adresse. Erreichen sie die Konsole über ihre IP-Adresse und ändert sich die Adresse, richten Sie sie mit backupzit-agent set-server auf die neue aus (siehe Agenten) oder verwenden Sie von Anfang an einen DNS-Namen. Bei DHCP reservieren Sie die Adresse der Appliance im DHCP-Server, damit sie sich nicht ändert.

Der SSH-Server der Appliance bietet nur AES-GCM/CTR-Chiffren und SHA-2-MACs an (kein chacha20-poly1305 und keine 64-Bit-MACs, die Schwachstellenscanner als schwach melden).

3. Installationsskript

Auf einem vorhandenen Server mit Debian 12+, Ubuntu 22.04+, AlmaLinux oder Rocky Linux 9+ (x86-64), als root:

curl -fsSL https://github.com/Max-Zit/backupzit/releases/latest/download/install.sh | sudo sh

Das Skript installiert PostgreSQL, lädt die neueste Version herunter, prüft ihre Signatur mit dem BackupZit-Versionsschlüssel und die Paketprüfsumme, installiert die Konsole, legt die Datenbank mit einem zufälligen Passwort an, schreibt /etc/backupzit/server.env, schaltet automatische Sicherheitsupdates ein, öffnet Port 8443 in firewalld oder ufw, falls aktiv, startet die Konsole und gibt ihre Adresse und das anfängliche admin-Passwort aus. Optionen (nach sh -s --):

OptionWirkung
--version 0.32.0diese Version statt der neuesten installieren
--db postgres://user:pw@host:5432/dbeine vorhandene PostgreSQL-Datenbank statt einer lokalen verwenden
--hosts backup.example.local,10.0.0.10Namen und Adressen für das Zertifikat der Konsole (Standard: Adresse und Name des Servers)
--no-auto-updatesautomatische Sicherheitsupdates unverändert lassen

Beispiel: curl -fsSL …/install.sh | sudo sh -s -- --hosts backup.example.local. Ein erneuter Aufruf des Skripts auf einer installierten Konsole aktualisiert BackupZit und behält Konfiguration und Daten. Um das Skript vor dem Ausführen zu lesen, laden Sie es zuerst herunter: curl -fsSLO …/install.sh; less install.sh; sudo sh install.sh.

4. Pakete von Hand

Debian / Ubuntu

apt install postgresql
apt install ./backupzit-server_*.deb

AlmaLinux / Rocky Linux

dnf install postgresql-server && postgresql-setup --initdb && systemctl enable --now postgresql
dnf install ./backupzit-server-*.rpm

Ändern Sie unter AlmaLinux und Rocky Linux in /var/lib/pgsql/data/pg_hba.conf für die Zeilen 127.0.0.1 und ::1 ident in scram-sha-256 und starten Sie PostgreSQL neu, damit sich die Konsole mit einem Passwort anmelden kann.

Datenbank anlegen

sudo -u postgres psql -c "SET password_encryption = 'scram-sha-256'; CREATE USER backupzit WITH PASSWORD 'choose-a-strong-password'"
sudo -u postgres psql -c "CREATE DATABASE backupzit OWNER backupzit"

Tragen Sie die Verbindungszeichenfolge in /etc/backupzit/server.env ein:

BACKUPZIT_DB=postgres://backupzit:choose-a-strong-password@localhost:5432/backupzit?sslmode=disable
BACKUPZIT_PUBLIC_URL=https://backup.example.local:8443
BACKUPZIT_TLS_HOSTS=backup.example.local,10.0.0.10
systemctl start backupzit-server

Erste Anmeldung

Öffnen Sie https://<server>:8443. Der anfängliche Administrator ist admin; das Passwort steht in /var/lib/backupzit/initial-admin-password.txt (oder setzen Sie BACKUPZIT_ADMIN_PASSWORD vor dem ersten Start). Ändern Sie es nach der Anmeldung. Ein vergessenes Passwort setzen Sie auf dem Server so zurück:

set -a; . /etc/backupzit/server.env; set +a
backupzit-server --set-admin-password 'NEW-PASSWORD'

Das Zertifikat

Beim ersten Start erstellt die Konsole ein selbstsigniertes Zertifikat. Ihr Browser warnt einmal davor; Agenten verlassen sich überhaupt nicht auf Zertifizierungsstellen — sie pinnen den Zertifikat-Fingerabdruck, der bei der Registrierung auf der Seite Agenten angezeigt wird. Das schützt Agenten auch in einem nicht vertrauenswürdigen Netzwerk vor einem gefälschten Server.

Ersetzen Sie dieses Zertifikat nicht (cert.pem/key.pem im Datenverzeichnis): Früher registrierte Agenten würden die Verbindung verweigern, bis sie erneut registriert sind. Fügen Sie für Browser stattdessen ein vertrauenswürdiges Zertifikat hinzu, wie unten beschrieben.

Ein vertrauenswürdiges Zertifikat für Browser

Um die Browserwarnung zu vermeiden, öffnen Sie Einstellungen → Zertifikat. Die Konsole antwortet dann zusätzlich unter einem DNS-Namen, zum Beispiel https://backup.example.com auf Port 443, mit einem vertrauenswürdigen Zertifikat. Agenten nutzen weiterhin Port 8443 und das gepinnte Zertifikat und sind daher nicht betroffen.

  • Zertifikat hochladen von Ihrer Firmen-CA oder einer öffentlichen CA, auch ein Wildcard-Zertifikat wie *.example.com. Fügen Sie das Zertifikat (mit seinen Zwischenzertifikaten) und den privaten Schlüssel als PEM ein oder wählen Sie die Dateien. Die Konsole prüft, dass der Schlüssel zum Zertifikat gehört, dass es jetzt gültig ist und den DNS-Namen abdeckt. Ohne internes DNS geben Sie stattdessen die IP-Adresse der Konsole ein und verwenden ein für diese IP-Adresse ausgestelltes Zertifikat (Subject Alternative Name IP:192.168.1.20); geben Sie der Konsole dann eine feste Adresse. Sie erhalten 21 Tage vor Ablauf eine E-Mail.
  • Let's Encrypt: kostenlose Zertifikate, automatisch 30 Tage vor Ablauf erneuert. Let's Encrypt muss prüfen, dass Sie den Namen kontrollieren, auf eine von zwei Arten:
    • DNS-Prüfung über Cloudflare, empfohlen für Konsolen, die nicht aus dem Internet erreichbar sind. BackupZit legt mit einem Cloudflare-API-Token einen temporären TXT-Eintrag an. Gehen Sie in Cloudflare zu My Profile → API Tokens → Create Token, verwenden Sie die Vorlage Edit zone DNS und beschränken Sie es auf Ihre Zone.
    • HTTP-Prüfung: Port 80 der Konsole muss unter dem DNS-Namen aus dem Internet erreichbar sein. Das ist für einen Sicherungsserver selten gewünscht.
    Probieren Sie die Einrichtung zuerst mit Das Let's-Encrypt-Testsystem verwenden. Seinen Zertifikaten vertrauen Browser nicht, aber es hat keine Ratenbegrenzungen.
  • Port 80 bedienen leitet http:// auf https:// um.

Der DNS-Name muss auf die IP-Adresse der Konsole zeigen, meist über einen A-Eintrag in Ihrem internen DNS. Die Zertifikatsdateien liegen in /var/lib/backupzit/web, und der Schlüssel ist nur für den Dienst lesbar. Unter Linux darf der Dienst die Ports 80 und 443 verwenden (CAP_NET_BIND_SERVICE); öffnen Sie sie in der Firewall, wenn Browser aus anderen Netzwerken zugreifen.

BackupZit aktualisieren

Standardmäßig bezieht die Konsole Updates aus den offiziellen BackupZit-Versionen auf GitHub (https://github.com/Max-Zit/backupzit/releases). Unter Einstellungen → Updates können Sie stattdessen eine andere Update-Quelle eintragen — Ihren eigenen HTTPS-Spiegel oder einen Ordner auf dem Server. Unabhängig von der Quelle muss jede Version eine gültige BackupZit-Signatur tragen. Die Konsole prüft täglich auf neue Versionen und schickt den Administratoren eine E-Mail, wenn eine verfügbar ist. Zum Installieren klicken Sie auf Installieren:

  1. Die Konsole prüft die Versionssignatur und die Paketprüfsumme und wartet, bis keine Sicherung oder Wiederherstellung läuft.
  2. Ein Systemdienst (backupzit-update, läuft als root) prüft die Signatur erneut mit den in BackupZit eingebauten Versionsschlüsseln. Selbst eine kompromittierte Konsole kann so kein anderes Paket installieren lassen.
  3. Er sichert die Datenbank (pg_dump), behält das aktuelle Programm, installiert das Paket und startet die Konsole neu.
  4. Antwortet die neue Version nicht innerhalb von zwei Minuten, werden das vorherige Programm und die Datenbank im vorherigen Zustand automatisch wiederhergestellt. Das Ergebnis mit dem Protokoll des fehlgeschlagenen Starts wird auf der Seite Updates angezeigt, im Audit-Protokoll festgehalten und per E-Mail versendet.
  5. Nach einem erfolgreichen Update werden auch die Agenten aktualisiert: Jeder installiert die neue Version, wenn er untätig ist. Schalten Sie das auf derselben Seite aus, wenn Sie sie lieber selbst aktualisieren.

Die Konsole ist etwa eine Minute lang nicht verfügbar. Die Datenbanksicherungen und vorherigen Programme der letzten drei Updates werden in /var/lib/backupzit-update aufbewahrt.

Ohne Internetzugang: Laden Sie die Versionsdateien (manifest.json, manifest.json.sig und das Serverpaket) auf einem anderen Computer herunter. Laden Sie sie dann unter Update aus Dateien installieren hoch, oder kopieren Sie sie in einen Ordner auf dem Server und verwenden Sie diesen Ordner als Update-Quelle.

Sie können weiterhin mit dem Paketmanager aktualisieren (apt install ./backupzit-server_….deb); die Datenbank wird migriert, wenn die neue Version startet.

Betriebssystem-Updates

Dieselbe Seite (Einstellungen → Updates) zeigt das Betriebssystem des Konsolenservers: wie viele Updates verfügbar sind, wie viele davon Sicherheitskorrekturen sind, ob ein Neustart nötig ist und ob automatische Sicherheitsupdates eingeschaltet sind. Der Status wird täglich aktualisiert oder mit Jetzt prüfen. Sie können:

  • Automatische Sicherheitsupdates einschalten (empfohlen). Das systemeigene Werkzeug installiert täglich nur Sicherheitskorrekturen: unattended-upgrades unter Debian und Ubuntu, dnf-automatic unter AlmaLinux und Rocky Linux.
  • Jetzt alle Updates installieren. Dienste wie PostgreSQL können kurz neu starten, und die Konsole verbindet sich von selbst wieder.
  • Server neu starten, zum Beispiel nach einem Kernel-Update. Die Konsole verweigert das, während Sicherungen oder Wiederherstellungen laufen. Agenten behalten ihre Aufträge und melden die Ergebnisse, sobald die Konsole zurück ist.

Diese Aufgaben laufen über denselben root-Dienst wie Konsolen-Updates. Sie werden im Audit-Protokoll festgehalten, und die Ausgabe der letzten Aufgabe wird auf der Seite angezeigt.

Die Konsole selbst sichern

Sicherungen auf Ihrem Speicher bleiben mithilfe der Wiederherstellungsblätter auch ohne die Konsole lesbar. Um nach dem Verlust ihres Servers auch die Konsole selbst zurückzubekommen, schalten Sie Einstellungen → Konsolensicherung ein. Das umfasst Aufträge, Zeitpläne, Agenten, Benutzer, Einstellungen, Laufverlauf und gespeicherte Zugangsdaten. Die Konsole sichert sich dann täglich auf ein Netzwerk-Speicherziel, in den Ordner backupzit-console.

Eine Konsolensicherung enthält:

  • die ganze Datenbank, Tabelle für Tabelle exportiert, sodass keine bestimmte pg_dump-Version nötig ist;
  • den Geheimnisschlüssel, der die gespeicherten Zugangsdaten entschlüsselt;
  • das Zertifikat der Konsole, das die Agenten pinnen.

Sie ist mit dem Wiederherstellungsschlüssel des Ziels verschlüsselt und dedupliziert. Die neuesten Sicherungen werden behalten: standardmäßig 14.

Die Konsole wiederherstellen

  1. Installieren Sie eine neue Konsole mit derselben oder einer neueren Version, zum Beispiel vom Appliance-ISO.
  2. Führen Sie auf dem neuen Server als root Folgendes aus. Die Zugangsdaten stammen vom Wiederherstellungsblatt des Speicherziels, und die Repository-Adresse wird auf der Seite Konsolensicherung angezeigt. 
    systemctl stop backupzit-server
set -a; . /etc/backupzit/server.env; set +a
export BACKUPZIT_PASSWORD='<recovery key>'
export BACKUPZIT_SFTP_PASSWORD='…' BACKUPZIT_SFTP_HOSTKEY='SHA256:…'   # or BACKUPZIT_S3_ACCESS_KEY/_SECRET_KEY, _SMB_PASSWORD, _AZURE_KEY, _HARDENED_KEY/_FINGERPRINT
backupzit-server --restore-console --repo 'sftp://backup@nas:22/backups/backupzit-console'
systemctl start backupzit-server
  3. Geben Sie dem neuen Server die IP-Adresse oder den DNS-Namen des alten Servers. Die Agenten vertrauen dem wiederhergestellten Zertifikat und verbinden sich von selbst wieder.

Die Wiederherstellung ersetzt die Datenbank der neuen Konsole durch die Sicherung und bringt die Datenbank auf den Stand der installierten Version. --snapshot ID stellt statt der neuesten eine ältere Sicherung wieder her.

Bewahren Sie außerdem eine Kopie der Wiederherstellungsblätter und von secrets.key außerhalb des Servers auf, zum Beispiel in Ihrem Passwortmanager.
