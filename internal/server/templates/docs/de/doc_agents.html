Agenten

Auf jedem geschützten Rechner wird ein Agent installiert. Er läuft als Dienst, fragt die Konsole alle 30 Sekunden nach Arbeit und spricht direkt mit dem Speicher.

Unterstützte Systeme

  • Windows 10, 11 und Windows Server 2016 und neuer — MSI Windows-Agent.
  • Windows 7 SP1, Windows Server 2008 R2 SP1 und 2012 R2 — MSI Windows-Agent — ältere Systeme (…-legacy.msi), mit denselben Funktionen einschließlich VSS und Festplattenabbildern.
  • Debian, Ubuntu, AlmaLinux, Rocky Linux (64 Bit).
  • Proxmox-VE-7- und -8-Knoten — das Debian-Paket; der Agent sichert dann auch die VMs und Container des Knotens (siehe Proxmox VE).
  • Hyper-V-Hosts (Windows Server 2016 und neuer, Windows 10/11 mit Hyper-V): das Windows-MSI. Der Agent sichert dann auch die VMs des Hosts (siehe Hyper-V).
  • VMware-ESXi-Hosts — auf ESXi wird nichts installiert: Fügen Sie den Host unter VMware-ESXi-Hosts hinzu und wählen Sie einen Agenten als Proxy (siehe VMware ESXi).

Agenten registrieren

  1. Klicken Sie auf der Seite Agenten auf Registrierungstoken erstellen. Die Konsole zeigt einen Registrierungscode (BZ1-…), 7 Tage gültig und für beliebig viele Rechner nutzbar. Er enthält die Konsolenadresse für Agenten (mit dem Agenten-Port, meist 8443, auch wenn die Seite über den Web-Port 443 geöffnet ist), das Token und den Zertifikat-Fingerabdruck. Agenten ab 0.33.6 registrieren sich auch mit Codes, die ältere Konsolen auf dem Web-Port erstellt haben.
  2. Windows: Führen Sie das MSI aus und fügen Sie den Code ein, wenn das Installationsprogramm danach fragt. Linux: Führen Sie den angezeigten Befehl aus.
  3. Der Rechner erscheint innerhalb einer Minute in der Agentenliste.

Ist die Konsole während der Installation nicht erreichbar, behält der Agent den Code und versucht es erneut, bis er sich registrieren kann. Upgrades behalten die Registrierung und fragen nicht erneut. Eine stille Installation mit ENROLLCODE auf einem bereits registrierten Rechner behält die Registrierung, wenn der Code für dieselbe Konsole ist (GPO oder RMM können sie gefahrlos wiederholen), und verschiebt den Rechner, wenn der Code für eine andere Konsole ist; die vorherige Registrierung bleibt als agent.json.replaced-Datum neben agent.json erhalten, sodass das Zurückbenennen den Rechner als denselben Agenten zu seiner alten Konsole zurückbringt.

Windows, still (GPO, Intune, RMM)

msiexec /i backupzit-agent.msi /qn ENROLLCODE="BZ1-..."

Die ältere Form SERVER="..." TOKEN="..." FINGERPRINT="SHA256:..." funktioniert weiterhin. Eine stille Installation ohne diese Eigenschaften richtet den Dienst ein, der wartet, bis Sie ihn mit backupzit-agent enroll --code "BZ1-..." in einer Administrator-Eingabeaufforderung registrieren.

Linux

apt install ./backupzit-agent_*.deb        # or: dnf install ./backupzit-agent-*.rpm
backupzit-agent enroll --code "BZ1-..."
systemctl enable --now backupzit-agent

Agenten aus der Konsole installieren

Statt Installationsprogramme auf jeden Rechner zu kopieren, lassen Sie die Konsole den Agenten installieren: Öffnen Sie unter Agenten Von hier aus auf einem Rechner installieren, wählen Sie Linux oder Windows und geben Sie die Adresse des Rechners und ein Administratorkonto ein.

  • Linux (Debian, Ubuntu, AlmaLinux, Rocky Linux; 64 Bit): Die Konsole verbindet sich über SSH als root oder als Benutzer mit sudo-Rechten (das Passwort wird auch für sudo verwendet; mit einem Schlüssel ist sudo ohne Passwort nötig). Passwort oder privater Schlüssel funktionieren. Geben Sie den SSH-Host-Key-Fingerabdruck des Rechners ein (ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub auf dem Rechner), damit die Konsole sicher mit dem richtigen Rechner spricht; ohne ihn wird der Fingerabdruck im Installationsprotokoll angezeigt.
  • Windows (64 Bit): Die Konsole verbindet sich über WinRM (Port 5985, Nachrichten mit NTLM verschlüsselt; 5986 für einen HTTPS-Listener) als lokaler oder Domänenadministrator. WinRM ist auf Windows Server standardmäßig aktiv; unter Windows 10/11 führen Sie einmal winrm quickconfig als Administrator aus. Lokale Konten außer dem integrierten Administrator brauchen Remote-Administratorrechte (LocalAccountTokenFilterPolicy) — oder verwenden Sie ein Domänenkonto. Ältere Systeme (Windows 7, Server 2008 R2/2012 R2) erhalten das Legacy-MSI.

Der Rechner lädt das neueste Agentenpaket über einen Link von der Konsole, der nur für diese Installation gilt (30 Minuten, drei Downloads), prüft seine SHA-256-Prüfsumme, installiert es und registriert sich. Die Installationsseite zeigt jeden Schritt; Konto und Passwort werden nur dafür verwendet und nicht gespeichert. Ist der Rechner bereits bei dieser Konsole registriert, bleibt die Registrierung erhalten und das Paket wird aktualisiert; eine der Konsole unbekannte Registrierung (ein früher entfernter Agent oder eine andere Konsole) wird ersetzt. Jede Installation steht im Audit-Protokoll. Der Rechner muss die Agentenadresse der Konsole erreichen, wie jeder Agent.

Agentenstatus

  • online — der Agent hat die Konsole in den letzten 3 Minuten kontaktiert.
  • offline — der Rechner ist aus, der Dienst gestoppt oder das Netzwerk blockiert. Geplante Sicherungen werden eingereiht und starten, sobald der Agent zurück ist.
  • Wiederherstellung — ein von einem Wiederherstellungs-ISO (Windows oder Linux) gestarteter Rechner, bereit für die Wiederherstellung eines Festplattenabbilds oder Linux-Systems. Wiederherstellungsagenten sind vorübergehend; entfernen Sie sie, wenn die Wiederherstellung abgeschlossen ist.

Die Spalte IP-Adressen listet die eigenen Adressen des Rechners, wie der Agent sie zuletzt gemeldet hat. gesehen von ist die Adresse, von der seine Verbindungen ankommen: im lokalen Netz dieselbe Adresse, bei einem Rechner hinter NAT (z. B. einem Laptop zu Hause) die öffentliche Adresse des Routers. Die Konsole fragt dafür keinen externen Dienst.

Der Agent auf dem Desktop (Windows)

Der Windows-Agent zeigt ein Symbol neben der Uhr (es kann unter dem Pfeil ^ der ausgeblendeten Symbole liegen — ziehen Sie es auf die Taskleiste, damit es sichtbar bleibt). Der Punkt auf dem Symbol zeigt den Zustand:

PunktBedeutung
grünSicherungen sind in Ordnung (oder warten auf die erste geplante Sicherung).
blauEine Sicherung, Wiederherstellung oder ein Wiederherstellungstest läuft.
orangeDie letzte Sicherung endete mit Warnungen (Dateien, die nicht gelesen werden konnten).
rotEin Sicherungsauftrag ist fehlgeschlagen.
grauDie Konsole ist nicht erreichbar oder der Agentendienst läuft nicht.

Klicken Sie auf das Symbol (oder öffnen Sie BackupZit Agent im Startmenü) für das Statusfenster: Schutzstatus, Fortschritt einer laufenden Sicherung, letzte und nächste Sicherung und alle Sicherungsaufträge des Computers mit Jetzt sichern. Rechtsklick öffnet das Menü: Back up now pro Auftrag, Open console in browser, Hide this icon (bis zur nächsten Anmeldung; Sicherungen laufen weiter). Das Fenster benötigt Microsoft Edge WebView2, das Teil von Windows 10 und 11 ist; auf älteren Systemen funktionieren Symbol und Menü, und Open zeigt die Konsole im Browser.

Benutzer können so eine Sicherung ihres Computers starten; Aufträge, Zeitpläne und Aufbewahrung werden nur in der Konsole festgelegt. Auf jedem System gibt backupzit-agent status (als Administrator oder root) dieselben Informationen aus.

Aktualisieren

Hat die Konsole ein neueres Agenten-Installationsprogramm als ein Agent ausführt, zeigt die Seite Agenten Aktualisieren auf x.y.z neben seiner Version und Alle Agenten aktualisieren unter der Liste. Der Agent dann:

  1. wartet, bis er untätig ist (eine laufende Sicherung wird nie unterbrochen),
  2. lädt das passende Installationsprogramm über seine gepinnte Verbindung von der Konsole — das MSI für Windows 10/11/2016+, das MSI ältere Systeme für Windows 7/2008 R2/2012 R2, das deb- oder rpm-Paket unter Linux — und prüft seine SHA-256,
  3. installiert es und startet neu; die neue Version erscheint innerhalb weniger Minuten in der Liste. Registrierung und alle Einstellungen bleiben erhalten.

Die Konsole bietet die neuesten Installationsprogramme in ihrem Verzeichnis dist an; das Serverpaket liefert die Agenten-Installationsprogramme seiner eigenen Version mit. Nachdem die Konsole über Einstellungen → Updates aktualisiert wurde, werden die Agenten automatisch aktualisiert (dort abschaltbar). Updates aus der Konsole funktionieren für Agenten ab Version 0.21; ältere Agenten werden einmal aktualisiert, indem das neuere MSI / Paket über das alte installiert wird (die Registrierung bleibt erhalten). Das Protokoll des Installationsprogramms liegt in C:\ProgramData\backupzit\updates oder /var/tmp/backupzit-updates.

Einen Agenten entfernen

Entfernen auf der Seite Agenten löscht den Agenten und seine Aufträge aus der Konsole. Mit eingeschalteter Vier-Augen-Freigabe muss ein zweiter Benutzer zuerst zustimmen. Sicherungen auf dem Speicher werden nicht gelöscht. Deinstallieren Sie die Software auf dem Rechner separat.

Zwei Rechner mit einem Agenten

Eine Kopie eines registrierten Rechners nimmt ihren Agenten und die Registrierung mit: eine als neue VM wiederhergestellte VM, eine Sofortwiederherstellung, ein gestartetes Replikat, eine geklonte Festplatte oder Vorlage. Läuft die Kopie neben dem Original, verbinden sich beide als derselbe Agent. Die Konsole bemerkt das innerhalb von ein, zwei Minuten und dann:

  • zeigt sie zwei Rechner mit beiden Namen und Adressen auf der Seite Agenten und den Agenten unter Benötigt Aufmerksamkeit im Dashboard;
  • hält sie die Sicherungen und Wiederherstellungen des Agenten an, damit nichts auf dem falschen Rechner läuft (eine Wiederherstellung an den ursprünglichen Ort könnte sonst die Kopie statt des Originals überschreiben);
  • sendet sie den Administratoren einmal eine E-Mail und schreibt einen Eintrag agent.duplicate ins Audit-Protokoll.

Stoppen Sie die Kopie oder — wenn sie bleiben soll — registrieren Sie sie auf der Kopie als neuen Rechner: backupzit-agent enroll --force --code "BZ1-..." (Code von der Seite Agenten). Die angehaltenen Läufe starten einige Minuten, nachdem nur noch ein Rechner übrig ist. Die Wiederherstellung eines Linux-Systems mit Ganzes System wiederherstellen hebt die Registrierung in der wiederhergestellten Kopie bereits auf, und Wiederherstellungstests starten ihre VMs ohne Netzwerk, sodass keines von beiden dies verursacht.

Wenn die Konsole eine neue Adresse bekommt

Agenten vertrauen der Konsole anhand ihres Zertifikats, das gleich bleibt, wenn sich IP-Adresse oder Name ändern, aber sie verbinden sich mit der Adresse, mit der sie registriert wurden. Führen Sie nach einer Änderung auf jedem Agentenrechner aus (als Administrator / root):

backupzit-agent set-server https://192.168.1.20:8443

Der Befehl prüft, dass die Konsole unter der neuen Adresse mit demselben Zertifikat antwortet, speichert sie, und der Agent verwendet sie nach einem Neustart seines Dienstes (systemctl restart backupzit-agent oder unter Windows den Dienst BackupZit Agent neu starten). Ein DNS-Name für die Konsole von Anfang an erspart diesen Schritt.

Wo der Agent seine Konfiguration speichert

  • Windows: C:\ProgramData\backupzit\agent.json (nur für SYSTEM und Administratoren zugänglich).
  • Linux: /etc/backupzit/agent.json (nur root).

Die Datei enthält das Geheimnis des Agenten. Wer sie lesen kann, kann als dieser Agent auftreten, behalten Sie also diese Berechtigungen bei.

Agentenprotokoll

  • Windows: C:\ProgramData\backupzit\agent.log
  • Linux: /etc/backupzit/agent.log und journalctl -u backupzit-agent
  • Wiederherstellungssysteme zeigen das Protokoll auf ihrem Bildschirm.

Deinstallieren

Windows: Einstellungen → Apps → BackupZit Agent → Deinstallieren (oder msiexec /x). Linux: apt remove backupzit-agent / dnf remove backupzit-agent. Entfernen Sie dann den Agenten in der Konsole. Sicherungen bleiben auf dem Speicher.

Unter Windows legt die Deinstallation die Registrierung beiseite (C:\ProgramData\backupzit\agent.json.removed-Datum), sodass eine erneute Installation des Agenten nach einem Registrierungscode fragt. Findet das Installationsprogramm eine Registrierung einer früheren Version, sagt es das: Lassen Sie den Code leer, um sie zu behalten, oder fügen Sie einen neuen Code ein, um den Computer erneut zu registrieren (zum Beispiel bei einer anderen Konsole).
