Erste Schritte

BackupZit schützt Windows- und Linux-Rechner, virtuelle Maschinen unter Proxmox VE, Hyper-V und VMware ESXi, Datenbanken (SQL Server, PostgreSQL, MySQL/MariaDB) und NAS-Freigaben — Dateien, ganze Festplatten und ganze Systeme — aus einer Webkonsole, die in Ihrem eigenen Netzwerk läuft.

Wie BackupZit funktioniert

  • Verwaltungskonsole (diese Webanwendung) — läuft auf einem Linux-Server in Ihrem Netzwerk. Sie speichert die Konfiguration, plant Aufträge, sammelt Ergebnisse und zeigt Berichte. Sie muss nie aus dem Internet erreichbar sein.
  • Agenten — ein kleiner Dienst auf jedem geschützten Rechner (Windows-MSI, Linux deb/rpm) und auf Proxmox- und Hyper-V-Hosts; VMware-ESXi-Hosts werden über einen Agenten als Proxy erreicht. Agenten kontaktieren die Konsole über HTTPS, erhalten Aufträge und senden die Sicherungsdaten direkt an den Speicher. Unter Windows zeigt der Agent seinen Zustand neben der Uhr.
  • Speicherziele — wo Sicherungen aufbewahrt werden: SFTP, S3-kompatibler Objektspeicher (AWS, Wasabi, Backblaze B2, MinIO, Google Cloud…), Azure Blob Storage, eine SMB-Freigabe/NAS, rotierende USB-Festplatten, eine lokale oder eingebundene Festplatte oder ein gehärtetes BackupZit-Repository.

Sicherungsdaten laufen nie durch die Konsole. Die Konsole koordiniert nur, daher genügt eine kleine virtuelle Maschine.

Erste Schritte

Um eine neue Konsole einzurichten, importieren Sie das fertige Appliance-Image in eine kleine VM, starten Sie das Appliance-ISO oder führen Sie das Installationsskript auf einem vorhandenen Linux-Server aus; siehe Server installieren.

  1. Fügen Sie ein Speicherziel hinzu unter Speicher. Lassen Sie Sicherungen verschlüsseln eingeschaltet und bewahren Sie das danach angezeigte Wiederherstellungsblatt sicher auf. Siehe Speicherziele.
  2. Installieren Sie Agenten: Klicken Sie unter Agenten auf Registrierungstoken erstellen, laden Sie das Installationsprogramm von derselben Seite herunter und fügen Sie den Registrierungscode ein, wenn das Windows-Installationsprogramm danach fragt (Linux: backupzit-agent enroll --code …). Für VMs installieren Sie den Agenten auf dem Proxmox- oder Hyper-V-Host; VMware-ESXi-Hosts fügen Sie unter Agenten → VMware-ESXi-Hosts hinzu. Siehe Agenten.
  3. Erstellen Sie einen Sicherungsauftrag unter Sicherungsaufträge: Wählen Sie den Agenten, den Speicher, was gesichert wird (Dateien, eine NAS-Freigabe, ein Festplattenabbild, Datenbanken, das ganze Linux-System oder die VMs eines Proxmox-, Hyper-V- oder VMware-ESXi-Hosts), wann er läuft und wie viele Sicherungen behalten werden. Siehe Sicherungsaufträge und Zeitpläne.
  4. Führen Sie ihn einmal manuell aus mit Sicherung jetzt ausführen auf der Auftragsseite und prüfen Sie das Ergebnis unter Aktivität.
  5. Testen Sie eine Wiederherstellung — eine Sicherung ist nur so gut wie ihre Wiederherstellung. Automatische Wiederherstellungstests laufen wöchentlich; stellen Sie auch einmal etwas von Hand mit dem Wiederherstellungsassistenten wieder her. Siehe Wiederherstellen.
  6. Bereiten Sie sich auf Katastrophen vor: Laden Sie die Wiederherstellungs-ISOs herunter und erstellen Sie einen Wiederherstellungscode unter Wiederherstellungsmedien.
  7. Richten Sie E-Mail-Warnungen ein unter Einstellungen → E-Mail-Benachrichtigungen, damit Sie von Fehlern erfahren, und optional einen wöchentlichen Bericht.

Sprache

Die Konsole ist in 14 Sprachen verfügbar: Englisch, Deutsch, Französisch, Spanisch, Italienisch, Portugiesisch (Brasilien), Niederländisch, Polnisch, Tschechisch, Serbisch (lateinische Schrift), Türkisch, Russisch, Chinesisch (vereinfacht) und Japanisch. Wählen Sie eine in der Sprachliste oben rechts oder auf der Anmeldeseite; die Wahl wird im Browser gespeichert. Ohne Wahl entscheidet die Sprache des Browsers (kroatische, bosnische und montenegrinische Browser erhalten Serbisch, slowakische Tschechisch, andere Sprachen Englisch). Auch diese Anleitung ist übersetzt (eine Seite ohne Übersetzung wird auf Englisch angezeigt). E-Mails, Chat-Benachrichtigungen und von den Agenten gemeldete Meldungen bleiben auf Englisch.

Die Übersetzungen liegen im Quellcode in internal/server/i18n/de.json: Der englische Text ist der Schlüssel, die Übersetzung sein Wert. go run ./tools/i18n missing de listet Texte ohne Übersetzung; nicht übersetzte Texte werden auf Englisch angezeigt.

Grundbegriffe

Snapshots und Deduplizierung

Jede Sicherung erstellt einen Snapshot: ein vollständiges, durchsuchbares Bild der Daten zu diesem Zeitpunkt. Dateien werden in Blöcke variabler Größe und Festplatten in Blöcke zerlegt, und jedes Stück wird nur einmal gespeichert, sodass die zweite und alle späteren Sicherungen nur Geändertes hochladen — und doch lässt sich jeder Snapshot für sich wiederherstellen. Es gibt keine „Voll- und inkrementelle Kette“ zu verwalten.

Repositories

Jeder Agent schreibt in sein eigenes Repository unterhalb des Speicherziels (<location>/<hostname>_<id>). Ein Repository ist in sich geschlossen: Mit dem Ort, den Speicherzugangsdaten und dem Wiederherstellungsschlüssel lässt es sich wiederherstellen, auch wenn die Konsole weg ist.

Aufbewahrung

Jeder Auftrag behält eine Anzahl aktueller, täglicher, wöchentlicher und monatlicher Sicherungen. Ältere Snapshots werden nach jedem Lauf entfernt und ihr Platz freigegeben.

Was BackupZit für Sie prüft

  • Wiederherstellungstests — die neueste Sicherung jedes Auftrags wird wöchentlich teilweise wiederhergestellt und überprüft (Wiederherstellen).
  • Ransomware-Erkennung — ungewöhnliche Sicherungen (Massenänderungen, verschlüsselte Daten, Massenlöschung, plötzliche Sprünge der Datenmenge) werden markiert und die Aufbewahrung pausiert (Ransomware-Schutz).
  • Warnungen und Berichte — E-Mails bei Fehlern und eine tägliche Zusammenfassung; geplante Berichte für die Geschäftsleitung (E-Mail-Benachrichtigungen, Überwachung).
