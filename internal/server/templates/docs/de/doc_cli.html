Befehlszeilenreferenz

Der Agent funktioniert auch eigenständig über die Befehlszeile — für Skripte, für Wiederherstellungen ohne Konsole und für Notfälle. Führen Sie backupzit-agent ohne Argumente für eine Übersicht aus und backupzit-agent <command> -h für die Optionen eines Befehls.

Repository und Zugangsdaten

Jeder Befehl nimmt --repo (oder BACKUPZIT_REPO). Für Geheimnisse sind Umgebungsvariablen vorzuziehen. Das Repository eines Agenten ist <Speicherort>/<hostname>_<id> — siehe die Repository-Spalte eines Laufs in Aktivität oder das Wiederherstellungsblatt.

OrtZugangsdaten
D:\Backups\pc1, /mnt/backup/pc1—
sftp://user@host:22/pathBACKUPZIT_SFTP_PASSWORD oder --sftp-key file; --sftp-hostkey SHA256:… (BACKUPZIT_SFTP_HOSTKEY)
s3://endpoint/bucket/prefix (?tls=false für HTTP)BACKUPZIT_S3_ACCESS_KEY, BACKUPZIT_S3_SECRET_KEY, --s3-region; --s3-lock-days N schreibt mit Object Lock
smb://[domain;]user@host/share/pathBACKUPZIT_SMB_PASSWORD, --smb-domain
azure://account/container/path (?endpoint=URL für souveräne Clouds, Azure Stack, Azurite)BACKUPZIT_AZURE_KEY oder BACKUPZIT_AZURE_SAS
hardened://host:8500/pathBACKUPZIT_HARDENED_KEY, BACKUPZIT_HARDENED_FINGERPRINT
usb://LABEL/path (Platzhalter: usb://BZBACKUP*/BackupZit)— (es wird die angeschlossene Festplatte mit dieser Volumebezeichnung verwendet)

Verschlüsselte Repositories benötigen den Wiederherstellungsschlüssel in BACKUPZIT_PASSWORD (oder --password).

Ansicht zu einem Zeitpunkt: Auf S3 mit Object Lock und auf einem gehärteten Repository zeigt --as-of 2026-10-01T14:30 (oder ein Datum) das Repository so, wie es zu diesem Zeitpunkt war — nur lesend, zur Wiederherstellung, nachdem Sicherungen gelöscht oder überschrieben wurden.

Dateien und Ordner

BefehlWas er tut
initErstellt ein neues Repository (verschlüsselt, wenn ein Passwort angegeben ist).
backup [--vss] [--exclude PATTERN]… [--tag TAG]… [--force] [--host NAME] PATH…Sichert Dateien und Ordner. --vss liest aus einer Volumeschattenkopie (Windows, Administrator); --force liest alle Dateien, auch unveränderte.
snapshotsListet Snapshots mit Zeit, Host, Größe und Pfaden auf.
ls SNAPSHOT|latest [PATH]Listet Dateien in einem Snapshot auf.
restore --target DIR [--include PATH]… [--verify] SNAPSHOT|latestStellt Dateien unterhalb von DIR wieder her (die ursprüngliche Ordnerstruktur wird nachgebildet). --original schreibt sie stattdessen an ihren ursprünglichen Ort zurück und überschreibt vorhandene Dateien.
check [--read-data]Prüft die Repository-Struktur; mit --read-data wird jedes Byte heruntergeladen und geprüft.

Festplattenabbilder (Windows)

BefehlWas er tut
disks [--json]Zeigt Festplatten und Partitionen mit ihren Nummern.
image-backup --disk N [--partitions 1,2] [--no-vss]
image-backup --all-disks		Sichert eine ganze Festplatte oder ausgewählte Partitionen, oder jede interne Festplatte in einem Snapshot.
image-restore --target-disk N --yes-erase-target [--keep-offline] [--source-disk N] SNAPSHOT|latestSchreibt ein Abbild auf eine Festplatte; löscht die Festplatte. --keep-offline, wenn sich die Originalfestplatte in derselben Maschine befindet; --source-disk wählt die Festplatte einer Alle-Datenträger-Sicherung.
image-ls [--disk N] --partition N SNAPSHOT|latest [\path]Listet Dateien in einer abgebildeten NTFS-Partition auf (--disk: die gesicherte Festplatte, bei Alle-Datenträger-Sicherungen).
image-extract [--disk N] --partition N --target DIR SNAPSHOT|latest \path…Kopiert Dateien und Ordner aus einer abgebildeten Partition.

Linux-System (Bare Metal, P2V)

BefehlWas er tut
system-backup [--exclude PATTERN]Sichert alle lokalen Dateisysteme und das Festplattenlayout. Siehe Linux-Systemsicherung.
system-show SNAPSHOT|latestZeigt das Festplattenlayout in einer Systemsicherung.
system-restore --target DEVICE [--new-hardware] [--rebuild-initramfs] --yes-erase-target SNAPSHOT|latestErstellt das System auf einer leeren Festplatte, einem logischen Volume oder einer Abbilddatei neu.

Windows: andere Hardware

BefehlWas er tut
prepare-hardware --disk N [--drivers DIR]Bereitet eine wiederhergestellte Windows-Festplatte für andere Hardware vor (Boot-Treiber, zusätzliche Treiber, Bootdateien) — dasselbe wie die Wiederherstellungsoption, z. B. um es vom Wiederherstellungs-ISO aus zu wiederholen.

VMware ESXi (jeder Agent als Proxy; Passwort in BACKUPZIT_VMWARE_PASSWORD)

BefehlWas er tut
vmware list --host H [--user root]Zeigt die VMs des Hosts, den Lizenzmodus, die Fingerabdrücke von Zertifikat und SSH-Schlüssel sowie die Datastores.
vmware backup --host H [--vmid N,N]Sichert VMs (Standard: alle) aus Snapshots; mit Changed Block Tracking werden nur geänderte Blöcke gelesen.
vmware restore --host H --vmid N [--new] [--name X] [--datastore DS] [--overwrite] [--start] SNAPSHOT|latestStellt eine VM an Ort und Stelle (Standard) oder mit --new als neue VM wieder her. --overwrite ersetzt die Festplatten einer vorhandenen VM; die alten werden umbenannt behalten. Siehe VMware ESXi.
esxi-nfs-serveStellt die Sofort-VMs von ESXi-Hosts über NFS aus /var/lib/backupzit/instant-esxi bereit (Linux; von der Sofortwiederherstellung als systemd-Unit backupzit-esxi-nfs gestartet).

Pinnen Sie den Host mit --thumbprint SHA256:… und --ssh-host-key SHA256:… (von vmware list angezeigt).

Hyper-V (Agent auf dem Hyper-V-Host, als Administrator)

BefehlWas er tut
hyperv listListet die VMs des Hosts mit ihren BackupZit-Nummern und die Ordner für wiederhergestellte Festplatten auf.
hyperv backup [--vmid N,N]Sichert VMs (Standard: alle) aus Produktionsprüfpunkten.
hyperv restore --vmid N [--new] [--name X] [--folder DIR] [--overwrite] [--start] SNAPSHOT|latestStellt eine VM an Ort und Stelle (Standard) oder mit --new als neue VM wieder her. --overwrite ersetzt die Festplatten einer vorhandenen VM. Siehe Hyper-V.

pve show, pve ls und pve extract funktionieren auch mit Hyper-V-Sicherungen.

Proxmox VE (Agent auf dem Proxmox-Host)

BefehlWas er tut
pve listListet die VMs und Container des Clusters und den für Wiederherstellungen nutzbaren Speicher auf.
pve backup [--vmid 100,200] [--exclude 300]Sichert Gäste dieses Knotens (Standard: alle) aus Proxmox-Snapshots.
pve show SNAPSHOT|latestZeigt die Gäste und Festplatten in einer VM-Sicherung.
pve ls --vmid N [--disk scsi0] [--volume ID] SNAPSHOT|latest [path]Listet die Partitionen und logischen Volumes einer Gastfestplatte oder die Dateien in einem Ordner auf (NTFS, ext4, XFS, auch auf LVM).
pve extract --vmid N --target DIR [--volume ID] SNAPSHOT|latest path...Kopiert Dateien und Ordner von einer Gastfestplatte, ohne die VM wiederherzustellen.
pve restore --vmid N [--new-vmid -1|N] [--name X] [--storage S] [--overwrite] [--start] SNAPSHOT|latestErstellt einen Gast neu; --new-vmid -1 nimmt die nächste freie ID, --overwrite ersetzt einen vorhandenen Gast mit derselben ID. Siehe Proxmox VE.
pve instant --vmid N [--new-vmid N] [--name X] SNAPSHOT|latestSofortige Wiederherstellung: startet eine VM innerhalb von Sekunden, während ihre Festplatten aus der Sicherung gelesen werden (neue VM, standardmäßig nächste freie ID).
pve instant-finish --vmid N --storage SVerschiebt die Festplatten einer Sofort-VM während des Betriebs auf Speicher; danach nutzt sie die Sicherung nicht mehr.
pve instant-discard --vmid NStoppt und löscht eine Sofort-VM samt ihren Änderungen.
nbd-serve --snapshot ID --vmid N --socket PATHStellt die Festplatten einer VM in einer Sicherung schreibgeschützt über NBD an einem Unix-Socket bereit (von der Sofortwiederherstellung als systemd-Unit gestartet).

Microsoft SQL Server (Agent auf der SQL-Server-Maschine)

BefehlWas er tut
sql list [--instance I]Listet die Datenbanken einer Instanz mit Wiederherstellungsmodell und Größe auf.
sql backup [--instance I] [--db a,b] [--system] [--log] [--copy-only]Vollsicherungen (Standard: alle Benutzerdatenbanken) oder, mit --log, Transaktionslog-Sicherungen in das Repository.
sql showListet die SQL-Server-Sicherungen im Repository mit ihren LSN-Bereichen auf.
sql restore --db NAME [--as NEW] [--replace] [--at TIME] SNAPSHOT|latestStellt eine Datenbank aus einer Vollsicherung und den Log-Sicherungen danach wieder her, optional zu einem Zeitpunkt. Siehe SQL Server.

PostgreSQL und MySQL/MariaDB (Agent auf dem Datenbankserver)

BefehlWas er tut
pg list [--port P]Datenbanken des lokalen Clusters und ob die WAL-Archivierung aktiv ist.
pg backup [--port P] [--db a,b] [--pitr | --wal]Vollsicherung (pg_basebackup, pg_dump jeder Datenbank; --pitr richtet die WAL-Archivierung ein) oder, mit --wal, das archivierte WAL.
pg restore --db NAME|"(cluster)" [--as NEW] [--replace] [--at TIME | --latest] SNAPSHOT|latestStellt eine Datenbank (aus ihrem Dump oder zu einem Zeitpunkt) oder den ganzen Cluster als separate Instanz wieder her.
mysql listDatenbanken und ob das Binärlog aktiv ist.
mysql backup [--db a,b] [--binlog]mysqldump jeder Datenbank mit ihrer Binärlog-Position, oder die geschlossenen Binärlogs.
mysql restore --db NAME [--as NEW] [--replace] [--at TIME | --latest] SNAPSHOT|latestLädt einen Dump und spielt die Binärlogs bis zu einem Zeitpunkt ein. Siehe Datenbanken.

Verwalteter Modus

BefehlWas er tut
enroll --code BZ1-… [--force]Verbindet den Agenten mit dem Registrierungscode von der Seite Agenten mit einer Konsole (--force ersetzt eine vorhandene Registrierung). Die ältere Form --server URL --token T --fingerprint F funktioniert weiterhin.
set-server https://address:8443Richtet einen registrierten Agenten auf eine neue Adresse der Konsole aus (gleiches Zertifikat); starten Sie danach den Agentendienst neu. Siehe Agenten.
statusZeigt, was der laufende Agent gerade tut, und seine Sicherungsaufträge (das Windows-Tray-Symbol zeigt dasselbe).
service install|uninstall|start|stop|status|runVerwaltet den Agentendienst (das erledigen die Installationsprogramme).
recoveryWiederherstellungsmodus, automatisch von den Wiederherstellungs-ISOs gestartet; auf einem beliebigen Linux-Live-System: sudo backupzit-agent recovery --server URL --token CODE.
versionGibt die Version aus.

Beispiele

set BACKUPZIT_PASSWORD=XXXX-XXXX-...
set BACKUPZIT_S3_ACCESS_KEY=...
set BACKUPZIT_S3_SECRET_KEY=...
backupzit-agent snapshots --repo s3://s3.wasabisys.com/company-backups/backupzit/pc1_1a2b3c4d
backupzit-agent restore --repo s3://s3.wasabisys.com/company-backups/backupzit/pc1_1a2b3c4d --target D:\Restore --include C:\Users\ana\Documents latest
backupzit-agent check --repo s3://... --read-data

backupzit-agent disks
backupzit-agent image-ls --repo usb://BZBACKUP1/BackupZit/pc1_1a2b3c4d --partition 3 latest \Users
backupzit-agent snapshots --repo hardened://vault:8500/backupzit/pc1_1a2b3c4d --as-of 2026-10-01T14:00

Gehärtetes Repository (backupzit-repo)

BefehlWas er tut
backupzit-repo serveStartet den Dienst (das erledigt systemd).
backupzit-repo add-key NAMEErstellt einen Zugriffsschlüssel (wird einmal angezeigt).
backupzit-repo keys / remove-key NAMEZugriffsschlüssel auflisten / widerrufen.
backupzit-repo fingerprintZertifikat-Fingerabdruck für die Konsole.
backupzit-repo statusGespeicherte und verborgene (gelöschte, noch aufbewahrte) Daten.
backupzit-repo undelete --since TIMEMacht seit TIME gelöschte Dateien wieder sichtbar.

Konfiguration: /etc/backupzit-repo/repo.env — BACKUPZIT_REPO_LOCK_DAYS, BACKUPZIT_REPO_DATA, BACKUPZIT_REPO_LISTEN, BACKUPZIT_REPO_TLS_HOSTS.
