Linux-Systemsicherung & P2V

Ein Auftrag Linux-System sichert eine ganze Linux-Maschine, damit sie auf einer leeren Festplatte neu erstellt werden kann — dieselbe Maschine nach einem Festplattenausfall, neue Hardware oder eine virtuelle Maschine in Proxmox VE (physisch zu virtuell, P2V).

Was gesichert wird

  • Jedes lokale Dateisystem (ext2/3/4, xfs, vfat), auch auf LVM, Datei für Datei mit Besitzern, Berechtigungen, setuid-Bits, ACLs, erweiterten Attributen (SELinux-Labels, Datei-Capabilities), Hardlinks und Gerätedateien. Jedes Dateisystem wird separat gesichert; Netzwerkfreigaben und virtuelle Dateisysteme (/proc, /sys, /run) werden übersprungen.
  • Das Festplattenlayout: GPT- oder MBR-Partitionstabellen mit ihren IDs, LVM-Volumegruppen (vgcfgbackup), Dateisystem-UUIDs, Labels und On-Disk-Features sowie der Bootcode (MBR und die BIOS-Boot-Partition von GRUB).

Wie Relax-and-Recover kopiert BackupZit die laufende Festplatte nicht blockweise: Linux hat keinen eingebauten Snapshot einer laufenden Festplatte, eine Rohkopie wäre also inkonsistent. Jede Datei wird vollständig gelesen, und das Layout macht die wiederhergestellte Festplatte wieder bootfähig. Datenbanken sollten vor der Sicherung gedumpt oder mit eigenen Werkzeugen gesichert werden.

Einzelne Dateien und Ordner werden aus einer Systemsicherung wie aus jeder Dateisicherung wiederhergestellt (Dateien aus dieser Sicherung wiederherstellen auf der Laufseite).

Noch nicht unterstützt

Verschlüsselte Festplatten (LUKS), Software-RAID (mdadm), btrfs und Systeme, die über mehrere Festplatten verteilt sind. Der Auftrag meldet diese klar, statt eine unvollständige Sicherung zu erstellen.

Das ganze System wiederherstellen

Öffnen Sie den Lauf der Systemsicherung (Auftragsseite oder Aktivität) und verwenden Sie Gesamtes System wiederherstellen:

Als neue Proxmox-VM

Wählen Sie den Proxmox-Knoten (sein BackupZit-Agent erledigt die Arbeit), Speicher, VM-ID, Name, Arbeitsspeicher und Kerne. BackupZit erstellt die VM mit derselben Firmware wie das Original (UEFI/OVMF oder BIOS), einer VirtIO-SCSI-Festplatte und Netzwerkkarte, erstellt die Festplatte neu, stellt alle Dateien wieder her und kann die VM starten. Da die VM eine Kopie ist, die neben dem Original laufen kann:

  • werden Netzwerkeinstellungen, die an die alten MAC-Adressen gebunden sind (üblich in Cloud-Images: netplan match: macaddress), so geändert, dass sie für jede kabelgebundene Schnittstelle gelten,
  • wird der BackupZit-Agent in der Kopie abgemeldet, damit er sich nicht als die Originalmaschine meldet.

Auf eine Festplatte

Stellen Sie auf eine leere Festplatte eines Linux-Agenten wieder her, z. B. eine zweite Festplatte (/dev/sdb), oder auf die neue Maschine selbst (Bare Metal):

  1. Laden Sie unter Wiederherstellung das Linux-Wiederherstellungs-ISO herunter und erstellen Sie einen Wiederherstellungscode. Schreiben Sie das ISO auf einen USB-Stick (Rufus, balenaEtcher) oder hängen Sie es an eine VM. Es startet auf BIOS- und UEFI-Maschinen.
  2. Starten Sie die Maschine davon. Das Wiederherstellungssystem startet den Agenten, der sich mit backupzit/recovery.json von einem anderen USB-Stick oder einer anderen Festplatte mit der Konsole verbindet oder nach Serveradresse und Wiederherstellungscode fragt.
  3. Die Maschine erscheint als Wiederherstellung-Agent. Wählen Sie im Lauf der Systemsicherung Auf eine Festplatte, diesen Agenten und seine Festplatte (meist /dev/sda, /dev/nvme0n1 oder /dev/vda).

Jedes Linux-Live-System funktioniert ebenfalls: Starten Sie dort den Agenten mit sudo backupzit-agent recovery --server https://console:8443 --token CODE; fehlende Werkzeuge (gdisk, LVM, mkfs) werden genannt. Aktivieren Sie Andere Hardware, wenn die Maschine nicht die ursprüngliche ist.

Das Ziel darf größer oder kleiner als die Originalfestplatte sein: Die letzte Partition wächst, um es zu füllen, oder schrumpft, solange ihre Daten passen. Dateisystem-UUIDs und Partitions-IDs bleiben gleich, sodass /etc/fstab und der Bootloader keine Änderungen brauchen. Bei UEFI-Systemen wird der Bootloader zusätzlich im Pfad für Wechselmedien \EFI\BOOT\BOOTX64.EFI installiert, den jede UEFI-Firmware ohne Booteintrag startet. RHEL-ähnliche Systeme (dracut) erhalten beim Umzug auf andere Hardware ein neues initramfs mit allen Treibern.

Befehlszeile

backupzit-agent system-backup  --repo ... [--exclude PATTERN]
backupzit-agent system-show    --repo ... latest
backupzit-agent system-restore --repo ... --target /dev/sdb [--new-hardware] --yes-erase-target latest
