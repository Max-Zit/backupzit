REST API

Binden Sie BackupZit an RMM-Plattformen, Überwachung (PRTG, Zabbix, Nagios, Uptime Kuma …) und eigene Skripte an.

Token

Erstellen Sie ein Token unter Mein Konto → API-Token. Geben Sie ihm die niedrigste Rolle, die genügt — Betrachter für die Überwachung, Wiederherstellungsoperator, um auch Sicherungen und Wiederherstellungstests zu starten. Das Token wird nur einmal angezeigt; senden Sie es mit jeder Anfrage:

Authorization: Bearer bzt_...

Token können ablaufen, von ihrem Besitzer oder einem Administrator widerrufen werden (Benutzer) und funktionieren nicht mehr, wenn der Besitzer deaktiviert wird. Mit einem Token ausgeführte Aktionen erscheinen im Prüfprotokoll mit dem Namen des Tokens.

Endpunkte

Alle Antworten sind JSON. Basis-URL: https://<konsole>:8443.

Methode und PfadRolleLiefert
GET /api/v1/statusBetrachterGesamtzustand: Agenten online, Fehler und Warnungen in 24 h, aktive Läufe, ungeprüfte verdächtige Sicherungen, "ok": true|false
GET /api/v1/agentsBetrachterAgenten mit Betriebssystem, Version, Online-Status und letztem Kontakt
GET /api/v1/jobs, GET /api/v1/jobs/{id}BetrachterAufträge mit Zeitplan, nächstem Lauf und letztem Ergebnis
POST /api/v1/jobs/{id}/runWiederherstellungsoperatorStartet den Auftrag sofort: {"run_id": 123} (202), oder 409, wenn bereits ein Lauf aktiv ist
POST /api/v1/jobs/{id}/testWiederherstellungsoperatorStartet einen Wiederherstellungstest der neuesten Sicherung des Auftrags
GET /api/v1/runs?job=&agent=&status=&limit=BetrachterLetzte Läufe, neueste zuerst (Standard 100, maximal 1000)
GET /api/v1/runs/{id}BetrachterEin Lauf mit Meldung, Fehlern und Statistik
GET /api/v1/report?period=&from=&to=&agent=&job=BetrachterDer Bericht für einen Zeitraum: Summen, Erfolgsquote und Details pro Auftrag
GET /api/v1/targetsBetrachterSpeicherziele (ohne Zugangsdaten)

Zeiträume: today, yesterday, last7, last30, last90, thisweek, lastweek, thismonth, lastmonth oder custom mit from=2026-09-01&to=2026-09-30.

Fehler liefern {"error": "..."} mit 400 (ungültige Anfrage), 401 (Token fehlt, ist ungültig oder abgelaufen), 403 (Rolle zu niedrig), 404 oder 409.

Beispiele

curl

curl -sk -H "Authorization: Bearer $BZ_TOKEN" https://backup.example.local:8443/api/v1/status
curl -sk -X POST -H "Authorization: Bearer $BZ_TOKEN" https://backup.example.local:8443/api/v1/jobs/7/run

PowerShell

$h = @{ Authorization = "Bearer $env:BZ_TOKEN" }
$s = Invoke-RestMethod -Uri https://backup.example.local:8443/api/v1/status -Headers $h -SkipCertificateCheck
if (-not $s.ok) { Write-Warning "BackupZit needs attention: $($s.failed_24h) failed backups" }

Verwenden Sie -k / -SkipCertificateCheck nur mit dem selbstsignierten Zertifikat der Konsole in einem vertrauenswürdigen Netz, oder installieren Sie das Konsolenzertifikat auf dem Überwachungshost.

Überwachungsprüfung

Fragen Sie /api/v1/status alle paar Minuten ab und alarmieren Sie, wenn ok false ist. Für Prüfungen pro Auftrag verwenden Sie /api/v1/jobs und alarmieren, wenn last_status failed ist oder last_finished älter als erwartet ist.
