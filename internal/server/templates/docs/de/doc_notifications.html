Benachrichtigungen: E-Mail, Slack, Teams, Webhooks

Erhalten Sie eine E-Mail, wenn eine Sicherung fehlschlägt, und jeden Morgen eine Tageszusammenfassung.

E-Mail einrichten

Unter Einstellungen → E-Mail-Benachrichtigungen:

FeldBeispiel
SMTP-Server / Portsmtp.office365.com / 587, smtp.gmail.com / 587, internes Relay / 25
SicherheitSTARTTLS (Port 587), TLS (Port 465) oder keine (nur internes Relay)
Benutzer / PasswortDas Postfach, über das gesendet wird; leer lassen für ein anonymes Relay. Microsoft 365 und Gmail benötigen ein App-Passwort.
Absenderbackup@example.com
EmpfängerEine oder mehrere Adressen, durch Kommas getrennt.

Prüfen Sie die Einstellungen mit Test-E-Mail senden.

Was gesendet wird

  • Fehler (empfohlen) — eine E-Mail pro fehlgeschlagenem Lauf mit dem Grund: Sicherungen, Kopien, Wiederherstellungen und fehlgeschlagene Wiederherstellungstests. Mit dieser Option erhalten Sie auch eine Warnung SUSPICIOUS, wenn eine Sicherung nach Ransomware oder Massenlöschung aussieht.
  • Warnungen — Läufe, in denen einige Dateien nicht gelesen werden konnten.
  • Erfolge — jeder erfolgreiche Lauf (meist zu viel; besser den Tagesbericht verwenden).
  • Tagesbericht — zur gewählten Stunde: Läufe der letzten 24 Stunden, Probleme und Agenten offline. Der Betreff beginnt mit OK, WARNINGS oder ATTENTION, sodass Mailregeln sie sortieren können.

Für wöchentliche oder monatliche Zusammenfassungen verwenden Sie geplante Berichte; sie werden mit denselben Mail-Einstellungen gesendet und haben eigene Empfänger. Betreffzeilen beginnen mit [BackupZit], sodass Mailregeln sie sortieren können. Das SMTP-Passwort wird verschlüsselt gespeichert.

Slack, Microsoft Teams und Webhooks

Unter Einstellungen → Chat und Webhooks fügen Sie beliebig viele Kanäle hinzu; jeder wählt, ob er Fehler, Warnungen und Erfolge erhält. Ungewöhnliche Sicherungen (mögliche Ransomware) zählen als Fehler. Test senden prüft einen Kanal sofort.

  • Slack: Erstellen Sie einen Incoming Webhook für den Kanal (Slack-App-Einstellungen → Incoming Webhooks) und fügen Sie dessen URL ein (https://hooks.slack.com/services/…).
  • Microsoft Teams: Fügen Sie im Kanal den Workflow Post to a channel when a webhook request is received hinzu und fügen Sie dessen URL ein. Nachrichten kommen als Karten mit einer Schaltfläche, die den Lauf in der Konsole öffnet.
  • Webhook: jede URL, die einen JSON-POST annimmt — ein Ticketsystem, eine Überwachung oder ein Automatisierungswerkzeug. Mit einem Signaturgeheimnis trägt jede Anfrage X-BackupZit-Signature: sha256=<hex>, den HMAC-SHA256 des Inhalts, sodass der Empfänger prüfen kann, dass sie von Ihrer Konsole stammt.

Das JSON eines Webhooks:

{"event": "run.finished", "run_id": 412, "kind": "vm-backup", "kind_title": "VM backup",
 "status": "failed", "suspicious": "", "job": "Proxmox VMs", "job_id": 7, "agent": "pve1",
 "message": "…", "errors": ["…"], "started_at": "2026-10-04T22:00:03+02:00",
 "finished_at": "2026-10-04T22:04:41+02:00", "url": "https://backup.example/runs/412"}

Nachrichten werden einmal pro Lauf gesendet, auch wenn E-Mail aus ist. Ein Kanal, der fehlschlägt (falsche URL, Dienst nicht erreichbar), wird im Konsolenprotokoll vermerkt und hält die anderen nicht auf. Webhook-URLs werden verschlüsselt gespeichert.
