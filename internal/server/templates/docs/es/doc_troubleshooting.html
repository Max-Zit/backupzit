Solución de problemas y preguntas frecuentes

Un agente aparece sin conexión

  • ¿Está la máquina encendida y el servicio en marcha? Windows: Get-Service backupzit-agent; Linux: systemctl status backupzit-agent.
  • ¿Llega la máquina a la consola? Test-NetConnection backup-server -Port 8443 o curl -k https://backup-server:8443/login.
  • Log del agente: C:\ProgramData\backupzit\agent.log, en Linux /etc/backupzit/agent.log o journalctl -u backupzit-agent. «fingerprint mismatch» significa que el certificado de la consola cambió: vuelva a registrar el agente.

Una copia falló

Abra la ejecución en Actividad; el mensaje indica la causa. Causas habituales:

El mensaje contieneSolución
host key mismatch / fingerprintLa clave del servidor SFTP cambió o la huella se introdujo mal. Compruébelo con ssh-keygen -lf en el servidor.
permission denied / access deniedCredenciales del almacenamiento o permisos de la carpeta. Pruebe el inicio de sesión con un cliente SFTP/SMB.
no space left / quotaEl almacenamiento está lleno. Reduzca la retención o añada espacio; las copias caducadas liberan espacio tras la siguiente ejecución.
repository is lockedOtra operación (p. ej. una limpieza) se está ejecutando en el mismo repositorio; la ejecución lo reintenta durante 30 minutos. Los bloqueos obsoletos caducan automáticamente.
wrong password / recovery keyEl repositorio se creó con otra clave: compruebe que el trabajo usa el destino de almacenamiento correcto.
bucket has no Object Lock enabledSe pidió inmutabilidad en un bucket creado sin Object Lock. Cree un bucket nuevo con Object Lock.

Otros mensajes

SituaciónQué hacer
«no matching backup disk is connected»Conecte uno de los discos USB rotativos (el mensaje indica la etiqueta necesaria y qué discos etiquetados están conectados). Una restauración necesita exactamente el disco que aparece en la ejecución de la copia.
«several backup disks are connected»Conecte solo uno de los discos rotativos a la vez.
Falló la prueba de restauraciónAbra la ejecución: el mensaje indica el archivo o bloque dañado o el motivo (p. ej. copia borrada en el almacenamiento). Ejecute backupzit-agent check --read-data sobre el repositorio, revise el almacenamiento e inicie una copia nueva. Si se borraron copias en almacenamiento inmutable, consulte Protección contra ransomware.
Copia marcada como sospechosaRevise la máquina en busca de ransomware o de un borrado masivo (p. ej. una carpeta sincronizada vaciada). Si todo está bien (p. ej. una migración planificada), haga clic en Revisado: reanudar la retención en la página del trabajo.
Let's Encrypt: «could not verify … is port 80 … reachable»La comprobación HTTP necesita el puerto 80 accesible desde Internet. Para consolas internas use la comprobación DNS mediante Cloudflare.
Let's Encrypt: «no Cloudflare zone … is accessible with this token»El token debe tener el permiso Zone → DNS → Edit para la zona que contiene el nombre de la consola.
«HTTPS port 443: … permission denied» o «address already in use»Otro programa usa el puerto, o el servicio no puede abrir puertos inferiores a 1024 (ejecútelo con CAP_NET_BIND_SERVICE, como hace el paquete). Elija otro puerto en Configuración → Certificado.
Actualizaciones: «updates from the console need the Linux package of the console»La consola no se instaló desde el paquete deb/rpm (por ejemplo, en modo de evaluación). Actualícela del mismo modo en que se instaló.
Actualizaciones: «the release is not signed with a BackupZit release key»El origen de la actualización no contiene una versión oficial, o los archivos se modificaron por el camino. Vuelva a descargarlos desde la dirección oficial.
Actualizaciones: estado rolled-backLa versión nueva no arrancó, así que se restauraron la anterior y su base de datos. El log del arranque fallido está en la página Actualizaciones; envíelo al soporte.
Sistema operativo: «no supported package manager»Las actualizaciones del sistema operativo se admiten en Debian, Ubuntu (apt) y AlmaLinux, Rocky Linux, RHEL (dnf).
Copia de la consola: «the backup was made by a newer BackupZit»Antes de restaurar, instale en la consola nueva la versión que hizo la copia, u otra más reciente.
Copia de la consola: «console backups need network storage»Elija un destino SFTP, S3, SMB, Azure o un repositorio reforzado; la consola no puede acceder a una ruta local de un agente.
«Demasiados inicios de sesión fallidos»Su dirección se bloqueó tras contraseñas erróneas repetidas: por defecto durante 30 minutos, más tiempo si se repiten los bloqueos. Un administrador puede levantar el bloqueo en Configuración → Inicio de sesión y seguridad. En el servidor, backupzit-server --unblock-ip all levanta todos los bloqueos. Las cuentas nunca se bloquean de forma permanente.
Teléfono perdido para el inicio de sesión en dos pasosUse uno de los códigos de recuperación; si no, un administrador restablece la verificación en dos pasos en su página de usuario. El último administrador puede restablecer su contraseña en el servidor con backupzit-server --set-admin-password.
«your directory account is not in any BackupZit group»Añada el usuario a uno de los grupos asignados en Configuración → LDAP / Active Directory, o asigne más grupos. Use Prueba allí para ver los grupos encontrados para un usuario.
La API devuelve 401 / 403401: token ausente, revocado, caducado o con el propietario deshabilitado. 403: el rol del token es insuficiente para la solicitud.
Azure: AuthenticationFailed / AuthorizationPermissionMismatchClave de cuenta incorrecta, o al token SAS le falta el permiso de lectura, escritura, borrado o listado, o ha caducado.
Una VM restaurada con Windows Server 2012 R2 / Windows 8.1 no arranca en Hyper-V Gen 2 («hash was denied (DBX)»)Microsoft revocó el antiguo cargador de arranque para Secure Boot. Desactive Secure Boot en esa VM, o actualice el sistema antes de copiarlo.

Máquinas virtuales, sistemas Linux y hardware nuevo

SituaciónQué hacer
Proxmox: «the guest is running and one of its disks is on storage without snapshot support»Los invitados en marcha necesitan discos LVM-thin, ZFS, Ceph RBD o qcow2. Mueva el disco (Disk Action → Move Storage) o copie el invitado mientras está detenido.
Hyper-V: la ejecución dice «crash-consistent»El invitado no pudo prepararse para el punto de control. En invitados Windows compruebe que los servicios de integración de Hyper-V (Backup (volume shadow copy)) están habilitados en la configuración de la VM. En invitados Linux instale hyperv-daemons (RHEL) o linux-cloud-tools / hyperv-daemons (Debian/Ubuntu).
VMware: «SSH off» o «SSH to …: connection refused»Habilite SSH en el host ESXi: Host → Actions → Services → Enable Secure Shell (y configúrelo para que arranque con el host). Lo necesitan las restauraciones y, con la licencia gratuita, las copias.
VMware: «changed block tracking is off and can be enabled … only while the VM is off»Licencia gratuita de ESXi: apague la VM una vez y ejecute el trabajo; BackupZit activa el seguimiento de bloques cambiados y las copias posteriores solo leen los bloques cambiados.
VMware: «copy the disk on the datastore (needs free space …)»Las VM en marcha se copian brevemente en su datastore. Libere espacio allí (tanto como usa el disco) o copie la VM apagada.
VMware: «… is a snapshot delta disk»La VM tiene instantáneas propias. Elimínelas o consolídelas en el cliente de host ESXi (Snapshots → Delete all).
VMware: «the ESXi certificate changed»El host se reinstaló u otra máquina responde en su dirección. Si es lo esperado, quite el host en Agentes y vuelva a añadirlo para fijar el certificado nuevo.
VMware: archivos *.replaced-DATE.vmdk junto a los discos de la VMLos discos antiguos de una VM restaurada en el sitio. Bórrelos en el explorador del datastore cuando la VM restaurada funcione.
Hyper-V: archivos *.replaced-DATE junto a los discos de la VMLos discos antiguos de una VM restaurada en el sitio. Bórrelos cuando la VM restaurada funcione.
Recuperación instantánea de Proxmox: la VM no arranca o se cuelgaCompruebe el servidor de discos: systemctl status backupzit-instant-ID y journalctl -u backupzit-instant-ID en el nodo. El almacenamiento de copias debe seguir accesible; si no se puede leer el repositorio, las lecturas de disco de la VM se detienen.
Recuperación instantánea de Proxmox: «efidisk0 stays on storage backupzit-instant»QEMU no puede mover el almacén de variables EFI mientras la VM está en marcha. Apague la VM y ejecute qm disk move ID efidisk0 STORAGE --delete 1; esto no depende de la copia.
Proxmox: «runs on node X; install the BackupZit agent on X»El invitado se migró. Instale el agente en cada nodo y copie los invitados de cada nodo con el agente de ese nodo.
Copias o restauraciones de Proxmox lentas, SFTP «connection lost», «message authentication code incorrect» en el servidor de almacenamientoProblema conocido de las tarjetas de red Intel e1000e en hosts Proxmox (log: «Detected Hardware Unit Hang», «Reset adapter unexpectedly»). Desactive el offloading: ethtool -K eno1 tso off gso off gro off y añádalo como línea post-up de la interfaz en /etc/network/interfaces.
Examinar archivos: «stored on a local path of the agent»La consola solo puede leer copias en almacenamiento de red. Use backupzit-agent pve ls/extract o image-ls/image-extract en el agente.
Restauración de sistema Linux: «missing programs …»Instale los paquetes indicados en la máquina que restaura, o arranque la ISO de recuperación de Linux de BackupZit, que los incluye.
La máquina Linux restaurada no tiene redLa configuración de red estaba vinculada a la dirección MAC antigua (netplan match: macaddress). Restaure con Hardware distinto, o elimine las líneas match en /etc/netplan/.
El Windows restaurado se detiene con INACCESSIBLE_BOOT_DEVICERestaure de nuevo con Restaurar en hardware distinto, o arranque la ISO de recuperación y ejecute backupzit-agent prepare-hardware --disk 0 [--drivers E:\Drivers].
Una copia restaurada de una máquina aparece como el agente originalLas restauraciones en una VM nueva de Proxmox dan de baja automáticamente el agente de la copia. En otras copias, elimine agent.json en la copia y regístrela como máquina nueva.
La actualización del agente no terminaConsulte el log del instalador en C:\ProgramData\backupzit\updates o /var/tmp/backupzit-updates; los agentes anteriores a 0.21 deben actualizarse una vez a mano.
Falta el icono de la bandejaHaga clic en la flecha ^ junto al reloj y arrastre el icono de BackupZit a la barra de tareas, o inicie BackupZit Agent desde el menú Inicio.

Una copia termina con «advertencia»

No se pudieron leer algunos archivos: normalmente archivos bloqueados por una aplicación mientras VSS no está disponible, o archivos para los que el agente no tiene permiso. La lista está en la página de la ejecución. Todo lo demás está copiado.

Las copias son lentas

  • La primera copia lee y envía todo; las siguientes solo leen los archivos cambiados y solo envían los datos nuevos.
  • Revise la ruta de red hasta el almacenamiento (Wi-Fi, VPN, velocidad de subida a Internet para almacenamiento en la nube).
  • Excluya cachés, archivos temporales y multimedia que no necesite.

Preguntas frecuentes

¿Puedo usar NFS?

Para copiar un recurso NFS (o SMB), cree un trabajo NAS / recurso compartido; un agente Linux monta el export en cada ejecución. Para guardar copias en NFS, monte el export en el agente (Linux: /etc/fstab) y use un destino Ruta local / montada como /mnt/nfs-backup; para máquinas Windows es mejor un destino SMB.

¿Puedo mover las copias a otro almacenamiento?

Copie la carpeta del repositorio (o el prefijo del bucket) tal cual —es autónoma— y añada un destino de almacenamiento que apunte a la nueva ubicación con la misma clave de recuperación.

¿Eliminar un trabajo elimina las copias?

No. Las copias permanecen en el almacenamiento y se pueden restaurar desde Actividad o la línea de comandos.

¿Qué pasa si la consola no está disponible?

No se inician copias programadas nuevas hasta que vuelva; las ejecuciones en cola continúan después. Las restauraciones siempre son posibles desde la línea de comandos con la hoja de recuperación.

¿Cuánto espacio necesitarán las copias?

Para la primera copia, aproximadamente el tamaño de los datos tras la compresión, más los cambios diarios de cada día conservado. La página Informes muestra cuánto se envió por trabajo.
