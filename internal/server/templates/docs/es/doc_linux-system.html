Copia del sistema Linux y P2V

Un trabajo de Sistema Linux copia una máquina Linux completa para poder recrearla en un disco vacío: la misma máquina tras un fallo de disco, hardware nuevo o una máquina virtual en Proxmox VE (de física a virtual, P2V).

Qué se copia

  • Cada sistema de archivos local (ext2/3/4, xfs, vfat), también sobre LVM, archivo por archivo con propietarios, permisos, bits setuid, ACL, atributos extendidos (etiquetas SELinux, capacidades de archivo), enlaces duros y archivos de dispositivo. Cada sistema de archivos se copia por separado; los recursos de red y los sistemas de archivos virtuales (/proc, /sys, /run) se omiten.
  • La disposición de los discos: tablas de particiones GPT o MBR con sus identificadores, grupos de volúmenes LVM (vgcfgbackup), UUID, etiquetas y características de los sistemas de archivos, y el código de arranque (MBR y la partición de arranque BIOS de GRUB).

Al igual que Relax-and-Recover, BackupZit no copia el disco en uso bloque a bloque: Linux no tiene una instantánea integrada de un disco en marcha, así que una copia en bruto sería incoherente. Cada archivo se lee completo y la disposición vuelve a hacer arrancable el disco restaurado. Las bases de datos deben volcarse antes de la copia o copiarse con sus propias herramientas.

Los archivos y carpetas sueltos se restauran desde una copia de sistema como desde cualquier copia de archivos (Restaurar archivos de esta copia en la página de la ejecución).

Aún no compatible

Discos cifrados (LUKS), RAID por software (mdadm), btrfs y sistemas repartidos en varios discos. El trabajo lo indica claramente en lugar de crear una copia incompleta.

Restaurar el sistema completo

Abra la ejecución de la copia del sistema (página del trabajo o Actividad) y use Restaurar todo el sistema:

Como nueva VM de Proxmox

Elija el nodo Proxmox (su agente BackupZit hace el trabajo), el almacenamiento, el ID de VM, el nombre, la memoria y los núcleos. BackupZit crea la VM con el mismo firmware que el original (UEFI/OVMF o BIOS), un disco y una tarjeta de red VirtIO SCSI, recrea el disco, restaura todos los archivos y puede iniciar la VM. Como la VM es una copia que puede ejecutarse junto al original:

  • la configuración de red vinculada a las direcciones MAC antiguas (habitual en imágenes de nube: netplan match: macaddress) se cambia para que se aplique a cualquier interfaz cableada,
  • el agente BackupZit dentro de la copia se da de baja, para que no se presente como la máquina original.

En un disco

Restaure en un disco vacío de un agente Linux, p. ej., un segundo disco (/dev/sdb), o en la propia máquina nueva (bare metal):

  1. En Recuperación descargue la ISO de recuperación de Linux y cree un código de recuperación. Grabe la ISO en una memoria USB (Rufus, balenaEtcher) o conéctela a una VM. Arranca en máquinas BIOS y UEFI.
  2. Arranque la máquina desde ella. El sistema de recuperación inicia el agente, que se conecta a la consola con backupzit/recovery.json de otra memoria USB u otro disco, o pide la dirección del servidor y el código de recuperación.
  3. La máquina aparece como agente de recuperación. En la ejecución de la copia del sistema elija En un disco, ese agente y su disco (normalmente /dev/sda, /dev/nvme0n1 o /dev/vda).

Cualquier sistema Linux en vivo sirve también: inicie allí el agente con sudo backupzit-agent recovery --server https://console:8443 --token CODE; si faltan herramientas (gdisk, LVM, mkfs), se indican. Marque Hardware distinto cuando la máquina no sea la original.

El destino puede ser mayor o menor que el disco original: la última partición crece para llenarlo, o se reduce siempre que sus datos quepan. Los UUID de los sistemas de archivos y los identificadores de partición no cambian, así que /etc/fstab y el cargador de arranque no necesitan cambios. En sistemas UEFI, el cargador de arranque también se instala en la ruta de medios extraíbles \EFI\BOOT\BOOTX64.EFI, que todo firmware UEFI arranca sin entrada de arranque. Los sistemas tipo RHEL (dracut) reciben un nuevo initramfs con todos los controladores al pasar a hardware distinto.

Línea de comandos

backupzit-agent system-backup  --repo ... [--exclude PATTERN]
backupzit-agent system-show    --repo ... latest
backupzit-agent system-restore --repo ... --target /dev/sdb [--new-hardware] --yes-erase-target latest
