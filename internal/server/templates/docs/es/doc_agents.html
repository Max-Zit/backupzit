Agentes

En cada equipo protegido se instala un agente. Se ejecuta como servicio, pide trabajo a la consola cada 30 segundos y se comunica directamente con el almacenamiento.

Sistemas compatibles

  • Windows 10, 11 y Windows Server 2016 y posteriores — MSI Agente de Windows.
  • Windows 7 SP1, Windows Server 2008 R2 SP1 y 2012 R2 — MSI Agente de Windows — sistemas antiguos (…-legacy.msi), con las mismas funciones, incluidos VSS e imágenes de disco.
  • Debian, Ubuntu, AlmaLinux, Rocky Linux (64 bits).
  • Nodos Proxmox VE 7 y 8 — el paquete Debian; el agente copia entonces también las VM y contenedores del nodo (consulte Proxmox VE).
  • Hosts Hyper-V (Windows Server 2016 y posteriores, Windows 10/11 con Hyper-V): el MSI de Windows. El agente copia entonces también las VM del host (consulte Hyper-V).
  • Hosts VMware ESXi — en ESXi no se instala nada: añada el host en Hosts VMware ESXi y elija un agente como proxy (consulte VMware ESXi).

Registrar agentes

  1. En la página Agentes haga clic en Crear token de registro. La consola muestra un código de registro (BZ1-…), válido 7 días y utilizable en cualquier número de equipos. Contiene la dirección de la consola para los agentes (con el puerto de agentes, normalmente 8443, aunque la página esté abierta en el puerto web 443), el token y la huella del certificado. Los agentes desde 0.33.6 también se registran con códigos que consolas anteriores crearon en el puerto web.
  2. Windows: ejecute el MSI y pegue el código cuando el instalador lo pida. Linux: ejecute el comando mostrado.
  3. El equipo aparece en la lista de agentes en menos de un minuto.

Si la consola no está accesible durante la instalación, el agente guarda el código y reintenta hasta poder registrarse. Las actualizaciones conservan el registro y no vuelven a preguntar. Una instalación silenciosa con ENROLLCODE en un equipo ya registrado conserva el registro cuando el código es de la misma consola (GPO o RMM pueden repetirla sin riesgo), y mueve el equipo cuando el código es de otra consola; el registro anterior se guarda como agent.json.replaced-fecha junto a agent.json, de modo que al renombrarlo el equipo vuelve a su antigua consola como el mismo agente.

Windows, silenciosa (GPO, Intune, RMM)

msiexec /i backupzit-agent.msi /qn ENROLLCODE="BZ1-..."

La forma antigua SERVER="..." TOKEN="..." FINGERPRINT="SHA256:..." sigue funcionando. Una instalación silenciosa sin estas propiedades configura el servicio, que espera hasta que lo registre con backupzit-agent enroll --code "BZ1-..." en un símbolo del sistema de administrador.

Linux

apt install ./backupzit-agent_*.deb        # or: dnf install ./backupzit-agent-*.rpm
backupzit-agent enroll --code "BZ1-..."
systemctl enable --now backupzit-agent

Instalar agentes desde la consola

En lugar de copiar instaladores a cada equipo, deje que la consola instale el agente: en Agentes abra Instalar en un equipo desde aquí, elija Linux o Windows e introduzca la dirección del equipo y una cuenta de administrador.

  • Linux (Debian, Ubuntu, AlmaLinux, Rocky Linux; 64 bits): la consola se conecta por SSH como root, o como un usuario con derechos de sudo (la contraseña también se usa para sudo; con una clave, se necesita sudo sin contraseña). Funciona una contraseña o una clave privada. Introduzca la huella de la clave de host SSH del equipo (ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub en el equipo) para asegurarse de que la consola habla con el equipo correcto; sin ella, la huella se muestra en el registro de instalación.
  • Windows (64 bits): la consola se conecta por WinRM (puerto 5985, mensajes cifrados con NTLM; 5986 para un agente de escucha HTTPS) como administrador local o de dominio. WinRM está activado por defecto en Windows Server; en Windows 10/11 ejecute una vez winrm quickconfig como administrador. Las cuentas locales distintas del Administrador integrado necesitan derechos de administración remota (LocalAccountTokenFilterPolicy), o use una cuenta de dominio. Los sistemas antiguos (Windows 7, Server 2008 R2/2012 R2) reciben el MSI legacy.

El equipo descarga el paquete de agente más reciente desde la consola mediante un enlace que solo sirve para esta instalación (30 minutos, tres descargas), comprueba su suma SHA-256, lo instala y se registra. La página de instalación muestra cada paso; la cuenta y la contraseña solo se usan para esto y no se guardan. Si el equipo ya está registrado en esta consola, se conserva el registro y se actualiza el paquete; un registro que la consola no conoce (un agente eliminado antes, u otra consola) se sustituye. Cada instalación queda en el registro de auditoría. El equipo debe alcanzar la dirección de agentes de la consola, como cualquier agente.

Estado del agente

  • online — el agente contactó con la consola en los últimos 3 minutos.
  • offline — el equipo está apagado, el servicio detenido o la red bloqueada. Las copias programadas se ponen en cola y comienzan en cuanto vuelve el agente.
  • recuperación — un equipo arrancado desde una ISO de recuperación (Windows o Linux), listo para recibir la restauración de una imagen de disco o de un sistema Linux. Los agentes de recuperación son temporales; elimínelos cuando termine la restauración.

La columna Direcciones IP muestra las direcciones propias del equipo tal como el agente las informó por última vez. visto desde es la dirección desde la que llegan sus conexiones: en una red local la misma dirección, para un equipo detrás de NAT (p. ej. un portátil en casa) la dirección pública del router. La consola no consulta ningún servicio externo para ello.

El agente en el escritorio (Windows)

El agente de Windows muestra un icono junto al reloj (puede estar bajo la flecha ^ de iconos ocultos; arrástrelo a la barra de tareas para que siga visible). El punto del icono indica el estado:

PuntoSignificado
verdeLas copias están bien (o esperan la primera copia programada).
azulSe está ejecutando una copia, una restauración o una prueba de restauración.
naranjaLa última copia terminó con advertencias (archivos que no se pudieron leer).
rojoUn trabajo de copia falló.
grisLa consola no está accesible o el servicio del agente no se está ejecutando.

Haga clic en el icono (o abra BackupZit Agent desde el menú Inicio) para ver la ventana de estado: estado de protección, progreso de una copia en curso, última y próxima copia, y todos los trabajos de copia del equipo con Copiar ahora. Con el botón derecho se abre el menú: Back up now por trabajo, Open console in browser, Hide this icon (hasta el siguiente inicio de sesión; las copias continúan). La ventana necesita Microsoft Edge WebView2, que forma parte de Windows 10 y 11; en sistemas antiguos el icono y el menú funcionan y Open muestra la consola en el navegador.

Así los usuarios pueden iniciar una copia de su equipo; los trabajos, programaciones y retención se configuran solo en la consola. En cualquier sistema, backupzit-agent status (como administrador o root) muestra la misma información.

Actualizar

Cuando la consola tiene un instalador de agente más reciente que el que ejecuta un agente, la página Agentes muestra Actualizar a x.y.z junto a su versión, y Actualizar todos los agentes bajo la lista. El agente entonces:

  1. espera hasta estar inactivo (nunca se interrumpe una copia en curso),
  2. descarga el instalador correspondiente desde la consola por su conexión fijada —el MSI para Windows 10/11/2016+, el MSI de sistemas antiguos para Windows 7/2008 R2/2012 R2, el paquete deb o rpm en Linux— y comprueba su SHA-256,
  3. lo instala y se reinicia; la nueva versión aparece en la lista en pocos minutos. Se conservan el registro y toda la configuración.

La consola ofrece los instaladores más recientes de su directorio dist; el paquete del servidor incluye los instaladores de agente de su propia versión. Después de actualizar la consola desde Configuración → Actualizaciones, los agentes se actualizan automáticamente (se puede desactivar allí). Las actualizaciones desde la consola funcionan para agentes desde la versión 0.21; los agentes más antiguos se actualizan una vez instalando el MSI / paquete más reciente sobre el antiguo (se conserva el registro). El registro del instalador está en C:\ProgramData\backupzit\updates o /var/tmp/backupzit-updates.

Quitar un agente

Quitar en la página Agentes elimina el agente y sus trabajos de la consola. Con la aprobación de cuatro ojos activada, primero debe aprobarlo un segundo usuario. Las copias en el almacenamiento no se eliminan. Desinstale el software del equipo por separado.

Dos equipos usando un mismo agente

Una copia de un equipo registrado lleva consigo su agente y su registro: una VM restaurada como VM nueva, una recuperación instantánea, una réplica iniciada, un disco o plantilla clonados. Cuando la copia se ejecuta junto al original, ambos se conectan como el mismo agente. La consola lo detecta en uno o dos minutos y entonces:

  • muestra dos equipos con ambos nombres y direcciones en la página Agentes, y el agente en Requiere atención en el panel;
  • retiene las copias y restauraciones del agente, para que nada se ejecute en el equipo equivocado (una restauración a la ubicación original podría si no sobrescribir la copia en lugar del original);
  • envía una vez un correo a los administradores y escribe una entrada agent.duplicate en el registro de auditoría.

Detenga la copia o, si debe quedarse, regístrela como equipo nuevo en la copia: backupzit-agent enroll --force --code "BZ1-..." (código de la página Agentes). Las ejecuciones retenidas comienzan unos minutos después de que quede un solo equipo. Restaurar un sistema Linux con Restaurar todo el sistema ya anula el registro del agente en la copia restaurada, y las pruebas de restauración arrancan sus VM sin red, así que ninguno de los dos provoca esto.

Cuando la consola cambia de dirección

Los agentes confían en la consola por su certificado, que no cambia cuando cambian su dirección IP o su nombre, pero se conectan a la dirección con la que se registraron. Tras un cambio, ejecute en cada equipo con agente (como administrador / root):

backupzit-agent set-server https://192.168.1.20:8443

El comando comprueba que la consola responde en la nueva dirección con el mismo certificado, la guarda, y el agente la usa tras reiniciar su servicio (systemctl restart backupzit-agent, o reinicie el servicio BackupZit Agent en Windows). Usar desde el principio un nombre DNS para la consola evita este paso.

Dónde guarda el agente su configuración

  • Windows: C:\ProgramData\backupzit\agent.json (accesible solo para SYSTEM y Administradores).
  • Linux: /etc/backupzit/agent.json (solo root).

El archivo contiene el secreto del agente. Quien pueda leerlo puede actuar como ese agente, así que mantenga estos permisos.

Registro del agente

  • Windows: C:\ProgramData\backupzit\agent.log
  • Linux: /etc/backupzit/agent.log y journalctl -u backupzit-agent
  • Los sistemas de recuperación muestran el registro en pantalla.

Desinstalar

Windows: Configuración → Aplicaciones → BackupZit Agent → Desinstalar (o msiexec /x). Linux: apt remove backupzit-agent / dnf remove backupzit-agent. Después quite el agente en la consola. Las copias permanecen en el almacenamiento.

En Windows, la desinstalación aparta el registro (C:\ProgramData\backupzit\agent.json.removed-fecha), de modo que al instalar de nuevo el agente se pide un código de registro. Si el instalador encuentra un registro de una versión anterior, lo indica: deje el código vacío para conservarlo o pegue un código nuevo para registrar de nuevo el equipo (por ejemplo en otra consola).
