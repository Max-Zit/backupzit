Primeros pasos

BackupZit protege equipos Windows y Linux, máquinas virtuales de Proxmox VE, Hyper-V y VMware ESXi, bases de datos (SQL Server, PostgreSQL, MySQL/MariaDB) y recursos compartidos NAS —archivos, discos completos y sistemas completos— desde una consola web que se ejecuta en su propia red.

Cómo funciona BackupZit

  • Consola de gestión (esta aplicación web): se ejecuta en un servidor Linux de su red. Guarda la configuración, programa trabajos, recoge resultados y muestra informes. Nunca necesita ser accesible desde Internet.
  • Agentes: un pequeño servicio en cada equipo protegido (MSI de Windows, deb/rpm de Linux) y en los hosts Proxmox y Hyper-V; a los hosts VMware ESXi se llega mediante un agente que hace de proxy. Los agentes contactan con la consola por HTTPS, reciben trabajos y envían los datos de copia directamente al almacenamiento. En Windows el agente muestra su estado junto al reloj.
  • Destinos de almacenamiento: donde se guardan las copias: SFTP, almacenamiento de objetos compatible con S3 (AWS, Wasabi, Backblaze B2, MinIO, Google Cloud…), Azure Blob Storage, un recurso SMB/NAS, discos USB rotativos, un disco local o montado, o un repositorio reforzado de BackupZit.

Los datos de copia nunca pasan por la consola. La consola solo coordina, por lo que basta una máquina virtual pequeña.

Primeros pasos

Para poner en marcha una consola nueva, importe la imagen de appliance lista para usar en una VM pequeña, arranque la ISO del appliance o ejecute el script de instalación en un servidor Linux existente; consulte Instalar el servidor.

  1. Añada un destino de almacenamiento en Almacenamiento. Deje activado Cifrar copias y guarde en un lugar seguro la hoja de recuperación que se muestra después. Consulte Destinos de almacenamiento.
  2. Instale agentes: en Agentes haga clic en Crear token de registro, descargue el instalador de la misma página y pegue el código de registro cuando el instalador de Windows lo pida (Linux: backupzit-agent enroll --code …). Para las VM, instale el agente en el host Proxmox o Hyper-V; añada los hosts VMware ESXi en Agentes → Hosts VMware ESXi. Consulte Agentes.
  3. Cree un trabajo de copia en Trabajos de copia: elija el agente, el almacenamiento, qué copiar (archivos, un recurso NAS, una imagen de disco, bases de datos, todo el sistema Linux o las VM de un host Proxmox, Hyper-V o VMware ESXi), cuándo ejecutarlo y cuántas copias conservar. Consulte Trabajos de copia y programaciones.
  4. Ejecútelo una vez manualmente con Ejecutar copia ahora en la página del trabajo y compruebe el resultado en Actividad.
  5. Pruebe una restauración: una copia vale lo que vale su restauración. Las pruebas de restauración automáticas se ejecutan cada semana; restaure algo también a mano una vez con el asistente de restauración. Consulte Restauración.
  6. Prepárese para desastres: descargue las ISO de recuperación y cree un código de recuperación en Medios de recuperación.
  7. Configure alertas por correo en Configuración → Notificaciones por correo para enterarse de los fallos y, opcionalmente, un informe semanal.

Idioma

La consola está disponible en 14 idiomas: inglés, alemán, francés, español, italiano, portugués (Brasil), neerlandés, polaco, checo, serbio (alfabeto latino), turco, ruso, chino (simplificado) y japonés. Elija uno en la lista de idiomas arriba a la derecha o en la página de inicio de sesión; la elección se recuerda en el navegador. Sin elección, decide el idioma del navegador (los navegadores croatas, bosnios y montenegrinos obtienen serbio, los eslovacos checo, los demás idiomas inglés). Esta guía también está traducida (una página sin traducción se muestra en inglés). Los correos, las notificaciones de chat y los mensajes enviados por los agentes se mantienen en inglés.

Las traducciones están en el código fuente, en internal/server/i18n/es.json: el texto en inglés es la clave y la traducción su valor. go run ./tools/i18n missing es muestra los textos sin traducción; los textos no traducidos se muestran en inglés.

Conceptos clave

Instantáneas y deduplicación

Cada copia crea una instantánea: una imagen completa y explorable de los datos en ese momento. Los archivos se dividen en fragmentos de tamaño variable y los discos en bloques, y cada pieza se guarda una sola vez, de modo que la segunda copia y las siguientes solo suben lo que cambió; aun así, cada instantánea se puede restaurar por sí sola. No hay que gestionar ninguna «cadena completa/incremental».

Repositorios

Cada agente escribe en su propio repositorio bajo la ubicación del destino de almacenamiento (<location>/<hostname>_<id>). Un repositorio es autónomo: con la ubicación, las credenciales del almacenamiento y la clave de recuperación, se puede restaurar aunque la consola ya no exista.

Retención

Cada trabajo conserva un número de copias recientes, diarias, semanales y mensuales. Las instantáneas más antiguas se eliminan tras cada ejecución y se libera el espacio que ocupaban.

Qué comprueba BackupZit por usted

  • Pruebas de restauración: la copia más reciente de cada trabajo se restaura parcialmente y se verifica cada semana (Restauración).
  • Detección de ransomware: las copias inusuales (cambios masivos, datos cifrados, borrado masivo, saltos bruscos del volumen de datos) se marcan y la retención se pausa (Protección contra ransomware).
  • Alertas e informes: correos ante fallos y un resumen diario; informes programados para la dirección (Notificaciones por correo, Supervisión).
