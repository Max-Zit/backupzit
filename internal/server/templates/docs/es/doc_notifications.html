Notificaciones: correo, Slack, Teams, webhooks

Reciba un correo cuando falle una copia y un resumen diario cada mañana.

Configurar el correo

En Configuración → Notificaciones por correo:

CampoEjemplo
Servidor SMTP / puertosmtp.office365.com / 587, smtp.gmail.com / 587, relé interno / 25
SeguridadSTARTTLS (puerto 587), TLS (puerto 465) o ninguna (solo relé interno)
Usuario / contraseñaEl buzón usado para enviar; déjelo vacío para un relé anónimo. Microsoft 365 y Gmail requieren una contraseña de aplicación.
Remitentebackup@example.com
DestinatariosUna o varias direcciones, separadas por comas.

Use Enviar correo de prueba para comprobar la configuración.

Qué se envía

  • Fallos (recomendado): un correo por cada ejecución fallida con el motivo: copias, copias secundarias, restauraciones y pruebas de restauración fallidas. Con esta opción también recibe una alerta SUSPICIOUS cuando una copia parece ransomware o un borrado masivo.
  • Advertencias: ejecuciones en las que no se pudieron leer algunos archivos.
  • Éxitos: cada ejecución correcta (normalmente demasiado; mejor el informe diario).
  • Informe diario: a la hora elegida: ejecuciones de las últimas 24 horas, problemas y agentes sin conexión. El asunto empieza por OK, WARNINGS o ATTENTION, para que las reglas de correo puedan clasificarlos.

Para resúmenes semanales o mensuales use los informes programados; se envían con la misma configuración de correo y tienen sus propios destinatarios. Los asuntos empiezan por [BackupZit] para que las reglas de correo puedan clasificarlos. La contraseña SMTP se guarda cifrada.

Slack, Microsoft Teams y webhooks

En Configuración → Chat y webhooks añada tantos canales como quiera; cada uno elige si recibe fallos, advertencias y éxitos. Las copias inusuales (posible ransomware) cuentan como fallos. Enviar prueba comprueba un canal al instante.

  • Slack: cree un incoming webhook para el canal (configuración de la app de Slack → Incoming Webhooks) y pegue su URL (https://hooks.slack.com/services/…).
  • Microsoft Teams: en el canal, añada el flujo Post to a channel when a webhook request is received y pegue su URL. Los mensajes llegan como tarjetas con un botón que abre la ejecución en la consola.
  • Webhook: cualquier URL que acepte un POST JSON: un sistema de tickets, supervisión o herramienta de automatización. Con un secreto de firma, cada solicitud lleva X-BackupZit-Signature: sha256=<hex>, el HMAC-SHA256 del cuerpo, para que el receptor compruebe que viene de su consola.

El JSON de un webhook:

{"event": "run.finished", "run_id": 412, "kind": "vm-backup", "kind_title": "VM backup",
 "status": "failed", "suspicious": "", "job": "Proxmox VMs", "job_id": 7, "agent": "pve1",
 "message": "…", "errors": ["…"], "started_at": "2026-10-04T22:00:03+02:00",
 "finished_at": "2026-10-04T22:04:41+02:00", "url": "https://backup.example/runs/412"}

Los mensajes se envían una vez por ejecución, también con el correo desactivado. Un canal que falla (URL incorrecta, servicio caído) se registra en el log de la consola y no retrasa a los demás. Las URL de los webhooks se guardan cifradas.
