Restauration

Chaque sauvegarde réussie peut être restaurée : entièrement ou seulement certains dossiers, sur la même machine, sur un autre agent ou en tant que nouvelle machine virtuelle.

L'assistant de restauration

Cliquez sur Restaurer dans le menu. L'assistant pose quatre questions :

  1. Quoi voulez-vous restaurer ?
    • une machine virtuelle complète
    • des fichiers d'une machine virtuelle
    • des fichiers et dossiers
    • une image disque / bare metal
    • des fichiers d'une image disque
    • une base de données (à un instant précis)
    • un système Linux complet
    • la messagerie Microsoft 365, OneDrive, les calendriers et contacts et les fichiers SharePoint (voir Microsoft 365)
    Chaque choix indique combien de points de restauration existent.
  2. Source : la machine virtuelle (tous hyperviseurs et tâches confondus), ou la tâche de sauvegarde et sa machine.
  3. Point de restauration : la sauvegarde à partir de laquelle restaurer, la plus récente d'abord, avec son état, son stockage et sa taille.
    • Les sauvegardes signalées comme suspectes (rançongiciel possible) sont marquées.
    • Les copies sur un stockage secondaire faites par une tâche de copie de sauvegarde sont listées comme copie (sauvegardes de fichiers et de VM).
  4. Options : où et comment restaurer. Un résumé de vos choix s'affiche au-dessus des options.

Les étapes en haut sont des liens, vous pouvez donc revenir à n'importe quelle étape précédente. Chaque étape a sa propre adresse, que vous pouvez mettre en favori ou partager.

Les options sont les mêmes que sur la page d'une sauvegarde dans Activité, où vous pouvez aussi lancer une restauration directement. Seuls les utilisateurs dont le rôle autorise la restauration voient l'assistant.

Restaurer depuis une sauvegarde de fichiers

  1. Choisissez Fichiers et dossiers dans l'assistant de restauration, puis la tâche et le point de restauration. Vous pouvez aussi ouvrir la sauvegarde dans Activité ou sur la page de la tâche.
  2. Sous Restaurer des fichiers depuis cette sauvegarde, choisissez l'agent qui doit recevoir les fichiers. Ce peut être une autre machine que celle sauvegardée — par exemple un PC de remplacement.
  3. Choisissez où :
    • Restaurer dans un dossier (recommandé) — p. ex. D:\Restore. L'arborescence d'origine y est recréée : D:\Restore\C\Users\ana\Documents\…. Rien d'existant n'est touché.
    • Restaurer à l’emplacement d’origine — réécrit les fichiers là où ils étaient, en écrasant les versions actuelles. Pour un partage NAS, l'agent reconnecte le partage en écriture. Les fichiers creux (images de VM, bases de données) sont restaurés creux. Sous Windows, seul un fichier qui était creux est de nouveau marqué comme creux (sparse) ; les autres, comme les disques VHD/VHDX (Hyper-V refuse les disques creux), sont restaurés comme fichiers normaux, de même que tous les fichiers des sauvegardes faites avec des agents antérieurs à 0.57, qui n'enregistraient pas l'attribut. Un lien symbolique ou une jonction qui se trouve sur le chemin n'est jamais traversé en écriture : une restauration dans un dossier le remplace par un dossier, et toute restauration n'écrit que dans les dossiers qu'elle a ouverts, même si un lien apparaît pendant qu'elle s'exécute (0.58 : aussi pour les sauvegardes de fichiers et à l'emplacement d'origine ; la racine d'un volume comme / ou C: ne peut pas être choisie comme dossier pour des fichiers de sauvegardes de VM et d'image). À l'emplacement d'origine, seuls les liens du système sont suivis (appartenant à root ou à l'utilisateur de l'agent sous Linux, à SYSTEM, à TrustedInstaller ou à un administrateur sous Windows, et que personne d'autre ne peut modifier ni remplacer : les anciens liens de compatibilité des profils utilisateur, comme Application Data, ne sont pas suivis) ; un lien vers un dossier qui n'existe pas est une erreur, et rien n'est créé là où il pointe. Le propriétaire, les autorisations et les attributs sont appliqués au fichier restauré lui-même, jamais à travers un lien mis à sa place. Depuis la 0.59, un tel lien doit aussi n'avoir qu'un seul nom : un lien physique vers lui, qu'un autre utilisateur pourrait créer, n'est pas suivi.
  4. Limitez éventuellement à Uniquement ces chemins, un par ligne, p. ex. C:\Users\ana\Documents\Contracts — ou sélectionnez-les dans le navigateur de fichiers (ci-dessous).
  5. Laissez Vérifier les fichiers restaurés activé : chaque fichier est relu et comparé à la somme de contrôle de la sauvegarde.
  6. Cliquez sur Lancer la restauration. La progression et les résultats s'affichent sur la page de l'exécution de restauration.

Les dates des fichiers, les attributs Windows (caché, lecture seule, …) et, sous Linux, les propriétaires, permissions (y compris les bits setuid), ACL, attributs étendus (étiquettes SELinux, capacités de fichiers), liens symboliques et physiques sont aussi restaurés. Sous macOS, également les indicateurs de fichier BSD (caché, verrouillé…), la date de création et les attributs étendus (voir Agents macOS). Les propriétaires ne sont définis que si l'agent tourne en root/administrateur.

Parcourir, télécharger et choisir des fichiers

Sur l'exécution de sauvegarde, Parcourir les fichiers montre les dossiers sauvegardés tels qu'ils étaient (aussi pour les partages NAS et les sauvegardes de système Linux). Ouvrez des dossiers, cochez des fichiers et des dossiers, puis :

  • Télécharger — un fichier arrive tel quel, plusieurs fichiers ou dossiers sous forme d'archive ZIP, directement dans le navigateur. Les téléchargements sont consignés dans le journal d'audit.
  • Les restaurer sur un agent — dans un dossier ou à l'emplacement d'origine, comme une restauration avec Uniquement ces chemins.

Un lien symbolique vers un fichier (p. ex. /etc/os-release) est téléchargé comme le fichier vers lequel il pointe, si ce fichier est dans la sauvegarde ; les liens vers des dossiers sont omis des archives ZIP. Il en va de même pour les fichiers téléchargés depuis des sauvegardes de machines virtuelles (ext4, XFS). Une restauration sur un agent recrée les liens en tant que liens.

La console lit elle-même la sauvegarde sur le stockage, le parcours fonctionne donc pour les sauvegardes sur un stockage réseau (SFTP, S3, SMB, Azure, dépôt renforcé) ; un stockage accessible aux agents uniquement est lu par l’intermédiaire d’un agent qui l’utilise (agents 0.61 et plus récents). Pour un disque local ou un disque USB d’un agent, restaurez avec les chemins. Les utilisateurs ayant un rôle de restauration peuvent parcourir et télécharger.

Trouver la bonne sauvegarde : utilisez le Calendrier pour voir quelles sauvegardes se sont exécutées quel jour, ou l'historique de la page de la tâche.

Restaurer des fichiers individuels depuis une image disque

Pour les sauvegardes d'image, cliquez sur Parcourir les fichiers dans l'exécution de sauvegarde. Vous pouvez parcourir le système de fichiers NTFS de l'image directement dans la console, cocher des fichiers et dossiers et les restaurer sur n'importe quel agent — sans restaurer le disque entier. Restaurés dans un dossier, les fichiers ont la même arborescence qu'avec une sauvegarde de fichiers : la lettre de lecteur devient le premier dossier (D:\Restore\C\Users\…).

Vous pouvez aussi télécharger les fichiers cochés directement dans le navigateur : un fichier arrive tel quel, plusieurs fichiers ou dossiers dans une archive ZIP — pratique pour un seul document d’une grande sauvegarde d’image. Comme la navigation, cela fonctionne pour les sauvegardes d’image sur un stockage réseau, nécessite l’autorisation Restauration, et le journal d’audit enregistre les chemins téléchargés.

Restaurer des fichiers individuels depuis une VM (Proxmox VE, Hyper-V, VMware)

Dans une exécution de sauvegarde de VM, cliquez sur Parcourir les fichiers à côté de l'invité. La console affiche les partitions et volumes LVM de ses disques et permet de parcourir les systèmes de fichiers NTFS, ext4 et XFS. Téléchargez les fichiers cochés (plusieurs sous forme d'archive ZIP) ou restaurez-les sur n'importe quel agent. Voir Proxmox VE, Hyper-V et VMware ESXi. Les fichiers restaurés sur un agent gardent les permissions Unix qu'ils avaient dans la VM (ext4, XFS) : les secrets restaurés comme /etc/shadow restent privés ; sous Linux, les fichiers des volumes NTFS ne sont lisibles que par leur propriétaire. Restaurés sur un agent Windows, les noms contenant : issus d'invités Linux (ext4, XFS) sont ignorés et listés : Windows lirait la partie après les deux-points comme un flux d'un autre fichier. Les flux de données alternatifs NTFS sont restaurés en tant que flux.

Restaurer des machines entières

  • Images disque Windows : sur un disque ou en bare metal, aussi sur un matériel différent — Images disque.
  • Systèmes Linux : sur un disque ou en bare metal, ou comme nouvelle VM Proxmox — Sauvegarde du système Linux.
  • VM et conteneurs Proxmox : comme nouvel invité ou sur place — Proxmox VE. Les VM Proxmox peuvent aussi tourner instantanément depuis la sauvegarde et être déplacées vers un stockage pendant qu'elles tournent (restauration instantanée).
  • Bases de données (SQL Server, PostgreSQL, MySQL/MariaDB) : sous un nouveau nom ou sur place, à un instant précis — Bases de données.
  • VM Hyper-V : comme nouvelle VM ou sur place (conserve l'ID et les adresses MAC) — Hyper-V.
  • VM VMware ESXi : comme nouvelle VM ou sur place (conserve l'UUID et les adresses MAC), sur n'importe quel hôte ESXi et datastore — VMware ESXi ; aussi instantanément depuis la sauvegarde via un agent proxy Linux, puis copiée sur un datastore (restauration instantanée).

ISO de récupération

Les restaurations bare metal démarrent la machine depuis une ISO de récupération (sur une clé USB ou attachée à une VM), voir Supports de récupération :

  • ISO de récupération Linux — publiée avec chaque version (backupzit-recovery-linux.iso) ; la page Supports de récupération la lie depuis la source de mise à jour.
  • ISO de récupération Windows — Windows PE ne peut pas être redistribué ; elle se construit donc une fois sur n'importe quel PC Windows 10/11 ou Server :
    1. Installez le Windows ADK gratuit (fonction Deployment Tools) et le module complémentaire Windows PE de Microsoft.
    2. Téléchargez build-winpe.ps1 depuis la version (à côté des paquets d'agent) et prenez backupzit-agent.exe dans C:\Program Files\backupzit Agent d'une machine dotée de l'agent.
    3. Dans un PowerShell administrateur : .\build-winpe.ps1 -AgentExe .\backupzit-agent.exe -Out .\backupzit-recovery.iso. Ajoutez -DriverDir C:\Drivers pour des pilotes de stockage ou de réseau (p. ex. VirtIO pour les VM Proxmox) et -RecoveryJson .\recovery.json pour qu'elle se connecte sans saisie.
    4. Au démarrage, l'ISO cherche \backupzit\recovery.json sur chaque lecteur. Si le fichier est présent, l'agent de récupération se connecte à cette console et la restauration est lancée d'ici : sur place, il suffit de démarrer sur la clé. Sinon, le programme graphique de récupération s'ouvre (backupzit-recovery.exe, installé à côté de l'agent) : restaurer une image disque ou des partitions isolées, aussi sur un disque plus petit ou plus grand, réparer le démarrage, charger des pilotes. L'invite de commandes du support lance l'autre (backupzit-recovery ou backupzit-agent recovery). Avec -AccessPackage .\backupzit.bzaccess (créé sous Supports de récupération), le programme ouvre les sauvegardes sans cette console ; seule la phrase secrète est nécessaire. Celle-ci doit compter 12 caractères de trois types (16 de deux, 20 d'un seul), et les mots de passe courants sont refusés ; la page en propose une générée, qui se tape de la même façon sur les claviers QWERTY, QWERTZ et AZERTY.
    5. La langue et le clavier de Windows PE sont ceux du PC qui crée l'ISO, comme le fuseau horaire (-Language de-de, -KeyboardLayout et -TimeZone en choisissent d'autres), si bien qu'une adresse de serveur ou une phrase secrète se tape comme sur ce PC. Le programme de récupération parle les 14 langues de la console. -NoUi n'intègre que l'agent en console. Le support contient les textes de licence et SOURCE-CODE.txt dans \backupzit\.
    6. Avant d'écrire, le programme vérifie de nouveau le disque cible par taille, modèle, numéro de série et ID de la table de partitions : un disque qui a reçu entre-temps le numéro choisi (un disque USB rebranché) est refusé, de même que les disques qui contiennent les sauvegardes, le support de récupération et un paquet d'accès. Une restauration sur le disque d'origine garde la disposition de la sauvegarde quand elle tient (aucune partition ne s'étend dans un espace vide) ; Adapter au disque cible est proposé pour un disque plus petit ou sur demande. Un disque converti en GPT ou MBR ne peut pas rester hors ligne. La réparation du démarrage sauvegarde d'abord les données de démarrage dans \backupzit sur un autre lecteur.
    7. Le programme s’utilise au clavier seul (Tab, Entrée, Espace, Échap) et fonctionne sur des écrans jusqu’à 800×600, où ses pages défilent. Le récapitulatif indique en rouge le disque qui sera effacé (numéro, modèle, taille) ; la restauration ne démarre qu’une fois ce numéro saisi. Un emplacement SFTP sans paquet d’accès affiche la clé d’hôte du serveur et demande avant de lui faire confiance : comparez-la avec ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub sur le serveur.
    8. Copiez éventuellement l'ISO dans le répertoire /var/lib/backupzit/dist de la console ; elle est alors proposée sur la page Supports de récupération.

Parcourir les fichiers dans la console fonctionne pour les sauvegardes sur un stockage réseau (SFTP, S3, SMB, Azure, dépôt renforcé) : la console les lit directement ou, pour un stockage accessible aux agents uniquement, par l’intermédiaire d’un agent qui l’utilise (également avec une clé SSH ; agents 0.61 et plus récents). Pour les sauvegardes sur un disque local d’un agent ou sur SFTP avec une clé SSH, une restauration avec Uniquement ces chemins fonctionne toujours depuis la console ; pour les examiner, utilisez la ligne de commande.

Restaurer sans la console

Si la console elle-même est perdue, n'importe quelle machine dotée de l'agent peut restaurer directement depuis le stockage à l'aide de la fiche de récupération de la cible de stockage :

set BACKUPZIT_PASSWORD=<recovery key>
set BACKUPZIT_SFTP_PASSWORD=...           (or the S3/SMB/hardened credentials)
set BACKUPZIT_SFTP_HOSTKEY=SHA256:...      (the SFTP host key, on the recovery sheet)
backupzit-agent snapshots --repo sftp://backup@nas:22/backups/pc1_1a2b3c4d
backupzit-agent restore   --repo sftp://backup@nas:22/backups/pc1_1a2b3c4d --target D:\Restore latest

latest est la sauvegarde la plus récente de n'importe quelle tâche de cet ordinateur ; pour restaurer une tâche précise, utilisez un ID d'instantané issu de snapshots. Voir Référence de la ligne de commande.

Tests de restauration automatiques

BackupZit éprouve vos sauvegardes régulièrement sans que vous ayez à intervenir : chaque semaine (réglable sous Paramètres → Tests de restauration), l'agent de chaque tâche restaure un échantillon aléatoire de fichiers de la sauvegarde la plus récente dans un dossier temporaire, vérifie chaque octet par rapport aux sommes de contrôle enregistrées, puis le supprime. Pour les images disque, des blocs aléatoires sont lus et vérifiés. Cela met à l'épreuve toute la chaîne — accès au stockage, identifiants, clé de chiffrement et intégrité des données.

  • Les résultats apparaissent dans Activité et l'historique de la tâche comme exécutions Test de restauration, et par tâche dans Rapports (colonne Test de restauration).
  • Un test échoué est un échec comme un autre et déclenche une alerte par e-mail.
  • Tester la restauration sur la page d'une tâche lance un test immédiatement.
  • La taille de l'échantillon limite la quantité lue depuis le stockage — gardez-la petite pour un stockage cloud avec frais de téléchargement.

Test de démarrage pour les VM Proxmox

Des blocs lisibles ne prouvent pas qu'une VM démarre encore. Avec Test de démarrage pour les sauvegardes de VM Proxmox activé (Paramètres → Tests de restauration), le test de restauration d'une tâche de VM Proxmox démarre aussi chaque VM de la sauvegarde la plus récente sur le nœud de la tâche, l'une après l'autre, avec la restauration instantanée : elle tourne depuis la sauvegarde avec un nouvel ID, cartes réseau déconnectées (pour ne pas entrer en conflit avec l'original), puis est supprimée juste après. Le test réussit quand l'agent invité QEMU de la VM répond dans le délai configuré, ce qui signifie que le système d'exploitation a démarré. Les VM sans agent invité réussissent si elles continuent de tourner pendant une minute ; la page de l'exécution les affiche alors comme en cours plutôt que démarrée. La copie omet aussi les paramètres qui sortent de la VM : un script hook, les arguments QEMU bruts (args), les périphériques PCI et USB transmis, les partages de l'hôte (virtiofs) et les ports série ou parallèles sur des périphériques de l'hôte ; la page de l'exécution indique ce qui a été omis. Une VM qui ne peut pas démarrer sans eux échoue au test de démarrage.

  • Le nœud a besoin de mémoire libre pour une VM de plus pendant le test.
  • Installez l'agent invité QEMU dans les VM (qemu-guest-agent sous Linux, les outils invités VirtIO sous Windows) et activez-le dans les options de la VM, pour que le test puisse confirmer le démarrage.
  • La page de l'exécution liste chaque VM avec son résultat et la durée du démarrage.

Vérifications dans la VM (agents 0.61 et plus récents) : une VM qui démarre peut être défectueuse, ou déjà compromise au moment de la sauvegarde. Dans une tâche de VM Proxmox, Vérifications du test de démarrage liste ce qui doit fonctionner dans la copie démarrée, une par ligne : service sshd (le service tourne), file /var/www/index.html (le fichier existe), port 443 (un programme écoute sur le port TCP) ou command … (votre propre commande se termine avec le code de sortie 0 ; sh sous Linux, cmd sous Windows). Une ligne qui commence par un ID de VM et deux-points, p. ex. 101: service nginx, ne vaut que pour cette VM. Les vérifications s’exécutent via l’agent invité QEMU en root ou SYSTEM dans la copie isolée et sont retentées jusqu’à ce qu’elles réussissent ou que l’attente du test de démarrage se termine ; la page de l’exécution affiche chacune. Seuls les utilisateurs autorisés à modifier les commandes les définissent.

Tester aussi le démarrage de la plus ancienne sauvegarde conservée par la tâche démarre aussi les VM du plus ancien point de restauration conservé : vous savez ainsi que le point sur lequel vous vous replieriez après une compromission passée inaperçue démarre encore. Une sauvegarde de VM dont les VM ont démarré et réussi leurs vérifications est marquée vérifiée sur sa page d’exécution, d’où elle est restaurée.

Vérification de toutes les données stockées

Les tests de restauration lisent un échantillon. En plus, un agent lit toutes les données de chaque dépôt, les vérifie par rapport à leur somme de contrôle et contrôle que les dossiers et données de chaque sauvegarde sont présents — une fois par mois par défaut (Paramètres → Tests de restauration : Vérifier les données stockées : mensuel, tous les trois mois ou jamais). On détecte ainsi les dommages sur le stockage lui-même, comme un disque défaillant dans un NAS ou la dégradation des données, avant d'avoir besoin de la sauvegarde. Chaque dépôt est vérifié une fois (les tâches d'un agent sur un stockage le partagent), par l'agent qui y écrit. La vérification lit tout le contenu du dépôt ; sur le stockage cloud (S3, Azure), elle ne s'exécute donc qu'avec Aussi sur le stockage cloud. Les problèmes font échouer l'exécution Vérification des données et envoient une notification d'échec ; Vérifier les données sur la page d'une tâche lance une vérification immédiatement. Nécessite des agents 0.39.0 ou plus récents. Sur S3, Azure et le stockage durci, la vérification lit plusieurs paquets de données à la fois (agents 0.54.2 et plus récents). Pendant une vérification, Activité et sa page d'exécution indiquent combien de paquets de données du dépôt elle a déjà vérifiés. Une vérification qui trouve des paquets de données endommagés propose Réparation sur la page de son exécution (Dépannage).

En plus, restaurez de temps en temps (p. ex. chaque trimestre) un vrai dossier à la main et ouvrez quelques fichiers — cela entraîne aussi les personnes qui devront le faire en cas d'urgence.
