Restauration

Chaque sauvegarde réussie peut être restaurée : entièrement ou seulement certains dossiers, sur la même machine, sur un autre agent ou en tant que nouvelle machine virtuelle.

L'assistant de restauration

Cliquez sur Restaurer dans le menu. L'assistant pose quatre questions :

  1. Quoi voulez-vous restaurer ?
    • une machine virtuelle complète
    • des fichiers d'une machine virtuelle
    • des fichiers et dossiers
    • une image disque / bare metal
    • des fichiers d'une image disque
    • une base de données (à un instant précis)
    • un système Linux complet
    • la messagerie Microsoft 365 et OneDrive (voir Microsoft 365)
    Chaque choix indique combien de points de restauration existent.
  2. Source : la machine virtuelle (tous hyperviseurs et tâches confondus), ou la tâche de sauvegarde et sa machine.
  3. Point de restauration : la sauvegarde à partir de laquelle restaurer, la plus récente d'abord, avec son état, son stockage et sa taille.
    • Les sauvegardes signalées comme suspectes (rançongiciel possible) sont marquées.
    • Les copies sur un stockage secondaire faites par une tâche de copie de sauvegarde sont listées comme copie (sauvegardes de fichiers et de VM).
  4. Options : où et comment restaurer. Un résumé de vos choix s'affiche au-dessus des options.

Les étapes en haut sont des liens, vous pouvez donc revenir à n'importe quelle étape précédente. Chaque étape a sa propre adresse, que vous pouvez mettre en favori ou partager.

Les options sont les mêmes que sur la page d'une sauvegarde dans Activité, où vous pouvez aussi lancer une restauration directement. Seuls les utilisateurs dont le rôle autorise la restauration voient l'assistant.

Restaurer depuis une sauvegarde de fichiers

  1. Choisissez Fichiers et dossiers dans l'assistant de restauration, puis la tâche et le point de restauration. Vous pouvez aussi ouvrir la sauvegarde dans Activité ou sur la page de la tâche.
  2. Sous Restaurer des fichiers depuis cette sauvegarde, choisissez l'agent qui doit recevoir les fichiers. Ce peut être une autre machine que celle sauvegardée — par exemple un PC de remplacement.
  3. Choisissez où :
    • Restaurer dans un dossier (recommandé) — p. ex. D:\Restore. L'arborescence d'origine y est recréée : D:\Restore\C\Users\ana\Documents\…. Rien d'existant n'est touché.
    • Restaurer à l’emplacement d’origine — réécrit les fichiers là où ils étaient, en écrasant les versions actuelles. Pour un partage NAS, l'agent reconnecte le partage en écriture.
  4. Limitez éventuellement à Uniquement ces chemins, un par ligne, p. ex. C:\Users\ana\Documents\Contracts — ou sélectionnez-les dans le navigateur de fichiers (ci-dessous).
  5. Laissez Vérifier les fichiers restaurés activé : chaque fichier est relu et comparé à la somme de contrôle de la sauvegarde.
  6. Cliquez sur Lancer la restauration. La progression et les résultats s'affichent sur la page de l'exécution de restauration.

Les dates des fichiers, les attributs Windows (caché, lecture seule, …) et, sous Linux, les propriétaires, permissions (y compris les bits setuid), ACL, attributs étendus (étiquettes SELinux, capacités de fichiers), liens symboliques et physiques sont aussi restaurés. Les propriétaires ne sont définis que si l'agent tourne en root/administrateur.

Parcourir, télécharger et choisir des fichiers

Sur l'exécution de sauvegarde, Parcourir les fichiers montre les dossiers sauvegardés tels qu'ils étaient (aussi pour les partages NAS et les sauvegardes de système Linux). Ouvrez des dossiers, cochez des fichiers et des dossiers, puis :

  • Télécharger — un fichier arrive tel quel, plusieurs fichiers ou dossiers sous forme d'archive ZIP, directement dans le navigateur. Les téléchargements sont consignés dans le journal d'audit.
  • Les restaurer sur un agent — dans un dossier ou à l'emplacement d'origine, comme une restauration avec Uniquement ces chemins.

Un lien symbolique vers un fichier (p. ex. /etc/os-release) est téléchargé comme le fichier vers lequel il pointe, si ce fichier est dans la sauvegarde ; les liens vers des dossiers sont omis des archives ZIP. Il en va de même pour les fichiers téléchargés depuis des sauvegardes de machines virtuelles (ext4, XFS). Une restauration sur un agent recrée les liens en tant que liens.

La console lit elle-même la sauvegarde depuis le stockage ; la navigation fonctionne donc pour les sauvegardes sur un stockage réseau (SFTP, S3, SMB, Azure, dépôt renforcé) ; pour un disque local ou USB d'un agent, restaurez avec les chemins. Les utilisateurs disposant d'un rôle de restauration peuvent parcourir et télécharger.

Trouver la bonne sauvegarde : utilisez le Calendrier pour voir quelles sauvegardes se sont exécutées quel jour, ou l'historique de la page de la tâche.

Restaurer des fichiers individuels depuis une image disque

Pour les sauvegardes d'image, cliquez sur Parcourir les fichiers dans l'exécution de sauvegarde. Vous pouvez parcourir le système de fichiers NTFS de l'image directement dans la console, cocher des fichiers et dossiers et les restaurer sur n'importe quel agent — sans restaurer le disque entier.

Restaurer des fichiers individuels depuis une VM (Proxmox VE, Hyper-V, VMware)

Dans une exécution de sauvegarde de VM, cliquez sur Parcourir les fichiers à côté de l'invité. La console affiche les partitions et volumes LVM de ses disques et permet de parcourir les systèmes de fichiers NTFS, ext4 et XFS. Téléchargez les fichiers cochés (plusieurs sous forme d'archive ZIP) ou restaurez-les sur n'importe quel agent. Voir Proxmox VE, Hyper-V et VMware ESXi.

Restaurer des machines entières

  • Images disque Windows : sur un disque ou en bare metal, aussi sur un matériel différent — Images disque.
  • Systèmes Linux : sur un disque ou en bare metal, ou comme nouvelle VM Proxmox — Sauvegarde du système Linux.
  • VM et conteneurs Proxmox : comme nouvel invité ou sur place — Proxmox VE. Les VM Proxmox peuvent aussi tourner instantanément depuis la sauvegarde et être déplacées vers un stockage pendant qu'elles tournent (restauration instantanée).
  • Bases de données (SQL Server, PostgreSQL, MySQL/MariaDB) : sous un nouveau nom ou sur place, à un instant précis — Bases de données.
  • VM Hyper-V : comme nouvelle VM ou sur place (conserve l'ID et les adresses MAC) — Hyper-V.
  • VM VMware ESXi : comme nouvelle VM ou sur place (conserve l'UUID et les adresses MAC), sur n'importe quel hôte ESXi et datastore — VMware ESXi ; aussi instantanément depuis la sauvegarde via un agent proxy Linux, puis copiée sur un datastore (restauration instantanée).

ISO de récupération

Les restaurations bare metal démarrent la machine depuis une ISO de récupération (sur une clé USB ou attachée à une VM), voir Supports de récupération :

  • ISO de récupération Linux — publiée avec chaque version (backupzit-recovery-linux.iso) ; la page Supports de récupération la lie depuis la source de mise à jour.
  • ISO de récupération Windows — Windows PE ne peut pas être redistribué ; elle se construit donc une fois sur n'importe quel PC Windows 10/11 ou Server :
    1. Installez le Windows ADK gratuit (fonction Deployment Tools) et le module complémentaire Windows PE de Microsoft.
    2. Téléchargez build-winpe.ps1 depuis la version (à côté des paquets d'agent) et prenez backupzit-agent.exe dans C:\Program Files\backupzit Agent d'une machine dotée de l'agent.
    3. Dans un PowerShell administrateur : .\build-winpe.ps1 -AgentExe .\backupzit-agent.exe -Out .\backupzit-recovery.iso. Ajoutez -DriverDir C:\Drivers pour des pilotes de stockage ou de réseau (p. ex. VirtIO pour les VM Proxmox) et -RecoveryJson .\recovery.json pour qu'elle se connecte sans saisie.
    4. Copiez éventuellement l'ISO dans le répertoire /var/lib/backupzit/dist de la console ; elle est alors proposée sur la page Supports de récupération.

La navigation dans les fichiers depuis la console fonctionne pour les sauvegardes sur un stockage réseau (SFTP, S3, SMB, Azure, dépôt renforcé) ; la console les lit directement. Pour les sauvegardes sur un disque local d'un agent, utilisez la ligne de commande.

Restaurer sans la console

Si la console elle-même est perdue, n'importe quelle machine dotée de l'agent peut restaurer directement depuis le stockage à l'aide de la fiche de récupération de la cible de stockage :

set BACKUPZIT_PASSWORD=<recovery key>
set BACKUPZIT_SFTP_PASSWORD=...           (or the S3/SMB/hardened credentials)
backupzit-agent snapshots --repo sftp://backup@nas:22/backups/pc1_1a2b3c4d
backupzit-agent restore   --repo sftp://backup@nas:22/backups/pc1_1a2b3c4d --target D:\Restore latest

Voir Référence de la ligne de commande.

Tests de restauration automatiques

BackupZit éprouve vos sauvegardes régulièrement sans que vous ayez à intervenir : chaque semaine (réglable sous Paramètres → Tests de restauration), l'agent de chaque tâche restaure un échantillon aléatoire de fichiers de la sauvegarde la plus récente dans un dossier temporaire, vérifie chaque octet par rapport aux sommes de contrôle enregistrées, puis le supprime. Pour les images disque, des blocs aléatoires sont lus et vérifiés. Cela met à l'épreuve toute la chaîne — accès au stockage, identifiants, clé de chiffrement et intégrité des données.

  • Les résultats apparaissent dans Activité et l'historique de la tâche comme exécutions Test de restauration, et par tâche dans Rapports (colonne Test de restauration).
  • Un test échoué est un échec comme un autre et déclenche une alerte par e-mail.
  • Tester la restauration sur la page d'une tâche lance un test immédiatement.
  • La taille de l'échantillon limite la quantité lue depuis le stockage — gardez-la petite pour un stockage cloud avec frais de téléchargement.

Test de démarrage pour les VM Proxmox

Des blocs lisibles ne prouvent pas qu'une VM démarre encore. Avec Test de démarrage pour les sauvegardes de VM Proxmox activé (Paramètres → Tests de restauration), le test de restauration d'une tâche de VM Proxmox démarre aussi chaque VM de la sauvegarde la plus récente sur le nœud de la tâche, l'une après l'autre, avec la restauration instantanée : elle tourne depuis la sauvegarde avec un nouvel ID, cartes réseau déconnectées (pour ne pas entrer en conflit avec l'original), puis est supprimée juste après. Le test réussit quand l'agent invité QEMU de la VM répond dans le délai configuré, ce qui signifie que le système d'exploitation a démarré. Les VM sans agent invité réussissent si elles continuent de tourner pendant une minute ; la page de l'exécution les affiche alors comme en cours plutôt que démarrée.

  • Le nœud a besoin de mémoire libre pour une VM de plus pendant le test.
  • Installez l'agent invité QEMU dans les VM (qemu-guest-agent sous Linux, les outils invités VirtIO sous Windows) et activez-le dans les options de la VM, pour que le test puisse confirmer le démarrage.
  • La page de l'exécution liste chaque VM avec son résultat et la durée du démarrage.

En plus, restaurez de temps en temps (p. ex. chaque trimestre) un vrai dossier à la main et ouvrez quelques fichiers — cela entraîne aussi les personnes qui devront le faire en cas d'urgence.
