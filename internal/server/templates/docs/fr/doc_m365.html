Microsoft 365 : Exchange Online, OneDrive et SharePoint

BackupZit sauvegarde les boîtes aux lettres (Exchange Online), calendriers, contacts, OneDrive et sites SharePoint d'un locataire Microsoft 365 via Microsoft Graph. Il ne fait que lire : rien n'est modifié ni supprimé dans le locataire. N'importe quel agent ayant accès à Internet télécharge les données — par exemple l'agent de la machine de la console — et les stocke comme toute sauvegarde : dédupliquées, chiffrées, avec rétention, tâches de copie et tests de restauration.

1. Enregistrer une application dans Microsoft Entra ID

Une fois par locataire, en tant qu'administrateur général, dans le centre d'administration Microsoft Entra :

  1. App registrations → New registration : nom par ex. BackupZit, Accounts in this organizational directory only, sans URI de redirection. Notez l'Application (client) ID et le Directory (tenant) ID dans sa vue d'ensemble.
  2. Certificates & secrets → New client secret : choisissez une durée de validité (par ex. 24 mois) et copiez immédiatement la Value du secret — elle n'est affichée qu'une fois. Le Secret ID n'est pas le secret.
  3. API permissions → Add a permission → Microsoft Graph → Application permissions (pas delegated) : User.Read.All, Mail.Read et Files.Read.All ; pour les calendriers et contacts aussi Calendars.Read et Contacts.Read, pour SharePoint Sites.Read.All.
  4. Cliquez sur Grant admin consent for …. D'ici là, l'état indique Not granted et les sauvegardes sont refusées.

Ce sont uniquement des autorisations de lecture. Restaurer plus tard dans les boîtes aux lettres nécessitera des autorisations d'écriture, que BackupZit ne demande pas.

Pour limiter l'application à certaines boîtes aux lettres, un administrateur Exchange peut ajouter une application access policy ou une étendue RBAC for Applications ; les comptes hors de cette étendue sont alors signalés comme illisibles.

2. Créer la tâche

Dans Tâches de sauvegarde, créez une tâche du type Microsoft 365 :

  • Agent : l'agent qui télécharge (Windows ou Linux, version 0.34.0 ou plus récente ; 0.35.0 pour les calendriers, contacts et SharePoint). Il a besoin d'un accès HTTPS à login.microsoftonline.com, graph.microsoft.com et, pour les fichiers OneDrive et SharePoint, *.sharepoint.com.
  • ID de l'annuaire (locataire), ID d'application (client) et Secret client de l'étape 1. Le secret est stocké chiffré.
  • Ce qu'il faut sauvegarder : Messagerie, OneDrive, Calendriers et contacts, Sites SharePoint — dans n'importe quelle combinaison.
  • Comptes : une adresse par ligne, ou vide pour chaque compte du locataire qui a une boîte aux lettres ou un OneDrive — les comptes ajoutés plus tard sont inclus automatiquement ; les comptes sans licence sont ignorés.
  • Sites SharePoint : une adresse de site par ligne (par ex. https://contoso.sharepoint.com/sites/sales), ou vide pour chaque site du locataire — les sites ajoutés plus tard sont inclus automatiquement. Les sites personnels (OneDrive) sont exclus ; ils sont sauvegardés avec les comptes. Une tâche uniquement SharePoint n'a pas besoin de comptes.

Au lieu de saisir les adresses, cliquez sur Choisir dans la liste : avec l'application saisie ci-dessus, la console lit les comptes (en marquant ceux sans licence, qui n'ont ni boîte aux lettres ni OneDrive) et les sites SharePoint du locataire et les liste pour que vous les cochiez ; ceux cochés remplissent les champs. Lors de la modification d'une tâche, le secret enregistré est utilisé.

À l'enregistrement de la tâche, la console se connecte en tant qu'application et vérifie les autorisations, les comptes et les sites, de sorte qu'un mauvais secret ou un consentement administrateur manquant apparaît aussitôt. Une console sans accès à Internet saute la vérification ; la première sauvegarde montre alors si cela fonctionne.

Ce qui est sauvegardé

  • Messagerie : tous les dossiers de courrier avec leurs sous-dossiers (Boîte de réception, Éléments envoyés, Éléments supprimés, Archive, vos propres dossiers…). Chaque message est stocké complet avec ses pièces jointes au format MIME sous forme de fichier .eml, nommé d'après sa date d'arrivée et son objet, par ex. 2026-10-07 0621 Offre pour octobre [3fa2c1d9e0].eml. Outlook, Thunderbird et la plupart des logiciels de messagerie ouvrent les fichiers .eml.
  • OneDrive : tous les fichiers et dossiers du OneDrive du compte, avec leur date de modification.
  • Calendriers : chaque calendrier du compte ; chaque événement sous forme de fichier iCalendar (.ics) avec heure, lieu, description, organisateur, participants, rappel et — pour une série — sa périodicité, nommé d'après son début et son objet, par ex. 2026-10-08 1000 Conseil d'administration [8c1e…].ics. Outlook, Google Agenda et Thunderbird importent les fichiers .ics. Les heures sont stockées en UTC.
  • Contacts : les contacts et dossiers de contacts du compte, chacun sous forme de vCard (.vcf) avec noms, adresses e-mail, numéros de téléphone, adresses, société et notes.
  • SharePoint : chaque bibliothèque de documents de chaque site (Documents, Ressources du site et bibliothèques que vous avez créées), avec tous les dossiers et fichiers.

Non inclus : les pièces jointes des événements du calendrier, les photos des contacts, les occurrences modifiées individuellement d'une série, les listes et pages SharePoint (uniquement les bibliothèques de documents), les conversations Teams et messages de canal (les fichiers Teams sont dans SharePoint et sont sauvegardés avec lui), et les boîtes aux lettres partagées sans compte utilisateur.

Une sauvegarde contient un dossier par compte — ana@contoso.com/Mail/Inbox/…, …/OneDrive/…, …/Calendar/Calendar/…, …/Contacts/… — et SharePoint/<site>/<library>/…. La première sauvegarde télécharge tout ; chaque sauvegarde suivante liste à nouveau les dossiers mais ne télécharge que les messages et fichiers nouveaux ou modifiés depuis la sauvegarde précédente (les messages lus, marqués, déplacés ou modifiés comptent comme modifiés) — les données inchangées sont reprises de la sauvegarde précédente. Microsoft limite la vitesse de lecture d'une application ; BackupZit attend lorsque Microsoft le demande, puis continue, de sorte qu'une première sauvegarde de grandes boîtes aux lettres peut prendre des heures.

Les sauvegardes d'un locataire sont stockées dans leur propre dépôt sur la cible de stockage (dossier m365-<tenant ID>), afin que l'agent de téléchargement puisse être remplacé sans tout recommencer.

Restauration

  • Parcourir les fichiers sur une exécution de sauvegarde : ouvrez les dossiers de courrier, le OneDrive, les calendriers ou les contacts d'un compte, ou un site SharePoint, cochez des messages, événements, fichiers ou dossiers et téléchargez-les (un fichier tel quel, plusieurs en ZIP) — ouvrez les fichiers .eml dans Outlook ou glissez-les dans une boîte aux lettres.
  • Restaurer dans un dossier sur n'importe quel agent : les messages sont écrits en fichiers .eml, les événements en .ics, les contacts en .vcf et les fichiers OneDrive et SharePoint tels qu'ils étaient, sous <folder>/<account>/… et <folder>/SharePoint/….

La restauration directe dans une boîte aux lettres ou un OneDrive est prévue ; elle n'écrira que dans un nouveau dossier et n'écrasera ni ne supprimera jamais rien.

Dépannage

  • AADSTS7000215 / invalid client secret : ce n'est pas la Value du secret qui a été copiée (mais son ID), ou il a expiré — créez-en un nouveau et saisissez-le dans la tâche.
  • missing the application permissions ou Authorization_RequestDenied : ajoutez les autorisations en tant qu'autorisations d'application et cliquez sur Grant admin consent.
  • the account has no Exchange Online mailbox : le compte n'a pas de licence Exchange (ou est un contact) ; retirez-le de la tâche.
  • Une exécution avec avertissements liste les messages ou fichiers qui n'ont pas pu être lus (par ex. un bloc-notes OneNote) ; le reste de la sauvegarde est complet.
