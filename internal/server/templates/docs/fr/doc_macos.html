Agents macOS (Apple silicon)

L'agent macOS sauvegarde les fichiers et dossiers d'un Mac avec puce Apple silicon. Il tourne comme service dès le démarrage, lit chaque sauvegarde du disque de démarrage depuis un instantané local APFS et conserve les métadonnées des fichiers du Mac. Une app de la barre des menus affiche son état et guide l'utilisateur à travers les autorisations que lui seul peut accorder.

Prérequis

  • Un Mac avec Apple silicon (M1 et plus récents, arm64) et macOS 13 ou plus récent. Les Mac Intel n'ont pas de paquet.
  • Un compte administrateur sur le Mac, pour l'installation et l'inscription.
  • L'utilisateur du Mac, pour accorder l'accès complet au disque : macOS ne laisse personne d'autre le faire, ni un script ni la console.
  • Comme tout agent, le Mac doit joindre l'adresse agents de la console (en général le port 8443) et le stockage.

Installation

  1. Sur la page Agents, téléchargez Agent macOS — Apple Silicon (backupzit-agent_version_darwin_arm64.pkg). Le paquet de la console le contient, comme les installateurs Windows et Linux.
  2. Ouvrez le .pkg sur le Mac et suivez l'installateur. Pour un paquet qui n'est pas signé avec un Apple Developer ID, macOS demande d'abord une confirmation : faites un clic droit dessus et choisissez Ouvrir (sur les macOS récents : Réglages Système → Confidentialité et sécurité → Ouvrir quand même).
  3. La dernière page de l'installateur explique les autorisations à accorder, et l'app de la barre des menus s'ouvre.

Le paquet installe :

Le programme n'est pas ajouté au PATH : dans le Terminal, appelez-le avec son chemin complet.

Inscription

Le service est installé et tourne avant même que le Mac soit inscrit ; il se met au travail dès qu'il l'est. Sur la page Agents, Créer un jeton d’inscription affiche les commandes pour macOS à côté de celles pour Windows et Linux. Choisissez l'une des trois méthodes :

  1. Dans le Terminal, après l'installation (la méthode habituelle) : 
    sudo /Library/BackupZit/bin/backupzit-agent enroll --code "BZ1-..."
  2. Avec un MDM (Jamf, Intune, Mosyle…) : avant l'installation du paquet, un script écrit le code dans un fichier appartenant à root : 
    echo "BZ1-..." | sudo sh -c 'umask 077; mkdir -p "/Library/Application Support/BackupZit"; cat > "/Library/Application Support/BackupZit/enroll-code"'
    Déployez ensuite le paquet. Son installation inscrit le Mac avec le code et supprime le fichier. Un fichier qui n'appartient pas à root est ignoré. C'est aussi la façon de déplacer un Mac inscrit vers une autre console.
  3. Un fichier à côté du paquet : backupzit-enroll.txt avec le code, dans le même dossier que le .pkg sur le disque de démarrage du Mac (par exemple dans /Users/Shared ; depuis une clé USB ou un partage réseau, copiez d'abord les deux sur le Mac : sur un tel volume, n'importe quel fichier peut se dire à root). Il n'est utilisé que tant que le Mac n'est pas encore enregistré, et seulement si personne d'autre n'a pu l'écrire : le fichier appartient à root ou à un administrateur du Mac, n'a qu'un seul nom et seul son propriétaire peut le modifier, et son dossier appartient à root ou à un administrateur et n'est pas modifiable par d'autres utilisateurs (ou a le bit sticky, comme /Users/Shared).

Si la console n'est pas joignable pendant l'installation, l'agent garde le code et réessaie. Si l'inscription échoue, la raison se trouve dans /Library/Application Support/BackupZit/enroll-error.log ; inscrivez ensuite le Mac dans le Terminal. Les mises à niveau et réinstallations conservent l'inscription.

Autorisations

macOS protège certaines données contre tout programme, même s'il tourne en root, jusqu'à ce que l'utilisateur l'autorise dans Réglages Système. Seul l'utilisateur devant le Mac peut accorder ces autorisations ; la dernière page de l'installateur et l'app de la barre des menus le guident.

Accès complet au disque pour l'agent

Sans lui, les sauvegardes omettent les dossiers que macOS protège, et aucun instantané APFS n'est pris (voir Ce qui est sauvegardé).

  1. Ouvrez Réglages Système → Confidentialité et sécurité → Accès complet au disque.
  2. Cliquez sur + sous la liste et saisissez votre mot de passe.
  3. Appuyez sur Commande-Maj-G, tapez /Library/BackupZit/bin/backupzit-agent, appuyez sur Retour et cliquez sur Ouvrir.
  4. Vérifiez que l'interrupteur à côté de backupzit-agent est activé.

Au lieu de +, vous pouvez faire glisser le fichier dans la liste : dans le Finder, choisissez Aller → Aller au dossier…, tapez /Library/BackupZit/bin et faites glisser backupzit-agent sur la liste.

L'agent en arrière-plan

Après l'installation, macOS affiche Éléments d'arrière-plan ajoutés. Dans Réglages Système → Général → Éléments de connexion et extensions, sous Autoriser en arrière-plan, backupzit-agent et BackupZit doivent rester activés : désactivé, l'agent ne tourne pas et aucune sauvegarde ne démarre.

Notifications et ouverture à la connexion

  • Notifications : autorisez-les quand l'app de la barre des menus le demande, ou plus tard dans Réglages Système → Notifications → BackupZit (Autoriser les notifications). L'app y prévient l'utilisateur quand une sauvegarde échoue.
  • Ouverture à la connexion : l'app de la barre des menus s'ouvre à chaque ouverture de session tant que BackupZit est activé sous Éléments de connexion et extensions → Autoriser en arrière-plan.

L'app de la barre des menus et son assistant

L'icône BackupZit dans la barre des menus affiche l'état de l'agent ; son menu propose Back up now pour chaque tâche du Mac, Open console in browser et Hide this icon (jusqu'à la prochaine ouverture de session ; les sauvegardes continuent). Sa section Permissions liste l'agent en arrière-plan, l'accès complet au disque, les notifications et l'ouverture à la connexion, chacun avec ✅ ou ❌. Un clic sur un élément ouvre sa page de Réglages Système ; une autorisation manquante est en plus expliquée une fois par session, dans une fenêtre qui donne les étapes à suivre. Tant qu'il manque quelque chose, elle revérifie d'elle-même toutes les quelques secondes, si bien que ✅ apparaît dès que l'autorisation est accordée. L'agent signale aussi un accès complet au disque manquant à la console, dans le rapport d'exécution.

Vérifier dans le Terminal

/Library/BackupZit/bin/backupzit-agent status

La commande fonctionne pour un utilisateur normal et affiche la console, les tâches et full disk access: granted ou denied (avec le programme à activer).

L'accès complet au disque après une mise à jour

macOS lie l'accès complet au disque à la signature du programme. Les paquets signés avec un Apple Developer ID le conservent d'une mise à jour à l'autre. Un paquet construit sans (signé ad hoc) le perd à chaque mise à jour automatique : les sauvegardes avertissent alors de nouveau, et l'app de la barre des menus indique que l'accès complet au disque a disparu depuis la mise à jour. Accordez-le de nouveau : dans la liste Accès complet au disque, sélectionnez backupzit-agent, cliquez sur − pour le retirer (le désactiver puis le réactiver ne suffit pas), puis ajoutez-le de nouveau avec + comme ci-dessus.

Ce qui est sauvegardé

Un agent Mac exécute des tâches fichiers et dossiers comme tout agent : des chemins comme /Users, /Applications ou /, des chemins {users} (/Users/<nom>/Documents) et des jokers, aussi dans une tâche pour plusieurs agents avec Tous les agents macOS.

Instantané local APFS

Chaque sauvegarde de fichiers du volume de données du disque de démarrage est lue depuis un instantané local APFS, l'équivalent macOS de VSS sous Windows : la sauvegarde voit chaque fichier tel qu'il était à un même instant, y compris ceux qu'un programme continue d'écrire. L'agent prend l'instantané (tmutil localsnapshot), le monte en lecture seule, y lit les fichiers, puis le démonte et le supprime après la sauvegarde. Les instantanés laissés par un plantage sont nettoyés au démarrage suivant ; les instantanés propres à Time Machine ne sont jamais touchés. Le rapport d'exécution indique Read from an APFS local snapshot of /System/Volumes/Data.

L'instantané nécessite le service (root) et l'accès complet au disque. Sans accès complet au disque, et pour les chemins sur d'autres volumes (/Volumes : disques externes, partages réseau), les fichiers sont lus sans instantané, et le rapport d'exécution le signale.

Métadonnées

Conservés avec chaque fichier et dossier : propriétaire et groupe, permissions, attributs étendus (sauf com.apple.provenance, que macOS gère lui-même), liens physiques, liens symboliques, indicateurs de fichier BSD (caché, verrouillé, nodump, ajout seul… ; les indicateurs système seulement quand l'agent tourne en root, comme le service), la date de création et les dates de modification à la nanoseconde. Les fichiers creux restent creux : leurs trous sont recréés sur APFS.

Dossiers gardés vides

Certains dossiers système sous un dossier sauvegardé sont gardés comme dossiers vides : les autres volumes (/Volumes), le swap (/System/Volumes/VM, /private/var/vm), les volumes de support dans /System/Volumes, /dev, les fichiers temporaires (/private/tmp, /private/var/folders), les caches (/Library/Caches, /System/Library/Caches, ~/Library/Caches), la Corbeille (~/.Trash, .Trashes), Spotlight, FSEvents, les versions de documents et les sauvegardes Time Machine locales et HFS+. Avec / comme source, les dossiers du volume de données que / montre déjà (/Users, /Applications…) ne sont pas lus deux fois. Un dossier indiqué comme source de la tâche est toujours lu, p. ex. /Volumes/USB ou ~/.Trash.

Avertissements dans le rapport d'exécution

Sans accès complet au disque, les dossiers que macOS protège ne peuvent pas être lus : Mail, Messages, Safari, Bureau et Documents, les données des autres apps, les volumes amovibles et réseau. Une sauvegarde dont les sources atteignent /Users (sauf /Users/Shared), /Library ou /Volumes, ou un dossier au-dessus comme /, se termine alors avec l'avertissement Full Disk Access is not granted to the BackupZit agent. Les sauvegardes d'autres dossiers (p. ex. /opt/data) n'avertissent pas.

Restauration

Les fichiers d'un Mac se restaurent comme toutes les sauvegardes de fichiers : la sauvegarde entière ou seulement certains chemins, dans un dossier ou à l'emplacement d'origine, sur le Mac ou sur un autre agent ; des fichiers individuels se téléchargent depuis la console. Une restauration sur un Mac remet les métadonnées ci-dessus. Comme sous Windows et Linux, elle n'écrit qu'à travers les dossiers qu'elle a ouverts, jamais par chemin, si bien qu'un lien placé en travers pendant la restauration n'est pas suivi. Une restauration par-dessus des fichiers verrouillés retire d'abord leurs indicateurs verrouillé et ajout seul, puis remet ceux enregistrés (les indicateurs système ne peuvent pas être retirés sur un Mac en marche).

Mise à jour et désinstallation

La page Agents propose Mettre à jour vers version pour un Mac comme pour les autres agents (voir Agents). L'agent télécharge le .pkg depuis la console, le vérifie par rapport à la liste signée des installateurs d'agent et à sa somme SHA-256, l'installe avec l'installer d'Apple dans une tâche launchd ponctuelle et redémarre avec la nouvelle version. Si launchd refuse cette tâche, l'exécution de mise à jour échoue avec le message de launchd. Le journal de l'installateur se trouve dans /Library/Application Support/BackupZit/updates. Vérifiez l'accès complet au disque après la mise à jour d'un paquet non signé.

Supprimer sur la page Agents avec Désinstaller l’agent de l’ordinateur retire le programme, l'app de la barre des menus, le LaunchDaemon et le LaunchAgent ainsi que le reçu du paquet ; la configuration et le journal restent. Pour désinstaller à la main :

sudo /Library/BackupZit/uninstall.sh            # keeps configuration and log
sudo /Library/BackupZit/uninstall.sh --purge    # deletes them too

Sans --purge, l'inscription est mise de côté (agent.json.removed-date), si bien qu'une nouvelle installation demande de nouveau un code. Après la désinstallation, retirez backupzit-agent de Confidentialité et sécurité → Accès complet au disque à la main : macOS ne laisse aucun programme le faire.

Ce qu'un agent Mac ne fait pas

Pas sur un MacÀ la place
Sauvegardes système Linux / bare-metalLa console refuse une tâche système pour un Mac (is a Mac: back it up with a files job) : son volume système est scellé et signé par Apple et se réinstalle, il ne se restaure pas. Sauvegardez les données avec une tâche de fichiers.
Images disqueWindows uniquement.
Hôtes Hyper-V, Proxmox VE et proxy VMware ESXiDes agents sur l'hôte Hyper-V (Windows), le nœud Proxmox (Linux) ou un agent proxy Linux.
Tâches NAS / partage de fichiers (SMB, NFS)Un agent Windows ou Linux pour l'instant : l'agent Mac ne monte pas encore de partages.
Tâches PostgreSQL / MySQLPas encore validées sous macOS : ne les utilisez sur un Mac qu'après avoir testé une restauration.

Les tâches Microsoft 365 tournent sur tout agent disposant d'un accès à Internet, un Mac aussi.

Journaux

  • Agent : /Library/Logs/BackupZit/agent.log (aussi listé dans Console.app) ; une trace de plantage va dans /Library/Logs/BackupZit/launchd.log.
  • Inscription par l'installateur : /Library/Application Support/BackupZit/enroll-error.log et le journal de l'installateur /var/log/install.log.
  • Mises à jour : /Library/Application Support/BackupZit/updates.
  • Obtenir le journal sur la page Agents récupère la fin du journal depuis la console (voir Journaux).
