REST API

Intégrez BackupZit aux plateformes RMM, à la supervision (PRTG, Zabbix, Nagios, Uptime Kuma…) et à vos propres scripts.

Jetons

Créez un jeton dans Mon compte → Jetons API. Donnez-lui le rôle le plus bas qui suffit — Lecteur pour la supervision, Opérateur de restauration pour aussi lancer des sauvegardes et des tests de restauration. Le jeton n'est affiché qu'une fois ; envoyez-le dans chaque requête :

Authorization: Bearer bzt_...

Les jetons peuvent expirer, être révoqués par leur propriétaire ou un administrateur (Utilisateurs) et cessent de fonctionner lorsque le propriétaire est désactivé. Les actions effectuées avec un jeton apparaissent dans le journal d'audit avec le nom du jeton.

Points de terminaison

Toutes les réponses sont en JSON. URL de base : https://<console>:8443.

Méthode et cheminRôleRenvoie
GET /api/v1/statusLecteurÉtat global : agents en ligne, échecs et avertissements sur 24 h, exécutions actives, sauvegardes suspectes non examinées, "ok": true|false
GET /api/v1/agentsLecteurAgents avec système, version, état en ligne et dernier contact
GET /api/v1/jobs, GET /api/v1/jobs/{id}LecteurTâches avec planification, prochaine exécution et dernier résultat
POST /api/v1/jobs/{id}/runOpérateur de restaurationLance la tâche immédiatement : {"run_id": 123} (202), ou 409 si une exécution est déjà active
POST /api/v1/jobs/{id}/testOpérateur de restaurationLance un test de restauration de la sauvegarde la plus récente de la tâche
GET /api/v1/runs?job=&agent=&status=&limit=LecteurExécutions récentes, les plus récentes en premier (100 par défaut, 1000 au maximum)
GET /api/v1/runs/{id}LecteurUne exécution avec message, erreurs et statistiques
GET /api/v1/report?period=&from=&to=&agent=&job=LecteurLe rapport d'une période : totaux, taux de réussite et détails par tâche
GET /api/v1/targetsLecteurCibles de stockage (sans identifiants)

Périodes : today, yesterday, last7, last30, last90, thisweek, lastweek, thismonth, lastmonth, ou custom avec from=2026-09-01&to=2026-09-30.

Les erreurs renvoient {"error": "..."} avec 400 (requête invalide), 401 (jeton absent, invalide ou expiré), 403 (rôle insuffisant), 404 ou 409.

Exemples

curl

curl -sk -H "Authorization: Bearer $BZ_TOKEN" https://backup.example.local:8443/api/v1/status
curl -sk -X POST -H "Authorization: Bearer $BZ_TOKEN" https://backup.example.local:8443/api/v1/jobs/7/run

PowerShell

$h = @{ Authorization = "Bearer $env:BZ_TOKEN" }
$s = Invoke-RestMethod -Uri https://backup.example.local:8443/api/v1/status -Headers $h -SkipCertificateCheck
if (-not $s.ok) { Write-Warning "BackupZit needs attention: $($s.failed_24h) failed backups" }

N'utilisez -k / -SkipCertificateCheck qu'avec le certificat auto-signé de la console sur un réseau de confiance, ou installez le certificat de la console sur l'hôte de supervision.

Contrôle de supervision

Interrogez /api/v1/status toutes les quelques minutes et alertez lorsque ok vaut false. Pour un contrôle par tâche, utilisez /api/v1/jobs et alertez lorsque last_status vaut failed ou que last_finished est plus ancien que prévu.
