Images disque et restauration bare-metal

Une sauvegarde image capture un disque entier — table de partitions, partitions d'amorçage, système et données — afin qu'une machine puisse être remise sur un disque vide ou neuf exactement telle qu'elle était.

La sauvegarde d'image disque est disponible pour les machines Windows (volumes NTFS, disques GPT et MBR). Pour les machines Linux, utilisez une tâche Système Linux.

Créer une tâche d'image

  1. Dans Tâches de sauvegarde, choisissez Image disque.
  2. L'agent signale automatiquement ses disques. Choisissez Tous les disques pour créer l'image de chaque disque interne de la machine dans une seule tâche, ou cochez un seul disque — entier ou seulement certaines partitions (par ex. ignorer une grande partition de données déjà couverte par une tâche de fichiers).
  3. Réglez la rétention et la planification comme pour toute tâche ; une image hebdomadaire plus des sauvegardes de fichiers quotidiennes est une combinaison courante.

Tous les disques

Une tâche Tous les disques sauvegarde chaque disque interne doté d'une table de partitions dans une seule sauvegarde, y compris les disques ajoutés plus tard. Tous les volumes de tous les disques sont lus depuis un même instantané VSS, de sorte que les disques sont cohérents entre eux (par ex. une base de données sur D: avec ses journaux sur E:). Les disques USB et SD, les fichiers VHD/VHDX montés et les supports amovibles sont exclus — un disque de sauvegarde externe ne doit pas s'inclure lui-même ; choisissez un tel disque seul si vous en avez besoin. La page de l'exécution liste chaque disque avec ses partitions ; on peut parcourir et restaurer des fichiers depuis chacun. La restauration écrit un disque à la fois : dans le formulaire de restauration, choisissez le Disque de la sauvegarde et le disque cible, puis recommencez pour le disque suivant (en bare metal : restaurez d'abord le disque système, depuis l'ISO de récupération). L'agent doit être en version 0.33.7 ou plus récente ; une version plus ancienne indique qu'elle doit être mise à jour.

Seuls les blocs utilisés sont lus (table d'allocation NTFS), l'image est prise depuis un instantané VSS pour que le système en marche soit cohérent, et les blocs inchangés sont dédupliqués par rapport aux images précédentes — la deuxième image de la même machine n'envoie généralement que quelques pour cent.

Restaurer une image sur un disque

Dans l'exécution de la sauvegarde image, utilisez Restaurer cette image sur un disque :

  • Restaurer sur l’agent — la machine qui possède le disque cible. Cela peut être une machine en marche avec un disque libre, ou une machine démarrée depuis l'ISO de récupération.
  • Disque cible — doit être au moins aussi grand que la zone utilisée de l'original. Toutes ses données sont détruites.
  • Laisser ensuite le disque hors ligne — cochez cette option lorsque le disque d'origine se trouve dans la même machine, afin que Windows ne modifie pas les identifiants de disque de la copie.

Les disques GPT et MBR, l'amorçage EFI et BIOS sont pris en charge. La disposition des partitions et les identifiants sont recréés, donc le disque restauré démarre comme avant.

Restauration bare-metal avec l'ISO de récupération

  1. Dans Supports de récupération, téléchargez l'ISO de récupération (Windows). Gravez-la sur une clé USB (Rufus, mode « image DD » ou « ISO ») ou attachez-la à une machine virtuelle.
  2. Créez éventuellement un code de récupération et téléchargez recovery.json ; copiez-le dans un dossier backupzit sur la clé pour que la machine se connecte sans saisie.
  3. Démarrez la machine à restaurer depuis la clé. Elle lance l'agent en mode récupération et se connecte à la console (ou demande l'adresse du serveur et le code de récupération).
  4. La machine apparaît comme agent de récupération avec ses disques.
  5. Ouvrez la sauvegarde image dans Activité, choisissez Restaurer cette image sur un disque, sélectionnez l'agent de récupération et son disque, confirmez.
  6. Une fois l'exécution terminée, retirez la clé et redémarrez.

Restaurer sur un matériel différent

Windows ne démarre qu'avec un pilote pour le contrôleur de disque depuis lequel il s'amorce, et l'installation de Windows désactive les pilotes dont elle n'avait pas besoin. L'image d'un PC à contrôleur Intel s'arrête donc avec INACCESSIBLE_BOOT_DEVICE sur une carte AMD, un disque NVMe, dans Hyper-V ou dans une VM Proxmox. Cochez Restaurer sur un matériel différent dans le formulaire de restauration et BackupZit prépare le Windows restauré après l'écriture de l'image :

  1. Les pilotes des contrôleurs de disque courants fournis avec Windows redémarrent à l'amorçage : AHCI/SATA, NVMe, Intel RST, LSI/Broadcom/Dell PERC SAS et RAID, HPE Smart Array, Hyper-V et VMware.
  2. Des pilotes supplémentaires sont ajoutés avec DISM : les pilotes présents sur l'ISO de récupération (elle contient les pilotes VirtIO pour Proxmox/KVM) et les dossiers que vous indiquez sous Pilotes supplémentaires — par ex. les pilotes de stockage et de réseau de la nouvelle carte mère, extraits sur une clé USB (E:\Drivers ; les sous-dossiers sont parcourus).
  3. Les fichiers d'amorçage sont reconstruits pour la nouvelle machine (bcdboot).

La page de l'exécution liste les pilotes activés et ajoutés. Windows détecte les autres nouveaux périphériques au premier démarrage ; l'activation peut devoir être refaite sur un nouveau matériel. La restauration entre UEFI et BIOS hérité n'est pas possible — la cible doit démarrer de la même manière que l'original.

PC ou serveur physique vers Proxmox VE : créez une VM avec OVMF (UEFI) pour les disques GPT ou SeaBIOS pour les disques MBR, un disque VirtIO SCSI au moins aussi grand que l'original et une carte réseau VirtIO, attachez l'ISO de récupération et restaurez avec Restaurer sur un matériel différent. L'ISO de récupération reconnaît elle-même les disques et cartes réseau VirtIO.

Restaurer sur une machine virtuelle

Créez un disque de VM vide au moins aussi grand que l'original, démarrez la VM depuis l'ISO de récupération et suivez les étapes ci-dessus. C'est aussi la manière la plus simple de vérifier que vos images démarrent vraiment.
