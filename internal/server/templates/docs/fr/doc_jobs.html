Tâches de sauvegarde et planifications

Une tâche indique quoi sauvegarder sur quel agent, où le stocker, quand l'exécuter et combien de sauvegardes conserver.

Créer une tâche

  1. Allez dans Tâches de sauvegarde et remplissez Nouvelle tâche de sauvegarde.
  2. Choisissez l'agent et la cible de stockage.
  3. Choisissez quoi sauvegarder :
    • Fichiers et dossiers — un chemin par ligne tel qu'il apparaît sur l'agent, p. ex. C:\Users, D:\Data, /home, /etc.
    • Image disque — un disque entier ou des partitions choisies, restaurable sur un disque vide ou un nouveau matériel. Voir Images disque.
    • Système Linux — tous les systèmes de fichiers et la disposition des disques d'une machine Linux, restaurable sur un disque vide ou comme VM Proxmox. Voir Sauvegarde du système Linux.
    • Machines virtuelles (Proxmox VE, Hyper-V, VMware) — les VM (et conteneurs Proxmox) d'un hôte hyperviseur, sauvegardées sans agent dans les invités : par l'agent de l'hôte Proxmox ou Hyper-V, ou pour VMware ESXi par l'agent proxy de l'hôte (choisissez l'hôte ESXi dans la liste des agents). Voir Proxmox VE, Hyper-V et VMware ESXi.
    • Bases de données — SQL Server, PostgreSQL ou MySQL/MariaDB sur la machine de l'agent, avec sauvegardes des journaux pour restaurer à tout instant. Voir Bases de données.
    • NAS / partage de fichiers — un partage SMB ou NFS lu par l'agent ; voir ci-dessous.
    • Microsoft 365 — boîtes aux lettres Exchange Online, calendriers, contacts, OneDrive et sites SharePoint, lus via Microsoft Graph par n'importe quel agent ; voir Microsoft 365.
  4. Ajoutez éventuellement des exclusions, une par ligne : un motif de nom, valable dans chaque dossier (*.tmp, node_modules, Thumbs.db, *.iso), ou un chemin complet, valable pour ce seul fichier ou dossier (C:\Data\Temp, /srv/www/cache, aussi avec jokers : D:\VMs\*.iso). Sous Windows, les chemins complets ignorent la casse.
  5. Définissez Conserver les sauvegardes et la Planification, puis Créer la tâche.

Dossiers de chaque utilisateur

Sous les chemins, Pour chaque utilisateur de l'ordinateur ajoute Bureau, Documents, Téléchargements, Images ou le Profil utilisateur complet. Ils s'écrivent {users}/Documents, et l'agent retrouve les dossiers à chaque sauvegarde : C:\Users\<nom>\Documents sous Windows (aussi un dossier déplacé par OneDrive, …\OneDrive\Documents), /home/<nom>/Documents et /root/Documents sous Linux, /Users/<nom>/Documents sous macOS. Les utilisateurs ajoutés plus tard sont sauvegardés sans modifier la tâche ; les profils système (Default, Public) sont ignorés. N'importe quel dossier peut suivre {users}, p. ex. {users}/AppData/Roaming/Thunderbird.

Les chemins peuvent aussi contenir les jokers * (n'importe quels caractères dans un nom de dossier) et ? (un caractère) : D:\Projets\*\Documentation, /srv/sites/*/uploads. Sous Windows, majuscules et minuscules n'importent pas ; sous Linux et macOS, elles comptent telles qu'écrites. Un chemin {users} ou avec jokers qui ne trouve rien sur un ordinateur n'est pas une erreur : l'exécution indique Nothing matched … et n'échoue que s'il ne reste rien à sauvegarder. Il faut l'agent 0.45.0 ou plus récent. Le profil complet contient aussi des caches ; excluez-les par des chemins complets comme C:\Users\*\AppData\Local\Temp.

Une tâche pour plusieurs agents

Pour sauvegarder les mêmes dossiers sur de nombreux ordinateurs, choisissez sous Agent une option de Plusieurs agents : Tous les agents, Tous les agents Windows, Tous les agents Linux, Tous les agents macOS ou Choisir des agents… (puis cochez-les). Une telle tâche sauvegarde des fichiers et dossiers ; avec des chemins {users}, p. ex. {users}/Documents, elle couvre les documents de toute l'entreprise en une seule tâche. Les agents inscrits plus tard rejoignent la tâche automatiquement en une minute (avec Choisir des agents…, seulement ceux cochés).

Une tâche pour plusieurs agents peut aussi être une tâche Image disque — elle crée l'image de tous les disques internes de chaque agent Windows couvert (les partitions ne se choisissent pas, chaque ordinateur ayant les siennes) — ou une tâche Système Linux pour chaque agent Linux couvert. Les agents d'autres systèmes d'exploitation en sont exclus automatiquement, aussi avec Tous les agents.

Chaque agent sauvegarde dans son propre dépôt sur la cible de stockage, avec son propre historique, ses restaurations et sa rétention, comme pour une tâche à un agent. La page des tâches la liste sous Tâches pour plusieurs agents ; sa page montre chaque agent avec son dernier résultat, et Lancer la sauvegarde maintenant sur tous les agents les démarre tous. La tâche d'un agent est marquée plusieurs agents : ouvrez-la pour l'historique et les restaurations, ou désactivez-la pour mettre cet ordinateur en pause. Dossiers, planification et rétention se modifient sur la tâche pour plusieurs agents et valent pour tous ses agents ; on peut aussi y exclure des agents. Exclure des agents ou supprimer la tâche conserve leurs sauvegardes sur le stockage. Avec l'approbation à quatre yeux, exclure des agents, raccourcir la rétention, désactiver et supprimer attendent un second utilisateur.

Un agent qui ne peut pas encore exécuter la tâche est listé avec la raison, p. ex. un agent antérieur à 0.45.0 pour {users} et les jokers ; il la rejoint après sa mise à jour. De nombreux agents avec la même planification démarrent en même temps ; une fenêtre de sauvegarde ou une heure différente par tâche répartit la charge sur le stockage.

NAS et partages de fichiers (SMB, NFS)

Une tâche NAS / partage de fichiers sauvegarde un partage réseau sans rien installer sur le NAS (Synology, QNAP, TrueNAS, un serveur de fichiers Windows …). Choisissez n'importe quel agent qui atteint le partage — il lit le partage et écrit la sauvegarde — et saisissez :

  • Partage : smb://nas01/data (éventuellement avec un dossier : smb://nas01/data/Office) ou nfs://nas01/volume1/data (le chemin d'export) ;
  • pour SMB, le compte (utilisateur, domaine facultatif, mot de passe — stocké chiffré) ; vide signifie accès invité. NFS utilise l'accès de la machine de l'agent à l'export (autorisez son adresse sur le NAS) ;
  • les dossiers du partage à sauvegarder, un par ligne (vide : tout le partage), et des exclusions comme #recycle, @eaDir ou .snapshot.

À chaque exécution, l'agent connecte le partage — les agents Windows via son chemin UNC (\\nas01\data, SMB uniquement), les agents Linux en le montant en lecture seule sous /mnt/backupzit-nas (nécessite cifs-utils pour SMB, nfs-common ou nfs-utils pour NFS ; Proxmox VE a les deux) — puis le déconnecte. Les sauvegardes sont des sauvegardes de fichiers ordinaires : dédupliquées et incrémentielles, avec rétention, tâches de copie, tests de restauration, navigation et restauration de fichiers. Restaurer à l’emplacement d’origine reconnecte le partage en écriture et y réécrit les fichiers ; vous pouvez aussi restaurer dans un dossier sur n'importe quel agent, ou télécharger.

Fichiers ouverts et verrouillés (VSS)

Sous Windows, l'agent utilise le service de cliché instantané de volume : il prend un instantané cohérent du volume à un instant donné et sauvegarde à partir de celui-ci, si bien que les fichiers ouverts (PST Outlook, bases de données, documents en cours d'édition) sont sauvegardés de façon cohérente. Les applications compatibles VSS (par exemple SQL Server) écrivent leurs données sur le disque avant la prise de l'instantané.

Planifications

OptionExemple
À des heures précisesChaque jour ouvré à 22:00 ; ou à 12:00 et 18:00 tous les jours. Jusqu'à trois fois par jour, les jours cochés.
Plusieurs foisToutes les 2 heures entre 08:00 et 18:00, du lundi au vendredi. Intervalles de 15 minutes à 12 heures.
Une fois par moisLe 1er à 23:00.
Manuellement uniquementS'exécute seulement quand vous cliquez sur Lancer la sauvegarde maintenant.
Après une autre tâcheD'abord la base de données, puis le serveur de fichiers : la tâche démarre dès que la tâche choisie s'est terminée avec succès — ou après tout résultat, avec même si cette tâche a échoué. Les chaînes peuvent être plus longues (A → B → C) ; une tâche ne peut pas s'exécuter après elle-même ni en boucle.

Les heures sont dans le fuseau horaire du serveur de la console (sur l'appliance : Paramètres → Réseau → Fuseau horaire ou l'élément 9 du menu de configuration ; au départ UTC). Si un agent est hors ligne à l'heure prévue, la sauvegarde attend dans la file et démarre dès que l'agent revient. Toutes les exécutions prévues sont visibles dans le Calendrier. La date et l'heure actuelles de la console s'affichent en bas à gauche, sous le fuseau horaire.

Fenêtre de sauvegarde

Avec Fenêtre de sauvegarde : démarrer uniquement entre dans le formulaire de la tâche (p. ex. 22 à 6), les exécutions planifiées et enchaînées de la tâche ne démarrent que dans la fenêtre. Une exécution encore en attente à la fermeture de la fenêtre — par exemple parce que les tâches de la nuit ont duré plus longtemps — est annulée, pour ne pas charger le réseau et les machines pendant les heures de travail. Une exécution déjà démarrée continue ; pour arrêter les exécutions longues, utilisez la durée maximale d'une exécution (plus bas). Un démarrage manuel ignore la fenêtre. Les heures des planifications quotidiennes et mensuelles doivent se trouver dans la fenêtre.

Objectif de point de récupération (RPO)

Le RPO indique l'âge maximal de la dernière bonne sauvegarde d'une tâche, en heures — par exemple 26 pour une sauvegarde quotidienne (un jour plus une marge). Il se règle dans le formulaire de la tâche sous Objectif de point de récupération (RPO), heures. Le tableau de bord indique combien de tâches sont dans le RPO et liste chaque tâche qui l'a dépassé ; la page de la tâche affiche son état. Une notification (e-mail et chat, comme pour un échec) est envoyée une fois quand une tâche dépasse son RPO, puis à nouveau seulement après l'avoir respecté entre-temps. Contrairement à l'état de la dernière exécution, le RPO détecte aussi une planification supprimée par erreur, un agent hors ligne depuis des jours et une sauvegarde qui échoue sans cesse.

Rétention : combien de sauvegardes conserver

Un instantané est conservé si une quelconque règle le sélectionne :

  • Plus récentes — les N sauvegardes les plus récentes.
  • Quotidien — la sauvegarde la plus récente de chacun des N derniers jours ayant des sauvegardes.
  • Hebdomadaire — la sauvegarde la plus récente de chacune des N dernières semaines.
  • Mensuel — la sauvegarde la plus récente de chacun des N derniers mois.

Exemple : 3 récentes, 7 quotidiennes, 4 hebdomadaires, 6 mensuelles conservent environ six mois d'historique avec ~20 points de restauration. Après chaque exécution réussie, les instantanés qui ne sont plus sélectionnés sont supprimés (affichés comme expiré dans Activité) et les données qu'aucun instantané n'utilise plus sont effacées du stockage. Que des zéros conserve tout.

Grâce à la déduplication, une longue rétention coûte peu : les données inchangées ne sont stockées qu'une fois, quel que soit le nombre d'instantanés qui y font référence.

Tâches de copie de sauvegarde (3-2-1)

Une tâche de copie de sauvegarde copie les sauvegardes d'une autre tâche vers une seconde cible de stockage — par exemple des sauvegardes nocturnes vers le NAS du bureau, copiées vers S3 ou un dépôt renforcé hors site. Choisissez Copie de sauvegarde dans le formulaire de tâche, sélectionnez la tâche à copier et le stockage de destination.

  • L'agent de la tâche source effectue la copie ; la machine protégée n'est pas relue.
  • Seules les données qui ne sont pas encore à destination sont transférées, rechiffrées avec la clé de la destination.
  • La planification Après chaque sauvegarde de la tâche source (par défaut) maintient la copie à jour ; toute planification normale fonctionne aussi, p. ex. une fois par nuit pour une ligne internet lente.
  • La copie a sa propre rétention, p. ex. 7 quotidiennes sur le NAS et 12 mensuelles dans le cloud.
  • Les sauvegardes de fichiers et de VM copiées (Proxmox VE, Hyper-V, VMware) se restaurent depuis la page de l'exécution de copie ou l'assistant de restauration, comme les originaux — VM entières, fichiers individuels des disques de VM et restauration instantanée Proxmox. Les sauvegardes de VM copiées par un agent antérieur à 0.29 ne peuvent pas être restaurées ainsi ; la prochaine exécution de copie avec un agent plus récent rend sa copie la plus récente restaurable. Les copies d'images disque se restaurent avec l'agent en ligne de commande.

Modifier une tâche

Ouvrez la tâche et cliquez sur Modifier ; le formulaire s'ouvre sur une page à part, qui ne se recharge pas pendant une sauvegarde. Vous pouvez changer le nom, les dossiers et exclusions (tâches de fichiers), les VM (tâches de VM), la planification, la rétention, la limite de débit, le niveau de compression et les commandes. L'agent, la cible de stockage et le disque d'une tâche d'image restent inchangés, afin que les sauvegardes de la tâche forment une seule chaîne ; pour déplacer une tâche, créez-en une nouvelle — avec une tâche de copie si les anciennes sauvegardes doivent suivre. Les modifications s'appliquent dès l'exécution suivante et sont consignées dans le journal d'audit. Avec l'approbation à quatre yeux activée, une rétention plus courte attend l'approbation d'un second utilisateur ; les autres modifications sont enregistrées immédiatement.

Réplicas (Proxmox VE)

Les tâches de VM Proxmox peuvent maintenir des copies arrêtées et à jour de leurs invités sur un nœud de votre choix, démarrées en un clic si un invité est perdu — voir Proxmox VE → Réplication.

Limite de débit

Sous Avancé dans le formulaire de tâche, Limiter le débit d’envoi à plafonne la vitesse à laquelle l'agent envoie les données au stockage, en Mo/s — par exemple 10 Mo/s de 08:00 à 18:00, pour que les sauvegardes pendant les heures de travail laissent la ligne du bureau utilisable ; en dehors de la plage, la tâche tourne à pleine vitesse. Les heures sont l'heure locale de l'agent, et une plage peut passer minuit (22:00 à 06:00). La limite s'applique aux sauvegardes et aux tâches de copie (l'envoi vers le second stockage), pas aux restaurations : une restauration tourne toujours à pleine vitesse.

Compression et déduplication

Chaque sauvegarde est dédupliquée : les données déjà présentes dans le dépôt — issues de sauvegardes antérieures de la même tâche ou d'autres tâches sur la même cible de stockage — ne sont pas stockées à nouveau. Les nouvelles données sont ensuite compressées avec zstd ; les morceaux qui ne rapetissent pas (vidéo, archives, fichiers chiffrés) sont stockés tels quels. Le chiffrement intervient après la compression.

Le niveau de compression est un réglage de la tâche (Modifier → Avancé) :

NiveauQuand l'utiliser
Standard (recommandé)Bonne compression à grande vitesse ; convient à presque toutes les tâches.
RapideUtilise moins de CPU sur les machines chargées ou peu puissantes ; les sauvegardes sont un peu plus grosses.
MaximaleGénéralement 5–15 % plus petite que Standard, mais plusieurs fois plus lente à compresser. Pour les liaisons lentes et le stockage cloud payant, quand la machine a du CPU disponible.
DésactivéPour des données déjà compressées : économise du CPU sans grossir les sauvegardes.

Le niveau s'applique aux nouvelles données dès l'exécution suivante ; les sauvegardes existantes restent telles quelles, et la restauration n'en dépend jamais. La page de l'exécution montre le résultat : le taux de compression des nouvelles données (p. ex. 2.4×) et la part des données lues qui était déjà stockée (déduplication).

Commandes avant et après la sauvegarde

Les administrateurs peuvent faire exécuter par une tâche une commande sur l'agent avant et après chaque sauvegarde — par exemple un dump de base de données, l'arrêt d'un service pour une copie cohérente, ou une notification :

pg_dump -U postgres app > /var/backups/app.sql          # Linux, before
sqlcmd -S . -Q "BACKUP DATABASE app TO DISK='D:\dump\app.bak'"   # Windows, before
  • Les commandes s'exécutent sous le compte de service de l'agent (root sous Linux, SYSTEM sous Windows) avec sh ou cmd ; plusieurs lignes sont permises. Seuls les Administrateurs peuvent les voir et les modifier — sinon un opérateur de sauvegarde pourrait exécuter n'importe quoi sur chaque machine.
  • Si la commande avant échoue (code de sortie différent de 0) ou dure plus que le délai (30 minutes par défaut), la sauvegarde n'est pas lancée et l'exécution échoue avec la sortie de la commande.
  • La commande après s'exécute aussi quand la sauvegarde a échoué, pour pouvoir redémarrer ce que la première a arrêté. Une commande après la sauvegarde qui échoue transforme l'exécution en avertissement.
  • Les deux reçoivent BACKUPZIT_STAGE (pre ou post), BACKUPZIT_JOB, BACKUPZIT_JOB_ID, BACKUPZIT_RUN_ID et, après la sauvegarde, BACKUPZIT_STATUS (success, warning ou failed).
  • La page de l'exécution affiche le résultat et la sortie de chaque commande, même en cas de succès.
  • Pour les tâches de VM, les commandes s'exécutent sur l'hôte hyperviseur (ou le proxy VMware), pas dans les VM. Les tâches de copie n'ont pas de commandes.

Exécuter, désactiver, supprimer

  • Lancer la sauvegarde maintenant (Copier maintenant pour les tâches de copie) met la tâche en file immédiatement.
  • Tester la restauration restaure un échantillon aléatoire de la sauvegarde la plus récente et le vérifie (voir Restauration).
  • Désactiver suspend la planification sans perdre la tâche (avec l'approbation à quatre yeux, un second utilisateur doit approuver).
  • Supprimer retire la tâche ; les sauvegardes existantes restent sur le stockage et restent restaurables depuis Activité.

Arrêter une exécution

Une sauvegarde, copie ou restauration en attente ou en cours peut être arrêtée avec Annuler ou Arrêter l'exécution sur la page de l'exécution, ou Arrêter l'exécution n°… sur la page de la tâche. Une exécution en attente est annulée aussitôt ; une exécution en cours est arrêtée par l'agent en quelques secondes — la commande avant la sauvegarde est aussi interrompue, la commande après la sauvegarde s'exécute quand même. L'exécution prend l'état annulée (message « Cancelled by » et le nom de l'utilisateur) : elle ne compte pas comme un échec dans les rapports, n'envoie aucun e-mail d'échec et est consignée dans le journal d'audit. Une sauvegarde interrompue n'est pas utilisée pour les restaurations. Les mises à jour d'agent ne peuvent pas être arrêtées.

Pour tout arrêter d'un coup, utilisez Annuler tout ce qui est en attente ou en cours en haut de Activité et confirmez. Seules les exécutions listées comme en attente ou en cours à ce moment sont annulées (celles en cours s'arrêtent en quelques secondes) ; les exécutions planifiées plus tard aujourd'hui ou d'autres jours, et les tâches enchaînées, démarrent comme prévu.

Durée maximale d'une exécution (heures), sous Avancé dans le formulaire de la tâche, arrête une sauvegarde ou copie de la tâche qui dure plus longtemps et la marque en échec ; dans ce cas, la notification d'échec est envoyée. Vide ou 0 signifie aucune limite. Si l'agent ne confirme pas l'arrêt sous 10 minutes, la console marque elle-même l'exécution en échec.

Rétention suspendue

Si une sauvegarde de la tâche ressemblait à un rançongiciel ou à une suppression massive, la page de la tâche affiche La rétention est suspendue : aucune sauvegarde n'est supprimée tant que quelqu'un n'a pas vérifié la machine et cliqué sur Examiné — reprendre la rétention (avec l'approbation à quatre yeux, un second utilisateur doit approuver). Voir Protection contre les rançongiciels.

Ce que rapporte une exécution de sauvegarde

Ouvrez une exécution dans Activité : nombre de fichiers, fichiers nouveaux/modifiés, données lues, nouvelles données envoyées (après déduplication et compression, avec le taux de compression et la part déjà stockée — voir Compression), durée, et les fichiers qui n'ont pas pu être lus. Une exécution avec des fichiers illisibles se termine avec l'état avertissement — le reste des données est sauvegardé.
