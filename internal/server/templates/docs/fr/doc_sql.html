Bases de données : SQL Server, PostgreSQL, MySQL

BackupZit sauvegarde les bases de données avec les outils propres au serveur de base de données, depuis l'agent installé sur la machine de la base : Microsoft SQL Server sous Windows, PostgreSQL et MySQL/MariaDB sous Linux. Les sauvegardes complètes suivent la planification de la tâche ; des sauvegardes de journaux toutes les quelques minutes permettent de restaurer une seule base à n'importe quel instant — par exemple une minute avant un DELETE erroné.

Créer une tâche

Dans Tâches de sauvegarde, créez une tâche du type Bases de données sur l'agent de la machine de la base, et choisissez :

  • Serveur de base de données : Microsoft SQL Server, PostgreSQL ou MySQL/MariaDB. Il ne peut pas être modifié ensuite.
  • Instance ou port : l'instance SQL Server (vide pour l'instance par défaut, par ex. SQLEXPRESS) ou le port PostgreSQL (vide pour 5432). MySQL/MariaDB est joint via le socket local.
  • Bases de données : un nom par ligne, ou vide pour toutes les bases utilisateur — les bases créées plus tard sont incluses automatiquement.
  • Sauvegarder les journaux toutes les … minutes : par ex. 15 — journaux de transactions (SQL Server), WAL archivés (PostgreSQL) ou journaux binaires (MySQL). Laissez vide si restaurer à l'heure d'une sauvegarde complète suffit.
  • La planification est celle des sauvegardes complètes, par ex. tous les jours à 22:00.

Les sauvegardes sont dédupliquées — les données inchangées ne sont pas renvoyées — et chiffrées comme toute sauvegarde. La rétention compte les sauvegardes complètes ; les sauvegardes de journaux sont conservées aussi longtemps que la sauvegarde complète sur laquelle elles reposent. La page de l'exécution indique ce que contient chaque sauvegarde.

Microsoft SQL Server

  1. Installez l'agent sur la machine Windows qui exécute SQL Server (toute édition à partir de 2012, y compris Express).
  2. L'agent tourne sous NT AUTHORITY\SYSTEM et se connecte avec l'authentification Windows. Donnez à ce compte le rôle sysadmin, une fois par instance : 
    sqlcmd -S .\SQLEXPRESS -E -Q "ALTER SERVER ROLE sysadmin ADD MEMBER [NT AUTHORITY\SYSTEM]"
  • Chaque exécution écrit un fichier de sauvegarde par base (BACKUP DATABASE / BACKUP LOG … WITH CHECKSUM) dans le dossier de sauvegarde par défaut de l'instance, stocke les fichiers puis les supprime. Le dossier a besoin, pendant l'exécution, d'espace libre pour la plus grande base.
  • Avec les sauvegardes de journaux activées, les sauvegardes complètes démarrent la chaîne de journaux. Sans elles, les sauvegardes complètes sont prises en COPY_ONLY, afin de ne pas perturber d'autres plans de sauvegarde ou de maintenance.
  • Les sauvegardes de journaux sont prises pour les bases en mode de récupération full ou bulk-logged ; les bases en mode simple n'ont que des sauvegardes complètes. Cochez bases système pour ajouter master, model et msdb.

PostgreSQL

L'agent travaille sous le compte postgres via le socket local — rien à configurer pour les sauvegardes. Une sauvegarde complète stocke tout le cluster (pg_basebackup), les rôles (pg_dumpall --globals-only) et un pg_dump de chaque base.

La restauration à un instant précis nécessite l'archivage des WAL. Avec les sauvegardes de journaux activées, la première sauvegarde complète le configure avec ALTER SYSTEM : archive_mode = on et un archive_command qui copie les segments WAL terminés dans /var/lib/backupzit-pg/wal ; les sauvegardes de journaux les y stockent puis les suppriment. archive_mode prend effet après un redémarrage de PostgreSQL (systemctl restart postgresql) — l'exécution vous le signale. Si un autre outil utilise déjà archive_command, BackupZit n'y touche pas et sauvegarde sans restauration à un instant précis. Si les sauvegardes de journaux s'arrêtent (tâche désactivée ou supprimée), désactivez à nouveau l'archivage (ALTER SYSTEM RESET archive_mode, redémarrage) pour que le dossier ne se remplisse pas.

  • Restaurer une base de données dans l'état de la sauvegarde complète : depuis son pg_dump vers le serveur en marche, sous un nouveau nom ou en remplaçant la base.
  • À un instant précis (ou le plus récent) : l'agent décompresse la sauvegarde du cluster dans une instance temporaire sur un port libre (socket uniquement, sans réseau, sans archivage), rejoue les WAL jusqu'à cet instant, en extrait la base vers le serveur en marche et supprime l'instance temporaire. La machine a besoin pendant un moment d'espace libre pour le cluster.
  • Cluster entier : restauré de la même manière en tant qu'instance séparée qui continue de tourner sur un port libre ; l'exécution vous indique son port et son répertoire de données (sous /var/lib/backupzit-pg) ainsi que la façon de s'y connecter et de l'arrêter.

MySQL et MariaDB

L'agent se connecte en tant que root via le socket local (authentification par socket, par défaut sous Debian et Ubuntu), ou avec les identifiants de /root/.my.cnf. Une sauvegarde complète stocke un mysqldump de chaque base (cohérent, avec routines, événements et déclencheurs) ainsi que la position du journal binaire correspondante.

La restauration à un instant précis nécessite le journal binaire. Activez-le une fois dans la configuration du serveur et redémarrez le serveur, par ex. /etc/mysql/mariadb.conf.d/60-binlog.cnf :

[mysqld]
server_id = 1
log_bin = /var/log/mysql/mysql-bin
binlog_format = ROW
expire_logs_days = 7

(créez le dossier du journal, avec le compte mysql comme propriétaire). Les sauvegardes de journaux stockent ensuite chaque journal binaire fermé. Gardez la durée d'expiration propre au serveur plus longue que l'intervalle des sauvegardes de journaux ; un trou est signalé, et les restaurations ne peuvent pas le franchir.

  • Restaurer une base de données : son dump est chargé dans une nouvelle base (ou remplace une base existante). À un instant précis ou le plus récent : les modifications de cette base enregistrées dans les journaux binaires après le dump sont rejouées jusqu'à cet instant — y compris quand la base reçoit un nouveau nom. Le rejeu n'est pas écrit dans le journal binaire du serveur.
  • Les utilisateurs et privilèges (la base système mysql) ne font pas partie des dumps.

Restauration

Ouvrez une exécution de sauvegarde complète (ou utilisez l'assistant de restauration → Base de données) et choisissez la base, la machine de restauration (le même serveur ou un autre avec le même serveur de base de données) et :

  • En tant que nouvelle base nommée par ex. sales_restored — l'original reste intact et vous pouvez recopier des lignes — ou sous son nom d'origine ; cochez la remplacer pour écraser une base existante (ses utilisateurs sont d'abord déconnectés).
  • État : celui de la sauvegarde complète ; l'état le plus récent (la sauvegarde complète et chaque sauvegarde de journaux suivante) ; ou un instant précis entre la sauvegarde complète et la plus récente sauvegarde de journaux utilisable, comme l'indique le tableau. Saisissez l'heure telle que la console l'affiche, dans le fuseau horaire du serveur de la console (voir Fuseau horaire) ; l'agent la convertit dans le fuseau horaire du serveur de base de données.

Ligne de commande

backupzit-agent sql list    [--instance SQLEXPRESS]
backupzit-agent sql backup  --repo ... [--instance I] [--db a,b] [--system] [--log] [--copy-only]
backupzit-agent sql restore --repo ... [--instance I] --db NAME [--as NEW] [--replace] [--at "2026-10-04 14:59:00"] SNAPSHOT|latest
backupzit-agent pg list     [--port 5432]
backupzit-agent pg backup   --repo ... [--port P] [--db a,b] [--pitr | --wal]
backupzit-agent pg restore  --repo ... --db NAME|"(cluster)" [--as NEW] [--replace] [--at TIME | --latest] SNAPSHOT|latest
backupzit-agent mysql list
backupzit-agent mysql backup  --repo ... [--db a,b] [--binlog]
backupzit-agent mysql restore --repo ... --db NAME [--as NEW] [--replace] [--at TIME | --latest] SNAPSHOT|latest

Non inclus

  • Les sauvegardes différentielles SQL Server et les groupes de disponibilité Always On ; les serveurs de base de données distants — l'agent sauvegarde les serveurs de sa propre machine.
  • La restauration de tables individuelles : restaurez la base sous un nouveau nom et copiez les lignes.
