Agents

Un agent est installé sur chaque machine protégée. Il fonctionne comme un service, demande du travail à la console toutes les 30 secondes et communique directement avec le stockage.

Systèmes pris en charge

  • Windows 10, 11 et Windows Server 2016 et plus récents — MSI Agent Windows.
  • Windows 7 SP1, Windows Server 2008 R2 SP1 et 2012 R2 — MSI Agent Windows — anciens systèmes (…-legacy.msi), avec les mêmes fonctions, y compris VSS et images disque.
  • Debian, Ubuntu, AlmaLinux, Rocky Linux (64 bits).
  • Nœuds Proxmox VE 7 et 8 — le paquet Debian ; l'agent sauvegarde alors aussi les VM et conteneurs du nœud (voir Proxmox VE).
  • Hôtes Hyper-V (Windows Server 2016 et plus récents, Windows 10/11 avec Hyper-V) : le MSI Windows. L'agent sauvegarde alors aussi les VM de l'hôte (voir Hyper-V).
  • Hôtes VMware ESXi — rien n'est installé sur ESXi : ajoutez l'hôte sous Hôtes VMware ESXi et choisissez un agent comme proxy (voir VMware ESXi).

Inscrire des agents

  1. Sur la page Agents, cliquez sur Créer un jeton d’inscription. La console affiche un code d’inscription (BZ1-…), valable 7 jours et utilisable pour un nombre quelconque de machines. Il contient l'adresse de la console pour les agents (avec le port des agents, généralement 8443, même lorsque la page est ouverte sur le port web 443), le jeton et l'empreinte du certificat. Les agents à partir de 0.33.6 s'inscrivent aussi avec des codes créés par des consoles plus anciennes sur le port web.
  2. Windows : lancez le MSI et collez le code quand l'installateur le demande. Linux : exécutez la commande affichée.
  3. La machine apparaît dans la liste des agents en moins d'une minute.

Si la console est injoignable pendant l'installation, l'agent garde le code et réessaie jusqu'à pouvoir s'inscrire. Les mises à niveau conservent l'inscription et ne redemandent rien. Une installation silencieuse avec ENROLLCODE sur une machine déjà inscrite conserve l'inscription quand le code est pour la même console (GPO ou RMM peuvent la répéter sans risque), et déplace la machine quand le code est pour une autre console ; l'inscription précédente est conservée sous agent.json.replaced-date à côté de agent.json, si bien que la renommer ramène la machine vers son ancienne console comme le même agent.

Windows, silencieux (GPO, Intune, RMM)

msiexec /i backupzit-agent.msi /qn ENROLLCODE="BZ1-..."

L'ancienne forme SERVER="..." TOKEN="..." FINGERPRINT="SHA256:..." fonctionne toujours. Une installation silencieuse sans ces propriétés installe le service, qui attend que vous l'inscriviez avec backupzit-agent enroll --code "BZ1-..." dans une invite administrateur.

Linux

apt install ./backupzit-agent_*.deb        # or: dnf install ./backupzit-agent-*.rpm
backupzit-agent enroll --code "BZ1-..."
systemctl enable --now backupzit-agent

Installer des agents depuis la console

Au lieu de copier les installateurs sur chaque machine, laissez la console installer l'agent : sur Agents, ouvrez Installer sur une machine depuis ici, choisissez Linux ou Windows et saisissez l'adresse de la machine et un compte administrateur.

  • Linux (Debian, Ubuntu, AlmaLinux, Rocky Linux ; 64 bits) : la console se connecte en SSH en tant que root, ou en tant qu'utilisateur disposant des droits sudo (le mot de passe sert aussi pour sudo ; avec une clé, sudo sans mot de passe est nécessaire). Un mot de passe ou une clé privée fonctionne. Saisissez l'empreinte de la clé d'hôte SSH de la machine (ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub sur la machine) pour vous assurer que la console parle à la bonne machine ; sans elle, l'empreinte s'affiche dans le journal d'installation.
  • Windows (64 bits) : la console se connecte via WinRM (port 5985, messages chiffrés avec NTLM ; 5986 pour un écouteur HTTPS) en tant qu'administrateur local ou de domaine. WinRM est activé par défaut sur Windows Server ; sur Windows 10/11, exécutez une fois winrm quickconfig en administrateur. Les comptes locaux autres que l'Administrateur intégré ont besoin des droits d'administration à distance (LocalAccountTokenFilterPolicy) — ou utilisez un compte de domaine. Les anciens systèmes (Windows 7, Server 2008 R2/2012 R2) reçoivent le MSI legacy.

La machine télécharge le paquet d'agent le plus récent depuis la console via un lien valable uniquement pour cette installation (30 minutes, trois téléchargements), vérifie sa somme SHA-256, l'installe et s'inscrit. La page d'installation montre chaque étape ; le compte et le mot de passe ne servent qu'à cela et ne sont pas enregistrés. Si la machine est déjà inscrite auprès de cette console, l'inscription est conservée et le paquet mis à jour ; une inscription que la console ne connaît pas (un agent supprimé auparavant, ou une autre console) est remplacée. Chaque installation figure dans le journal d'audit. La machine doit joindre l'adresse agents de la console, comme tout agent.

État de l'agent

  • online — l'agent a contacté la console au cours des 3 dernières minutes.
  • offline — la machine est éteinte, le service arrêté ou le réseau bloqué. Les sauvegardes planifiées sont mises en file d'attente et démarrent dès que l'agent revient.
  • récupération — une machine démarrée depuis une ISO de récupération (Windows ou Linux), prête à recevoir la restauration d'une image disque ou d'un système Linux. Les agents de récupération sont temporaires ; supprimez-les une fois la restauration terminée.

La colonne Adresses IP liste les adresses propres de la machine telles que l'agent les a signalées en dernier. vu depuis est l'adresse d'où arrivent ses connexions : sur un réseau local la même adresse, pour une machine derrière un NAT (p. ex. un portable à la maison) l'adresse publique du routeur. La console n'interroge aucun service externe pour cela.

L'agent sur le bureau (Windows)

L'agent Windows affiche une icône à côté de l'horloge (elle peut se trouver sous la flèche ^ des icônes masquées — faites-la glisser sur la barre des tâches pour qu'elle reste visible). Le point sur l'icône indique l'état :

PointSignification
vertLes sauvegardes vont bien (ou attendent la première sauvegarde planifiée).
bleuUne sauvegarde, une restauration ou un test de restauration est en cours.
orangeLa dernière sauvegarde s'est terminée avec des avertissements (fichiers illisibles).
rougeUne tâche de sauvegarde a échoué.
grisLa console est injoignable ou le service de l'agent ne tourne pas.

Cliquez sur l'icône (ou ouvrez BackupZit Agent depuis le menu Démarrer) pour la fenêtre d'état : état de protection, progression d'une sauvegarde en cours, dernière et prochaine sauvegarde, et toutes les tâches de sauvegarde de l'ordinateur avec Sauvegarder maintenant. Un clic droit ouvre le menu : Back up now par tâche, Open console in browser, Hide this icon (jusqu'à la prochaine connexion ; les sauvegardes continuent). La fenêtre nécessite Microsoft Edge WebView2, inclus dans Windows 10 et 11 ; sur les anciens systèmes, l'icône et le menu fonctionnent et Open affiche la console dans le navigateur.

Les utilisateurs peuvent ainsi lancer une sauvegarde de leur ordinateur ; les tâches, planifications et rétention se règlent uniquement dans la console. Sur tout système, backupzit-agent status (en administrateur ou root) affiche les mêmes informations.

Mise à niveau

Quand la console dispose d'un installateur d'agent plus récent que celui d'un agent, la page Agents affiche Mettre à jour vers x.y.z à côté de sa version, et Mettre à jour tous les agents sous la liste. L'agent alors :

  1. attend d'être inactif (une sauvegarde en cours n'est jamais interrompue),
  2. télécharge l'installateur correspondant depuis la console via sa connexion épinglée — le MSI pour Windows 10/11/2016+, le MSI anciens systèmes pour Windows 7/2008 R2/2012 R2, le paquet deb ou rpm sous Linux — et vérifie son SHA-256,
  3. l'installe et redémarre ; la nouvelle version apparaît dans la liste en quelques minutes. L'inscription et tous les réglages sont conservés.

La console propose les installateurs les plus récents de son répertoire dist ; le paquet serveur fournit les installateurs d'agent de sa propre version. Après la mise à jour de la console depuis Paramètres → Mises à jour, les agents sont mis à jour automatiquement (désactivable à cet endroit). Les mises à jour depuis la console fonctionnent pour les agents à partir de la version 0.21 ; les agents plus anciens sont mis à jour une fois en installant le MSI / paquet plus récent par-dessus l'ancien (l'inscription est conservée). Le journal de l'installateur se trouve dans C:\ProgramData\backupzit\updates ou /var/tmp/backupzit-updates.

Supprimer un agent

Supprimer sur la page Agents efface l'agent et ses tâches de la console. Avec l'approbation à quatre yeux activée, un second utilisateur doit d'abord l'approuver. Les sauvegardes sur le stockage ne sont pas supprimées. Désinstallez le logiciel sur la machine séparément.

Deux machines utilisant un même agent

Une copie d'une machine inscrite emporte son agent et son inscription : une VM restaurée comme nouvelle VM, une restauration instantanée, un réplica démarré, un disque ou un modèle cloné. Quand la copie tourne à côté de l'original, les deux se connectent comme le même agent. La console le remarque en une ou deux minutes, puis :

  • affiche deux machines avec les deux noms et adresses sur la page Agents, et l'agent sous Nécessite votre attention dans le tableau de bord ;
  • met en attente les sauvegardes et restaurations de l'agent, pour que rien ne s'exécute sur la mauvaise machine (une restauration à l'emplacement d'origine pourrait sinon écraser la copie au lieu de l'original) ;
  • envoie une fois un e-mail aux administrateurs et écrit une entrée agent.duplicate dans le journal d'audit.

Arrêtez la copie ou — si elle doit rester — inscrivez-la comme nouvelle machine sur la copie : backupzit-agent enroll --force --code "BZ1-..." (code de la page Agents). Les exécutions en attente démarrent quelques minutes après qu'il ne reste qu'une machine. La restauration d'un système Linux avec Restaurer tout le système désinscrit déjà l'agent dans la copie restaurée, et les tests de restauration démarrent leurs VM sans réseau, donc ni l'un ni l'autre ne provoque cette situation.

Quand la console change d'adresse

Les agents font confiance à la console grâce à son certificat, qui reste le même quand son adresse IP ou son nom change, mais ils se connectent à l'adresse avec laquelle ils ont été inscrits. Après un changement, exécutez sur chaque machine agent (en administrateur / root) :

backupzit-agent set-server https://192.168.1.20:8443

La commande vérifie que la console répond à la nouvelle adresse avec le même certificat, l'enregistre, et l'agent l'utilise après un redémarrage de son service (systemctl restart backupzit-agent, ou redémarrez le service BackupZit Agent sous Windows). Utiliser dès le départ un nom DNS pour la console évite cette étape.

Où l'agent garde sa configuration

  • Windows : C:\ProgramData\backupzit\agent.json (accessible uniquement à SYSTEM et aux Administrateurs).
  • Linux : /etc/backupzit/agent.json (root uniquement).

Le fichier contient le secret de l'agent. Quiconque peut le lire peut agir en tant que cet agent ; conservez donc ces permissions.

Journal de l'agent

  • Windows : C:\ProgramData\backupzit\agent.log
  • Linux : /etc/backupzit/agent.log et journalctl -u backupzit-agent
  • Les systèmes de récupération affichent le journal à l'écran.

Désinstallation

Windows : Paramètres → Applications → BackupZit Agent → Désinstaller (ou msiexec /x). Linux : apt remove backupzit-agent / dnf remove backupzit-agent. Supprimez ensuite l'agent dans la console. Les sauvegardes restent sur le stockage.

Sous Windows, la désinstallation met l'inscription de côté (C:\ProgramData\backupzit\agent.json.removed-date), si bien qu'une nouvelle installation de l'agent demande un code d'inscription. Si l'installateur trouve une inscription d'une version antérieure, il le signale : laissez le code vide pour la conserver, ou collez un nouveau code pour inscrire à nouveau l'ordinateur (par exemple auprès d'une autre console).
