Sauvegarde du système Linux et P2V

Une tâche Système Linux sauvegarde une machine Linux entière afin de pouvoir la recréer sur un disque vide — la même machine après une panne de disque, un nouveau matériel ou une machine virtuelle dans Proxmox VE (physique vers virtuel, P2V).

Ce qui est sauvegardé

  • Chaque système de fichiers local (ext2/3/4, xfs, vfat), y compris sur LVM, fichier par fichier avec propriétaires, permissions, bits setuid, ACL, attributs étendus (étiquettes SELinux, capacités de fichiers), liens physiques et fichiers de périphériques. Chaque système de fichiers est sauvegardé séparément ; les partages réseau et les systèmes de fichiers virtuels (/proc, /sys, /run) sont ignorés.
  • La disposition des disques : tables de partitions GPT ou MBR avec leurs identifiants, groupes de volumes LVM (vgcfgbackup), UUID, étiquettes et fonctionnalités des systèmes de fichiers, et le code d'amorçage (MBR et partition d'amorçage BIOS de GRUB).

Comme Relax-and-Recover, BackupZit ne copie pas le disque en cours d'utilisation bloc par bloc : Linux n'a pas d'instantané intégré d'un disque en marche, une copie brute serait donc incohérente. Chaque fichier est lu en entier, et la disposition rend le disque restauré à nouveau amorçable. Les bases de données doivent être exportées avant la sauvegarde ou sauvegardées avec leurs propres outils.

Les fichiers et dossiers individuels se restaurent depuis une sauvegarde système comme depuis toute sauvegarde de fichiers (Restaurer des fichiers depuis cette sauvegarde sur la page de l'exécution).

Pas encore pris en charge

Disques chiffrés (LUKS), RAID logiciel (mdadm), btrfs et systèmes répartis sur plusieurs disques. La tâche les signale clairement au lieu de créer une sauvegarde incomplète.

Restaurer le système entier

Ouvrez l'exécution de la sauvegarde système (page de la tâche ou Activité) et utilisez Restaurer tout le système :

En tant que nouvelle VM Proxmox

Choisissez le nœud Proxmox (son agent BackupZit fait le travail), le stockage, l'ID de VM, le nom, la mémoire et les cœurs. BackupZit crée la VM avec le même micrologiciel que l'original (UEFI/OVMF ou BIOS), un disque et une carte réseau VirtIO SCSI, recrée le disque, restaure tous les fichiers et peut démarrer la VM. Comme la VM est une copie qui peut tourner à côté de l'original :

  • les paramètres réseau liés aux anciennes adresses MAC (courants dans les images cloud : netplan match: macaddress) sont modifiés pour s'appliquer à toute interface filaire,
  • l'agent BackupZit de la copie est désinscrit, afin qu'il ne se présente pas comme la machine d'origine.

Sur un disque

Restaurez sur un disque vide d'un agent Linux, par ex. un second disque (/dev/sdb), ou sur la nouvelle machine elle-même (bare metal) :

  1. Dans Récupération, téléchargez l'ISO de récupération Linux et créez un code de récupération. Écrivez l'ISO sur une clé USB (Rufus, balenaEtcher) ou attachez-la à une VM. Elle démarre sur les machines BIOS et UEFI.
  2. Démarrez la machine dessus. Le système de récupération lance l'agent, qui se connecte à la console avec backupzit/recovery.json présent sur une autre clé USB ou un autre disque, ou demande l'adresse du serveur et le code de récupération.
  3. La machine apparaît comme agent de récupération. Dans l'exécution de la sauvegarde système, choisissez Sur un disque, cet agent et son disque (généralement /dev/sda, /dev/nvme0n1 ou /dev/vda).

Tout système Linux live convient aussi : lancez-y l'agent avec sudo backupzit-agent recovery --server https://console:8443 --token CODE ; les outils nécessaires (gdisk, LVM, mkfs) sont nommés s'ils manquent. Cochez Matériel différent lorsque la machine n'est pas l'originale.

La cible peut être plus grande ou plus petite que le disque d'origine : la dernière partition s'agrandit pour la remplir, ou se réduit tant que ses données tiennent. Les UUID des systèmes de fichiers et les identifiants de partitions restent identiques, donc /etc/fstab et le chargeur d'amorçage n'ont pas besoin de modifications. Pour les systèmes UEFI, le chargeur d'amorçage est aussi installé au chemin des supports amovibles \EFI\BOOT\BOOTX64.EFI, que tout micrologiciel UEFI démarre sans entrée d'amorçage. Les systèmes de type RHEL (dracut) reçoivent un nouvel initramfs avec tous les pilotes lorsqu'ils sont déplacés vers un matériel différent.

Ligne de commande

backupzit-agent system-backup  --repo ... [--exclude PATTERN]
backupzit-agent system-show    --repo ... latest
backupzit-agent system-restore --repo ... --target /dev/sdb [--new-hardware] --yes-erase-target latest
