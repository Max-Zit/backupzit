Dépannage et FAQ

Un agent apparaît hors ligne

  • La machine est-elle allumée et le service tourne-t-il ? Windows : Get-Service backupzit-agent ; Linux : systemctl status backupzit-agent.
  • La machine atteint-elle la console ? Test-NetConnection backup-server -Port 8443 ou curl -k https://backup-server:8443/login.
  • Journal de l'agent : C:\ProgramData\backupzit\agent.log, sous Linux /etc/backupzit/agent.log ou journalctl -u backupzit-agent. « fingerprint mismatch » signifie que le certificat de la console a changé — inscrivez à nouveau l'agent.

Une sauvegarde a échoué

Ouvrez l'exécution dans Activité ; le message indique la cause. Causes fréquentes :

Le message contientSolution
host key mismatch / fingerprintLa clé du serveur SFTP a changé ou l'empreinte a été mal saisie. Vérifiez avec ssh-keygen -lf sur le serveur.
permission denied / access deniedIdentifiants du stockage ou droits sur le dossier. Testez la connexion avec un client SFTP/SMB.
no space left / quotaLe stockage est plein. Réduisez la rétention ou ajoutez de l'espace ; les sauvegardes expirées libèrent de l'espace après l'exécution suivante.
repository is lockedUne autre opération (par ex. un nettoyage) tourne sur le même dépôt ; l'exécution réessaie pendant 30 minutes. Les verrous obsolètes expirent automatiquement.
wrong password / recovery keyLe dépôt a été créé avec une autre clé — vérifiez que la tâche utilise la bonne cible de stockage.
bucket has no Object Lock enabledL'immuabilité a été demandée sur un bucket créé sans Object Lock. Créez un nouveau bucket avec Object Lock.

Let's Encrypt : « could not verify … is port 80 … reachable »La vérification HTTP nécessite que le port 80 soit joignable depuis Internet. Pour les consoles internes, utilisez la vérification DNS via Cloudflare.

Mises à jour : « updates from the console need the Linux package of the console »La console n'a pas été installée depuis le paquet deb/rpm (par exemple en mode d'évaluation). Mettez-la à jour de la même manière qu'elle a été installée.
Mises à jour : « the release is not signed with a BackupZit release key »La source de mise à jour ne contient pas de version officielle, ou les fichiers ont été modifiés en route. Téléchargez-les à nouveau depuis l'adresse officielle.
Mises à jour : état rolled-backLa nouvelle version n'a pas démarré, la précédente et sa base de données ont donc été restaurées. Le journal du démarrage raté se trouve sur la page Mises à jour ; envoyez-le au support.
Système d'exploitation : « no supported package manager »Les mises à jour du système d'exploitation sont prises en charge sous Debian, Ubuntu (apt) et AlmaLinux, Rocky Linux, RHEL (dnf).
Sauvegarde de la console : « the backup was made by a newer BackupZit »Installez sur la nouvelle console la version qui a créé la sauvegarde, ou une plus récente, avant de restaurer.
Sauvegarde de la console : « console backups need network storage »Choisissez une cible SFTP, S3, SMB, Azure ou un dépôt renforcé ; un chemin local d'un agent n'est pas accessible depuis la console.
« Trop d'échecs de connexion »Votre adresse a été bloquée après des mots de passe erronés répétés : par défaut 30 minutes, plus longtemps en cas de blocages répétés. Un administrateur peut lever le blocage dans Paramètres → Connexion et sécurité. Sur le serveur, backupzit-server --unblock-ip all lève tous les blocages. Les comptes ne sont jamais verrouillés définitivement.
Téléphone perdu pour la double authentificationUtilisez l'un des codes de récupération ; sinon un administrateur réinitialise la double authentification sur votre page utilisateur. Le dernier administrateur peut réinitialiser son mot de passe sur le serveur avec backupzit-server --set-admin-password.
« your directory account is not in any BackupZit group »Ajoutez l'utilisateur à l'un des groupes associés dans Paramètres → LDAP / Active Directory, ou associez davantage de groupes. Utilisez Test à cet endroit pour voir les groupes trouvés pour un utilisateur.
L'API renvoie 401 / 403401 : jeton absent, révoqué, expiré ou propriétaire désactivé. 403 : le rôle du jeton est insuffisant pour la requête.
Azure : AuthenticationFailed / AuthorizationPermissionMismatchMauvaise clé de compte, ou le jeton SAS n'a pas l'autorisation de lecture, d'écriture, de suppression ou de listage, ou il a expiré.
Une VM Windows Server 2012 R2 / Windows 8.1 restaurée ne démarre pas sous Hyper-V Gen 2 (« hash was denied (DBX) »)Microsoft a révoqué l'ancien chargeur d'amorçage pour Secure Boot. Désactivez Secure Boot pour cette VM, ou mettez le système à jour avant de le sauvegarder.

Proxmox : « the guest is running and one of its disks is on storage without snapshot support »Les invités en marche nécessitent des disques LVM-thin, ZFS, Ceph RBD ou qcow2. Déplacez le disque (Disk Action → Move Storage) ou sauvegardez l'invité lorsqu'il est arrêté.

VMware : « SSH off » ou « SSH to …: connection refused »Activez SSH sur l'hôte ESXi : Host → Actions → Services → Enable Secure Shell (et réglez-le pour démarrer avec l'hôte). Les restaurations, et les sauvegardes avec la licence gratuite, en ont besoin.
VMware : « changed block tracking is off and can be enabled … only while the VM is off »Licence ESXi gratuite : éteignez la VM une fois, puis lancez la tâche ; BackupZit active le suivi des blocs modifiés et les sauvegardes suivantes ne lisent que les blocs modifiés.
VMware : « copy the disk on the datastore (needs free space …) »Les VM en marche sont brièvement copiées sur leur datastore. Libérez-y de l'espace (autant que le disque en utilise), ou sauvegardez la VM éteinte.
VMware : « … is a snapshot delta disk »La VM a ses propres instantanés. Supprimez-les ou consolidez-les dans le client hôte ESXi (Snapshots → Delete all).
VMware : « the ESXi certificate changed »L'hôte a été réinstallé ou une autre machine répond à son adresse. Si c'est attendu, supprimez l'hôte dans Agents et ajoutez-le à nouveau pour épingler le nouveau certificat.
VMware : fichiers *.replaced-DATE.vmdk à côté des disques de VMLes anciens disques d'une VM restaurée sur place. Supprimez-les dans le navigateur de datastore une fois que la VM restaurée fonctionne.
Hyper-V : fichiers *.replaced-DATE à côté des disques de VMLes anciens disques d'une VM restaurée sur place. Supprimez-les une fois que la VM restaurée fonctionne.

Le stockage de sauvegarde doit rester joignable ; quand le dépôt ne peut pas être lu, les lectures de disque de la VM se bloquent.

Parcourir les fichiers : « stored on a local path of the agent »La console ne peut lire que les sauvegardes sur un stockage réseau. Utilisez backupzit-agent pve ls/extract ou image-ls/image-extract sur l'agent.
Restauration d'un système Linux : « missing programs … »Installez les paquets indiqués sur la machine qui restaure, ou démarrez l'ISO de récupération Linux de BackupZit, qui les contient.
La machine Linux restaurée n'a pas de réseauLes paramètres réseau étaient liés à l'ancienne adresse MAC (netplan match: macaddress). Restaurez avec Matériel différent, ou supprimez les lignes match dans /etc/netplan/.

Une copie restaurée d'une machine apparaît comme l'agent d'origineLes restaurations dans une nouvelle VM Proxmox désinscrivent automatiquement l'agent dans la copie. Pour les autres copies, supprimez agent.json dans la copie et inscrivez-la comme nouvelle machine.

Une sauvegarde se termine par un « avertissement »

Certains fichiers n'ont pas pu être lus — en général des fichiers verrouillés par une application alors que VSS n'est pas disponible, ou des fichiers pour lesquels l'agent n'a pas d'autorisation. La liste figure sur la page de l'exécution. Tout le reste est sauvegardé.

Les sauvegardes sont lentes

  • La première sauvegarde lit et envoie tout ; les suivantes ne lisent que les fichiers modifiés et n'envoient que les nouvelles données.
  • Vérifiez le chemin réseau vers le stockage (Wi-Fi, VPN, débit montant Internet pour un stockage cloud).
  • Excluez les caches, fichiers temporaires et médias dont vous n'avez pas besoin.

FAQ

Puis-je utiliser NFS ?

Pour sauvegarder un partage NFS (ou SMB), créez une tâche NAS / partage de fichiers ; un agent Linux monte l'export à chaque exécution. Pour stocker les sauvegardes sur NFS, montez l'export sur l'agent (Linux : /etc/fstab) et utilisez une cible Chemin local / monté comme /mnt/nfs-backup ; pour les machines Windows, une cible SMB est un meilleur choix.

Puis-je déplacer les sauvegardes vers un autre stockage ?

Copiez le dossier du dépôt (ou le préfixe du bucket) tel quel — il est autonome — et ajoutez une cible de stockage pointant vers le nouvel emplacement avec la même clé de récupération.

Supprimer une tâche supprime-t-il les sauvegardes ?

Non. Les sauvegardes restent sur le stockage et restent restaurables depuis Activité ou la ligne de commande.

Que se passe-t-il si la console est hors service ?

Aucune nouvelle sauvegarde planifiée ne démarre jusqu'à son retour ; les exécutions en file d'attente reprennent ensuite. Les restaurations sont toujours possibles en ligne de commande avec la fiche de récupération.

Combien d'espace les sauvegardes nécessiteront-elles ?

Pour la première sauvegarde, à peu près la taille des données après compression, plus les modifications quotidiennes pour chaque jour conservé. La page Rapports indique combien a été envoyé par tâche.
