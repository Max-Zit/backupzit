Machines virtuelles VMware ESXi

BackupZit sauvegarde les machines virtuelles des hôtes VMware ESXi sans rien installer sur ESXi ni dans les VM. Un agent BackupZit sur n'importe quelle machine du réseau sert de proxy à l'hôte. Il prend des instantanés, lit uniquement les blocs modifiés des disques virtuels et les écrit sur votre stockage.

Prérequis

  • ESXi 6.7, 7 ou 8, connecté directement. Les hôtes gérés par vCenter s'ajoutent un par un avec leur propre adresse ; vCenter lui-même n'est pas encore pris en charge.
  • Un utilisateur disposant des droits d'administrateur sur l'hôte, généralement root.
  • SSH activé sur l'hôte : Host → Actions → Services → Enable Secure Shell. Les restaurations en ont toujours besoin. Les hôtes sous licence ESXi gratuite en ont aussi besoin pour les instantanés, car leur API est en lecture seule.
  • Un agent proxy : tout agent Windows ou Linux qui atteint l'hôte sur les ports 443 et 22. Les données de sauvegarde passent par lui ; placez-le donc sur un réseau rapide, proche de l'hôte et du stockage.
  • De l'espace libre sur le datastore de la VM pendant la sauvegarde d'une VM en marche. BackupZit y copie brièvement le disque (voir ci-dessous). La copie est thin, elle a donc besoin d'autant d'espace que le disque en utilise réellement.

Ajouter un hôte

  1. Ouvrez Agents → Hôtes VMware ESXi → Ajouter un hôte ESXi.
  2. Saisissez l'adresse, l'utilisateur, le mot de passe et l'agent proxy.
  3. La console se connecte une fois pour les vérifier. Elle lit la liste des VM et la licence, et épingle le certificat HTTPS et la clé d'hôte SSH de l'hôte. Si l'hôte est plus tard remplacé par une autre machine à la même adresse, BackupZit refuse de se connecter au lieu de lui envoyer le mot de passe.

Le mot de passe est stocké chiffré, comme tous les autres secrets. La liste des VM est actualisée toutes les 10 minutes, ou immédiatement avec Actualiser. Le tableau indique le mode de chaque hôte :

  • vSphere API : hôtes sous licence.
  • Licence gratuite : les instantanés et les restaurations passent par SSH.

Tâches de sauvegarde

Dans Tâches de sauvegarde, choisissez l'hôte ESXi (listé sous Hôtes VMware ESXi dans la liste des agents) et Machines virtuelles. Sauvegardez toutes les VM de l'hôte (les VM créées plus tard sont incluses automatiquement) ou cochez-en certaines. La tâche s'exécute sur l'agent proxy de l'hôte. Si vous changez de proxy, les tâches existantes suivent.

Comment une VM est sauvegardée

  1. Le suivi des blocs modifiés (CBT) est activé pour la VM s'il est désactivé.
    • Sur les hôtes sous licence, cela se fait automatiquement.
    • Sur les hôtes gratuits, le CBT ne peut être activé que lorsque la VM est éteinte. BackupZit le fait lors de la première sauvegarde qui trouve la VM éteinte. D'ici là, chaque sauvegarde lit les disques entiers et l'exécution affiche un avertissement.
  2. Un instantané backupzit_… est pris. Lorsque les VMware Tools tournent dans l'invité, l'instantané est suspendu (quiesced) : les applications et systèmes de fichiers sont vidés d'abord, ce qui rend la sauvegarde cohérente au niveau applicatif. Sans VMware Tools, elle est cohérente en cas de crash. Installez open-vm-tools dans les VM Linux et VMware Tools dans les VM Windows.
  3. Le CBT indique quels blocs lire :
    • pour la première sauvegarde, uniquement les blocs utilisés ;
    • ensuite, uniquement les blocs modifiés depuis la sauvegarde précédente.
  4. Une VM en marche garde ses disques verrouillés. Ses disques sont donc copiés sur le datastore (thin) et l'instantané est supprimé aussitôt, généralement après quelques secondes. La copie est ensuite lue via HTTPS et supprimée. Les VM éteintes sont lues directement.
  5. La configuration de la VM (.vmx) et la NVRAM sont stockées avec la sauvegarde.

Exemple du laboratoire de test : une VM Debian avec un disque de 8 Go, dont 1,6 Go utilisés. La première sauvegarde a lu 1,6 Go. La suivante, après 50 Mo de nouvelles données, a lu 70 Mo et a duré 23 secondes.

Restaurer une VM

Utilisez l'assistant de restauration (Machine virtuelle complète) ou la page de la sauvegarde dans Activité. Choisissez :

  • En tant que nouvelle VM à côté de l'original : une copie avec un nouveau nom, un nouvel UUID et de nouvelles adresses MAC. Le nom par défaut est celui de l'original suivi de -restored- et de la date. Les paramètres réseau de l'invité liés aux anciennes adresses MAC, comme netplan match: macaddress dans les images cloud, ne s'appliquent pas à la copie.
  • À la place de la VM d'origine : avec l'arrêter et remplacer ses disques, BackupZit :
    • éteint la VM et supprime ses instantanés ;
    • renomme les disques actuels en ….replaced-DATE.vmdk (supprimez-les une fois que la VM restaurée fonctionne) ;
    • écrit la sauvegarde dans de nouveaux disques portant les noms d'origine, et règle le processeur et la mémoire comme dans la sauvegarde.
    La VM conserve son UUID, ses cartes réseau et ses adresses MAC. Si la VM a été supprimée, elle est recréée avec son identité d'origine.
  • Hôte ESXi et datastore : un autre hôte, ou un autre datastore du même hôte.
  • Démarrer la VM après la restauration.

Les disques sont restaurés en thin, et seuls les blocs contenant des données sont écrits. Les images ISO connectées aux lecteurs CD/DVD ne font pas partie de la sauvegarde ; ces lecteurs restent donc vides.

Restauration instantanée

Choisissez Instantanément, en s’exécutant depuis la sauvegarde pour démarrer une VM en quelques secondes, sans copier d'abord ses disques. L'agent proxy de l'hôte — il doit s'agir d'un agent Linux — sert les disques de la VM directement depuis la sauvegarde via NFS ; l'hôte les monte comme datastore backupzit-<agent> et exécute la VM depuis celui-ci. Les modifications faites par la VM sont conservées sur l'agent (/var/lib/backupzit/instant-esxi, qui a donc besoin d'espace libre) ; la sauvegarde elle-même n'est jamais modifiée, et la rétention la conserve tant que la VM tourne depuis elle. Si la VM d'origine existe encore, la VM instantanée reçoit un nouvel UUID et de nouvelles adresses MAC.

Sur la page de l'exécution, lorsque la VM fonctionne comme prévu :

  • Terminer la copie sur un datastore de l'hôte : la VM est arrêtée (via VMware Tools s'ils tournent), ses disques sont copiés en thin avec vmkfstools, elle est enregistrée depuis le datastore et redémarrée. La licence ESXi gratuite n'a pas de Storage vMotion, cela nécessite donc une courte interruption qui augmente avec la taille des disques. Si la copie échoue, la VM continue de tourner depuis la sauvegarde.
  • Abandonner arrête et supprime la VM avec toutes ses modifications.

L'agent répond en NFS sur le port 2049 (et l'enregistre auprès du rpcbind de la machine sur le port 111, ou répond lui-même sur le port 111) uniquement pour l'adresse de l'hôte ESXi ; ouvrez ces ports de l'hôte vers l'agent si un pare-feu se trouve entre les deux. Lorsque la dernière VM instantanée est terminée ou abandonnée, le datastore est supprimé et le serveur NFS s'arrête.

Fichiers individuels

Parcourir les fichiers sur la page de la sauvegarde (ou Fichiers d’une machine virtuelle dans l'assistant de restauration) ouvre les disques de la VM. Vous pouvez parcourir NTFS, ext2/3/4 et XFS, y compris sur LVM, et télécharger des fichiers ou les restaurer sur n'importe quel agent.

Ligne de commande

Ces commandes s'exécutent sur n'importe quel agent. Définissez le mot de passe ESXi dans BACKUPZIT_VMWARE_PASSWORD :

backupzit-agent vmware list    --host 192.168.1.20 [--user root]
backupzit-agent vmware backup  --host … --repo … [--vmid N,N]
backupzit-agent vmware restore --host … --repo … --vmid N [--new] [--name NAME] [--datastore DS] [--overwrite] [--start] SNAPSHOT|latest

vmware list affiche les empreintes du certificat et de la clé SSH de l'hôte. Passez-les avec --thumbprint et --ssh-host-key pour les épingler aussi en ligne de commande.

Pas encore inclus

  • vCenter. Ajoutez chaque hôte ESXi directement.
  • Les VM ayant leurs propres instantanés. Leurs disques sont des deltas ; supprimez ou consolidez d'abord les instantanés.
  • Certains types de disques. Les mappages de périphériques bruts (RDM) et les disques indépendants.
  • La restauration instantanée via un agent proxy Windows. La restauration instantanée nécessite un agent proxy Linux.
