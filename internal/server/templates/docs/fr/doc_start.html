Prise en main

BackupZit protège les machines Windows et Linux, les machines virtuelles Proxmox VE, Hyper-V et VMware ESXi, les bases de données (SQL Server, PostgreSQL, MySQL/MariaDB) et les partages NAS — fichiers, disques entiers et systèmes entiers — depuis une console web qui tourne sur votre propre réseau.

Comment fonctionne BackupZit

  • Console de gestion (cette application web) — tourne sur un serveur Linux de votre réseau. Elle stocke la configuration, planifie les tâches, collecte les résultats et affiche les rapports. Elle n'a jamais besoin d'être joignable depuis Internet.
  • Agents — un petit service sur chaque machine protégée (MSI Windows, deb/rpm Linux) et sur les hôtes Proxmox et Hyper-V ; les hôtes VMware ESXi sont atteints via un agent servant de proxy. Les agents contactent la console en HTTPS, reçoivent les tâches et envoient les données de sauvegarde directement au stockage. Sous Windows, l'agent affiche son état à côté de l'horloge.
  • Cibles de stockage — là où les sauvegardes sont conservées : SFTP, stockage objet compatible S3 (AWS, Wasabi, Backblaze B2, MinIO, Google Cloud…), Azure Blob Storage, un partage SMB/NAS, des disques USB en rotation, un disque local ou monté, ou un dépôt renforcé BackupZit.

Les données de sauvegarde ne passent jamais par la console. La console ne fait que coordonner ; une petite machine virtuelle lui suffit.

Premiers pas

Pour mettre en place une nouvelle console, importez l'image d'appliance prête à l'emploi dans une petite VM, démarrez l'ISO de l'appliance ou lancez le script d'installation sur un serveur Linux existant ; voir Installer le serveur.

  1. Ajoutez une cible de stockage sous Stockage. Laissez Chiffrer les sauvegardes activé et conservez en lieu sûr la fiche de récupération affichée ensuite. Voir Cibles de stockage.
  2. Installez des agents : sous Agents, cliquez sur Créer un jeton d’inscription, téléchargez l'installateur depuis la même page et collez le code d'inscription quand l'installateur Windows le demande (Linux : backupzit-agent enroll --code …). Pour les VM, installez l'agent sur l'hôte Proxmox ou Hyper-V ; ajoutez les hôtes VMware ESXi sous Agents → Hôtes VMware ESXi. Voir Agents.
  3. Créez une tâche de sauvegarde sous Tâches de sauvegarde : choisissez l'agent, le stockage, ce qu'il faut sauvegarder (fichiers, un partage NAS, une image disque, des bases de données, tout le système Linux ou les VM d'un hôte Proxmox, Hyper-V ou VMware ESXi), quand l'exécuter et combien de sauvegardes conserver. Voir Tâches de sauvegarde et planifications.
  4. Exécutez-la une fois manuellement avec Lancer la sauvegarde maintenant sur la page de la tâche et vérifiez le résultat sous Activité.
  5. Testez une restauration — une sauvegarde ne vaut que par sa restauration. Les tests de restauration automatiques s'exécutent chaque semaine ; restaurez aussi une fois quelque chose à la main avec l'assistant de restauration. Voir Restauration.
  6. Préparez-vous aux sinistres : téléchargez les ISO de récupération et créez un code de récupération sous Supports de récupération.
  7. Configurez les alertes par e-mail sous Paramètres → Notifications par e-mail pour être informé des échecs, et éventuellement un rapport hebdomadaire.

Langue

La console est disponible en 14 langues : anglais, allemand, français, espagnol, italien, portugais (Brésil), néerlandais, polonais, tchèque, serbe (alphabet latin), turc, russe, chinois (simplifié) et japonais. Choisissez-en une dans la liste des langues en haut à droite ou sur la page de connexion ; le choix est mémorisé dans le navigateur. Sans choix, c'est la langue du navigateur qui décide (les navigateurs croates, bosniens et monténégrins obtiennent le serbe, les slovaques le tchèque, les autres langues l'anglais). Ce guide est également traduit (une page sans traduction s'affiche en anglais). Les e-mails, notifications de chat et messages remontés par les agents restent en anglais.

Les traductions se trouvent dans le code source, dans internal/server/i18n/fr.json : le texte anglais est la clé, la traduction sa valeur. go run ./tools/i18n missing fr liste les textes sans traduction ; les textes non traduits s'affichent en anglais.

Notions clés

Instantanés et déduplication

Chaque sauvegarde crée un instantané : une image complète et consultable des données à ce moment. Les fichiers sont découpés en morceaux de taille variable et les disques en blocs, et chaque morceau n'est stocké qu'une fois ; la deuxième sauvegarde et les suivantes n'envoient donc que ce qui a changé — et pourtant chaque instantané peut être restauré seul. Il n'y a pas de « chaîne complète/incrémentale » à gérer.

Dépôts

Chaque agent écrit dans son propre dépôt sous l'emplacement de la cible de stockage (<location>/<hostname>_<id>). Un dépôt est autonome : avec l'emplacement, les identifiants du stockage et la clé de récupération, il peut être restauré même si la console a disparu.

Rétention

Chaque tâche conserve un certain nombre de sauvegardes récentes, quotidiennes, hebdomadaires et mensuelles. Les instantanés plus anciens sont supprimés après chaque exécution et l'espace qu'ils occupaient est libéré.

Ce que BackupZit vérifie pour vous

  • Tests de restauration — la sauvegarde la plus récente de chaque tâche est partiellement restaurée et vérifiée chaque semaine (Restauration).
  • Détection des rançongiciels — les sauvegardes inhabituelles (modifications massives, données chiffrées, suppression massive, sauts soudains du volume de données) sont signalées et la rétention est suspendue (Protection contre les rançongiciels).
  • Alertes et rapports — e-mails en cas d'échec et résumé quotidien ; rapports planifiés pour la direction (Notifications par e-mail, Supervision).
