Notifications : e-mail, Slack, Teams, webhooks

Recevez un e-mail quand une sauvegarde échoue, et un résumé quotidien chaque matin.

Configurer l'e-mail

Dans Paramètres → Notifications par e-mail :

ChampExemple
Serveur SMTP / portsmtp.office365.com / 587, smtp.gmail.com / 587, relais interne / 25
SécuritéSTARTTLS (port 587), TLS (port 465) ou aucune (relais interne uniquement)
Utilisateur / mot de passeLa boîte aux lettres utilisée pour l'envoi ; laissez vide pour un relais anonyme. Microsoft 365 et Gmail exigent un mot de passe d'application.
Expéditeurbackup@example.com
DestinatairesUne ou plusieurs adresses, séparées par des virgules.

Utilisez Envoyer un e-mail de test pour vérifier les paramètres.

Ce qui est envoyé

  • Échecs (recommandé) — un e-mail par exécution échouée avec la raison : sauvegardes, copies, restaurations et tests de restauration échoués. Avec cette option, vous recevez aussi une alerte SUSPICIOUS lorsqu'une sauvegarde ressemble à un rançongiciel ou à une suppression massive.
  • Avertissements — exécutions où certains fichiers n'ont pas pu être lus.
  • Réussites — chaque exécution réussie (souvent trop ; préférez le rapport quotidien).
  • Rapport quotidien — à l'heure choisie : exécutions des dernières 24 heures, problèmes et agents hors ligne. L'objet commence par OK, WARNINGS ou ATTENTION, afin que les règles de messagerie puissent les trier.

Pour des résumés hebdomadaires ou mensuels, utilisez les rapports planifiés ; ils sont envoyés avec les mêmes paramètres de messagerie et ont leurs propres destinataires. Les objets commencent par [BackupZit] afin que les règles de messagerie puissent les trier. Le mot de passe SMTP est stocké chiffré.

Slack, Microsoft Teams et webhooks

Dans Paramètres → Chat et webhooks, ajoutez autant de canaux que vous voulez ; chacun choisit s'il reçoit les échecs, les avertissements et les réussites. Les sauvegardes inhabituelles (rançongiciel possible) comptent comme des échecs. Envoyer un test vérifie immédiatement un canal.

  • Slack : créez un incoming webhook pour le canal (paramètres de l'application Slack → Incoming Webhooks) et collez son URL (https://hooks.slack.com/services/…).
  • Microsoft Teams : dans le canal, ajoutez le workflow Post to a channel when a webhook request is received et collez son URL. Les messages arrivent sous forme de cartes avec un bouton qui ouvre l'exécution dans la console.
  • Webhook : toute URL qui accepte un POST JSON — système de tickets, supervision ou outil d'automatisation. Avec un secret de signature, chaque requête porte X-BackupZit-Signature: sha256=<hex>, le HMAC-SHA256 du corps, afin que le destinataire puisse vérifier qu'elle vient de votre console.

Le JSON d'un webhook :

{"event": "run.finished", "run_id": 412, "kind": "vm-backup", "kind_title": "VM backup",
 "status": "failed", "suspicious": "", "job": "Proxmox VMs", "job_id": 7, "agent": "pve1",
 "message": "…", "errors": ["…"], "started_at": "2026-10-04T22:00:03+02:00",
 "finished_at": "2026-10-04T22:04:41+02:00", "url": "https://backup.example/runs/412"}

Les messages sont envoyés une fois par exécution, même lorsque l'e-mail est désactivé. Un canal en échec (mauvaise URL, service indisponible) est consigné dans le journal de la console et ne bloque pas les autres. Les URL de webhook sont stockées chiffrées.
