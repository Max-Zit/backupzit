Machines virtuelles Hyper-V

BackupZit sauvegarde les machines virtuelles Hyper-V depuis l'agent installé sur l'hôte Hyper-V ; rien n'est installé dans les VM. Les invités Windows et Linux sont capturés sans être arrêtés. Vous pouvez les restaurer en tant que nouvelle VM ou à la place de l'original.

Mise en place

  1. Installez le MSI de l'Agent Windows depuis Agents sur l'hôte Hyper-V et inscrivez-le. Hôtes pris en charge : Windows Server 2016 ou plus récent avec le rôle Hyper-V, ou Windows 10/11 avec Hyper-V. Dans un cluster, installez l'agent sur chaque hôte.
  2. En moins d'une minute, l'hôte apparaît sur la page Agents avec le badge Hyper-V · N VMs.
  3. Dans Tâches de sauvegarde, sélectionnez cet agent et choisissez Machines virtuelles (Proxmox VE, Hyper-V, VMware). Choisissez ensuite :
    • toutes les VM de l'hôte, ce qui couvre aussi les VM créées plus tard ;
    • des VM individuelles, en les cochant.

L'agent passe par les interfaces propres à Hyper-V : le module PowerShell Hyper-V et l'API Virtual Disk de Windows. La console ne stocke aucun identifiant Hyper-V.

Comment une VM est sauvegardée

  1. Un point de contrôle de récupération temporaire (backupzit_…) est créé. C'est le type de point de contrôle qu'Hyper-V fournit aux applications de sauvegarde. Hyper-V demande à l'invité de s'y préparer :
    • Les invités Windows vident les tampons de leurs applications via VSS.
    • Les invités Linux gèlent leurs systèmes de fichiers, si les démons Hyper-V sont installés (hyperv-daemons / hv-vss-daemon).
    Si l'invité ne peut faire ni l'un ni l'autre, le point de contrôle est pris en cohérence de crash. La page de l'exécution indique le type utilisé.
  2. Le point de contrôle de récupération active le Resilient Change Tracking (RCT) pour les disques de la VM ; vous verrez des fichiers .rct et .mrt à côté d'eux. La première sauvegarde lit les disques entiers. Ensuite, RCT indique quels blocs ont changé depuis la sauvegarde précédente, et seuls ceux-ci sont lus.
  3. Les disques sont lus dans l'état du point de contrôle, via l'API Virtual Disk, par blocs de 1 Mio. Cela couvre les fichiers VHDX et VHD, y compris les chaînes de points de contrôle antérieurs. Les blocs vides ne sont pas stockés, et les blocs déjà présents dans le dépôt ne sont pas renvoyés.
  4. Le point de contrôle est supprimé et Hyper-V le fusionne en arrière-plan.
  5. La configuration de la VM est stockée avec la sauvegarde : génération, processeur, mémoire, cartes réseau (commutateur, VLAN, adresse MAC), contrôleurs de disque, démarrage sécurisé et TPM.

Les VM éteintes sont lues directement, sans point de contrôle. Sur les hôtes antérieurs à Windows Server 2016 (sans points de contrôle de récupération), un point de contrôle de production est utilisé et chaque sauvegarde lit les disques entiers.

Exemple du laboratoire de test : une VM Linux avec un disque de 3 Go. La première sauvegarde a lu 3 Go. La suivante, après 64 Mo de nouvelles données, a lu 96 Mo.

Sous Windows 10/11, Hyper-V crée un point de contrôle automatique au démarrage d'une VM, sauf si cette option est désactivée dans les paramètres de la VM. BackupZit gère ces points de contrôle, mais pour des serveurs vous voudrez désactiver les points de contrôle automatiques (paramètres de la VM → Points de contrôle).

Restaurer une VM

Ouvrez l'exécution de la sauvegarde de VM (depuis la page de la tâche ou Activité) et utilisez Restaurer une VM Hyper-V.

En tant que nouvelle VM à côté de l'original

Crée une seconde VM avec de nouvelles adresses MAC, afin qu'elle puisse tourner sur le même réseau que l'original. Par défaut, elle porte le nom de l'original suivi de « restored » et de la date. Les points de contrôle automatiques y sont désactivés (Windows les active pour les nouvelles VM), donc son démarrage ne laisse pas de fichiers de point de contrôle. Si la copie tourne à côté de l'original et contient l'agent BackupZit, voir Deux machines utilisant un même agent.

Les paramètres réseau de l'invité liés à une adresse MAC ne s'appliquent pas aux nouvelles cartes. Un exemple est match: macaddress de netplan, utilisé par les images cloud Linux.

À la place de la VM d'origine

Cochez l'arrêter et remplacer ses disques. BackupZit alors :

  • éteint la VM existante ;
  • fusionne ses points de contrôle ;
  • remplace ses disques par les disques restaurés.

La VM conserve son ID, ses cartes réseau et ses adresses MAC, donc les tâches, la supervision et le réseau de l'invité continuent de fonctionner.

Les anciens fichiers de disque ne sont pas supprimés ; ils sont renommés en ….replaced-DATE. Supprimez-les une fois que la VM restaurée fonctionne.

Si la VM d'origine n'existe plus, elle est recréée, avec un nouvel ID Hyper-V.

Options

  • Dossier des disques virtuels : le dossier par défaut de l'hôte ou tout dossier contenant des disques de VM. Une restauration sur place met les nouveaux disques à côté des originaux.
  • Démarrer la VM après la restauration.

Ce que reçoit une VM restaurée

  • Les commutateurs virtuels sont connectés par leur nom. Si un commutateur n'existe pas sur l'hôte, la carte reste déconnectée.
  • Chaque VM restaurée reçoit un nouvel ID de génération, afin que les contrôleurs de domaine Active Directory détectent la restauration en toute sécurité.

Restaurer des fichiers individuels

Dans le tableau des VM de l'exécution, cliquez sur Parcourir les fichiers pour voir les partitions et volumes des disques de la VM. Vous pouvez parcourir NTFS, ext2/3/4 et XFS, y compris dans LVM. De là, vous pouvez télécharger des fichiers ou les restaurer sur n'importe quel agent. Cela fonctionne exactement comme pour Proxmox VE.

Ligne de commande

Exécutez ces commandes sur l'hôte Hyper-V, en tant qu'administrateur :

backupzit-agent hyperv list
backupzit-agent hyperv backup  --repo ... [--vmid N,N]
backupzit-agent hyperv restore --repo ... --vmid N [--new] [--name NAME] [--folder D:\VMs] [--overwrite] [--start] SNAPSHOT|latest
  • --vmid est le numéro affiché par hyperv list. BackupZit le dérive du GUID de la VM.
  • Sans --new, la VM est restaurée sur place.
  • --overwrite confirme que les disques d'une VM existante doivent être remplacés.

Les options du dépôt sont les mêmes que pour toutes les commandes ; voir Référence de la ligne de commande.

Pas encore inclus

  • Certains types de disques. Les VHDX partagés, les ensembles VHD (VHD Set) et les disques pass-through ne sont pas sauvegardés.
