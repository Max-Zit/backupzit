REST API

将 BackupZit 与 RMM 平台、监控系统（PRTG、Zabbix、Nagios、Uptime Kuma 等）以及您自己的脚本集成。

令牌

在 我的帐户 → API 令牌 中创建令牌。授予它够用的最低角色 —— 监控用 查看者，若还需启动备份和还原测试则用 还原操作员。令牌只显示一次；在每个请求中发送它：

Authorization: Bearer bzt_...

令牌可以设置过期时间，可由其所有者或管理员撤销（用户），所有者被禁用后令牌也会失效。使用令牌执行的操作会以令牌名称记录在审计日志中。

端点

所有响应均为 JSON。基础 URL：https://<控制台>:8443。

方法和路径角色返回
GET /api/v1/status查看者总体状态：在线代理、24 小时内的失败和警告、正在进行的运行、未检查的可疑备份，"ok": true|false
GET /api/v1/agents查看者代理及其操作系统、版本、在线状态和最后联系时间
GET /api/v1/jobs, GET /api/v1/jobs/{id}查看者作业及其计划、下次运行和上次结果
POST /api/v1/jobs/{id}/run还原操作员立即启动作业：{"run_id": 123}（202），如已有运行在进行则返回 409
POST /api/v1/jobs/{id}/test还原操作员对作业的最新备份启动还原测试
GET /api/v1/runs?job=&agent=&status=&limit=查看者最近的运行，最新的在前（默认 100，最多 1000）
GET /api/v1/runs/{id}查看者单次运行及其消息、错误和统计信息
GET /api/v1/report?period=&from=&to=&agent=&job=查看者某个时段的报告：合计、成功率和每个作业的详情
GET /api/v1/targets查看者存储目标（不含凭据）

时段：today、yesterday、last7、last30、last90、thisweek、lastweek、thismonth、lastmonth，或 custom 加 from=2026-09-01&to=2026-09-30。

错误返回 {"error": "..."}，状态码为 400（请求有误）、401（令牌缺失、无效或已过期）、403（角色权限不足）、404 或 409。

示例

curl

curl -sk -H "Authorization: Bearer $BZ_TOKEN" https://backup.example.local:8443/api/v1/status
curl -sk -X POST -H "Authorization: Bearer $BZ_TOKEN" https://backup.example.local:8443/api/v1/jobs/7/run

PowerShell

$h = @{ Authorization = "Bearer $env:BZ_TOKEN" }
$s = Invoke-RestMethod -Uri https://backup.example.local:8443/api/v1/status -Headers $h -SkipCertificateCheck
if (-not $s.ok) { Write-Warning "BackupZit needs attention: $($s.failed_24h) failed backups" }

仅在可信网络中针对控制台的自签名证书使用 -k / -SkipCertificateCheck，或者在监控主机上安装控制台证书。

监控检查

每隔几分钟轮询一次 /api/v1/status，当 ok 为 false 时发出警报。若要按作业检查，请使用 /api/v1/jobs，当 last_status 为 failed 或 last_finished 早于预期时发出警报。
