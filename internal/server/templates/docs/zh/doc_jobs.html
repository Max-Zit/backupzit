备份作业和计划

作业规定在哪个代理上备份什么、存储到哪里、何时运行以及保留多少个备份。

创建作业

  1. 转到 备份作业 并填写新建备份作业。
  2. 选择代理和存储目标。
  3. 选择要备份的内容：
    • 文件和文件夹——每行一个路径，按代理上的路径填写，例如 C:\Users、D:\Data、/home、/etc。
    • 磁盘映像——整个磁盘或选定分区，可还原到空磁盘或新硬件。参见 磁盘映像。
    • Linux 系统——Linux 机器的所有文件系统和磁盘布局，可还原到空磁盘或作为 Proxmox 虚拟机。参见 Linux 系统备份。
    • 虚拟机（Proxmox VE、Hyper-V、VMware）——虚拟化主机的虚拟机（以及 Proxmox 容器），客户机内无需代理：由 Proxmox 或 Hyper-V 主机上的代理备份，VMware ESXi 则由该主机的代理服务器代理备份（在代理列表中选择 ESXi 主机）。参见 Proxmox VE、Hyper-V 和 VMware ESXi。
    • 数据库——代理所在机器上的 SQL Server、PostgreSQL 或 MySQL/MariaDB，带有日志备份，可还原到任意时刻。参见 数据库。
    • NAS / 文件共享——由代理读取的 SMB 或 NFS 共享；参见下文。
    • Microsoft 365——Exchange Online 邮箱、日历、联系人、OneDrive 和 SharePoint 网站，由任意代理通过 Microsoft Graph 读取；参见 Microsoft 365。
  4. 可选添加排除项，每行一个：名称模式，适用于每个文件夹（*.tmp、node_modules、Thumbs.db、*.iso），或完整路径，仅适用于该文件或文件夹（C:\Data\Temp、/srv/www/cache，也可使用通配符：D:\VMs\*.iso）。在 Windows 上，完整路径不区分大小写。
  5. 设置保留备份和计划，然后点击创建作业。

每个用户的文件夹

在路径下方，计算机的每个用户 可添加 桌面、文档、下载、图片 或 整个用户配置文件。它们写作 {users}/Documents，代理在每次备份时重新查找这些文件夹：Windows 上为 C:\Users\<名称>\Documents（以及 OneDrive 移动后的文件夹 …\OneDrive\Documents），Linux 上为 /home/<名称>/Documents 和 /root/Documents，macOS 上为 /Users/<名称>/Documents。之后新增的用户无需修改作业即可备份；系统配置文件（Default、Public）会被跳过。{users} 后可接任何文件夹，例如 {users}/AppData/Roaming/Thunderbird。

路径中还可以使用通配符 *（一个文件夹名称内的任意字符）和 ?（一个字符）：D:\Projects\*\Docs、/srv/sites/*/uploads。大小写按所写内容匹配。在某台计算机上找不到任何内容的 {users} 或通配符路径不算错误：运行会报告 Nothing matched …，只有在完全没有可备份内容时才会失败。需要代理 0.45.0 或更高版本。整个配置文件也包含缓存；可使用完整路径排除，例如 C:\Users\*\AppData\Local\Temp。

一个作业用于多个代理

要在许多计算机上备份相同的文件夹，请在 代理 下选择 多个代理 中的一项：所有代理、所有 Windows 代理、所有 Linux 代理、所有 macOS 代理 或 选择代理…（然后勾选）。此类作业备份文件和文件夹；配合 {users} 路径（例如 {users}/Documents），一个作业即可覆盖公司所有人的文档。之后注册的代理会在一分钟内自动加入作业（选择代理… 时仅限勾选的代理）。

每个代理备份到存储目标上自己的存储库，拥有各自的历史记录、还原和保留期，与单代理作业相同。作业页面在 多代理作业 下列出该作业；其页面显示每个代理及其最近结果，立即在所有代理上运行备份 会启动所有代理。单个代理的作业带有 多个代理 标记：打开它可查看历史记录和还原，或停用它以暂停该计算机。文件夹、计划和保留期在多代理作业中更改，并适用于其所有代理；在那里也可以排除代理。排除代理或删除作业会保留其备份在存储上。启用四眼审批时，排除代理、缩短保留期、停用和删除需等待第二位用户。

暂时无法运行该作业的代理会列出原因，例如对 {users} 和通配符而言早于 0.45.0 的代理；更新后即会加入。许多计划相同的代理会同时开始；备份时间窗口 或每个作业不同的时间可分散存储负载。

NAS 和文件共享（SMB、NFS）

NAS / 文件共享作业备份网络共享，无需在 NAS（Synology、QNAP、TrueNAS、Windows 文件服务器……）上安装任何东西。选择任意一个能访问该共享的代理——由它读取共享并写入备份——然后输入：

  • 共享：smb://nas01/data（可附带文件夹：smb://nas01/data/Office）或 nfs://nas01/volume1/data（导出路径）；
  • 对于 SMB，填写帐户（用户、可选的域、密码——加密存储）；留空表示来宾访问。NFS 使用代理机器对导出的访问权限（在 NAS 上允许其地址）；
  • 要备份的共享中的文件夹，每行一个（留空：整个共享），以及排除项，例如 #recycle、@eaDir 或 .snapshot。

每次运行时，代理都会连接共享——Windows 代理通过其 UNC 路径（\\nas01\data，仅 SMB），Linux 代理以只读方式挂载到 /mnt/backupzit-nas 下（SMB 需要 cifs-utils，NFS 需要 nfs-common 或 nfs-utils；Proxmox VE 两者都有）——之后断开连接。这些备份是普通的文件备份：经过重复数据删除且为增量，支持保留、复制作业、还原测试、浏览和文件还原。还原到原位置会以可写方式重新连接共享并将文件写回；也可以还原到任意代理上的文件夹或下载。

打开和锁定的文件（VSS）

在 Windows 上，代理使用卷影复制服务：它为卷创建一致的时间点快照并从中备份，因此打开的文件（Outlook PST、数据库、正在编辑的文档）都能一致地备份。支持 VSS 的应用程序（例如 SQL Server）会在创建快照前将数据刷新到磁盘。

计划

选项示例
在指定时间每个工作日 22:00；或每天 12:00 和 18:00。在勾选的日期中每天最多三次。
重复运行周一至周五 08:00 到 18:00 之间每 2 小时一次。间隔从 15 分钟到 12 小时。
每月一次每月 1 日 23:00。
仅手动仅在点击立即运行备份时运行。
在另一个作业之后先数据库，再文件服务器：所选作业成功完成后立即开始本作业——勾选即使该作业失败也运行时，则在任何结果之后开始。链可以更长（A → B → C）；作业不能在其自身之后运行，也不能形成循环。

时间以控制台服务器的时区为准（在设备上：设置 → 网络 → 时区或设置菜单的第 9 项；初始为 UTC）。如果代理在计划时间离线，备份会在队列中等待，代理一恢复就开始。所有计划的运行都可以在 日历 中查看。控制台的当前日期和时间显示在左下角的时区下方。

备份时间窗口

在作业表单中勾选备份时间窗口：仅在以下时间之间开始（例如 22 至 6）后，该作业的计划运行和链式运行只在窗口内开始。窗口关闭时仍在等待的运行（例如因为夜间作业耗时更长）会被取消，以免在工作时间占用网络和机器。已经开始的运行会继续；要停止过长的运行，请使用运行时间限制（见下文）。手动启动作业不受窗口限制。每日和每月计划的时间必须位于窗口内。

恢复点目标（RPO）

RPO 规定作业最新成功备份最多可以有多旧，以小时计——例如每日备份设为 26（一天加一些余量）。在作业表单的 恢复点目标（RPO），小时 中设置。仪表板显示有多少作业 符合 RPO，并列出每个未达成的作业；作业页面显示其状态。作业未达成 RPO 时会发送一次通知（邮件和聊天，与失败相同），之后只有在期间重新达成后才会再次发送。与上次运行的状态不同，RPO 还能发现被误删的计划、离线多日的代理以及持续失败的备份。

保留：保留多少个备份

只要任一规则选中某个快照，它就会被保留：

  • 最新——最新的 N 个备份。
  • 每日——最近 N 个有备份的日子里每天最新的备份。
  • 每周——最近 N 周中每周最新的备份。
  • 每月——最近 N 个月中每月最新的备份。

示例：3 个最新、7 个每日、4 个每周、6 个每月，可保留约半年的历史，约 20 个还原点。每次成功运行后，不再被选中的快照会被删除（在“活动”中显示为已过期），不再被任何快照使用的数据会从存储中删除。全部为零则保留一切。

得益于重复数据删除，长期保留的成本很低：未更改的数据无论被多少快照引用，都只存储一次。

备份复制作业（3-2-1）

备份副本作业将另一个作业的备份复制到第二个存储目标——例如每晚备份到办公室 NAS，再复制到 S3 或异地加固存储库。在作业表单中选择备份副本，选择要复制的作业和目标存储。

  • 由源作业的代理执行复制；受保护的机器不会被再次读取。
  • 只传输目标中尚不存在的数据，并使用目标的密钥重新加密。
  • 计划在源作业每次备份后（默认）使副本保持最新；任何普通计划也可以，例如网络较慢时每晚一次。
  • 副本有自己的保留策略，例如 NAS 上保留 7 个每日备份，云中保留 12 个每月备份。
  • 复制的文件备份和虚拟机备份（Proxmox VE、Hyper-V、VMware）与原始备份一样，可从复制运行的页面或还原向导还原——整个虚拟机、虚拟机磁盘中的单个文件以及 Proxmox 即时恢复。由早于 0.29 的代理复制的虚拟机备份无法以这种方式还原；使用较新代理的下一次复制运行会使其最新副本可还原。磁盘映像的副本使用命令行代理还原。

更改作业

打开作业并点击编辑；表单在单独的页面中打开，备份运行时不会刷新。您可以更改名称、文件夹和排除项（文件作业）、虚拟机（虚拟机作业）、计划、保留、速度限制、压缩级别和命令。代理、存储目标以及映像作业的磁盘保持不变，以使作业的备份保持为一条链；要迁移作业，请创建一个新作业——如果需要带上旧备份，再配合一个复制作业。更改从下次运行开始生效，并记录在审计日志中。启用四眼审批时，缩短保留期需要等待第二个用户批准；其他更改会立即保存。

副本（Proxmox VE）

Proxmox 虚拟机作业可以在您选择的节点上保留其客户机的已停止的最新副本，在客户机丢失时一键启动——参见 Proxmox VE → 复制。

速度限制

在作业表单的高级中，将上传速度限制为限制代理向存储发送数据的速度（MB/s）——例如 08:00 至 18:00 限制为 10 MB/s，使工作时间的备份不影响办公室线路的使用；在该时间段之外，作业以全速运行。时间为代理的本地时间，时间段可以跨越午夜（22:00 至 06:00）。该限制适用于备份和复制作业（上传到第二个存储），不适用于还原：还原始终以全速运行。

压缩和重复数据删除

每次备份都会进行重复数据删除：存储库中已有的数据——来自同一作业的早期备份，或同一存储目标上的其他作业——不会再次存储。新数据随后使用 zstd 压缩；无法变小的部分（视频、压缩包、加密文件）按原样存储。加密在压缩之后进行。

压缩级别是作业设置（编辑 → 高级）：

级别适用场景
标准（推荐）高速下的良好压缩；几乎适用于所有作业。
快速在繁忙或性能较弱的机器上占用更少 CPU；备份略大。
最大通常比标准小 5–15%，但压缩速度慢数倍。适用于慢速上行链路和付费云存储，且机器有富余 CPU 时。
关闭适用于已压缩的数据：节省 CPU，且不会让备份变大。

该级别从下次运行开始应用于新数据；现有备份保持不变，还原也从不依赖它。运行页面显示结果：新数据的压缩比（例如 2.4×）以及读取的数据中有多少已经存储过（重复数据删除）。

备份前后的命令

管理员可以让作业在每次备份前后在代理上运行命令——例如数据库转储、为获得一致副本而停止服务，或发送通知：

pg_dump -U postgres app > /var/backups/app.sql          # Linux, before
sqlcmd -S . -Q "BACKUP DATABASE app TO DISK='D:\dump\app.bak'"   # Windows, before
  • 命令以代理的服务帐户（Linux 上为 root，Windows 上为 SYSTEM）通过 sh 或 cmd 运行；允许多行。只有管理员可以查看和更改——否则备份操作员就能在每台机器上运行任意命令。
  • 如果之前的命令失败（退出代码不为 0）或运行时间超过时间限制（默认 30 分钟），则不运行备份，运行会失败并显示命令的输出。
  • 之后的命令在备份失败时也会运行，以便重新启动第一个命令停止的内容。备份后的命令失败会使运行变为警告。
  • 两者都会获得 BACKUPZIT_STAGE（pre 或 post）、BACKUPZIT_JOB、BACKUPZIT_JOB_ID、BACKUPZIT_RUN_ID，备份后还有 BACKUPZIT_STATUS（success、warning 或 failed）。
  • 运行页面会显示每个命令的结果和输出，命令成功时也会显示。
  • 对于虚拟机作业，命令在虚拟化主机（或 VMware 代理服务器）上运行，而不是在虚拟机内运行。复制作业没有命令。

运行、禁用、删除

  • 立即运行备份（复制作业为立即复制）会立即将作业加入队列。
  • 测试还原会还原最新备份的随机样本并进行验证（参见 还原）。
  • 禁用会暂停计划而不丢失作业（启用四眼审批时，需要第二个用户批准）。
  • 删除会移除作业；现有备份保留在存储上，仍可从“活动”中还原。

停止运行

排队中或正在运行的备份、复制或还原可以停止：在运行页面点击 取消 或 停止运行，或在作业页面点击 停止运行 #…。排队中的运行会立即取消；正在运行的由代理在几秒钟内停止——备份前的命令也会被终止，备份后的命令仍会执行。该运行的状态为 已取消（消息为“Cancelled by”加用户名）：在报告中不计为失败，不发送失败邮件，并记录到审计日志中。中途停止的备份不会用于还原。代理更新无法停止。

要一次性全部停止，请点击活动页面顶部的取消所有排队和运行中的运行并确认。只取消当时列表中排队或正在运行的运行（正在运行的会在几秒内停止）；今天稍后或其他日期计划的运行以及链式作业将照常开始。

作业表单 高级 中的 运行时间限制（小时） 会停止运行时间更长的备份或复制，并将其标记为失败；这种情况会发送失败通知。留空或 0 表示不限制。如果代理在 10 分钟内未确认停止，控制台会自行将该运行标记为失败。

保留已暂停

如果作业的某次备份看起来像勒索软件或大规模删除，作业页面会显示保留已暂停：在有人检查机器并点击已检查 — 恢复保留之前，不会删除任何备份（启用四眼审批时，需要第二个用户批准）。参见 勒索软件防护。

备份运行报告的内容

在 活动 中打开一次运行：文件数量、新增/更改的文件、读取的数据、上传的新数据（经过重复数据删除和压缩后，附带压缩比和已存储的比例——参见压缩）、持续时间以及无法读取的文件。包含无法读取文件的运行以警告状态结束——其余数据已备份。
