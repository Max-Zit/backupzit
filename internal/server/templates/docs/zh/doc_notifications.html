通知：电子邮件、Slack、Teams、Webhook

备份失败时收到电子邮件，每天早上收到每日摘要。

设置电子邮件

在 设置 → 电子邮件通知 中：

字段示例
SMTP 服务器 / 端口smtp.office365.com / 587，smtp.gmail.com / 587，内部中继 / 25
安全STARTTLS（端口 587）、TLS（端口 465）或无（仅限内部中继）
用户 / 密码用于发送的邮箱；匿名中继请留空。Microsoft 365 和 Gmail 需要应用密码。
发件人backup@example.com
收件人一个或多个地址，以逗号分隔。

使用 发送测试邮件 检查设置。

发送哪些内容

  • 失败（推荐）—— 每次运行失败发送一封邮件并说明原因：备份、复制、还原以及失败的还原测试。开启此项后，当备份看起来像勒索软件或大规模删除时，您还会收到 SUSPICIOUS 警报。
  • 警告 —— 有些文件无法读取的运行。
  • 成功 —— 每次成功的运行（通常太多；建议使用每日报告）。
  • 每日报告 —— 在所选时间发送：过去 24 小时的运行、问题和离线代理。主题以 OK、WARNINGS 或 ATTENTION 开头，便于邮件规则分类。

如需每周或每月摘要，请使用计划报告；它们使用相同的邮件设置发送，并有自己的收件人。主题以 [BackupZit] 开头，便于邮件规则分类。SMTP 密码加密存储。

Slack、Microsoft Teams 和 Webhook

在 设置 → 聊天和 Webhook 中可添加任意数量的通道；每个通道选择是否接收失败、警告和成功。异常备份（可能是勒索软件）计为失败。发送测试 会立即检查通道。

  • Slack：为频道创建 incoming webhook（Slack 应用设置 → Incoming Webhooks），并粘贴其 URL（https://hooks.slack.com/services/…）。
  • Microsoft Teams：在频道中添加工作流 Post to a channel when a webhook request is received，并粘贴其 URL。消息以卡片形式到达，卡片上有一个按钮可在控制台中打开该运行。
  • Webhook：任何接受 JSON POST 的 URL —— 工单系统、监控或自动化工具。配置签名密钥后，每个请求都带有 X-BackupZit-Signature: sha256=<hex>，即请求体的 HMAC-SHA256，接收方可据此验证请求来自您的控制台。

Webhook 的 JSON：

{"event": "run.finished", "run_id": 412, "kind": "vm-backup", "kind_title": "VM backup",
 "status": "failed", "suspicious": "", "job": "Proxmox VMs", "job_id": 7, "agent": "pve1",
 "message": "…", "errors": ["…"], "started_at": "2026-10-04T22:00:03+02:00",
 "finished_at": "2026-10-04T22:04:41+02:00", "url": "https://backup.example/runs/412"}

每次运行只发送一次消息，即使关闭了电子邮件也会发送。出错的通道（URL 错误、服务不可用）会记录在控制台日志中，不会耽误其他通道。Webhook URL 加密存储。
