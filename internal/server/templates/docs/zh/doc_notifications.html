通知：电子邮件、Slack、Teams、Webhook

备份失败时收到电子邮件，每天早上收到每日摘要。

设置电子邮件

在 设置 → 电子邮件通知 中勾选 发送电子邮件通知（不勾选则不会发送任何电子邮件），并填写：

字段示例
SMTP 服务器 / 端口smtp.office365.com / 587，smtp.gmail.com / 587，内部中继 / 25
安全STARTTLS（端口 587）、TLS（端口 465）或无（仅限无需登录的内部中继：用户名和密码绝不会以未加密方式发送）
用户名 / 密码用于发送的邮箱；无需登录的中继请留空。Gmail 需要应用密码；Microsoft 365 正在停用基本 SMTP 身份验证，使用 SMTP 中继或连接器更为稳妥。
发件人backup@example.com
收件人一个或多个地址，以逗号分隔。

使用 发送测试邮件 检查设置，然后单击 保存（测试不会保存设置）。电子邮件、聊天消息和报告使用同一表单中选择的语言（默认为保存设置时控制台的语言）。

发送哪些内容

  • 失败（推荐）—— 每次运行失败发送一封邮件并说明原因：备份、复制、还原以及失败的还原测试。开启此项后，当备份看起来像勒索软件或大规模删除时，您还会收到 SUSPICIOUS 警报。
  • 警告 —— 有些文件无法读取的运行。
  • 成功 —— 每次成功的运行（通常太多；建议使用每日报告）。
  • 每日报告 —— 在所选时间发送：过去 24 小时的运行、问题和离线代理。主题以 OK、WARNINGS 或 ATTENTION 结尾（例如 [BackupZit] Daily report 2026-11-17: OK），便于邮件规则分类。

开启失败后，未达到恢复点目标（RPO）的作业也会被通知——只通知一次，期间重新达标后才会再次通知。被用户停止的运行（状态已取消）不发送失败邮件；因时间限制而停止的运行会发送。

每个作业一封邮件,以及邮件过滤

同时打开成功,即可为每个作业的每次完成运行收到一封邮件(主题中包含作业和计算机),而不仅仅是每日摘要。如需每个作业一份摘要,请为该作业创建计划报告。主题使用邮件语言书写,因此为便于邮件规则,每封运行邮件还带有不随语言变化的标头:X-BackupZit-Status(success、warning 或 failed)、X-BackupZit-Job、X-BackupZit-Agent(控制台中显示的名称)、X-BackupZit-Host(计算机报告的主机名)、X-BackupZit-Kind 和 X-BackupZit-Run。看起来像勒索软件的备份还会带有 X-BackupZit-Suspicious: yes——不要让归档成功运行的规则把它隐藏。

无论这些选项如何，以下情况通知收件人也会收到邮件：

  • 某项更改等待第二位用户批准（四眼审批）；
  • 两台机器使用同一个代理注册；
  • 审计日志被更改；
  • 控制台自身的备份失败；
  • 浏览器 HTTPS 证书续订失败，或上传的证书将在 21 天内过期；
  • 有新的 BackupZit 版本可用（可在“设置 → 更新”中关闭），或控制台更新失败；
  • 某个地址因登录失败次数过多被封锁（可在暴力破解防护中关闭）。

如需每周或每月摘要，请使用计划报告；它们使用相同的邮件设置发送，并有自己的收件人。主题以 [BackupZit] 开头，便于邮件规则分类。SMTP 密码加密存储。邮件、聊天消息和报告中的链接指向您在浏览器中打开控制台所用的地址（或通过 --public-url 设置的地址）。

启用了带受信任证书的 HTTPS Web 端口时(设置 → 证书),邮件、聊天消息和报告中的链接使用该端口的地址,即使 8443 端口只服务代理。 否则使用 --public-url；如果也没有，则使用有权更改设置的用户最后一次打开控制台时的地址。

Slack、Microsoft Teams 和 Webhook

在 设置 → 聊天和 Webhook 中可添加任意数量的通道；每个通道选择是否接收失败、警告和成功。异常备份（可能是勒索软件）计为失败。发送测试 会立即检查通道。

  • Slack：为频道创建 incoming webhook（Slack 应用设置 → Incoming Webhooks），并粘贴其 URL（https://hooks.slack.com/services/…）。
  • Microsoft Teams：在频道中添加工作流 Post to a channel when a webhook request is received，并粘贴其 URL。消息以卡片形式到达，卡片上有一个按钮可在控制台中打开该运行。
  • Webhook：任何接受 JSON POST 的 URL —— 工单系统、监控或自动化工具。配置签名密钥后，每个请求都带有 X-BackupZit-Signature: sha256=<hex>，即请求体的 HMAC-SHA256，接收方可据此验证请求来自您的控制台。

Webhook 的 JSON：

{"event": "run.finished", "run_id": 412, "kind": "vm-backup", "kind_title": "VM backup",
 "status": "failed", "suspicious": "", "job": "Proxmox VMs", "job_id": 7, "agent": "pve1", "agent_id": 3,
 "message": "…", "errors": ["…"], "started_at": "2026-10-04T22:00:03+02:00",
 "finished_at": "2026-10-04T22:04:41+02:00", "duration_s": 278, "files": 4, "bytes": 85899345920,
 "bytes_read": 12884901888, "bytes_stored": 1073741824, "snapshot": "9f3c2a1b",
 "url": "https://backup.example/runs/412"}

duration_s 是运行耗时（秒）。对于备份，files 和 bytes 是被备份数据的大小，bytes_read 是读取的量，bytes_stored 是上传到存储的量；snapshot 是新备份的 ID。

错过恢复点目标的作业会发送 {"event": "rpo.missed", "job_id", "job", "agent", "rpo_hours", "last_good_backup", "url"}；空字段（例如 suspicious，或不属于任何作业的运行的作业字段）会被省略。Slack 和 Teams 的 URL 必须使用 https://。每次运行只发送一次消息，即使关闭了电子邮件也会发送。出错的通道（URL 错误、服务不可用）会记录在控制台日志中，不会耽误其他通道。Webhook URL 加密存储。
