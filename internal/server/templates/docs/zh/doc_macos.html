macOS 代理（Apple 芯片）

macOS 代理备份搭载 Apple 芯片的 Mac 上的文件和文件夹。它从首次启动起就作为服务运行，启动磁盘的每次备份都从 APFS 本地快照读取，并保留 Mac 的文件元数据。菜单栏 App 显示其状态，并引导用户授予只有用户本人才能授予的权限。

预览版。macOS 代理是 0.59 的新功能，由一位贡献者编写并在 Mac 上测试；我们自己的测试在构建流水线的 macOS 上运行。如有问题，请在 GitHub Issues 中报告。

要求

  • 搭载 Apple 芯片（M1 及更新，arm64）并运行 macOS 13 或更高版本的 Mac。Intel Mac 没有安装包。
  • Mac 上的管理员帐户，用于安装和注册。
  • 由 Mac 的用户授予完全磁盘访问权限：macOS 不允许其他任何人这样做，脚本和控制台都不行。
  • 与所有代理一样，Mac 必须能访问控制台的代理地址（通常为端口 8443）和存储。

安装

  1. 在 Agent 页面下载 macOS 代理 — Apple 芯片（backupzit-agent_version_darwin_arm64.pkg）。与 Windows 和 Linux 安装程序一样，它包含在控制台软件包中。
  2. 在 Mac 上打开 .pkg 并按照安装器操作。未使用 Apple Developer ID 签名的安装包会让 macOS 先要求确认：右键点按它并选择打开（在较新的 macOS 上：系统设置 → 隐私与安全性 → 仍要打开）。
  3. 安装器的最后一页会说明需要授予的权限，并打开菜单栏 App。

安装包安装的内容：

内容位置
代理程序/Library/BackupZit/bin/backupzit-agent
卸载程序/Library/BackupZit/uninstall.sh
菜单栏 App/Applications/BackupZit.app
代理服务（LaunchDaemon：以 root 身份运行，开机时启动，停止后自动重启）/Library/LaunchDaemons/com.backupzit.agent.plist
登录时启动的菜单栏 App（LaunchAgent）/Library/LaunchAgents/com.backupzit.tray.plist
配置（仅 root，注册时创建）/Library/Application Support/BackupZit/agent.json
日志/Library/Logs/BackupZit/agent.log

该程序不会加入 PATH：在“终端”中请使用其完整路径调用。

注册

即使 Mac 尚未注册，服务也已安装并在运行；一旦注册，它就开始工作。在 Agent 页面，创建注册令牌会在 Windows 和 Linux 的命令旁边显示 macOS 的命令。从以下三种方式中选择一种：

  1. 安装后在“终端”中（常用方式）： 
    sudo /Library/BackupZit/bin/backupzit-agent enroll --code "BZ1-..."
  2. 使用 MDM（Jamf、Intune、Mosyle……）：在安装安装包之前，由脚本将注册码写入一个属于 root 的文件： 
    echo "BZ1-..." | sudo sh -c 'umask 077; mkdir -p "/Library/Application Support/BackupZit"; cat > "/Library/Application Support/BackupZit/enroll-code"'
    然后部署安装包。安装时会用该注册码注册 Mac 并删除该文件。不属于 root 的文件会被忽略。这也是将已注册的 Mac 迁移到另一个控制台的方法。
  3. 软件包旁的文件：在 Mac 启动磁盘上与 .pkg 相同的文件夹中放一个写有代码的 backupzit-enroll.txt（例如 /Users/Shared；如果来自 U 盘或网络共享，请先把两者复制到 Mac 上：在这类卷上，任何文件都可以声称属于 root）。只有在 Mac 尚未注册、并且没有其他人可能写入它时才会使用：该文件属于 root 或 Mac 的管理员，只有一个名称且只有其所有者可以更改，其文件夹属于 root 或管理员，其他用户不能写入（或者像 /Users/Shared 那样设置了粘滞位）。

如果安装期间无法连接控制台，代理会保留注册码并不断重试。如果注册失败，原因记录在 /Library/Application Support/BackupZit/enroll-error.log 中；之后请在“终端”中注册。升级和重新安装会保留注册。

权限

macOS 会保护某些数据不被任何程序读取（即使以 root 身份运行），直到用户在“系统设置”中允许。只有坐在 Mac 前的用户才能授予这些权限；安装器的最后一页和菜单栏 App 会引导用户完成。

代理的完全磁盘访问权限

没有它，备份会缺少 macOS 保护的文件夹，并且不会创建 APFS 快照（参见备份的内容）。

  1. 打开系统设置 → 隐私与安全性 → 完全磁盘访问权限。
  2. 点按列表下方的 + 并输入密码。
  3. 按下 Command-Shift-G，输入 /Library/BackupZit/bin/backupzit-agent，按 Return 键，然后点按打开。
  4. 检查 backupzit-agent 旁边的开关已打开。

也可以不用 +，而是将文件拖入列表：在“访达”中选择前往 → 前往文件夹…，输入 /Library/BackupZit/bin，然后将 backupzit-agent 拖到列表上。

在后台运行的代理

安装后 macOS 会显示已添加后台项目。在系统设置 → 通用 → 登录项与扩展的允许在后台下，backupzit-agent 和 BackupZit 必须保持打开：关闭后，代理不会运行，也不会开始任何备份。

通知和登录时打开

  • 通知：在菜单栏 App 请求时允许，或稍后在系统设置 → 通知 → BackupZit（允许通知）中允许。备份失败时，App 会通过通知告知用户。
  • 登录时打开：只要 BackupZit 在登录项与扩展 → 允许在后台下处于打开状态，菜单栏 App 就会在每次登录时打开。

菜单栏 App 及其助手

菜单栏中的 BackupZit 图标显示代理的状态；其菜单包含针对 Mac 每个作业的 Back up now、Open console in browser 和 Hide this icon（直到下次登录；备份继续进行）。其 Permissions 部分列出后台运行的代理、完全磁盘访问权限、通知和登录时打开，每项都带有 ✅ 或 ❌。点按某一项会打开“系统设置”中相应的页面；缺少的权限还会在每次登录后通过对话框说明一次，并给出操作步骤。只要还缺少某项权限，它就会每隔几秒自动重新检查，因此一旦授予权限就会显示 ✅。代理也会在运行报告中向控制台报告缺少完全磁盘访问权限。

在“终端”中检查

/Library/BackupZit/bin/backupzit-agent status

普通用户也可以运行，它会显示控制台、作业以及 full disk access: granted 或 denied（并指出需要打开的程序）。

更新后的完全磁盘访问权限

macOS 将完全磁盘访问权限与程序的签名绑定。使用 Apple Developer ID 签名的安装包在更新后会保留该权限。没有 Developer ID 构建（ad hoc 签名）的安装包每次自更新都会失去该权限：备份会再次发出警告，菜单栏 App 会提示自更新以来完全磁盘访问权限已丢失。请重新授予：在完全磁盘访问权限列表中选择 backupzit-agent，点按 − 将其移除（关闭再打开开关是不够的），然后按上述方法用 + 重新添加。

备份的内容

Mac 代理与任何代理一样运行文件和文件夹作业：如 /Users、/Applications 或 / 等路径、{users} 路径（/Users/<name>/Documents）和通配符，也可以在使用 所有 macOS 代理 的多代理作业中使用。

APFS 本地快照

启动磁盘数据卷的每次文件备份都从 APFS 本地快照读取，这是 macOS 上相当于 Windows VSS 的机制：备份看到的每个文件都处于同一时刻的状态，包括程序仍在写入的文件。代理创建快照（tmutil localsnapshot），以只读方式挂载，从中读取文件，并在备份后卸载和删除它。崩溃遗留的快照会在下次启动时清理；Time Machine 自己的快照绝不会被触碰。运行报告显示 Read from an APFS local snapshot of /System/Volumes/Data.

快照需要服务（root）和完全磁盘访问权限。没有完全磁盘访问权限时，以及对于其他卷上的路径（/Volumes：外置磁盘、网络共享），文件会在没有快照的情况下读取，运行报告会说明这一点。

元数据

随每个文件和文件夹一起保存：所有者和组、权限、扩展属性（由 macOS 自行管理的 com.apple.provenance 除外）、硬链接、符号链接、BSD 文件标志（隐藏、锁定、nodump、append-only……；系统标志仅在代理以 root 身份运行时保存，服务即是如此）、创建时间以及精确到纳秒的修改时间。稀疏文件保持稀疏：在 APFS 上会重新打出其空洞。

保留为空的文件夹

已备份文件夹下的某些系统文件夹会保留为空文件夹：其他卷（/Volumes）、交换区（/System/Volumes/VM、/private/var/vm）、/System/Volumes 中的支持卷、/dev、临时文件（/private/tmp、/private/var/folders）、缓存（/Library/Caches、/System/Library/Caches、~/Library/Caches）、废纸篓（~/.Trash、.Trashes）、Spotlight、FSEvents、文稿版本以及本地和 HFS+ 的 Time Machine 备份。以 / 作为来源时，/ 已显示的数据卷文件夹（/Users、/Applications……）不会被读取两次。作为作业来源指定的文件夹总会被读取，例如 /Volumes/USB 或 ~/.Trash。

运行报告中的警告

没有完全磁盘访问权限时，无法读取 macOS 保护的文件夹：邮件、信息、Safari 浏览器、桌面和文稿、其他 App 的数据、可移除卷和网络卷。此时，来源涉及 /Users（/Users/Shared 除外）、/Library 或 /Volumes，或其上层文件夹（如 /）的备份会以警告 Full Disk Access is not granted to the BackupZit agent 结束。其他文件夹（例如 /opt/data）的备份不会发出警告。

还原

Mac 的文件与所有文件备份一样还原：整个备份或仅部分路径，还原到文件夹或原始位置，在该 Mac 或其他代理上；单个文件可以从控制台下载。在 Mac 上还原会重新设置上述元数据。与 Windows 和 Linux 一样，它只通过已打开的文件夹写入，绝不按路径写入，因此还原期间被放在路径中的链接不会被跟随。覆盖已锁定的文件进行还原时，会先清除其锁定和 append-only 标志，然后重新设置保存的标志（系统标志无法在运行中的 Mac 上清除）。

更新和卸载

与其他代理一样，Agent 页面也会为 Mac 提供更新到 version（参见 Agent）。代理从控制台下载 .pkg，根据已签名的代理安装程序列表及其 SHA-256 校验和进行检查，在一次性的 launchd 作业中使用 Apple 的 installer 安装，然后以新版本重启。如果 launchd 拒绝该作业，更新运行会失败并显示 launchd 的消息。安装程序日志位于 /Library/Application Support/BackupZit/updates。更新未签名的安装包后，请检查完全磁盘访问权限。

在 Agent 页面上使用移除并选择从计算机卸载代理，会移除程序、菜单栏 App、LaunchDaemon 和 LaunchAgent 以及安装包回执；配置和日志会保留。手动卸载：

sudo /Library/BackupZit/uninstall.sh            # keeps configuration and log
sudo /Library/BackupZit/uninstall.sh --purge    # deletes them too

不带 --purge 时，注册会被搁置（agent.json.removed-date），因此重新安装会再次要求注册码。卸载后，请手动从隐私与安全性 → 完全磁盘访问权限中移除 backupzit-agent：macOS 不允许程序这样做。

Mac 代理不能做什么

Mac 上不支持替代方案
Linux 系统 / 裸机备份控制台会拒绝为 Mac 创建系统作业（is a Mac: back it up with a files job）：其系统卷由 Apple 密封并签名，应重新安装而不是还原。请用文件作业备份数据。
磁盘映像仅限 Windows。
Hyper-V、Proxmox VE 主机和 VMware ESXi 代理服务器Hyper-V 主机（Windows）、Proxmox 节点（Linux）上的代理或 Linux 代理服务器。
NAS / 文件共享作业（SMB、NFS）目前请使用 Windows 或 Linux 代理：Mac 代理尚不能挂载共享。
PostgreSQL / MySQL 作业尚未在 macOS 上验证：请先测试还原，再在 Mac 上使用。

Microsoft 365 作业可在任何能访问互联网的代理上运行，Mac 也可以。

故障排除

情况处理方法
Mac 未出现或显示为离线检查它是否已注册（backupzit-agent status，注册），以及 backupzit-agent 在登录项与扩展 → 允许在后台下是否已打开。sudo launchctl print system/com.backupzit.agent 显示服务；sudo /Library/BackupZit/bin/backupzit-agent service start 启动服务。然后像对任何代理一样检查到控制台的网络路径（故障排除）。
“Full Disk Access is not granted to the BackupZit agent”，full disk access: denied按照完全磁盘访问权限中的步骤授予。
更新后完全磁盘访问权限丢失安装包未使用 Apple Developer ID 签名：用 − 从列表中移除 backupzit-agent，然后重新添加（更新后的完全磁盘访问权限）。
运行显示文件是“without a snapshot”读取的“No APFS local snapshot … was taken”：授予完全磁盘访问权限。“Not on the startup disk's data volume”：该路径位于外置磁盘或共享上，APFS 本地快照不覆盖它；它仍会被备份。其他原因见消息。
更新运行失败运行会显示原因，例如 launchd 拒绝了安装程序作业。安装程序的输出位于 /Library/Application Support/BackupZit/updates（Agent 页面上的获取日志也包含它）。手动安装较新的 .pkg 也可以；注册会保留。
Mac 的系统作业被拒绝这是预期行为：参见 Mac 代理不能做什么。

日志

  • 代理：/Library/Logs/BackupZit/agent.log（也会列在“控制台”App 中）；崩溃跟踪写入 /Library/Logs/BackupZit/launchd.log。
  • 安装器执行的注册：/Library/Application Support/BackupZit/enroll-error.log 和安装器日志 /var/log/install.log。
  • 更新：/Library/Application Support/BackupZit/updates。
  • Agent 页面上的获取日志会从控制台获取日志末尾（参见 日志）。
