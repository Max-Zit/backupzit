存储目标

存储目标是代理写入备份的位置。每个代理在目标位置下使用自己的存储库。

选择存储类型

类型适用于说明
SFTP任何带 SSH 的 Linux 服务器或 NAS加密传输；服务器的主机密钥会被固定。
S3 兼容异地 / 云副本：AWS S3、Wasabi、Backblaze B2、MinIO、Ceph、Google Cloud Storage通过 Object Lock 支持不可变性。
Azure Blob Storage以 Microsoft 为中心的公司的异地副本帐户密钥或 SAS 令牌；通过 Azure 的版本级不可变策略实现不可变性。
SMB 共享Windows 文件服务器、Synology/QNAP NASSMB 2/3；代理自行登录，无需映射驱动器。
加固存储库防勒索软件的本地存储运行 backupzit-repo 的 Linux 服务器；备份在其不可变期结束前无法删除。
轮换 USB 磁盘小型办公室的离线副本：两块或更多磁盘每周轮换按卷标（BZBACKUP1、BZBACKUP2 …）识别，而不是按驱动器号。
本地 / 挂载路径USB 磁盘、第二块磁盘，或挂载在代理上的 NFS/iSCSI 卷代理看到的路径，例如 E:\Backups 或 /mnt/backup。

3-2-1 规则：保留 3 份数据副本，存放在 2 种不同介质上，其中 1 份异地存放——例如一个作业备份到本地 NAS，另一个备份到 S3 或另一栋楼中的加固存储库。

测试连接

添加存储目标时，控制台会立即用输入的凭据进行测试：写入一个小文件、读回并删除。在不可变存储（启用 Object Lock 的 S3、加固存储库）上，它只登录并列出内容，以免留下被锁定的数据；对于 S3，在要求不可变性时还会检查存储桶是否启用了 Object Lock。无论结果如何目标都会被保存，并显示测试结果——错误的密码、主机密钥、存储桶或共享会立即暴露，而不是等到第一次备份。存储页面上的测试连接可重复测试。控制台从其自身网络进行测试；备份由代理写入，因此只有代理能访问的目标（本地或 USB 磁盘）由第一次备份来测试。

SFTP

位置：sftp://user@host:22/path（相对于用户主目录的路径请使用 /~/path）。输入密码或私钥，以及服务器的主机密钥指纹，可在服务器上通过以下命令获取：

ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub

创建一个只能写入备份文件夹的专用用户。

S3 兼容

输入端点（例如 s3.eu-central-1.amazonaws.com、s3.wasabisys.com、10.0.0.5:9000）、存储桶、可选文件夹，以及对该存储桶具有读写权限的访问密钥。仅在本地 MinIO 没有证书时才勾选明文 HTTP。

不可变备份（Object Lock）

创建存储桶时启用 Object Lock，并勾选不可变备份 … N 天。代理写入的每个文件都会以合规模式锁定 N 天（另加 1 天余量）：在此之前，任何人——无论是持有密钥的攻击者还是存储桶所有者——都无法删除或覆盖它。每次备份后，从旧备份复用的数据的锁定期会被延长，因此每个还原点在整个期限内都受到保护。

删除（由保留策略或攻击者执行）只会添加一个“删除标记”。请添加一条生命周期规则，让非当前版本在一天后过期，以便锁定结束后释放空间。参见 勒索软件防护。

Google Cloud Storage

Google Cloud Storage 通过其互操作性 API 作为 S3 兼容目标使用：

  1. 在 Google Cloud 控制台中打开 Cloud Storage → Settings → Interoperability，为在该存储桶上拥有 Storage Object Admin 角色的服务帐号创建 HMAC 密钥。
  2. 添加 S3 目标，端点为 storage.googleapis.com，填写存储桶名称、HMAC 访问密钥和密钥，区域为 auto。

Google Cloud Storage 不提供 S3 Object Lock 选项；如需不可变性，请在 Google Cloud 中设置存储桶保留政策（并锁定）。删除的备份将保留到保留期结束。

Azure Blob Storage

  1. 在 Azure 门户中创建一个存储帐户（StorageV2，任意冗余）和一个容器，例如 backups。
  2. 添加 Azure Blob Storage 目标，填写帐户名、容器和可选文件夹。
  3. 使用访问密钥（存储帐户 → 访问密钥）进行身份验证，或者使用权限更受限的容器 SAS 令牌，具备读取、写入、删除和列出权限以及合适的有效期。

如需勒索软件防护，请在容器上启用带有基于时间的保留策略的版本级不可变性；被删除或覆盖的备份在此期间仍可恢复。高级中的端点字段仅用于 Azure Government/China、Azure Stack Hub 或 Azurite 模拟器。

轮换 USB 磁盘

断开连接并带离办公室的磁盘是小型办公室防范勒索软件、火灾和盗窃最简单的方式。BackupZit 通过卷标找到磁盘，无论 Windows 分配了哪个驱动器号：

  1. 将两块或更多磁盘格式化为 NTFS（Linux：ext4），并命名为 BZBACKUP1、BZBACKUP2、…（Windows：右键单击驱动器 → 属性 → 名称）。
  2. 添加类型为轮换 USB / 可移动磁盘的存储目标，卷标为 BZBACKUP*。
  3. 创建一个备份到该目标的备份作业——或者更好的是，创建一个备份复制作业，将 NAS 或云作业复制到磁盘。
  4. 定期（例如每周）轮换磁盘，并将断开的磁盘存放在安全的地方。
  • 每块磁盘都包含完整、独立的备份，有各自的保留策略；所有磁盘都使用该目标的恢复密钥加密。
  • 运行记录会显示使用了哪块磁盘（磁盘 BZBACKUP2）。还原时会准确要求这块磁盘，并告诉您当前连接的是哪块。
  • 如果没有连接磁盘，运行会失败并显示明确的消息和警报——提醒您重新插入磁盘。
  • 一次只连接一块磁盘。

SMB 共享

服务器、共享、可选文件夹、用户、密码以及（域帐户的）域。代理自行使用这些凭据连接，因此对以 SYSTEM 身份运行的服务同样有效。

加固存储库

在专用 Linux 服务器上安装 backupzit-repo 软件包，然后在该服务器上运行：

backupzit-repo add-key office-console     # shows the access key once
backupzit-repo fingerprint                # certificate fingerprint

在控制台中输入服务器地址、访问密钥和指纹。不可变期在存储库服务器上配置（/etc/backupzit-repo/repo.env），无法从控制台或代理更改。详情见 勒索软件防护。

加密和恢复密钥

启用加密备份（默认）时，存储库中的所有内容——文件内容、文件名、文件夹结构、快照列表——在离开代理前都会使用 AES-256-GCM 加密。存储提供商只能看到随机数据。

创建加密目标时，控制台会显示恢复密钥，并提供恢复单供下载。

请打印恢复单或将其保存在密码管理器中，并与备份分开存放。如果控制台丢失，只需恢复密钥加上存储位置和凭据即可还原。没有密钥，任何人都无法读取加密的备份——包括 BackupZit 支持人员。

以后可以通过存储列表中的恢复密钥再次显示密钥；此操作会被记录。

存储列表

列表显示每个目标的类型、位置、加密情况（管理员可访问恢复密钥）和不可变性：S3 显示 Object Lock 期限，加固存储库显示在存储库服务器上设置。凭据保存后不会再显示，并以加密方式存储。只有管理员可以添加或移除目标以及查看恢复密钥。

存储使用情况和预测

每次备份（及其保留处理）后，代理会报告其存储库占用的空间，并且——对于本地和 USB 磁盘、SFTP 服务器（OpenSSH 的 statvfs 扩展）以及 SMB 共享——报告存储的大小和可用空间。在 存储 → 存储使用情况 下，每个目标显示：

  • 其上所有存储库占用的空间（每个代理一个；轮换 USB 磁盘按每块磁盘分别计算）；
  • 对于大小已知的存储，其使用率（75% 起显示黄色，90% 起显示红色），图表中以红色虚线表示容量；
  • 最近 90 天的图表，以及在一周的备份之后，每日增长量（最近 30 天的线性趋势），以虚线向前绘制 30 天，并显示存储何时会满——或者在大小未知时，显示 90 天后的预计用量。

当存储目标已满 90% 或将在 30 天内用满时，仪表板上的需要关注会发出警告。S3 和 Azure 没有固定大小；那里只显示已用空间及其增长。已用空间是存储的（压缩、加密、去重后的）数据；存储因其他原因保留的文件（对象版本、其他程序）不计算在内。

移除目标

从控制台移除存储目标不会删除存储上的任何数据。启用四眼审批时，需要第二个用户先批准。
