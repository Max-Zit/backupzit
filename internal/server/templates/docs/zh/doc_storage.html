存储目标

存储目标是代理写入备份的位置。每个代理在目标位置下使用自己的存储库。

选择存储类型

类型适用于说明
SFTP任何带 SSH 的 Linux 服务器或 NAS加密传输；服务器的主机密钥会被固定。
S3 兼容异地 / 云副本：AWS S3、Wasabi、Backblaze B2、MinIO、Ceph、Google Cloud Storage通过 Object Lock 支持不可变性。
Azure Blob Storage以 Microsoft 为中心的公司的异地副本帐户密钥或 SAS 令牌；通过 Azure 的版本级不可变策略实现不可变性。
SMB 共享Windows 文件服务器、Synology/QNAP NASSMB 2/3；代理自行登录，无需映射驱动器。
加固存储库防勒索软件的本地存储运行 backupzit-repo 的 Linux 服务器；备份在其不可变期结束前无法删除。
轮换 USB 磁盘小型办公室的离线副本：两块或更多磁盘每周轮换按卷标（BZBACKUP1、BZBACKUP2 …）识别，而不是按驱动器号。
本地 / 挂载路径USB 磁盘、第二块磁盘，或挂载在代理上的 NFS/iSCSI 卷代理看到的路径，例如 E:\Backups 或 /mnt/backup。在该文件夹下，代理只使用真实的文件夹和文件：指向其外部的链接、指向文件夹的链接、联接（junction）以及其中的装载点都会被忽略（0.59）。

3-2-1 规则：保留 3 份数据副本，存放在 2 种不同介质上，其中 1 份异地存放——例如一个作业备份到本地 NAS，另一个备份到 S3 或另一栋楼中的加固存储库。

测试连接

添加存储目标时，会立即用输入的凭据进行测试：写入一个小文件、读回并删除。在不可变存储（启用 Object Lock 的 S3、加固存储库）上，测试只登录并列出内容，以免留下被锁定的数据；对于 S3，在要求不可变性时还会检查存储桶是否启用了 Object Lock。无论结果如何目标都会被保存，并显示测试结果——错误的密码、主机密钥、存储桶或共享会立即暴露，而不是等到第一次备份。存储页面上的测试连接可重复测试。

测试在您选择的位置运行：添加目标时在测试连接的位置下选择，或在测试连接打开的页面上选择。此控制台从控制台自身的网络进行测试。代理从其所在的网络进行测试；当控制台运行在别处（例如 VPS 上）而存储位于客户网络中时，起决定作用的正是这一点（代理 0.60.0 或更新版本；恢复介质除外）。页面会推荐最近一次备份使用过该目标的代理。在代理上，测试是一次步骤相同的短运行（“活动”中的连接测试）；繁忙的代理会在备份的同时运行它。页面会等待测试完成，随后存储页面显示结果。本地或 USB 磁盘只能由其代理访问，由第一次备份进行测试。

失败的测试（无论在控制台上还是在代理上）还会连同目标、其类型、测试运行位置和错误一起写入控制台日志（storage connection test failed），以便日后查找，例如在设置 → 诊断下。

仅代理可访问的存储

客户网络中的 NAS、SFTP 服务器或加固存储库通常可由该站点的代理访问，但控制台无法访问，而且不应将其暴露到互联网。添加此类目标时勾选仅代理可访问，或在列表中现有目标旁点击仅代理可访问（允许控制台连接可再次关闭该选项）。列表会将该目标标记为仅代理。备份、还原、还原测试、数据检查和保留照常在代理上运行；只是控制台自身不再连接该存储：

  • 控制台在添加时及之后都不会测试它；测试连接只提供代理可选；
  • 查找备份通过代理搜索它，与本地磁盘和 USB 磁盘相同；
  • 它不会出现在控制台备份的可选目标中，控制台备份所用的目标也不能启用此选项；
  • 浏览其备份中的文件和下载单个文件会通过使用该存储的代理进行：创建该备份的代理，若它离线，则由曾使用此存储的另一个在线代理进行（代理 0.61 及更高版本；在代理收到请求之前，第一个页面最多可能需要半分钟）。对于较旧的代理，请改用仅这些路径进行还原（参见“还原”）；
  • 移除代理时，控制台不会删除其在该存储上的备份；请直接在存储上删除该文件夹。

SFTP

位置：sftp://user@host:22/path（相对于用户主目录的路径请使用 /~/path）。输入密码或私钥，以及服务器的主机密钥指纹，可在服务器上通过以下命令获取：

ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub

创建一个只能写入备份文件夹的专用用户。

S3 兼容

输入端点（例如 s3.eu-central-1.amazonaws.com、s3.wasabisys.com、10.0.0.5:9000）、存储桶、可选文件夹，以及对该存储桶具有读写权限的访问密钥。仅在本地 MinIO 没有证书时才勾选明文 HTTP。

对象存储偶尔会响应缓慢或返回临时错误。代理最多等待五分钟的响应,遇到超时、连接中断、读取不完整、服务器错误和限流(SlowDown)时,会以逐渐增长的间隔重试多次,然后备份或恢复才会放弃。重新发送某个部分是安全的,启用 Object Lock 时也是如此。 每次上传都带有由提供商验证的校验和（Content-MD5），每次上传后代理都会检查已存储对象的大小：到达时不完整的对象会重新上传（代理 0.54.2 及更高版本）。

在 S3、Azure 和加固存储库上，代理最多同时上传四个包，虚拟机和磁盘恢复最多预读四个块，这对远程或较慢的服务商帮助最大。带宽限制仍然对总量有效。SFTP、SMB 以及本地或 USB 磁盘可同时接收两个包（代理 0.62 及更高版本），因此在写入一个包的同时可以填充下一个包，还原时也会从中最多预读三个块（代理和恢复介质 0.61 及更高版本），因此网络和目标磁盘可以同时工作；文件还原同样会预读大文件的各个部分，检查全部数据时会同时读取多个包（0.62）。大型存储库的索引在这些存储上也会每次读取八个文件；在此期间，代理日志会显示 "loading the repository index" 及进度。

不可变备份（Object Lock）

创建存储桶时启用 Object Lock，并勾选不可变备份 … N 天。代理写入的每个文件都会以合规模式锁定 N 天（另加 1 天余量）：在此之前，任何人——无论是持有密钥的攻击者还是存储桶所有者——都无法删除或覆盖它。每次备份后，从旧备份复用的数据的锁定期会被延长，因此每个还原点在整个期限内都受到保护。代理每次同时延长 16 个对象，并在自己的文件夹中记住已知的锁定日期，因此重启或更新后不会重新检查每个对象。代理首先读取作业保留的备份，每次同时读取多个树和块映射（运行会显示 正在为对象锁定读取保留的备份：已读取 N），然后运行会显示 正在延长对象锁定 N / M；代理日志会记录每个步骤耗时多久。

还要为存储桶设置至少 N 天、合规模式的默认保留（AWS：Object Lock → Default retention；MinIO：mc retention set --default COMPLIANCE 30d）。这样存储桶会自行锁定每个新对象，即使被入侵的计算机写入时未加锁。若默认保留缺失或短于 N 天，目标的连接测试会发出警告。

删除（由保留策略或攻击者执行）只会添加一个“删除标记”。请添加一条生命周期规则，让非当前版本在一天后过期，以便锁定结束后释放空间。参见 勒索软件防护。

Backblaze B2

  1. 在 Backblaze 中打开 Application Keys，创建一个对该存储桶有读写权限的应用密钥。B2 的 S3 API 不接受账户的主密钥（master key）：此时 BackupZit 会报告 Malformed Access Key Id。
  2. 添加一个 S3 目标：使用存储桶页面上显示的 S3 端点，例如 s3.us-west-004.backblazeb2.com（不含存储桶名称），填写存储桶名称，以应用密钥的 keyID 作为访问密钥、其 applicationKey 作为秘密密钥，并填写端点中的区域（us-west-004）。

与密钥一起复制的空格和换行会在保存目标时去除。如需不可变性，请创建启用了 Object Lock 的存储桶。

Google Cloud Storage

Google Cloud Storage 通过其互操作性 API 作为 S3 兼容目标使用：

  1. 在 Google Cloud 控制台中打开 Cloud Storage → Settings → Interoperability，为在该存储桶上拥有 Storage Object Admin 角色的服务帐号创建 HMAC 密钥。
  2. 添加 S3 目标，端点为 storage.googleapis.com，填写存储桶名称、HMAC 访问密钥和密钥，区域为 auto。

Google Cloud Storage 不提供 S3 Object Lock 选项；如需不可变性，请在 Google Cloud 中设置存储桶保留政策（并锁定）。删除的备份将保留到保留期结束。

Azure Blob Storage

  1. 在 Azure 门户中创建一个存储帐户（StorageV2，任意冗余）和一个容器，例如 backups。
  2. 添加 Azure Blob Storage 目标，填写帐户名、容器和可选文件夹。
  3. 使用访问密钥（存储帐户 → 访问密钥）进行身份验证，或者使用权限更受限的容器 SAS 令牌，具备读取、写入、删除和列出权限以及合适的有效期。

如需勒索软件防护，请在容器上启用带有基于时间的保留策略的版本级不可变性；被删除或覆盖的备份在此期间仍可恢复。高级中的端点字段仅用于 Azure Government/China、Azure Stack Hub 或 Azurite 模拟器。

轮换 USB 磁盘

断开连接并带离办公室的磁盘是小型办公室防范勒索软件、火灾和盗窃最简单的方式。BackupZit 通过卷标找到磁盘，无论 Windows 分配了哪个驱动器号：

  1. 将两块或更多磁盘格式化为 NTFS（Linux：ext4），并命名为 BZBACKUP1、BZBACKUP2、…（Windows：右键单击驱动器 → 属性 → 名称）。
  2. 添加类型为轮换 USB / 可移动磁盘的存储目标，卷标为 BZBACKUP*。
  3. 创建一个备份到该目标的备份作业——或者更好的是，创建一个备份复制作业，将 NAS 或云作业复制到磁盘。
  4. 定期（例如每周）轮换磁盘，并将断开的磁盘存放在安全的地方。
  • 每块磁盘都包含完整、独立的备份，有各自的保留策略；所有磁盘都使用该目标的恢复密钥加密。
  • 运行记录会显示使用了哪块磁盘（磁盘 BZBACKUP2）。还原时会准确要求这块磁盘，并告诉您当前连接的是哪块。
  • 如果没有连接磁盘，运行会失败并显示明确的消息和警报——提醒您重新插入磁盘。
  • 一次只连接一块磁盘。

SMB 共享

服务器、共享、可选文件夹、用户、密码以及（域帐户的）域。代理自行使用这些凭据连接，因此对以 SYSTEM 身份运行的服务同样有效。

SMB 账户除了能够创建、读取和删除文件外，还必须能够通过重命名临时文件来替换仓库中的现有文件。这样，锁的刷新会以原子方式可见。替换失败时会返回写入错误，并保留原来的文件。 如果无法读取仓库锁，维护操作会停止，而不会假定锁不存在。

加固存储库

在专用 Linux 服务器上安装 backupzit-repo 软件包，然后在该服务器上运行：

backupzit-repo add-key office-console     # shows the access key once
backupzit-repo fingerprint                # certificate fingerprint

在控制台中输入服务器地址、访问密钥和指纹。不可变期在存储库服务器上配置（/etc/backupzit-repo/repo.env），无法从控制台或代理更改。详情见 勒索软件防护。

访问密钥可以绑定到存储库的一个路径并加以限制。为每台计算机配置自己的存储目标和密钥，这样被入侵的计算机只能访问它自己的备份：

backupzit-repo add-key pc-anna --path office/pc-anna --quota 500G --daily 100G --rate 600
backupzit-repo set-key pc-anna --quota 1T     # 修改限制；none 表示取消
backupzit-repo keys                           # 密钥及其限制

使用 --path 后，对该密钥而言 hardened://server/office/pc-anna 之外的内容都不存在。--quota 限制该路径下存储的数据（已删除但仍在保留期内的文件也计入），--daily 限制每天（UTC）的新数据，--rate 限制每分钟的写入请求。限制只会拒绝新的上传，备份随之失败并给出提示；它从不删除或缩短任何内容，读取和还原也从不受限。不带选项时密钥没有限制，因此不会意外阻止较大的首次备份。

加密和恢复密钥

启用加密备份（默认）时，存储库中的所有内容——文件内容、文件名、文件夹结构、快照列表——在离开代理前都会使用 AES-256-GCM 加密。存储提供商只能看到随机数据。

创建加密目标时，控制台会显示恢复密钥，并提供恢复单供下载。

请打印恢复单或将其保存在密码管理器中，并与备份分开存放。如果控制台丢失，只需恢复密钥加上存储位置和凭据即可还原。没有密钥，任何人都无法读取加密的备份——包括 BackupZit 支持人员。

以后可以通过存储列表中的恢复密钥再次显示密钥；此操作会被记录。

要读取之前使用已知密钥创建的备份（例如在没有控制台备份的情况下重装控制台后），请在使用相同位置和凭据添加目标时，将其填入现有恢复密钥，然后使用查找备份。

存储列表

列表显示每个目标的类型、位置、加密情况（管理员可访问恢复密钥）和不可变性：S3 显示 Object Lock 期限，加固存储库显示在存储库服务器上设置。仅代理可访问的存储标记为仅代理，列表下方附有说明。凭据保存后不会再显示，并以加密方式存储。只有管理员可以添加或移除目标以及查看恢复密钥。

在存储上查找备份

存储列表中的查找备份会在目标上搜索控制台不认识的存储库：之前移除的代理的存储库，或由其他控制台创建的存储库（例如重装之前）。它列出每个文件夹及其计算机、作业（按备份内容命名）、备份数量和日期；无法读取的文件夹会被标记，例如使用其他恢复密钥加密的文件夹。添加所选备份会将它们记录为以该计算机命名的已移除代理的历史：它们显示在“Agent”页面的保留了备份的已移除代理下以及“活动”中（触发方式为已导入），可恢复到任何代理、关联到该计算机的代理或删除（参见“Agent”）。存储上的内容不会被更改。控制台已有的存储库不会列出；重复添加不会添加任何内容。

网络存储由控制台从其自身网络搜索，因此控制台必须能访问该存储。本地磁盘或 USB 磁盘由其所连接计算机上的代理搜索：请在搜索页面选择该代理（代理 0.44.0 或更新版本）；对于轮换使用的 USB 磁盘，搜索的是当时连接的磁盘。仅代理可访问的存储由您选择的代理搜索，该代理使用目标的凭据登录（代理 0.60.0 或更新版本）；最近一次备份使用过该目标的代理排在最前。VMware 连接和 Microsoft 365 租户的备份可以恢复，但不能关联到代理。

存储目标上的虚拟机备份

存储列表中的虚拟机备份会显示目标上所有具有恢复点的虚拟机和容器及其时间和大小，也包括作业已被删除或不再选择它们的虚拟机。这些虚拟机会标记为无作业，并在仪表板的需要关注中列出：在有人删除之前，它们会一直占用存储。只包含该虚拟机的恢复点可以在那里删除：勾选它，然后用密码或双重验证码确认（启用四眼审批时，需先由另一位用户批准）；控制台会释放只有它使用的空间，审计日志会显示结果。虚拟机作业每次运行会为其所有虚拟机写入一个备份，因此同时包含其他虚拟机的恢复点会一直保留，直到作业的保留策略将其删除；其他虚拟机的历史记录永远不会受到影响。如果该作业已被删除，就不会再为它运行保留策略：此时可以在那里删除整个恢复点，连同其中其他虚拟机的备份，页面会在旁边列出这些虚拟机。不可变存储（Object Lock、加固存储库）在锁定到期之前会拒绝删除。控制台只在它自己能访问的存储上删除；对于代理计算机的磁盘、使用 SSH 密钥登录或仅代理可访问的存储，备份由作业的保留策略删除。

存储使用情况和预测

每次备份（及其保留处理）后，代理会报告其存储库占用的空间，并且——对于本地和 USB 磁盘、SFTP 服务器（OpenSSH 的 statvfs 扩展）以及 SMB 共享——报告存储的大小和可用空间。在 存储 → 存储使用情况 下，每个目标显示：

  • 其上所有存储库占用的空间（每个代理一个；轮换 USB 磁盘按每块磁盘分别计算）；
  • 对于大小已知的存储，其使用率（75% 起显示黄色，90% 起显示红色），图表中以红色虚线表示容量；
  • 最近 90 天的图表，以及在一周的备份之后，每日增长量（最近 30 天的线性趋势），以虚线向前绘制 30 天，并显示存储何时会满——或者在大小未知时，显示 90 天后的预计用量。

当存储目标已满 90% 或将在 30 天内用满时，仪表板上的需要关注会发出警告。S3 和 Azure 没有固定大小；那里只显示已用空间及其增长。已用空间是存储的（压缩、加密、去重后的）数据；存储因其他原因保留的文件（对象版本、其他程序）不计算在内。

移除目标

仍被作业使用的存储目标无法移除。从控制台移除存储目标不会删除存储上的任何数据，但控制台会忘记其凭据和恢复密钥，因此其备份将无法再从控制台还原——请先下载恢复单。启用四眼审批时，需要第二个用户先批准。
