Linux 系统备份和 P2V

Linux 系统作业会备份整台 Linux 机器，以便在空磁盘上重建它 —— 磁盘故障后的同一台机器、新硬件，或 Proxmox VE 中的虚拟机（物理到虚拟，P2V）。

备份内容

  • 每个本地文件系统（ext2/3/4、xfs、vfat），包括 LVM 上的文件系统，逐个文件备份，并保留所有者、权限、setuid 位、ACL、扩展属性（SELinux 标签、文件 capabilities）、硬链接和设备文件。每个文件系统单独备份；网络共享和虚拟文件系统（/proc、/sys、/run）会被跳过。
  • 磁盘布局：带 ID 的 GPT 或 MBR 分区表、LVM 卷组（vgcfgbackup）、文件系统 UUID、标签和磁盘特性，以及引导代码（MBR 和 GRUB 的 BIOS 引导分区）。

与 Relax-and-Recover 一样，BackupZit 不会逐块复制正在运行的磁盘：Linux 没有内置的运行中磁盘快照，因此原始复制会不一致。每个文件都被完整读取，而布局信息使还原后的磁盘能够再次引导。数据库应在备份前导出，或使用其自身的工具备份。

单个文件和文件夹可以像任何文件备份一样从系统备份中还原（运行页面上的 从此备份还原文件）。

暂不支持

加密磁盘（LUKS）、软件 RAID（mdadm）、btrfs 以及分布在多块磁盘上的系统。作业会明确报告这些情况，而不是创建不完整的备份。

还原整个系统

打开系统备份的运行（作业页面或 活动），使用 还原整个系统：

作为新的 Proxmox 虚拟机

选择 Proxmox 节点（由其 BackupZit 代理执行）、存储、虚拟机 ID、名称、内存和核心数。BackupZit 会使用与原机相同的固件（UEFI/OVMF 或 BIOS）创建虚拟机，配备 VirtIO SCSI 磁盘和网卡，重建磁盘，还原所有文件，并可启动虚拟机。由于该虚拟机是可与原机并行运行的副本：

  • 绑定到旧 MAC 地址的网络设置（在云镜像中很常见：netplan match: macaddress）会被改为适用于任意有线接口，
  • 副本中的 BackupZit 代理会被取消注册，因此不会冒充原机器上报。

到磁盘

还原到 Linux 代理的空磁盘，例如第二块磁盘（/dev/sdb），或还原到新机器本身（裸机）：

  1. 在 恢复 页面下载 Linux 恢复 ISO 并创建恢复代码。将 ISO 写入 U 盘（Rufus、balenaEtcher）或挂载到虚拟机。它可在 BIOS 和 UEFI 机器上启动。
  2. 从它启动机器。恢复系统会启动代理，代理使用另一个 U 盘或磁盘上的 backupzit/recovery.json 连接控制台，或者询问服务器地址和恢复代码。
  3. 机器会显示为 恢复 代理。在系统备份的运行中选择 到磁盘、该代理及其磁盘（通常是 /dev/sda、/dev/nvme0n1 或 /dev/vda）。

任何 Linux Live 系统也可以：在其中用 sudo backupzit-agent recovery --server https://console:8443 --token CODE 启动代理；缺少所需工具（gdisk、LVM、mkfs）时会给出名称。如果机器不是原机器，请勾选 不同硬件。

目标磁盘可以比原磁盘大或小：最后一个分区会扩展以填满磁盘，或在数据能放下的前提下缩小。文件系统 UUID 和分区 ID 保持不变，因此 /etc/fstab 和引导加载程序无需修改。对于 UEFI 系统，引导加载程序还会安装到可移动介质路径 \EFI\BOOT\BOOTX64.EFI，任何 UEFI 固件都可在没有引导项的情况下启动它。类 RHEL 系统（dracut）迁移到不同硬件时会获得包含所有驱动程序的新 initramfs。

命令行

backupzit-agent system-backup  --repo ... [--exclude PATTERN]
backupzit-agent system-show    --repo ... latest
backupzit-agent system-restore --repo ... --target /dev/sdb [--new-hardware] --yes-erase-target latest
