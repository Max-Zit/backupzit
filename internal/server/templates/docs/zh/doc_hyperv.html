Hyper-V 虚拟机

BackupZit 通过 Hyper-V 主机上的代理备份 Hyper-V 虚拟机；虚拟机内部无需安装任何东西。Windows 和 Linux 来宾在保持运行的情况下被捕获。您可以将其还原为新虚拟机，或替换原虚拟机。

设置

  1. 从 Agent 页面在 Hyper-V 主机上安装 Windows 代理 MSI 并注册。支持的主机：带 Hyper-V 角色的 Windows Server 2016 或更高版本，或启用了 Hyper-V 的 Windows 10/11。在群集中，请在每台主机上安装代理。
  2. 一分钟内，该主机会出现在代理页面上，并带有 Hyper-V · N VMs 标记。
  3. 在 备份作业 中选择该代理并选择 虚拟机（Proxmox VE、Hyper-V、VMware）。然后选择：
    • 主机上的所有虚拟机（及容器），也包括以后创建的虚拟机；
    • 勾选单个虚拟机。

代理通过 Hyper-V 自身的接口工作：Hyper-V PowerShell 模块和 Windows Virtual Disk API。控制台不存储任何 Hyper-V 凭据。

虚拟机如何备份

  1. 创建一个临时恢复检查点（backupzit_…）。这是 Hyper-V 为备份应用程序提供的检查点类型。Hyper-V 会要求来宾做好准备：
    • Windows 来宾通过 VSS 刷新其应用程序。
    • 如果安装了 Hyper-V 守护程序（hyperv-daemons / hv-vss-daemon），Linux 来宾会冻结其文件系统。
    如果来宾两者都无法做到，则以崩溃一致方式创建检查点。运行页面会显示使用了哪种方式。
  2. 恢复检查点会为虚拟机的磁盘启用 Resilient Change Tracking（RCT）；您会在磁盘旁看到 .rct 和 .mrt 文件。第一次备份读取整个磁盘。之后，RCT 会报告自上次备份以来更改了哪些块，只读取这些块。
  3. 通过 Virtual Disk API，以 1 MiB 块读取检查点时刻的磁盘。这包括 VHDX 和 VHD 文件，以及更早检查点形成的链。空块不会存储，存储库中已有的块不会再次上传。
  4. 检查点被删除，Hyper-V 会在后台合并它。
  5. 虚拟机配置随备份一起保存：代数、CPU、内存、网络适配器（交换机、VLAN、MAC 地址）、磁盘控制器、安全启动和 TPM。

已关闭的虚拟机直接读取，无需检查点。在早于 Windows Server 2016 的主机上（没有恢复检查点），会使用生产检查点，并且每次备份都读取整个磁盘。

仅应用程序一致。 对于 Active Directory、SQL Server、Exchange 和其他数据库，请在作业中勾选 要求应用程序一致的检查点（群集作业中同样适用）。这样，运行中的虚拟机只从来宾通过 VSS 准备好的检查点备份；如果失败，不会创建崩溃一致的检查点，该虚拟机不会被备份，运行失败（并发送通知）。作业中的其他虚拟机仍会被备份，并可从该次运行恢复。请检查虚拟机设置中的集成服务 Backup (volume shadow copy) 以及来宾内的 VSS（vssadmin list writers）。需要 0.48.0 或更新的代理；较旧的代理会使运行失败并提示更新。

vTPM 与 BitLocker。 对于带虚拟 TPM 的第 2 代虚拟机，备份还会保存 vTPM（来宾状态文件及其密钥保护器）。在同一主机、或拥有原主机守护者证书的主机上作为新虚拟机恢复时，虚拟机会取回其 vTPM，BitLocker 不会要求恢复密钥。在其他主机上，虚拟机会获得新的空 vTPM，恢复结果会说明这一点；为避免这种情况，请先在该主机导入原主机的 UntrustedGuardian 证书。覆盖现有虚拟机的恢复会保留其 vTPM。不支持受防护的虚拟机（Host Guardian Service）。请仍然妥善保管 BitLocker 恢复密钥。

测试实验室中的示例：一台带 3 GB 磁盘的 Linux 虚拟机。第一次备份读取了 3 GB。下一次在新增 64 MB 数据后读取了 96 MB。

在 Windows 10/11 上，除非在虚拟机设置中关闭该选项，否则 Hyper-V 会在虚拟机启动时创建自动检查点。BackupZit 能处理此类检查点，但对于服务器，建议关闭自动检查点（虚拟机设置 → 检查点）。

还原虚拟机

打开虚拟机备份的运行（从作业页面或 活动），使用 还原 Hyper-V 虚拟机。

作为原虚拟机旁边的新虚拟机

创建一台使用新 MAC 地址的第二台虚拟机，使其可以与原虚拟机在同一网络中运行。默认情况下，其名称为原名称加上“restored”和日期。会在其上关闭自动检查点（Windows 会为新虚拟机开启它们），因此启动它不会留下检查点文件。如果副本与原机并行运行且内部装有 BackupZit 代理，请参见 两台机器使用同一个代理。

与 MAC 地址绑定的来宾网络设置不适用于新的适配器。例如 Linux 云镜像使用的 netplan match: macaddress。

替换原虚拟机

勾选 关闭它并替换其磁盘。BackupZit 会：

  • 关闭现有虚拟机；
  • 合并其检查点；
  • 用还原的磁盘替换其磁盘。

虚拟机保留其 ID、网络适配器和 MAC 地址，因此作业、监控和来宾网络都能继续工作。

在停止原虚拟机或合并其检查点之前，BackupZit 会在所选磁盘文件夹（默认为原磁盘文件夹）的唯一 backupzit-restore-* 子文件夹中重建所有磁盘。准备失败不会改变虚拟机。旧磁盘文件保留原路径；请在验证恢复后的虚拟机后再删除。切换开始后发生错误可能需要手动恢复：重建的磁盘会被保留，错误信息中会显示其文件夹，虚拟机设置和检查点不会自动回滚。

如果原虚拟机已不存在，则会使用新的 Hyper-V ID 重新创建。

选项

  • 虚拟磁盘文件夹：主机的默认文件夹或任何存放虚拟机磁盘的文件夹。原位还原会将新磁盘放在原磁盘旁边。
  • 还原后启动虚拟机。

还原的虚拟机会得到什么

  • 虚拟交换机按名称连接。如果主机上不存在某个交换机，该适配器保持断开。
  • 每台还原的虚拟机都会获得新的代 ID，以便 Active Directory 域控制器安全地检测到还原。

故障转移群集

Hyper-V 故障转移群集中的虚拟机通过整个群集的一个作业备份。三个步骤：

1. 在每个节点上安装代理

在群集的每个节点上安装 Windows 代理（不是在虚拟机内）。虚拟机始终由其当时运行所在节点的代理备份：Hyper-V 的检查点和更改跟踪只在那里工作。虚拟机在没有代理的节点上运行期间不会被备份；一旦迁移到有代理的节点，就会重新备份。

2. 控制台自动识别群集

无需在 BackupZit 或 Windows 中为群集做任何设置。每个代理（0.47.0 或更高版本）都会报告其节点所属的故障转移群集以及哪些虚拟机属于群集。安装或更新代理大约一分钟后：

  • Agents 页面会为每个节点标注 cluster 名称；
  • 群集会出现在作业表单中（下一步），并显示其节点数。

以后加入群集的节点也会以同样方式被识别，并在安装代理后自动加入作业。

3. 为群集创建作业

  1. 打开 Backup jobs 和 New backup job 表单。
  2. 打开 Agent 列表并滚动到末尾：在 Hyper-V failover clusters (virtual machines) 下选择群集，例如 HVC01 — 2 nodes。请选择群集，而不是单个节点。
  3. 类型会设为 Virtual machines。选择 All clustered VMs（包括以后加入群集的虚拟机）或 Only these；每个虚拟机旁边会显示它当前运行的节点。
  4. 选择存储目标、计划以及要保留的备份数量，然后单击 Create job。

作业页面会列出每个节点及其最近结果；Run backup now on all agents 会启动所有节点。当时没有运行作业中任何虚拟机的节点会报告 None of the job's VMs runs on this node now，这属于成功。

之前为单个节点创建的虚拟机作业：在群集作业首次备份后请将其停用或删除，否则群集虚拟机会被备份两次；它们的备份仍保留在存储上。不属于群集的虚拟机（属于某个节点）不在群集作业中，请用该节点的作业备份。

工作原理

  • 每个节点备份当时在其上运行的群集虚拟机，全部存入存储上群集的同一个存储库。
  • 虚拟机迁移到其他节点（实时迁移或故障转移）后，其历史记录在那里继续，Resilient Change Tracking 仍只读取更改过的块：不会产生新的完整备份。
  • 在备份期间迁移的虚拟机仍会被完整备份。备份读取完成后，虚拟机迁移到的节点会在几分钟内删除备份的检查点；运行结果会说明虚拟机已迁移。

还原

  • 替换原始虚拟机会在当前拥有该虚拟机的节点上运行（由控制台选择）。虚拟机通过群集停止和启动，因此群集不会把停止当作故障。
  • 作为新虚拟机：请选择群集共享卷上的文件夹（C:\ClusterStorage\…）。虚拟机的配置也会放在那里，并作为角色添加到群集。

还原单个文件

在运行的虚拟机表格中，点击 浏览文件 可查看虚拟机磁盘上的分区和卷。您可以浏览 NTFS、ext2/3/4 和 XFS，也包括 LVM 中的卷。可以从那里下载文件或将其还原到任意代理。操作方式与 Proxmox VE 完全相同。

命令行

以管理员身份在 Hyper-V 主机上运行：

backupzit-agent hyperv list
backupzit-agent hyperv backup  --repo ... [--vmid N,N]
backupzit-agent hyperv restore --repo ... --vmid N [--new] [--name NAME] [--folder D:\VMs] [--overwrite] [--start] SNAPSHOT|latest
  • --vmid 是 hyperv list 显示的编号。BackupZit 根据虚拟机的 GUID 推导出它。
  • 不带 --new 时，虚拟机原位还原。
  • --overwrite 确认应替换现有虚拟机的磁盘。

存储库选项与所有命令相同；参见 命令行参考。

尚未包含

  • 某些磁盘类型。 共享 VHDX、VHD Set 和直通（pass-through）磁盘不会备份。
