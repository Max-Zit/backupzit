安全与最佳实践

BackupZit 如何保护您的数据和控制台，以及您需要做些什么。

内置保护

  • 源端加密 —— 代理中使用 AES-256-GCM；存储只能看到加密数据。密钥使用 Argon2id 派生。
  • 固定连接 —— 代理固定控制台证书；SFTP 主机密钥和加固存储库证书也会被固定。任何证书颁发机构都无法被滥用来冒充它们。
  • 面向浏览器的受信任证书 —— 可选地在单独地址上使用上传的证书或 Let's Encrypt 证书（TLS 1.2+），并自动续订；参见 安装服务器。
  • 静态机密 —— 存储密码和密钥、恢复密钥、SMTP/LDAP 密码以及双因素密钥都在数据库中加密，所用密钥保存在数据库之外（secrets.key）。
  • 代理机密 —— 每个代理都有自己的机密，在控制台上只以哈希形式存储，在代理上存放于只有管理员可读的文件中。
  • Web 控制台 —— HttpOnly、SameSite=Strict 的会话 Cookie；防护跨站请求和点击劫持；严格的 Content-Security-Policy；密码使用 bcrypt 哈希；敏感页面从不缓存。
  • 暴力破解防护 —— 登录失败过多的地址会被封锁：包括密码、双因素代码和 API 令牌。封锁在重启后依然有效，屡犯者封锁更久，管理员会收到电子邮件。见下文。
  • 帐户 —— 最小权限角色、可选的双因素身份验证（TOTP）和 LDAPS 登录；API 令牌拥有自己的、更低的角色和有效期。
  • 四眼审批（可选）—— 删除或禁用作业，删除代理、ESXi 主机、存储目标和用户，缩短保留期，关闭审批，以及任何可能让一名管理员获得第二个审批人的操作（新审批人、更多权限、重置密码和双因素、更改 LDAP 和 SSO），都需要第二个用户批准。参见 用户、角色和 LDAP。
  • 审计跟踪 —— 登录、失败的登录、用户和角色更改、作业、存储目标、还原、已显示的恢复密钥、设置更改和 API 操作都会记录在 审计日志 中；记录相互链接，可以检测数据库中的更改和删除，并可复制到 syslog 服务器或 SIEM（防篡改保护）；加固存储库上的删除会记录在该服务器上。
  • 控制台更新 —— 发布版本使用 BackupZit 发布密钥（Ed25519）签名。控制台和安装更新的 root 服务都会验证签名，先备份数据库，更新失败时会回滚。
  • 代理更新 —— 代理只通过固定连接从自己的控制台下载新版本，并且只在 SHA-256 校验和匹配时才安装。
  • 本地状态通道 —— 托盘应用通过本地命名管道（Windows）或仅 root 可访问的套接字（Linux）与代理服务通信。已登录该机器的用户可以读取状态并启动本机的备份作业；除此之外不能做任何事（作业、计划、存储和还原只能在控制台中管理）。
  • 虚拟化平台备份 —— Proxmox 或 Hyper-V 主机上的代理使用主机自身的工具；不会为其存储虚拟化平台密码。对于 VMware ESXi，控制台加密存储主机密码，固定其 HTTPS 证书和 SSH 主机密钥，并且只在运行时将连接交给该主机的代理（proxy）。
  • 备份完整性 —— 还原时会用 SHA-256 哈希验证每个数据块；自动还原测试和勒索软件检测持续监控备份。

暴力破解防护

在 设置 → 登录与安全 中配置。默认值对大多数部署都是安全的：

设置默认值含义
每个地址的失败次数5在统计周期内来自同一 IP 地址的失败登录会封锁该地址。计入错误的密码、错误的双因素代码和无效的 API 令牌。
统计周期15 分钟更早的失败会被忽略。
封锁时长30 分钟被封锁的地址即使使用正确的密码也无法登录。登录页面会显示“登录失败次数过多”，API 返回 HTTP 429。
对屡犯者延长封锁开启同一天内对同一地址的每次后续封锁时间加倍：30 分钟、1 小时、2 小时……最长 7 天。
每个用户名的失败次数20某个用户名来自任意地址的失败会暂停该用户名的登录，直到统计周期结束。这可以阻止分散到大量地址的猜测。帐户永远不会被永久锁定，因此攻击者无法把管理员锁在外面。
从不封锁这些网络无可选的网络，例如管理员所在子网，永远不会被封锁。按用户名的限制仍然适用。
反向代理无如果控制台运行在 nginx、Traefik 或其他代理之后，请输入其地址：此时客户端地址取自 X-Forwarded-For（否则所有客户端看起来都像代理），当代理发送 X-Forwarded-Proto: https 时，登录 Cookie 会标记为 Secure。来自任何其他地址的这两个标头都会被忽略，因此无法伪造。
封锁地址时发送电子邮件开启发送给 电子邮件设置 中的收件人。

同一页面列出了被封锁的地址及每次封锁的原因和时长，并可解除封锁。封锁和解除都会记录在 审计日志 中。

如果您把自己锁在外面了，请从其他地址登录，或在服务器上使用与服务相同的数据库选项运行：

backupzit-server --unblock-ip all

要解除单个封锁，请用该地址替换 all。

Web 控制台访问（公网地址）

代理通过 8443 端口连接到控制台。若要在公网地址上提供控制台 —— 供其他站点或客户处的代理使用 —— 同时只允许您的管理员打开 Web 控制台，请使用 设置 → 登录与安全 → Web 控制台访问：

设置效果
允许的地址IP 地址或网络（例如 203.0.113.10、10.0.0.0/24）。Web 控制台、REST API 和所有页面只响应这些地址；其他地址会收到“not found”，就好像没有控制台一样。代理始终可以访问其 API（注册、轮询、结果、下载、推送安装）。留空：所有人。控制台会拒绝不包含您自己地址的列表。
端口 8443 仅供代理使用此时 Web 控制台只在带有受信任证书的 Web 端口上提供（设置 → 证书，通常为 443），这样防火墙可以对所有人开放 8443，而只对您的地址开放 443。Web 端口运行后可用；请从 Web 端口而不是 8443 更改此设置。

公网控制台的典型防火墙：8443 对所有人开放（代理），443 和 80（Let's Encrypt HTTP 检查）只对您的地址开放，SSH 只对您的地址开放或关闭，其余全部关闭。

被锁在外面了？在服务器本机（localhost）上控制台始终响应。在一体机（appliance）上，其屏幕上设置菜单的第 5 项可以解除登录封锁和这些限制。

建议

控制台

  • 将控制台放在内部网络中；不要把 8443 端口发布到互联网。远程管理请使用 VPN。
  • 使用长且唯一的管理员密码，并更改初始密码。
  • 要求管理员使用 双因素身份验证（设置 → 登录与安全）。
  • 为每个人分配自己的帐户并使用够用的最低角色；监控请使用查看者角色的 API 令牌。
  • 将 secrets.key 与数据库分开备份（安装服务器）。
  • 在 设置 → 登录与安全 中选择合适的登录会话时长（越短越安全）。
  • 保持服务器（包括 PostgreSQL）为最新状态（apt upgrade / dnf upgrade）。

存储

  • 为每个存储目标使用单独的帐户，只允许访问备份文件夹或存储桶。
  • 不要将备份存储加入 Windows 域；使用在其他地方都不使用的凭据。
  • 至少保留一份不可变副本（S3 Object Lock 或加固存储库）和一份异地副本。

密钥

  • 离线保存恢复单。没有它们，控制台丢失后加密备份将无法还原。
  • 仅凭恢复单从命令行测试一次还原，以确认流程可行。
  • 像对待钥匙一样对待装有 recovery.json 的 U 盘：在恢复代码过期（30 天）之前，它可以让一台机器作为恢复代理加入控制台。需要时创建新代码，而不要保留旧 U 盘。
  • 恢复 ISO 会为任何从其启动的人提供 root / 管理员命令行 —— 与任何启动介质一样。请用固件（BIOS/UEFI）密码和安全启动设置保护服务器。

代理和虚拟化平台

  • 控制台可以在代理上安装软件（代理更新）并向其还原数据。请相应地保护管理员帐户：双因素身份验证、尽量少的管理员。
  • 浏览虚拟机磁盘中的文件时，由控制台和代理解析；损坏或恶意的文件系统数据只会产生错误，而不会导致崩溃。
