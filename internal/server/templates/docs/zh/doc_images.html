磁盘映像和裸机恢复

映像备份会捕获整个磁盘 —— 分区表、引导分区、系统和数据 —— 从而可以在空磁盘或新磁盘上将机器完全恢复原样。

磁盘映像备份适用于 Windows 机器（NTFS 卷、GPT 和 MBR 磁盘）。Linux 机器请使用 Linux 系统作业。

创建映像作业

  1. 在 备份作业 中选择 磁盘映像。
  2. 代理会自动报告其磁盘。选择 所有磁盘 可在一个作业中为机器的每块内部磁盘创建映像，或者勾选单块磁盘 —— 整块或仅部分分区（例如跳过已由文件作业覆盖的大型数据分区）。
  3. 像任何作业一样设置保留期和计划；每周映像加每日文件备份是常见组合。

所有磁盘

所有磁盘作业会将每块带分区表的内部磁盘备份到同一个备份中，包括以后添加的磁盘。所有磁盘的所有卷都从同一个 VSS 快照读取，因此磁盘之间保持一致（例如 D: 上的数据库及其位于 E: 上的日志）。USB 和 SD 磁盘、已挂载的 VHD/VHDX 文件以及可移动介质不包括在内 —— 外部备份磁盘不应备份自身；如需备份此类磁盘，请单独选择。运行页面列出每块磁盘及其分区；可以从每块磁盘浏览和还原文件。还原一次写入一块磁盘：在还原表单中选择 备份中的磁盘 和目标磁盘，然后对下一块磁盘重复（裸机：先从恢复 ISO 还原系统磁盘）。代理必须为 0.33.7 或更新版本；旧版本会提示需要更新。

只读取已使用的块（NTFS 分配图），映像取自 VSS 快照以保证正在运行的系统一致，未更改的块会与之前的映像进行重复数据删除 —— 同一台机器的第二个映像通常只上传百分之几。

将映像还原到磁盘

在映像备份的运行中，使用 将此映像还原到磁盘：

  • 在代理上还原 —— 拥有目标磁盘的机器。可以是带有空闲磁盘的运行中机器，也可以是从恢复 ISO 启动的机器。
  • 目标磁盘 —— 至少要与原磁盘的已用区域一样大。其上的所有数据都会被销毁。
  • 之后让磁盘保持脱机 —— 当原磁盘位于同一台机器中时勾选此项，这样 Windows 不会更改副本的磁盘 ID。

支持 GPT 和 MBR 磁盘，以及 EFI 和 BIOS 引导。分区布局和 ID 会被重建，因此还原后的磁盘能像以前一样启动。

使用恢复 ISO 进行裸机恢复

  1. 在 恢复介质 下载（Windows）恢复 ISO。将其写入 U 盘（Rufus，“DD 映像”或“ISO”模式）或挂载到虚拟机。
  2. 可选：创建 恢复代码 并下载 recovery.json；将其复制到 U 盘上的 backupzit 文件夹，这样机器无需输入即可连接。
  3. 从 U 盘启动要还原的机器。它会以恢复模式启动代理并连接控制台（或询问服务器地址和恢复代码）。
  4. 该机器会作为带有其磁盘的 恢复 代理出现。
  5. 在活动中打开映像备份，选择 将此映像还原到磁盘，选择恢复代理及其磁盘，然后确认。
  6. 运行完成后，拔出 U 盘并重新启动。

还原到不同硬件

Windows 只有在具备其引导所用磁盘控制器的驱动程序时才能启动，而 Windows 安装程序会禁用它不需要的驱动程序。因此，带 Intel 控制器的 PC 的映像在 AMD 主板、NVMe 驱动器、Hyper-V 或 Proxmox 虚拟机中会停在 INACCESSIBLE_BOOT_DEVICE。在还原表单中勾选 还原到不同硬件，BackupZit 会在写入映像后对还原的 Windows 进行准备：

  1. Windows 自带的常见磁盘控制器驱动程序会在启动时重新加载：AHCI/SATA、NVMe、Intel RST、LSI/Broadcom/Dell PERC SAS 和 RAID、HPE Smart Array、Hyper-V 和 VMware。
  2. 使用 DISM 添加其他驱动程序：恢复 ISO 上的驱动程序（包含用于 Proxmox/KVM 的 VirtIO 驱动程序）以及您在 附加驱动程序 中输入的文件夹 —— 例如新主板的存储和网络驱动程序，解压到 U 盘上（E:\Drivers；会搜索子文件夹）。
  3. 为新机器重建引导文件（bcdboot）。

运行页面会列出已启用和已添加的驱动程序。Windows 会在首次启动时检测其余新设备；在新硬件上可能需要重新激活。无法在 UEFI 和传统 BIOS 之间还原 —— 目标必须以与原机相同的方式引导。

物理 PC 或服务器迁移到 Proxmox VE： 创建一台虚拟机，GPT 磁盘使用 OVMF（UEFI），MBR 磁盘使用 SeaBIOS，配备至少与原磁盘一样大的 VirtIO SCSI 磁盘和 VirtIO 网卡，挂载恢复 ISO，并使用 还原到不同硬件 进行还原。恢复 ISO 本身就能识别 VirtIO 磁盘和网卡。

还原到虚拟机

创建一个至少与原磁盘一样大的空虚拟机磁盘，从恢复 ISO 启动虚拟机，然后按上述步骤操作。这也是测试映像是否真正能够启动的最简单方法。
