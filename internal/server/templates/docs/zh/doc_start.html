入门

BackupZit 通过一个运行在您自己网络中的 Web 控制台，保护 Windows 和 Linux 机器、Proxmox VE、Hyper-V 和 VMware ESXi 虚拟机、数据库（SQL Server、PostgreSQL、MySQL/MariaDB）以及 NAS 共享——文件、整个磁盘和整个系统。

BackupZit 保护什么

对象方式还原
文件和文件夹（Windows、Linux）机器上的代理；Windows 上打开的文件通过 VSS 读取。备份作业整个备份或单个文件夹，还原到任意代理、原始位置或其他文件夹。还原
Windows 磁盘从 VSS 快照创建整个磁盘或选定分区的磁盘映像。磁盘映像使用 Windows 恢复 ISO 还原到空磁盘或裸机，也可还原到不同硬件或虚拟机；从映像中提取单个文件。
Linux 系统所有本地文件系统以及磁盘布局（分区、LVM、UUID、引导代码）。Linux 系统备份使用 Linux 恢复 ISO 还原到空磁盘或裸机，或作为新的 Proxmox 虚拟机（P2V）；单个文件。
Hyper-V 虚拟机Hyper-V 主机上的代理，虚拟机内无需代理；恢复检查点（客户机内 VSS），Resilient Change Tracking 只读取更改的块。Hyper-V整个虚拟机作为新虚拟机或就地还原（保留 ID 和 MAC 地址）；从虚拟机磁盘提取单个文件。
VMware ESXi 虚拟机任意代理都可作为代理服务器，ESXi 和虚拟机内无需安装任何东西；静默快照，Changed Block Tracking 只读取更改的块。VMware ESXi整个虚拟机作为新虚拟机或就地还原（保留 UUID 和 MAC 地址），可还原到任意主机和数据存储；单个文件。
NAS 和文件共享（SMB、NFS）NAS 上无需软件：任意机器上的代理读取共享。备份作业文件和文件夹还原回共享、某个文件夹或作为下载。
数据库：SQL Server、PostgreSQL、MySQL/MariaDB数据库机器上的代理；使用服务器自带工具，完整备份和日志备份。数据库单个数据库以新名称或就地还原，可还原到日志备份覆盖的任意时刻。
Proxmox VE 虚拟机和容器Proxmox 主机上的代理，客户机内无需代理；基于 Proxmox 快照，只上传更改的块。Proxmox VE整个客户机作为新客户机或就地还原，可还原到任意节点和存储；直接从备份即时启动虚拟机（即时恢复，也支持 VMware ESXi）；从虚拟机磁盘（NTFS、ext4、XFS、LVM）提取单个文件，可下载或发送到代理。

BackupZit 的工作方式

  • 管理控制台（本 Web 应用）——运行在您网络中的 Linux 服务器上。它存储配置、调度作业、收集结果并显示报告。它永远不需要从互联网访问。
  • 代理——每台受保护机器（Windows MSI、Linux deb/rpm）以及 Proxmox 和 Hyper-V 主机上的小型服务；VMware ESXi 主机通过作为代理服务器的代理访问。代理通过 HTTPS 联系控制台，接收作业，并将备份数据直接发送到存储。在 Windows 上，代理会在时钟旁显示其状态。
  • 存储目标——保存备份的位置：SFTP、S3 兼容对象存储（AWS、Wasabi、Backblaze B2、MinIO、Google Cloud…）、Azure Blob Storage、SMB 共享/NAS、轮换的 USB 磁盘、本地或已挂载的磁盘，或 BackupZit 加固存储库。

备份数据从不经过控制台。控制台只负责协调，因此一台小型虚拟机就足够了。

第一步

要搭建新的控制台，可将现成的设备映像导入一台小型虚拟机、启动设备 ISO，或在现有 Linux 服务器上运行安装脚本；参见 安装服务器。

  1. 在 存储 下添加存储目标。保持加密备份处于启用状态，并将随后显示的恢复单保存在安全的地方。参见 存储目标。
  2. 安装代理：在 Agent 下点击创建注册令牌，从同一页面下载安装程序，并在 Windows 安装程序要求时粘贴注册码（Linux：backupzit-agent enroll --code …）。对于虚拟机，请在 Proxmox 或 Hyper-V 主机上安装代理；在 Agent → VMware ESXi 主机 下添加 VMware ESXi 主机。参见 Agent。
  3. 在 备份作业 下创建备份作业：选择代理、存储、要备份的内容（文件、NAS 共享、磁盘映像、数据库、整个 Linux 系统，或 Proxmox、Hyper-V、VMware ESXi 主机的虚拟机）、运行时间以及保留的备份数量。参见 备份作业和计划。
  4. 在作业页面上使用立即运行备份手动运行一次，并在 活动 下检查结果。
  5. 测试还原——备份的价值取决于能否还原。自动还原测试每周运行；也请使用还原向导手动还原一次。参见 还原。
  6. 为灾难做好准备：在 恢复介质 下下载恢复 ISO 并创建恢复码。
  7. 在 设置 → 电子邮件通知 下设置电子邮件警报，以便及时了解故障，还可以设置每周报告。

语言

控制台提供 14 种语言：英语、德语、法语、西班牙语、意大利语、葡萄牙语（巴西）、荷兰语、波兰语、捷克语、塞尔维亚语（拉丁字母）、土耳其语、俄语、中文（简体）和日语。在右上角的语言列表或登录页面中选择一种；选择会保存在浏览器中。未作选择时，由浏览器语言决定（克罗地亚语、波斯尼亚语和黑山语浏览器使用塞尔维亚语，斯洛伐克语浏览器使用捷克语，其他语言使用英语）。本指南也已翻译（没有翻译的页面以英语显示）。电子邮件、聊天通知和代理报告的消息保持英语。

翻译位于源代码的 internal/server/i18n/zh.json 中：英语文本是键，翻译是其值。go run ./tools/i18n missing zh 列出未翻译的文本；未翻译的文本以英语显示。

关键概念

快照和重复数据删除

每次备份都会创建一个快照：数据在该时刻的完整、可浏览的映像。文件被拆分为大小可变的块，磁盘被拆分为块，每一块只存储一次，因此第二次及以后的备份只上传更改的内容——但每个快照都可以单独还原。无需管理“完整/增量链”。

存储库

每个代理写入存储目标位置下自己的存储库（<location>/<hostname>_<id>）。存储库是自包含的：有了位置、存储凭据和恢复密钥，即使控制台已不存在也能还原。

保留

每个作业保留一定数量的最近、每日、每周和每月备份。较旧的快照在每次运行后删除，其占用的空间随之释放。

BackupZit 为您检查的内容

  • 还原测试——每个作业的最新备份每周会被部分还原并验证（还原）。
  • 勒索软件检测——异常备份（大规模更改、加密数据、大规模删除、数据量突然激增）会被标记，并暂停保留清理（勒索软件防护）。
  • 警报和报告——故障时发送电子邮件并提供每日摘要；为管理层提供计划报告（电子邮件通知、监控）。
