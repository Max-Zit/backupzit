VMware ESXi 虚拟机

BackupZit 备份 VMware ESXi 主机上的虚拟机，无需在 ESXi 或虚拟机内部安装任何东西。网络中任意机器上的 BackupZit 代理都可以充当主机的代理（proxy）。它创建快照，只读取虚拟磁盘中更改的块，并将其写入您的存储。

要求

  • 直接连接的 ESXi 6.7、7 或 8，或带有其 ESXi 主机的 vCenter Server 7 或 8（参见vCenter Server）。
  • 在主机上拥有管理员权限的用户，通常为 root。
  • 使用免费许可证的主机需启用 SSH： Host → Actions → Services → Enable Secure Shell。免费 ESXi 许可证使 API 只读，因此快照和还原通过 SSH 进行。有许可证的主机通过 vSphere API 更改，无需 SSH。
  • 代理（proxy）代理程序： 任何能通过 443 端口（使用 SSH 时还需 22 端口）访问主机的 Windows 或 Linux 代理。备份数据会经过它，因此请将其放在靠近主机和存储的快速网络中。
  • 备份运行中的虚拟机时，虚拟机数据存储上需有可用空间。BackupZit 会在那里短暂复制磁盘（见下文）。副本为精简（thin）格式，因此所需空间与磁盘实际使用量相同。使用热添加时不会创建副本。

添加主机

  1. 打开 Agent → VMware ESXi 主机 → 添加 ESXi 主机或 vCenter Server。
  2. 输入地址、用户、密码和代理（proxy）代理程序。
  3. 控制台会连接一次以进行检查。它读取虚拟机列表和许可证，并固定主机的 HTTPS 证书和 SSH 主机密钥。如果主机之后被具有相同地址的另一台机器替换，BackupZit 会拒绝连接，而不是把密码发给它。 如果证书因已知原因更改（主机已重新安装、获得了新证书，或已添加到 vCenter（vCenter 会替换其主机的证书）），主机会在“Agent”页面上显示新指纹和接受新证书按钮。接受之前，请将指纹与主机上的进行比较。

密码与所有其他机密一样加密存储。控制台本身会连接到主机（HTTPS 443，免费许可证还需 SSH 22）：添加主机时、点击 刷新 时，以及每 10 分钟刷新虚拟机列表时。移除 会删除主机及其备份作业；备份保留在存储上。表格显示每台主机的模式：

  • vSphere API（有许可证的主机，无需 SSH）： 快照、磁盘复制、还原和即时恢复都通过 API 进行。
  • vCenter Server（vSphere API）： 包含其 ESXi 主机的 vCenter；所有操作都通过 vCenter API 进行。
  • 免费许可证：快照和还原通过 SSH： 主机的 API 是只读的，因此这些步骤通过 SSH 进行。
  • SSH（为此主机选择）： 即使主机的 API 能够执行，主机也通过 SSH 进行更改（添加主机时选择 始终使用 SSH）。

选择自动时由控制台自行选择，因此之后获得许可证的主机无需额外设置即可改用 API。主机所在行（以及添加时）的主机的更改方式可以强制为始终使用 SSH或始终使用 vSphere API；更改会立即检查。以前的备份及其还原点不受方式影响。

vCenter Server

像添加主机一样添加 vCenter Server：填写其地址、administrator@vsphere.local（或具有 Administrator 角色的用户）和一个代理。之后 BackupZit 通过这一个连接即可看到数据中心内所有 ESXi 主机和集群的虚拟机；不会通过 SSH 进行任何更改，也不需要任何主机的密码。

  • 通过 vMotion 迁移到其他主机的虚拟机会继续被备份：虚拟机按实例 UUID 识别，而不是按主机。
  • 还原时可以选择运行虚拟机的 ESXi 主机（默认：原虚拟机所在主机）和数据存储。
  • 即时恢复会在所选主机上启动虚拟机；完成 会在虚拟机继续运行时通过 Storage vMotion 将其迁移到数据存储，无需停机。
  • 暂时无法添加包含多个数据中心的 vCenter；请直接添加其他数据中心的主机。

不要将同一台 ESXi 主机既直接添加又通过 vCenter 添加：每个连接都有自己的存储库，其虚拟机会被备份两次。 如果 BackupZit 直接备份的主机后来被添加到 vCenter，请在“Agent”页面上接受其新证书；其作业会继续运行——vCenter 会为在独立主机上创建的虚拟机分配新的 ID，BackupZit 会在下次刷新时将作业切换到新 ID。

备份作业

在 备份作业 中，选择 ESXi 主机（在代理列表的 VMware ESXi 主机 下列出）和 虚拟机。备份主机的所有虚拟机（以后创建的虚拟机会自动包含）或勾选单个虚拟机。作业在主机的代理（proxy）上运行。如果更换代理，现有作业会随之更改。

如需排除个别虚拟机，例如 BackupZit 控制台所在的虚拟机，请选择主机上除勾选项外的所有虚拟机（及容器）并勾选它们。

虚拟机如何备份

  1. 如果虚拟机的更改块跟踪（CBT）处于关闭状态，则会将其开启。
    • 在已授权的主机上会自动完成。
    • 在免费主机上，只有在虚拟机关闭时才能开启 CBT。BackupZit 会在第一次发现虚拟机处于关闭状态的备份时开启它。在此之前，每次备份都读取整个磁盘，运行会显示警告。
  2. 创建快照 backupzit_…。当来宾中运行着 VMware Tools 时，快照会静默（quiesced）：先刷新应用程序和文件系统，使备份具有应用一致性。没有 VMware Tools 时则为崩溃一致性。请在 Linux 虚拟机中安装 open-vm-tools，在 Windows 虚拟机中安装 VMware Tools。
  3. CBT 报告需要读取哪些块：
    • 第一次备份时，只读取已使用的块；
    • 之后，只读取自上次备份以来更改的块。
  4. 运行中的虚拟机会锁定其磁盘。因此会在数据存储上复制其磁盘（精简），并立即删除快照，通常只需几秒钟。然后通过 HTTPS 读取副本并将其删除。已关闭的虚拟机直接读取。使用热添加时，运行中虚拟机的磁盘改为通过代理自身的虚拟机读取，无需复制。
  5. 虚拟机的配置（.vmx）和 NVRAM 随备份一起存储。

测试实验室中的示例：一台带 8 GB 磁盘的 Debian 虚拟机，其中已用 1.6 GB。第一次备份读取了 1.6 GB。下一次在新增 50 MB 数据后读取了 70 MB，耗时 23 秒。

热添加：不在数据存储上复制

复制运行中虚拟机的磁盘时，每次备份（包括增量备份）都会在生产数据存储上耗费时间和 I/O，并且需要为磁盘的已用块准备可用空间。对于慢速磁盘上的大型虚拟机，这一点很重要。启用热添加（Agent → VMware ESXi 主机，“备份代理”下方的复选框）后，代理改为就地读取磁盘：

  • 要求： 代理是虚拟机中的 Linux 代理，能看到该虚拟机的数据存储（在同一主机上，或在同一 vCenter 中可访问这些数据存储的主机上），并且主机通过 vSphere API 更改（vCenter 或已授权的主机）。代理通过 BIOS UUID 找到自身所在的虚拟机。
  • 工作方式： 快照存在期间，每个磁盘以 independent-nonpersistent 方式挂接到代理的虚拟机上。代理以只读方式打开磁盘；写入其中的任何内容都会进入 redo log，vSphere 在分离磁盘时将其丢弃，因此虚拟机的磁盘永远不会被更改。代理只读取 CBT 报告的块，然后分离磁盘，再删除快照。
  • 节省了什么： 无需临时副本，也无需数据存储上的额外空间。一台 2 TB 的虚拟机有 20 GB 更改时，增量备份只读取 20 GB。快照会在读取磁盘的整个过程中保留（而不仅是复制期间），因此虚拟机写入快照的时间会稍长一些。
  • 回退： 如果代理不是该主机的虚拟机，或者挂接或读取磁盘失败，该磁盘会像以前一样在数据存储上复制，并且运行会显示带有原因的警告。热添加默认关闭；0.54 之前的代理会忽略它。运行页面会显示通过热添加读取的磁盘数量。
  • 在代理虚拟机上： 使用 LVM 的设备文件（/etc/lvm/lvm.conf 中的 use_devicesfile = 1，并用 lvmdevices 登记代理自身的磁盘），防止 LVM 激活所挂接磁盘上的卷。LVM 仍然激活的卷会在分离磁盘前被移除。不要手动将其他虚拟机的磁盘挂接到代理：来自其他虚拟机文件夹的 independent-nonpersistent 磁盘会被视为中断的备份遗留下来的磁盘，并被分离。

多个备份代理（vCenter）

一个备份代理逐个读取磁盘，且只能在能看到其数据存储的主机上使用热添加。对于 vCenter 连接，请将每台 ESXi 主机上某个虚拟机中的 Linux 代理添加为其他备份代理（Agent → VMware ESXi 主机，备份代理下方的其他备份代理；代理 0.55 或更新版本）：

  • 按主机拆分：作业的每次备份都会拆分。每个虚拟机交给其所在 ESXi 主机上的备份代理（依据最近的虚拟机列表），其余虚拟机交给连接的备份代理。每个备份代理将自己的部分作为单独的运行，与其他代理同时，通过自己主机上的热添加进行备份。只有在线的备份代理参与：已关闭的备份代理的虚拟机交给连接的备份代理。写入新存储库的第一次备份以及备份到本地或 USB 目标的备份不拆分。
  • 一次启动：作业将一次启动的各部分作为整体显示：只要有部分在运行就是运行中，有部分失败就是失败。RPO 警报和仪表板在所有部分都成功后才计为一次备份；链接的作业或“每次备份后”的复制在最后一个部分之后启动一次。
  • 不重叠：连接在不同备份代理上的备份和还原不会同时运行（只有同一次启动的各部分会同时运行），因此在主机之间迁移的虚拟机绝不会同时由两个备份代理处理。
  • 按备份代理保留：每个部分为其虚拟机保留作业设定数量的备份，复制作业也按部分复制和保留。作业拆分之前的备份以及已移除的备份代理的备份保持原样：它们仍是其虚拟机的还原点。迁移到另一台主机的虚拟机（vMotion）从下一次刷新虚拟机列表起交给该主机的备份代理。
  • BackupZit 根据代理报告的 BIOS UUID 找到备份代理所在的主机；Agent 页面会在每个代理旁显示。未找到 ESXi 主机：该代理不是此 vCenter 的虚拟机，或虚拟机列表比代理旧（点击刷新）。

取消 VMware 备份（活动 → 取消）也会停止正在数据存储上进行的磁盘复制并删除不完整的副本；快照会像每次备份后一样被删除。

还原虚拟机

使用 还原向导（整台虚拟机）或活动中该备份的页面。选择：

  • 作为原虚拟机旁边的新虚拟机： 一个具有新名称、UUID 和 MAC 地址的副本。默认名称为原名称加上 -restored- 和日期。绑定到旧 MAC 地址的来宾网络设置（例如云镜像中的 netplan match: macaddress）不适用于副本。
  • 替换原虚拟机： 选中 关闭它并替换其磁盘 后，BackupZit 会：
    • 关闭虚拟机并删除其快照；
    • 将当前磁盘重命名为 ….replaced-DATE.vmdk（确认还原的虚拟机正常后删除它们）；
    • 将备份写入使用原名称的新磁盘，并按备份设置 CPU 和内存。
    虚拟机保留其 UUID、网络适配器和 MAC 地址。如果虚拟机已被删除，则以其原始身份重新创建。
  • ESXi 主机和数据存储： 另一台主机，或同一主机的另一个数据存储。
  • 还原后启动虚拟机。

磁盘以精简方式还原，只写入有数据的块。连接到 CD/DVD 驱动器的 ISO 映像不属于备份，因此这些驱动器保持为空。

即时恢复

选择 即时从备份运行，即可在几秒钟内启动虚拟机，而无需先复制其磁盘。主机的代理（proxy）—— 必须是 Linux 代理 —— 通过 NFS 直接从备份提供虚拟机磁盘；主机将其挂载为数据存储 backupzit-<agent> 并从中运行虚拟机。虚拟机所做的更改保存在代理上（/var/lib/backupzit/instant-esxi，因此需要为此留出可用空间）；备份本身永远不会被更改，只要虚拟机还从中运行，保留策略就会保留它。如果原虚拟机仍然存在，即时虚拟机会获得新的 UUID 和新的 MAC 地址。

在运行页面上，当虚拟机按预期工作时：

  • 完成 会将其复制到主机的数据存储：关闭虚拟机（如果 VMware Tools 正在运行则通过它关闭），以精简方式复制其磁盘（有许可证的主机通过 API，免费许可证通过 SSH 使用 vmkfstools），从数据存储注册并重新启动。独立主机没有 Storage vMotion，因此需要短暂停机，停机时间随磁盘大小增加。如果复制失败，虚拟机将继续从备份运行。
  • 放弃 会停止并删除虚拟机及其所有更改。

代理只为 ESXi 主机的地址在 2049 端口响应 NFS（并将其注册到本机 111 端口的 rpcbind，或自行响应 111 端口）；如果中间有防火墙，请开放从主机到代理的这些端口。当最后一台即时虚拟机完成或被放弃后，数据存储会被移除，NFS 服务器停止。

单个文件

备份页面上的 浏览文件（或还原向导中的 虚拟机中的文件）会打开虚拟机的磁盘。您可以浏览 NTFS、ext2/3/4 和 XFS（包括 LVM 上的），并下载文件或将其还原到任意代理。

命令行

这些命令可在任意代理上运行。请在 BACKUPZIT_VMWARE_PASSWORD 中设置 ESXi 密码：

backupzit-agent vmware list    --host 192.168.1.20 [--user root]
backupzit-agent vmware backup  --host … --repo … [--vmid N,N]
backupzit-agent vmware restore --host … --repo … --vmid N [--new] [--name NAME] [--datastore DS] [--overwrite] [--start] SNAPSHOT|latest

vmware list 会显示主机证书和 SSH 密钥的指纹。使用 --thumbprint 和 --ssh-host-key 传入它们，即可在命令行中同样进行固定。

尚未包含

  • 包含多个数据中心的 vCenter。 只能添加只有一个数据中心的 vCenter；其他数据中心的主机请直接添加。
  • 自带快照的虚拟机。 其磁盘是增量磁盘；请先删除或合并快照。
  • 某些磁盘类型。 裸设备映射（RDM）和独立磁盘。
  • 通过 Windows 代理（proxy）进行即时恢复。 即时恢复需要 Linux 代理（proxy）。
