还原

每个成功的备份都可以还原：完整还原或只还原选定的文件夹，还原到同一台机器、另一个代理，或作为新的虚拟机。

还原向导

点击菜单中的 还原。向导会问四个问题：

  1. 要还原什么？
    • 整台虚拟机
    • 虚拟机中的文件
    • 文件和文件夹
    • 磁盘映像 / 裸机
    • 磁盘映像中的文件
    • 数据库（还原到某一时刻）
    • 整个 Linux 系统
    • Microsoft 365 邮件和 OneDrive（参见 Microsoft 365）
    每个选项都会显示有多少个可用的还原点。
  2. 来源：虚拟机（跨所有虚拟化平台和作业），或备份作业及其机器。
  3. 还原点：要从中还原的备份，最新的在前，显示其状态、存储和大小。
    • 被标记为可疑（可能是勒索软件）的备份会有标识。
    • 由备份复制作业在二级存储上创建的副本会列为副本（文件和虚拟机备份）。
  4. 选项：还原到哪里以及如何还原。选项上方会显示您所选内容的摘要。

顶部的步骤都是链接，因此可以返回之前的任意步骤。每一步都有自己的地址，可以加入书签或分享。

这些选项与 活动 中备份页面上的选项相同，也可以在那里直接开始还原。只有角色允许还原的用户才能看到向导。

从文件备份还原

  1. 在还原向导中选择文件和文件夹，然后选择作业和还原点。也可以在 活动 或作业页面中打开该备份。
  2. 在从此备份还原文件下选择接收文件的代理。它可以是与被备份机器不同的机器——例如替换用的 PC。
  3. 选择还原位置：
    • 还原到文件夹（推荐）——例如 D:\Restore。原始结构会在其下重建：D:\Restore\C\Users\ana\Documents\…。不会改动任何现有内容。
    • 还原到原位置——将文件写回原处，覆盖当前版本。对于 NAS 共享，代理会以可写方式重新连接共享。
  4. 可选择限制为仅这些路径，每行一个，例如 C:\Users\ana\Documents\Contracts——或在文件浏览器中选择（见下文）。
  5. 保持验证已还原的文件处于开启状态：每个文件都会被读回并与备份中的校验和进行比较。
  6. 点击开始还原。进度和结果显示在还原运行的页面上。

文件时间、Windows 属性（隐藏、只读……）以及 Linux 上的所有者、权限（包括 setuid 位）、ACL、扩展属性（SELinux 标签、文件 capabilities）、符号链接和硬链接也会一并还原。只有当代理以 root/管理员身份运行时才会设置所有者。

浏览、下载和选择文件

在备份运行中，浏览文件会按原样显示备份的文件夹（NAS 共享和 Linux 系统备份也可以）。打开文件夹，勾选文件和文件夹，然后：

  • 下载——单个文件按原样下载，多个文件或文件夹打包为 ZIP 压缩包，直接在浏览器中下载。下载会记录在审计日志中。
  • 在代理上还原它们——还原到文件夹或原位置，如同使用仅这些路径的还原。

指向文件的符号链接（例如 /etc/os-release）在其目标文件位于备份中时，会作为目标文件下载；指向文件夹的链接不会包含在 ZIP 压缩包中。从虚拟机备份（ext4、XFS）下载的文件同样如此。在代理上还原时，链接会重新创建为链接。

控制台会自行从存储读取备份，因此浏览功能适用于网络存储上的备份（SFTP、S3、SMB、Azure、加固存储库）；对于代理的本地磁盘或 USB 磁盘，请通过路径还原。拥有还原角色的用户可以浏览和下载。

搜索备份

不知道文件在哪个备份里？打开搜索备份，输入名称的一部分（baojia）或 *.xlsx、baojia*2025* 之类的模式；对于 Microsoft 365 备份，输入邮件主题的一部分。不区分大小写。可以将搜索限定到一个作业。

  • 搜索网络存储上所有文件、NAS 共享、Linux 系统和 Microsoft 365 的备份，涵盖仍保留的所有日期。
  • 每个结果显示作业、代理、完整路径、大小和最新备份的日期。版本下列出每个不同的版本；文件未改变的备份合并为一行。
  • 打开会显示该备份中的文件夹，您可以在其中下载文件或将其还原到代理。

不搜索磁盘映像和虚拟机备份。控制台无法读取代理本地磁盘或 USB 磁盘上的备份，这些备份计为已跳过。搜索也可以通过 REST API 使用（/api/v1/search）。

找到正确的备份：使用 日历 查看哪天运行了哪些备份，或查看作业页面的历史记录。

从磁盘映像还原单个文件

对于映像备份，点击备份运行中的浏览文件。可以直接在控制台中浏览映像内的 NTFS 文件系统，勾选文件和文件夹，并将其还原到任意代理——无需还原整个磁盘。 还原到文件夹时，文件的目录结构与文件备份相同：驱动器号成为第一级文件夹（D:RestoreCUsers…）。

从虚拟机还原单个文件（Proxmox VE、Hyper-V、VMware）

在虚拟机备份运行中，点击客户机旁的浏览文件。控制台会显示其磁盘的分区和 LVM 卷，并可浏览 NTFS、ext4 和 XFS 文件系统。下载勾选的文件（多个文件打包为 ZIP）或将其还原到任意代理。参见 Proxmox VE、Hyper-V 和 VMware ESXi。

还原整台机器

  • Windows 磁盘映像：还原到磁盘或裸机，也可还原到不同硬件——磁盘映像。
  • Linux 系统：还原到磁盘或裸机，或作为新的 Proxmox 虚拟机——Linux 系统备份。
  • Proxmox 虚拟机和容器：作为新客户机或就地还原——Proxmox VE。Proxmox 虚拟机还可以直接从备份即时运行，并在运行时迁移到存储（即时恢复）。
  • 数据库（SQL Server、PostgreSQL、MySQL/MariaDB）：以新名称或就地还原到某一时刻——数据库。
  • Hyper-V 虚拟机：作为新虚拟机或就地还原（保留 ID 和 MAC 地址）——Hyper-V。
  • VMware ESXi 虚拟机：作为新虚拟机或就地还原（保留 UUID 和 MAC 地址），可还原到任意 ESXi 主机和数据存储——VMware ESXi；也可通过 Linux 代理服务器代理从备份即时运行，然后复制到数据存储（即时恢复）。

恢复 ISO

裸机还原从恢复 ISO（写入 USB 闪存盘或挂载到虚拟机）启动机器，参见 恢复介质：

  • Linux 恢复 ISO——随每个版本发布（backupzit-recovery-linux.iso）；恢复介质页面会从更新源链接到它。
  • Windows 恢复 ISO——Windows PE 不允许再分发，因此需要在任意 Windows 10/11 或 Server PC 上构建一次：
    1. 从 Microsoft 安装免费的 Windows ADK（功能 Deployment Tools）和 Windows PE 加载项。
    2. 从发布中下载 build-winpe.ps1（位于代理软件包旁），并从装有代理的机器的 C:\Program Files\backupzit Agent 中取得 backupzit-agent.exe。
    3. 在管理员 PowerShell 中运行：.\build-winpe.ps1 -AgentExe .\backupzit-agent.exe -Out .\backupzit-recovery.iso。添加 -DriverDir C:\Drivers 以包含存储或网络驱动程序（例如 Proxmox 虚拟机的 VirtIO），添加 -RecoveryJson .\recovery.json 使其无需输入即可连接。
    4. 可选择将 ISO 复制到控制台的 /var/lib/backupzit/dist 目录；之后它会出现在恢复介质页面上。

控制台中的文件浏览适用于网络存储上的备份（SFTP、S3、SMB、Azure、加固存储库）；控制台会直接读取它们。对于代理本地磁盘上的备份，请使用命令行。

不通过控制台还原

如果控制台本身丢失，任何安装了代理的机器都可以使用存储目标的恢复单直接从存储还原：

set BACKUPZIT_PASSWORD=<recovery key>
set BACKUPZIT_SFTP_PASSWORD=...           (or the S3/SMB/hardened credentials)
backupzit-agent snapshots --repo sftp://backup@nas:22/backups/pc1_1a2b3c4d
backupzit-agent restore   --repo sftp://backup@nas:22/backups/pc1_1a2b3c4d --target D:\Restore latest

参见 命令行参考。

自动还原测试

BackupZit 会定期验证您的备份，无需您做任何操作：每周（可在 设置 → 还原测试 中配置）每个作业的代理会从最新备份中还原一个随机文件样本到临时文件夹，根据存储的校验和验证每个字节，然后再删除。对于磁盘映像，会读取并验证随机块。这会检验整个链条——存储访问、凭据、加密密钥和数据完整性。

  • 结果以还原测试运行的形式显示在“活动”和作业历史中，并按作业显示在 报告 中（还原测试列）。
  • 测试失败与其他任何故障一样，会触发电子邮件警报。
  • 作业页面上的测试还原会立即开始测试。
  • 样本大小限制了从存储读取的数据量——对于收取下载费用的云存储，请保持较小的样本。

Proxmox 虚拟机的启动测试

可读的块并不能证明虚拟机仍能启动。启用Proxmox 虚拟机备份的启动测试（设置 → 还原测试）后，Proxmox 虚拟机作业的还原测试还会通过即时恢复在作业所在节点上逐个启动最新备份中的每台虚拟机：它以新 ID 从备份运行，网卡处于断开状态（以免与原机器冲突），随后立即被删除。当虚拟机的 QEMU 客户机代理在配置的时间内响应时，即表示操作系统已启动，测试通过。没有客户机代理的虚拟机若持续运行一分钟即视为通过；运行页面会将其显示为运行中而不是已启动。

  • 测试运行期间，节点需要有足够的空闲内存再运行一台虚拟机。
  • 在虚拟机中安装 QEMU 客户机代理（Linux 上为 qemu-guest-agent，Windows 上为 VirtIO 客户机工具）并在虚拟机选项中启用，以便测试能确认启动。
  • 运行页面列出每台虚拟机的结果及启动所用时间。

检查所有已存储的数据

还原测试只读取一个样本。此外，代理会读取每个存储库中的 全部 数据，按校验和进行校验，并检查每个备份的文件夹和数据是否完整——默认每月一次（设置 → 还原测试：检查已存储的数据：每月、每三个月或从不）。这样可以在需要备份之前发现存储本身的损坏，例如 NAS 中的故障磁盘或数据腐化。每个存储库只检查一次（同一代理在同一存储上的作业共享该存储库），由写入它的代理执行。检查会读取存储库的全部内容，因此在云存储（S3、Azure）上只有开启 也包括云存储 时才会运行。发现问题时 数据检查 运行失败并发送失败通知；作业页面上的 检查数据 可立即开始检查。需要代理 0.39.0 或更高版本。

此外，请不时（例如每季度）手动还原一个真实的文件夹并打开几个文件——这也能训练那些在紧急情况下需要执行还原的人员。
