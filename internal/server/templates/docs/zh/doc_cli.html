命令行参考

代理也可以在命令行中独立工作——用于脚本、在没有控制台的情况下还原以及应急。不带参数运行 backupzit-agent 查看概览，运行 backupzit-agent <command> -h 查看某个命令的选项。

存储库和凭据

每个命令都接受 --repo（或 BACKUPZIT_REPO）。机密信息最好使用环境变量。代理的存储库是 <存储位置>/<hostname>_<id>——请查看“活动”中某次运行的存储库列，或恢复单。

位置凭据
D:\Backups\pc1, /mnt/backup/pc1—
sftp://user@host:22/pathBACKUPZIT_SFTP_PASSWORD 或 --sftp-key file；--sftp-hostkey SHA256:…（BACKUPZIT_SFTP_HOSTKEY）
s3://endpoint/bucket/prefix（HTTP 用 ?tls=false）BACKUPZIT_S3_ACCESS_KEY、BACKUPZIT_S3_SECRET_KEY、--s3-region；--s3-lock-days N 以 Object Lock 写入
smb://[domain;]user@host/share/pathBACKUPZIT_SMB_PASSWORD、--smb-domain
azure://account/container/path（主权云、Azure Stack、Azurite 用 ?endpoint=URL）BACKUPZIT_AZURE_KEY 或 BACKUPZIT_AZURE_SAS
hardened://host:8500/pathBACKUPZIT_HARDENED_KEY、BACKUPZIT_HARDENED_FINGERPRINT
usb://LABEL/path（通配符：usb://BZBACKUP*/BackupZit）—（使用带有该卷标的已连接磁盘）

加密的存储库需要在 BACKUPZIT_PASSWORD（或 --password）中提供恢复密钥。

某一时刻的视图：在启用 Object Lock 的 S3 和加固存储库上，--as-of 2026-10-01T14:30（或一个日期）会显示存储库在该时刻的样子——只读，用于在备份被删除或覆盖后进行恢复。

文件和文件夹

命令作用
init创建新的存储库（如果提供了密码则加密）。
backup [--vss] [--exclude PATTERN]… [--tag TAG]… [--force] [--host NAME] PATH…备份文件和文件夹。--vss 从卷影副本读取（Windows，管理员）；--force 读取所有文件，包括未更改的。
snapshots列出快照及其时间、主机、大小和路径。
ls SNAPSHOT|latest [PATH]列出快照中的文件。
restore --target DIR [--include PATH]… [--verify] SNAPSHOT|latest将文件还原到 DIR 下（重建原始文件夹结构）。--original 则将其写回原始位置，覆盖现有文件。
check [--read-data]检查存储库结构；使用 --read-data 时会下载并校验每个字节。

磁盘映像（Windows）

命令作用
disks [--json]显示磁盘和分区及其编号。
image-backup --disk N [--partitions 1,2] [--no-vss]
image-backup --all-disks		备份整个磁盘或选定的分区，或将所有内部磁盘备份到一个快照中。
image-restore --target-disk N --yes-erase-target [--keep-offline] [--source-disk N] SNAPSHOT|latest将映像写入磁盘；会擦除该磁盘。原始磁盘在同一台机器中时使用 --keep-offline；--source-disk 从所有磁盘备份中选择磁盘。
image-ls [--disk N] --partition N SNAPSHOT|latest [\path]列出映像中 NTFS 分区的文件（--disk：所有磁盘备份中被备份的磁盘）。
image-extract [--disk N] --partition N --target DIR SNAPSHOT|latest \path…从映像中的分区复制文件和文件夹。

Linux 系统（裸机，P2V）

命令作用
system-backup [--exclude PATTERN]备份所有本地文件系统和磁盘布局。参见 Linux 系统备份。
system-show SNAPSHOT|latest显示系统备份中的磁盘布局。
system-restore --target DEVICE [--new-hardware] [--rebuild-initramfs] --yes-erase-target SNAPSHOT|latest在空磁盘、逻辑卷或映像文件上重建系统。

Windows：不同硬件

命令作用
prepare-hardware --disk N [--drivers DIR]为不同硬件准备已还原的 Windows 磁盘（启动驱动程序、附加驱动程序、启动文件）——与还原选项相同，例如可从恢复 ISO 中再次执行。

VMware ESXi（任意代理作为代理服务器；密码在 BACKUPZIT_VMWARE_PASSWORD 中）

命令作用
vmware list --host H [--user root]显示主机的虚拟机、许可证模式、证书和 SSH 密钥指纹以及数据存储。
vmware backup --host H [--vmid N,N]从快照备份虚拟机（默认：全部）；启用 Changed Block Tracking 时只读取更改的块。
vmware restore --host H --vmid N [--new] [--name X] [--datastore DS] [--overwrite] [--start] SNAPSHOT|latest就地还原虚拟机（默认），或使用 --new 作为新虚拟机还原。--overwrite 替换现有虚拟机的磁盘；旧磁盘会改名保留。参见 VMware ESXi。
esxi-nfs-serve通过 NFS 从 /var/lib/backupzit/instant-esxi 向 ESXi 主机提供即时虚拟机（Linux；由即时恢复作为 systemd 单元 backupzit-esxi-nfs 启动）。

用 --thumbprint SHA256:… 和 --ssh-host-key SHA256:… 固定主机（由 vmware list 显示）。

Hyper-V（Hyper-V 主机上的代理，以管理员身份）

命令作用
hyperv list列出主机的虚拟机及其 BackupZit 编号，以及用于还原磁盘的文件夹。
hyperv backup [--vmid N,N]从生产检查点备份虚拟机（默认：全部）。
hyperv restore --vmid N [--new] [--name X] [--folder DIR] [--overwrite] [--start] SNAPSHOT|latest就地还原虚拟机（默认），或使用 --new 作为新虚拟机还原。--overwrite 替换现有虚拟机的磁盘。参见 Hyper-V。

pve show、pve ls 和 pve extract 也适用于 Hyper-V 备份。

Proxmox VE（Proxmox 主机上的代理）

命令作用
pve list列出集群的虚拟机和容器，以及可用于还原的存储。
pve backup [--vmid 100,200] [--exclude 300]从 Proxmox 快照备份此节点的客户机（默认：全部）。
pve show SNAPSHOT|latest显示虚拟机备份中的客户机和磁盘。
pve ls --vmid N [--disk scsi0] [--volume ID] SNAPSHOT|latest [path]列出客户机磁盘的分区和逻辑卷，或文件夹中的文件（NTFS、ext4、XFS，也支持 LVM 上的）。
pve extract --vmid N --target DIR [--volume ID] SNAPSHOT|latest path...从客户机磁盘复制文件和文件夹，无需还原虚拟机。
pve restore --vmid N [--new-vmid -1|N] [--name X] [--storage S] [--overwrite] [--start] SNAPSHOT|latest重建客户机；--new-vmid -1 使用下一个空闲 ID，--overwrite 替换具有相同 ID 的现有客户机。参见 Proxmox VE。
pve instant --vmid N [--new-vmid N] [--name X] SNAPSHOT|latest即时恢复：在几秒钟内启动虚拟机，同时从备份读取其磁盘（新虚拟机，默认使用下一个空闲 ID）。
pve instant-finish --vmid N --storage S在运行时将即时虚拟机的磁盘迁移到存储；之后不再使用备份。
pve instant-discard --vmid N停止并删除即时虚拟机及其更改。
nbd-serve --snapshot ID --vmid N --socket PATH通过 Unix 套接字上的 NBD 以只读方式提供备份中虚拟机的磁盘（由即时恢复作为 systemd 单元启动）。

Microsoft SQL Server（SQL Server 机器上的代理）

命令作用
sql list [--instance I]列出实例的数据库及其恢复模式和大小。
sql backup [--instance I] [--db a,b] [--system] [--log] [--copy-only]完整备份（默认：所有用户数据库），或使用 --log 将事务日志备份到存储库。
sql show列出存储库中的 SQL Server 备份及其 LSN 范围。
sql restore --db NAME [--as NEW] [--replace] [--at TIME] SNAPSHOT|latest从完整备份及其后的日志备份还原数据库，可选择还原到某一时刻。参见 SQL Server。

PostgreSQL 和 MySQL/MariaDB（数据库服务器上的代理）

命令作用
pg list [--port P]本地集群的数据库，以及 WAL 归档是否开启。
pg backup [--port P] [--db a,b] [--pitr | --wal]完整备份（pg_basebackup、每个数据库的 pg_dump；--pitr 设置 WAL 归档），或使用 --wal 备份已归档的 WAL。
pg restore --db NAME|"(cluster)" [--as NEW] [--replace] [--at TIME | --latest] SNAPSHOT|latest还原一个数据库（从其转储或到某一时刻），或将整个集群还原为单独的实例。
mysql list数据库，以及二进制日志是否开启。
mysql backup [--db a,b] [--binlog]每个数据库的 mysqldump 及其二进制日志位置，或已关闭的二进制日志。
mysql restore --db NAME [--as NEW] [--replace] [--at TIME | --latest] SNAPSHOT|latest加载转储并重放二进制日志到某一时刻。参见 数据库。

托管模式

命令作用
enroll --code BZ1-… [--force]使用“Agent”页面上的注册码将代理连接到控制台（--force 替换现有注册）。旧形式 --server URL --token T --fingerprint F 仍然可用。
set-server https://address:8443将已注册的代理指向控制台的新地址（相同证书）；然后重启代理服务。参见 Agent。
status显示正在运行的代理在做什么及其备份作业（Windows 托盘图标显示相同内容）。
service install|uninstall|start|stop|status|run管理代理服务（安装程序会处理）。
recovery恢复模式，由恢复 ISO 自动启动；在任何 Linux 实时系统上：sudo backupzit-agent recovery --server URL --token CODE。
version打印版本。

示例

set BACKUPZIT_PASSWORD=XXXX-XXXX-...
set BACKUPZIT_S3_ACCESS_KEY=...
set BACKUPZIT_S3_SECRET_KEY=...
backupzit-agent snapshots --repo s3://s3.wasabisys.com/company-backups/backupzit/pc1_1a2b3c4d
backupzit-agent restore --repo s3://s3.wasabisys.com/company-backups/backupzit/pc1_1a2b3c4d --target D:\Restore --include C:\Users\ana\Documents latest
backupzit-agent check --repo s3://... --read-data

backupzit-agent disks
backupzit-agent image-ls --repo usb://BZBACKUP1/BackupZit/pc1_1a2b3c4d --partition 3 latest \Users
backupzit-agent snapshots --repo hardened://vault:8500/backupzit/pc1_1a2b3c4d --as-of 2026-10-01T14:00

加固存储库（backupzit-repo）

命令作用
backupzit-repo serve运行服务（由 systemd 负责）。
backupzit-repo add-key NAME创建访问密钥（只显示一次）。
backupzit-repo keys / remove-key NAME列出 / 吊销访问密钥。
backupzit-repo fingerprint供控制台使用的证书指纹。
backupzit-repo status已存储和隐藏（已删除、仍保留）的数据。
backupzit-repo undelete --since TIME使自 TIME 以来删除的文件重新可见。

配置：/etc/backupzit-repo/repo.env — BACKUPZIT_REPO_LOCK_DAYS、BACKUPZIT_REPO_DATA、BACKUPZIT_REPO_LISTEN、BACKUPZIT_REPO_TLS_HOSTS。

管理服务器（backupzit-server）

选项 / 环境变量含义
--db / BACKUPZIT_DBPostgreSQL 连接字符串（必需）。
--listen / BACKUPZIT_LISTENHTTPS 地址，默认 :8443。
--data-dir / BACKUPZIT_DATA_DIR证书、secrets.key、代理下载（dist/）。
--public-url / BACKUPZIT_PUBLIC_URL代理和电子邮件链接使用的 URL。
--tls-hosts / BACKUPZIT_TLS_HOSTS自签名证书的附加名称/IP。
BACKUPZIT_ADMIN_PASSWORD初始管理员密码（仅首次启动时）。
BACKUPZIT_SECRETS_KEY机密密钥（base64），代替 secrets.key 文件。
--set-admin-password NEW重置 admin 的密码（重新启用其本地管理员身份）并退出。
--unblock-ip ADDRESS|all解除某个地址或所有地址的登录封锁（暴力破解防护）并退出。
--restore-console --repo R [--snapshot ID]从控制台备份还原控制台并退出（参见 安装服务器）。
--dev-embedded-db, --dev-http ADDR仅用于试用：数据目录中的私有 PostgreSQL，localhost 上的明文 HTTP。
--version打印版本。
