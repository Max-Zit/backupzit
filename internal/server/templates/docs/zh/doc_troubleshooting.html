故障排除和常见问题

代理显示为离线

  • 机器是否开机、服务是否在运行？Windows：Get-Service backupzit-agent；Linux：systemctl status backupzit-agent；macOS：sudo launchctl print system/com.backupzit.agent（参见 macOS 代理）。
  • 机器能否访问控制台？Test-NetConnection backup-server -Port 8443 或 curl -k https://backup-server:8443/login。
  • 代理日志：C:\ProgramData\backupzit\agent.log，Linux 上为 /var/log/backupzit/agent.log 或 journalctl -u backupzit-agent，macOS 上为 /Library/Logs/BackupZit/agent.log。“fingerprint mismatch” 表示控制台证书已更改 —— 请重新注册代理。

备份失败

在活动中打开该运行；消息会说明原因。常见原因：

消息包含解决方法
host key mismatch / fingerprintSFTP 服务器的密钥已更改，或指纹输入错误。在服务器上用 ssh-keygen -lf 检查。
permission denied / access denied存储凭据或文件夹权限问题。用 SFTP/SMB 客户端测试登录。
no space left / quota存储已满。缩短保留期或增加空间；过期的备份会在下一次运行后释放空间。
repository is locked同一存储库上正在运行其他操作（例如清理）；该运行会在 30 分钟内重试。过期的锁会自动失效。
wrong password / recovery key存储库是用另一个密钥创建的 —— 请检查作业是否使用了正确的存储目标。
bucket has no Object Lock enabled在未启用 Object Lock 的存储桶上请求了不可变性。请创建启用 Object Lock 的新存储桶。
S3 / Azure："the clock of this computer differs from the storage's by more than 15 minutes"（RequestTimeTooSkewed、Request date header too old）云存储会用时间签名每个请求，时钟偏差超过约 15 分钟时会拒绝请求。请校正运行中所列计算机的时间（代理；对于测试连接则为控制台），并开启时间同步：Windows 设置 → 时间和语言 → 自动设置时间；Linux 使用 timedatectl set-ntp true 或 chrony。虚拟机在长时间关机后或夏令时切换后可能时间不正确。

其他消息

情况处理方法
“no matching backup disk is connected”插入一块轮换使用的 USB 磁盘（消息会说明需要的卷标以及已连接了哪些带卷标的磁盘）。还原需要的正是备份运行中显示的那块磁盘。
“several backup disks are connected”每次只连接一块轮换磁盘。
还原测试失败打开该运行：消息会指出损坏的文件或数据块，或原因（例如存储上的备份被删除）。对存储库运行 backupzit-agent check --read-data，检查存储，然后启动新的备份。如果不可变存储上的备份被删除，请参见 勒索软件防护。
数据检查发现损坏的数据包存储丢失或更改了数据（例如提供商故障）。只要损坏的包还在索引中，新的备份就会继续复用其数据。在检查的运行页面上点击 修复：将损坏的数据移出索引，或运行 backupzit-agent repair --repo …（--dry-run 仅列出）：在独占锁下重新读取存储，损坏的包移出索引，运行会列出需要丢失数据的备份。这些备份会保留，并可还原剩余部分；勾选 同时删除需要丢失数据的备份 可将其删除，之后的数据检查和保留策略后的空间释放就会恢复正常。删除时需要输入密码或双因素代码；启用四眼审批时还需要第二位用户批准；正在运行 VM 的备份（即时恢复）会保留；在可疑备份后保留被暂停期间会拒绝删除。后续备份会重新存储这些数据。代理 0.55 及更高版本。自 0.55 起，只有确认损坏的包才会被移出：缺失的包，或完整读取后与其内容不符的包。如果存储中的包完整，但传到此代理时被截短，则会暂停后重新读取，仍失败时只列出并保留不动；请检查网络路径（代理、防火墙、IPS、NAT）。包文件本身由下一次清理删除。 无法从此代理读取文件夹列表的备份会被保留，绝不会作为受影响的备份删除。如果连续 20 个数据包无法读取，检查会以“the storage stopped answering”停止且不做任何判断：请检查存储和网络路径，然后重新运行。自 0.56 起，存储文件列表中缺失的包会先单独查找并多次重试，然后才算作缺失；如果列表为空，或一次缺少大部分包，则不作判断，检查会失败并说明原因，因此存储的临时故障绝不会把数据移出索引。
存储库的某个索引文件已损坏从 0.59 起，备份和还原会继续：该文件列出的包从其自身的包头读取，在重建索引之前，新备份不会重用其数据。在此期间，保留、释放空间和删除代理的备份会等待（较旧的还原点会保留，运行会发出警告）。修复会重建索引：重新列出包，验证损坏文件列出的每个包（尝试三次），检查备份使用的每个块都在新索引中或在已证实损坏的包中，然后才写入新索引；损坏的文件会用存储库的密钥封存后保留在 index-damaged/ 中。如果备份使用了任何包中都没有的数据，修复会列出这些备份并停止：请检查存储的所有数据文件夹是否都在，或勾选 同时删除需要丢失数据的备份 将其删除（仅当存储的两次列表一致时）。修复期间消失的包会使修复停止，且不做任何更改。释放空间时，如果某个不在索引中的包含有备份使用、而索引在别处没有的数据（索引文件丢失或被手动删除），绝不会删除它，而是验证该包并将其放回索引。数据检查在读取时发现存储刚刚列出的大多数包都不见了，不会做出任何判断。自 0.63 起，一个索引文件最多包含 256 个包、约 500,000 个块。代理 0.62.0 至 0.62.2 在清理写入了更大的索引文件后，无法打开含有大量小文件的存储库（“larger than 134217728 bytes”）：0.63 可以打开它，下一次释放空间会把索引重新写成较小的文件。
备份被标记为可疑检查该机器是否有勒索软件或大规模删除（例如同步文件夹被清空）。如果一切正常（例如计划内的迁移），请在作业页面点击 已检查 — 恢复保留。
Let's Encrypt：“could not verify … is port 80 … reachable”HTTP 验证要求 80 端口可从互联网访问。内部控制台请使用通过 Cloudflare 的 DNS 验证。
Let's Encrypt：“no Cloudflare zone … is accessible with this token”令牌必须对包含控制台名称的区域拥有 Zone → DNS → Edit 权限。
“HTTPS port 443: … permission denied” 或 “address already in use”其他程序占用了该端口，或者服务无法绑定 1024 以下的端口（请像软件包那样以 CAP_NET_BIND_SERVICE 运行它）。在 设置 → 证书 中选择其他端口。
更新：“updates from the console need the Linux package of the console”控制台不是通过 deb/rpm 软件包安装的（例如评估模式）。请按安装时的方式更新它。
更新：“the release is not signed with a BackupZit release key”更新源中没有官方发布版本，或文件在传输中被篡改。请从官方地址重新下载。
更新：状态为 rolled-back新版本未能启动，因此已还原之前的版本及其数据库。启动失败的日志在更新页面上；请将其发送给技术支持。
"The agent is no longer running this"代理在运行期间被重启或停止（例如计算机或服务重启），或无法提交结果。0.52.0 及更新的代理会报告正在处理的运行，因此控制台会在大约两分钟内将此类运行标记为失败，而不是一直显示为运行中直到有人停止它；对于旧版代理，请在其页面上停止它。Agent 页面上的 获取日志 可查看发生了什么。下一次计划运行照常开始。 如果代理正常关闭（停止服务、为更新而重启），运行会以 "The agent was stopped during the run" 结束。 在 Windows 上，0.62 及更新版本的代理会接收关机前通知：在网络断开之前，Windows 最多等待三分钟，让代理停止运行、解锁存储库并报告。
"agent stopped responding while the run was in progress"运行期间代理超过 10 分钟没有联系控制台（网络中断，或代理所在机器已停止）。控制台自身停机的时间不计算在内。代理会在两小时内持续尝试提交结果；结果到达后，运行会显示真实结果，其备份可以还原。
操作系统：“no supported package manager”操作系统更新支持 Debian、Ubuntu（apt）以及 AlmaLinux、Rocky Linux、RHEL（dnf）。
控制台备份：“the backup was made by a newer BackupZit”还原之前，请在新控制台上安装生成该备份的版本或更新的版本。
控制台备份：“console backups need network storage”请选择 SFTP、S3、SMB、Azure 或加固存储库目标；控制台无法访问代理的本地路径。
“登录失败次数过多”您的地址在多次输错密码后被封锁：默认 30 分钟，重复封锁时更久。管理员可以在 设置 → 登录与安全 中解除封锁。在服务器上，backupzit-server --unblock-ip all 会解除所有封锁。帐户永远不会被永久锁定。
丢失了双重验证登录的手机使用一个恢复代码;否则由管理员在您的用户页面上重置双重验证。如果已没有管理员能够登录,请在服务器上运行 backupzit-server --reset-two-factor USER(Docker:docker compose exec backupzit backupzit-server --reset-two-factor USER):它会关闭该用户的双重验证登录、注销其所有会话并记录到审计日志;然后用密码登录并重新设置。
“your directory account is not in any BackupZit group”将用户加入 设置 → LDAP / Active Directory 中已映射的某个组，或映射更多组。在那里使用 测试 可查看为某个用户找到的组。
API 返回 401 / 403401：令牌缺失、已撤销、已过期或其所有者已被禁用。403：令牌的角色权限不足以执行该请求。
Azure：AuthenticationFailed / AuthorizationPermissionMismatch帐户密钥错误，或者 SAS 令牌缺少读取、写入、删除或列出权限，或已过期。
还原的 Windows Server 2012 R2 / Windows 8.1 虚拟机无法在 Hyper-V 第 2 代上启动（“hash was denied (DBX)”）Microsoft 已为安全启动吊销了旧的引导加载程序。请为该虚拟机关闭安全启动，或在备份前更新系统。

虚拟机、Linux 系统和新硬件

情况处理方法
Proxmox：“the guest is running and one of its disks is on storage without snapshot support”运行中的来宾需要 LVM-thin、ZFS、Ceph RBD 或 qcow2 磁盘。移动磁盘（Disk Action → Move Storage），或在来宾停止时备份。
Proxmox：“container volumes that are directories on dir storage are not supported yet”容器的卷是目录、NFS 或 btrfs 存储上的一个目录。只有 ZFS 上的目录（子卷）会逐个文件备份；请将卷移动到 ZFS、LVM-thin 或 Ceph RBD（Volume Action → Move Storage）。
Hyper-V：运行显示 “crash-consistent”来宾无法为检查点做好准备。在 Windows 来宾中，检查虚拟机设置中的 Hyper-V 集成服务（Backup (volume shadow copy)）是否已启用。在 Linux 来宾中安装 hyperv-daemons（RHEL）或 linux-cloud-tools / hyperv-daemons（Debian/Ubuntu）。
VMware：“SSH off” 或 “SSH to …: connection refused”在 ESXi 主机上启用 SSH：Host → Actions → Services → Enable Secure Shell（并设置为随主机启动）。还原以及免费许可证下的备份都需要它。
VMware：“changed block tracking is off and can be enabled … only while the VM is off”免费 ESXi 许可证：关闭虚拟机一次，然后运行作业；BackupZit 会开启更改块跟踪，之后的备份只读取更改的块。
VMware：“copy the disk on the datastore (needs free space …)”运行中的虚拟机会在其数据存储上短暂复制。请在那里腾出空间（与磁盘实际使用量相同），或在虚拟机关闭时备份。
VMware：“… is a snapshot delta disk”该虚拟机有自己的快照。请在 ESXi 主机客户端中删除或合并它们（Snapshots → Delete all）；BackupZit 从不触碰它们。没有快照、但磁盘仅需合并（快照删除未完成）的虚拟机，会由代理在备份前合并（代理 0.57，vSphere API）；使用免费许可证时，请在主机客户端中运行 Snapshots → Consolidate。0.58 之前的代理还会拒绝静默快照在某些主机（ESXi 6.7，VMware Tools 正在运行）上写入的小型增量，尽管该虚拟机并没有快照：请更新代理。
VMware：“The session is not authenticated” 或 “401 Unauthorized”vSphere 会话在运行期间结束：0.55 之前的代理在长时间读取磁盘后会出现这种情况，主机的管理服务重启时也会出现。0.57 版代理会重新登录，并继续处理下一个虚拟机和快照删除；请更新旧版代理。遗留的快照会在仪表板上列出，并带有立即移除。
仪表板：“备份快照 … 已在 … 上遗留 …”、“备份检查点 …”、“临时磁盘副本 …”或“备份锁”备份未能删除它在虚拟机管理程序上创建的内容（代理中途被停止，或删除失败）；只要它还在，虚拟机的磁盘就会不断增长，或者在有锁的情况下来宾无法启动。代理会自行重试（Proxmox VE 和 Hyper-V 每 15 分钟一次，VMware 在该连接的下一次备份时）。单击立即移除可让它立即尝试；活动页面上的清理运行会显示删除了什么以及其余部分失败的原因（例如数据存储或存储繁忙、文件被其他程序锁定）。如果仍然失败，请使用虚拟机管理程序自己的工具删除：vSphere Client（Snapshots → Delete，然后 Consolidate）、Proxmox VE（qm delsnapshot ID NAME --force、qm unlock ID）、Hyper-V 管理器（Checkpoints → Delete）。请参阅 VMware、Proxmox VE 和 Hyper-V。
Proxmox：“guest … already has the backup lock”该来宾的另一个备份正在运行（BackupZit 或 vzdump），或者中断的运行留下了锁。代理会在 15 分钟内删除它自己设置的锁；其他任何锁，在没有备份运行时，可用 qm unlock ID 删除（容器：pct unlock ID）。
VMware：“the ESXi certificate changed”主机已重新安装，或其他机器在其地址上响应。如果这是预期情况，请核对指纹，然后在 Agent 页面上该主机旁单击接受新证书。
VMware：虚拟机磁盘旁出现 *.replaced-DATE.vmdk 文件原位还原的虚拟机的旧磁盘。确认还原的虚拟机工作正常后，在数据存储浏览器中删除它们。
Hyper-V：原位还原后留下的旧 VHDX 文件还原会分离虚拟机的旧磁盘并将其保留在原处（运行会逐一列出：old disk kept at …）；还原的磁盘位于 backupzit-restore-… 子文件夹中。确认还原的虚拟机工作正常后删除旧文件。
Proxmox 即时恢复：虚拟机无法启动或卡住检查磁盘服务器：在节点上运行 systemctl status backupzit-instant-ID 和 journalctl -u backupzit-instant-ID。备份存储必须保持可访问；无法读取存储库时，虚拟机的磁盘读取会停滞。
Proxmox 即时恢复：“efidisk0 stays on storage backupzit-instant”虚拟机运行时 QEMU 无法移动 EFI 变量存储。关闭虚拟机并运行 qm disk move ID efidisk0 STORAGE --delete 1；这不依赖于备份。
Proxmox：“runs on node X; install the BackupZit agent on X”该来宾已被迁移。在每个节点上安装代理，并用各节点的代理备份该节点的来宾。
Proxmox 备份或还原很慢，存储服务器上出现 SFTP “connection lost”、“message authentication code incorrect”Proxmox 主机上 Intel e1000e 网卡的已知问题（日志：“Detected Hardware Unit Hang”、“Reset adapter unexpectedly”）。关闭卸载功能：ethtool -K eno1 tso off gso off gro off，并将其作为接口的 post-up 行添加到 /etc/network/interfaces 中。
浏览文件：“stored on a local path of the agent”控制台只能读取网络存储上的备份。请在代理上使用 backupzit-agent pve ls/extract 或 image-ls/image-extract。
浏览文件：“this btrfs file system spans … devices”或“stripes data (RAID 0/10/5/6)”只能从备份中读取单个磁盘上的 btrfs。请通过即时恢复在原虚拟机旁边启动该虚拟机并复制文件，或使用虚拟机内代理的文件作业备份这些文件。请参阅恢复。
添加或测试存储目标时：“连接测试失败 … 控制台能否访问存储”，但代理的备份正常控制台无法访问该存储，例如控制台运行在 VPS 上，而 NAS 位于客户网络中。请从该站点的代理进行测试（测试连接，然后选择该代理），并将目标标记为仅代理可访问，使控制台不再连接它。之后，浏览文件会通过该站点的代理读取其备份（代理 0.61 及更高版本）。
Linux 系统还原：“missing programs …”在执行还原的机器上安装所列软件包，或从包含这些软件包的 BackupZit Linux 恢复 ISO 启动。
还原后的 Linux 机器没有网络网络设置绑定到了旧的 MAC 地址（netplan match: macaddress）。使用 不同硬件 还原，或删除 /etc/netplan/ 中的 match 行。
还原后的 Windows 停在 INACCESSIBLE_BOOT_DEVICE使用 还原到不同硬件 重新还原，或从恢复 ISO 启动并运行 backupzit-agent prepare-hardware --disk 0 [--drivers E:\Drivers]。
还原的机器副本显示为原来的代理作为新虚拟机还原的 Linux 系统会自动取消注册。对于其他副本（作为新虚拟机还原的虚拟机、即时恢复、虚拟机副本、克隆的磁盘），控制台会暂停该代理的运行并显示两台计算机；请将副本注册为新机器（参见 两台机器使用同一个代理）。
代理更新无法完成查看 C:\ProgramData\backupzit\updates、/var/lib/backupzit-agent/updates 或 /Library/Application Support/BackupZit/updates（macOS）中的安装程序日志；0.21 之前的代理需要手动更新一次。
Mac：“Full Disk Access is not granted”，文件“without a snapshot”读取，更新后完全磁盘访问权限丢失参见 macOS 代理：只有 Mac 的用户才能授予完全磁盘访问权限，未签名的安装包每次更新都会失去该权限。
“… is a Mac: back it up with a files job”Mac 不能作为系统进行备份；请使用文件作业（macOS 代理）。
托盘图标不见了点击时钟旁边的 ^ 箭头，把 BackupZit 图标拖到任务栏上，或从开始菜单启动 BackupZit Agent。

备份以“警告”结束

有些文件无法读取 —— 通常是在 VSS 不可用时被应用程序锁定的文件，或代理没有权限的文件。列表在运行页面上。其余内容都已备份。在 Mac 上，缺少完全磁盘访问权限也会产生警告（macOS 代理）。

仅在云端的文件。Mac 上的 iCloud 云盘（优化 Mac 储存空间）和 Windows 上的 OneDrive（文件随选，标记为仅在线可用的文件）会将许多文件的内容仅保存在云端。备份无法读取它们，自 0.60 起代理也不会尝试读取。上一次备份中未更改的文件会沿用那次备份中的内容。其他文件会被排除，并与读取错误分开、按文件夹列在运行页面的 仅在云端，未备份 下。运行会以警告结束，因为这些内容不在备份中。请在备份之前将文件下载到计算机上（Mac：“访达” → 立即下载；Windows：右键单击 → 始终保留在此设备上），或关闭“优化 Mac 储存空间”。工作或学校 OneDrive 也可以通过 Microsoft 365 作业直接从云端备份，包括仅在线可用的文件。另请参见 iCloud 云盘中的文件。

备份很慢

  • 第一次备份会读取并上传所有内容；之后只读取更改的文件，只上传新数据。
  • 检查到存储的网络路径（Wi-Fi、VPN、云存储的互联网上传速度）。
  • 排除不需要的缓存、临时文件和媒体文件。

常见问题

可以使用 NFS 吗？

要备份 NFS（或 SMB）共享，请创建 NAS / 文件共享 作业；Linux 代理会在每次运行时挂载该导出。要将备份存储到 NFS，请在代理上挂载导出（Linux：/etc/fstab），并使用 本地 / 挂载路径 目标，例如 /mnt/nfs-backup；对于 Windows 机器，SMB 目标是更好的选择。

可以把备份移到其他存储吗？

按原样复制存储库文件夹（或存储桶前缀）—— 它是自包含的 —— 然后添加一个指向新位置、使用相同恢复密钥的存储目标。

删除作业会删除备份吗？

不会。备份保留在存储上，仍可从活动或命令行还原。被删除作业的复制作业会随之删除；它们生成的副本保留在各自的存储上。

控制台宕机会怎样？

在控制台恢复之前不会启动新的计划备份；之后，每个已错过计划时间的作业会运行一次（除非其备份时间窗口已结束），排队的运行也会继续。始终可以凭恢复单从命令行进行还原。

备份需要多少空间？

第一次备份大约为压缩后的数据大小，再加上每个保留日的每日更改。报告页面会显示每个作业上传了多少数据。
