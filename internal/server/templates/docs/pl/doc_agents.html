Agenci

Na każdej chronionej maszynie instaluje się agenta. Działa jako usługa, co 30 sekund pyta konsolę o zadania i komunikuje się bezpośrednio z magazynem.

Obsługiwane systemy

  • Windows 10, 11 oraz Windows Server 2016 i nowsze — MSI Agent Windows.
  • Windows 7 SP1, Windows Server 2008 R2 SP1 i 2012 R2 — MSI Agent Windows — starsze systemy (…-legacy.msi), z tymi samymi funkcjami, w tym VSS i obrazami dysków.
  • Debian, Ubuntu, AlmaLinux, Rocky Linux (64-bitowe).
  • Węzły Proxmox VE 7 i 8 — pakiet Debiana; agent tworzy wtedy także kopie maszyn wirtualnych i kontenerów węzła (zobacz Proxmox VE).
  • Hosty Hyper-V (Windows Server 2016 i nowsze, Windows 10/11 z Hyper-V): MSI dla Windows. Agent tworzy wtedy także kopie maszyn wirtualnych hosta (zobacz Hyper-V).
  • Hosty VMware ESXi — na ESXi nic się nie instaluje: dodaj host w Hosty VMware ESXi i wybierz agenta jako proxy (zobacz VMware ESXi).

Rejestrowanie agentów

  1. Na stronie Agenci kliknij Utwórz token rejestracji. Konsola pokaże kod rejestracji (BZ1-…), ważny 7 dni i używalny na dowolnej liczbie maszyn. Zawiera adres konsoli dla agentów (z portem agentów, zwykle 8443, także gdy strona jest otwarta na porcie WWW 443), token i odcisk certyfikatu. Agenci od 0.33.6 rejestrują się także kodami, które starsze konsole utworzyły na porcie WWW.
  2. Windows: uruchom MSI i wklej kod, gdy instalator o niego poprosi. Linux: wykonaj pokazane polecenie.
  3. Maszyna pojawi się na liście agentów w ciągu minuty.

Jeśli konsola jest niedostępna podczas instalacji, agent zachowuje kod i ponawia próby, aż zdoła się zarejestrować. Aktualizacje zachowują rejestrację i nie pytają ponownie. Cicha instalacja z ENROLLCODE na już zarejestrowanej maszynie zachowuje rejestrację, gdy kod dotyczy tej samej konsoli (GPO lub RMM mogą ją bezpiecznie powtarzać), i przenosi maszynę, gdy kod dotyczy innej konsoli; poprzednia rejestracja jest zachowywana jako agent.json.replaced-data obok agent.json, więc przywrócenie nazwy przenosi maszynę z powrotem do starej konsoli jako tego samego agenta.

Windows, cicho (GPO, Intune, RMM)

msiexec /i backupzit-agent.msi /qn ENROLLCODE="BZ1-..."

Starsza forma SERVER="..." TOKEN="..." FINGERPRINT="SHA256:..." nadal działa. Cicha instalacja bez tych właściwości instaluje usługę, która czeka, aż zarejestrujesz ją poleceniem backupzit-agent enroll --code "BZ1-..." w wierszu poleceń administratora.

Linux

apt install ./backupzit-agent_*.deb        # or: dnf install ./backupzit-agent-*.rpm
backupzit-agent enroll --code "BZ1-..."
systemctl enable --now backupzit-agent

Instalowanie agentów z konsoli

Zamiast kopiować instalatory na każdą maszynę, pozwól konsoli zainstalować agenta: na stronie Agenci otwórz Zainstaluj na maszynie stąd, wybierz Linux lub Windows i podaj adres maszyny oraz konto administratora.

  • Linux (Debian, Ubuntu, AlmaLinux, Rocky Linux; 64-bitowe): konsola łączy się przez SSH jako root lub jako użytkownik z uprawnieniami sudo (hasło służy też do sudo; przy kluczu potrzebne jest sudo bez hasła). Działa hasło lub klucz prywatny. Podaj odcisk klucza hosta SSH maszyny (ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub na maszynie), aby mieć pewność, że konsola rozmawia z właściwą maszyną; bez niego odcisk zostanie pokazany w dzienniku instalacji.
  • Windows (64-bitowy): konsola łączy się przez WinRM (port 5985, komunikaty szyfrowane NTLM; 5986 dla nasłuchiwania HTTPS) jako administrator lokalny lub domenowy. WinRM jest domyślnie włączony w Windows Server; w Windows 10/11 uruchom raz winrm quickconfig jako administrator. Konta lokalne inne niż wbudowany Administrator potrzebują uprawnień zdalnej administracji (LocalAccountTokenFilterPolicy) — albo użyj konta domenowego. Starsze systemy (Windows 7, Server 2008 R2/2012 R2) dostają MSI legacy.

Maszyna pobiera najnowszy pakiet agenta z konsoli przez link ważny tylko dla tej instalacji (30 minut, trzy pobrania), sprawdza jego sumę SHA-256, instaluje go i się rejestruje. Strona instalacji pokazuje każdy krok; konto i hasło są używane tylko do tego i nie są zapisywane. Jeśli maszyna jest już zarejestrowana w tej konsoli, rejestracja zostaje zachowana, a pakiet zaktualizowany; rejestracja, której konsola nie zna (wcześniej usunięty agent lub inna konsola), zostaje zastąpiona. Każda instalacja trafia do dziennika audytu. Maszyna musi docierać do adresu agentów konsoli, jak każdy agent.

Stan agenta

  • online — agent kontaktował się z konsolą w ciągu ostatnich 3 minut.
  • offline — maszyna jest wyłączona, usługa zatrzymana lub sieć zablokowana. Zaplanowane kopie trafiają do kolejki i startują, gdy tylko agent wróci.
  • odzyskiwanie — maszyna uruchomiona z ISO odzyskiwania (Windows lub Linux), gotowa na przywrócenie obrazu dysku lub systemu Linux. Agenci odzyskiwania są tymczasowi; usuń ich po zakończeniu przywracania.

Kolumna Adresy IP pokazuje własne adresy maszyny, tak jak agent ostatnio je zgłosił. widziany z to adres, z którego przychodzą jego połączenia: w sieci lokalnej ten sam adres, dla maszyny za NAT (np. laptopa w domu) publiczny adres routera. Konsola nie pyta o to żadnej usługi zewnętrznej.

Agent na pulpicie (Windows)

Agent Windows pokazuje ikonę obok zegara (może być pod strzałką ^ ukrytych ikon — przeciągnij ją na pasek zadań, aby była stale widoczna). Kropka na ikonie pokazuje stan:

KropkaZnaczenie
zielonaKopie są w porządku (lub czekają na pierwszą zaplanowaną kopię).
niebieskaTrwa kopia, przywracanie lub test przywracania.
pomarańczowaOstatnia kopia zakończyła się ostrzeżeniami (pliki, których nie dało się odczytać).
czerwonaZadanie kopii nie powiodło się.
szaraKonsola jest niedostępna lub usługa agenta nie działa.

Kliknij ikonę (lub otwórz BackupZit Agent z menu Start), aby zobaczyć okno stanu: stan ochrony, postęp trwającej kopii, ostatnia i następna kopia oraz wszystkie zadania kopii komputera z przyciskiem Utwórz kopię teraz. Prawy przycisk otwiera menu: Back up now dla każdego zadania, Open console in browser, Hide this icon (do następnego logowania; kopie trwają dalej). Okno wymaga Microsoft Edge WebView2, który jest częścią Windows 10 i 11; w starszych systemach ikona i menu działają, a Open pokazuje konsolę w przeglądarce.

Użytkownicy mogą w ten sposób uruchomić kopię swojego komputera; zadania, harmonogramy i retencję ustawia się tylko w konsoli. W każdym systemie backupzit-agent status (jako administrator lub root) wyświetla te same informacje.

Aktualizacja

Gdy konsola ma nowszy instalator agenta niż ten, który działa na agencie, strona Agenci pokazuje Zaktualizuj do x.y.z obok jego wersji oraz Zaktualizuj wszystkich agentów pod listą. Agent wtedy:

  1. czeka, aż będzie bezczynny (trwająca kopia nigdy nie jest przerywana),
  2. pobiera z konsoli odpowiedni instalator przez swoje przypięte połączenie — MSI dla Windows 10/11/2016+, MSI starsze systemy dla Windows 7/2008 R2/2012 R2, pakiet deb lub rpm w Linuksie — i sprawdza jego SHA-256,
  3. instaluje go i uruchamia się ponownie; nowa wersja pojawia się na liście w ciągu kilku minut. Rejestracja i wszystkie ustawienia zostają zachowane.

Konsola oferuje najnowsze instalatory ze swojego katalogu dist; pakiet serwera zawiera instalatory agentów swojej własnej wersji. Po zaktualizowaniu konsoli w Ustawienia → Aktualizacje agenci są aktualizowani automatycznie (można to tam wyłączyć). Aktualizacje z konsoli działają dla agentów od wersji 0.21; starszych agentów aktualizuje się raz, instalując nowszy MSI / pakiet na starym (rejestracja zostaje zachowana). Dziennik instalatora jest w C:\ProgramData\backupzit\updates lub /var/tmp/backupzit-updates.

Usuwanie agenta

Usuń na stronie Agenci usuwa agenta i jego zadania z konsoli. Przy włączonym zatwierdzaniu na cztery oczy drugi użytkownik musi to najpierw zatwierdzić. Kopie w magazynie nie są usuwane. Odinstaluj oprogramowanie na maszynie osobno.

Dwie maszyny używające jednego agenta

Kopia zarejestrowanej maszyny zabiera ze sobą agenta i rejestrację: maszyna wirtualna przywrócona jako nowa, natychmiastowe odzyskiwanie, uruchomiona replika, sklonowany dysk lub szablon. Gdy kopia działa obok oryginału, obie łączą się jako ten sam agent. Konsola zauważa to w ciągu minuty lub dwóch, a następnie:

  • pokazuje dwa komputery z obiema nazwami i adresami na stronie Agenci, a agenta w sekcji Wymaga uwagi na pulpicie;
  • wstrzymuje kopie i przywracania agenta, aby nic nie uruchomiło się na niewłaściwej maszynie (przywracanie do oryginalnej lokalizacji mogłoby inaczej nadpisać kopię zamiast oryginału);
  • wysyła raz e-mail do administratorów i zapisuje wpis agent.duplicate w dzienniku audytu.

Zatrzymaj kopię lub — jeśli ma zostać — zarejestruj ją na kopii jako nową maszynę: backupzit-agent enroll --force --code "BZ1-..." (kod ze strony Agenci). Wstrzymane uruchomienia startują kilka minut po tym, jak zostanie tylko jedna maszyna. Przywrócenie systemu Linux przez Przywróć cały system już wyrejestrowuje agenta w przywróconej kopii, a testy przywracania uruchamiają swoje maszyny bez sieci, więc żadne z nich tego nie powoduje.

Gdy konsola dostaje nowy adres

Agenci ufają konsoli na podstawie jej certyfikatu, który pozostaje taki sam po zmianie adresu IP lub nazwy, ale łączą się z adresem, z którym zostali zarejestrowani. Po zmianie wykonaj na każdej maszynie z agentem (jako administrator / root):

backupzit-agent set-server https://192.168.1.20:8443

Polecenie sprawdza, czy konsola odpowiada pod nowym adresem z tym samym certyfikatem, zapisuje go, a agent używa go po ponownym uruchomieniu swojej usługi (systemctl restart backupzit-agent lub w Windows uruchom ponownie usługę BackupZit Agent). Użycie od początku nazwy DNS dla konsoli pozwala uniknąć tego kroku.

Gdzie agent przechowuje konfigurację

  • Windows: C:\ProgramData\backupzit\agent.json (dostępny tylko dla SYSTEM i Administratorów).
  • Linux: /etc/backupzit/agent.json (tylko root).

Plik zawiera sekret agenta. Każdy, kto może go odczytać, może działać jako ten agent, więc zachowaj te uprawnienia.

Dziennik agenta

  • Windows: C:\ProgramData\backupzit\agent.log
  • Linux: /etc/backupzit/agent.log i journalctl -u backupzit-agent
  • Systemy odzyskiwania wyświetlają dziennik na ekranie.

Odinstalowanie

Windows: Ustawienia → Aplikacje → BackupZit Agent → Odinstaluj (lub msiexec /x). Linux: apt remove backupzit-agent / dnf remove backupzit-agent. Następnie usuń agenta w konsoli. Kopie pozostają w magazynie.

W Windows odinstalowanie odkłada rejestrację na bok (C:\ProgramData\backupzit\agent.json.removed-data), więc ponowna instalacja agenta poprosi o kod rejestracji. Jeśli instalator znajdzie rejestrację wcześniejszej wersji, poinformuje o tym: zostaw kod pusty, aby ją zachować, lub wklej nowy kod, aby ponownie zarejestrować komputer (na przykład w innej konsoli).
