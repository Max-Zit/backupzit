Agenci

Na każdej chronionej maszynie instaluje się agenta. Działa jako usługa, co 30 sekund pyta konsolę o zadania i komunikuje się bezpośrednio z magazynem.

Obsługiwane systemy

  • Windows 10, 11 oraz Windows Server 2016 i nowsze — MSI Agent Windows.
  • Windows 7 SP1, Windows Server 2008 R2 SP1 i 2012 R2 — MSI Agent Windows — starsze systemy (…-legacy.msi), z tymi samymi funkcjami, w tym VSS i obrazami dysków.
  • Debian, Ubuntu, AlmaLinux, Rocky Linux (64-bitowe).
  • Komputery Mac z czipem Apple lub procesorem Intel, macOS 13 i nowszy — pakiet Agent macOS (…_darwin_universal.pkg), dla plików i folderów (zobacz Agenci macOS).
  • Węzły Proxmox VE 7, 8 i 9 — pakiet Debiana; agent tworzy wtedy także kopie maszyn wirtualnych i kontenerów węzła (zobacz Proxmox VE).
  • Hosty Hyper-V (Windows Server 2016 i nowsze, Windows 10/11 z Hyper-V): MSI dla Windows. Agent tworzy wtedy także kopie maszyn wirtualnych hosta (zobacz Hyper-V).
  • Hosty VMware ESXi — na ESXi nic się nie instaluje: dodaj host w Hosty VMware ESXi i wybierz agenta jako proxy (zobacz VMware ESXi).

Rejestrowanie agentów

  1. Na stronie Agenci kliknij Utwórz token rejestracji. Konsola pokaże kod rejestracji (BZ1-…), ważny 7 dni i używalny na dowolnej liczbie maszyn. Zawiera adres konsoli dla agentów (z portem agentów, zwykle 8443, także gdy strona jest otwarta na porcie WWW 443), token i odcisk certyfikatu. Agenci od 0.33.6 rejestrują się także kodami, które starsze konsole utworzyły na porcie WWW. Kod, który konsola tworzy dla instalacji ze strony Agenty, działa raz i jest usuwany po zakończeniu instalacji. Odwołaj wszystkie kody rejestracji usuwa wszystkie kody (także te na nośnikach odzyskiwania), np. gdy któryś udostępniono przez pomyłkę; zarejestrowane agenty działają dalej.
  2. Windows: uruchom MSI i wklej kod, gdy instalator o niego poprosi. Linux: wykonaj pokazane polecenie. macOS: zainstaluj pakiet i wklej kod, gdy aplikacja na pasku menu o niego poprosi, albo wykonaj pokazane polecenie w Terminalu (zobacz Agenci macOS).
  3. Maszyna pojawi się na liście agentów w ciągu minuty.

Jeśli konsola jest niedostępna podczas instalacji, agent zachowuje kod i ponawia próby, aż zdoła się zarejestrować. Aktualizacje zachowują rejestrację i nie pytają ponownie. Cicha instalacja z ENROLLCODE na już zarejestrowanej maszynie zachowuje rejestrację, gdy kod dotyczy tej samej konsoli (GPO lub RMM mogą ją bezpiecznie powtarzać), i przenosi maszynę, gdy kod dotyczy innej konsoli; poprzednia rejestracja jest zachowywana jako agent.json.replaced-data obok agent.json, więc przywrócenie nazwy przenosi maszynę z powrotem do starej konsoli jako tego samego agenta.

Windows, cicho (GPO, Intune, RMM)

msiexec /i backupzit-agent.msi /qn ENROLLCODE="BZ1-..."

Starsza forma SERVER="..." TOKEN="..." FINGERPRINT="SHA256:..." nadal działa. Cicha instalacja bez tych właściwości instaluje usługę, która czeka, aż zarejestrujesz ją poleceniem backupzit-agent enroll --code "BZ1-..." w wierszu poleceń administratora.

Linux

apt install ./backupzit-agent_*.deb        # or: dnf install ./backupzit-agent-*.rpm
backupzit-agent enroll --code "BZ1-..."
systemctl enable --now backupzit-agent

macOS

sudo /Library/BackupZit/bin/backupzit-agent enroll --code "BZ1-..."

Wykonaj je po zainstalowaniu .pkg albo wklej kod do aplikacji BackupZit na pasku menu, która prosi o niego po instalacji (później: Enroll this Mac… w jej menu). MDM zamiast tego zapisuje kod do /Library/Application Support/BackupZit/enroll-code przed instalacją pakietu. Pełny dostęp do dysku musi potem przyznać użytkownik Maca; zobacz Agenci macOS.

Instalowanie agentów z konsoli

Zamiast kopiować instalatory na każdą maszynę, pozwól konsoli zainstalować agenta: na stronie Agenci otwórz Zainstaluj na maszynie stąd, wybierz Linux lub Windows i podaj adres maszyny oraz konto administratora.

  • Linux (Debian, Ubuntu, AlmaLinux, Rocky Linux; 64-bitowe): konsola łączy się przez SSH jako root lub jako użytkownik z uprawnieniami sudo, za pomocą hasła lub klucza prywatnego (hasło klucza wpisuje się w Hasło klucza i służy ono tylko do otwarcia klucza). Konsola najpierw próbuje sudo bez hasła (sudo -n); hasło przekazuje sudo tylko wtedy, gdy sudo o nie poprosi — hasło użytkownika albo Hasło sudo, jeśli jest inne lub używany jest klucz — i hasło nigdy nie jest częścią skryptu instalacji. Hasła i hasła kluczy są ukryte w dzienniku instalacji. Podaj odcisk klucza hosta SSH maszyny (ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub na maszynie), aby mieć pewność, że konsola rozmawia z właściwą maszyną; bez niego odcisk zostanie pokazany w dzienniku instalacji.
  • Windows (64-bitowy): konsola łączy się przez WinRM (port 5985, komunikaty szyfrowane NTLM; 5986 dla nasłuchiwania HTTPS) jako administrator lokalny lub domenowy. WinRM jest domyślnie włączony w Windows Server; w Windows 10/11 uruchom raz winrm quickconfig jako administrator. Konta lokalne inne niż wbudowany Administrator potrzebują uprawnień zdalnej administracji (LocalAccountTokenFilterPolicy) — albo użyj konta domenowego. Starsze systemy (Windows 7, Server 2008 R2/2012 R2) dostają MSI legacy.

Gdy formularz nie podaje odcisku klucza hosta ani certyfikatu, konsola najpierw bez logowania odczytuje klucz hosta SSH (Linux) lub certyfikat odbiornika HTTPS usługi WinRM (Windows, port 5986), pokazuje go i wysyła hasło dopiero po Twoim potwierdzeniu; instalacja przyjmuje potem tylko ten klucz lub certyfikat. Porównaj go z maszyną (na Linuksie ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub). WinRM przez HTTP (port 5985) nie ma certyfikatu do sprawdzenia; tam, gdzie sieć między konsolą a maszyną nie jest zaufana, używaj odbiornika HTTPS.

Maców nie instaluje się stąd: wdróż .pkg ręcznie lub przez MDM (Agenci macOS).

Maszyna pobiera najnowszy pakiet agenta z konsoli przez link ważny tylko dla tej instalacji (30 minut, trzy pobrania), sprawdza jego sumę SHA-256, instaluje go i się rejestruje. Wcześniej konsola sprawdza pakiet według podpisanej listy instalatorów agenta swojego wydania, tak jak przy aktualizacjach agentów; w Linuksie nowy agent odczytuje kod rejestracji ze swojego wejścia, więc kod nie pojawia się na liście procesów. Strona instalacji pokazuje każdy krok; konto i hasło są używane tylko do tego i nie są zapisywane. Jeśli maszyna jest już zarejestrowana w tej konsoli, rejestracja zostaje zachowana, a pakiet zaktualizowany; rejestracja, której konsola nie zna (wcześniej usunięty agent lub inna konsola), zostaje zastąpiona. Każda instalacja trafia do dziennika audytu. Maszyna musi docierać do adresu agentów konsoli, jak każdy agent.

Stan agenta

  • online — agent kontaktował się z konsolą w ciągu ostatnich 3 minut.
  • offline — maszyna jest wyłączona, usługa zatrzymana lub sieć zablokowana. Zaplanowane kopie trafiają do kolejki i startują, gdy tylko agent wróci.
  • odzyskiwanie — maszyna uruchomiona z ISO odzyskiwania (Windows lub Linux), gotowa na przywrócenie obrazu dysku lub systemu Linux. Agenci odzyskiwania są tymczasowi; usuń ich po zakończeniu przywracania. W przeciwnym razie są usuwani automatycznie tydzień po ostatnim kontakcie.
  • zegar się różni — zegar komputera różni się od zegara konsoli o 2 minuty lub więcej (agenci 0.44.0 i nowsi przesyłają swój czas przy każdym odpytaniu); ostrzega też pulpit. Włącz synchronizację czasu na tym komputerze: od 15 minut magazyny S3 i Azure odrzucają jego kopie (zobacz Rozwiązywanie problemów). Jeśli pokazują to wszyscy agenci, błędny jest zegar samej konsoli.
  • Odśwież sprawia, że agent wyśle swoje dyski i VM (Proxmox VE, Hyper-V) przy następnym odpytaniu, np. po dodaniu magazynu lub gościa na hoście. W przeciwnym razie agenci wysyłają je co 15 minut, gdy są bezczynni, i po każdym uruchomieniu VM (agenci 0.54.1 i nowsi).
  • brak zadania kopii — żadne włączone zadanie kopii nie obejmuje tego komputera (jako jego agent ani jako proxy zadania VMware), liczone godzinę po rejestracji; pulpit wymienia tych agentów w sekcji Wymaga uwagi. Dodaj komputer do zadania, np. do zadania dla wielu agentów.

Kolumna Adresy IP pokazuje własne adresy maszyny, tak jak agent ostatnio je zgłosił. widziany z to adres, z którego przychodzą jego połączenia: w sieci lokalnej ten sam adres, dla maszyny za NAT (np. laptopa w domu) publiczny adres routera. Konsola nie pyta o to żadnej usługi zewnętrznej.

Nazwy i tagi

Serwery różnych klientów lub lokalizacji często mają tę samą nazwę hosta. Kliknij agenta na stronie Agenty, aby nadać mu nazwę wyświetlaną w konsoli i tagi — dowolne etykiety, np. klient lub lokalizacja, oddzielone przecinkami. Nazwa jest używana w formularzach zadań, przy przywracaniu, w Aktywności, raportach i e-mailach; nazwa hosta zgłaszana przez komputer pozostaje widoczna obok, a strona agenta ostrzega, gdy inne agenty zgłaszają tę samą nazwę hosta. Kliknij tag, aby pokazać tylko agenty, które go mają.

Zmiana nazwy zmienia tylko to, co pokazuje konsola: agent, jego repozytorium i kopie zapasowe pozostają bez zmian, a komputer nie może zmienić swojej nazwy ani tagów. Ich zmiana wymaga uprawnienia do agentów i jest zapisywana w dzienniku audytu. Tagi pomagają znaleźć agenty; nie dają ani nie ograniczają dostępu i nie dodają agentów do zadań. Każdy, kto może zalogować się do konsoli, widzi wszystkie agenty, a konsola przechowuje klucze wszystkich ich kopii — klienci, którzy muszą być ściśle rozdzieleni, potrzebują osobnej konsoli.

Agent na pulpicie (Windows)

Agent Windows pokazuje ikonę obok zegara (może być pod strzałką ^ ukrytych ikon — przeciągnij ją na pasek zadań, aby była stale widoczna). Kropka na ikonie pokazuje stan:

KropkaZnaczenie
zielonaKopie są w porządku (lub czekają na pierwszą zaplanowaną kopię).
niebieskaTrwa kopia, przywracanie lub test przywracania.
pomarańczowaOstatnia kopia zakończyła się ostrzeżeniami (pliki, których nie dało się odczytać).
czerwonaZadanie kopii nie powiodło się.
szaraKonsola jest niedostępna lub usługa agenta nie działa.

Kliknij ikonę (lub otwórz BackupZit Agent z menu Start), aby zobaczyć okno stanu: stan ochrony, postęp trwającej kopii, ostatnia i następna kopia oraz wszystkie zadania kopii komputera z przyciskiem Utwórz kopię teraz. Prawy przycisk otwiera menu: Back up now dla każdego zadania, Open console in browser, Hide this icon (do następnego logowania; kopie trwają dalej). Okno wymaga Microsoft Edge WebView2, który jest częścią Windows 10 i 11; w starszych systemach ikona i menu działają, a Open pokazuje konsolę w przeglądarce. Open console in browser otwiera adres internetowy konsoli, także gdy port 8443 obsługuje tylko agentów (agent i konsola 0.61 i nowsze).

Na Macu aplikacja na pasku menu robi to samo i dodatkowo sprawdza uprawnienia, o które macOS prosi użytkownika (zobacz Agenci macOS).

Użytkownicy mogą w ten sposób uruchomić kopię swojego komputera; zadania, harmonogramy i retencję ustawia się tylko w konsoli. W każdym systemie backupzit-agent status (jako administrator lub root) wyświetla te same informacje.

Kilka zadań naraz

Domyślnie agent wykonuje jedno zadanie naraz; pozostałe czekają w kolejce. W kolumnie Zadania naraz na stronie Agenci możesz pozwolić na maksymalnie 8 — przydatne dla agentów kopiujących wiele rzeczy, np. agenta proxy dla ESXi, Proxmox, Microsoft 365 lub udziałów NAS. Dwa uruchomienia tego samego zadania nigdy nie działają jednocześnie, a aktualizacje agenta czekają, aż będzie wolny. Uruchomienia równoległe dzielą procesor, dyski i sieć maszyny; zwiększaj liczbę stopniowo. W Windows migawki VSS są tworzone jedna po drugiej. Wymaga agentów 0.39.0 lub nowszych.

Aktualizacja

Gdy konsola ma nowszy instalator agenta niż ten, który działa na agencie, strona Agenci pokazuje Zaktualizuj do x.y.z obok jego wersji oraz Zaktualizuj wszystkich agentów pod listą. Agent wtedy:

  1. czeka, aż będzie bezczynny (trwająca kopia nigdy nie jest przerywana),
  2. pobiera z konsoli odpowiedni instalator przez swoje przypięte połączenie — MSI dla Windows 10/11/2016+, MSI starsze systemy dla Windows 7/2008 R2/2012 R2, pakiet deb lub rpm w Linuksie, .pkg na Macu — i sprawdza go: od 0.56 instalator musi znajdować się na liście instalatorów agenta podpisanej kluczem wydań BackupZit, którą agent sprawdza wbudowanym w siebie kluczem, więc instalator zmieniony na konsoli zostaje odrzucony,
  3. instaluje go i uruchamia się ponownie; nowa wersja pojawia się na liście w ciągu kilku minut. Rejestracja i wszystkie ustawienia zostają zachowane.

Konsola oferuje najnowsze instalatory ze swojego katalogu dist; pakiet serwera zawiera instalatory agentów swojej własnej wersji. Po zaktualizowaniu konsoli w Ustawienia → Aktualizacje agenci są aktualizowani automatycznie (można to tam wyłączyć). Aktualizacje z konsoli działają dla agentów od wersji 0.21; starszych agentów aktualizuje się raz, instalując nowszy MSI / pakiet na starym (rejestracja zostaje zachowana). Agenci 0.56 i nowsi przyjmują aktualizację tylko od konsoli 0.56 lub nowszej (jej pakiet zawiera podpisaną listę) i nigdy do wersji starszej niż własna. Dziennik instalatora jest w C:\ProgramData\backupzit\updates, /var/lib/backupzit-agent/updates lub, na Macu, /Library/Application Support/BackupZit/updates. Aktualizacja agenta na Macu, którego pakiet nie jest podpisany identyfikatorem Apple Developer ID, odbiera mu pełny dostęp do dysku (zobacz Agenci macOS).

Usuwanie agenta

Usuń na stronie Agenci otwiera stronę z dwoma wyborami; przy włączonym zatwierdzaniu na cztery oczy najpierw musi to zatwierdzić drugi użytkownik.

  • Odinstaluj agenta z komputera (agenci online od wersji 0.42.7): agent się zgłasza, sam się odinstalowuje, a potem jest usuwany z konsoli wraz z zadaniami. Agent offline jest usuwany tylko z konsoli — odinstaluj go na komputerze (patrz niżej).
  • Jego kopie: zachowaj wszystkie (domyślnie — pozostają w magazynie i nadal można je przywrócić), zachowaj tylko najnowszą kopię każdego zadania (każda kopia jest pełna, więc najnowsza przywraca wszystko na swoją datę) lub usuń wszystkie. Usunięcie wymaga wpisania nazwy komputera; konsola usuwa w tle i zapisuje wynik w dzienniku audytu. Niezmienny magazyn przechowuje zablokowane dane do wygaśnięcia blokady; kopie na dysku samego komputera i kopie zadań kopiowania nie są usuwane. Agent, który wykonuje kopie innych systemów (Proxmox, VMware, Hyper-V, Microsoft 365, NAS), zabiera ich kopie ze sobą.

Usuwanie kopii wymaga też Twojego hasła — lub bieżącego kodu z aplikacji uwierzytelniającej, gdy logowanie dwuskładnikowe jest włączone — aby sama skradziona sesja przeglądarki nie wystarczyła do ich usunięcia. Drugi użytkownik zatwierdzający usunięcie potwierdza w ten sam sposób. Użytkownicy logujący się przez SSO potrzebują do tego logowania dwuskładnikowego.

Zachowane kopie pozostają w Aktywności (oznaczone jako usunięty) i w kreatorze przywracania, i można je przywrócić na dowolnego innego agenta. Strona Agenci pokazuje usunięte agenty z zachowanymi kopiami: Usuń kopie usuwa je później (zachowaj najnowszą kopię każdego zadania lub wszystkie). Gdy komputer ponownie dostanie agenta, Połącz z bieżącym agentem przenosi je do nowego agenta o tej samej nazwie: pokazuje je on, a jego zadania kontynuują w tych samych repozytoriach, z deduplikacją względem starych kopii. Agent, który ma już własne kopie, przejmuje tylko historię; jego zadania zachowują swoje repozytoria. Kopie znalezione w magazynie (zob. Wyszukiwanie kopii w magazynie) są wyświetlane i łączone w ten sam sposób.

Dwie maszyny używające jednego agenta

Kopia zarejestrowanej maszyny zabiera ze sobą agenta i rejestrację: maszyna wirtualna przywrócona jako nowa, natychmiastowe odzyskiwanie, uruchomiona replika, sklonowany dysk lub szablon. Gdy kopia działa obok oryginału, obie łączą się jako ten sam agent. Konsola zauważa to w ciągu minuty lub dwóch, a następnie:

  • pokazuje dwa komputery z obiema nazwami i adresami na stronie Agenci, a agenta w sekcji Wymaga uwagi na pulpicie;
  • wstrzymuje kopie i przywracania agenta, aby nic nie uruchomiło się na niewłaściwej maszynie (przywracanie do oryginalnej lokalizacji mogłoby inaczej nadpisać kopię zamiast oryginału);
  • wysyła raz e-mail do administratorów i zapisuje wpis agent.duplicate w dzienniku audytu.

Zatrzymaj kopię lub — jeśli ma zostać — zarejestruj ją na kopii jako nową maszynę: backupzit-agent enroll --force --code "BZ1-..." (kod ze strony Agenci). Wstrzymane uruchomienia startują kilka minut po tym, jak zostanie tylko jedna maszyna. Przywrócenie systemu Linux przez Przywróć cały system już wyrejestrowuje agenta w przywróconej kopii, a testy przywracania uruchamiają swoje maszyny bez sieci, więc żadne z nich tego nie powoduje.

Gdy konsola dostaje nowy adres

Agenci ufają konsoli na podstawie jej certyfikatu, który pozostaje taki sam po zmianie adresu IP lub nazwy, ale łączą się z adresem, z którym zostali zarejestrowani. Po zmianie wykonaj na każdej maszynie z agentem (jako administrator / root):

backupzit-agent set-server https://192.168.1.20:8443

Polecenie sprawdza, czy konsola odpowiada pod nowym adresem z tym samym certyfikatem, zapisuje go, a agent używa go po ponownym uruchomieniu swojej usługi (systemctl restart backupzit-agent lub w Windows uruchom ponownie usługę BackupZit Agent). Użycie od początku nazwy DNS dla konsoli pozwala uniknąć tego kroku.

Gdzie agent przechowuje konfigurację

  • Windows: C:\ProgramData\backupzit\agent.json (dostępny tylko dla SYSTEM i Administratorów). Agent używa folderu tylko wtedy, gdy jest to prawdziwy folder, którego właścicielem jest SYSTEM lub Administratorzy: folder utworzony przed instalacją przez innego użytkownika albo łącze (junction) do innego folderu odkłada na bok bez czytania jako C:\ProgramData\backupzit.untrusted-data i uruchamia się bez rejestracji (agenci 0.63 i nowsi).
  • Linux: /etc/backupzit/agent.json (tylko root).
  • macOS: /Library/Application Support/BackupZit/agent.json (tylko root).

Plik zawiera sekret agenta. Każdy, kto może go odczytać, może działać jako ten agent, więc zachowaj te uprawnienia.

Dziennik agenta

  • Windows: C:\ProgramData\backupzit\agent.log
  • Linux: /var/log/backupzit/agent.log i journalctl -u backupzit-agent
  • macOS: /Library/Logs/BackupZit/agent.log
  • Systemy odzyskiwania wyświetlają dziennik na ekranie.
  • Dziennik obejmuje do 4 plików po 10 MB (agent.log oraz agent.log.1 do .3); starsze wpisy są usuwane.
  • Pobierz dziennik na stronie Agenci pobiera koniec dziennika do konsoli — zobacz Dzienniki.

Odinstalowanie

Windows: Ustawienia → Aplikacje → BackupZit Agent → Odinstaluj (lub msiexec /x). Linux: apt remove backupzit-agent / dnf remove backupzit-agent. macOS: sudo /Library/BackupZit/uninstall.sh (zobacz Agenci macOS). Następnie usuń agenta w konsoli. Kopie pozostają w magazynie.

W Windows odinstalowanie odkłada rejestrację na bok (C:\ProgramData\backupzit\agent.json.removed-data), więc ponowna instalacja agenta poprosi o kod rejestracji. Jeśli instalator znajdzie rejestrację wcześniejszej wersji, poinformuje o tym: zostaw kod pusty, aby ją zachować, lub wklej nowy kod, aby ponownie zarejestrować komputer (na przykład w innej konsoli).
