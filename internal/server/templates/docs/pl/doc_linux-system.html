Kopia systemu Linux i P2V

Zadanie System Linux tworzy kopię całej maszyny Linux, aby można ją było odtworzyć na pustym dysku — tę samą maszynę po awarii dysku, nowy sprzęt lub maszynę wirtualną w Proxmox VE (z fizycznej na wirtualną, P2V).

Co jest kopiowane

  • Każdy lokalny system plików (ext2/3/4, xfs, vfat), także na LVM, plik po pliku z właścicielami, uprawnieniami, bitami setuid, listami ACL, atrybutami rozszerzonymi (etykiety SELinux, capabilities plików), dowiązaniami twardymi i plikami urządzeń. Każdy system plików jest kopiowany osobno; udziały sieciowe i wirtualne systemy plików (/proc, /sys, /run) są pomijane.
  • Układ dysków: tablice partycji GPT lub MBR z ich identyfikatorami, grupy woluminów LVM (vgcfgbackup), UUID, etykiety i funkcje systemów plików oraz kod rozruchowy (MBR i partycja rozruchowa BIOS dla GRUB).

Podobnie jak Relax-and-Recover, BackupZit nie kopiuje działającego dysku blok po bloku: Linux nie ma wbudowanej migawki działającego dysku, więc surowa kopia byłaby niespójna. Każdy plik jest odczytywany w całości, a układ sprawia, że przywrócony dysk znów się uruchamia. Bazy danych należy przed kopią zrzucić lub kopiować ich własnymi narzędziami.

Pojedyncze pliki i foldery przywraca się z kopii systemu jak z każdej kopii plików (Przywróć pliki z tej kopii na stronie uruchomienia).

Jeszcze nieobsługiwane

Szyfrowane dyski (LUKS), programowy RAID (mdadm), btrfs i systemy rozłożone na kilka dysków. Zadanie wyraźnie to zgłasza, zamiast tworzyć niepełną kopię.

Przywracanie całego systemu

Otwórz uruchomienie kopii systemu (strona zadania lub Aktywność) i użyj Przywróć cały system:

Jako nowa VM Proxmox

Wybierz węzeł Proxmox (pracę wykonuje jego agent BackupZit), magazyn, ID maszyny, nazwę, pamięć i rdzenie. BackupZit tworzy maszynę z tym samym firmware co oryginał (UEFI/OVMF lub BIOS), dyskiem i kartą sieciową VirtIO SCSI, odtwarza dysk, przywraca wszystkie pliki i może uruchomić maszynę. Ponieważ maszyna jest kopią, która może działać obok oryginału:

  • ustawienia sieci powiązane ze starymi adresami MAC (typowe w obrazach chmurowych: netplan match: macaddress) są zmieniane tak, by dotyczyły dowolnego interfejsu przewodowego,
  • agent BackupZit w kopii jest wyrejestrowywany, aby nie zgłaszał się jako oryginalna maszyna.

Na dysk

Przywróć na pusty dysk agenta Linux, np. drugi dysk (/dev/sdb), albo na samą nową maszynę (bare metal):

  1. W Odzyskiwanie pobierz ISO odzyskiwania Linux i utwórz kod odzyskiwania. Zapisz ISO na pendrive (Rufus, balenaEtcher) lub podłącz do maszyny wirtualnej. Uruchamia się na maszynach BIOS i UEFI.
  2. Uruchom z niego maszynę. System odzyskiwania uruchamia agenta, który łączy się z konsolą za pomocą backupzit/recovery.json z innego pendrive'a lub dysku albo pyta o adres serwera i kod odzyskiwania.
  3. Maszyna pojawia się jako agent odzyskiwanie. W uruchomieniu kopii systemu wybierz Na dysk, tego agenta i jego dysk (zwykle /dev/sda, /dev/nvme0n1 lub /dev/vda).

Działa też dowolny system Linux live: uruchom w nim agenta poleceniem sudo backupzit-agent recovery --server https://console:8443 --token CODE; brakujące narzędzia (gdisk, LVM, mkfs) zostaną wymienione. Zaznacz Inny sprzęt, gdy maszyna nie jest oryginalna.

Cel może być większy lub mniejszy niż oryginalny dysk: ostatnia partycja powiększa się, by go wypełnić, lub zmniejsza, o ile jej dane się mieszczą. UUID systemów plików i identyfikatory partycji pozostają te same, więc /etc/fstab i program rozruchowy nie wymagają zmian. W systemach UEFI program rozruchowy jest też instalowany w ścieżce nośników wymiennych \EFI\BOOT\BOOTX64.EFI, którą każdy firmware UEFI uruchamia bez wpisu rozruchowego. Systemy podobne do RHEL (dracut) dostają nowy initramfs ze wszystkimi sterownikami przy przenosinach na inny sprzęt.

Wiersz poleceń

backupzit-agent system-backup  --repo ... [--exclude PATTERN]
backupzit-agent system-show    --repo ... latest
backupzit-agent system-restore --repo ... --target /dev/sdb [--new-hardware] --yes-erase-target latest
