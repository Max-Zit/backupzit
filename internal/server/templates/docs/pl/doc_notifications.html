Powiadomienia: e-mail, Slack, Teams, webhooki

Otrzymuj e-mail, gdy kopia się nie powiedzie, i codzienne podsumowanie każdego ranka.

Konfiguracja e-maila

W Ustawienia → Powiadomienia e-mail:

PolePrzykład
Serwer SMTP / portsmtp.office365.com / 587, smtp.gmail.com / 587, wewnętrzny przekaźnik / 25
BezpieczeństwoSTARTTLS (port 587), TLS (port 465) lub brak (tylko wewnętrzny przekaźnik)
Użytkownik / hasłoSkrzynka używana do wysyłania; pozostaw puste dla anonimowego przekaźnika. Microsoft 365 i Gmail wymagają hasła aplikacji.
Nadawcabackup@example.com
OdbiorcyJeden lub więcej adresów, rozdzielonych przecinkami.

Użyj Wyślij testowy e-mail, aby sprawdzić ustawienia.

Co jest wysyłane

  • Błędy (zalecane) — jeden e-mail na każde nieudane uruchomienie z przyczyną: kopie, kopie wtórne, przywracania i nieudane testy przywracania. Przy tej opcji otrzymasz też alert SUSPICIOUS, gdy kopia wygląda na ransomware lub masowe usunięcie.
  • Ostrzeżenia — uruchomienia, w których nie udało się odczytać części plików.
  • Sukcesy — każde udane uruchomienie (zwykle za dużo; lepiej raport dzienny).
  • Raport dzienny — o wybranej godzinie: uruchomienia z ostatnich 24 godzin, problemy i agenci offline. Temat zaczyna się od OK, WARNINGS lub ATTENTION, więc reguły poczty mogą je sortować.

Do podsumowań tygodniowych lub miesięcznych używaj raportów zaplanowanych; są wysyłane z tymi samymi ustawieniami poczty i mają własnych odbiorców. Tematy zaczynają się od [BackupZit], więc reguły poczty mogą je sortować. Hasło SMTP jest przechowywane w postaci zaszyfrowanej.

Slack, Microsoft Teams i webhooki

W Ustawienia → Czat i webhooki dodaj dowolną liczbę kanałów; każdy wybiera, czy otrzymuje błędy, ostrzeżenia i sukcesy. Nietypowe kopie (możliwy ransomware) liczą się jako błędy. Wyślij test od razu sprawdza kanał.

  • Slack: utwórz incoming webhook dla kanału (ustawienia aplikacji Slack → Incoming Webhooks) i wklej jego URL (https://hooks.slack.com/services/…).
  • Microsoft Teams: w kanale dodaj przepływ pracy Post to a channel when a webhook request is received i wklej jego URL. Wiadomości przychodzą jako karty z przyciskiem otwierającym uruchomienie w konsoli.
  • Webhook: dowolny URL przyjmujący POST z JSON — system zgłoszeń, monitoring lub narzędzie automatyzacji. Z sekretem podpisu każde żądanie zawiera X-BackupZit-Signature: sha256=<hex>, HMAC-SHA256 treści, więc odbiorca może sprawdzić, że pochodzi z Twojej konsoli.

JSON webhooka:

{"event": "run.finished", "run_id": 412, "kind": "vm-backup", "kind_title": "VM backup",
 "status": "failed", "suspicious": "", "job": "Proxmox VMs", "job_id": 7, "agent": "pve1",
 "message": "…", "errors": ["…"], "started_at": "2026-10-04T22:00:03+02:00",
 "finished_at": "2026-10-04T22:04:41+02:00", "url": "https://backup.example/runs/412"}

Wiadomości są wysyłane raz na uruchomienie, także gdy e-mail jest wyłączony. Kanał, który zawiedzie (błędny URL, usługa niedostępna), jest zapisywany w logu konsoli i nie wstrzymuje pozostałych. Adresy URL webhooków są przechowywane w postaci zaszyfrowanej.
