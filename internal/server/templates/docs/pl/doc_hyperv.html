Maszyny wirtualne Hyper-V

BackupZit tworzy kopie maszyn wirtualnych Hyper-V za pomocą agenta na hoście Hyper-V; wewnątrz maszyn nic nie jest instalowane. Goście Windows i Linux są przechwytywani bez zatrzymywania. Można je przywrócić jako nową maszynę lub w miejsce oryginału.

Konfiguracja

  1. Zainstaluj MSI Agent Windows z Agenci na hoście Hyper-V i zarejestruj go. Obsługiwane hosty: Windows Server 2016 lub nowszy z rolą Hyper-V albo Windows 10/11 z Hyper-V. W klastrze zainstaluj agenta na każdym hoście.
  2. W ciągu minuty host pojawia się na stronie Agenci z oznaczeniem Hyper-V · N VMs.
  3. W Zadania kopii wybierz tego agenta i Maszyny wirtualne (Proxmox VE, Hyper-V, VMware). Następnie wybierz:
    • wszystkie maszyny hosta, co obejmuje też maszyny utworzone później;
    • pojedyncze maszyny, zaznaczając je.

Agent korzysta z własnych interfejsów Hyper-V: modułu PowerShell Hyper-V i interfejsu Windows Virtual Disk API. Konsola nie przechowuje danych logowania Hyper-V.

Jak kopiowana jest maszyna

  1. Tworzony jest tymczasowy punkt kontrolny odzyskiwania (backupzit_…). To typ punktu kontrolnego, który Hyper-V udostępnia aplikacjom do kopii. Hyper-V prosi gościa o przygotowanie:
    • Goście Windows opróżniają bufory aplikacji przez VSS.
    • Goście Linux zamrażają systemy plików, jeśli zainstalowano demony Hyper-V (hyperv-daemons / hv-vss-daemon).
    Jeśli gość nie może zrobić żadnego z nich, punkt kontrolny jest tworzony w trybie spójności awaryjnej (crash-consistent). Strona uruchomienia pokazuje, który rodzaj został użyty.
  2. Punkt kontrolny odzyskiwania włącza Resilient Change Tracking (RCT) dla dysków maszyny; obok nich zobaczysz pliki .rct i .mrt. Pierwsza kopia odczytuje całe dyski. Potem RCT wskazuje, które bloki zmieniły się od poprzedniej kopii, i tylko one są odczytywane.
  3. Dyski są odczytywane w stanie z punktu kontrolnego, przez Virtual Disk API, w blokach po 1 MiB. Obejmuje to pliki VHDX i VHD, w tym łańcuchy wcześniejszych punktów kontrolnych. Puste bloki nie są zapisywane, a bloki już obecne w repozytorium nie są ponownie wysyłane.
  4. Punkt kontrolny jest usuwany, a Hyper-V scala go w tle.
  5. Konfiguracja maszyny jest zapisywana razem z kopią: generacja, procesor, pamięć, karty sieciowe (przełącznik, VLAN, adres MAC), kontrolery dysków, bezpieczny rozruch i TPM.

Wyłączone maszyny są odczytywane bezpośrednio, bez punktu kontrolnego. Na hostach starszych niż Windows Server 2016 (bez punktów kontrolnych odzyskiwania) używany jest produkcyjny punkt kontrolny, a każda kopia odczytuje całe dyski.

Przykład z laboratorium testowego: maszyna Linux z dyskiem 3 GB. Pierwsza kopia odczytała 3 GB. Następna, po 64 MB nowych danych, odczytała 96 MB.

W Windows 10/11 Hyper-V tworzy automatyczny punkt kontrolny przy starcie maszyny, chyba że ta opcja jest wyłączona w ustawieniach maszyny. BackupZit radzi sobie z takimi punktami, ale na serwerach warto wyłączyć automatyczne punkty kontrolne (ustawienia maszyny → Punkty kontrolne).

Przywracanie maszyny

Otwórz uruchomienie kopii maszyny (ze strony zadania lub z Aktywność) i użyj Przywróć VM Hyper-V.

Jako nowa maszyna obok oryginału

Tworzy drugą maszynę z nowymi adresami MAC, aby mogła działać w tej samej sieci co oryginał. Domyślnie nosi nazwę oryginału z dopiskiem „restored” i datą. Automatyczne punkty kontrolne są w niej wyłączane (Windows włącza je w nowych maszynach), więc jej uruchomienie nie pozostawia plików punktów kontrolnych. Jeśli kopia działa obok oryginału i zawiera agenta BackupZit, zobacz Dwie maszyny z jednym agentem.

Ustawienia sieci gościa powiązane z adresem MAC nie dotyczą nowych kart. Przykładem jest match: macaddress w netplan, używane przez obrazy chmurowe Linux.

W miejsce oryginalnej maszyny

Zaznacz wyłącz ją i zastąp jej dyski. BackupZit wtedy:

  • wyłącza istniejącą maszynę;
  • scala jej punkty kontrolne;
  • zamienia jej dyski na przywrócone.

Maszyna zachowuje swój identyfikator, karty sieciowe i adresy MAC, więc zadania, monitoring i sieć gościa nadal działają.

Stare pliki dysków nie są usuwane; zmienia się ich nazwę na ….replaced-DATE. Usuń je, gdy przywrócona maszyna działa.

Jeśli oryginalna maszyna już nie istnieje, jest tworzona ponownie, z nowym identyfikatorem Hyper-V.

Opcje

  • Folder na dyski wirtualne: domyślny folder hosta lub dowolny folder z dyskami maszyn. Przywracanie w miejscu umieszcza nowe dyski obok oryginalnych.
  • Uruchom VM po przywróceniu.

Co otrzymuje przywrócona maszyna

  • Przełączniki wirtualne są łączone według nazwy. Jeśli przełącznik nie istnieje na hoście, karta pozostaje odłączona.
  • Każda przywrócona maszyna otrzymuje nowy identyfikator generacji, aby kontrolery domeny Active Directory bezpiecznie wykryły przywrócenie.

Przywracanie pojedynczych plików

W tabeli maszyn uruchomienia kliknij Przeglądaj pliki, aby zobaczyć partycje i woluminy na dyskach maszyny. Możesz przeglądać NTFS, ext2/3/4 i XFS, także wewnątrz LVM. Stamtąd pobierzesz pliki lub przywrócisz je na dowolnego agenta. Działa to dokładnie tak jak w Proxmox VE.

Wiersz poleceń

Uruchom na hoście Hyper-V jako administrator:

backupzit-agent hyperv list
backupzit-agent hyperv backup  --repo ... [--vmid N,N]
backupzit-agent hyperv restore --repo ... --vmid N [--new] [--name NAME] [--folder D:\VMs] [--overwrite] [--start] SNAPSHOT|latest
  • --vmid to numer pokazywany przez hyperv list. BackupZit wylicza go z GUID maszyny.
  • Bez --new maszyna jest przywracana w miejscu.
  • --overwrite potwierdza, że dyski istniejącej maszyny mają zostać zastąpione.

Opcje repozytorium są takie same jak dla wszystkich poleceń; zobacz Wiersz poleceń — dokumentacja.

Jeszcze nieobsługiwane

  • Niektóre typy dysków. Współdzielone VHDX, VHD Set i dyski pass-through nie są kopiowane.
