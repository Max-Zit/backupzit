Rozwiązywanie problemów i FAQ

Agent jest pokazywany jako offline

  • Czy maszyna jest włączona i usługa działa? Windows: Get-Service backupzit-agent; Linux: systemctl status backupzit-agent.
  • Czy maszyna dociera do konsoli? Test-NetConnection backup-server -Port 8443 lub curl -k https://backup-server:8443/login.
  • Dziennik agenta: C:\ProgramData\backupzit\agent.log, w Linuksie /etc/backupzit/agent.log lub journalctl -u backupzit-agent. „fingerprint mismatch” oznacza, że certyfikat konsoli się zmienił — zarejestruj agenta ponownie.

Kopia się nie powiodła

Otwórz uruchomienie w Aktywność; komunikat podaje przyczynę. Częste przyczyny:

Komunikat zawieraRozwiązanie
host key mismatch / fingerprintKlucz serwera SFTP się zmienił lub odcisk wpisano błędnie. Sprawdź poleceniem ssh-keygen -lf na serwerze.
permission denied / access deniedDane logowania magazynu lub uprawnienia do folderu. Przetestuj logowanie klientem SFTP/SMB.
no space left / quotaMagazyn jest pełny. Skróć przechowywanie lub dodaj miejsce; wygasłe kopie zwalniają miejsce po następnym uruchomieniu.
repository is lockedInna operacja (np. czyszczenie) działa na tym samym repozytorium; uruchomienie ponawia próby przez 30 minut. Przestarzałe blokady wygasają automatycznie.
wrong password / recovery keyRepozytorium utworzono innym kluczem — sprawdź, czy zadanie używa właściwego magazynu.
bucket has no Object Lock enabledZażądano niezmienności dla bucketu utworzonego bez Object Lock. Utwórz nowy bucket z Object Lock.

Inne komunikaty

SytuacjaCo zrobić
„no matching backup disk is connected”Podłącz jeden z rotacyjnych dysków USB (komunikat podaje wymaganą etykietę i podłączone dyski z etykietami). Przywracanie wymaga dokładnie tego dysku, który pokazano w uruchomieniu kopii.
„several backup disks are connected”Podłączaj naraz tylko jeden z rotacyjnych dysków.
Test przywracania nie powiódł sięOtwórz uruchomienie: komunikat podaje uszkodzony plik lub blok albo przyczynę (np. kopia usunięta z magazynu). Uruchom backupzit-agent check --read-data dla repozytorium, sprawdź magazyn i uruchom nową kopię. Jeśli kopie usunięto z niezmiennego magazynu, zobacz Ochrona przed ransomware.
Kopia oznaczona jako podejrzanaSprawdź maszynę pod kątem ransomware lub masowego usunięcia (np. opróżniony folder synchronizowany). Jeśli wszystko jest w porządku (np. zaplanowana migracja), kliknij Sprawdzono — wznów przechowywanie na stronie zadania.
Let's Encrypt: „could not verify … is port 80 … reachable”Sprawdzenie HTTP wymaga portu 80 dostępnego z internetu. Dla konsol wewnętrznych użyj sprawdzenia DNS przez Cloudflare.
Let's Encrypt: „no Cloudflare zone … is accessible with this token”Token musi mieć uprawnienie Zone → DNS → Edit dla strefy zawierającej nazwę konsoli.
„HTTPS port 443: … permission denied” lub „address already in use”Inny program używa portu albo usługa nie może otwierać portów poniżej 1024 (uruchom ją z CAP_NET_BIND_SERVICE, jak robi to pakiet). Wybierz inny port w Ustawienia → Certyfikat.
Aktualizacje: „updates from the console need the Linux package of the console”Konsoli nie zainstalowano z pakietu deb/rpm (np. tryb próbny). Aktualizuj ją tak, jak została zainstalowana.
Aktualizacje: „the release is not signed with a BackupZit release key”Źródło aktualizacji nie zawiera oficjalnego wydania albo pliki zostały zmienione po drodze. Pobierz je ponownie z oficjalnego adresu.
Aktualizacje: stan rolled-backNowa wersja się nie uruchomiła, więc przywrócono poprzednią i jej bazę danych. Dziennik nieudanego startu jest na stronie Aktualizacje; wyślij go do pomocy technicznej.
System operacyjny: „no supported package manager”Aktualizacje systemu operacyjnego są obsługiwane w Debianie, Ubuntu (apt) oraz AlmaLinux, Rocky Linux, RHEL (dnf).
Kopia konsoli: „the backup was made by a newer BackupZit”Przed przywróceniem zainstaluj na nowej konsoli wersję, która utworzyła kopię, lub nowszą.
Kopia konsoli: „console backups need network storage”Wybierz magazyn SFTP, S3, SMB, Azure lub utwardzone repozytorium; ścieżka lokalna agenta jest niedostępna dla konsoli.
„Zbyt wiele nieudanych logowań”Twój adres zablokowano po powtarzanych błędnych hasłach: domyślnie na 30 minut, dłużej przy powtarzanych blokadach. Administrator może zdjąć blokadę w Ustawienia → Logowanie i bezpieczeństwo. Na serwerze backupzit-server --unblock-ip all zdejmuje wszystkie blokady. Konta nigdy nie są blokowane na stałe.
Zgubiony telefon do logowania dwuskładnikowegoUżyj jednego z kodów odzyskiwania; w przeciwnym razie administrator zresetuje logowanie dwuskładnikowe na Twojej stronie użytkownika. Ostatni administrator może zresetować swoje hasło na serwerze poleceniem backupzit-server --set-admin-password.
„your directory account is not in any BackupZit group”Dodaj użytkownika do jednej z grup przypisanych w Ustawienia → LDAP / Active Directory lub przypisz więcej grup. Użyj tam Test, aby zobaczyć grupy znalezione dla użytkownika.
API zwraca 401 / 403401: brak tokenu, token odwołany, wygasły lub jego właściciel wyłączony. 403: rola tokenu jest za niska dla żądania.
Azure: AuthenticationFailed / AuthorizationPermissionMismatchBłędny klucz konta albo tokenowi SAS brakuje prawa odczytu, zapisu, usuwania lub listowania, albo wygasł.
Przywrócona maszyna z Windows Server 2012 R2 / Windows 8.1 nie uruchamia się w Hyper-V Gen 2 („hash was denied (DBX)”)Microsoft unieważnił stary program rozruchowy dla Secure Boot. Wyłącz Secure Boot dla tej maszyny albo zaktualizuj system przed wykonaniem kopii.

Maszyny wirtualne, systemy Linux i nowy sprzęt

SytuacjaCo zrobić
Proxmox: „the guest is running and one of its disks is on storage without snapshot support”Działający goście wymagają dysków LVM-thin, ZFS, Ceph RBD lub qcow2. Przenieś dysk (Disk Action → Move Storage) albo kopiuj gościa, gdy jest zatrzymany.
Hyper-V: uruchomienie podaje „crash-consistent”Gość nie mógł się przygotować do punktu kontrolnego. W gościach Windows sprawdź, czy usługi integracji Hyper-V (Backup (volume shadow copy)) są włączone w ustawieniach maszyny. W gościach Linux zainstaluj hyperv-daemons (RHEL) lub linux-cloud-tools / hyperv-daemons (Debian/Ubuntu).
VMware: „SSH off” lub „SSH to …: connection refused”Włącz SSH na hoście ESXi: Host → Actions → Services → Enable Secure Shell (i ustaw uruchamianie razem z hostem). Wymagają tego przywracania, a przy darmowej licencji także kopie.
VMware: „changed block tracking is off and can be enabled … only while the VM is off”Darmowa licencja ESXi: wyłącz raz maszynę, a potem uruchom zadanie; BackupZit włączy śledzenie zmienionych bloków i kolejne kopie będą czytać tylko zmienione bloki.
VMware: „copy the disk on the datastore (needs free space …)”Działające maszyny są na chwilę kopiowane w swoim datastore. Zwolnij tam miejsce (tyle, ile zajmuje dysk) albo kopiuj maszynę, gdy jest wyłączona.
VMware: „… is a snapshot delta disk”Maszyna ma własne migawki. Usuń je lub skonsoliduj w kliencie hosta ESXi (Snapshots → Delete all).
VMware: „the ESXi certificate changed”Host zainstalowano ponownie albo pod jego adresem odpowiada inna maszyna. Jeśli to oczekiwane, usuń host w Agenci i dodaj go ponownie, aby przypiąć nowy certyfikat.
VMware: pliki *.replaced-DATE.vmdk obok dysków maszynyStare dyski maszyny przywróconej w miejscu. Usuń je w przeglądarce datastore, gdy przywrócona maszyna działa.
Hyper-V: pliki *.replaced-DATE obok dysków maszynyStare dyski maszyny przywróconej w miejscu. Usuń je, gdy przywrócona maszyna działa.
Natychmiastowe odzyskiwanie Proxmox: maszyna się nie uruchamia lub zawieszaSprawdź serwer dysków: systemctl status backupzit-instant-ID i journalctl -u backupzit-instant-ID na węźle. Magazyn kopii musi pozostać dostępny; gdy repozytorium nie da się odczytać, odczyty dysku maszyny stają.
Natychmiastowe odzyskiwanie Proxmox: „efidisk0 stays on storage backupzit-instant”QEMU nie może przenieść magazynu zmiennych EFI, gdy maszyna działa. Wyłącz maszynę i uruchom qm disk move ID efidisk0 STORAGE --delete 1; nie zależy to od kopii.
Proxmox: „runs on node X; install the BackupZit agent on X”Gość został zmigrowany. Zainstaluj agenta na każdym węźle i kopiuj gości każdego węzła agentem tego węzła.
Wolne kopie lub przywracanie w Proxmox, SFTP „connection lost”, „message authentication code incorrect” na serwerze magazynuZnany problem kart sieciowych Intel e1000e na hostach Proxmox (dziennik: „Detected Hardware Unit Hang”, „Reset adapter unexpectedly”). Wyłącz offloading: ethtool -K eno1 tso off gso off gro off i dodaj to jako wiersz post-up interfejsu w /etc/network/interfaces.
Przeglądanie plików: „stored on a local path of the agent”Konsola może czytać tylko kopie w magazynie sieciowym. Użyj backupzit-agent pve ls/extract lub image-ls/image-extract na agencie.
Przywracanie systemu Linux: „missing programs …”Zainstaluj wymienione pakiety na przywracającej maszynie albo uruchom ISO odzyskiwania Linux BackupZit, które je zawiera.
Przywrócona maszyna Linux nie ma sieciUstawienia sieci były powiązane ze starym adresem MAC (netplan match: macaddress). Przywróć z opcją Inny sprzęt albo usuń wiersze match w /etc/netplan/.
Przywrócony Windows zatrzymuje się z INACCESSIBLE_BOOT_DEVICEPrzywróć ponownie z opcją Przywróć na inny sprzęt albo uruchom ISO odzyskiwania i wykonaj backupzit-agent prepare-hardware --disk 0 [--drivers E:\Drivers].
Przywrócona kopia maszyny pojawia się jako oryginalny agentPrzywracanie do nowej maszyny Proxmox automatycznie wyrejestrowuje agenta w kopii. W innych kopiach usuń agent.json w kopii i zarejestruj ją jako nową maszynę.
Aktualizacja agenta się nie kończyZobacz dziennik instalatora w C:\ProgramData\backupzit\updates lub /var/tmp/backupzit-updates; agentów starszych niż 0.21 trzeba raz zaktualizować ręcznie.
Brak ikony w zasobnikuKliknij strzałkę ^ obok zegara i przeciągnij ikonę BackupZit na pasek zadań albo uruchom BackupZit Agent z menu Start.

Kopia kończy się „ostrzeżeniem”

Części plików nie udało się odczytać — zwykle plików zablokowanych przez aplikację, gdy VSS nie jest dostępny, lub plików, do których agent nie ma uprawnień. Lista jest na stronie uruchomienia. Wszystko inne zostało skopiowane.

Kopie są wolne

  • Pierwsza kopia odczytuje i wysyła wszystko; kolejne odczytują tylko zmienione pliki i wysyłają tylko nowe dane.
  • Sprawdź ścieżkę sieciową do magazynu (Wi-Fi, VPN, prędkość wysyłania do internetu w przypadku magazynu w chmurze).
  • Wyklucz pamięci podręczne, pliki tymczasowe i niepotrzebne multimedia.

FAQ

Czy mogę użyć NFS?

Aby kopiować udział NFS (lub SMB), utwórz zadanie NAS / udział plików; agent Linux montuje eksport przy każdym uruchomieniu. Aby przechowywać kopie na NFS, zamontuj eksport na agencie (Linux: /etc/fstab) i użyj magazynu Ścieżka lokalna / zamontowana, np. /mnt/nfs-backup; dla maszyn Windows lepszym wyborem jest magazyn SMB.

Czy mogę przenieść kopie do innego magazynu?

Skopiuj folder repozytorium (lub prefiks bucketu) bez zmian — jest samodzielny — i dodaj magazyn wskazujący nowe miejsce z tym samym kluczem odzyskiwania.

Czy usunięcie zadania usuwa kopie?

Nie. Kopie pozostają w magazynie i można je przywrócić z Aktywność lub z wiersza poleceń.

Co się dzieje, gdy konsola nie działa?

Do jej powrotu nie startują nowe zaplanowane kopie; uruchomienia w kolejce są potem kontynuowane. Przywracanie jest zawsze możliwe z wiersza poleceń z arkuszem odzyskiwania.

Ile miejsca będą potrzebować kopie?

Dla pierwszej kopii mniej więcej rozmiar danych po kompresji, plus codzienne zmiany za każdy przechowywany dzień. Strona Raporty pokazuje, ile wysłano dla każdego zadania.
