REST API

Zintegruj BackupZit z platformami RMM, monitoringiem (PRTG, Zabbix, Nagios, Uptime Kuma …) i własnymi skryptami.

Tokeny

Utwórz token w Moje konto → Tokeny API. Nadaj mu najniższą wystarczającą rolę — Obserwator do monitoringu, Operator przywracania, aby także uruchamiać kopie i testy przywracania. Token jest pokazywany tylko raz; wysyłaj go w każdym żądaniu:

Authorization: Bearer bzt_...

Tokeny mogą wygasać, mogą zostać odwołane przez właściciela lub administratora (Użytkownicy) i przestają działać, gdy właściciel zostanie wyłączony. Działania wykonane tokenem pojawiają się w dzienniku audytu z nazwą tokenu.

Punkty końcowe

Wszystkie odpowiedzi są w JSON. Bazowy URL: https://<konsola>:8443.

Metoda i ścieżkaRolaZwraca
GET /api/v1/statusObserwatorOgólny stan: agenci online, błędy i ostrzeżenia w ciągu 24 h, aktywne uruchomienia, niesprawdzone podejrzane kopie, "ok": true|false
GET /api/v1/agentsObserwatorAgenci z systemem, wersją, stanem online i ostatnim kontaktem
GET /api/v1/jobs, GET /api/v1/jobs/{id}ObserwatorZadania z harmonogramem, następnym uruchomieniem i ostatnim wynikiem
POST /api/v1/jobs/{id}/runOperator przywracaniaUruchamia zadanie teraz: {"run_id": 123} (202) lub 409, jeśli uruchomienie jest już aktywne
POST /api/v1/jobs/{id}/testOperator przywracaniaUruchamia test przywracania najnowszej kopii zadania
GET /api/v1/runs?job=&agent=&status=&limit=ObserwatorOstatnie uruchomienia, od najnowszych (domyślnie 100, maks. 1000)
GET /api/v1/runs/{id}ObserwatorJedno uruchomienie z komunikatem, błędami i statystyką
GET /api/v1/report?period=&from=&to=&agent=&job=ObserwatorRaport za okres: sumy, odsetek sukcesów i szczegóły dla każdego zadania
GET /api/v1/targetsObserwatorMagazyny docelowe (bez danych logowania)

Okresy: today, yesterday, last7, last30, last90, thisweek, lastweek, thismonth, lastmonth lub custom z from=2026-09-01&to=2026-09-30.

Błędy zwracają {"error": "..."} z kodem 400 (błędne żądanie), 401 (brak tokenu, token nieprawidłowy lub wygasły), 403 (zbyt niska rola), 404 lub 409.

Przykłady

curl

curl -sk -H "Authorization: Bearer $BZ_TOKEN" https://backup.example.local:8443/api/v1/status
curl -sk -X POST -H "Authorization: Bearer $BZ_TOKEN" https://backup.example.local:8443/api/v1/jobs/7/run

PowerShell

$h = @{ Authorization = "Bearer $env:BZ_TOKEN" }
$s = Invoke-RestMethod -Uri https://backup.example.local:8443/api/v1/status -Headers $h -SkipCertificateCheck
if (-not $s.ok) { Write-Warning "BackupZit needs attention: $($s.failed_24h) failed backups" }

Używaj -k / -SkipCertificateCheck tylko z certyfikatem samopodpisanym konsoli w zaufanej sieci albo zainstaluj certyfikat konsoli na hoście monitoringu.

Sprawdzanie w monitoringu

Odpytuj /api/v1/status co kilka minut i alarmuj, gdy ok ma wartość false. Do sprawdzania poszczególnych zadań użyj /api/v1/jobs i alarmuj, gdy last_status to failed albo last_finished jest starszy niż oczekiwano.
