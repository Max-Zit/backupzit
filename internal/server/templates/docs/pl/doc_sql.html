Bazy danych: SQL Server, PostgreSQL, MySQL

BackupZit tworzy kopie baz danych narzędziami samego serwera bazy, za pomocą agenta na maszynie z bazą: Microsoft SQL Server w Windows, PostgreSQL i MySQL/MariaDB w Linuksie. Pełne kopie działają według harmonogramu zadania; kopie dzienników co kilka minut pozwalają przywrócić pojedynczą bazę na dowolny moment — na przykład na minutę przed błędnym DELETE.

Tworzenie zadania

W Zadania kopii utwórz zadanie typu Bazy danych na agencie maszyny z bazą i wybierz:

  • Serwer bazy danych: Microsoft SQL Server, PostgreSQL lub MySQL/MariaDB. Nie można go później zmienić.
  • Instancja lub port: instancja SQL Server (puste dla instancji domyślnej, np. SQLEXPRESS) lub port PostgreSQL (puste dla 5432). Z MySQL/MariaDB agent łączy się przez lokalne gniazdo.
  • Bazy danych: jedna nazwa w wierszu albo puste dla wszystkich baz użytkownika — bazy utworzone później są dołączane automatycznie.
  • Kopiuj dzienniki co … minut: np. 15 — dzienniki transakcji (SQL Server), zarchiwizowany WAL (PostgreSQL) lub dzienniki binarne (MySQL). Pozostaw puste, jeśli wystarczy przywracanie na czas pełnej kopii.
  • Harmonogram dotyczy pełnych kopii, np. codziennie o 22:00.

Kopie są deduplikowane — niezmienione dane nie są wysyłane ponownie — i szyfrowane jak każda kopia. Przechowywanie liczy pełne kopie; kopie dzienników są przechowywane tak długo jak pełna kopia, na której się opierają. Strona uruchomienia pokazuje, co zawiera każda kopia.

Microsoft SQL Server

  1. Zainstaluj agenta na maszynie Windows, na której działa SQL Server (dowolna edycja od 2012, w tym Express).
  2. Agent działa jako NT AUTHORITY\SYSTEM i łączy się z uwierzytelnianiem Windows. Nadaj temu kontu rolę sysadmin, raz na instancję: 
    sqlcmd -S .\SQLEXPRESS -E -Q "ALTER SERVER ROLE sysadmin ADD MEMBER [NT AUTHORITY\SYSTEM]"
  • Każde uruchomienie zapisuje jeden plik kopii na bazę (BACKUP DATABASE / BACKUP LOG … WITH CHECKSUM) w domyślnym folderze kopii instancji, zapisuje pliki w magazynie i je usuwa. Na czas uruchomienia folder potrzebuje wolnego miejsca na największą bazę.
  • Przy włączonych kopiach dzienników pełne kopie rozpoczynają łańcuch dzienników. Bez nich pełne kopie są wykonywane jako COPY_ONLY, aby nie zakłócać innych planów kopii ani konserwacji.
  • Kopie dzienników są wykonywane dla baz w modelu odzyskiwania full lub bulk-logged; bazy w modelu simple dostają tylko pełne kopie. Zaznacz bazy systemowe, aby dodać master, model i msdb.

PostgreSQL

Agent działa jako konto postgres przez lokalne gniazdo — dla kopii nie trzeba nic konfigurować. Pełna kopia zapisuje cały klaster (pg_basebackup), role (pg_dumpall --globals-only) i pg_dump każdej bazy.

Odtwarzanie na określoną chwilę wymaga archiwizacji WAL. Przy włączonych kopiach dzienników pierwsza pełna kopia konfiguruje ją przez ALTER SYSTEM: archive_mode = on i archive_command, które kopiuje zakończone segmenty WAL do /var/lib/backupzit-pg/wal; kopie dzienników zapisują je i stamtąd usuwają. archive_mode zaczyna działać po jednym restarcie PostgreSQL (systemctl restart postgresql) — uruchomienie o tym informuje. Jeśli inne narzędzie już używa archive_command, BackupZit go nie rusza i tworzy kopie bez odtwarzania na określoną chwilę. Jeśli kopie dzienników ustaną (zadanie wyłączone lub usunięte), ponownie wyłącz archiwizację (ALTER SYSTEM RESET archive_mode, restart), aby folder się nie zapełnił.

  • Przywróć bazę danych w stanie pełnej kopii: z jej pg_dump do działającego serwera, pod nową nazwą lub zastępując bazę.
  • Na określoną chwilę (lub najnowszy stan): agent rozpakowuje kopię klastra do tymczasowej instancji na wolnym porcie (tylko gniazdo, bez sieci, bez archiwizacji), odtwarza WAL do tej chwili, zrzuca z niej bazę do działającego serwera i usuwa tymczasową instancję. Maszyna potrzebuje przez pewien czas wolnego miejsca na klaster.
  • Cały klaster: przywracany w ten sam sposób jako osobna instancja, która działa dalej na wolnym porcie; uruchomienie podaje jej port i katalog danych (w /var/lib/backupzit-pg) oraz jak się z nią połączyć i ją zatrzymać.

MySQL i MariaDB

Agent łączy się jako root przez lokalne gniazdo (uwierzytelnianie przez gniazdo, domyślne w Debianie i Ubuntu) albo z danymi logowania z /root/.my.cnf. Pełna kopia zapisuje mysqldump każdej bazy (spójny, z procedurami, zdarzeniami i wyzwalaczami) wraz z odpowiadającą mu pozycją dziennika binarnego.

Odtwarzanie na określoną chwilę wymaga dziennika binarnego. Włącz go raz w konfiguracji serwera i zrestartuj serwer, np. /etc/mysql/mariadb.conf.d/60-binlog.cnf:

[mysqld]
server_id = 1
log_bin = /var/log/mysql/mysql-bin
binlog_format = ROW
expire_logs_days = 7

(utwórz folder na dziennik, z kontem mysql jako właścicielem). Kopie dzienników zapisują wtedy każdy zamknięty dziennik binarny. Utrzymuj własny czas wygasania serwera dłuższy niż odstęp kopii dzienników; luka jest zgłaszana, a przywracanie nie może jej przeskoczyć.

  • Przywróć bazę danych: jej zrzut jest ładowany do nowej bazy (lub zastępuje istniejącą). Na określoną chwilę lub najnowszy stan: zmiany tej bazy zapisane w dziennikach binarnych po zrzucie są odtwarzane do tej chwili — także gdy baza dostaje nową nazwę. Odtwarzanie nie jest zapisywane w dzienniku binarnym serwera.
  • Użytkownicy i uprawnienia (systemowa baza mysql) nie są częścią zrzutów.

Przywracanie

Otwórz uruchomienie pełnej kopii (lub użyj kreatora przywracania → Baza danych) i wybierz bazę, maszynę docelową (ten sam serwer lub inny z tym samym serwerem bazy) oraz:

  • Jako nowa baza o nazwie np. sales_restored — oryginał pozostaje nietknięty i możesz skopiować wiersze z powrotem — lub pod oryginalną nazwą; zaznacz zastąp ją, aby nadpisać istniejącą bazę (jej użytkownicy są najpierw rozłączani).
  • Stan: stan pełnej kopii; najnowszy stan (pełna kopia i każda kopia dzienników po niej); lub określona chwila między pełną kopią a najnowszą użyteczną kopią dzienników, jak pokazuje tabela. Wpisz czas tak, jak wyświetla go konsola, w strefie czasowej serwera konsoli (zobacz Strefa czasowa); agent przelicza go na strefę czasową serwera bazy.

Wiersz poleceń

backupzit-agent sql list    [--instance SQLEXPRESS]
backupzit-agent sql backup  --repo ... [--instance I] [--db a,b] [--system] [--log] [--copy-only]
backupzit-agent sql restore --repo ... [--instance I] --db NAME [--as NEW] [--replace] [--at "2026-10-04 14:59:00"] SNAPSHOT|latest
backupzit-agent pg list     [--port 5432]
backupzit-agent pg backup   --repo ... [--port P] [--db a,b] [--pitr | --wal]
backupzit-agent pg restore  --repo ... --db NAME|"(cluster)" [--as NEW] [--replace] [--at TIME | --latest] SNAPSHOT|latest
backupzit-agent mysql list
backupzit-agent mysql backup  --repo ... [--db a,b] [--binlog]
backupzit-agent mysql restore --repo ... --db NAME [--as NEW] [--replace] [--at TIME | --latest] SNAPSHOT|latest

Nieobsługiwane

  • Kopie różnicowe SQL Server i grupy dostępności Always On; zdalne serwery baz — agent kopiuje serwery na swojej własnej maszynie.
  • Przywracanie pojedynczych tabel: przywróć bazę pod nową nazwą i skopiuj wiersze.
