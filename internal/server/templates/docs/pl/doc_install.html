Instalacja serwera

Konsola działa na Linuksie (Debian, Ubuntu, AlmaLinux, Rocky Linux) z PostgreSQL. Każda organizacja uruchamia własną konsolę we własnej sieci.

Wymagania

  • Maszyna wirtualna lub serwer z Linuksem: 2 vCPU, 2–4 GB RAM i 20 GB dysku w zupełności wystarczą dla setek agentów (dane kopii nie są tam przechowywane).
  • PostgreSQL 13 lub nowszy (lokalnie lub na innym serwerze).
  • Sieć: agenci muszą łączyć się z konsolą po TCP 8443 (HTTPS). Agenci muszą też mieć bezpośredni dostęp do magazynu.

1. Gotowy obraz maszyny wirtualnej

Gotowe appliance (Debian, PostgreSQL, konsola, automatyczne aktualizacje zabezpieczeń), które uruchamia się w niecałą minutę i nie potrzebuje dostępu do internetu:

HipernadzorcaJak
VMware ESXiHost Client: Create / Register VM → Deploy a virtual machine from an OVF or OVA file, wybierz backupzit-appliance.ova. vSphere: Deploy OVF Template. Workstation i VirtualBox: File → Open / Import.
Proxmox VESkopiuj backupzit-appliance.qcow2 na węzeł, utwórz maszynę bez dysku (2 vCPU, 2–4 GB RAM, sieć VirtIO), potem
qm importdisk <vmid> backupzit-appliance.qcow2 local-lvm
podłącz zaimportowany dysk jako SCSI, ustaw go jako dysk rozruchowy i włącz agenta gościa QEMU.
Hyper-VRozpakuj backupzit-appliance-vhdx.zip, potem Nowy → Maszyna wirtualna, generacja 1, 2–4 GB RAM, Użyj istniejącego wirtualnego dysku twardego: plik VHDX.

Uruchom maszynę. Jej ekran pokazuje adres konsoli WWW i początkowe hasło konta admin (zobacz Pierwsze logowanie). Daj maszynie 2 vCPU i 2–4 GB RAM; dysk 16 GB możesz w każdej chwili powiększyć — appliance zacznie używać nowego miejsca przy następnym uruchomieniu (główny system plików rośnie w trakcie działania). Przy pierwszym uruchomieniu każda kopia tworzy własne klucze SSH, hasło bazy danych i klucz sekretów, więc jeden obraz można wdrożyć wiele razy. Karta sieciowa dostaje adres z DHCP.

2. ISO appliance

ISO appliance instaluje wszystko bez pytań: Debiana, PostgreSQL, konsolę i automatyczne aktualizacje zabezpieczeń.

  1. Utwórz maszynę wirtualną (lub użyj serwera) z 2 vCPU, 2–4 GB RAM i dyskiem 16 GB lub większym. Użyj VirtIO lub domyślnych urządzeń hipernadzorcy, BIOS lub UEFI.
  2. Uruchom ją z backupzit-appliance.iso. Po 5 sekundach instalacja startuje sama, kasuje pierwszy dysk i instaluje. Pobiera pakiety systemu operacyjnego, więc serwer potrzebuje dostępu do internetu podczas instalacji. Trwa to około 10–20 minut, po czym serwer uruchamia się ponownie.
  3. Ekran serwera pokazuje adres konsoli WWW i początkowe hasło konta admin. Otwórz adres, zaloguj się i zmień hasło.

Appliance (obraz lub ISO)

Appliance ma dwa osobne konta:

  • admin w konsoli WWW (https://<address>:8443) do codziennej pracy. Jego początkowe hasło pojawia się na ekranie serwera po pierwszym uruchomieniu; zmień je w Moje konto.
  • bzadmin na samym serwerze (jego ekran w konsoli hipernadzorcy lub SSH), hasło początkowe backupzit. Musisz je zmienić przy pierwszym logowaniu; użytkownik może używać sudo. Root nie może się zalogować.

Aktualizacjami BackupZit i systemu operacyjnego zarządza się z konsoli (zobacz niżej). VMware Tools i agent gościa QEMU są wbudowane, więc hipernadzorcy pokazują adres appliance.

Te same ustawienia sieci, nazwy serwera, SSH i strefy czasowej są w konsoli WWW w Ustawienia → Sieć (tylko administratorzy). Tam adres statyczny, którego brama nie odpowie w ciągu pół minuty, jest automatycznie cofany, więc literówka nie odetnie appliance od sieci; jeśli konsola nadal jest nieosiągalna, użyj menu na ekranie serwera, które działa nawet przy wyłączonym SSH.

Agenci zapamiętują certyfikat konsoli, a nie jej adres. Jeśli łączą się z konsolą po adresie IP i ten adres się zmieni, skieruj ich na nowy poleceniem backupzit-agent set-server (zobacz Agenci) albo od początku używaj nazwy DNS. Przy DHCP zarezerwuj adres appliance w serwerze DHCP, aby się nie zmieniał.

Serwer SSH appliance oferuje tylko szyfry AES-GCM/CTR i MAC SHA-2 (bez chacha20-poly1305 i 64-bitowych MAC, które skanery podatności zgłaszają jako słabe).

3. Skrypt instalacyjny

Na istniejącym serwerze z Debianem 12+, Ubuntu 22.04+, AlmaLinux lub Rocky Linux 9+ (x86-64), jako root:

curl -fsSL https://github.com/Max-Zit/backupzit/releases/latest/download/install.sh | sudo sh

Skrypt instaluje PostgreSQL, pobiera najnowsze wydanie, sprawdza jego podpis kluczem wydań BackupZit oraz sumę kontrolną pakietu, instaluje konsolę, tworzy bazę danych z losowym hasłem, zapisuje /etc/backupzit/server.env, włącza automatyczne aktualizacje zabezpieczeń, otwiera port 8443 w firewalld lub ufw, jeśli są aktywne, uruchamia konsolę i wyświetla jej adres oraz początkowe hasło admina. Opcje (po sh -s --):

OpcjaDziałanie
--version 0.32.0instaluje to wydanie zamiast najnowszego
--db postgres://user:pw@host:5432/dbużywa istniejącej bazy PostgreSQL zamiast lokalnej
--hosts backup.example.local,10.0.0.10nazwy i adresy dla certyfikatu konsoli (domyślnie: adres i nazwa serwera)
--no-auto-updatespozostawia automatyczne aktualizacje zabezpieczeń bez zmian

Przykład: curl -fsSL …/install.sh | sudo sh -s -- --hosts backup.example.local. Ponowne uruchomienie skryptu na zainstalowanej konsoli aktualizuje BackupZit z zachowaniem konfiguracji i danych. Aby przeczytać skrypt przed uruchomieniem, najpierw go pobierz: curl -fsSLO …/install.sh; less install.sh; sudo sh install.sh.

4. Pakiety ręcznie

Debian / Ubuntu

apt install postgresql
apt install ./backupzit-server_*.deb

AlmaLinux / Rocky Linux

dnf install postgresql-server && postgresql-setup --initdb && systemctl enable --now postgresql
dnf install ./backupzit-server-*.rpm

W AlmaLinux i Rocky Linux zmień ident na scram-sha-256 w wierszach 127.0.0.1 i ::1 pliku /var/lib/pgsql/data/pg_hba.conf i uruchom ponownie PostgreSQL, aby konsola mogła logować się hasłem.

Utworzenie bazy danych

sudo -u postgres psql -c "SET password_encryption = 'scram-sha-256'; CREATE USER backupzit WITH PASSWORD 'choose-a-strong-password'"
sudo -u postgres psql -c "CREATE DATABASE backupzit OWNER backupzit"

Wpisz ciąg połączenia do /etc/backupzit/server.env:

BACKUPZIT_DB=postgres://backupzit:choose-a-strong-password@localhost:5432/backupzit?sslmode=disable
BACKUPZIT_PUBLIC_URL=https://backup.example.local:8443
BACKUPZIT_TLS_HOSTS=backup.example.local,10.0.0.10
systemctl start backupzit-server

Pierwsze logowanie

Otwórz https://<server>:8443. Początkowym administratorem jest admin; hasło jest w /var/lib/backupzit/initial-admin-password.txt (lub ustaw BACKUPZIT_ADMIN_PASSWORD przed pierwszym uruchomieniem). Zmień je po zalogowaniu. Aby zresetować zapomniane hasło na serwerze:

set -a; . /etc/backupzit/server.env; set +a
backupzit-server --set-admin-password 'NEW-PASSWORD'

Certyfikat

Przy pierwszym uruchomieniu konsola tworzy certyfikat z podpisem własnym. Przeglądarka raz o tym ostrzeże; agenci w ogóle nie polegają na urzędach certyfikacji — przypinają odcisk certyfikatu pokazywany na stronie Agenci podczas rejestracji. Chroni to agentów przed fałszywym serwerem nawet w niezaufanej sieci.

Nie zastępuj tego certyfikatu (cert.pem/key.pem w katalogu danych): wcześniej zarejestrowani agenci odmówiliby połączenia, dopóki nie zostaną ponownie zarejestrowani. Dla przeglądarek dodaj zamiast tego zaufany certyfikat, jak opisano niżej.

Zaufany certyfikat dla przeglądarek

Aby uniknąć ostrzeżenia przeglądarki, otwórz Ustawienia → Certyfikat. Konsola odpowiada wtedy także pod nazwą DNS, na przykład https://backup.example.com na porcie 443, z zaufanym certyfikatem. Agenci dalej używają portu 8443 i przypiętego certyfikatu, więc ich to nie dotyczy.

  • Prześlij certyfikat z firmowego CA lub publicznego CA, także certyfikat wieloznaczny, np. *.example.com. Wklej certyfikat (z certyfikatami pośrednimi) i klucz prywatny jako PEM albo wybierz pliki. Konsola sprawdza, czy klucz pasuje do certyfikatu, czy certyfikat jest teraz ważny i czy obejmuje nazwę DNS. Bez wewnętrznego DNS podaj zamiast tego adres IP konsoli i użyj certyfikatu wystawionego na ten adres IP (nazwa alternatywna IP:192.168.1.20); nadaj wtedy konsoli stały adres. Otrzymasz e-mail 21 dni przed wygaśnięciem.
  • Let's Encrypt: bezpłatne certyfikaty, odnawiane automatycznie 30 dni przed wygaśnięciem. Let's Encrypt musi sprawdzić, że kontrolujesz nazwę, na jeden z dwóch sposobów:
    • Weryfikacja DNS przez Cloudflare, zalecana dla konsol niedostępnych z internetu. BackupZit tworzy tymczasowy rekord TXT tokenem API Cloudflare. W Cloudflare przejdź do My Profile → API Tokens → Create Token, użyj szablonu Edit zone DNS i ogranicz go do swojej strefy.
    • Weryfikacja HTTP: port 80 konsoli musi być dostępny z internetu pod nazwą DNS. Dla serwera kopii rzadko jest to pożądane.
    Najpierw wypróbuj konfigurację z Użyj systemu testowego Let's Encrypt. Przeglądarki nie ufają jego certyfikatom, ale nie ma on limitów częstotliwości.
  • Obsługuj port 80 przekierowuje http:// na https://.

Nazwa DNS musi wskazywać adres IP konsoli, zwykle przez rekord A w wewnętrznym DNS. Pliki certyfikatu są w /var/lib/backupzit/web, a klucz może odczytać tylko usługa. W Linuksie usługa może używać portów 80 i 443 (CAP_NET_BIND_SERVICE); otwórz je w zaporze, jeśli przeglądarki łączą się z innych sieci.

Aktualizacja BackupZit

Domyślnie konsola pobiera aktualizacje z oficjalnych wydań BackupZit na GitHubie (https://github.com/Max-Zit/backupzit/releases). W Ustawienia → Aktualizacje możesz zamiast tego podać inne źródło aktualizacji — własny serwer lustrzany HTTPS lub folder na serwerze. Niezależnie od źródła każde wydanie musi mieć ważny podpis BackupZit. Konsola codziennie sprawdza nowe wydania i wysyła e-mail do administratorów, gdy jakieś jest dostępne. Aby je zainstalować, kliknij Zainstaluj:

  1. Konsola sprawdza podpis wydania i sumę kontrolną pakietu oraz czeka, aż nie będzie trwała żadna kopia ani przywracanie.
  2. Usługa systemowa (backupzit-update, działająca jako root) ponownie sprawdza podpis kluczami wydań wbudowanymi w BackupZit. Nawet przejęta konsola nie może zlecić instalacji innego pakietu.
  3. Tworzy kopię bazy danych (pg_dump), zachowuje bieżący program, instaluje pakiet i ponownie uruchamia konsolę.
  4. Jeśli nowa wersja nie odpowie w ciągu dwóch minut, poprzedni program i baza danych w poprzednim stanie są automatycznie przywracane. Wynik z dziennikiem nieudanego uruchomienia jest pokazywany na stronie Aktualizacje, zapisywany w dzienniku audytu i wysyłany e-mailem.
  5. Po udanej aktualizacji aktualizowani są też agenci: każdy instaluje nową wersję, gdy jest bezczynny. Wyłącz to na tej samej stronie, jeśli wolisz aktualizować ich samodzielnie.

Konsola jest niedostępna przez około minutę. Kopie bazy danych i poprzednie programy z trzech ostatnich aktualizacji są przechowywane w /var/lib/backupzit-update.

Bez dostępu do internetu: pobierz pliki wydania (manifest.json, manifest.json.sig i pakiet serwera) na innym komputerze. Następnie prześlij je w Zainstaluj aktualizację z plików albo skopiuj do folderu na serwerze i użyj tego folderu jako źródła aktualizacji.

Nadal możesz aktualizować menedżerem pakietów (apt install ./backupzit-server_….deb); baza danych jest migrowana przy uruchomieniu nowej wersji.

Aktualizacje systemu operacyjnego

Ta sama strona (Ustawienia → Aktualizacje) pokazuje system operacyjny serwera konsoli: ile aktualizacji jest dostępnych, ile z nich to poprawki zabezpieczeń, czy potrzebny jest restart i czy automatyczne aktualizacje zabezpieczeń są włączone. Stan jest odświeżany codziennie lub przyciskiem Sprawdź teraz. Możesz:

  • Włącz automatyczne aktualizacje zabezpieczeń (zalecane). Narzędzie systemu codziennie instaluje tylko poprawki zabezpieczeń: unattended-upgrades w Debianie i Ubuntu, dnf-automatic w AlmaLinux i Rocky Linux.
  • Zainstaluj teraz wszystkie aktualizacje. Usługi takie jak PostgreSQL mogą na chwilę się zrestartować, a konsola sama ponownie się połączy.
  • Uruchom ponownie serwer, na przykład po aktualizacji jądra. Konsola odmawia, gdy trwają kopie lub przywracania. Agenci zachowują swoje zadania i zgłaszają wyniki, gdy konsola wróci.

Te operacje przechodzą przez tę samą usługę root co aktualizacje konsoli. Są zapisywane w dzienniku audytu, a wynik ostatniej operacji jest pokazywany na stronie.

Kopia samej konsoli

Kopie w Twoim magazynie pozostają czytelne bez konsoli dzięki arkuszom odzyskiwania. Aby po utracie serwera odzyskać także samą konsolę, włącz Ustawienia → Kopia konsoli. Obejmuje to zadania, harmonogramy, agentów, użytkowników, ustawienia, historię uruchomień i zapisane dane dostępu. Konsola codziennie tworzy wtedy własną kopię w sieciowym miejscu docelowym, w folderze backupzit-console.

Kopia konsoli zawiera:

  • całą bazę danych, eksportowaną tabela po tabeli, więc nie jest potrzebna żadna konkretna wersja pg_dump;
  • klucz sekretów, który odszyfrowuje zapisane dane dostępu;
  • certyfikat konsoli, który przypinają agenci.

Jest szyfrowana kluczem odzyskiwania miejsca docelowego i deduplikowana. Zachowywane są najnowsze kopie: domyślnie 14.

Przywracanie konsoli

  1. Zainstaluj nową konsolę w tej samej lub nowszej wersji, na przykład z ISO appliance.
  2. Na nowym serwerze jako root wykonaj poniższe polecenia. Dane dostępu pochodzą z arkusza odzyskiwania miejsca docelowego, a adres repozytorium jest pokazany na stronie Kopia konsoli. 
    systemctl stop backupzit-server
set -a; . /etc/backupzit/server.env; set +a
export BACKUPZIT_PASSWORD='<recovery key>'
export BACKUPZIT_SFTP_PASSWORD='…' BACKUPZIT_SFTP_HOSTKEY='SHA256:…'   # or BACKUPZIT_S3_ACCESS_KEY/_SECRET_KEY, _SMB_PASSWORD, _AZURE_KEY, _HARDENED_KEY/_FINGERPRINT
backupzit-server --restore-console --repo 'sftp://backup@nas:22/backups/backupzit-console'
systemctl start backupzit-server
  3. Nadaj nowemu serwerowi adres IP lub nazwę DNS starego. Agenci ufają przywróconemu certyfikatowi i sami ponownie się łączą.

Przywracanie zastępuje bazę danych nowej konsoli bazą z kopii i aktualizuje ją do zainstalowanej wersji. --snapshot ID przywraca starszą kopię zamiast najnowszej.

Przechowuj też kopię arkuszy odzyskiwania i pliku secrets.key poza serwerem, na przykład w menedżerze haseł.
