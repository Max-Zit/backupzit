Ochrona przed ransomware

Atakujący próbują usunąć lub zaszyfrować kopie, zanim zaszyfrują dane produkcyjne. BackupZit oferuje magazyny, na których kopii nie da się zniszczyć, nawet skradzionymi danymi logowania.

Warstwy ochrony

WarstwaChroni przed
Szyfrowanie (AES-256)Odczytem lub modyfikacją kopii w magazynie. Każda zmiana jest wykrywana.
Niezmienny S3 (Object Lock, tryb zgodności)Usunięciem lub nadpisaniem kopii — przez atakującego z kluczami, nieuczciwego administratora lub przez pomyłkę.
Utwardzone repozytoriumTo samo na Twoim własnym serwerze Linux: pliki są zapisywane tylko raz i otrzymują flagę niezmienności systemu plików.
Kopia poza siedzibąPożarem, kradzieżą, całkowitą utratą lokalizacji.
Zatwierdzanie na cztery oczy (opcjonalne)Jednym skradzionym lub nadużytym kontem konsoli, które usuwa zadania i magazyny lub skraca przechowywanie: drugi użytkownik musi zatwierdzić. Zobacz Użytkownicy, role i LDAP.

Automatyczne wykrywanie podejrzanych kopii

Każda kopia jest porównywana z niedawną historią jej zadania. Zostaje oznaczona jako podejrzana, gdy widać w niej ślady ransomware lub masowego usuwania:

  • zmieniło się znacznie więcej plików niż zwykle (np. 95 % zamiast typowego 1 %),
  • nowe dane przestały się kompresować — zaszyfrowane pliki wyglądają jak dane losowe,
  • liczba plików nagle spadła o jedną trzecią lub więcej,
  • nagły skok ilości nowych danych (także dla obrazów dysków, systemów Linux i maszyn wirtualnych).

Wtedy BackupZit wysyła e-mail z alertem (przy włączonych powiadomieniach o błędach), pokazuje kopię na pulpicie jako podejrzanych kopii do sprawdzenia i wstrzymuje przechowywanie zadania: żadna starsza kopia nie jest usuwana, więc ostatnie czyste kopie pozostają możliwe do przywrócenia, nawet jeśli nadal napływają uszkodzone kopie. Po sprawdzeniu maszyny kliknij Sprawdzono — wznów przechowywanie na stronie zadania.

Niezmienny S3 z Object Lock

  1. Utwórz bucket z włączonym Object Lock (AWS, Wasabi, Backblaze B2, MinIO: mc mb --with-lock).
  2. Dodaj regułę cyklu życia, która usuwa nieaktualne wersje (noncurrent versions) po 1 dniu (MinIO: mc ilm rule add --noncurrent-expire-days 1 --expire-delete-marker).
  3. Dodaj magazyn S3 i zaznacz Niezmienne kopie przez N dni. Wybierz N co najmniej tak długie, jak najdłuższe przechowywanie, które chcesz chronić, np. 30.

Każdy punkt przywracania pozostaje zablokowany co najmniej N dni od utworzenia; dane współdzielone z nowszymi kopiami są przedłużane automatycznie.

Utwardzone repozytorium

Osobny serwer Linux z backupzit-repo:

  • Agenci i konsola mogą tylko dodawać pliki; istniejące pliki nigdy nie są nadpisywane.
  • Każdy plik otrzymuje atrybut chattr +i na okres ustawiony na tym serwerze. Nawet root nie może go usunąć bez wcześniejszego zdjęcia flagi.
  • Usunięcia przez klientów tylko ukrywają pliki do końca ich okresu.
  • Usługa działa jako nieuprzywilejowany użytkownik; jej jedynym uprawnieniem jest ustawianie flagi niezmienności.
apt install ./backupzit-repo_*.deb
vi /etc/backupzit-repo/repo.env        # BACKUPZIT_REPO_LOCK_DAYS=30
systemctl start backupzit-repo
backupzit-repo add-key office-console
backupzit-repo fingerprint

Po konfiguracji wyłącz SSH i inny zdalny dostęp na serwerze repozytorium i zabezpiecz dostęp do jego lokalnej konsoli / iDRAC / iLO / hiperwizora. Ochrona jest tak silna jak konto root tej maszyny.

Odzyskiwanie po ataku

Jeśli atakujący usunął lub nadpisał kopie, odczytaj magazyn w stanie sprzed ataku — to tylko odczyt i niczego nie zmienia:

backupzit-agent snapshots --repo <repozytorium> --as-of 2026-10-01T14:30
backupzit-agent restore   --repo <repozytorium> --as-of 2026-10-01T14:30 --target D:\Restore latest

W utwardzonym repozytorium administrator może też przywrócić ukryte pliki, aby kopie działały dalej normalnie:

backupzit-repo status
backupzit-repo undelete --since 2026-10-01T14:00

Zalecenia

  • Używaj dla magazynu osobnego konta, które nie należy do Twojej domeny Windows.
  • Utrzymuj co najmniej jedną niezmienną kopię (S3 Object Lock lub utwardzone repozytorium).
  • Przechowuj arkusze odzyskiwania offline (wydrukowane, w sejfie).
  • Włącz alerty e-mail — nagła zmiana liczby błędów lub ilości wysyłanych danych jest często pierwszym sygnałem ataku.
