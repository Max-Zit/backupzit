Агенты

На каждую защищаемую машину устанавливается агент. Он работает как служба, каждые 30 секунд запрашивает у консоли задания и обращается к хранилищу напрямую.

Поддерживаемые системы

  • Windows 10, 11 и Windows Server 2016 и новее — MSI Агент Windows.
  • Windows 7 SP1, Windows Server 2008 R2 SP1 и 2012 R2 — MSI Агент Windows — старые системы (…-legacy.msi), с теми же функциями, включая VSS и образы дисков.
  • Debian, Ubuntu, AlmaLinux, Rocky Linux (64-разрядные).
  • Узлы Proxmox VE 7 и 8 — пакет Debian; агент тогда копирует и ВМ и контейнеры узла (см. Proxmox VE).
  • Хосты Hyper-V (Windows Server 2016 и новее, Windows 10/11 с Hyper-V): MSI для Windows. Агент тогда копирует и ВМ хоста (см. Hyper-V).
  • Хосты VMware ESXi — на ESXi ничего не устанавливается: добавьте хост в разделе Хосты VMware ESXi и выберите агента в качестве прокси (см. VMware ESXi).

Регистрация агентов

  1. На странице Агенты нажмите Создать токен регистрации. Консоль покажет код регистрации (BZ1-…), действительный 7 дней и пригодный для любого числа машин. Он содержит адрес консоли для агентов (с портом агентов, обычно 8443, даже если страница открыта через веб-порт 443), токен и отпечаток сертификата. Агенты начиная с 0.33.6 регистрируются и по кодам, которые старые консоли создавали на веб-порту.
  2. Windows: запустите MSI и вставьте код, когда установщик его запросит. Linux: выполните показанную команду.
  3. Машина появится в списке агентов в течение минуты.

Если консоль недоступна во время установки, агент сохраняет код и повторяет попытки, пока не зарегистрируется. Обновления сохраняют регистрацию и не спрашивают повторно. Тихая установка с ENROLLCODE на уже зарегистрированной машине сохраняет регистрацию, если код от той же консоли (GPO или RMM могут безопасно её повторять), и переносит машину, если код от другой консоли; предыдущая регистрация сохраняется как agent.json.replaced-дата рядом с agent.json, так что обратное переименование возвращает машину к старой консоли как тот же агент.

Windows, тихая установка (GPO, Intune, RMM)

msiexec /i backupzit-agent.msi /qn ENROLLCODE="BZ1-..."

Старая форма SERVER="..." TOKEN="..." FINGERPRINT="SHA256:..." по-прежнему работает. Тихая установка без этих свойств устанавливает службу, которая ждёт, пока вы не зарегистрируете её командой backupzit-agent enroll --code "BZ1-..." в командной строке администратора.

Linux

apt install ./backupzit-agent_*.deb        # or: dnf install ./backupzit-agent-*.rpm
backupzit-agent enroll --code "BZ1-..."
systemctl enable --now backupzit-agent

Установка агентов из консоли

Вместо копирования установщиков на каждую машину позвольте консоли установить агента: на странице Агенты откройте Установить на машину отсюда, выберите Linux или Windows и введите адрес машины и учётную запись администратора.

  • Linux (Debian, Ubuntu, AlmaLinux, Rocky Linux; 64-разрядные): консоль подключается по SSH как root или как пользователь с правами sudo (пароль используется и для sudo; с ключом нужен sudo без пароля). Подойдёт пароль или закрытый ключ. Введите отпечаток ключа хоста SSH машины (ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub на машине), чтобы быть уверенным, что консоль общается с нужной машиной; без него отпечаток будет показан в журнале установки.
  • Windows (64-разрядная): консоль подключается через WinRM (порт 5985, сообщения шифруются NTLM; 5986 для прослушивателя HTTPS) как локальный или доменный администратор. WinRM включён по умолчанию в Windows Server; в Windows 10/11 один раз выполните winrm quickconfig от имени администратора. Локальным учётным записям, кроме встроенного Администратора, нужны права удалённого администрирования (LocalAccountTokenFilterPolicy) — или используйте доменную учётную запись. Старые системы (Windows 7, Server 2008 R2/2012 R2) получают legacy MSI.

Машина скачивает новейший пакет агента с консоли по ссылке, действующей только для этой установки (30 минут, три загрузки), проверяет его контрольную сумму SHA-256, устанавливает и регистрируется. Страница установки показывает каждый шаг; учётная запись и пароль используются только для этого и не сохраняются. Если машина уже зарегистрирована в этой консоли, регистрация сохраняется, а пакет обновляется; регистрация, которую консоль не знает (ранее удалённый агент или другая консоль), заменяется. Каждая установка попадает в журнал аудита. Машина должна иметь доступ к адресу консоли для агентов, как любой агент.

Состояние агента

  • online — агент связывался с консолью в последние 3 минуты.
  • offline — машина выключена, служба остановлена или сеть заблокирована. Запланированные копии ставятся в очередь и запускаются, как только агент вернётся.
  • восстановление — машина, загруженная с ISO восстановления (Windows или Linux), готовая принять восстановление образа диска или системы Linux. Агенты восстановления временные; удалите их после завершения восстановления.

Столбец IP-адреса показывает собственные адреса машины в том виде, в каком агент сообщил их в последний раз. виден с — адрес, с которого приходят его подключения: в локальной сети тот же адрес, для машины за NAT (например, ноутбука дома) — публичный адрес маршрутизатора. Консоль не обращается для этого ни к каким внешним службам.

Агент на рабочем столе (Windows)

Агент Windows показывает значок рядом с часами (он может быть под стрелкой ^ скрытых значков — перетащите его на панель задач, чтобы он оставался видимым). Точка на значке показывает состояние:

ТочкаЗначение
зелёнаяКопии в порядке (или ожидают первую запланированную копию).
синяяВыполняется копирование, восстановление или проверка восстановления.
оранжеваяПоследняя копия завершилась с предупреждениями (файлы, которые не удалось прочитать).
краснаяЗадание копирования завершилось ошибкой.
сераяКонсоль недоступна или служба агента не запущена.

Щёлкните значок (или откройте BackupZit Agent из меню «Пуск»), чтобы увидеть окно состояния: состояние защиты, ход выполняющейся копии, последняя и следующая копия и все задания копирования компьютера с кнопкой Создать копию сейчас. Правый щелчок открывает меню: Back up now для каждого задания, Open console in browser, Hide this icon (до следующего входа; копирование продолжается). Окну нужен Microsoft Edge WebView2, входящий в Windows 10 и 11; в старых системах значок и меню работают, а Open показывает консоль в браузере.

Так пользователи могут запустить копирование своего компьютера; задания, расписания и хранение настраиваются только в консоли. В любой системе backupzit-agent status (от имени администратора или root) выводит те же сведения.

Обновление

Если у консоли есть более новый установщик агента, чем тот, на котором работает агент, страница «Агенты» показывает Обновить до x.y.z рядом с его версией и Обновить всех агентов под списком. Тогда агент:

  1. ждёт, пока освободится (выполняющаяся копия никогда не прерывается),
  2. скачивает с консоли подходящий установщик по своему закреплённому соединению — MSI для Windows 10/11/2016+, MSI старые системы для Windows 7/2008 R2/2012 R2, пакет deb или rpm в Linux — и проверяет его SHA-256,
  3. устанавливает его и перезапускается; новая версия появляется в списке через несколько минут. Регистрация и все настройки сохраняются.

Консоль предлагает новейшие установщики из своего каталога dist; пакет сервера содержит установщики агентов своей версии. После обновления консоли в разделе Настройки → Обновления агенты обновляются автоматически (это можно там отключить). Обновления из консоли работают для агентов начиная с версии 0.21; более старые агенты обновляются один раз установкой нового MSI / пакета поверх старого (регистрация сохраняется). Журнал установщика находится в C:\ProgramData\backupzit\updates или /var/tmp/backupzit-updates.

Удаление агента

Удалить на странице «Агенты» удаляет агента и его задания из консоли. При включённом одобрении по принципу четырёх глаз сначала должен одобрить второй пользователь. Копии в хранилище не удаляются. Удалите программу на машине отдельно.

Две машины с одним агентом

Копия зарегистрированной машины уносит с собой агента и регистрацию: ВМ, восстановленная как новая, мгновенное восстановление, запущенная реплика, клонированный диск или шаблон. Когда копия работает рядом с оригиналом, обе подключаются как один и тот же агент. Консоль замечает это за минуту-две и затем:

  • показывает две машины с обоими именами и адресами на странице «Агенты», а агента — в разделе Требует внимания на панели мониторинга;
  • приостанавливает копирование и восстановление агента, чтобы ничего не запустилось не на той машине (иначе восстановление в исходное место могло бы перезаписать копию вместо оригинала);
  • один раз отправляет письмо администраторам и записывает событие agent.duplicate в журнал аудита.

Остановите копию или — если она должна остаться — зарегистрируйте её на копии как новую машину: backupzit-agent enroll --force --code "BZ1-..." (код со страницы «Агенты»). Приостановленные запуски стартуют через несколько минут после того, как останется одна машина. Восстановление системы Linux через Восстановить всю систему уже отменяет регистрацию агента в восстановленной копии, а проверки восстановления запускают свои ВМ без сети, так что ни то ни другое к этому не приводит.

Когда у консоли меняется адрес

Агенты доверяют консоли по её сертификату, который не меняется при смене IP-адреса или имени, но подключаются к адресу, с которым были зарегистрированы. После изменения выполните на каждой машине с агентом (от имени администратора / root):

backupzit-agent set-server https://192.168.1.20:8443

Команда проверяет, что консоль отвечает по новому адресу с тем же сертификатом, сохраняет его, и агент использует его после перезапуска своей службы (systemctl restart backupzit-agent или перезапустите службу BackupZit Agent в Windows). Использование DNS-имени для консоли с самого начала избавляет от этого шага.

Где агент хранит конфигурацию

  • Windows: C:\ProgramData\backupzit\agent.json (доступен только SYSTEM и Администраторам).
  • Linux: /etc/backupzit/agent.json (только root).

Файл содержит секрет агента. Любой, кто может его прочитать, может действовать от имени этого агента, поэтому сохраняйте эти права доступа.

Журнал агента

  • Windows: C:\ProgramData\backupzit\agent.log
  • Linux: /etc/backupzit/agent.log и journalctl -u backupzit-agent
  • Системы восстановления выводят журнал на экран.

Удаление программы

Windows: Параметры → Приложения → BackupZit Agent → Удалить (или msiexec /x). Linux: apt remove backupzit-agent / dnf remove backupzit-agent. Затем удалите агента в консоли. Копии остаются в хранилище.

В Windows удаление откладывает регистрацию (C:\ProgramData\backupzit\agent.json.removed-дата), поэтому при повторной установке агента запрашивается код регистрации. Если установщик находит регистрацию предыдущей версии, он сообщает об этом: оставьте код пустым, чтобы сохранить её, или вставьте новый код, чтобы зарегистрировать компьютер заново (например, в другой консоли).
