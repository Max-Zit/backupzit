Агенты

На каждую защищаемую машину устанавливается агент. Он работает как служба, каждые 30 секунд запрашивает у консоли задания и обращается к хранилищу напрямую.

Поддерживаемые системы

  • Windows 10, 11 и Windows Server 2016 и новее — MSI Агент Windows.
  • Windows 7 SP1, Windows Server 2008 R2 SP1 и 2012 R2 — MSI Агент Windows — старые системы (…-legacy.msi), с теми же функциями, включая VSS и образы дисков.
  • Debian, Ubuntu, AlmaLinux, Rocky Linux (64-разрядные).
  • Mac с чипом Apple или с процессором Intel, macOS 13 и новее — пакет Агент macOS (…_darwin_universal.pkg), для файлов и папок (см. Агенты macOS).
  • Узлы Proxmox VE 7, 8 и 9 — пакет Debian; агент тогда копирует и ВМ и контейнеры узла (см. Proxmox VE).
  • Хосты Hyper-V (Windows Server 2016 и новее, Windows 10/11 с Hyper-V): MSI для Windows. Агент тогда копирует и ВМ хоста (см. Hyper-V).
  • Хосты VMware ESXi — на ESXi ничего не устанавливается: добавьте хост в разделе Хосты VMware ESXi и выберите агента в качестве прокси (см. VMware ESXi).

Регистрация агентов

  1. На странице Агенты нажмите Создать токен регистрации. Консоль покажет код регистрации (BZ1-…), действительный 7 дней и пригодный для любого числа машин. Он содержит адрес консоли для агентов (с портом агентов, обычно 8443, даже если страница открыта через веб-порт 443), токен и отпечаток сертификата. Агенты начиная с 0.33.6 регистрируются и по кодам, которые старые консоли создавали на веб-порту.
  2. Windows: запустите MSI и вставьте код, когда установщик его запросит. Linux: выполните показанную команду. macOS: установите пакет и вставьте код, когда приложение в строке меню его запросит, или выполните показанную команду в Терминале (см. Агенты macOS).
  3. Машина появится в списке агентов в течение минуты.

Если консоль недоступна во время установки, агент сохраняет код и повторяет попытки, пока не зарегистрируется. Обновления сохраняют регистрацию и не спрашивают повторно. Тихая установка с ENROLLCODE на уже зарегистрированной машине сохраняет регистрацию, если код от той же консоли (GPO или RMM могут безопасно её повторять), и переносит машину, если код от другой консоли; предыдущая регистрация сохраняется как agent.json.replaced-дата рядом с agent.json, так что обратное переименование возвращает машину к старой консоли как тот же агент.

Windows, тихая установка (GPO, Intune, RMM)

msiexec /i backupzit-agent.msi /qn ENROLLCODE="BZ1-..."

Старая форма SERVER="..." TOKEN="..." FINGERPRINT="SHA256:..." по-прежнему работает. Тихая установка без этих свойств устанавливает службу, которая ждёт, пока вы не зарегистрируете её командой backupzit-agent enroll --code "BZ1-..." в командной строке администратора.

Linux

apt install ./backupzit-agent_*.deb        # or: dnf install ./backupzit-agent-*.rpm
backupzit-agent enroll --code "BZ1-..."
systemctl enable --now backupzit-agent

macOS

sudo /Library/BackupZit/bin/backupzit-agent enroll --code "BZ1-..."

Выполните её после установки .pkg или вставьте код в приложение BackupZit в строке меню, которое запрашивает его после установки (позже: Enroll this Mac… в его меню). Вместо этого MDM записывает код в /Library/Application Support/BackupZit/enroll-code до установки пакета. Затем полный доступ к диску должен предоставить пользователь Mac; см. Агенты macOS.

Установка агентов из консоли

Вместо копирования установщиков на каждую машину позвольте консоли установить агента: на странице Агенты откройте Установить на машину отсюда, выберите Linux или Windows и введите адрес машины и учётную запись администратора.

  • Linux (Debian, Ubuntu, AlmaLinux, Rocky Linux; 64-разрядные): консоль подключается по SSH как root или как пользователь с правами sudo, с паролем или закрытым ключом (парольная фраза ключа вводится в поле Парольная фраза ключа и служит только для открытия ключа). Консоль сначала пробует sudo без пароля (sudo -n); пароль передаётся sudo, только если он его запрашивает, — пароль пользователя или Пароль sudo, если он другой или используется ключ, — и пароль никогда не попадает в скрипт установки. Пароли и парольные фразы скрываются в журнале установки. Введите отпечаток ключа хоста SSH машины (ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub на машине), чтобы быть уверенным, что консоль общается с нужной машиной; без него отпечаток будет показан в журнале установки.
  • Windows (64-разрядная): консоль подключается через WinRM (порт 5985, сообщения шифруются NTLM; 5986 для прослушивателя HTTPS) как локальный или доменный администратор. WinRM включён по умолчанию в Windows Server; в Windows 10/11 один раз выполните winrm quickconfig от имени администратора. Локальным учётным записям, кроме встроенного Администратора, нужны права удалённого администрирования (LocalAccountTokenFilterPolicy) — или используйте доменную учётную запись. Старые системы (Windows 7, Server 2008 R2/2012 R2) получают legacy MSI.

Mac отсюда не устанавливаются: разверните .pkg вручную или через MDM (Агенты macOS).

Машина скачивает новейший пакет агента с консоли по ссылке, действующей только для этой установки (30 минут, три загрузки), проверяет его контрольную сумму SHA-256, устанавливает и регистрируется. Страница установки показывает каждый шаг; учётная запись и пароль используются только для этого и не сохраняются. Если машина уже зарегистрирована в этой консоли, регистрация сохраняется, а пакет обновляется; регистрация, которую консоль не знает (ранее удалённый агент или другая консоль), заменяется. Каждая установка попадает в журнал аудита. Машина должна иметь доступ к адресу консоли для агентов, как любой агент.

Состояние агента

  • online — агент связывался с консолью в последние 3 минуты.
  • offline — машина выключена, служба остановлена или сеть заблокирована. Запланированные копии ставятся в очередь и запускаются, как только агент вернётся.
  • восстановление — машина, загруженная с ISO восстановления (Windows или Linux), готовая принять восстановление образа диска или системы Linux. Агенты восстановления временные; удалите их после завершения восстановления. Иначе они удаляются автоматически через неделю после последнего выхода на связь.
  • часы расходятся — часы компьютера отличаются от часов консоли на 2 минуты или больше (агенты 0.44.0 и новее сообщают своё время при каждом опросе); предупреждает и панель. Включите на этом компьютере синхронизацию времени: начиная с 15 минут хранилища S3 и Azure отклоняют его копии (см. Устранение неполадок). Если это показывают все агенты, неверны часы самой консоли.
  • Обновить заставляет агента отправить свои диски и ВМ (Proxmox VE, Hyper-V) при следующем опросе, например после добавления хранилища или гостя на хосте. Иначе агенты отправляют их каждые 15 минут, когда свободны, и после каждого запуска с ВМ (агенты 0.54.1 и новее).
  • нет задания копирования — ни одно включённое задание не копирует этот компьютер (как его агент или как прокси задания VMware), учитывается через час после регистрации; панель показывает таких агентов в разделе Требует внимания. Добавьте компьютер в задание, например в задание для нескольких агентов.

Столбец IP-адреса показывает собственные адреса машины в том виде, в каком агент сообщил их в последний раз. виден с — адрес, с которого приходят его подключения: в локальной сети тот же адрес, для машины за NAT (например, ноутбука дома) — публичный адрес маршрутизатора. Консоль не обращается для этого ни к каким внешним службам.

Имена и метки

У серверов разных клиентов или площадок часто одинаковое имя хоста. Щёлкните агента на странице Агенты, чтобы задать ему имя в консоли и метки — произвольные подписи, например клиент или площадка, через запятую. Имя используется в формах заданий, при восстановлении, в журнале активности, отчётах и письмах; имя хоста, сообщаемое компьютером, остаётся видно рядом, а страница агента предупреждает, если другие агенты сообщают то же имя хоста. Щёлкните метку, чтобы показать только агентов с ней.

Переименование меняет только то, что показывает консоль: агент, его репозиторий и резервные копии остаются как есть, а компьютер не может изменить своё имя или метки. Для изменения нужно право на агентов, каждое изменение записывается в журнал аудита. Метки помогают находить агентов; они не дают и не ограничивают доступ и не добавляют агентов в задания. Каждый, кто может войти в консоль, видит всех агентов, а консоль хранит ключи всех их копий — клиентам, которых нужно строго разделить, нужна отдельная консоль.

Агент на рабочем столе (Windows)

Агент Windows показывает значок рядом с часами (он может быть под стрелкой ^ скрытых значков — перетащите его на панель задач, чтобы он оставался видимым). Точка на значке показывает состояние:

ТочкаЗначение
зелёнаяКопии в порядке (или ожидают первую запланированную копию).
синяяВыполняется копирование, восстановление или проверка восстановления.
оранжеваяПоследняя копия завершилась с предупреждениями (файлы, которые не удалось прочитать).
краснаяЗадание копирования завершилось ошибкой.
сераяКонсоль недоступна или служба агента не запущена.

Щёлкните значок (или откройте BackupZit Agent из меню «Пуск»), чтобы увидеть окно состояния: состояние защиты, ход выполняющейся копии, последняя и следующая копия и все задания копирования компьютера с кнопкой Создать копию сейчас. Правый щелчок открывает меню: Back up now для каждого задания, Open console in browser, Hide this icon (до следующего входа; копирование продолжается). Окну нужен Microsoft Edge WebView2, входящий в Windows 10 и 11; в старых системах значок и меню работают, а Open показывает консоль в браузере.

На Mac то же делает приложение в строке меню, которое также проверяет разрешения, запрашиваемые macOS у пользователя (см. Агенты macOS).

Так пользователи могут запустить копирование своего компьютера; задания, расписания и хранение настраиваются только в консоли. В любой системе backupzit-agent status (от имени администратора или root) выводит те же сведения.

Несколько заданий одновременно

По умолчанию агент выполняет одно задание за раз; остальные ждут в очереди. В столбце Заданий одновременно на странице «Агенты» можно разрешить до 8 — полезно для агентов, которые копируют многое, например прокси-агента для ESXi, Proxmox, Microsoft 365 или общих папок NAS. Два запуска одного задания никогда не выполняются одновременно, а обновления агента ждут, пока он освободится. Одновременные запуски делят процессор, диски и сеть машины; увеличивайте число постепенно. В Windows снимки VSS создаются по очереди. Нужны агенты 0.39.0 и новее.

Обновление

Если у консоли есть более новый установщик агента, чем тот, на котором работает агент, страница «Агенты» показывает Обновить до x.y.z рядом с его версией и Обновить всех агентов под списком. Тогда агент:

  1. ждёт, пока освободится (выполняющаяся копия никогда не прерывается),
  2. скачивает с консоли подходящий установщик по своему закреплённому соединению — MSI для Windows 10/11/2016+, MSI старые системы для Windows 7/2008 R2/2012 R2, пакет deb или rpm в Linux, .pkg на Mac — и проверяет его: начиная с 0.56 установщик должен быть в списке установщиков агента, подписанном ключом выпуска BackupZit, который агент проверяет встроенным в него ключом, поэтому установщик, изменённый на консоли, отклоняется,
  3. устанавливает его и перезапускается; новая версия появляется в списке через несколько минут. Регистрация и все настройки сохраняются.

Консоль предлагает новейшие установщики из своего каталога dist; пакет сервера содержит установщики агентов своей версии. После обновления консоли в разделе Настройки → Обновления агенты обновляются автоматически (это можно там отключить). Обновления из консоли работают для агентов начиная с версии 0.21; более старые агенты обновляются один раз установкой нового MSI / пакета поверх старого (регистрация сохраняется). Агенты 0.56 и новее принимают обновление только от консоли 0.56 или новее (её пакет содержит подписанный список) и никогда не обновляются до версии старше своей. Журнал установщика находится в C:\ProgramData\backupzit\updates, /var/lib/backupzit-agent/updates или, на Mac, /Library/Application Support/BackupZit/updates. Обновление агента на Mac, пакет которого не подписан Apple Developer ID, лишает его полного доступа к диску (см. Агенты macOS).

Удаление агента

Удалить на странице «Агенты» открывает страницу с двумя вариантами выбора; при включённом подтверждении «четыре глаза» сначала должен подтвердить второй пользователь.

  • Деинсталлировать агента с компьютера (агенты в сети начиная с версии 0.42.7): агент сообщает консоли, сам деинсталлируется и затем удаляется из консоли вместе с заданиями. Агент не в сети удаляется только из консоли — деинсталлируйте его на компьютере (см. ниже).
  • Его резервные копии: сохранить все (по умолчанию — они остаются в хранилище и могут быть восстановлены), сохранить только самую новую копию каждого задания (каждая копия полная, поэтому самая новая восстанавливает всё на свою дату) или удалить все. Для удаления нужно ввести имя компьютера; консоль удаляет в фоне и записывает результат в журнал аудита. Неизменяемое хранилище хранит заблокированные данные до истечения блокировки; копии на диске самого компьютера и копии заданий копирования не удаляются. Агент, который делает копии других систем (Proxmox, VMware, Hyper-V, Microsoft 365, NAS), забирает с собой и их копии.

Удаление копий также требует вашего пароля — или текущего кода из приложения-аутентификатора, если включён двухфакторный вход, — чтобы одной украденной сессии браузера было недостаточно для их удаления. Второй пользователь, утверждающий удаление, подтверждает так же. Пользователям, входящим через SSO, для этого нужен двухфакторный вход.

Сохранённые копии остаются в «Активности» (с пометкой удалён) и в мастере восстановления, и их можно восстановить на любого другого агента. На странице «Агенты» перечислены удалённые агенты с сохранёнными копиями: Удалить копии удаляет их позже (оставить самую новую копию каждого задания или все). Когда на компьютер снова установят агента, Подключить к текущему агенту переносит их к новому агенту с тем же именем: он показывает их, а его задания продолжаются в тех же репозиториях с дедупликацией относительно старых копий. Агент, у которого уже есть собственные копии, получает только историю; его задания сохраняют свои репозитории. Копии, найденные в хранилище (см. Поиск копий в хранилище), показываются и подключаются так же.

Две машины с одним агентом

Копия зарегистрированной машины уносит с собой агента и регистрацию: ВМ, восстановленная как новая, мгновенное восстановление, запущенная реплика, клонированный диск или шаблон. Когда копия работает рядом с оригиналом, обе подключаются как один и тот же агент. Консоль замечает это за минуту-две и затем:

  • показывает две машины с обоими именами и адресами на странице «Агенты», а агента — в разделе Требует внимания на панели мониторинга;
  • приостанавливает копирование и восстановление агента, чтобы ничего не запустилось не на той машине (иначе восстановление в исходное место могло бы перезаписать копию вместо оригинала);
  • один раз отправляет письмо администраторам и записывает событие agent.duplicate в журнал аудита.

Остановите копию или — если она должна остаться — зарегистрируйте её на копии как новую машину: backupzit-agent enroll --force --code "BZ1-..." (код со страницы «Агенты»). Приостановленные запуски стартуют через несколько минут после того, как останется одна машина. Восстановление системы Linux через Восстановить всю систему уже отменяет регистрацию агента в восстановленной копии, а проверки восстановления запускают свои ВМ без сети, так что ни то ни другое к этому не приводит.

Когда у консоли меняется адрес

Агенты доверяют консоли по её сертификату, который не меняется при смене IP-адреса или имени, но подключаются к адресу, с которым были зарегистрированы. После изменения выполните на каждой машине с агентом (от имени администратора / root):

backupzit-agent set-server https://192.168.1.20:8443

Команда проверяет, что консоль отвечает по новому адресу с тем же сертификатом, сохраняет его, и агент использует его после перезапуска своей службы (systemctl restart backupzit-agent или перезапустите службу BackupZit Agent в Windows). Использование DNS-имени для консоли с самого начала избавляет от этого шага.

Где агент хранит конфигурацию

  • Windows: C:\ProgramData\backupzit\agent.json (доступен только SYSTEM и Администраторам).
  • Linux: /etc/backupzit/agent.json (только root).
  • macOS: /Library/Application Support/BackupZit/agent.json (только root).

Файл содержит секрет агента. Любой, кто может его прочитать, может действовать от имени этого агента, поэтому сохраняйте эти права доступа.

Журнал агента

  • Windows: C:\ProgramData\backupzit\agent.log
  • Linux: /var/log/backupzit/agent.log и journalctl -u backupzit-agent
  • macOS: /Library/Logs/BackupZit/agent.log
  • Системы восстановления выводят журнал на экран.
  • Журнал хранит до 4 файлов по 10 МБ (agent.log и agent.log.1–.3); более старые записи удаляются.
  • Получить журнал на странице «Агенты» передаёт конец журнала в консоль — см. Журналы.

Удаление программы

Windows: Параметры → Приложения → BackupZit Agent → Удалить (или msiexec /x). Linux: apt remove backupzit-agent / dnf remove backupzit-agent. macOS: sudo /Library/BackupZit/uninstall.sh (см. Агенты macOS). Затем удалите агента в консоли. Копии остаются в хранилище.

В Windows удаление откладывает регистрацию (C:\ProgramData\backupzit\agent.json.removed-дата), поэтому при повторной установке агента запрашивается код регистрации. Если установщик находит регистрацию предыдущей версии, он сообщает об этом: оставьте код пустым, чтобы сохранить её, или вставьте новый код, чтобы зарегистрировать компьютер заново (например, в другой консоли).
