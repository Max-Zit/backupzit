Устранение неполадок и вопросы

Агент отображается как не в сети

  • Включена ли машина и работает ли служба? Windows: Get-Service backupzit-agent; Linux: systemctl status backupzit-agent; macOS: sudo launchctl print system/com.backupzit.agent (см. Агенты macOS).
  • Доступна ли консоль с машины? Test-NetConnection backup-server -Port 8443 или curl -k https://backup-server:8443/login.
  • Журнал агента: C:\ProgramData\backupzit\agent.log, в Linux /var/log/backupzit/agent.log или journalctl -u backupzit-agent, в macOS /Library/Logs/BackupZit/agent.log. «fingerprint mismatch» означает, что сертификат консоли изменился — зарегистрируйте агента заново.

Копирование завершилось ошибкой

Откройте запуск в Активности; сообщение называет причину. Частые причины:

Сообщение содержитРешение
host key mismatch / fingerprintКлюч SFTP-сервера изменился или отпечаток введён неверно. Проверьте командой ssh-keygen -lf на сервере.
permission denied / access deniedУчётные данные хранилища или права на папку. Проверьте вход SFTP/SMB-клиентом.
no space left / quotaХранилище заполнено. Сократите хранение или добавьте место; истёкшие копии освобождают место после следующего запуска.
repository is lockedВ том же репозитории выполняется другая операция (например, очистка); запуск повторяет попытки 30 минут. Устаревшие блокировки снимаются автоматически.
wrong password / recovery keyРепозиторий создан с другим ключом — проверьте, что задание использует правильное хранилище.
bucket has no Object Lock enabledНеизменяемость запрошена для бакета, созданного без Object Lock. Создайте новый бакет с Object Lock.
S3 / Azure: "the clock of this computer differs from the storage's by more than 15 minutes" (RequestTimeTooSkewed, Request date header too old)Облачное хранилище подписывает каждый запрос временем и отклоняет его, если часы расходятся более чем примерно на 15 минут. Исправьте время на компьютере, указанном в запуске (агент; для Проверить подключение — консоль), и включите синхронизацию времени: Параметры Windows → Время и язык → Установить время автоматически; Linux timedatectl set-ntp true или chrony. Виртуальные машины могут получить неверное время после долгого простоя или при переходе на летнее/зимнее время.

Другие сообщения

СитуацияЧто делать
«no matching backup disk is connected»Подключите один из ротируемых USB-дисков (сообщение называет нужную метку и какие помеченные диски подключены). Для восстановления нужен именно тот диск, который указан в запуске копирования.
«several backup disks are connected»Подключайте одновременно только один из ротируемых дисков.
Тест восстановления не пройденОткройте запуск: сообщение называет повреждённый файл или блок либо причину (например, копия удалена в хранилище). Выполните backupzit-agent check --read-data для репозитория, проверьте хранилище и запустите новое копирование. Если копии удалены в неизменяемом хранилище, см. Защита от программ-вымогателей.
Проверка данных нашла повреждённые пакетыХранилище потеряло или изменило данные (например, из-за сбоя у провайдера). Пока повреждённые пакеты в индексе, новые резервные копии продолжают использовать их данные. Нажмите Исправить: убрать повреждённые данные из индекса на странице запуска проверки или выполните backupzit-agent repair --repo … (--dry-run только перечисляет): хранилище читается заново под эксклюзивной блокировкой, повреждённые пакеты покидают индекс, а запуск перечисляет копии, которым нужны потерянные данные. Они остаются и восстанавливают то, что уцелело; отметьте Также удалить копии, которым нужны потерянные данные, чтобы удалить их, и следующие проверки данных и освобождение места по сроку хранения снова будут работать. Удаление требует пароль или двухфакторный код, при включённом принципе четырёх глаз — также одобрение второго пользователя, сохраняет копии, из которых работает ВМ (мгновенное восстановление), и отклоняется, пока хранение приостановлено после подозрительной копии. Следующие резервные копии сохраняют эти данные заново. Агенты 0.55 и новее. С 0.55 убираются только пакеты с доказанным повреждением: отсутствующие или не совпадающие со своим содержимым при полном чтении. Пакет, который доходит до этого агента укороченным, хотя хранилище держит его целиком, читается заново после паузы, затем только перечисляется и остаётся; проверьте сетевой путь (прокси, межсетевой экран, IPS, NAT). Сами файлы пакетов удаляет следующая очистка. Резервные копии, списки папок которых этот агент не может прочитать, сохраняются и никогда не удаляются как затронутые. Если 20 пакетов данных подряд не удаётся прочитать, проверка останавливается с сообщением «the storage stopped answering» и ничего не оценивает: проверьте хранилище и сетевой путь и запустите её снова. Начиная с 0.56 пакет, которого нет в списке файлов хранилища, сначала ищется отдельно, в несколько попыток, и только потом считается отсутствующим; пустой список или список, в котором разом нет большинства пакетов, не даёт вердикта, и проверка завершается ошибкой с указанием причины, так что сбой хранилища никогда не выводит данные из индекса.
Файл индекса репозитория повреждёнНачиная с 0.59 резервное копирование и восстановление продолжаются: пакеты, перечисленные в этом файле, читаются из их собственных заголовков, а новые копии не используют их данные повторно, пока индекс не будет перестроен. Хранение, освобождение места и удаление копий агента тем временем ждут (старые точки восстановления сохраняются, запуск предупреждает). Восстановить перестраивает индекс: заново перечисляет пакеты, проверяет каждый пакет из повреждённого файла (три попытки), убеждается, что каждый блок, используемый копией, есть в новом индексе или в пакете, повреждение которого доказано, и только затем записывает новый индекс; повреждённый файл остаётся в index-damaged/, запечатанный ключом репозитория. Если копии используют данные, которых нет ни в одном пакете, восстановление называет их и останавливается: проверьте, что все папки с данными хранилища на месте, или отметьте Также удалить копии, которым нужны потерянные данные, чтобы удалить их (только если два списка хранилища совпадают). Пакет, исчезнувший во время восстановления, останавливает его без изменений. Освобождение места никогда не удаляет пакет, которого нет в индексе, если в нём есть данные, используемые копией, которых больше нигде в индексе нет (потерянный или вручную удалённый файл индекса): пакет проверяется и возвращается в индекс. Проверка данных, которая при чтении не находит большинства пакетов, только что перечисленных хранилищем, ничего не оценивает.
Копия помечена как подозрительнаяПроверьте машину на вымогателя или массовое удаление (например, очищенная синхронизируемая папка). Если всё в порядке (например, плановая миграция), нажмите Проверено — возобновить хранение на странице задания.
Let's Encrypt: «could not verify … is port 80 … reachable»Для HTTP-проверки порт 80 должен быть доступен из интернета. Для внутренних консолей используйте DNS-проверку через Cloudflare.
Let's Encrypt: «no Cloudflare zone … is accessible with this token»У токена должно быть право Zone → DNS → Edit для зоны, содержащей имя консоли.
«HTTPS port 443: … permission denied» или «address already in use»Порт занят другой программой, или службе нельзя открывать порты ниже 1024 (запускайте её с CAP_NET_BIND_SERVICE, как это делает пакет). Выберите другой порт в Настройки → Сертификат.
Обновления: «updates from the console need the Linux package of the console»Консоль установлена не из пакета deb/rpm (например, в ознакомительном режиме). Обновляйте её тем же способом, каким она была установлена.
Обновления: «the release is not signed with a BackupZit release key»Источник обновлений не содержит официального релиза, или файлы были изменены по пути. Скачайте их заново с официального адреса.
Обновления: статус rolled-backНовая версия не запустилась, поэтому восстановлены предыдущая версия и её база данных. Журнал неудачного запуска находится на странице Обновления; отправьте его в поддержку.
"The agent is no longer running this"Агент был перезапущен или остановлен во время запуска (например, перезагрузка компьютера или службы) либо не смог передать результат. Агенты 0.52.0 и новее сообщают, над какими запусками работают, поэтому консоль примерно через две минуты отмечает такой запуск как неудачный, а не показывает его выполняющимся, пока кто-нибудь его не остановит; со старыми агентами остановите его на его странице. Получить журнал на странице Агенты показывает, что произошло. Следующий запуск по расписанию начинается как обычно. Если агент завершается штатно (остановка службы, перезагрузка для обновлений), запуск вместо этого заканчивается сообщением "The agent was stopped during the run". В Windows агенты 0.62 и новее принимают уведомление перед завершением работы: Windows ждёт до трёх минут, пока агент остановит запуск, снимет блокировку репозитория и сообщит об этом, прежде чем пропадёт сеть.
"agent stopped responding while the run was in progress"Во время запуска агент более 10 минут не связывался с консолью (сбой сети или остановлена машина агента). Время, когда не работала сама консоль, не учитывается. Агент два часа пытается доставить результат; когда он приходит, запуск показывает настоящий результат, и его копию можно восстановить.
Операционная система: «no supported package manager»Обновления операционной системы поддерживаются в Debian, Ubuntu (apt) и AlmaLinux, Rocky Linux, RHEL (dnf).
Копия консоли: «the backup was made by a newer BackupZit»Перед восстановлением установите на новую консоль версию, которая сделала копию, или более новую.
Копия консоли: «console backups need network storage»Выберите хранилище SFTP, S3, SMB, Azure или защищённый репозиторий; локальный путь агента недоступен консоли.
«Слишком много неудачных входов»Ваш адрес заблокирован после повторяющихся неверных паролей: по умолчанию на 30 минут, при повторных блокировках дольше. Администратор может снять блокировку в Настройки → Вход и безопасность. На сервере backupzit-server --unblock-ip all снимает все блокировки. Учётные записи никогда не блокируются навсегда.
Потерян телефон для двухфакторного входаИспользуйте один из кодов восстановления; иначе администратор сбрасывает двухфакторный вход на странице вашего пользователя. Если ни один администратор больше не может войти, выполните на сервере backupzit-server --reset-two-factor USER (Docker: docker compose exec backupzit backupzit-server --reset-two-factor USER): команда отключает двухфакторный вход этому пользователю, завершает его сеансы и записывается в журнал аудита; затем войдите с паролем и настройте его заново.
«your directory account is not in any BackupZit group»Добавьте пользователя в одну из групп, сопоставленных в Настройки → LDAP / Active Directory, или сопоставьте больше групп. Нажмите там Проверка, чтобы увидеть группы, найденные для пользователя.
API возвращает 401 / 403401: токен отсутствует, отозван, истёк или его владелец отключён. 403: роль токена недостаточна для запроса.
Azure: AuthenticationFailed / AuthorizationPermissionMismatchНеверный ключ учётной записи, или у SAS-токена нет права чтения, записи, удаления или перечисления, или он истёк.
Восстановленная ВМ с Windows Server 2012 R2 / Windows 8.1 не загружается в Hyper-V Gen 2 («hash was denied (DBX)»)Microsoft отозвала старый загрузчик для Secure Boot. Выключите Secure Boot для этой ВМ или обновите систему перед копированием.

Виртуальные машины, системы Linux и новое оборудование

СитуацияЧто делать
Proxmox: «the guest is running and one of its disks is on storage without snapshot support»Работающим гостям нужны диски LVM-thin, ZFS, Ceph RBD или qcow2. Переместите диск (Disk Action → Move Storage) или копируйте гостя, когда он остановлен.
Proxmox: «container volumes that are directories on dir storage are not supported yet»Том контейнера — каталог на хранилище типа каталог, NFS или btrfs. Пофайлово сохраняются только каталоги на ZFS (подтома); перенесите том на ZFS, LVM-thin или Ceph RBD (Volume Action → Move Storage).
Hyper-V: запуск сообщает «crash-consistent»Гость не смог подготовиться к контрольной точке. В гостевых Windows проверьте, что службы интеграции Hyper-V (Backup (volume shadow copy)) включены в параметрах ВМ. В гостевых Linux установите hyperv-daemons (RHEL) или linux-cloud-tools / hyperv-daemons (Debian/Ubuntu).
VMware: «SSH off» или «SSH to …: connection refused»Включите SSH на хосте ESXi: Host → Actions → Services → Enable Secure Shell (и настройте запуск вместе с хостом). Он нужен для восстановления, а при бесплатной лицензии — и для копирования.
VMware: «changed block tracking is off and can be enabled … only while the VM is off»Бесплатная лицензия ESXi: один раз выключите ВМ, затем запустите задание; BackupZit включит отслеживание изменённых блоков, и следующие копии будут читать только изменённые блоки.
VMware: «copy the disk on the datastore (needs free space …)»Работающие ВМ ненадолго копируются в своём хранилище данных. Освободите там место (столько, сколько занимает диск) или копируйте ВМ выключенной.
VMware: «… is a snapshot delta disk»У ВМ есть собственные снимки. Удалите или консолидируйте их в ESXi Host Client (Snapshots → Delete all); BackupZit их никогда не трогает. ВМ без снимков, диски которой нуждаются только в консолидации (незавершённое удаление снимка), агент консолидирует перед её копированием (агент 0.57, vSphere API); при бесплатной лицензии выполните Snapshots → Consolidate в Host Client. Агенты до 0.58 также отклоняли небольшую дельту, которую снимок с приостановкой записывает на некоторых хостах (ESXi 6.7, работают VMware Tools), хотя у ВМ не было снимков: обновите агент.
VMware: «The session is not authenticated» или «401 Unauthorized»Сеанс vSphere завершился во время запуска: у агентов до 0.55 — после долгого чтения диска, либо при перезапуске служб управления хоста. Агенты 0.57 входят снова и продолжают со следующей ВМ и удалением снимка; обновите старые агенты. Оставшийся снимок отображается на панели мониторинга с кнопкой Удалить сейчас.
Панель мониторинга: «снимок резервного копирования … на … остаётся уже …», «контрольная точка резервного копирования …», «временная копия диска …» или «блокировка резервного копирования»Резервное копирование не смогло удалить то, что создало на гипервизоре (агент был остановлен посередине или удаление не удалось); пока остаток на месте, диски ВМ растут, а при блокировке гость не может запуститься. Агент сам повторяет попытку (Proxmox VE и Hyper-V каждые 15 минут, VMware при следующем резервном копировании подключения). Нажмите Удалить сейчас, чтобы он попробовал сразу; запуск очистки на странице «Активность» показывает, что удалено и почему не удалось остальное (например, занятое хранилище данных или хранилище, файл, заблокированный другой программой). Если ошибка повторяется, удалите остаток средствами самого гипервизора: vSphere Client (Snapshots → Delete, затем Consolidate), Proxmox VE (qm delsnapshot ID NAME --force, qm unlock ID), диспетчер Hyper-V (Checkpoints → Delete). См. VMware, Proxmox VE и Hyper-V.
Proxmox: «guest … already has the backup lock»Идёт другое резервное копирование гостя (BackupZit или vzdump), или прерванный запуск оставил блокировку. Блокировку, установленную им самим, агент снимает в течение 15 минут; любую другую, когда не идёт ни одно резервное копирование, снимают командой qm unlock ID (контейнеры: pct unlock ID).
VMware: «the ESXi certificate changed»Хост переустановлен или по его адресу отвечает другая машина. Если это ожидаемо, проверьте отпечаток и нажмите Принять новый сертификат рядом с хостом на странице «Агенты».
VMware: файлы *.replaced-DATE.vmdk рядом с дисками ВМСтарые диски ВМ, восстановленной на месте. Удалите их в браузере хранилища данных, когда восстановленная ВМ заработает.
Hyper-V: старые файлы VHDX после восстановления на местеВосстановление отключает старые диски ВМ и оставляет их там, где они были (запуск перечисляет каждый: old disk kept at …); восстановленные диски находятся в подпапке backupzit-restore-…. Удалите старые файлы, когда восстановленная ВМ заработает.
Мгновенное восстановление Proxmox: ВМ не загружается или зависаетПроверьте дисковый сервер: systemctl status backupzit-instant-ID и journalctl -u backupzit-instant-ID на узле. Хранилище копий должно оставаться доступным; если репозиторий не читается, чтение дисков ВМ останавливается.
Мгновенное восстановление Proxmox: «efidisk0 stays on storage backupzit-instant»QEMU не может переместить хранилище переменных EFI, пока ВМ работает. Выключите ВМ и выполните qm disk move ID efidisk0 STORAGE --delete 1; это не зависит от копии.
Proxmox: «runs on node X; install the BackupZit agent on X»Гость перенесён. Установите агента на каждый узел и копируйте гостей каждого узла агентом этого узла.
Медленное копирование или восстановление в Proxmox, SFTP «connection lost», «message authentication code incorrect» на сервере хранилищаИзвестная проблема сетевых карт Intel e1000e на хостах Proxmox (журнал: «Detected Hardware Unit Hang», «Reset adapter unexpectedly»). Отключите offloading: ethtool -K eno1 tso off gso off gro off и добавьте это строкой post-up интерфейса в /etc/network/interfaces.
Просмотр файлов: «stored on a local path of the agent»Консоль может читать только копии в сетевом хранилище. Используйте backupzit-agent pve ls/extract или image-ls/image-extract на агенте.
Просмотр файлов: «this btrfs file system spans … devices» или «stripes data (RAID 0/10/5/6)»Из копии можно читать только btrfs на одном диске. Запустите ВМ через мгновенное восстановление рядом с оригиналом и скопируйте файлы или копируйте их файловым заданием агента внутри ВМ. См. Восстановление.
Добавление или проверка хранилища: «connection test failed … that the console can reach the storage», хотя резервное копирование на агентах работаетКонсоль не имеет доступа к хранилищу, например к NAS в сети клиента, когда консоль работает на VPS. Проверьте его через агента на этой площадке (Проверить подключение, затем выберите агента) и отметьте место хранения как доступное только агентам, чтобы консоль перестала к нему подключаться. Тогда просмотр файлов читает его копии через агента на этой площадке (агенты 0.61 и новее).
Восстановление системы Linux: «missing programs …»Установите названные пакеты на восстанавливающую машину или загрузитесь с ISO восстановления Linux от BackupZit, в котором они есть.
У восстановленной Linux-машины нет сетиСетевые настройки были привязаны к старому MAC-адресу (netplan match: macaddress). Восстановите с опцией Другое оборудование или удалите строки match в /etc/netplan/.
Восстановленная Windows останавливается с INACCESSIBLE_BOOT_DEVICEВосстановите заново с опцией Восстановить на другое оборудование или загрузитесь с ISO восстановления и выполните backupzit-agent prepare-hardware --disk 0 [--drivers E:\Drivers].
Восстановленная копия машины отображается как исходный агентУ системы Linux, восстановленной как новая ВМ, регистрация агента снимается автоматически. Для других копий (ВМ, восстановленная как новая ВМ, мгновенное восстановление, реплика, клонированный диск) консоль приостанавливает запуски агента и показывает две машины; зарегистрируйте копию как новую машину (см. Две машины с одним агентом).
Обновление агента не завершаетсяСмотрите журнал установщика в C:\ProgramData\backupzit\updates, /var/lib/backupzit-agent/updates или /Library/Application Support/BackupZit/updates (macOS); агентов версий до 0.21 нужно один раз обновить вручную.
Mac: «Full Disk Access is not granted», файлы прочитаны «without a snapshot», полный доступ к диску пропал после обновленияСм. Агенты macOS: полный доступ к диску может предоставить только пользователь Mac, а неподписанный пакет теряет его при каждом обновлении.
«… is a Mac: back it up with a files job»Mac нельзя скопировать как систему; используйте задание файлов (Агенты macOS).
Нет значка в трееНажмите стрелку ^ рядом с часами и перетащите значок BackupZit на панель задач или запустите BackupZit Agent из меню «Пуск».

Копирование завершается с «предупреждением»

Некоторые файлы не удалось прочитать — обычно файлы, заблокированные приложением, когда VSS недоступен, или файлы, на которые у агента нет прав. Список есть на странице запуска. Всё остальное скопировано. На Mac предупреждение даёт и отсутствие полного доступа к диску (Агенты macOS).

Файлы только в облаке. iCloud Drive на Mac (Оптимизировать хранилище Mac) и OneDrive в Windows (Файлы по запросу, файлы, помеченные как доступные только в сети) хранят содержимое многих файлов только в облаке. Копия не может их прочитать, и начиная с 0.60 агент не пытается. Файл, который есть в предыдущей копии без изменений, сохраняет содержимое оттуда. Остальные пропускаются и перечисляются отдельно от ошибок чтения, по папкам, в разделе Только в облаке, нет в резервной копии на странице запуска. Запуск завершается предупреждением, потому что этого содержимого нет в копии. Загрузите файлы на компьютер до копирования (Mac: Finder → Загрузить сейчас; Windows: правая кнопка → Всегда сохранять на этом устройстве) или выключите «Оптимизировать хранилище Mac». OneDrive для работы или учебы можно также копировать из облака заданием Microsoft 365, включая файлы, доступные только в сети. См. также Файлы в iCloud Drive.

Копирование идёт медленно

  • Первая копия читает и отправляет всё; следующие читают только изменённые файлы и отправляют только новые данные.
  • Проверьте сетевой путь до хранилища (Wi-Fi, VPN, скорость отдачи в интернет для облачного хранилища).
  • Исключите кеши, временные файлы и ненужные медиафайлы.

Вопросы и ответы

Можно ли использовать NFS?

Чтобы копировать общий ресурс NFS (или SMB), создайте задание NAS / общая папка; Linux-агент монтирует экспорт при каждом запуске. Чтобы хранить копии на NFS, смонтируйте экспорт на агенте (Linux: /etc/fstab) и используйте хранилище Локальный / смонтированный путь, например /mnt/nfs-backup; для машин с Windows лучше выбрать хранилище SMB.

Можно ли перенести копии в другое хранилище?

Скопируйте папку репозитория (или префикс бакета) как есть — она самодостаточна — и добавьте хранилище, указывающее на новое место, с тем же ключом восстановления.

Удаляет ли удаление задания копии?

Нет. Копии остаются в хранилище и могут быть восстановлены из Активности или из командной строки. Задания копирования копий удалённого задания удаляются вместе с ним; сделанные ими копии остаются в своём хранилище.

Что будет, если консоль недоступна?

Пока она не вернётся, новые копирования по расписанию не начинаются; затем каждое задание, время которого по расписанию прошло, выполняется один раз (если его окно копирования ещё не закончилось), а запуски из очереди продолжаются. Восстановление всегда возможно из командной строки с листом восстановления.

Сколько места понадобится копиям?

Для первой копии — примерно объём данных после сжатия, плюс ежедневные изменения за каждый хранимый день. Страница Отчёты показывает, сколько отправлено по каждому заданию.
