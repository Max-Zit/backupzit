Устранение неполадок и вопросы

Агент отображается как не в сети

  • Включена ли машина и работает ли служба? Windows: Get-Service backupzit-agent; Linux: systemctl status backupzit-agent.
  • Доступна ли консоль с машины? Test-NetConnection backup-server -Port 8443 или curl -k https://backup-server:8443/login.
  • Журнал агента: C:\ProgramData\backupzit\agent.log, в Linux /etc/backupzit/agent.log или journalctl -u backupzit-agent. «fingerprint mismatch» означает, что сертификат консоли изменился — зарегистрируйте агента заново.

Копирование завершилось ошибкой

Откройте запуск в Активности; сообщение называет причину. Частые причины:

Сообщение содержитРешение
host key mismatch / fingerprintКлюч SFTP-сервера изменился или отпечаток введён неверно. Проверьте командой ssh-keygen -lf на сервере.
permission denied / access deniedУчётные данные хранилища или права на папку. Проверьте вход SFTP/SMB-клиентом.
no space left / quotaХранилище заполнено. Сократите хранение или добавьте место; истёкшие копии освобождают место после следующего запуска.
repository is lockedВ том же репозитории выполняется другая операция (например, очистка); запуск повторяет попытки 30 минут. Устаревшие блокировки снимаются автоматически.
wrong password / recovery keyРепозиторий создан с другим ключом — проверьте, что задание использует правильное хранилище.
bucket has no Object Lock enabledНеизменяемость запрошена для бакета, созданного без Object Lock. Создайте новый бакет с Object Lock.

Другие сообщения

СитуацияЧто делать
«no matching backup disk is connected»Подключите один из ротируемых USB-дисков (сообщение называет нужную метку и какие помеченные диски подключены). Для восстановления нужен именно тот диск, который указан в запуске копирования.
«several backup disks are connected»Подключайте одновременно только один из ротируемых дисков.
Тест восстановления не пройденОткройте запуск: сообщение называет повреждённый файл или блок либо причину (например, копия удалена в хранилище). Выполните backupzit-agent check --read-data для репозитория, проверьте хранилище и запустите новое копирование. Если копии удалены в неизменяемом хранилище, см. Защита от программ-вымогателей.
Копия помечена как подозрительнаяПроверьте машину на вымогателя или массовое удаление (например, очищенная синхронизируемая папка). Если всё в порядке (например, плановая миграция), нажмите Проверено — возобновить хранение на странице задания.
Let's Encrypt: «could not verify … is port 80 … reachable»Для HTTP-проверки порт 80 должен быть доступен из интернета. Для внутренних консолей используйте DNS-проверку через Cloudflare.
Let's Encrypt: «no Cloudflare zone … is accessible with this token»У токена должно быть право Zone → DNS → Edit для зоны, содержащей имя консоли.
«HTTPS port 443: … permission denied» или «address already in use»Порт занят другой программой, или службе нельзя открывать порты ниже 1024 (запускайте её с CAP_NET_BIND_SERVICE, как это делает пакет). Выберите другой порт в Настройки → Сертификат.
Обновления: «updates from the console need the Linux package of the console»Консоль установлена не из пакета deb/rpm (например, в ознакомительном режиме). Обновляйте её тем же способом, каким она была установлена.
Обновления: «the release is not signed with a BackupZit release key»Источник обновлений не содержит официального релиза, или файлы были изменены по пути. Скачайте их заново с официального адреса.
Обновления: статус rolled-backНовая версия не запустилась, поэтому восстановлены предыдущая версия и её база данных. Журнал неудачного запуска находится на странице Обновления; отправьте его в поддержку.
Операционная система: «no supported package manager»Обновления операционной системы поддерживаются в Debian, Ubuntu (apt) и AlmaLinux, Rocky Linux, RHEL (dnf).
Копия консоли: «the backup was made by a newer BackupZit»Перед восстановлением установите на новую консоль версию, которая сделала копию, или более новую.
Копия консоли: «console backups need network storage»Выберите хранилище SFTP, S3, SMB, Azure или защищённый репозиторий; локальный путь агента недоступен консоли.
«Слишком много неудачных входов»Ваш адрес заблокирован после повторяющихся неверных паролей: по умолчанию на 30 минут, при повторных блокировках дольше. Администратор может снять блокировку в Настройки → Вход и безопасность. На сервере backupzit-server --unblock-ip all снимает все блокировки. Учётные записи никогда не блокируются навсегда.
Потерян телефон для двухфакторного входаИспользуйте один из кодов восстановления; иначе администратор сбросит двухфакторный вход на странице вашего пользователя. Последний администратор может сбросить свой пароль на сервере командой backupzit-server --set-admin-password.
«your directory account is not in any BackupZit group»Добавьте пользователя в одну из групп, сопоставленных в Настройки → LDAP / Active Directory, или сопоставьте больше групп. Нажмите там Проверка, чтобы увидеть группы, найденные для пользователя.
API возвращает 401 / 403401: токен отсутствует, отозван, истёк или его владелец отключён. 403: роль токена недостаточна для запроса.
Azure: AuthenticationFailed / AuthorizationPermissionMismatchНеверный ключ учётной записи, или у SAS-токена нет права чтения, записи, удаления или перечисления, или он истёк.
Восстановленная ВМ с Windows Server 2012 R2 / Windows 8.1 не загружается в Hyper-V Gen 2 («hash was denied (DBX)»)Microsoft отозвала старый загрузчик для Secure Boot. Выключите Secure Boot для этой ВМ или обновите систему перед копированием.

Виртуальные машины, системы Linux и новое оборудование

СитуацияЧто делать
Proxmox: «the guest is running and one of its disks is on storage without snapshot support»Работающим гостям нужны диски LVM-thin, ZFS, Ceph RBD или qcow2. Переместите диск (Disk Action → Move Storage) или копируйте гостя, когда он остановлен.
Hyper-V: запуск сообщает «crash-consistent»Гость не смог подготовиться к контрольной точке. В гостевых Windows проверьте, что службы интеграции Hyper-V (Backup (volume shadow copy)) включены в параметрах ВМ. В гостевых Linux установите hyperv-daemons (RHEL) или linux-cloud-tools / hyperv-daemons (Debian/Ubuntu).
VMware: «SSH off» или «SSH to …: connection refused»Включите SSH на хосте ESXi: Host → Actions → Services → Enable Secure Shell (и настройте запуск вместе с хостом). Он нужен для восстановления, а при бесплатной лицензии — и для копирования.
VMware: «changed block tracking is off and can be enabled … only while the VM is off»Бесплатная лицензия ESXi: один раз выключите ВМ, затем запустите задание; BackupZit включит отслеживание изменённых блоков, и следующие копии будут читать только изменённые блоки.
VMware: «copy the disk on the datastore (needs free space …)»Работающие ВМ ненадолго копируются в своём хранилище данных. Освободите там место (столько, сколько занимает диск) или копируйте ВМ выключенной.
VMware: «… is a snapshot delta disk»У ВМ есть собственные снимки. Удалите или консолидируйте их в ESXi Host Client (Snapshots → Delete all).
VMware: «the ESXi certificate changed»Хост переустановлен или по его адресу отвечает другая машина. Если это ожидаемо, удалите хост в Агенты и добавьте его снова, чтобы закрепить новый сертификат.
VMware: файлы *.replaced-DATE.vmdk рядом с дисками ВМСтарые диски ВМ, восстановленной на месте. Удалите их в браузере хранилища данных, когда восстановленная ВМ заработает.
Hyper-V: файлы *.replaced-DATE рядом с дисками ВМСтарые диски ВМ, восстановленной на месте. Удалите их, когда восстановленная ВМ заработает.
Мгновенное восстановление Proxmox: ВМ не загружается или зависаетПроверьте дисковый сервер: systemctl status backupzit-instant-ID и journalctl -u backupzit-instant-ID на узле. Хранилище копий должно оставаться доступным; если репозиторий не читается, чтение дисков ВМ останавливается.
Мгновенное восстановление Proxmox: «efidisk0 stays on storage backupzit-instant»QEMU не может переместить хранилище переменных EFI, пока ВМ работает. Выключите ВМ и выполните qm disk move ID efidisk0 STORAGE --delete 1; это не зависит от копии.
Proxmox: «runs on node X; install the BackupZit agent on X»Гость перенесён. Установите агента на каждый узел и копируйте гостей каждого узла агентом этого узла.
Медленное копирование или восстановление в Proxmox, SFTP «connection lost», «message authentication code incorrect» на сервере хранилищаИзвестная проблема сетевых карт Intel e1000e на хостах Proxmox (журнал: «Detected Hardware Unit Hang», «Reset adapter unexpectedly»). Отключите offloading: ethtool -K eno1 tso off gso off gro off и добавьте это строкой post-up интерфейса в /etc/network/interfaces.
Просмотр файлов: «stored on a local path of the agent»Консоль может читать только копии в сетевом хранилище. Используйте backupzit-agent pve ls/extract или image-ls/image-extract на агенте.
Восстановление системы Linux: «missing programs …»Установите названные пакеты на восстанавливающую машину или загрузитесь с ISO восстановления Linux от BackupZit, в котором они есть.
У восстановленной Linux-машины нет сетиСетевые настройки были привязаны к старому MAC-адресу (netplan match: macaddress). Восстановите с опцией Другое оборудование или удалите строки match в /etc/netplan/.
Восстановленная Windows останавливается с INACCESSIBLE_BOOT_DEVICEВосстановите заново с опцией Восстановить на другое оборудование или загрузитесь с ISO восстановления и выполните backupzit-agent prepare-hardware --disk 0 [--drivers E:\Drivers].
Восстановленная копия машины отображается как исходный агентПри восстановлении в новую ВМ Proxmox регистрация агента в копии снимается автоматически. Для других копий удалите agent.json в копии и зарегистрируйте её как новую машину.
Обновление агента не завершаетсяСмотрите журнал установщика в C:\ProgramData\backupzit\updates или /var/tmp/backupzit-updates; агентов версий до 0.21 нужно один раз обновить вручную.
Нет значка в трееНажмите стрелку ^ рядом с часами и перетащите значок BackupZit на панель задач или запустите BackupZit Agent из меню «Пуск».

Копирование завершается с «предупреждением»

Некоторые файлы не удалось прочитать — обычно файлы, заблокированные приложением, когда VSS недоступен, или файлы, на которые у агента нет прав. Список есть на странице запуска. Всё остальное скопировано.

Копирование идёт медленно

  • Первая копия читает и отправляет всё; следующие читают только изменённые файлы и отправляют только новые данные.
  • Проверьте сетевой путь до хранилища (Wi-Fi, VPN, скорость отдачи в интернет для облачного хранилища).
  • Исключите кеши, временные файлы и ненужные медиафайлы.

Вопросы и ответы

Можно ли использовать NFS?

Чтобы копировать общий ресурс NFS (или SMB), создайте задание NAS / общая папка; Linux-агент монтирует экспорт при каждом запуске. Чтобы хранить копии на NFS, смонтируйте экспорт на агенте (Linux: /etc/fstab) и используйте хранилище Локальный / смонтированный путь, например /mnt/nfs-backup; для машин с Windows лучше выбрать хранилище SMB.

Можно ли перенести копии в другое хранилище?

Скопируйте папку репозитория (или префикс бакета) как есть — она самодостаточна — и добавьте хранилище, указывающее на новое место, с тем же ключом восстановления.

Удаляет ли удаление задания копии?

Нет. Копии остаются в хранилище и могут быть восстановлены из Активности или из командной строки.

Что будет, если консоль недоступна?

Пока она не вернётся, новые копирования по расписанию не начинаются; запуски из очереди продолжатся позже. Восстановление всегда возможно из командной строки с листом восстановления.

Сколько места понадобится копиям?

Для первой копии — примерно объём данных после сжатия, плюс ежедневные изменения за каждый хранимый день. Страница Отчёты показывает, сколько отправлено по каждому заданию.
