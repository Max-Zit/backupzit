Задания копирования и расписания

Задание определяет, что копировать на каком агенте, где хранить, когда запускать и сколько копий хранить.

Создание задания

  1. Перейдите в Задания копирования и заполните Новое задание копирования.
  2. Выберите агента и место хранения.
  3. Выберите, что копировать:
    • Файлы и папки — по одному пути в строке, как их видит агент, например C:\Users, D:\Data, /home, /etc.
    • Образ диска — весь диск или выбранные разделы, восстанавливаемые на пустой диск или новое оборудование. См. Образы дисков.
    • Система Linux — все файловые системы и разметка дисков Linux-машины, восстанавливаемые на пустой диск или как ВМ Proxmox. См. Копирование системы Linux.
    • Виртуальные машины (Proxmox VE, Hyper-V, VMware) — ВМ (и контейнеры Proxmox) хоста гипервизора, копируемые без агентов в гостях: агентом на хосте Proxmox или Hyper-V либо, для VMware ESXi, прокси-агентом хоста (выберите хост ESXi в списке агентов). См. Proxmox VE, Hyper-V и VMware ESXi.
    • Базы данных — SQL Server, PostgreSQL или MySQL/MariaDB на машине агента, с копиями журналов для восстановления на любой момент. См. Базы данных.
    • NAS / общая папка — общая папка SMB или NFS, которую читает агент; см. ниже.
    • Microsoft 365 — почтовые ящики Exchange Online, календари, контакты, OneDrive и сайты SharePoint, которые любой агент читает через Microsoft Graph; см. Microsoft 365.
  4. При желании добавьте исключения, по одному в строке: шаблон имени, действующий в каждой папке (*.tmp, node_modules, Thumbs.db, *.iso), или полный путь, действующий только для этого файла или папки (C:\Data\Temp, /srv/www/cache, в том числе с подстановочными знаками: D:\VMs\*.iso). В Windows полные пути не учитывают регистр.
  5. Задайте Хранить копии и Расписание, затем Создать задание.

Папки всех пользователей

Под путями кнопки Для каждого пользователя компьютера добавляют Рабочий стол, Документы, Загрузки, Изображения или Весь профиль пользователя. Они записываются как {users}/Documents, и агент заново находит папки при каждом резервном копировании: C:\Users\<имя>\Documents в Windows (и папку, перемещённую OneDrive, …\OneDrive\Documents), /home/<имя>/Documents и /root/Documents в Linux, /Users/<имя>/Documents в macOS. Пользователи, добавленные позже, копируются без изменения задания; системные профили (Default, Public) пропускаются. После {users} может идти любая папка, например {users}/AppData/Roaming/Thunderbird.

Пути также могут содержать подстановочные знаки * (любые символы в имени одной папки) и ? (один символ): D:\Проекты\*\Документация, /srv/sites/*/uploads. В Windows регистр букв не важен; в Linux и macOS он учитывается так, как написано. Путь с {users} или подстановочными знаками, который на компьютере ничего не находит, не является ошибкой: запуск сообщает Nothing matched … и завершается ошибкой, только если копировать больше нечего. Нужен агент 0.45.0 или новее. Весь профиль включает и кэши; исключите их полными путями, например C:\Users\*\AppData\Local\Temp.

Одно задание для нескольких агентов

Чтобы копировать одни и те же папки на многих компьютерах, выберите в поле Агент один из вариантов Несколько агентов: Все агенты, Все агенты Windows, Все агенты Linux, Все агенты macOS или Выбрать агентов… (и отметьте их). Такое задание копирует файлы и папки; вместе с путями {users}, например {users}/Documents, одно задание охватывает документы всех сотрудников компании. Агенты, зарегистрированные позже, присоединяются к заданию автоматически в течение минуты (для Выбрать агентов… только отмеченные).

Задание для нескольких агентов может быть и заданием Образ диска — оно создаёт образ всех внутренних дисков каждого охваченного агента Windows (разделы не выбираются, у каждого компьютера свои) — или заданием Система Linux для каждого охваченного агента Linux. Агенты других операционных систем исключаются автоматически, и при Все агенты.

Каждый агент копирует в собственный репозиторий в хранилище, со своей историей, восстановлением и хранением, как в задании для одного агента. Страница заданий показывает задание в разделе Задания для нескольких агентов; его страница показывает каждого агента с последним результатом, а Запустить копирование сейчас на всех агентах запускает всех. Задание одного агента помечено несколько агентов: откройте его для истории и восстановления или отключите, чтобы приостановить этот компьютер. Папки, расписание и хранение меняются в задании для нескольких агентов и действуют для всех его агентов; там же агентов можно исключить. Исключение агентов или удаление задания сохраняет их копии в хранилище. При утверждении двумя людьми исключение агентов, сокращение хранения, отключение и удаление ждут второго пользователя.

Агент, который пока не может выполнить задание, указан с причиной, например агент старше 0.45.0 для {users} и подстановочных знаков; он присоединится после обновления. Много агентов с одинаковым расписанием стартуют одновременно; окно копирования или другое время для задания распределяет нагрузку на хранилище.

NAS и общие папки (SMB, NFS)

Задание NAS / общая папка копирует сетевую общую папку, ничего не устанавливая на NAS (Synology, QNAP, TrueNAS, файловый сервер Windows …). Выберите любого агента, у которого есть доступ к общей папке, — он читает её и пишет копию — и введите:

  • Общая папка: smb://nas01/data (при желании с папкой: smb://nas01/data/Office) или nfs://nas01/volume1/data (путь экспорта);
  • для SMB — учётную запись (пользователь, необязательный домен, пароль — хранится в зашифрованном виде); пустое значение означает гостевой доступ. NFS использует доступ машины агента к экспорту (разрешите её адрес на NAS);
  • папки в общей папке для копирования, по одной в строке (пусто: вся общая папка), и исключения, такие как #recycle, @eaDir или .snapshot.

При каждом запуске агент подключает общую папку — агенты Windows через путь UNC (\\nas01\data, только SMB), агенты Linux монтируя её только для чтения в /mnt/backupzit-nas (нужны cifs-utils для SMB, nfs-common или nfs-utils для NFS; в Proxmox VE есть оба) — и затем отключает её. Копии — обычные копии файлов: с дедупликацией и инкрементные, с хранением, заданиями копирования копий, проверками восстановления, просмотром и восстановлением файлов. Восстановить в исходное расположение снова подключает общую папку с правом записи и записывает файлы обратно; либо восстановите в папку на любом агенте или скачайте.

Открытые и заблокированные файлы (VSS)

В Windows агент использует службу теневого копирования томов: создаёт согласованный снимок тома на определённый момент и копирует из него, поэтому открытые файлы (PST Outlook, базы данных, редактируемые документы) копируются согласованно. Приложения с поддержкой VSS (например, SQL Server) сбрасывают данные на диск до создания снимка.

Текущие дата и время консоли показаны слева внизу, под часовым поясом.

Окно копирования

С параметром Окно копирования: запускать только между в форме задания (например, с 22 до 6) запланированные и связанные запуски задания начинаются только внутри окна. Запуск, который ещё ждёт, когда окно закрывается, — например, потому что ночные задания шли дольше, — отменяется, чтобы не нагружать сеть и машины в рабочее время. Уже начавшийся запуск продолжается; чтобы останавливать долгие запуски, используйте ограничение времени запуска (ниже). Ручной запуск задания окно не учитывает. Время ежедневного и ежемесячного расписания должно быть внутри окна.

Целевая точка восстановления (RPO)

RPO задаёт, насколько старой может быть последняя удачная копия задания, в часах — например, 26 для ежедневного копирования (сутки плюс запас). Он задаётся в форме задания в поле Целевая точка восстановления (RPO), часы. Панель показывает, сколько заданий в пределах RPO, и перечисляет каждое задание, нарушившее его; страница задания показывает состояние. Уведомление (письмо и чат, как при ошибке) отправляется один раз, когда задание нарушает RPO, и снова — только после того, как оно в промежутке его соблюдало. В отличие от статуса последнего запуска, RPO замечает и случайно удалённое расписание, агента, который несколько дней не в сети, и копирование, которое постоянно завершается ошибкой.

Хранение: сколько копий хранить

Снимок сохраняется, если его выбирает любое правило:

  • Последние — N самых новых копий.
  • Ежедневно — самая новая копия за каждый из последних N дней, в которые были копии.
  • Еженедельно — самая новая копия за каждую из последних N недель.
  • Ежемесячно — самая новая копия за каждый из последних N месяцев.

Пример: 3 последние, 7 ежедневных, 4 еженедельных, 6 ежемесячных хранят около полугода истории с ~20 точками восстановления. После каждого успешного запуска снимки, которые больше не выбраны, удаляются (в разделе «Активность» отмечены как истёк), а данные, не используемые ни одним снимком, удаляются из хранилища. Все нули — хранится всё.

Благодаря дедупликации долгое хранение обходится дёшево: неизменённые данные хранятся один раз, сколько бы снимков на них ни ссылалось.

Задания копирования копий (3-2-1)

Задание копии резервной копии копирует копии другого задания во второе место хранения — например, ночные копии на офисный NAS, скопированные в S3 или во внешний защищённый репозиторий. Выберите Копия резервной копии в форме задания, укажите копируемое задание и целевое хранилище.

  • Копирует агент исходного задания; защищаемая машина повторно не читается.
  • Передаются только данные, которых ещё нет в целевом хранилище, перешифрованные ключом цели.
  • Расписание После каждой копии исходного задания (по умолчанию) поддерживает копию актуальной; подойдёт и любое обычное расписание, например раз в ночь для медленного интернет-канала.
  • У копии своё хранение, например 7 ежедневных на NAS и 12 ежемесячных в облаке.
  • Скопированные копии файлов и ВМ (Proxmox VE, Hyper-V, VMware) восстанавливаются со страницы запуска копирования или в мастере восстановления, как и оригиналы, — целые ВМ, отдельные файлы с дисков ВМ и мгновенное восстановление Proxmox. Копии ВМ, скопированные агентом старше 0.29, так восстановить нельзя; следующий запуск копирования с более новым агентом делает его последнюю копию восстанавливаемой. Копии образов дисков восстанавливаются агентом из командной строки.

Изменение задания

Откройте задание и нажмите Изменить; форма открывается на отдельной странице, которая не перезагружается во время копирования. Можно изменить имя, папки и исключения (задания файлов), ВМ (задания ВМ), расписание, хранение, ограничение скорости, уровень сжатия и команды. Агент, место хранения и диск задания образа остаются прежними, чтобы копии задания оставались одной цепочкой; чтобы перенести задание, создайте новое — с заданием копирования копий, если старые копии должны переехать вместе с ним. Изменения действуют со следующего запуска и записываются в журнал аудита. При включённом одобрении по принципу четырёх глаз более короткое хранение ждёт одобрения второго пользователя; остальные изменения сохраняются сразу.

Реплики (Proxmox VE)

Задания ВМ Proxmox могут держать остановленные актуальные копии своих гостей на выбранном узле, которые запускаются одним щелчком, если гость утрачен, — см. Proxmox VE → Репликация.

Ограничение скорости

В разделе Дополнительно формы задания параметр Ограничить скорость отправки до ограничивает, с какой скоростью агент отправляет данные в хранилище, в МБ/с — например 10 МБ/с с 08:00 до 18:00, чтобы копирование в рабочее время оставляло офисный канал пригодным для работы; вне этого окна задание работает на полной скорости. Часы указываются по местному времени агента, и окно может переходить через полночь (с 22:00 до 06:00). Ограничение действует на копирование и задания копирования копий (отправку во второе хранилище), но не на восстановление: восстановление всегда идёт на полной скорости.

Сжатие и дедупликация

Каждая копия проходит дедупликацию: данные, которые уже есть в репозитории — из прежних копий того же задания или из других заданий в том же месте хранения, — повторно не сохраняются. Новые данные затем сжимаются zstd; фрагменты, которые не уменьшаются (видео, архивы, зашифрованные файлы), сохраняются как есть. Шифрование выполняется после сжатия.

Уровень сжатия — параметр задания (Изменить → Дополнительно):

УровеньКогда использовать
Стандартное (рекомендуется)Хорошее сжатие на высокой скорости; подходит почти для любого задания.
БыстроеМеньше нагружает ЦП на загруженных или слабых машинах; копии немного больше.
МаксимальноеОбычно на 5–15 % меньше стандартного, но сжатие в несколько раз медленнее. Для медленных исходящих каналов и платного облачного хранилища, когда у машины есть свободный ЦП.
ВыключеноДля уже сжатых данных: экономит ЦП, не увеличивая копии.

Уровень применяется к новым данным со следующего запуска; существующие копии не меняются, и восстановление от него никогда не зависит. Страница запуска показывает результат: коэффициент сжатия новых данных (например, 2.4×) и какая часть прочитанных данных уже была сохранена (дедупликация).

Команды до и после копирования

Администраторы могут поручить заданию выполнять команду на агенте до и после каждого копирования — например дамп базы данных, остановку службы ради согласованной копии или уведомление:

pg_dump -U postgres app > /var/backups/app.sql          # Linux, before
sqlcmd -S . -Q "BACKUP DATABASE app TO DISK='D:\dump\app.bak'"   # Windows, before
  • Команды выполняются от имени служебной учётной записи агента (root в Linux, SYSTEM в Windows) через sh или cmd; допускается несколько строк. Видеть и менять их могут только Администраторы — иначе оператор копирования мог бы выполнить что угодно на любой машине.
  • Если команда до завершается ошибкой (код выхода не 0) или выполняется дольше лимита времени (по умолчанию 30 минут), копирование не запускается, а запуск завершается ошибкой с выводом команды.
  • Команда после выполняется и тогда, когда копирование не удалось, чтобы можно было снова запустить то, что остановила первая. Ошибка команды после копирования превращает запуск в предупреждение.
  • Обе получают BACKUPZIT_STAGE (pre или post), BACKUPZIT_JOB, BACKUPZIT_JOB_ID, BACKUPZIT_RUN_ID и, после копирования, BACKUPZIT_STATUS (success, warning или failed).
  • Страница запуска показывает результат и вывод каждой команды, даже если она выполнилась успешно.
  • Для заданий ВМ команды выполняются на хосте гипервизора (или прокси VMware), а не внутри ВМ. У заданий копирования копий команд нет.

Запуск, отключение, удаление

  • Запустить копирование сейчас (Копировать сейчас для заданий копирования копий) сразу ставит задание в очередь.
  • Проверить восстановление восстанавливает случайную выборку из последней копии и проверяет её (см. Восстановление).
  • Отключить приостанавливает расписание, не теряя задание (при включённом одобрении по принципу четырёх глаз сначала должен одобрить второй пользователь).
  • Удалить удаляет задание; существующие копии остаются в хранилище и по-прежнему восстанавливаются из раздела «Активность».

Остановка запуска

Резервное копирование, копию или восстановление в очереди или в процессе можно остановить кнопкой Отмена или Остановить запуск на странице запуска либо Остановить запуск №… на странице задания. Запуск в очереди отменяется сразу; выполняющийся агент останавливает за несколько секунд — команда перед копированием тоже прерывается, а команда после копирования всё равно выполняется. Запуск получает статус отменено (сообщение «Cancelled by» и имя пользователя): в отчётах он не считается ошибкой, письмо об ошибке не отправляется, а запись попадает в журнал аудита. Прерванная на полпути копия не используется для восстановления. Обновления агента остановить нельзя.

Чтобы остановить всё сразу, нажмите Отменить все ожидающие и выполняющиеся вверху страницы Активность и подтвердите. Отменяются только запуски, которые в этот момент указаны в списке как ожидающие или выполняющиеся (выполняющиеся останавливаются за несколько секунд); запуски, запланированные позже сегодня или на другие дни, и связанные задания начнутся по плану.

Ограничение времени запуска (часы) в разделе Дополнительно формы задания останавливает копирование задания, которое длится дольше, и помечает его как неудачное; в этом случае уведомление об ошибке отправляется. Пусто или 0 — без ограничения. Если агент не подтвердит остановку в течение 10 минут, консоль сама помечает запуск как неудачный.

Хранение приостановлено

Если копия задания выглядела как работа программы-вымогателя или массовое удаление, страница задания показывает Хранение приостановлено: никакие копии не удаляются, пока кто-нибудь не проверит машину и не нажмёт Проверено — возобновить хранение (при включённом одобрении по принципу четырёх глаз сначала должен одобрить второй пользователь). См. Защита от программ-вымогателей.

Что сообщает запуск копирования

Откройте запуск в разделе Активность: число файлов, новые/изменённые файлы, прочитанные данные, отправленные новые данные (после дедупликации и сжатия, с коэффициентом сжатия и долей уже сохранённых данных — см. Сжатие), длительность и файлы, которые не удалось прочитать. Запуск с нечитаемыми файлами завершается со статусом предупреждение — остальные данные скопированы.
