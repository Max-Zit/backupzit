Базы данных: SQL Server, PostgreSQL, MySQL

BackupZit копирует базы данных собственными средствами сервера баз данных, через агента на машине с базой: Microsoft SQL Server в Windows, PostgreSQL и MySQL/MariaDB в Linux. Полные копии выполняются по расписанию задания; копии журналов каждые несколько минут позволяют восстановить отдельную базу на любой момент времени — например, на минуту раньше ошибочного DELETE.

Создание задания

В Задания копирования создайте задание типа Базы данных на агенте машины с базой и выберите:

  • Сервер базы данных: Microsoft SQL Server, PostgreSQL или MySQL/MariaDB. Изменить позже нельзя.
  • Экземпляр или порт: экземпляр SQL Server (пусто для экземпляра по умолчанию, например SQLEXPRESS) или порт PostgreSQL (пусто для 5432). К MySQL/MariaDB агент подключается через локальный сокет.
  • Базы данных: по одному имени в строке или пусто для всех пользовательских баз — базы, созданные позже, включаются автоматически.
  • Копировать журналы каждые … минут: например 15 — журналы транзакций (SQL Server), архивный WAL (PostgreSQL) или двоичные журналы (MySQL). Оставьте пустым, если достаточно восстановления на время полной копии.
  • Расписание относится к полным копиям, например ежедневно в 22:00.

Копии дедуплицируются — неизменённые данные не отправляются повторно — и шифруются, как любая копия. Хранение считает полные копии; копии журналов хранятся, пока существует полная копия, на которую они опираются. Страница запуска показывает, что содержит каждая копия.

Microsoft SQL Server

  1. Установите агента на машину Windows, где работает SQL Server (любая редакция начиная с 2012, включая Express).
  2. Агент работает как NT AUTHORITY\SYSTEM и подключается с проверкой подлинности Windows. Дайте этой учётной записи роль sysadmin, один раз для каждого экземпляра: 
    sqlcmd -S .\SQLEXPRESS -E -Q "ALTER SERVER ROLE sysadmin ADD MEMBER [NT AUTHORITY\SYSTEM]"
  • Каждый запуск записывает по одному файлу копии на базу (BACKUP DATABASE / BACKUP LOG … WITH CHECKSUM) в папку резервных копий экземпляра по умолчанию, сохраняет файлы и удаляет их. На время запуска в папке нужно свободное место для самой большой базы.
  • При включённом копировании журналов полные копии начинают цепочку журналов. Без него полные копии делаются как COPY_ONLY, чтобы не мешать другим планам копирования или обслуживания.
  • Копии журналов делаются для баз в модели восстановления full или bulk-logged; базы в модели simple получают только полные копии. Отметьте системные базы, чтобы добавить master, model и msdb.

PostgreSQL

Агент работает под учётной записью postgres через локальный сокет — для копирования ничего настраивать не нужно. Полная копия сохраняет весь кластер (pg_basebackup), роли (pg_dumpall --globals-only) и pg_dump каждой базы.

Восстановление на момент времени требует архивирования WAL. При включённом копировании журналов первая полная копия настраивает его через ALTER SYSTEM: archive_mode = on и archive_command, который копирует завершённые сегменты WAL в /var/lib/backupzit-pg/wal; копии журналов сохраняют их и удаляют оттуда. archive_mode вступает в силу после одного перезапуска PostgreSQL (systemctl restart postgresql) — запуск сообщит об этом. Если archive_command уже использует другой инструмент, BackupZit его не трогает и копирует без восстановления на момент времени. Если копирование журналов прекращается (задание отключено или удалено), снова выключите архивирование (ALTER SYSTEM RESET archive_mode, перезапуск), чтобы папка не переполнилась.

  • Восстановить базу данных на момент полной копии: из её pg_dump в работающий сервер, под новым именем или вместо базы.
  • На момент времени (или последнее состояние): агент распаковывает копию кластера во временный экземпляр на свободном порту (только сокет, без сети, без архивирования), воспроизводит WAL до этого момента, выгружает из него базу в работающий сервер и удаляет временный экземпляр. На время машине нужно свободное место для кластера.
  • Весь кластер: восстанавливается так же, как отдельный экземпляр, который продолжает работать на свободном порту; запуск сообщает его порт и каталог данных (в /var/lib/backupzit-pg), а также как подключиться и остановить его.

MySQL и MariaDB

Агент подключается как root через локальный сокет (аутентификация по сокету, по умолчанию в Debian и Ubuntu) или с учётными данными из /root/.my.cnf. Полная копия сохраняет mysqldump каждой базы (согласованный, с процедурами, событиями и триггерами) вместе с соответствующей позицией двоичного журнала.

Восстановление на момент времени требует двоичного журнала. Включите его один раз в конфигурации сервера и перезапустите сервер, например /etc/mysql/mariadb.conf.d/60-binlog.cnf:

[mysqld]
server_id = 1
log_bin = /var/log/mysql/mysql-bin
binlog_format = ROW
expire_logs_days = 7

(создайте папку для журнала, владелец — учётная запись mysql). После этого копии журналов сохраняют каждый закрытый двоичный журнал. Держите собственный срок хранения сервера больше интервала копирования журналов; разрыв отображается, и восстановление не может его преодолеть.

  • Восстановить базу данных: её дамп загружается в новую базу (или заменяет существующую). На момент времени или последнее состояние: изменения этой базы, записанные в двоичные журналы после дампа, воспроизводятся до этого момента — и тогда, когда база получает новое имя. Воспроизведение не записывается в двоичный журнал сервера.
  • Пользователи и права (системная база mysql) не входят в дампы.

Восстановление

Откройте запуск полной копии (или используйте мастер восстановления → База данных) и выберите базу, машину для восстановления (тот же сервер или другой с тем же сервером баз данных) и:

  • Как новую базу с именем, например, sales_restored — оригинал остаётся нетронутым, и вы можете скопировать строки обратно — или под исходным именем; отметьте заменить её, чтобы перезаписать существующую базу (её пользователи сначала отключаются).
  • Состояние: на момент полной копии; последнее состояние (полная копия и каждая копия журналов после неё); или момент времени между полной копией и самой новой пригодной копией журналов, как показывает таблица. Вводите время так, как его показывает консоль, в часовом поясе сервера консоли (см. Часовой пояс); агент переводит его в часовой пояс сервера баз данных.

Командная строка

backupzit-agent sql list    [--instance SQLEXPRESS]
backupzit-agent sql backup  --repo ... [--instance I] [--db a,b] [--system] [--log] [--copy-only]
backupzit-agent sql restore --repo ... [--instance I] --db NAME [--as NEW] [--replace] [--at "2026-10-04 14:59:00"] SNAPSHOT|latest
backupzit-agent pg list     [--port 5432]
backupzit-agent pg backup   --repo ... [--port P] [--db a,b] [--pitr | --wal]
backupzit-agent pg restore  --repo ... --db NAME|"(cluster)" [--as NEW] [--replace] [--at TIME | --latest] SNAPSHOT|latest
backupzit-agent mysql list
backupzit-agent mysql backup  --repo ... [--db a,b] [--binlog]
backupzit-agent mysql restore --repo ... --db NAME [--as NEW] [--replace] [--at TIME | --latest] SNAPSHOT|latest

Не поддерживается

  • Разностные копии SQL Server и группы доступности Always On; удалённые серверы баз данных — агент копирует серверы на своей машине.
  • Восстановление отдельных таблиц: восстановите базу под новым именем и скопируйте строки.
