Уведомления: почта, Slack, Teams, вебхуки

Получайте письмо, когда копирование завершается с ошибкой, и ежедневную сводку каждое утро.

Настройка почты

В Настройки → Уведомления по почте отметьте Отправлять уведомления по почте (без этого письма не отправляются) и заполните:

ПолеПример
SMTP-сервер / портsmtp.office365.com / 587, smtp.gmail.com / 587, внутренний релей / 25
БезопасностьSTARTTLS (порт 587), TLS (порт 465) или Нет (только для внутреннего релея без входа: имя пользователя и пароль никогда не отправляются в незашифрованном виде)
Имя пользователя / ПарольПочтовый ящик, с которого идёт отправка; оставьте пустым для релея без входа. Gmail требует пароль приложения; для Microsoft 365, где базовая аутентификация SMTP выводится из эксплуатации, надёжнее использовать SMTP-релей или соединитель.
Отbackup@example.com
КомуОдин или несколько адресов через запятую.

Проверьте настройки кнопкой Отправить тестовое письмо, затем нажмите Сохранить (проверка их не сохраняет). Письма, сообщения в чат и отчёты пишутся на языке, выбранном в той же форме (по умолчанию — язык консоли при сохранении).

Что отправляется

  • Ошибки (рекомендуется) — одно письмо на каждый неудачный запуск с причиной: копирование, вторичные копии, восстановления и неудачные тесты восстановления. С этой опцией вы также получаете оповещение SUSPICIOUS, когда копия похожа на работу вымогателя или массовое удаление.
  • Предупреждения — запуски, в которых часть файлов не удалось прочитать.
  • Успешные — каждый успешный запуск (обычно слишком много; лучше ежедневный отчёт).
  • Ежедневный отчёт — в выбранный час: запуски за последние 24 часа, проблемы и агенты не в сети. Тема заканчивается на OK, WARNINGS или ATTENTION (например [BackupZit] Daily report 2026-11-17: OK), чтобы почтовые правила могли их сортировать.

Если включено Ошибки, сообщается и о задании, не выдержавшем свою целевую точку восстановления (RPO) — один раз и повторно только после того, как в промежутке оно её выдержало. Запуски, остановленные пользователем (статус отменено), не отправляют письмо о сбое; запуск, остановленный ограничением времени, отправляет.

Одно письмо на задание и почтовые фильтры

Включите также Успешные, чтобы получать письмо о каждом завершённом запуске каждого задания — с заданием и компьютером в теме, — а не только ежедневную сводку. Для одной сводки по заданию создайте для него отчёт по расписанию. Тема пишется на языке писем, поэтому для почтовых правил каждое письмо о запуске содержит и заголовки, которые не зависят от языка: X-BackupZit-Status (success, warning или failed), X-BackupZit-Job, X-BackupZit-Agent (имя в консоли), X-BackupZit-Host (имя хоста, сообщаемое компьютером), X-BackupZit-Kind и X-BackupZit-Run. Копия, похожая на работу шифровальщика, дополнительно получает X-BackupZit-Suspicious: yes — не позволяйте правилам, убирающим успешные запуски, скрывать её.

Независимо от этих параметров получатели уведомлений также получают письмо, когда:

  • изменение ждёт одобрения второго пользователя (принцип четырёх глаз);
  • две машины используют одну регистрацию агента;
  • журнал аудита был изменён;
  • не удалось резервное копирование самой консоли;
  • не удалось продлить HTTPS-сертификат для браузеров или срок действия загруженного сертификата истекает в течение 21 дня;
  • доступна новая версия BackupZit (можно отключить в разделе Настройки → Обновления) или не удалось обновить консоль;
  • адрес заблокирован после слишком многих неудачных входов (можно отключить в защите от подбора паролей).

Для еженедельных или ежемесячных сводок используйте отчёты по расписанию; они отправляются с теми же почтовыми настройками и имеют своих получателей. Темы начинаются с [BackupZit], чтобы почтовые правила могли их сортировать. Пароль SMTP хранится в зашифрованном виде. Ссылки в письмах, сообщениях в чат и отчётах ведут в консоль по адресу, с которого вы открываете её в браузере (или по адресу, заданному через --public-url).

Когда включён веб-порт HTTPS с доверенным сертификатом (Настройки → Сертификат), ссылки в письмах, сообщениях чата и отчётах ведут на его адрес, даже если порт 8443 обслуживает только агентов. Иначе используется --public-url, а если его нет — адрес, по которому консоль последний раз открывал пользователь с правом менять настройки.

Slack, Microsoft Teams и вебхуки

В Настройки → Чаты и вебхуки добавьте любое число каналов; каждый выбирает, получать ли ошибки, предупреждения и успешные запуски. Необычные копии (возможный вымогатель) считаются ошибками. Отправить тест сразу проверяет канал.

  • Slack: создайте для канала incoming webhook (настройки приложения Slack → Incoming Webhooks) и вставьте его URL (https://hooks.slack.com/services/…).
  • Microsoft Teams: в канале добавьте рабочий процесс Post to a channel when a webhook request is received и вставьте его URL. Сообщения приходят карточками с кнопкой, открывающей запуск в консоли.
  • Вебхук: любой URL, принимающий JSON POST — система заявок, мониторинг или средство автоматизации. С секретом подписи каждый запрос несёт X-BackupZit-Signature: sha256=<hex>, HMAC-SHA256 тела, чтобы получатель мог проверить, что запрос пришёл от вашей консоли. Перенаправления не выполняются (ответ 3xx считается ошибкой), а link-local-адреса (169.254.x.x, например службы метаданных облака, и fe80::) отклоняются; внутренние адреса работают.

JSON вебхука:

{"event": "run.finished", "run_id": 412, "kind": "vm-backup", "kind_title": "VM backup",
 "status": "failed", "suspicious": "", "job": "Proxmox VMs", "job_id": 7, "agent": "pve1", "agent_id": 3,
 "message": "…", "errors": ["…"], "started_at": "2026-10-04T22:00:03+02:00",
 "finished_at": "2026-10-04T22:04:41+02:00", "duration_s": 278, "files": 4, "bytes": 85899345920,
 "bytes_read": 12884901888, "bytes_stored": 1073741824, "snapshot": "9f3c2a1b",
 "url": "https://backup.example/runs/412"}

duration_s — длительность запуска в секундах. Для резервных копий files и bytes — размер копируемых данных, bytes_read — сколько из них прочитано, bytes_stored — сколько загружено в хранилище; snapshot — ID новой копии.

Задание, пропустившее целевую точку восстановления, отправляет {"event": "rpo.missed", "job_id", "job", "agent", "rpo_hours", "last_good_backup", "url"}; пустые поля (например suspicious или задание у запуска без задания) не передаются. URL Slack и Teams должны использовать https://. Сообщения отправляются один раз за запуск, даже когда почта выключена. Неработающий канал (неверный URL, сервис недоступен) записывается в журнал консоли и не задерживает остальные. URL вебхуков хранятся в зашифрованном виде. Плановое резервное копирование, пропущенное из-за того, что предыдущий запуск задания ещё выполняется, или не запущенное в окне резервного копирования задания, отправляет одно уведомление на задание (письмо с уведомлениями о сбоях и {"event": "schedule.skipped"} или "schedule.window_missed" с "job_id", "job", "agent", "count", "since"), а следующее — только после того, как задание тем временем успешно выполнило копирование.
