Установка сервера

Консоль работает в Linux (Debian, Ubuntu, AlmaLinux, Rocky Linux) с PostgreSQL. Каждая организация держит собственную консоль в собственной сети.

Требования

  • Linux-ВМ или сервер: 2 vCPU, 2–4 ГБ ОЗУ и 20 ГБ диска с запасом хватает на сотни агентов (данные копий на нём не хранятся).
  • PostgreSQL 13 или новее (локально или на другом сервере).
  • Сеть: агенты должны достигать консоли по TCP 8443 (HTTPS). Агенты также должны иметь прямой доступ к хранилищу.

Выбор способа установки

СпособЛучше всего дляНужно
1. Готовый образ ВМ (OVA, qcow2, VHDX)Быстрее всего: импортировать, запустить, войтиVMware, Proxmox/KVM или Hyper-V; доступ в интернет не нужен
2. ISO applianceНовая ВМ или физический сервер, автоматическая установкадоступ в интернет во время установки (пакеты Debian)
3. Сценарий установкиСуществующий сервер Debian, Ubuntu, AlmaLinux или Rocky Linuxroot и доступ в интернет
4. Пакеты вручнуюСобственный PostgreSQL, управление конфигурацией, без доступа в интернетпакет сервера из выпуска

Пакеты (backupzit-server_X_amd64.deb, backupzit-server-X.x86_64.rpm, агенты) перечислены на странице выпуска. Каждый образ занимает около 1,5 ГБ. Проверьте загрузку командой sha256sum -c SHA256SUMS --ignore-missing (Linux) или Get-FileHash file -Algorithm SHA256 (Windows).

1. Готовый образ ВМ

Готовый appliance (Debian, PostgreSQL, консоль, автоматические обновления безопасности), который запускается меньше чем за минуту и не требует доступа в интернет:

ГипервизорКак
VMware ESXiHost Client: Create / Register VM → Deploy a virtual machine from an OVF or OVA file, выберите backupzit-appliance.ova. vSphere: Deploy OVF Template. Workstation и VirtualBox: File → Open / Import.
Proxmox VEСкопируйте backupzit-appliance.qcow2 на узел, создайте ВМ без диска (2 vCPU, 2–4 ГБ ОЗУ, сеть VirtIO), затем
qm importdisk <vmid> backupzit-appliance.qcow2 local-lvm
подключите импортированный диск как SCSI, сделайте его загрузочным и включите гостевой агент QEMU.
Hyper-VРаспакуйте backupzit-appliance-vhdx.zip, затем Создать → Виртуальная машина, поколение 1, 2–4 ГБ ОЗУ, Использовать имеющийся виртуальный жёсткий диск: VHDX.

Запустите ВМ. На её экране показаны адрес веб-консоли и начальный пароль admin (см. Первый вход). Выделите ВМ 2 vCPU и 2–4 ГБ ОЗУ; диск 16 ГБ можно в любой момент увеличить — appliance начнёт использовать новое место при следующем запуске (корневая файловая система расширяется на ходу). При первом запуске каждая копия создаёт собственные ключи SSH, пароль базы данных и ключ секретов, поэтому один образ можно развернуть много раз. Сетевой адаптер получает адрес по DHCP.

2. ISO appliance

ISO appliance устанавливает всё без вопросов: Debian, PostgreSQL, консоль и автоматические обновления безопасности.

  1. Создайте ВМ (или возьмите сервер) с 2 vCPU, 2–4 ГБ ОЗУ и диском от 16 ГБ. Используйте VirtIO или стандартные устройства гипервизора, BIOS или UEFI.
  2. Загрузите её с backupzit-appliance.iso. Через 5 секунд установка начнётся сама, сотрёт первый диск и выполнит установку. Она скачивает пакеты операционной системы, поэтому серверу во время установки нужен доступ в интернет. Это занимает около 10–20 минут, затем сервер перезагружается.
  3. На экране сервера показаны адрес веб-консоли и начальный пароль admin. Откройте адрес, войдите и смените пароль.

Appliance (образ или ISO)

У appliance две отдельные учётные записи:

  • admin в веб-консоли (https://<address>:8443) для повседневной работы. Его начальный пароль показывается на экране сервера после первого запуска; смените его в разделе Моя учётная запись.
  • bzadmin на самом сервере (его экран в консоли гипервизора или SSH), начальный пароль backupzit. При первом входе его нужно сменить; пользователь может использовать sudo. Root войти не может.

Обновления BackupZit и операционной системы управляются из консоли (см. ниже). VMware Tools и гостевой агент QEMU включены, поэтому гипервизоры показывают адрес appliance.

Меню настройки на экране сервера

Когда bzadmin входит на собственном экране сервера (не по SSH), открывается меню:

ПунктЧто делает
1 NetworkDHCP или статический адрес с длиной префикса (например 192.168.1.20/24), шлюз и до трёх DNS-серверов.
2 Server nameИмя хоста (буквы, цифры и -).
3 SSHВключает или выключает SSH-сервер и меняет его порт. Порты консоли (80, 443, 8443), PostgreSQL (5432) и мгновенного восстановления (111, 2049) использовать нельзя.
4 Reset the password of "admin"Для забытого пароля веб-консоли; также снимает блокировки входа. После этого экран перестаёт показывать сгенерированный начальный пароль (так же — со следующего запуска, после того как пароль admin изменён в веб-консоли).
5 Lift sign-in blocks and web console limitsКогда слишком много неудачных входов заблокировали адрес или веб-консоль ограничена адресами, которые вы больше не можете использовать (см. Безопасность).
6–8Перезапуск веб-консоли, перезагрузка или выключение сервера.
9 Time zoneAppliance стартует в UTC. Задайте свой пояс, например Europe/Belgrade: консоль показывает в нём всё время, выполняет расписания и читает точки восстановления (в том числе момент восстановления базы данных). Консоль перезапускается, чтобы применить его.
0 Command lineВыходит из меню. Откройте его снова командой sudo backupzit-server --setup (в том числе по SSH).

Те же настройки сети, имени сервера, SSH и часового пояса есть в веб-консоли в разделе Настройки → Сеть (только администраторы). Там статический адрес, шлюз которого не отвечает в течение полуминуты, автоматически откатывается, поэтому опечатка не отрежет appliance от сети; если консоль всё равно недоступна, используйте меню на экране сервера, которое работает даже при выключенном SSH.

Агенты запоминают сертификат консоли, а не её адрес. Если они обращаются к консоли по IP-адресу и он меняется, направьте их на новый командой backupzit-agent set-server (см. Агенты) или с самого начала используйте DNS-имя. При DHCP зарезервируйте адрес appliance на DHCP-сервере, чтобы он не менялся.

SSH-сервер appliance предлагает только шифры AES-GCM/CTR и MAC SHA-2 (без chacha20-poly1305 и 64-битных MAC, которые сканеры уязвимостей считают слабыми).

3. Сценарий установки

На существующем сервере с Debian 12+, Ubuntu 22.04+, AlmaLinux или Rocky Linux 9+ (x86-64), от имени root:

curl -fsSL https://github.com/Max-Zit/backupzit/releases/latest/download/install.sh | sudo sh

Сценарий устанавливает PostgreSQL, скачивает новейший выпуск, проверяет его подпись ключом выпусков BackupZit и контрольную сумму пакета, устанавливает консоль, создаёт базу данных со случайным паролем, записывает /etc/backupzit/server.env, включает автоматические обновления безопасности, открывает порт 8443 в firewalld или ufw, если они активны, запускает консоль и выводит её адрес и начальный пароль admin. Параметры (после sh -s --):

ПараметрДействие
--version 0.32.0установить этот выпуск вместо новейшего
--db postgres://user:pw@host:5432/dbиспользовать существующую базу PostgreSQL вместо локальной
--hosts backup.example.local,10.0.0.10имена и адреса для сертификата консоли (по умолчанию: адрес и имя сервера)
--no-auto-updatesоставить автоматические обновления безопасности как есть

Пример: curl -fsSL …/install.sh | sudo sh -s -- --hosts backup.example.local. Повторный запуск сценария на установленной консоли обновляет BackupZit, сохраняя конфигурацию и данные. Чтобы прочитать сценарий перед запуском, сначала скачайте его: curl -fsSLO …/install.sh; less install.sh; sudo sh install.sh.

4. Пакеты вручную

Debian / Ubuntu

apt install postgresql
apt install ./backupzit-server_*.deb

AlmaLinux / Rocky Linux

dnf install postgresql-server && postgresql-setup --initdb && systemctl enable --now postgresql
dnf install ./backupzit-server-*.rpm

В AlmaLinux и Rocky Linux замените ident на scram-sha-256 в строках 127.0.0.1 и ::1 файла /var/lib/pgsql/data/pg_hba.conf и перезапустите PostgreSQL, чтобы консоль могла входить по паролю.

Создание базы данных

sudo -u postgres psql -c "SET password_encryption = 'scram-sha-256'; CREATE USER backupzit WITH PASSWORD 'choose-a-strong-password'"
sudo -u postgres psql -c "CREATE DATABASE backupzit OWNER backupzit"

Запишите строку подключения в /etc/backupzit/server.env:

BACKUPZIT_DB=postgres://backupzit:choose-a-strong-password@localhost:5432/backupzit?sslmode=disable
BACKUPZIT_PUBLIC_URL=https://backup.example.local:8443
BACKUPZIT_TLS_HOSTS=backup.example.local,10.0.0.10
systemctl start backupzit-server

Первый вход

Откройте https://<server>:8443. Начальный администратор — admin; пароль находится в /var/lib/backupzit/initial-admin-password.txt (или задайте BACKUPZIT_ADMIN_PASSWORD до первого запуска). Смените его после входа. Чтобы сбросить забытый пароль на сервере:

set -a; . /etc/backupzit/server.env; set +a
backupzit-server --set-admin-password 'NEW-PASSWORD'

Сертификат

При первом запуске консоль создаёт самоподписанный сертификат. Браузер один раз предупредит об этом; агенты вообще не полагаются на центры сертификации — они закрепляют отпечаток сертификата, который показывается на странице Агенты при регистрации. Это защищает агентов от поддельного сервера даже в недоверенной сети.

Не заменяйте этот сертификат (cert.pem/key.pem в каталоге данных): ранее зарегистрированные агенты откажутся подключаться, пока их не зарегистрируют заново. Для браузеров вместо этого добавьте доверенный сертификат, как описано ниже.

Доверенный сертификат для браузеров

Чтобы избежать предупреждения браузера, откройте Настройки → Сертификат. Тогда консоль отвечает ещё и по DNS-имени, например https://backup.example.com на порту 443, с доверенным сертификатом. Агенты продолжают использовать порт 8443 и закреплённый сертификат, поэтому их это не затрагивает.

  • Загрузить сертификат от корпоративного или публичного ЦС, в том числе wildcard-сертификат, например *.example.com. Вставьте сертификат (с промежуточными сертификатами) и закрытый ключ в формате PEM или выберите файлы. Консоль проверяет, что ключ соответствует сертификату, что сертификат действителен сейчас и покрывает DNS-имя. Без внутреннего DNS укажите вместо этого IP-адрес консоли и используйте сертификат, выпущенный для этого IP (альтернативное имя IP:192.168.1.20); в этом случае дайте консоли постоянный адрес. За 21 день до истечения срока придёт письмо.
  • Let's Encrypt: бесплатные сертификаты, автоматически продлеваемые за 30 дней до истечения. Let's Encrypt должен проверить, что вы управляете именем, одним из двух способов:
    • DNS-проверка через Cloudflare, рекомендуется для консолей, недоступных из интернета. BackupZit создаёт временную TXT-запись с помощью API-токена Cloudflare. В Cloudflare откройте My Profile → API Tokens → Create Token, используйте шаблон Edit zone DNS и ограничьте его своей зоной.
    • HTTP-проверка: порт 80 консоли должен быть доступен из интернета по DNS-имени. Для сервера копий это редко желательно.
    Сначала попробуйте настройку с Использовать тестовую систему Let's Encrypt. Браузеры не доверяют её сертификатам, но у неё нет ограничений частоты.
  • Обслуживать порт 80 перенаправляет http:// на https://.

DNS-имя должно указывать на IP-адрес консоли, обычно через A-запись во внутреннем DNS. Файлы сертификата хранятся в /var/lib/backupzit/web, а ключ может читать только служба. В Linux службе разрешено использовать порты 80 и 443 (CAP_NET_BIND_SERVICE); откройте их в межсетевом экране, если браузеры подключаются из других сетей.

Обновление BackupZit

По умолчанию консоль берёт обновления из официальных выпусков BackupZit на GitHub (https://github.com/Max-Zit/backupzit/releases). В разделе Настройки → Обновления можно указать другой источник обновлений — собственное HTTPS-зеркало или папку на сервере. Каким бы ни был источник, каждый выпуск должен иметь действительную подпись BackupZit. Консоль ежедневно проверяет наличие новых выпусков и отправляет администраторам письмо, когда выпуск доступен. Чтобы установить его, нажмите Установить:

  1. Консоль проверяет подпись выпуска и контрольную сумму пакета и ждёт, пока не останется выполняющихся копирований и восстановлений.
  2. Системная служба (backupzit-update, работает от root) повторно проверяет подпись ключами выпусков, встроенными в BackupZit. Даже скомпрометированная консоль не сможет добиться установки другого пакета.
  3. Она создаёт копию базы данных (pg_dump), сохраняет текущую программу, устанавливает пакет и перезапускает консоль.
  4. Если новая версия не отвечает в течение двух минут, предыдущая программа и база данных в прежнем состоянии восстанавливаются автоматически. Результат с журналом неудачного запуска показывается на странице «Обновления», записывается в журнал аудита и отправляется по почте.
  5. После успешного обновления обновляются и агенты: каждый устанавливает новую версию, когда свободен. Отключите это на той же странице, если предпочитаете обновлять их сами.

Консоль недоступна около минуты. Копии базы данных и предыдущие программы трёх последних обновлений хранятся в /var/lib/backupzit-update.

Без доступа в интернет: скачайте файлы выпуска (manifest.json, manifest.json.sig и пакет сервера) на другом компьютере. Затем загрузите их в разделе Установить обновление из файлов или скопируйте в папку на сервере и используйте эту папку как источник обновлений.

Обновляться можно и менеджером пакетов (apt install ./backupzit-server_….deb); база данных переносится при запуске новой версии.

Обновления операционной системы

На той же странице (Настройки → Обновления) показана операционная система сервера консоли: сколько обновлений доступно, сколько из них исправления безопасности, нужна ли перезагрузка и включены ли автоматические обновления безопасности. Состояние обновляется ежедневно или кнопкой Проверить сейчас. Вы можете:

  • Включить автоматические обновления безопасности (рекомендуется). Собственное средство системы ежедневно устанавливает только исправления безопасности: unattended-upgrades в Debian и Ubuntu, dnf-automatic в AlmaLinux и Rocky Linux.
  • Установить все обновления сейчас. Службы вроде PostgreSQL могут ненадолго перезапуститься, консоль переподключится сама.
  • Перезапустить сервер, например после обновления ядра. Консоль отказывается это делать, пока выполняются копирование или восстановление. Агенты сохраняют свои задания и сообщают результаты, когда консоль вернётся.

Эти задачи выполняются через ту же службу root, что и обновления консоли. Они записываются в журнал аудита, а вывод последней задачи показывается на странице.

Резервная копия самой консоли

Копии в вашем хранилище остаются читаемыми без консоли благодаря листам восстановления. Чтобы после потери сервера вернуть и саму консоль, включите Настройки → Резервная копия консоли. Это включает задания, расписания, агентов, пользователей, настройки, историю запусков и сохранённые учётные данные. Тогда консоль ежедневно копирует себя в сетевое место хранения, в папку backupzit-console.

Резервная копия консоли содержит:

  • всю базу данных, выгруженную таблица за таблицей, поэтому конкретная версия pg_dump не нужна;
  • ключ секретов, расшифровывающий сохранённые учётные данные;
  • сертификат консоли, который закрепляют агенты.

Она шифруется ключом восстановления места хранения и проходит дедупликацию. Хранятся самые новые копии: по умолчанию 14.

Восстановление консоли

  1. Установите новую консоль той же или более новой версии, например с ISO appliance.
  2. На новом сервере от имени root выполните следующее. Учётные данные берутся из листа восстановления места хранения, а адрес репозитория показан на странице «Резервная копия консоли». 
    systemctl stop backupzit-server
set -a; . /etc/backupzit/server.env; set +a
export BACKUPZIT_PASSWORD='<recovery key>'
export BACKUPZIT_SFTP_PASSWORD='…' BACKUPZIT_SFTP_HOSTKEY='SHA256:…'   # or BACKUPZIT_S3_ACCESS_KEY/_SECRET_KEY, _SMB_PASSWORD, _AZURE_KEY, _HARDENED_KEY/_FINGERPRINT
backupzit-server --restore-console --repo 'sftp://backup@nas:22/backups/backupzit-console'
systemctl start backupzit-server
  3. Присвойте новому серверу IP-адрес или DNS-имя старого. Агенты доверяют восстановленному сертификату и переподключаются сами.

Восстановление заменяет базу данных новой консоли базой из копии и приводит её к установленной версии. --snapshot ID восстанавливает более старую копию вместо новейшей.

Также храните копию листов восстановления и secrets.key вне сервера, например в менеджере паролей.
