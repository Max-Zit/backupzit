Места хранения

Место хранения — это то, куда агенты записывают свои копии. Каждый агент использует собственный репозиторий внутри места хранения.

Правило 3-2-1: храните 3 копии данных на 2 разных носителях, 1 из них — вне офиса; например, одно задание на локальный NAS, а другое — в S3 или в защищённый репозиторий в другом здании.

Проверка подключения

При добавлении места хранения консоль сразу проверяет его с введёнными учётными данными: записывает небольшой файл, читает его и удаляет. На неизменяемом хранилище (S3 с Object Lock, защищённый репозиторий) она только входит и выводит список, чтобы не оставить ничего заблокированного; для S3 она также проверяет, что у bucket есть Object Lock, если запрошена неизменяемость. Место хранения сохраняется в любом случае, а результат показывается — неверный пароль, ключ хоста, bucket или общая папка обнаружатся сейчас, а не при первом копировании. Проверить подключение на странице «Хранилище» повторяет проверку. Консоль проверяет из своей сети; копии пишут агенты, поэтому место, доступное только агентам (локальный или USB-диск), проверяется первым копированием.

SFTP

Расположение: sftp://user@host:22/path (для пути относительно домашнего каталога пользователя используйте /~/path). Введите пароль или закрытый ключ и отпечаток ключа хоста сервера, который можно получить на сервере командой:

ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub

Создайте отдельного пользователя, который может писать только в папку копий.

S3-совместимое

Введите конечную точку (например, s3.eu-central-1.amazonaws.com, s3.wasabisys.com, 10.0.0.5:9000), bucket, необязательную папку и ключ доступа с правами чтения/записи в этот bucket. Отмечайте Незашифрованный HTTP только для локального MinIO без сертификата.

Неизменяемые копии (Object Lock)

Создайте bucket с включённым Object Lock и отметьте Неизменяемые копии … на N дней. Каждый файл, который записывают агенты, блокируется в режиме соответствия на N дней (+1 день запаса): никто — ни злоумышленник с ключами, ни владелец bucket — не может удалить или перезаписать его раньше. После каждого копирования блокировка данных, повторно используемых из старых копий, продлевается, поэтому каждая точка восстановления защищена на весь срок.

Удаление (хранением или злоумышленником) лишь добавляет «маркер удаления». Добавьте правило жизненного цикла, удаляющее неактуальные версии через день, чтобы место освобождалось по окончании блокировок. См. Защита от программ-вымогателей.

Google Cloud Storage

Google Cloud Storage работает как S3-совместимое место хранения через свой API совместимости:

  1. В консоли Google Cloud откройте Cloud Storage → Settings → Interoperability и создайте ключ HMAC для сервисного аккаунта с ролью Storage Object Admin на bucket.
  2. Добавьте место хранения S3 с конечной точкой storage.googleapis.com, именем bucket, ключом доступа и секретом HMAC и регионом auto.

Параметр S3 Object Lock в Google Cloud Storage недоступен; для неизменяемости задайте в Google Cloud политику хранения bucket (и заблокируйте её). Удалённые копии тогда сохраняются до окончания срока хранения.

Azure Blob Storage

  1. На портале Azure создайте учётную запись хранения (StorageV2, любая избыточность) и контейнер, например backups.
  2. Добавьте место хранения Azure Blob Storage с именем учётной записи, контейнером и необязательной папкой.
  3. Проходите проверку подлинности с ключом доступа (Учётная запись хранения → Ключи доступа) или, с меньшими правами, с токеном SAS для контейнера с правами чтения, записи, удаления и вывода списка и подходящим сроком действия.

Для защиты от программ-вымогателей включите на контейнере неизменяемость на уровне версий с политикой хранения на основе времени; удалённые или перезаписанные копии остаются восстанавливаемыми в течение этого срока. Поле конечной точки в разделе Дополнительно нужно только для Azure Government/China, Azure Stack Hub или эмулятора Azurite.

Сменные USB-диски

Диски, которые отключают и увозят из офиса, — самая простая защита небольших офисов от программ-вымогателей, пожара и кражи. BackupZit находит диск по метке тома, какую бы букву ни назначила Windows:

  1. Отформатируйте два или более дисков в NTFS (Linux: ext4) и назовите их BZBACKUP1, BZBACKUP2, … (Windows: правый щелчок по диску → Свойства → имя).
  2. Добавьте место хранения типа Сменные USB / съёмные диски с меткой BZBACKUP*.
  3. Создайте задание копирования на него — или лучше задание копирования копий, которое копирует задание NAS или облака на диск.
  4. Регулярно меняйте диски (например, еженедельно) и храните отключённый в надёжном месте.
  • Каждый диск содержит полную независимую копию со своим хранением; все диски шифруются ключом восстановления места хранения.
  • Запуск показывает, какой диск использовался (Диск BZBACKUP2). Восстановление запрашивает именно этот диск и сообщает, какой подключён.
  • Если ни один диск не подключён, запуск завершается ошибкой с понятным сообщением и оповещением — напоминанием снова подключить диск.
  • Подключайте одновременно только один из дисков.

Общая папка SMB

Сервер, общая папка, необязательная папка, пользователь, пароль и (для доменных учётных записей) домен. Агенты подключаются с этими учётными данными сами, поэтому это работает и для служб, запущенных от имени SYSTEM.

Защищённый репозиторий

Установите пакет backupzit-repo на выделенный Linux-сервер, затем на этом сервере:

backupzit-repo add-key office-console     # shows the access key once
backupzit-repo fingerprint                # certificate fingerprint

Введите в консоли адрес сервера, ключ доступа и отпечаток. Срок неизменяемости задаётся на сервере репозитория (/etc/backupzit-repo/repo.env) и не может быть изменён из консоли или агентами. Подробности в разделе Защита от программ-вымогателей.

Шифрование и ключ восстановления

При Шифровать копии (по умолчанию) всё в репозитории — содержимое и имена файлов, структура папок, списки снимков — шифруется AES-256-GCM до того, как покинет агента. Поставщик хранилища видит только случайные данные.

При создании зашифрованного места хранения консоль показывает ключ восстановления и предлагает скачать лист восстановления.

Распечатайте лист восстановления или сохраните его в менеджере паролей, отдельно от копий. Если консоль утрачена, для восстановления нужны только ключ восстановления, расположение и учётные данные хранилища. Без ключа зашифрованные копии не сможет прочитать никто — включая поддержку BackupZit.

Позже ключ можно снова показать кнопкой Ключ восстановления в списке хранилищ; это записывается в журнал.

Список хранилищ

Список показывает для каждого места хранения тип, расположение, шифрование (с доступом к ключу восстановления для администраторов) и неизменяемость: срок Object Lock для S3 или задаётся на сервере репозитория для защищённых репозиториев. Учётные данные после сохранения больше никогда не показываются и хранятся в зашифрованном виде. Добавлять и удалять места хранения и видеть ключи восстановления могут только администраторы.

Использование хранилищ и прогноз

После каждого копирования (и его хранения) агент сообщает, сколько места занимает его репозиторий, а для локальных и USB-дисков, SFTP-серверов (расширение OpenSSH statvfs) и общих папок SMB — размер и свободное место хранилища. В разделе Хранилище → Использование хранилищ каждое место хранения показывает:

  • место, занятое всеми репозиториями на нём (по одному на агента; для сменных USB-дисков считается каждый диск);
  • для хранилища с известным размером — насколько оно заполнено (жёлтым от 75 %, красным от 90 %), с ёмкостью в виде красной пунктирной линии на графике;
  • график за последние 90 дней и, после недели копирования, рост в день (линейный тренд за последние 30 дней), продлённый на 30 дней вперёд пунктиром, и когда хранилище заполнится — или, без известного размера, ожидаемое использование через 90 дней.

Требует внимания на панели предупреждает, когда место хранения заполнено на 90 % или заполнится в течение 30 дней. У S3 и Azure нет фиксированного размера; там показываются только занятое место и его рост. Занятое место — это хранимые (сжатые, зашифрованные, дедуплицированные) данные; файлы, которые хранилище держит по другим причинам (версии объектов, другие программы), не учитываются.

Удаление места хранения

Удаление места хранения из консоли не удаляет никаких данных в хранилище. При включённом одобрении по принципу четырёх глаз сначала должен одобрить второй пользователь.
