Виртуальные машины Hyper-V

BackupZit копирует виртуальные машины Hyper-V через агента на хосте Hyper-V; внутри ВМ ничего не устанавливается. Гостевые Windows и Linux захватываются без остановки. Их можно восстановить как новую ВМ или вместо исходной.

Настройка

  1. Установите MSI Агент Windows со страницы Агенты на хост Hyper-V и зарегистрируйте его. Поддерживаемые хосты: Windows Server 2016 или новее с ролью Hyper-V либо Windows 10/11 с Hyper-V. В кластере установите агента на каждый хост.
  2. В течение минуты хост появляется на странице Агенты с меткой Hyper-V · N VMs.
  3. В Задания копирования выберите этого агента и Виртуальные машины (Proxmox VE, Hyper-V, VMware). Затем выберите:
    • все ВМ хоста — это охватывает и ВМ, созданные позже;
    • отдельные ВМ, отметив их.

Агент работает через собственные интерфейсы Hyper-V: модуль PowerShell Hyper-V и Windows Virtual Disk API. Консоль не хранит учётные данные Hyper-V.

Как копируется ВМ

  1. Создаётся временная контрольная точка восстановления (backupzit_…). Это тип контрольной точки, который Hyper-V предоставляет приложениям резервного копирования. Hyper-V просит гостя подготовиться:
    • Гостевые Windows сбрасывают буферы приложений через VSS.
    • Гостевые Linux замораживают файловые системы, если установлены демоны Hyper-V (hyperv-daemons / hv-vss-daemon).
    Если гость не может сделать ни того, ни другого, контрольная точка создаётся с согласованностью на уровне сбоя (crash-consistent). Страница запуска показывает, какой вид использовался.
  2. Контрольная точка восстановления включает Resilient Change Tracking (RCT) для дисков ВМ; рядом с ними появятся файлы .rct и .mrt. Первая копия читает диски целиком. Далее RCT сообщает, какие блоки изменились с прошлой копии, и читаются только они.
  3. Диски читаются в состоянии контрольной точки через Virtual Disk API блоками по 1 МиБ. Это охватывает файлы VHDX и VHD, включая цепочки прежних контрольных точек. Пустые блоки не сохраняются, а блоки, уже имеющиеся в репозитории, не отправляются повторно.
  4. Контрольная точка удаляется, и Hyper-V объединяет её в фоне.
  5. Конфигурация ВМ сохраняется вместе с копией: поколение, ЦП, память, сетевые адаптеры (коммутатор, VLAN, MAC-адрес), контроллеры дисков, безопасная загрузка и TPM.

Выключенные ВМ читаются напрямую, без контрольной точки. На хостах старше Windows Server 2016 (нет контрольных точек восстановления) используется рабочая контрольная точка, и каждая копия читает диски целиком.

Пример из тестовой лаборатории: Linux-ВМ с диском 3 ГБ. Первая копия прочитала 3 ГБ. Следующая, после 64 МБ новых данных, прочитала 96 МБ.

В Windows 10/11 Hyper-V создаёт автоматическую контрольную точку при запуске ВМ, если эта опция не выключена в параметрах ВМ. BackupZit справляется с такими контрольными точками, но для серверов автоматические контрольные точки лучше выключить (параметры ВМ → Контрольные точки).

Восстановление ВМ

Откройте запуск копии ВМ (со страницы задания или из Активность) и используйте Восстановить ВМ Hyper-V.

Как новая ВМ рядом с исходной

Создаёт вторую ВМ с новыми MAC-адресами, чтобы она могла работать в той же сети, что и исходная. По умолчанию она называется как исходная с добавлением «restored» и даты. Автоматические контрольные точки в ней выключаются (Windows включает их для новых ВМ), поэтому её запуск не оставляет файлов контрольных точек. Если копия работает рядом с исходной и содержит агента BackupZit, см. Две машины с одним агентом.

Сетевые настройки гостя, привязанные к MAC-адресу, не применяются к новым адаптерам. Пример — match: macaddress в netplan, который используют облачные образы Linux.

Вместо исходной ВМ

Отметьте выключить её и заменить её диски. Тогда BackupZit:

  • выключает существующую ВМ;
  • объединяет её контрольные точки;
  • заменяет её диски восстановленными.

ВМ сохраняет свой ID, сетевые адаптеры и MAC-адреса, поэтому задания, мониторинг и сеть гостя продолжают работать.

Старые файлы дисков не удаляются, а переименовываются в ….replaced-DATE. Удалите их, когда восстановленная ВМ заработает.

Если исходной ВМ больше нет, она создаётся заново, с новым ID Hyper-V.

Параметры

  • Папка для виртуальных дисков: папка хоста по умолчанию или любая папка с дисками ВМ. Восстановление на месте кладёт новые диски рядом с исходными.
  • Запустить ВМ после восстановления.

Что получает восстановленная ВМ

  • Виртуальные коммутаторы подключаются по имени. Если коммутатора нет на хосте, адаптер остаётся отключённым.
  • Каждая восстановленная ВМ получает новый идентификатор поколения, чтобы контроллеры домена Active Directory безопасно распознали восстановление.

Восстановление отдельных файлов

В таблице ВМ запуска нажмите Просмотр файлов, чтобы увидеть разделы и тома на дисках ВМ. Можно просматривать NTFS, ext2/3/4 и XFS, в том числе внутри LVM. Оттуда можно скачать файлы или восстановить их на любой агент. Это работает точно так же, как для Proxmox VE.

Командная строка

Выполняйте на хосте Hyper-V от имени администратора:

backupzit-agent hyperv list
backupzit-agent hyperv backup  --repo ... [--vmid N,N]
backupzit-agent hyperv restore --repo ... --vmid N [--new] [--name NAME] [--folder D:\VMs] [--overwrite] [--start] SNAPSHOT|latest
  • --vmid — номер, который показывает hyperv list. BackupZit вычисляет его из GUID ВМ.
  • Без --new ВМ восстанавливается на месте.
  • --overwrite подтверждает, что диски существующей ВМ нужно заменить.

Параметры репозитория те же, что у всех команд; см. Справочник по командной строке.

Пока не поддерживается

  • Некоторые типы дисков. Общие VHDX, VHD Set и проходные (pass-through) диски не копируются.
