Агенты macOS (Apple silicon)

Агент macOS копирует файлы и папки Mac с чипом Apple. Он работает как служба с первой загрузки, читает каждую копию загрузочного диска из локального снимка APFS и сохраняет метаданные файлов Mac. Приложение в строке меню показывает его состояние и проводит пользователя через разрешения, которые может дать только он.

Требования

  • Mac с чипом Apple silicon (M1 и новее, arm64) и macOS 13 или новее. Для Mac с процессором Intel пакета нет.
  • Учётная запись администратора на Mac для установки и регистрации.
  • Пользователь Mac, чтобы предоставить полный доступ к диску: macOS не позволяет сделать это никому другому — ни скрипту, ни консоли.
  • Как и любой агент, Mac должен иметь доступ к адресу консоли для агентов (обычно порт 8443) и к хранилищу.

Установка

  1. На странице Агенты скачайте Агент macOS — Apple Silicon (backupzit-agent_версия_darwin_arm64.pkg). Пакет консоли содержит его, как и установщики Windows и Linux.
  2. Откройте .pkg на Mac и следуйте указаниям установщика. Для пакета, не подписанного Apple Developer ID, macOS сначала запрашивает подтверждение: щёлкните его правой кнопкой и выберите Открыть (в новых версиях macOS: Системные настройки → Конфиденциальность и безопасность → Всё равно открыть).
  3. Последняя страница установщика объясняет, какие разрешения нужно дать, и открывается приложение в строке меню.

Пакет устанавливает:

Программа не добавляется в PATH: в Терминале вызывайте её по полному пути.

Регистрация

Служба установлена и работает ещё до регистрации Mac; она начинает работу сразу после неё. На странице Агенты кнопка Создать токен регистрации показывает команды для macOS рядом с командами для Windows и Linux. Выберите один из трёх способов:

  1. В Терминале после установки (обычный способ): 
    sudo /Library/BackupZit/bin/backupzit-agent enroll --code "BZ1-..."
  2. Через MDM (Jamf, Intune, Mosyle…): до установки пакета скрипт записывает код в файл, владельцем которого является root: 
    echo "BZ1-..." | sudo sh -c 'umask 077; mkdir -p "/Library/Application Support/BackupZit"; cat > "/Library/Application Support/BackupZit/enroll-code"'
    Затем разверните пакет. Его установка регистрирует Mac с этим кодом и удаляет файл. Файл, владелец которого не root, игнорируется. Так же можно перенести зарегистрированный Mac на другую консоль.
  3. Файл рядом с пакетом: backupzit-enroll.txt с кодом в той же папке, что и .pkg (например, на USB-накопителе или в общей папке). Он используется, только пока Mac ещё не зарегистрирован, и только если никто другой не мог его записать: владелец файла — root или владелец пакета, а его папка недоступна для записи другим пользователям (или имеет бит sticky, как /Users/Shared).

Если консоль недоступна во время установки, агент сохраняет код и повторяет попытки. Если регистрация не удалась, причина записана в /Library/Application Support/BackupZit/enroll-error.log; затем зарегистрируйте Mac в Терминале. Обновления и переустановки сохраняют регистрацию.

Разрешения

macOS защищает часть данных от любой программы, даже работающей от root, пока пользователь не разрешит доступ в Системных настройках. Дать эти разрешения может только пользователь за Mac; последняя страница установщика и приложение в строке меню проводят его через них.

Полный доступ к диску для агента

Без него в копиях нет папок, защищённых macOS, и снимок APFS не создаётся (см. Что копируется).

  1. Откройте Системные настройки → Конфиденциальность и безопасность → Доступ к диску.
  2. Нажмите + под списком и введите пароль.
  3. Нажмите Command-Shift-G, введите /Library/BackupZit/bin/backupzit-agent, нажмите Return и нажмите Открыть.
  4. Проверьте, что переключатель рядом с backupzit-agent включён.

Вместо + можно перетащить файл в список: в Finder выберите Переход → Переход к папке…, введите /Library/BackupZit/bin и перетащите backupzit-agent в список.

Агент в фоновом режиме

После установки macOS показывает Добавлены фоновые объекты. В Системные настройки → Основные → Объекты входа и расширения, в разделе Разрешать в фоновом режиме, backupzit-agent и BackupZit должны оставаться включёнными: если их выключить, агент не работает и ни одна копия не запускается.

Уведомления и открытие при входе

  • Уведомления: разрешите их, когда приложение в строке меню попросит, или позже в Системные настройки → Уведомления → BackupZit (Разрешить уведомления). Так приложение сообщает пользователю о неудачной копии.
  • Открытие при входе: приложение в строке меню открывается при каждом входе, пока BackupZit включён в Объекты входа и расширения → Разрешать в фоновом режиме.

Приложение в строке меню и его помощник

Значок BackupZit в строке меню показывает состояние агента; в его меню есть Back up now для каждого задания Mac, Open console in browser и Hide this icon (до следующего входа; копирование продолжается). Раздел Permissions перечисляет агента в фоновом режиме, полный доступ к диску, уведомления и открытие при входе, каждое с ✅ или ❌. Щелчок по пункту открывает его страницу Системных настроек; недостающее разрешение приложение также объясняет один раз после каждого входа в систему, в окне с порядком действий. Пока чего-то не хватает, оно само проверяет снова каждые несколько секунд, так что ✅ появляется, как только разрешение дано. Агент также сообщает консоли об отсутствии полного доступа к диску в отчёте о запуске.

Проверка в Терминале

/Library/BackupZit/bin/backupzit-agent status

Работает от обычного пользователя и показывает консоль, задания и full disk access: granted или denied (с программой, которую нужно включить).

Полный доступ к диску после обновления

macOS привязывает полный доступ к диску к подписи программы. Пакеты, подписанные Apple Developer ID, сохраняют его при обновлениях. Пакет, собранный без неё (подписанный ad hoc), теряет его при каждом самообновлении: копии снова предупреждают, а приложение в строке меню сообщает, что полный доступ к диску пропал после обновления. Дайте его снова: в списке «Полный доступ к диску» выберите backupzit-agent, нажмите −, чтобы удалить его (выключить и включить недостаточно), затем снова добавьте его через +, как описано выше.

Что копируется

Агент Mac выполняет задания файлов и папок, как любой агент: пути вроде /Users, /Applications или /, пути с {users} (/Users/<имя>/Documents) и подстановочные знаки, в том числе в задании для нескольких агентов с Все агенты macOS.

Локальный снимок APFS

Каждая копия файлов с тома данных загрузочного диска читается из локального снимка APFS — аналога VSS из Windows в macOS: копия видит каждый файл на один момент, в том числе те, в которые программа продолжает писать. Агент создаёт снимок (tmutil localsnapshot), монтирует его только для чтения, читает из него файлы, а после копирования отмонтирует и удаляет его. Снимки, оставшиеся после сбоя, удаляются при следующем запуске; собственные снимки Time Machine агент никогда не трогает. Отчёт о запуске сообщает Read from an APFS local snapshot of /System/Volumes/Data.

Снимку нужны служба (root) и полный доступ к диску. Без полного доступа к диску, а также для путей на других томах (/Volumes: внешние диски, сетевые папки) файлы читаются без снимка, и отчёт о запуске сообщает об этом.

Метаданные

Сохраняются с каждым файлом и папкой: владелец и группа, права, расширенные атрибуты (кроме com.apple.provenance, которым macOS управляет сама), жёсткие ссылки, символические ссылки, флаги файлов BSD (скрытый, защищённый, nodump, только добавление…; системные флаги — только когда агент работает от root, как служба), время создания и время изменения с точностью до наносекунды. Разреженные файлы остаются разреженными: их пустоты на APFS восстанавливаются.

Папки, сохраняемые пустыми

Некоторые системные папки внутри копируемой папки сохраняются как пустые папки: другие тома (/Volumes), файл подкачки (/System/Volumes/VM, /private/var/vm), служебные тома в /System/Volumes, /dev, временные файлы (/private/tmp, /private/var/folders), кэши (/Library/Caches, /System/Library/Caches, ~/Library/Caches), Корзина (~/.Trash, .Trashes), Spotlight, FSEvents, версии документов, а также локальные копии Time Machine и копии Time Machine на HFS+. Если источник — /, папки тома данных, которые / уже показывает (/Users, /Applications…), не читаются дважды. Папка, указанная как источник задания, читается всегда, например /Volumes/USB или ~/.Trash.

Предупреждения в отчёте о запуске

Без полного доступа к диску папки, защищённые macOS, прочитать нельзя: Почта, Сообщения, Safari, Рабочий стол и Документы, данные других приложений, съёмные и сетевые тома. Копия, источники которой затрагивают /Users (кроме /Users/Shared), /Library или /Volumes, либо папку над ними, например /, тогда завершается предупреждением Full Disk Access is not granted to the BackupZit agent. Копии других папок (например, /opt/data) не предупреждают.

Восстановление

Файлы Mac восстанавливаются как все копии файлов: вся копия или только некоторые пути, в папку или в исходное расположение, на Mac или на другом агенте; отдельные файлы можно скачать из консоли. Восстановление на Mac снова устанавливает перечисленные выше метаданные. Как в Windows и Linux, оно пишет только через открытые им папки, никогда по пути, поэтому ссылка, подложенная во время восстановления, не отслеживается. Восстановление поверх защищённых файлов сначала снимает их флаги защиты и «только добавление», а затем снова устанавливает сохранённые (системные флаги на работающем Mac снять нельзя).

Обновление и удаление

Страница Агенты предлагает для Mac Обновить до версия, как и для других агентов (см. Агенты). Агент скачивает .pkg с консоли, проверяет его по подписанному списку установщиков агента и по контрольной сумме SHA-256, устанавливает его программой Apple installer в одноразовом задании launchd и перезапускается с новой версией. Если launchd отклоняет это задание, запуск обновления завершается ошибкой с сообщением launchd. Журнал установщика находится в /Library/Application Support/BackupZit/updates. После обновления неподписанного пакета проверьте полный доступ к диску.

Удалить на странице «Агенты» с вариантом Деинсталлировать агента с компьютера удаляет программу, приложение в строке меню, LaunchDaemon и LaunchAgent и запись об установке пакета; конфигурация и журнал остаются. Удаление вручную:

sudo /Library/BackupZit/uninstall.sh            # keeps configuration and log
sudo /Library/BackupZit/uninstall.sh --purge    # deletes them too

Без --purge регистрация откладывается (agent.json.removed-дата), поэтому новая установка снова запрашивает код. После удаления вручную уберите backupzit-agent из Конфиденциальность и безопасность → Доступ к диску: macOS не позволяет сделать это программе.

Чего не умеет агент Mac

Не на MacВместо этого
Копии системы Linux / bare-metalКонсоль отклоняет системное задание для Mac (is a Mac: back it up with a files job): его системный том запечатан и подписан Apple и переустанавливается, а не восстанавливается. Копируйте данные заданием файлов.
Образы дисковТолько Windows.
Хосты Hyper-V, Proxmox VE и прокси VMware ESXiАгенты на хосте Hyper-V (Windows), на узле Proxmox (Linux) или агент Linux в роли прокси.
Задания NAS / общей папки (SMB, NFS)Пока агент Windows или Linux: агент Mac ещё не подключает общие папки.
Задания PostgreSQL / MySQLВ macOS пока не проверены: используйте их на Mac только после проверки восстановления.

Задания Microsoft 365 выполняются на любом агенте с доступом в интернет, в том числе на Mac.

СитуацияЧто делать

Затем проверьте сетевой путь к консоли, как для любого агента (Устранение неполадок).

Журналы

  • Агент: /Library/Logs/BackupZit/agent.log (виден и в приложении «Консоль»); трассировка сбоя попадает в /Library/Logs/BackupZit/launchd.log.
  • Регистрация установщиком: /Library/Application Support/BackupZit/enroll-error.log и журнал установщика /var/log/install.log.
  • Обновления: /Library/Application Support/BackupZit/updates.
  • Получить журнал на странице Агенты получает конец журнала через консоль (см. Журналы).
