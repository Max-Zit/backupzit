Виртуальные машины VMware ESXi

BackupZit копирует виртуальные машины хостов VMware ESXi, ничего не устанавливая ни на ESXi, ни внутрь ВМ. Агент BackupZit на любой машине в сети работает как прокси хоста. Он создаёт снимки, читает только изменённые блоки виртуальных дисков и записывает их в ваше хранилище.

Требования

  • ESXi 6.7, 7 или 8 с прямым подключением или vCenter Server 7 или 8 с его хостами ESXi (см. vCenter Server).
  • Пользователь с правами администратора на хосте, обычно root.
  • SSH включён на хостах с бесплатной лицензией: Host → Actions → Services → Enable Secure Shell. Бесплатная лицензия ESXi делает API доступным только для чтения, поэтому снимки и восстановление идут через SSH. Лицензированные хосты изменяются через vSphere API, и SSH им не нужен.
  • Прокси-агент: любой агент Windows или Linux, который достигает хоста по порту 443 (и 22, когда используется SSH). Данные копий идут через него, поэтому разместите его в быстрой сети рядом с хостом и хранилищем.
  • Свободное место в хранилище данных ВМ во время копирования работающей ВМ. BackupZit ненадолго копирует туда диск (см. ниже). Копия тонкая (thin), поэтому ей нужно столько места, сколько диск реально занимает. С hot-add копия не создаётся.

Добавление хоста

  1. Откройте Агенты → Хосты VMware ESXi → Добавить хост ESXi или vCenter Server.
  2. Введите адрес, пользователя, пароль и прокси-агента.
  3. Консоль один раз подключается, чтобы их проверить. Она читает список ВМ и лицензию и закрепляет HTTPS-сертификат и SSH-ключ хоста. Если позже хост заменят другой машиной с тем же адресом, BackupZit откажется подключаться, а не отправит ей пароль. Если сертификат изменился по известной причине — хост переустановлен, получил новый сертификат или добавлен в vCenter (который заменяет сертификаты своих хостов), — на странице «Агенты» хост показывает новый отпечаток и кнопку Принять новый сертификат. Перед принятием сравните отпечаток с хостом.

Пароль хранится в зашифрованном виде, как и все остальные секреты. К хосту подключается сама консоль (HTTPS 443, а при бесплатной лицензии ещё и SSH 22): при добавлении, по кнопке Обновить и каждые 10 минут, чтобы обновить список ВМ, если только к хосту не подключаются через агент-прокси. Удалить удаляет хост вместе с его заданиями резервного копирования; копии остаются в хранилище. Таблица показывает режим каждого хоста:

  • vSphere API (лицензированный хост, SSH не нужен): снимки, копии дисков, восстановление и мгновенное восстановление идут через API.
  • vCenter Server (vSphere API): vCenter со своими хостами ESXi; всё идёт через API vCenter.
  • бесплатная лицензия: снимки и восстановление через SSH: API хоста только для чтения, поэтому эти шаги идут через SSH.
  • SSH (выбран для этого хоста): хост изменяется через SSH, хотя его API мог бы это сделать (Всегда SSH при добавлении хоста).

Через агент-прокси (агент 0.56 или новее): отметьте Подключаться через агент-прокси при добавлении хоста или Подключаться через прокси в его строке, и консоль никогда не будет подключаться к хосту сама. Агент-прокси проверяет адрес и пароль, читает список ВМ, версию и лицензию и сообщает HTTPS-сертификат и SSH-ключ хоста, которые он увидел; консоль закрепляет их в первый раз, как и при прямом подключении, а с этого момента агент-прокси отклоняет хост, предъявивший другой сертификат (тогда в строке хоста появляется Принять новый сертификат). Обновить и список ВМ каждые 10 минут тоже идут через агент-прокси; эти проверки не показываются в «Активности». Достучаться до хоста должен только агент-прокси — точно так же, как для резервного копирования и восстановления, поэтому консоль может находиться в другой сети, за NAT или в пересекающемся диапазоне адресов. Неверный адрес или пароль отображается как ошибка хоста после первой проверки агентом-прокси: удалите хост и добавьте его снова. Пока агент-прокси не в сети или занят, остаётся последний список ВМ.

При Автоматически консоль выбирает сама, поэтому хост, получивший лицензию позже, переходит на API без дополнительной настройки. Как изменяется хост в строке хоста (и при добавлении) позволяет задать Всегда SSH или Всегда vSphere API; изменение сразу проверяется. Прежние копии и их точки восстановления от способа не зависят.

vCenter Server

Добавьте vCenter Server так же, как хост: его адрес, administrator@vsphere.local (или пользователя с ролью Administrator) и прокси-агента. Тогда BackupZit через одно это подключение видит ВМ всех хостов ESXi и кластеров центра обработки данных; ничего не изменяется через SSH, и пароль хостов не нужен.

  • ВМ, перенесённая на другой хост с помощью vMotion, продолжает копироваться: ВМ узнаются по UUID экземпляра, а не по хосту.
  • При восстановлении можно выбрать хост ESXi, на котором будет работать ВМ (по умолчанию: хост исходной ВМ), и хранилище данных.
  • Мгновенное восстановление запускает ВМ на выбранном хосте; Завершить переносит её в хранилище данных с помощью Storage vMotion на ходу, без простоя.
  • vCenter с несколькими центрами обработки данных пока нельзя добавить; хосты остальных центров добавьте напрямую.

Не добавляйте один и тот же хост ESXi и напрямую, и через vCenter: у каждого подключения свой репозиторий, поэтому его ВМ копировались бы дважды. Если хост, который BackupZit копирует напрямую, позже добавлен в vCenter, примите его новый сертификат на странице «Агенты»; его задания продолжают работать — vCenter присваивает ВМ, созданным на автономном хосте, новый ID, и BackupZit при следующем обновлении переводит задания на него.

Задания копирования

В Задания копирования выберите хост ESXi (он указан в разделе Хосты VMware ESXi списка агентов) и Виртуальные машины. Копируйте все ВМ хоста (ВМ, созданные позже, включаются автоматически) или отметьте отдельные. Задание выполняется на прокси-агенте хоста. Если вы смените прокси, существующие задания последуют за ним.

Чтобы исключить отдельные ВМ, например ВМ консоли BackupZit, выберите Все ВМ (и контейнеры) на хосте, кроме отмеченных и отметьте их.

Как копируется ВМ

  1. Для ВМ включается отслеживание изменённых блоков (CBT), если оно выключено.
    • На лицензированных хостах это происходит автоматически.
    • На бесплатных хостах CBT можно включить только при выключенной ВМ. BackupZit делает это при первой копии, которая застанет ВМ выключенной. До тех пор каждая копия читает диски целиком, а запуск показывает предупреждение.
  2. Создаётся снимок backupzit_…. Когда в госте работают VMware Tools, снимок приостанавливает гостя (quiesced): приложения и файловые системы сначала сбрасывают буферы, что делает копию согласованной на уровне приложений. Без VMware Tools она согласована на уровне сбоя. Установите open-vm-tools в Linux-ВМ и VMware Tools в Windows-ВМ. Для гостя, у которого приостановка не удаётся или работает неправильно, включите в задании Аварийно-согласованные снимки (без приостановки гостя через VMware Tools): его копии тогда аварийно-согласованные, как после отключения питания (агент 0.58). На некоторых хостах (ESXi 6.7) диск снимка с приостановкой — это небольшая дельта, которую записала сама приостановка; агент читает её вместе со снимком (агент 0.58; более старые агенты отклоняли её как дельта-диск снимка).
  3. CBT сообщает, какие блоки читать:
    • при первой копии — только используемые блоки;
    • затем — только блоки, изменившиеся с прошлой копии.
  4. Работающая ВМ держит свои диски заблокированными. Поэтому её диски копируются в хранилище данных (thin), а снимок сразу удаляется, обычно через несколько секунд. Затем копия читается по HTTPS и удаляется. Выключенные ВМ читаются напрямую. С hot-add диски работающих ВМ вместо этого читаются через собственную ВМ прокси, без копии.
  5. Конфигурация ВМ (.vmx) и NVRAM сохраняются вместе с копией.

Пример из тестовой лаборатории: ВМ Debian с диском 8 ГБ, из которых занято 1,6 ГБ. Первая копия прочитала 1,6 ГБ. Следующая, после 50 МБ новых данных, прочитала 70 МБ и заняла 23 секунды.

Hot-add: без копии в хранилище данных

Копирование дисков работающей ВМ при каждой копии, в том числе инкрементной, стоит времени и операций ввода-вывода в рабочем хранилище данных и требует свободного места под занятые блоки дисков. Для больших ВМ на медленных дисках это важно. С Hot-add (Агенты → Хосты VMware ESXi, флажок под агентом-прокси) прокси вместо этого читает их на месте:

  • Требования: прокси — это агент Linux в ВМ, которая видит хранилища данных копируемой ВМ (на том же хосте или на хосте того же vCenter с доступом к ним), а хост изменяется через vSphere API (vCenter или лицензированный хост). Прокси находит свою ВМ по её BIOS UUID.
  • Как: пока существует снимок, каждый диск подключается к ВМ прокси в режиме independent-nonpersistent. Прокси открывает его только для чтения; всё, что было бы в него записано, попало бы в redo log, который vSphere отбрасывает при отключении диска, поэтому диск ВМ никогда не меняется. Прокси читает только блоки, о которых сообщает CBT, отключает диск, и затем снимок удаляется.
  • Что это экономит: ни временной копии, ни дополнительного места в хранилище данных. Инкрементная копия ВМ на 2 ТБ с 20 ГБ изменений читает 20 ГБ. Снимок остаётся, пока читаются диски (а не только на время копирования), поэтому ВМ пишет в снимок немного дольше.
  • Запасной вариант: если прокси не является ВМ этого хоста или подключение либо чтение диска не удаётся, этот диск, как и раньше, копируется в хранилище данных, а запуск показывает предупреждение с причиной. Hot-add по умолчанию выключен; агенты до 0.54 его игнорируют. На странице запуска видно, сколько дисков прочитано через hot-add.
  • На ВМ прокси: не давайте LVM активировать тома подключённых дисков — с помощью файла устройств LVM (use_devicesfile = 1 в /etc/lvm/lvm.conf, собственные диски прокси внесены через lvmdevices). Тома, которые LVM всё же активирует, удаляются до отключения диска. Не подключайте к прокси вручную диски других ВМ: диск independent-nonpersistent из папки другой ВМ принимается за оставленный прерванной копией и отключается.

Несколько агентов-прокси (vCenter)

Один агент-прокси читает диски один за другим, а через hot-add — только на хостах, хранилища данных которых он видит. При подключении к vCenter добавьте агент Linux в ВМ на каждом хосте ESXi как дополнительный агент-прокси (Агенты → Хосты VMware ESXi, Дополнительные агенты-прокси под агентом-прокси; агенты 0.55 или новее):

  • Разделение по хостам: каждая резервная копия задания разделяется. Каждая ВМ достаётся агенту-прокси на хосте ESXi, где она работает (по последнему списку ВМ), каждая другая ВМ — агенту-прокси подключения. Каждый агент-прокси создаёт копию своей доли отдельным запуском, одновременно с остальными, через hot-add на своём хосте. Участвуют только агенты-прокси в сети: ВМ выключенного агента-прокси достаются агенту-прокси подключения. Первая резервная копия в новый репозиторий и копии на локальную или USB-цель не разделяются.
  • Один запуск: задание показывает части одного запуска как целое: выполняется, пока выполняется какая-либо часть, ошибка, если какая-либо часть завершилась ошибкой. Оповещения RPO и панель учитывают резервную копию, только когда все части успешны; связанное задание или копия «после каждой резервной копии» запускается один раз, после последней части.
  • Без пересечений: резервные копии и восстановления подключения на разных агентах-прокси не выполняются одновременно (одновременно идут только части одного запуска), поэтому ВМ, перенесённую между хостами, никогда не обрабатывают два агента-прокси сразу.
  • Хранение по агентам-прокси: каждая часть хранит заданное число резервных копий своих ВМ, и задания копирования тоже копируют и хранят их по частям. Резервные копии, сделанные до разделения задания, и копии удалённого агента-прокси остаются как есть: они по-прежнему точки восстановления своих ВМ. ВМ, перенесённая на другой хост (vMotion), со следующего обновления списка ВМ достаётся агенту-прокси этого хоста.
  • Хост агента-прокси BackupZit находит по BIOS UUID, который сообщает его агент; страница «Агенты» показывает его рядом с каждым агентом. Хост ESXi не найден: агент не является ВМ этого vCenter, или список ВМ старше агента (нажмите Обновить).

Отмена резервного копирования VMware (Активность → Отмена) также останавливает идущее копирование диска в хранилище данных и удаляет неполную копию; снимок удаляется, как после каждого резервного копирования. Если в момент отмены снимок ещё создаётся, агент дожидается его (до пяти минут) и тоже удаляет.

Оставшиеся снимки. Агент-прокси записывает каждый снимок и временную копию диска до их создания и удаляет запись только тогда, когда видит, что объекта больше нет: после удаления он снова получает список снимков ВМ, делает до трёх попыток примерно за десять минут, снова входит в систему, если сеанс vSphere завершился (также перед каждой ВМ, чтобы один потерянный сеанс не приводил к сбою следующих ВМ), и консолидирует диски, если vSphere сообщает, что это нужно; ВМ без снимков, диски которой после прежнего удаления ещё требуют консолидации, консолидируется перед следующим копированием. Если агент остановится посередине (сбой, отключение питания) или удаление раз за разом не удаётся, запись остаётся:

  • Консоль ставит в очередь запуск очистки на агенте-прокси (учётные данные хоста есть только у него), а агент-прокси также удаляет такие остатки после каждого резервного копирования подключения. ВМ, с которыми работает резервное копирование или восстановление агента-прокси, не затрагиваются.
  • Панель мониторинга показывает каждый остаток в разделе Требует внимания (ВМ, с какого времени, почему) с кнопкой Удалить сейчас, а по каждому остатку, который остаётся, один раз отправляется уведомление (почта, чат).
  • Кроме того, консоль ищет снимки backupzit_… старше шести часов в списке ВМ, который обновляет каждые 10 минут, пока не идёт ни одно резервное копирование подключения, поэтому появляются и остатки старых агентов. Удаляются только снимки с именем backupzit_…; собственные снимки ВМ никогда не затрагиваются.

Восстановление ВМ

Используйте мастер восстановления (Вся виртуальная машина) или страницу копии в Активности. Выберите:

  • Как новую ВМ рядом с исходной: копия с новым именем, UUID и MAC-адресами. Имя по умолчанию — имя оригинала плюс -restored- и дата. Сетевые настройки гостя, привязанные к старым MAC-адресам, например netplan match: macaddress в облачных образах, к копии не применяются.
  • Вместо исходной ВМ: с опцией выключить её и заменить её диски BackupZit:
    • выключает ВМ и удаляет её снимки;
    • переименовывает текущие диски в ….replaced-DATE.vmdk (удалите их, когда восстановленная ВМ заработает);
    • записывает копию в новые диски с исходными именами и задаёт ЦП и память как в копии.
    ВМ сохраняет UUID, сетевые адаптеры и MAC-адреса. Если ВМ была удалена, она создаётся заново с исходной идентичностью.
  • Хост ESXi и хранилище данных: другой хост или другое хранилище того же хоста.
  • Запустить ВМ после восстановления.

Диски восстанавливаются тонкими, записываются только блоки с данными. ISO-образы, подключённые к приводам CD/DVD, не входят в копию, поэтому эти приводы остаются пустыми.

Мгновенное восстановление

Выберите Мгновенно, работая из копии, чтобы запустить ВМ за несколько секунд, не копируя сначала её диски. Прокси-агент хоста — это должен быть агент Linux — отдаёт диски ВМ прямо из копии по NFS; хост монтирует это как хранилище данных backupzit-<agent> и запускает из него ВМ. Изменения, вносимые ВМ, хранятся на агенте (/var/lib/backupzit/instant-esxi, поэтому ему нужно для них свободное место); сама копия никогда не меняется, и хранение удерживает её, пока ВМ работает из неё. Если исходная ВМ ещё существует, мгновенная ВМ получает новый UUID и новые MAC-адреса.

На странице запуска, когда ВМ работает как надо:

  • Завершить копирует её в хранилище данных хоста: ВМ выключается (через VMware Tools, если они работают), её диски копируются тонкими (через API на лицензированных хостах, с помощью vmkfstools через SSH при бесплатной лицензии), она регистрируется из хранилища данных и снова запускается. У отдельного хоста нет Storage vMotion, поэтому требуется короткий простой, растущий с размером дисков. Если копирование не удалось, ВМ продолжает работать из копии.
  • Отменить останавливает и удаляет ВМ со всеми её изменениями.

Агент отвечает по NFS на порту 2049 (и регистрирует его в rpcbind машины на порту 111 или сам отвечает на порту 111) только для адреса хоста ESXi; откройте эти порты от хоста к агенту, если между ними есть межсетевой экран. Когда последняя мгновенная ВМ завершена или отменена, хранилище данных удаляется, а NFS-сервер останавливается.

Отдельные файлы

Просмотр файлов на странице копии (или Файлы из виртуальной машины в мастере восстановления) открывает диски ВМ. Можно просматривать NTFS, ext2/3/4 и XFS, в том числе на LVM, и скачивать файлы или восстанавливать их на любой агент.

Командная строка

Эти команды работают на любом агенте. Задайте пароль ESXi в BACKUPZIT_VMWARE_PASSWORD:

backupzit-agent vmware list    --host 192.168.1.20 [--user root]
backupzit-agent vmware backup  --host … --repo … [--vmid N,N]
backupzit-agent vmware restore --host … --repo … --vmid N [--new] [--name NAME] [--datastore DS] [--overwrite] [--start] SNAPSHOT|latest

vmware list показывает отпечатки сертификата и SSH-ключа хоста. Передайте их через --thumbprint и --ssh-host-key, чтобы закрепить их и в командной строке.

Пока не поддерживается

  • vCenter с несколькими центрами обработки данных. Можно добавить только vCenter с одним центром; хосты остальных добавьте напрямую.
  • ВМ с собственными снимками. Их диски — дельты; сначала удалите или консолидируйте снимки. (Небольшая дельта, которую записывает снимок с приостановкой, принадлежит самой копии и читается вместе с ней.)
  • Некоторые типы дисков. Raw device mapping (RDM) и независимые диски.
  • Мгновенное восстановление через прокси-агента Windows. Для мгновенного восстановления нужен прокси-агент Linux.
