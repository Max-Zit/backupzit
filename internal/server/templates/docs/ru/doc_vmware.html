Виртуальные машины VMware ESXi

BackupZit копирует виртуальные машины хостов VMware ESXi, ничего не устанавливая ни на ESXi, ни внутрь ВМ. Агент BackupZit на любой машине в сети работает как прокси хоста. Он создаёт снимки, читает только изменённые блоки виртуальных дисков и записывает их в ваше хранилище.

Требования

  • ESXi 6.7, 7 или 8, подключённый напрямую. Хосты под управлением vCenter добавляются по одному со своим адресом; сам vCenter пока не поддерживается.
  • Пользователь с правами администратора на хосте, обычно root.
  • SSH включён на хосте: Host → Actions → Services → Enable Secure Shell. Он всегда нужен для восстановления. Хостам с бесплатной лицензией ESXi он нужен и для снимков, потому что их API доступен только для чтения.
  • Прокси-агент: любой агент Windows или Linux, который достигает хоста по портам 443 и 22. Данные копий идут через него, поэтому разместите его в быстрой сети рядом с хостом и хранилищем.
  • Свободное место в хранилище данных ВМ во время копирования работающей ВМ. BackupZit ненадолго копирует туда диск (см. ниже). Копия тонкая (thin), поэтому ей нужно столько места, сколько диск реально занимает.

Добавление хоста

  1. Откройте Агенты → Хосты VMware ESXi → Добавить хост ESXi.
  2. Введите адрес, пользователя, пароль и прокси-агента.
  3. Консоль один раз подключается, чтобы их проверить. Она читает список ВМ и лицензию и закрепляет HTTPS-сертификат и SSH-ключ хоста. Если позже хост заменят другой машиной с тем же адресом, BackupZit откажется подключаться, а не отправит ей пароль.

Пароль хранится в зашифрованном виде, как и все остальные секреты. Список ВМ обновляется каждые 10 минут или сразу по кнопке Обновить. Таблица показывает режим каждого хоста:

  • vSphere API: лицензированные хосты.
  • Бесплатная лицензия: снимки и восстановления идут через SSH.

Задания копирования

В Задания копирования выберите хост ESXi (он указан в разделе Хосты VMware ESXi списка агентов) и Виртуальные машины. Копируйте все ВМ хоста (ВМ, созданные позже, включаются автоматически) или отметьте отдельные. Задание выполняется на прокси-агенте хоста. Если вы смените прокси, существующие задания последуют за ним.

Как копируется ВМ

  1. Для ВМ включается отслеживание изменённых блоков (CBT), если оно выключено.
    • На лицензированных хостах это происходит автоматически.
    • На бесплатных хостах CBT можно включить только при выключенной ВМ. BackupZit делает это при первой копии, которая застанет ВМ выключенной. До тех пор каждая копия читает диски целиком, а запуск показывает предупреждение.
  2. Создаётся снимок backupzit_…. Когда в госте работают VMware Tools, снимок приостанавливает гостя (quiesced): приложения и файловые системы сначала сбрасывают буферы, что делает копию согласованной на уровне приложений. Без VMware Tools она согласована на уровне сбоя. Установите open-vm-tools в Linux-ВМ и VMware Tools в Windows-ВМ.
  3. CBT сообщает, какие блоки читать:
    • при первой копии — только используемые блоки;
    • затем — только блоки, изменившиеся с прошлой копии.
  4. Работающая ВМ держит свои диски заблокированными. Поэтому её диски копируются в хранилище данных (thin), а снимок сразу удаляется, обычно через несколько секунд. Затем копия читается по HTTPS и удаляется. Выключенные ВМ читаются напрямую.
  5. Конфигурация ВМ (.vmx) и NVRAM сохраняются вместе с копией.

Пример из тестовой лаборатории: ВМ Debian с диском 8 ГБ, из которых занято 1,6 ГБ. Первая копия прочитала 1,6 ГБ. Следующая, после 50 МБ новых данных, прочитала 70 МБ и заняла 23 секунды.

Восстановление ВМ

Используйте мастер восстановления (Вся виртуальная машина) или страницу копии в Активности. Выберите:

  • Как новую ВМ рядом с исходной: копия с новым именем, UUID и MAC-адресами. Имя по умолчанию — имя оригинала плюс -restored- и дата. Сетевые настройки гостя, привязанные к старым MAC-адресам, например netplan match: macaddress в облачных образах, к копии не применяются.
  • Вместо исходной ВМ: с опцией выключить её и заменить её диски BackupZit:
    • выключает ВМ и удаляет её снимки;
    • переименовывает текущие диски в ….replaced-DATE.vmdk (удалите их, когда восстановленная ВМ заработает);
    • записывает копию в новые диски с исходными именами и задаёт ЦП и память как в копии.
    ВМ сохраняет UUID, сетевые адаптеры и MAC-адреса. Если ВМ была удалена, она создаётся заново с исходной идентичностью.
  • Хост ESXi и хранилище данных: другой хост или другое хранилище того же хоста.
  • Запустить ВМ после восстановления.

Диски восстанавливаются тонкими, записываются только блоки с данными. ISO-образы, подключённые к приводам CD/DVD, не входят в копию, поэтому эти приводы остаются пустыми.

Мгновенное восстановление

Выберите Мгновенно, работая из копии, чтобы запустить ВМ за несколько секунд, не копируя сначала её диски. Прокси-агент хоста — это должен быть агент Linux — отдаёт диски ВМ прямо из копии по NFS; хост монтирует это как хранилище данных backupzit-<agent> и запускает из него ВМ. Изменения, вносимые ВМ, хранятся на агенте (/var/lib/backupzit/instant-esxi, поэтому ему нужно для них свободное место); сама копия никогда не меняется, и хранение удерживает её, пока ВМ работает из неё. Если исходная ВМ ещё существует, мгновенная ВМ получает новый UUID и новые MAC-адреса.

На странице запуска, когда ВМ работает как надо:

  • Завершить копирует её в хранилище данных хоста: ВМ выключается (через VMware Tools, если они работают), её диски копируются тонкими с помощью vmkfstools, она регистрируется из хранилища данных и снова запускается. В бесплатной лицензии ESXi нет Storage vMotion, поэтому требуется короткий простой, растущий с размером дисков. Если копирование не удалось, ВМ продолжает работать из копии.
  • Отменить останавливает и удаляет ВМ со всеми её изменениями.

Агент отвечает по NFS на порту 2049 (и регистрирует его в rpcbind машины на порту 111 или сам отвечает на порту 111) только для адреса хоста ESXi; откройте эти порты от хоста к агенту, если между ними есть межсетевой экран. Когда последняя мгновенная ВМ завершена или отменена, хранилище данных удаляется, а NFS-сервер останавливается.

Отдельные файлы

Просмотр файлов на странице копии (или Файлы из виртуальной машины в мастере восстановления) открывает диски ВМ. Можно просматривать NTFS, ext2/3/4 и XFS, в том числе на LVM, и скачивать файлы или восстанавливать их на любой агент.

Командная строка

Эти команды работают на любом агенте. Задайте пароль ESXi в BACKUPZIT_VMWARE_PASSWORD:

backupzit-agent vmware list    --host 192.168.1.20 [--user root]
backupzit-agent vmware backup  --host … --repo … [--vmid N,N]
backupzit-agent vmware restore --host … --repo … --vmid N [--new] [--name NAME] [--datastore DS] [--overwrite] [--start] SNAPSHOT|latest

vmware list показывает отпечатки сертификата и SSH-ключа хоста. Передайте их через --thumbprint и --ssh-host-key, чтобы закрепить их и в командной строке.

Пока не поддерживается

  • vCenter. Добавляйте каждый хост ESXi напрямую.
  • ВМ с собственными снимками. Их диски — дельты; сначала удалите или консолидируйте снимки.
  • Некоторые типы дисков. Raw device mapping (RDM) и независимые диски.
  • Мгновенное восстановление через прокси-агента Windows. Для мгновенного восстановления нужен прокси-агент Linux.
