Виртуальные машины Proxmox VE

BackupZit копирует виртуальные машины (QEMU) и контейнеры (LXC) Proxmox VE, ничего не устанавливая внутрь гостей. Агент работает на хосте Proxmox, делает снимок каждого гостя, читает его диски и сохраняет их с дедупликацией в любом хранилище.

Настройка

  1. Установите пакет Агент Linux — Debian / Ubuntu со страницы Агенты на каждый узел Proxmox (Proxmox VE 7 и 8 основаны на Debian): 
    apt install ./backupzit-agent_*.deb
backupzit-agent enroll --code "BZ1-..."
systemctl enable --now backupzit-agent
  2. В течение минуты узел появляется на странице Агенты с меткой Proxmox VE · N guests.
  3. В Задания копирования выберите этого агента и Виртуальные машины (Proxmox VE, Hyper-V, VMware). Копируйте всех гостей узла (гости, созданные позже, включаются автоматически) или отметьте отдельных.

Агент использует собственные инструменты узла (qm, pct, pvesm, LVM, ZFS, Ceph); в консоли не хранится ни API-токен, ни пароль.

Как копируется гость

  1. Создаётся временный снимок Proxmox (backupzit_…, виден в разделе Snapshots от нескольких секунд до минут). Гость продолжает работать.
  2. Если в ВМ работает гостевой агент QEMU (и он включён в параметрах ВМ), Proxmox замораживает файловые системы для снимка — копия тогда согласована на уровне приложений. Без него копия согласована на уровне сбоя, как при отключении питания. Установите qemu-guest-agent в Linux-ВМ и гостевые инструменты VirtIO в Windows-ВМ.
  3. Каждый диск читается из снимка блоками по 1 МиБ. Пустые блоки не сохраняются, а блоки, уже имеющиеся в репозитории, не отправляются повторно, поэтому после первой копии передаются только изменённые данные.
  4. Снимок удаляется. Конфигурация гостя (ЦП, память, сеть, диски) сохраняется вместе с копией.

Страница запуска перечисляет каждого гостя, его диски и способ захвата. Тесты восстановления проверяют случайные блоки копий ВМ так же, как у образов дисков, а при включённом тесте загрузки запускают каждую ВМ из копии, изолированно от сети, чтобы доказать, что она загружается.

Диски, помеченные в Proxmox как Backup: no (backup=0), проброшенные физические диски и bind-монтирования пропускаются и отображаются как предупреждения. Диски cloud-init не сохраняются; при восстановлении они создаются заново из конфигурации.

Восстановление ВМ или контейнера

Откройте запуск копии ВМ (со страницы задания или из Активность) и используйте Восстановить ВМ или контейнер:

  • Гость — один из гостей в этой копии.
  • Восстановить на узле Proxmox — любой узел с агентом BackupZit, в том числе узел другого кластера.
  • Как новый гость со следующим свободным ID (по умолчанию) или с ID … — оригинал продолжает работать. Поскольку существуют оба, сетевые карты копии получают новые MAC-адреса.
  • С исходным ID — после удаления гостя. Если он ещё существует, отметьте остановить и удалить его, чтобы заменить его копией; сначала удаляются существующий гость и его диски.
  • Имя и Хранилище для дисков — например, восстановить в другое хранилище, чем у оригинала.
  • Запустить гостя после восстановления.

Каждое восстановление даёт ВМ новый идентификатор поколения (vmgenid), чтобы контроллеры домена Windows и другое ПО безопасно распознали откат. Диски выделяются через pvesm в выбранном хранилище; в хранилище типа «каталог» они восстанавливаются как файлы raw.

Мгновенное восстановление

Восстановление большой ВМ длится столько же, сколько копирование её дисков. С вариантом Мгновенно, работая из копии в форме восстановления ВМ вместо этого работает уже через несколько секунд, пока её диски остаются в копии:

  1. Агент отдаёт диски ВМ из копии только для чтения (небольшой NBD-сервер, работающий как юнит systemd backupzit-instant-<ID>) и создаёт новую ВМ со следующим свободным ID, диски которой — оверлеи qcow2 в хранилище-каталоге backupzit-instant (/var/lib/backupzit-instant, добавляется автоматически). Данные читаются из копии по запросу; всё, что пишет ВМ, остаётся в оверлеях. Переменные прошивки (диск EFI) и состояние TPM невелики и копируются.
  2. ВМ запускается. Проверьте её — как любая копия, она получает новые MAC-адреса. Панель показывает каждую ВМ, которая всё ещё работает из копии.
  3. На странице запуска либо Завершить: диски переносятся в выбранное хранилище, пока ВМ работает (qm disk move), после чего копия больше не используется. Либо Отменить: ВМ останавливается и удаляется вместе с её изменениями.

Пока ВМ работает из копии, хранение никогда не удаляет эту копию. ВМ работает настолько быстро, насколько позволяет хранилище копий: лучше всего — репозиторий на локальном диске или быстром сетевом ресурсе; чтение по SFTP или S3 издалека замедляет её, пока она не завершена. Мгновенное восстановление предназначено для ВМ (не контейнеров) и создаёт новую ВМ — восстановление на месте выполняется обычным восстановлением. Диск EFI нельзя переместить, пока ВМ работает; тогда он остаётся в backupzit-instant (см. сообщение запуска) и может быть перемещён после выключения ВМ: qm disk move ID efidisk0 STORAGE --delete 1.

Репликация

Для гостей, которые должны вернуться за минуты, задание ВМ может поддерживать реплики: в разделе Дополнительно формы задания отметьте Поддерживать реплики ВМ и выберите узел (любой узел с агентом BackupZit, также в другом кластере) и хранилище. После каждой копии агент на этом узле обновляет остановленную копию каждого гостя задания:

  • В первый раз реплика восстанавливается как новый гость (следующий свободный ID, имя original-replica, новые MAC-адреса, никогда не запускается вместе с узлом).
  • Далее записываются только блоки, изменившиеся с копии, которую содержит реплика, — обычно несколько секунд на копию.
  • Страница задания показывает реплики, копию в каждой и их состояние. Если гость потерян, нажмите Запустить реплику: она работает с данными последней копии, без восстановления. Запускайте её, только если оригинал действительно пропал — оба одновременно в сети могут конфликтовать.
  • Пока реплика работает, она больше не обновляется (запуск сообщает об этом). Чтобы реплицировать снова, удалите гостя-реплику в Proxmox; следующая копия создаст новую. Реплики со снимками Proxmox тоже не обновляются.
  • Диски, добавленные гостю позже, не реплицируются (удалите реплику, чтобы начать заново); увеличенные диски увеличиваются и в реплике. Изменения конфигурации (память, ЦП) применяются при создании реплики.
  • Репликация читает копии как восстановление: узел реплики должен иметь доступ к хранилищу. Выключение репликации оставляет реплики как есть.

Командная строка

backupzit-agent pve list
backupzit-agent pve backup  --repo ... [--vmid 100,200] [--exclude 300]
backupzit-agent pve show    --repo ... latest
backupzit-agent pve restore --repo ... --vmid 100 [--new-vmid -1|N] [--name copy] [--storage local-lvm] [--overwrite] [--start] SNAPSHOT|latest
backupzit-agent pve instant --repo ... --vmid 100 [--new-vmid N] [--name X] SNAPSHOT|latest
backupzit-agent pve instant-finish --vmid 101 --storage local-lvm
backupzit-agent pve instant-discard --vmid 101

Параметры репозитория те же, что у всех команд (см. Справочник по командной строке). Командная строка работает без консоли, например чтобы восстановить целый узел после аварии.

Кластеры

Установите агента на каждый узел. Задание копирует гостей, работающих на узле его агента; гость из задания, перенесённый на другой узел, отображается как предупреждение с именем этого узла — копируйте каждый узел собственным заданием или используйте всех гостей узла на каждом узле, чтобы перенесённые гости всегда были охвачены.

Восстановление отдельных файлов

В таблице гостей запуска копии ВМ нажмите Просмотр файлов. Консоль читает диск прямо из копии — предварительно ничего не восстанавливается — и показывает его разделы и логические тома LVM; можно просматривать NTFS (Windows), ext2/3/4 и XFS (Linux), в том числе внутри LVM. Отметьте файлы и папки и:

  • Скачать — один файл как есть, несколько файлов или папок архивом ZIP, прямо в браузер;
  • Восстановить на агенте — скопировать их в папку на любом агенте, например обратно в ВМ (если в ней работает агент BackupZit) или на файловый сервер.

В командной строке: backupzit-agent pve ls --vmid 100 latest /etc и backupzit-agent pve extract --vmid 100 --target /srv/restore latest /etc/nginx; --volume выбирает раздел или логический том (pve ls без пути перечисляет их). Для просмотра в консоли копия должна находиться в сетевом хранилище (SFTP, S3, SMB, Azure, защищённый репозиторий).
