Защита от программ-вымогателей

Злоумышленники стараются удалить или зашифровать резервные копии до того, как зашифруют рабочие данные. BackupZit предлагает хранилища, в которых копии нельзя уничтожить даже с украденными учётными данными.

Уровни защиты

УровеньЗащищает от
Шифрование (AES-256)Чтения или подмены копий в хранилище. Любое изменение обнаруживается.
Неизменяемый S3 (Object Lock, режим compliance)Удаления или перезаписи копий — злоумышленником с ключами, недобросовестным администратором или по ошибке.
Защищённый репозиторийТо же самое на вашем собственном Linux-сервере: файлы записываются один раз и получают флаг неизменяемости файловой системы.
Копия вне площадкиПожара, кражи, полной потери площадки.
Принцип четырёх глаз (необязательно)Одной украденной или используемой во вред учётной записи консоли, которая удаляет задания и хранилища или сокращает срок хранения: требуется подтверждение второго пользователя. См. Пользователи, роли и LDAP.

Автоматическое обнаружение подозрительных копий

Каждая копия сравнивается с недавней историей своего задания. Она помечается как подозрительная, если в ней видны следы вымогателя или массового удаления:

  • изменилось гораздо больше файлов, чем обычно (например, 95 % вместо обычного 1 %),
  • новые данные перестали сжиматься — зашифрованные файлы выглядят как случайные данные,
  • число файлов внезапно упало на треть или больше,
  • внезапный скачок объёма новых данных (также для образов дисков, систем Linux и ВМ).

Тогда BackupZit отправляет письмо с оповещением (при включённых уведомлениях об ошибках), показывает копию на панели как подозрительных копий для проверки и приостанавливает хранение задания: ни одна старая копия не удаляется, так что последние чистые копии остаются восстанавливаемыми, даже если повреждённые копии продолжают поступать. Проверив машину, нажмите Проверено — возобновить хранение на странице задания.

Неизменяемый S3 с Object Lock

  1. Создайте бакет с включённым Object Lock (AWS, Wasabi, Backblaze B2, MinIO: mc mb --with-lock).
  2. Добавьте правило жизненного цикла, удаляющее неактуальные версии (noncurrent versions) через 1 день (MinIO: mc ilm rule add --noncurrent-expire-days 1 --expire-delete-marker).
  3. Добавьте хранилище S3 и отметьте Неизменяемые копии на N дней. Выберите N не меньше самого долгого срока хранения, который нужно защитить, например 30.

Каждая точка восстановления остаётся заблокированной не менее N дней после создания; срок для данных, общих с более новыми копиями, продлевается автоматически.

Защищённый репозиторий

Отдельный Linux-сервер с backupzit-repo:

  • Агенты и консоль могут только добавлять файлы; существующие файлы никогда не перезаписываются.
  • Каждый файл получает атрибут chattr +i на срок, заданный на этом сервере. Даже root не может удалить его, не сняв сначала флаг.
  • Удаления со стороны клиентов только скрывают файлы до окончания их срока.
  • Служба работает от непривилегированного пользователя; её единственное право — устанавливать флаг неизменяемости.
apt install ./backupzit-repo_*.deb
vi /etc/backupzit-repo/repo.env        # BACKUPZIT_REPO_LOCK_DAYS=30
systemctl start backupzit-repo
backupzit-repo add-key office-console
backupzit-repo fingerprint

После настройки отключите SSH и другой удалённый доступ на сервере репозитория и защитите доступ к его локальной консоли / iDRAC / iLO / гипервизору. Защита не сильнее учётной записи root этой машины.

Восстановление после атаки

Если злоумышленник удалил или перезаписал копии, читайте хранилище в том виде, в каком оно было до атаки — это только чтение, ничего не меняется:

backupzit-agent snapshots --repo <репозиторий> --as-of 2026-10-01T14:30
backupzit-agent restore   --repo <репозиторий> --as-of 2026-10-01T14:30 --target D:\Restore latest

В защищённом репозитории администратор может также вернуть скрытые файлы, чтобы копирование продолжалось как обычно:

backupzit-repo status
backupzit-repo undelete --since 2026-10-01T14:00

Рекомендации

  • Используйте для хранилища отдельную учётную запись, не входящую в ваш домен Windows.
  • Держите хотя бы одну неизменяемую копию (S3 Object Lock или защищённый репозиторий).
  • Храните листы восстановления офлайн (в распечатанном виде, в сейфе).
  • Включите оповещения по почте — внезапное изменение числа ошибок или объёма отправленных данных часто бывает первым признаком атаки.
