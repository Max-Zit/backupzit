Начало работы

BackupZit защищает компьютеры с Windows и Linux, виртуальные машины Proxmox VE, Hyper-V и VMware ESXi, базы данных (SQL Server, PostgreSQL, MySQL/MariaDB) и общие папки NAS — файлы, целые диски и целые системы — из одной веб-консоли, работающей в вашей собственной сети.

Как работает BackupZit

  • Консоль управления (это веб-приложение) — работает на Linux-сервере в вашей сети. Хранит конфигурацию, планирует задания, собирает результаты и показывает отчёты. Ей никогда не нужен доступ из интернета.
  • Агенты — небольшая служба на каждой защищаемой машине (MSI для Windows, deb/rpm для Linux) и на хостах Proxmox и Hyper-V; к хостам VMware ESXi обращаются через агента, работающего как прокси. Агенты связываются с консолью по HTTPS, получают задания и отправляют данные копий напрямую в хранилище. В Windows агент показывает своё состояние рядом с часами.
  • Места хранения — где хранятся копии: SFTP, S3-совместимое объектное хранилище (AWS, Wasabi, Backblaze B2, MinIO, Google Cloud…), Azure Blob Storage, общая папка SMB/NAS, сменные USB-диски, локальный или подключённый диск либо защищённый репозиторий BackupZit.

Данные копий никогда не проходят через консоль. Консоль только координирует, поэтому ей достаточно небольшой виртуальной машины.

Первые шаги

Чтобы развернуть новую консоль, импортируйте готовый образ appliance в небольшую ВМ, загрузите ISO appliance или запустите сценарий установки на существующем Linux-сервере; см. Установка сервера.

  1. Добавьте место хранения в разделе Хранилище. Оставьте включённым Шифровать копии и сохраните в надёжном месте лист восстановления, показанный после этого. См. Места хранения.
  2. Установите агентов: в разделе Агенты нажмите Создать токен регистрации, скачайте установщик с той же страницы и вставьте код регистрации, когда установщик Windows его запросит (Linux: backupzit-agent enroll --code …). Для ВМ установите агента на хост Proxmox или Hyper-V; хосты VMware ESXi добавьте в разделе Агенты → Хосты VMware ESXi. См. Агенты.
  3. Создайте задание копирования в разделе Задания копирования: выберите агента, хранилище, что копировать (файлы, общую папку NAS, образ диска, базы данных, всю систему Linux или ВМ хоста Proxmox, Hyper-V или VMware ESXi), когда запускать и сколько копий хранить. См. Задания копирования и расписания.
  4. Запустите его один раз вручную кнопкой Запустить копирование сейчас на странице задания и проверьте результат в разделе Активность.
  5. Проверьте восстановление — копия хороша настолько, насколько хорошо её восстановление. Автоматические проверки восстановления выполняются еженедельно; также один раз восстановите что-нибудь вручную с помощью мастера восстановления. См. Восстановление.
  6. Подготовьтесь к авариям: скачайте ISO восстановления и создайте код восстановления в разделе Носители восстановления.
  7. Настройте оповещения по почте в разделе Настройки → Уведомления по почте, чтобы узнавать о сбоях, и при желании еженедельный отчёт.

Язык

Консоль доступна на 14 языках: английском, немецком, французском, испанском, итальянском, португальском (Бразилия), нидерландском, польском, чешском, сербском (латиница), турецком, русском, китайском (упрощённом) и японском. Выберите язык в списке справа вверху или на странице входа; выбор запоминается в браузере. Без выбора решает язык браузера (хорватские, боснийские и черногорские браузеры получают сербский, словацкие — чешский, остальные языки — английский). Это руководство тоже переведено (страница без перевода показывается на английском). Письма, уведомления в чатах и сообщения от агентов остаются на английском.

Переводы находятся в исходном коде, в internal/server/i18n/ru.json: английский текст — ключ, перевод — его значение. go run ./tools/i18n missing ru выводит тексты без перевода; непереведённые тексты показываются на английском.

Основные понятия

Снимки и дедупликация

Каждое копирование создаёт снимок: полную, доступную для просмотра картину данных на тот момент. Файлы делятся на фрагменты переменного размера, диски — на блоки, и каждый фрагмент хранится только один раз, поэтому второе и последующие копирования выгружают только изменения — и всё же каждый снимок можно восстановить отдельно. Никакой «цепочки полных и инкрементных копий» вести не нужно.

Репозитории

Каждый агент пишет в собственный репозиторий внутри места хранения (<location>/<hostname>_<id>). Репозиторий самодостаточен: зная расположение, учётные данные хранилища и ключ восстановления, его можно восстановить, даже если консоли больше нет.

Хранение

Каждое задание хранит некоторое число последних, ежедневных, еженедельных и ежемесячных копий. Более старые снимки удаляются после каждого запуска, а занятое ими место освобождается.

Что BackupZit проверяет за вас

  • Проверки восстановления — последняя копия каждого задания еженедельно частично восстанавливается и проверяется (Восстановление).
  • Обнаружение программ-вымогателей — необычные копии (массовые изменения, зашифрованные данные, массовое удаление, резкие скачки объёма данных) помечаются, а хранение приостанавливается (Защита от программ-вымогателей).
  • Оповещения и отчёты — письма о сбоях и ежедневная сводка; отчёты по расписанию для руководства (Уведомления по почте, Мониторинг).
