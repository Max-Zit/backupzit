{{template "icon" "storage"}} Backup of the console

If the console server is lost, the backups on your storage stay readable with the recovery sheets. To also get back the console itself (jobs, schedules, users, settings, history and the stored credentials) and let all agents simply reconnect, back it up every day. The backup holds the database, the secrets key and the console's certificate, which agents pin. It is encrypted with the storage target's recovery key.

Last backup
{{if .LastAt.IsZero}}never{{else}}{{ts .LastAt}} {{if .LastError}}failed
{{.LastError}}{{else}}ok {{bytes .LastBytes}}, backup {{short .LastSnapshot}}{{end}}{{end}}

Restoring the console

  1. Install a new console, for example from the BackupZit appliance ISO, with the same or a newer version.
  2. Take the recovery sheet of the storage target. It holds the address, the access credentials and the recovery key.
  3. On the new console server, as root, set the credentials as on the recovery sheet and run: 
    systemctl stop backupzit-server
set -a; . /etc/backupzit/server.env; set +a
export BACKUPZIT_PASSWORD='<recovery key>'  BACKUPZIT_SFTP_PASSWORD='…'   # or the S3/SMB/Azure/hardened variables
backupzit-server --restore-console --repo '{{with .RepoURL}}{{.}}{{else}}<target address>/backupzit-console{{end}}'
systemctl start backupzit-server
  4. Give the new server the old server's address (IP or DNS name). The agents then reconnect by themselves.

{{template "icon" "users"}} LDAP / Active Directory sign-in

Let users sign in with their directory accounts. Their role follows their group membership at every sign-in. Local accounts keep working, so an administrator can always sign in even if the directory is unreachable.

Groups → roles full group DNs; the highest matching role wins; users in none of them cannot sign in
Certificate trust

By default the server certificate must be issued by a CA trusted by this server. For an internal CA paste its certificate; for a self-signed directory certificate enter its fingerprint.

Test

Tests the current form values without saving. Without a user name only the connection and the service account are checked; without a password the user's groups are checked.

{{template "icon" "check"}} Automatic restore tests

A backup is only proven when it has been restored. With restore tests on, the agent of each job regularly restores a random sample of files from the newest backup into a temporary folder, checks every byte against the stored checksums and deletes it again. For disk images, random blocks are read and verified. Results appear in Activity, the job history and Reports; a failed test triggers a failure email.
