Command line reference

The agent also works on its own from the command line — for scripting, for restoring without the console, and for emergencies. Run backupzit-agent without arguments for an overview and backupzit-agent <command> -h for the options of a command.

Repository and credentials

Every command takes --repo (or BACKUPZIT_REPO). Prefer environment variables for secrets. The repository of an agent is <storage location>/<hostname>_<id> — see the repository column of a run in Activity, or the recovery sheet.

LocationCredentials
D:\Backups\pc1, /mnt/backup/pc1—
sftp://user@host:22/pathBACKUPZIT_SFTP_PASSWORD or --sftp-key file; --sftp-hostkey SHA256:… (BACKUPZIT_SFTP_HOSTKEY)
s3://endpoint/bucket/prefix (?tls=false for HTTP)BACKUPZIT_S3_ACCESS_KEY, BACKUPZIT_S3_SECRET_KEY, --s3-region; --s3-lock-days N writes with Object Lock
smb://[domain;]user@host/share/pathBACKUPZIT_SMB_PASSWORD, --smb-domain
azure://account/container/path (?endpoint=URL for sovereign clouds, Azure Stack, Azurite)BACKUPZIT_AZURE_KEY or BACKUPZIT_AZURE_SAS
hardened://host:8500/pathBACKUPZIT_HARDENED_KEY, BACKUPZIT_HARDENED_FINGERPRINT
usb://LABEL/path (wildcards: usb://BZBACKUP*/BackupZit)— (the connected disk with that volume label is used)

Encrypted repositories need the recovery key in BACKUPZIT_PASSWORD (or --password).

Point-in-time view: on S3 with Object Lock and on a hardened repository, --as-of 2026-10-01T14:30 (or a date) shows the repository as it was at that time — read-only, for recovering after backups were deleted or overwritten.

Files and folders

CommandWhat it does
initCreate a new repository (encrypted when a password is given).
backup [--vss] [--exclude PATTERN]… [--tag TAG]… [--force] [--host NAME] PATH…Back up files and folders. --vss reads from a Volume Shadow Copy (Windows, administrator); --force reads all files even if unchanged.
snapshotsList snapshots with time, host, size and paths.
ls SNAPSHOT|latest [PATH]List files in a snapshot.
restore --target DIR [--include PATH]… [--verify] SNAPSHOT|latestRestore files below DIR (the original folder structure is recreated). --original instead writes them back to their original location, overwriting existing files.
check [--read-data]Verify the repository structure; with --read-data every byte is downloaded and checked.

Disk images (Windows)

CommandWhat it does
disks [--json]Show disks and partitions with their numbers.
image-backup --disk N [--partitions 1,2] [--no-vss]Back up a whole disk or selected partitions.
image-restore --target-disk N --yes-erase-target [--keep-offline] SNAPSHOT|latestWrite an image onto a disk; erases the disk. --keep-offline when the original disk is in the same machine.
image-ls --partition N SNAPSHOT|latest [\path]List files inside an imaged NTFS partition.
image-extract --partition N --target DIR SNAPSHOT|latest \path…Copy files and folders out of an imaged partition.

Linux system (bare metal, P2V)

CommandWhat it does
system-backup [--exclude PATTERN]Back up all local file systems and the disk layout. See Linux system backup.
system-show SNAPSHOT|latestShow the disk layout in a system backup.
system-restore --target DEVICE [--new-hardware] [--rebuild-initramfs] --yes-erase-target SNAPSHOT|latestRecreate the system on an empty disk, logical volume or image file.

Windows: different hardware

CommandWhat it does
prepare-hardware --disk N [--drivers DIR]Prepare a restored Windows disk for different hardware (boot drivers, extra drivers, boot files) — the same as the restore option, e.g. to repeat it from the recovery ISO.

VMware ESXi (any agent as proxy; password in BACKUPZIT_VMWARE_PASSWORD)

CommandWhat it does
vmware list --host H [--user root]Show the host's VMs, license mode, certificate and SSH key fingerprints, and datastores.
vmware backup --host H [--vmid N,N]Back up VMs (default: all) from snapshots; with changed block tracking only changed blocks are read.
vmware restore --host H --vmid N [--new] [--name X] [--datastore DS] [--overwrite] [--start] SNAPSHOT|latestRestore a VM in place (default) or as a new VM with --new. --overwrite replaces the disks of an existing VM; the old ones are kept renamed. See VMware ESXi.

Pin the host with --thumbprint SHA256:… and --ssh-host-key SHA256:… (shown by vmware list).

Hyper-V (agent on the Hyper-V host, as administrator)

CommandWhat it does
hyperv listList the host's VMs with their BackupZit numbers, and the folders for restored disks.
hyperv backup [--vmid N,N]Back up VMs (default: all) from production checkpoints.
hyperv restore --vmid N [--new] [--name X] [--folder DIR] [--overwrite] [--start] SNAPSHOT|latestRestore a VM in place (default) or as a new VM with --new. --overwrite replaces the disks of an existing VM. See Hyper-V.

pve show, pve ls and pve extract also work with Hyper-V backups.

Proxmox VE (agent on the Proxmox host)

CommandWhat it does
pve listList the VMs and containers of the cluster and the storage usable for restores.
pve backup [--vmid 100,200] [--exclude 300]Back up guests of this node (default: all) from Proxmox snapshots.
pve show SNAPSHOT|latestShow the guests and disks in a VM backup.
pve ls --vmid N [--disk scsi0] [--volume ID] SNAPSHOT|latest [path]List the partitions and logical volumes of a guest disk, or the files in a folder (NTFS, ext4, XFS, also on LVM).
pve extract --vmid N --target DIR [--volume ID] SNAPSHOT|latest path...Copy files and folders out of a guest disk without restoring the VM.
pve restore --vmid N [--new-vmid -1|N] [--name X] [--storage S] [--overwrite] [--start] SNAPSHOT|latestRecreate a guest; --new-vmid -1 takes the next free ID, --overwrite replaces an existing guest with the same ID. See Proxmox VE.
pve instant --vmid N [--new-vmid N] [--name X] SNAPSHOT|latestInstant recovery: start a VM within seconds while its disks are read from the backup (new VM, next free ID by default).
pve instant-finish --vmid N --storage SMove the disks of an instant VM to storage while it runs; then it no longer uses the backup.
pve instant-discard --vmid NStop and delete an instant VM with its changes.
nbd-serve --snapshot ID --vmid N --socket PATHServe the disks of a VM in a backup read-only over NBD on a unix socket (started by instant recovery as a systemd unit).

Managed mode

CommandWhat it does
enroll --code BZ1-… [--force]Connect the agent to a console with the enrollment code from the Agents page (--force replaces an existing enrollment). The older form --server URL --token T --fingerprint F still works.
statusShow what the running agent is doing and its backup jobs (the Windows tray icon shows the same).
service install|uninstall|start|stop|status|runManage the agent service (the installers do this).
recoveryRecovery mode, started automatically by the recovery ISOs; on any Linux live system: sudo backupzit-agent recovery --server URL --token CODE.
versionPrint the version.

Examples

set BACKUPZIT_PASSWORD=XXXX-XXXX-...
set BACKUPZIT_S3_ACCESS_KEY=...
set BACKUPZIT_S3_SECRET_KEY=...
backupzit-agent snapshots --repo s3://s3.wasabisys.com/company-backups/backupzit/pc1_1a2b3c4d
backupzit-agent restore --repo s3://s3.wasabisys.com/company-backups/backupzit/pc1_1a2b3c4d --target D:\Restore --include C:\Users\ana\Documents latest
backupzit-agent check --repo s3://... --read-data

backupzit-agent disks
backupzit-agent image-ls --repo usb://BZBACKUP1/BackupZit/pc1_1a2b3c4d --partition 3 latest \Users
backupzit-agent snapshots --repo hardened://vault:8500/backupzit/pc1_1a2b3c4d --as-of 2026-10-01T14:00

Hardened repository (backupzit-repo)

CommandWhat it does
backupzit-repo serveRun the service (systemd does this).
backupzit-repo add-key NAMECreate an access key (shown once).
backupzit-repo keys / remove-key NAMEList / revoke access keys.
backupzit-repo fingerprintCertificate fingerprint for the console.
backupzit-repo statusStored and hidden (deleted, still retained) data.
backupzit-repo undelete --since TIMEMake files deleted since TIME visible again.

Configuration: /etc/backupzit-repo/repo.env — BACKUPZIT_REPO_LOCK_DAYS, BACKUPZIT_REPO_DATA, BACKUPZIT_REPO_LISTEN, BACKUPZIT_REPO_TLS_HOSTS.
